# Changelog

本檔記錄 flight-deals 對使用者有影響的變更，最新版本在最上面；版號依語意化版本（0.x 階段 MINOR 視為可能不相容的變更）。

## [Unreleased]

### Added

- 列表卡上標「可能已過期」的價格旁邊有「刷新」按鈕（主卡與其他 2 組都有，只在啟用中、未結束的監看出現）。按下去和「立即查價」一樣重查整張監看，不只那一列，會連同本輪取樣一起查，實測約 1 分鐘，可能更久；完成後頁面自動更新，等太久時會提示稍後自行重新整理。刷新不保證每組都拿到新價格：查詢失敗、沒查到價格、額度用完，或超過每輪補查上限時，仍可能顯示較早查到的價格並繼續標「可能已過期」；重查後那一列也可能換成別的日期。
- 列表卡多列 2 組日期：日期範圍監看在主卡下方「其他日期組合（依價格）」依價格再列 2 組，每組有查到時間和自己的「查看並訂票」，有資料時另顯示去程航班與 Google 標示。只在已查到價格的日期裡排，還沒查到價格的日期可能更便宜；這 2 組每輪會重查；但查詢失敗、沒查到價格、額度用完，或重查後順序改變、換上別的日期時，顯示的可能是較早查到的價格，每組都標了查到時間。
- 覆蓋率：列表卡與監看詳情顯示「已查到價格 n／共 total 組日期」；列表頁有任一監看還有日期沒查到價格時，頁首加一句「只涵蓋已取樣的日期；未取樣的日期不代表沒有更便宜的價格。」
- 分段購票標示：Google 標示要分開買的來回價格，價格旁顯示「Google 標示此價要分開買」（網頁、Telegram 價格通知與 `/watch`）。沒標示不代表單張機票。只有 1 位成人經濟艙會標。
- 回程班次：列表卡與監看詳情主卡顯示本輪最低價組合的回程，每個監看每輪多 1 次查詢。
- 手提行李標示：Google 標示票價不含頭頂行李架時，價格旁顯示「此價至少一程不含手提行李」（來回）或「票價不含手提行李」（單程），並有一句說明。網頁、Telegram 價格通知與 `/watch` 都有。資料表多一欄（migration 0010），舊紀錄沒有標示，重新查價後才有。沒有標示不代表含手提行李。
- 看得到是哪一班：列表、監看詳情、探索、比價都顯示航空公司、航班號碼、去程起降時刻（含跨日 +1）、直飛或轉機點。來回行程只列去程班次（主卡查到回程時除外），回程要在 Google Flights 選擇。升級前的舊價格紀錄沒有這些資料，會顯示「—」。
- 每個有價格的位置都有「查看並訂票」連結，開啟 Google Flights 該日期組合的結果頁（不是直接訂位）。
- Telegram 價格通知與 `/watch` 也會帶航班號碼與起降時刻。

### Changed

- 每輪掃描都會先重查列表卡顯示的 3 組日期（主卡加其他 2 組；已在本輪取樣內的不另外加，每輪最多多 3 組），讓這 3 組的價格每輪更新。1 位成人經濟艙的來回監看，主卡那組也有機會查到回程與分段標示，仍受每小時查詢上限限制。
- 每輪重查列表卡的 3 組後，若有其他日期因此換上卡片，本輪會接著重查這些日期，直到卡上都是本輪查過的日期，每輪最多多查 9 組（彈性窗監看每輪最多由 16 次增為 25 次查詢），仍受每小時查詢上限限制。查詢失敗或沒查到價格的日期本輪不再重試，卡上會留著它較早查到的價格；9 組用完或額度用完時，卡上也仍可能有較早查到的價格，每組都標了查到時間。補查因額度停止時，該輪掃描紀錄不會標示達到上限。
- 來回說明合併成一句：「標示來自 Google，沒有標示不代表單張機票或含手提行李。同班可能有多種價格與買法，是否分開請看訂票頁各選項；分開時退改與行李規定可能不同，以航空公司或訂票網站為準。」
- 監看詳情的「航班時刻為各機場當地時間」移到訂票按鈕下方。
- 監看詳情的「較前一輪」說明移到訂票按鈕下方；探索頁「最便宜前 5 個日期」加上排序只看總價的註記。
- 價格來源說明改為「價格取自 Google 預設排序的結果；「最低價格」分頁的數字可能較低，但兩者都可能與訂票頁金額不同。」Telegram 價格通知、每日摘要、`/list`、`/watch`、`/scan` 也帶這句。2026-11-03 抽樣的 5 筆「最低價格」分頁數字都沒有延續到訂票頁，所以當時不改取價來源。
- Telegram 與網頁說明的「目前最低價」改為「已查到最低價」；比價頁註明未比較行李。
- 列表改成卡片，詳情頁頂部直接顯示已查到最低價那一班；次要表格（最近價格紀錄、本次取樣、最近掃描等）預設收合。
- 大幅減字：「Google 未在頁面內嵌…」長句改為「需人工查價」短標籤，只在完全沒有價格時顯示；重複的說明每頁只留一次，長說明收進「說明」；內部英文診斷不再出現在一般頁面。
- 1 位成人時，網頁不再逐列顯示「（1 人總價）」，改在價格旁顯示一次「1 位成人・經濟艙」；多人仍逐價標示。Telegram 不變。
- 同一組日期有多班同價時，固定選最早出發那班。
- 列表卡片顯示最低價的查到時間，過久標「可能已過期」，連續未更新標「近 N 輪未更新」。
- 已全部出發的監看，標示由「已過期」改為「已結束」。

### Fixed

- 凌晨 0 點起飛或抵達的航班時刻不再顯示「—」（Google 省略小時 0）。已存的舊紀錄要重新查價才會更新。

### Security

- 訂票連結增加執行期檢查，只接受 Google Flights 的 https 網址。

### Migration

- 資料庫升到 v11（三張表各新增 `split_ticket`，`price_observation` 新增 8 個回程欄位，都可空），啟動時自動升級並備份成 `flight-deals.pre-v11.db`。舊紀錄不回補。
- 資料庫升到 v10（三張表各新增 1 個可空欄位 `overhead_bin_excluded`），啟動時自動升級並備份成 `flight-deals.pre-v10.db`。舊紀錄不回補。
- 資料庫升到 v9（三張表各新增 4 個可空欄位），啟動時自動升級並備份成 `flight-deals.pre-v9.db`。

## [0.1.0] - 2026-11-01

首個版本，彙整 FD-1 至 FD-10。

### Added

- 監看服務：本機網頁後台可建立、修改、停用、刪除監看（固定日期或彈性窗、單程或來回），排程定時查價並保存價格歷史，詳情頁有趨勢、最便宜日期組合與查票連結。（FD-1）
- Telegram 推播：價格低於預算門檻、較上次下跌達一定比例、此監看紀錄新低時通知，同價不重複；設定頁可發測試訊息。（FD-1）
- 健康頁：資料源與斷路器狀態、連續失敗告警。（FD-1）
- 出發地與目的地改為輸入即建議，可用中文、英文或代碼片段搜尋並下拉選取。（FD-2）
- 每日摘要：每天固定時間（預設 08:00，台北時間，可改可關）推一則 Telegram。（FD-4）
- `uv run flight-deals telegram-setup` 精靈：找出 chat id 並可發送測試訊息，不修改任何檔案。（FD-4）
- Windows 登入自動啟動：`install-autostart.bat`、`uninstall-autostart.bat`，健康頁顯示自動啟動狀態，背景實例 log 寫入 `data\flight-deals.log`。（FD-4）
- 列表顯示較前一輪掃描的價格漲跌。（FD-4）
- 行程條件：成人與兒童人數、艙等、航空公司偏好（最多 5 家）、去程出發時段；價格以整組乘客總價計，畫面與通知標示人數與艙等。（FD-5）
- 探索模式：對一個月內每個出發日各查一次，以價格日曆與最低價前 5 個日期呈現，可預填建立監看。（FD-6）
- Telegram 雙向指令：`/help`、`/list`、`/watch`、`/scan`、`/digest`、`/status`、`/pause`、`/resume`，只回應設定的 chat id。（FD-7）
- 資料保留與維護：每日清除過期資料（觀測與掃描預設 180 天、通知 365 天）、清除前備份（保留 7 份）、每週 `VACUUM`，健康頁新增資料維護區塊。（FD-7）
- 多目的地比價：固定日期對 2 到 8 個目的地各查一次，依總價排序，可預填建立監看。（FD-9）
- 啟動旗標：CLI `--replace` 取代同資料庫的舊實例；`dev-up.bat` 支援 `--open`、`--no-pause`、`--skip-pull`。（FD-9）
- 出發星期篩選：彈性窗監看與探索可勾選去程出發的星期，條件摘要顯示例如「週五、週六出發」。（FD-10）
- 探索可跨多月：連續最多 3 個月，總格數最多 31，日曆依月份分段。（FD-10）

### Changed

- 查價結果同時讀取「最佳航班」與「其他航班」兩個區段並去重合併；新增「未內嵌結果」狀態，來回加商務艙加多人時 Google 不內嵌結果，不再被當成資料源異常。（FD-5）
- 列表最低價改為排除已出發的日期。（FD-4）
- 探索進行中，排程掃描與立即查價會順延並在畫面上說明。（FD-6）
- 比價進行中時，`/status` 與 `/scan` 回覆會提示「排程掃描順延」。（FD-10）
- 查價容錯：航班清單中部分無價格時，有價格者照常記錄並於詳情頁註明略過筆數，不再誤判為資料源異常。（FD-3）
- 「立即查價」完成後頁面自動更新。（FD-3）
- 同一資料庫只允許一份排程；第二個實例拒絕啟動並說明原因。（FD-3）
- 修改舊監看時，已過期的日期欄位旁會提示。（FD-3）
- `dev-up.bat` 啟動前自動結束舊的 flight-deals 實例，成功後預設不再開瀏覽器。（FD-9）
- 登入自動啟動的指令改帶 `--replace`；先前已安裝者需重新執行 `install-autostart.bat` 才會更新。（FD-9）
- `/scan` 失敗輪次文案、詳情頁「所有價格已出發」與「尚未查到價格」空狀態文案、`/watch` 最短等於最長時顯示「旅程 N 天」。（FD-9）
- 健康頁資料維護區塊新增比價相關筆數；探索頁文案集中管理。（FD-10）
- Telegram 設定精靈與服務的指令輪詢互斥：輪詢運作中時精靈會提示先關閉指令功能。（FD-7）
- 資料庫 migration 套用前自動備份為 `*.pre-vN.db`（已有資料的資料庫）。（FD-4、FD-5、FD-7、FD-9）
- 每小時查詢用量的統計改走索引，行為不變。（FD-11）
- 比價在寫入前會檢查機場代碼格式。（FD-11）
- Telegram 與預填處只接受 ASCII 數字。（FD-11）

### Fixed

- 解析漏讀「最佳航班」區段：自 FD-1 起最低價可能偏高，現在兩個區段合併計價。（FD-5）
- 180 天穩態下監看列表由約 1,165 ms 降到約 185 ms：讀取只取需要的觀測，使用者看到的內容不變。（FD-8）
- 瀏覽器沿用舊版 JavaScript 快取導致比價頁下拉無法使用：靜態資源網址加上內容版本，更新後自動換新。（FD-9）
- 403（缺自訂 header）與 400（Host 不符）的早退回應補上與一般頁面相同的安全標頭。（FD-3）
- 下拉選單未高亮時按 Enter 的行為：只有一筆或代碼完全相同才直接選取，其餘提示用上下鍵選取。（FD-3）
- 超大編號的網址現在顯示「找不到」頁，而不是錯誤頁。（FD-11）
- 探索的預估查詢次數在最接近可查上限的月份不再多估。（FD-11）
- 探索超量時，訊息會寫出需要的查詢次數與上限。（FD-11）
- 探索或比價排程失敗時，不再短暫占住而無法建立新的。（FD-11）
- 刪除監看時，若排程剛好執行完畢不再出錯。（FD-11）
- `dev-up.bat` 從其他目錄帶參數執行時路徑算錯的問題已修正。（FD-11）

### Security

- 服務只綁 `127.0.0.1`，只接受 Host 為 `127.0.0.1` 或 `localhost` 的請求，寫入請求須帶自訂 header，回應帶 CSP 與其他安全標頭。（FD-1）
- bot token 只從環境變數或 `.env` 讀取，log 與網頁遮蔽；設定精靈不接受命令列傳入 token。（FD-1、FD-4）
- Telegram 指令只執行設定的 chat id 的私訊，其他來源不執行、不回覆、不記錄內容。（FD-7）
