# local-run — 本機啟動／重啟的轉介規則

> 本 skill 屬員工線，對產品零耦合：不含任何產品的路徑、port、資料庫檔名、腳本內部細節或商業邏輯。
> 產品的啟動與重啟細節只存在於該產品分支，由產品的追蹤清單與 README 定義。本 skill 只規定 coordinator 要去哪裡找、哪些事不能做。

## 適用時機

CEO 說「啟動」「重啟」「跑起來」「開起來測試」，或任何等同意思的話時。

## 轉介步驟

1. coordinator 不臨場輸出任何指令或操作步驟，也不憑記憶或舊會話內容回答。
2. 先到該產品分支的 README，找「給 CEO 的操作」那一段。只轉述該段（或該產品追蹤清單）中已由 risk-compliance-officer 定稿的字面，不改寫、不補充、不摘要成自己的話。
3. 查該產品有沒有常設限制，例如「不得自行重新啟動」的規則，或進行中的紀錄（預測紀錄、驗收、排程中的作業）。有的話：
   - 要請 CEO 重新執行任何東西，一律走該產品追蹤清單列出的定稿請求，並照該請求的送出條件辦；
   - 不在送出條件內的時段或狀態，不回答啟動或重啟的方式；
   - 屬於重新啟動的要求，coordinator 照實記錄並轉 devops-sre，不輸出指令。
4. 該產品的 CEO 操作段尚未落地時，轉介目標暫為「coordinator 依該產品追蹤清單中的常設規則」；操作段落地後改指向該段。
5. 找不到合適的定稿字面時，不自行拼湊，先送 risk-compliance-officer 定稿，並請 devops-sre 協助確認產品現況。

## 禁止事項（coordinator 對 CEO 一律不得）

逐條可檢查，任何一條成立即違規：

1. 輸出手動啟動指令，例如 `uv run`、`npm run`、`bash …sh`。
2. 輸出任何 `git` 指令。
3. 輸出 `taskkill`、`kill`、`lsof`、`pgrep`、`Stop-Process`。
4. 輸出備份或還原步驟。
5. 檢查或修改 `.env` 或環境變數，或請 CEO 去查、去改。
6. 請 CEO 判讀視窗或終端機訊息。

## 維護

- 產品的啟動、重啟、備份、資料位置等工程內容，一律寫在該產品分支的工程文件，不寫進本 skill。
- 本 skill 不寫任何給 CEO 看的字面；對 CEO 的字面只能來自已定稿的產品文件。
- 修改本 skill 須經 qa-reviewer 審查，並確認沒有帶入產品路徑與給 CEO 的句子。
