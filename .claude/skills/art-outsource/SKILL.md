# art-outsource — 美術外包出圖流程

## 為什麼是這個形狀

本環境無法程式化呼叫圖像生成 API(網路政策 + ChatGPT Pro 訂閱不含 API 額度),
但 CEO 的 Pro 訂閱可以在 ChatGPT 介面手動出圖。因此流程設計為:

- **美術部門的專業放在 prompt 工程與風格一致性把關**,不是按按鈕。
- **CEO 只做一件事**:貼 prompt、挑圖、回傳。每張圖的判斷依據都已寫在工單裡。
- 圖像生成引擎是可替換的(ChatGPT / 其他工具皆可),工單格式不綁定特定服務。

## 角色分工

| 角色 | 做什麼 |
| --- | --- |
| art-lead | 視覺規範、出圖工單、驗收 |
| creative-lead | (需要時)命名、文案、資產背後的概念 |
| CEO | 在 ChatGPT 貼 prompt 出圖,回傳檔案 |
| frontend-engineer / dev-lead | 驗收通過後把資產接進產品 |

## 流程

### 第 1 步:確認視覺規範存在

art-lead 檢查該產品是否已有視覺規範(`work/<產品>-視覺規範.md`)。
沒有就先補——**沒有規範就出圖,等於把風格一致性交給運氣**。
規範至少要有:色彩系統、風格關鍵詞(正面與負面)、質感與光影方向、禁用元素。

### 第 2 步:art-lead 產出「出圖工單」

落檔 `work/<產品>-出圖工單-<批次>.md`,每一張資產一節,格式:

```markdown
## 資產:<用途名稱>(例:app icon)

- **檔名**:`assets/<產品>/<檔名>.png`
- **用途與出現位置**:(哪個畫面、什麼尺寸下顯示)
- **尺寸/比例**:(例:1024×1024,正方形;實際輸出尺寸依 ChatGPT 能力,比例為準)
- **prompt(直接複製貼上)**:

  > (完整英文 prompt,含風格關鍵詞、構圖、色彩、光影、
  >  以及從視覺規範帶入的一致性 token)

- **避免出現**:(負面清單,寫在 prompt 內或另列提醒)
- **驗收標準**:(2~4 條可勾選的具體條件,例:主體置中、背景單色、
  無文字、色調落在規範的主色域內)
- **備選 prompt**:(第一版不理想時的調整方向,先寫好,減少來回)
```

工單開頭必註明:引用的視覺規範版本(檔名 + commit)、本批次的資產總數。

### 第 3 步:CEO 出圖

1. 開 ChatGPT(Pro),逐節貼 prompt。
2. 同一資產可出多張挑最好的;不滿意就用備選 prompt 調整。
3. 回傳方式擇一:
   - 直接在對話中上傳圖檔給協調者(建議,快),或
   - 自行放進 repo 的 `work/assets/<產品>/` 並推上分支。

### 第 4 步:art-lead 驗收

- 逐張對照工單的驗收標準,**逐條勾選**,不合格就退回並附修正後的 prompt
  (說明差在哪一條,不要只說「再試一次」)。
- 整批檢查風格一致性:並排看全部資產,有沒有哪張明顯不同世界觀。
- 驗收通過後,資產歸檔至產品線的正式位置(由實作部門接手),
  並在工單底部記錄:每張資產的最終檔案、出圖日期、使用的 prompt 版本。

### 第 5 步:接進產品

frontend-engineer / dev-lead 把資產接進產品,依產品線一般流程過 qa-reviewer;
涉及 UI 呈現的加 qa-e2e 實機驗收。

## 紅線

- **工單裡的每個風格宣稱都要能對回視覺規範**;規範沒有的風格決定,先回頭改規範,
  不要在 prompt 裡即興發明——那是風格漂移的起點。
- **不得在 prompt 或工單裡放任何祕密**(API key、內部網址)。
- 出圖內容不得包含真實人物肖像、他人商標或現有作品的仿冒描述。
- 圖像使用權利依 OpenAI 使用條款;**商用發布前由 CEO 確認當時條款**,
  工單記錄出圖日期即為此用途。
- 資產進 repo 前確認檔案大小合理(單張建議 < 1MB,超過先壓縮)。

## 已知限制

- 出圖品質與一致性受 ChatGPT 圖像模型能力限制;同一 prompt 重跑結果會不同,
  「備選 prompt + 明確驗收標準」是主要的收斂手段。
- 此流程是人工迴圈。若未來出圖量大到值得自動化,需另開 OpenAI API 帳戶
  (與 Pro 訂閱分開計費)並放行網域,屆時另立自動化版本的 skill。
