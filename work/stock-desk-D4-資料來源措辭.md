## 二、逐條對應 V1–V4 處置說明

### V1（禁止斷言可運作）

- 問題：原草案「已接線可運作」對真實環境做出功能斷言，與「未經真實驗證」自承互斥。
- 處置：改寫為「已完成接線，並以測試替身通過自動化測試」，字面僅止於此，全文（表格欄位、揭露句）搜尋確認**不含**「可運作」「可用」「正常運作」「已可支援美股」等字樣。
- 事實層級核對：僅陳述「接線完成」與「以測試替身通過自動化測試」兩件已發生且可驗證之事，不推論到「對真實市場資料可用」。

### V2（AV 是 API key，非帳號；yfinance 不需憑證）

- 問題：原草案用「對真實帳號」，混淆 Alpha Vantage 的憑證性質（API key）與 yfinance（無需憑證）的差異。
- 處置：改為「尚未以真實 API key 對外部服務實際發送過請求」，主詞是「對外部服務」而非「帳號」，且措辭本身不排除 yfinance 無需憑證此一事實（yfinance 未提及 API key，不會誤導成需要憑證）。

### V3（鏈序需含快取優先層，與 `deps.py:96` `cache_first=True` 一致）

- 問題：原草案鏈序漏掉「TTL 內本地快取優先於主要來源」這一層，與程式碼行為不符。
- 處置：採用風控建議的第一個選項，備援鏈欄字面完整列出五層：
  「TTL 內本地快取（優先於主要來源）→ Alpha Vantage → yfinance → 任何可用快取 → 資料不足」。
  未採用「主來源欄註明 TTL 內不呼叫本層」的第二選項，因為完整鏈序寫在備援鏈欄已足以如實呈現，且與 TW 列格式一致（TW 列亦為單欄完整鏈序），版面一致性較佳。

### V4（呈現規格：常駐、不摺疊、字級、對比）

- 問題：原草案未定義揭露句的呈現位置與樣式，僅有文字內容。
- 處置：見上「呈現規格」段——明確要求同區塊常駐、禁止摺疊、字級下限（不得低於表格內文 `text-sm`）、對比下限（不得低於 `neutral-400`，實務建議 `neutral-300`），並明文排除現行 `text-xs text-neutral-500`（第 28 行原有樣式）作為承載此句的樣式來源。

### 保留句（原樣保留，未改寫）

- 「需設定環境變數 `ALPHA_VANTAGE_API_KEY`；未設定時此層直接跳過，不嘗試發送請求」——已逐字保留於揭露句中。
- 「實際覆蓋率、速率限制與資料品質目前未知，應視為待查證狀態」——已逐字保留於揭露句中。

### 額度句（suggested）

- 依 suggested 意見，未寫額度／速率限制的具體斷言句；「未知，應視為待查證狀態」已涵蓋此不確定性，不另外補充「額度用完就沒資料」一類具體宣稱。
