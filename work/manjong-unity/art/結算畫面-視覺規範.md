# 結算畫面（每局結束）視覺規範 v1

- 產品：manjong-unity（台灣 16 張麻將，Unity uGUI）
- 範圍：`ResultPanel`（`hand_end` / `game_end` 兩種階段共用）。只改版面與配色，**不改資料契約**。
- 參考解析度 1920×1080；16:10 時畫布約 1821×1138（canvas match 0.5）。
- 所有座標單位為 UI units，除非特別說明，**原點為所屬容器左上角、y 向下**（與 `ResultPanel.TopLeft()` 一致）。
- 需求來源：CEO「胡牌的那位資訊要額外顯示，除非流局才是四個玩家顯示在下方。把胡牌弄得更清楚，台數也清楚。」
- 沿用先前回饋：畫面上不放「手牌 / 吃 / 碰 / 槓 / 花牌 / 胡」說明文字，全靠排版區分；花牌＋副露在左、手牌靠右、胡的那張隔開放最右；吃牌被吃的那張放中間、不加標示。

## 0. 設計決策摘要

| # | 決策 | 理由 |
| --- | --- | --- |
| D1 | 胡牌局分成「贏家主舞台」＋「其他三家精簡列」；流局沒有主舞台，四家全部用同一種精簡列 | CEO 明確要求；贏家資訊與其他人拉開層級 |
| D2 | 主舞台用**深可可色底（ResultStage）**，不是粉彩底 | 白底牌面在深色上最跳；胡的那張加金框後一眼可辨；整張卡其餘維持淺色可愛風，只有舞台是「聚光燈」 |
| D3 | 總台數與贏得金額做成**一塊白色 / 金色「計分牌」**放舞台右上，字級 64–88 | 這兩個數字是視覺焦點；金底數字 + 象牙底金額，兩者都 >= 6.4:1 |
| D4 | 台數名目改成「名目 + 金色台數徽章」的格狀 chip（每列 6 個），莊家台 / 連莊台獨立一個珊瑚色寬 chip，排在最後 | 名目與台數分兩塊，掃讀快；莊家台不屬於 totalTai，要視覺上分開 |
| D5 | 胡的那張：**放大到 69×92（一般牌 54×72 的 1.28 倍）+ 金色粗框 + 金色光暈 + 與手牌隔 44 的間距 + 靠最右**，不加任何文字 | 遵守「不加說明文字」；用尺寸、色、位置三個管道同時區分（不只靠顏色） |
| D6 | 其他三家**仍顯示牌面**，用 Mini（33×44）；流局時四家用 Small（42×56） | 見 §4.1 理由 |
| D7 | 放槍者列加橘紅外框 + 「放槍」膠囊；放槍者排在三家的第一位 | 贏家頁面已有「xx 放槍」，下方再標一次形成呼應 |
| D8 | 卡片高度**動態**（<= 1040），寬度固定 1780 | 流局與一般胡牌局不必撐滿 1040，視覺較緊湊；最壞情況剛好貼 1032 |

## 3. 胡牌局版面（`result.kind == "win"` 且 `winnerSeat >= 0`）

由上而下：標題 -> 主舞台 -> 其他三家精簡列 -> 按鈕區。

### 3.1 標題

- 位置：`(30, 14)`，寬 1720，高 60，置中，46 pt Bold，`Ink`。
- 文字：自摸局 `自摸！`；放槍局 `胡牌！`。`game_end` 前綴 `整場結束·`；`bankrupt` 見 §6。
- 不再有副標題（舞台裡已有誰胡、誰放槍、哪張牌）。

### 3.2 主舞台 `ResultStage`

卡片座標 `(30, 82)`，寬 **1720**，高 `S`（動態，見 §3.2.5），radius 32，底 `ResultStage`，
外描邊 `ResultGold` 4 px，陰影 `CardShadow`（0,-6）。以下座標皆為**舞台內**座標，舞台內距 24。

#### 3.2.1 A 帶：身分與計分（y 16 ~ 150，高 134）

| 元件 | 座標 (x, y) | 尺寸 | 規格 |
| --- | --- | --- | --- |
| 贏家頭像 | (24, 21) | 108×108 圓 | `UiFactory.CreateAvatar`；外加 4 px `ResultGold` 圓環 |
| 贏家名字 | (150, 20) | 470×56 | 46pt Bold `ResultStageText`，單行，超出 best-fit 縮小 |
| 門風膠囊 | (150, 84) | 寬 = 26×字數+28，高 40 | `Cream` 底、26pt Bold `Ink`；例「東家」 |
| 莊 膠囊（贏家是莊才有）| 接在門風膠囊右側 8 | 40×40 圓 | `DealerBadge` 底、26pt Bold `Ink`，文字「莊」|
| 自摸膠囊（selfDraw）| (640, 47) | 240×72 | `ResultGold` 底、radius 36、48pt Bold `Ink`，文字「自摸」|
| 放槍膠囊（放槍局）| (640, 47) | 456×72 | `Coral` 底、radius 36；內容由左到右：放槍者頭像 48 圓 (x+12)、名字 30pt Bold `Ink`、「放槍」36pt Bold `Ink`；名字 best-fit |
| 計分牌 | (1136, 16) | 560×134 | 見 §3.2.2 |

#### 3.2.2 計分牌（視覺焦點）

- 外框：radius 28；整塊外加 4 px `ResultGold` 描邊。
- 左半（x 0 ~ 236）：底 `ResultGold`。
  - 總台數數字：`r.totalTai`，88pt Bold `Ink`，水平置中偏左（x 20 ~ 160）。
  - 「台」：40pt Bold `Ink`，緊接數字右下（baseline 對齊）。
  - 0 台時照樣顯示「0 台」。
- 右半（x 236 ~ 560）：底 `Card`。
  - 贏得金額：`Format.Signed(delta[winnerSeat])`（例 `+1,250`），64pt Bold `Gain`，置中，(236+16, 14) 292×78，best-fit。
  - 副行（(252, 98) 292×28，24pt `InkSoft`）：`hand_end` 顯示「金幣」；`game_end` 顯示「本場 +N」（`sessionDelta`，贏為 `Gain` 色）。
- 兩半以 2 px `ResultDivider` 分隔即可（左右底色已經分開，線可省略）。

#### 3.2.3 B 帶：贏家牌面（y 164 起，高 112；有第二行花牌時 +56）

- 基準線：**所有牌底緣對齊 y = 164+104 = 268**（胡牌 69×92 的上緣 = 176，Stage 牌 54×72 上緣 = 196，花牌 36×48 上緣 = 220）。
- 由左到右：
  1. 花牌（`StageFlower` 36×48，間距 step 37，底緣對齊）；從 x = 24 起。
  2. 與副露間距 `BlockGap` = **40**。
  3. 副露（`Stage` 54×72，牌 step 55，**副露之間 `MeldGap` = 28**）。吃牌被吃那張在中間不加標示；暗槓外側兩張蓋牌、明槓 / 加槓四張正面（沿用 `TileView.CreateMeld`）。
  4. （中間留白）
  5. 手牌（`Stage` 54×72，step 55），**右緣對齊 x = `winX` - 44**（胡牌與手牌間距 **44**，大於一張牌寬 69 的 0.6 倍，視覺上明確隔開；比花牌 / 副露間距 40 稍大）。
  6. 胡的那張：`StageWin` 69×92，**x = 1696 - 8 - 69 = 1619**（右緣 1688，留 8 給外框），底緣在基準線。
- 胡牌強調（缺一不可）：
  - 背後光暈：`ResultGlow`，比牌四邊各外擴 12（radius = 牌 radius+12），在牌**之下**。
  - 外框：`ResultGold` 5 px，外擴 6（沿用 `TileView.AddRing(tile, ResultGold, StageWin, 5)`）。
  - 不加文字徽章（遵守「不要『胡』說明文字」）。
- 花牌胡（八仙過海 / 七搶一）：胡的那張依然是 `StageWin` 放最右（複製該花牌）；若該花牌也在花牌群裡（`FlowerIndex >= 0`），在群裡那張加 `ResultGold` 3 px 小框；不持有（七搶一，`FlowerIndex < 0`）則只出現在最右。此時不從手牌扣牌。
- 手牌資料：`WinSplit.For` 邏輯不變（Hand / WinningTile / IsFlowerWin）。

#### 3.2.4 C 帶：台數明細（B 帶底 + 16 起）

台數明細是 CEO 點名要清楚的地方，**不再塞在一條文字裡**，改用「chip 格」。

- 網格：每列 **6 欄**，chip 寬 **270**，欄距 10，列高 **48**，列距 10；總寬 6×270+5×10 = 1670 <= 1672（舞台內寬）。從 x = 24 起，由左到右、由上到下依 `items` 順序（保持伺服器順序）。
- 單一 chip（名目台數）：
  - 底 `Cream`、radius 14。
  - 左段名目：x 14 起、寬 186，28pt `Ink`，單行 best-fit（最小 18）。
  - 右段台數徽章：靠右 64×48，`ResultGold` 底、右側 radius 14，字 30pt Bold `Ink`，內容只放數字（例 `3`），**不加「台」**（徽章整體語意就是台）。
- 莊家台 chip（`dealerTai > 0`）：
  - **佔 2 欄**（寬 550），排在所有名目之後；若該列剩餘不足 2 欄，換到下一列。
  - 底 `DealerBadge`、文字 28pt `Ink`；徽章同樣 `ResultGold`，內容 `+N`（N = `dealerTai`）。
  - 文字規則：`dealerTai == 1` -> `莊家`；`dealerTai >= 3` -> `莊家＋連 k 拉 k`，其中 k = (dealerTai-1)/2（取整）。
  - 為何分開：莊家台**不含在 totalTai**，只加在牽涉莊家的支付（見 `規則與台數表.md` §4），所以顏色與寬度都和一般名目不同。
- 莊家台說明行（`dealerTai > 0` 時才出現）：chip 格下方 8，高 30，22pt `ResultStageText`，文字「莊家台只加在與莊家有關的那筆支付」。
- 無名目（`items` 空）：不畫格，改畫一行 26pt `ResultStageText`：「沒有台數名目（只算底）」，高 48。
- 超量保護：chip 單位數（名目數 + 莊家台 2）> 18 時改 8 欄（chip 寬 202、名目 24pt），其餘不變。

#### 3.2.5 舞台高度 `S`（由上而下累加）

```
S = 16                        上緣
  + 134                       A 帶
  + 14                        間距
  + 112 (+56 若花牌換行)       B 帶
  + 16                        間距
  + chipRows*48 + (chipRows-1)*10   C 帶（無名目時 48）
  + (有莊家台 ? 8+30 : 0)      說明行
  + 18                        下緣
```

| 情境 | chipRows | 花牌換行 | S |
| --- | --- | --- | --- |
| 典型（5 名目、含莊家台）| 2 | 否 | 16+134+14+112+16+106+38+18 = **454** |
| 最壞（12 名目 + 莊家台 + 8 花 + 5 槓）| 3 | 是 | 16+134+14+168+16+164+38+18 = **568** |

## 4. 其他玩家精簡列（胡牌局的三家；流局的四家共用同一元件）

### 4.1 決定：仍顯示牌面，用 Mini（流局用 Small）

理由：
1. 玩家結算時會想看「放槍者 / 其他人差幾張聽」，牌面是遊戲的核心資訊，拿掉容易被抱怨。
2. 縮到 Mini（33×44，比舞台牌 54×72 小約 40% 面積）後，視覺權重明顯低於贏家，不搶焦點。
3. 版面空間夠：最壞情況也不需要換行（見 §6）。
4. 流局沒有主舞台，牌面是唯一內容，所以放大到 Small（42×56），列高 104，其他規格完全相同。

## 6. 最壞情況與換行規則

假設：贏家 5 組槓（共 20 張牌 + 手牌 1 張 + 胡牌 1 張）、8 張花、台數名目 12 項 + 莊家台。

### 6.1 主舞台牌面

- 一行放得下的條件：
  `LeftW(flowers, melds) + 44 + HandW + 44 + 69 + 8 <= 1672`，
  `LeftW = (flowers>0 ? flowers*37-1 + 40 : 0) + Σ(meld 張數*55-1) + (meld 數-1)*28`。
- 最壞數值：副露 20 張 = 20×55-1 = 1099，加 4 個間距 112 = **1211**；花牌 8×37-1 = 295，加 40 = 335。
  單行 = 335+1211 + 44 + 手牌 1×54 + 44 + 77 = **1765 > 1672 -> 換行**。
- **換行規則（只有一條）**：花牌移到第二行，左起 x = 24，`StageFlower` 36×48，上緣 = 基準線 + 8（即 B 帶高 +56）。第二行只放花牌。
- 換行後第一行 = 1211+44+54+44+77 = **1430 <= 1672**，必定放得下。
  理論最寬（17 張牌 + 5 槓額外 5 張共 22 張、5 個副露間距）也 <= 1424，所以**副露與手牌永遠不需要再換行或縮小**。
- 若實作遇到未預期資料使 `LeftW(0 花) + 44 + HandW + 44 + 69 + 8 > 1672`：改用整排等比縮放，縮放係數 = 1672 / 寬度，下限 0.85，並 `Debug.LogWarning`（不應發生）。

### 6.2 台數 chip

- 12 名目 + 莊家台（2 欄）= 14 單位 / 6 欄 = **3 列**，高 = 3×48+2×10 = 164，已含在 §3.2.5 最壞 S = 568。
- 名目最長約 6 個中文字（28pt = 168 寬）+ 14 邊距 <= 186 名目區，通過；更長則 best-fit 縮到最小 18pt。
- 超過 18 單位才切 8 欄（見 §3.2.4），理論上不會發生。

### 6.3 精簡列（三家，最壞：某一家 5 槓）

- compact：副露 20 張 Mini = 20×34-1 = 679，加 4 個 24 = **775**；花牌最多 8 張 Mini = 8×34-1 = 271（實務上贏家持有多花時其他家花少，此為保守上限），加 36；手牌 1 張 33；總需 = 271+36+775+36+33 = **1151 <= 1242**，不需換行。
- roomy（流局）：副露 20 張 Small = 20×43-1 = 859，加 4 個 28 = **971**；花牌 8 張 Mini = 271，+36；手牌 1 張 42：總需 = 271+36+971+36+42 = **1356 > 1242 -> 換行**。
  - 換行規則：花牌移到第二行（上緣 = 牌上緣 + 56 + 6），列高增為 `max(104, 24+56+6+44+10) = 140`。
  - 流局不可能有 8 花單家（8 花 = 八仙過海 = 胡），實務上花牌 <= 7，仍保留此規則。

### 6.4 整體高度

- 胡牌局最壞：contentEnd = 908，卡高 **1032**（<= 1040）。
- 流局最壞（一家換行 +36）：contentEnd = 618，卡高 742。
