## 背景與目標

**現況（N203 查證）**：排程台的標的範圍完全由 `playbook_batches` 裡有哪些 symbol 決定。唯一會建立批次列的是 `ensure_batches`，app 內沒有任何呼叫點，也沒有 API、頁面或 CLI 可以設定、移除、換標的。REBALANCE 只重算 TOTAL_DEPLOY。`high_volatility` 欄位存在但沒有寫入也沒有讀取，P3 永遠用 +15%，規則集寫的 +20% 碰不到。

**目標**：提供一個正式、單一的入口，讓使用者（CEO）自己維護排程台的標的名單，並把 N203 §1.4 的 8 點風險關掉。價值來自**紀律**（CEO #112～#114）：每個交易日都靠排程台出指令，所以名單的每一次變動都必須是有意識、有紀錄、不會悄悄改壞帳的動作。

**成功指標**：
1. 首次設定、季末換標的、停止新進場、重新加入，四個情境都能只靠入口完成，不需要手寫 SQL 或呼叫 Python。
2. N203 §1.4 的 8 點風險，每一點都有對應的需求與 AC（見「風險對照表」）。
3. 任何操作後，「啟用檔數」「每檔批數」與參數的關係，要嘛一致，要嘛畫面明講不一致，沒有靜默偏離。
4. 全程不違反 ADR-0035「批次永不重置」與 N172-C11（不 DELETE、不 UPDATE 既有指令列）。

## 使用者與情境

唯一使用者：CEO（單人使用，本機部署）。每個交易日會看排程台，每季末換一次標的。

| 情境 | 描述 |
|---|---|
| S-A 第一次設定 5 檔 | 批次表為空，使用者一次輸入 `n_targets` 檔代號 |
| S-B 季末換標的 | 季度 REBALANCE 窗口內，以書面提交新名單，留住的保留、退出的停止新進場、新的加入 |
| S-C 某一檔停止新進場 | 季中任何時間，使用者不想再對某檔進場；已持有的部位不動 |
| S-D 重新加入 | 先前停止（或已出清）的標的再次列入名單 |
| S-E 高波動清單 | 使用者自己指定哪幾檔適用 P3 的 +20% 門檻 |

### 名詞（本 PRD 內使用）

- **啟用**：該檔的 planned 批次可以產生 R1 買進指令。
- **停止新進場**：該檔不再產生 R1 買進指令；列保留；已持有（open）批次照常走 S、P 系列出場規則。表達方式（新狀態、symbol 層旗標或其他）由 TA 判定，PRD 只規定行為。
- **啟用檔數**：目前處於啟用的標的數。
- **季度窗口**：季末最後交易日收盤後起、至下個季度第一次評估日之前（裁決一）。精確邊界見開放問題 Q-C1。

## 範圍內 / 範圍外

**範圍內**
1. 首次設定標的。
2. 檢視目前名單與每檔狀態。
3. 單檔停止新進場（季中任何時間）。
4. 重新加入。
5. 季度換標的（書面提交）。
6. 與 REBALANCE、confirm-rules（資金確認）的互斥與先後約束。
7. 啟用檔數與 `n_targets`、批數與 `batches_per_target` 的一致性守門與揭露。
8. 高波動清單的設定與接線（N-204）。
9. 變更稽核紀錄。

**範圍外（non-goals）**
1. **任何形式的選股協助**：不推薦、不排序、不評分、不預填、不顯示「候選」、不自動補位。這是紅線，不是未排期。
2. 自動補位（裁決四：名額不補）。
3. 調整 `n_targets`、`batches_per_target` 本身（屬規則參數變更，走 `request_rule_change`，另案）。
4. 移除（刪除）批次列。永遠不刪。
5. 只出清單一標的的快捷操作（EMERGENCY_EXIT 僅限全部出清，裁決六）。
6. 非台股標的支援（排程台只支援台股）。
7. 把 REBALANCE 本身做成畫面（另案；本單只規定它與標的設定的關係）。
8. 技術選型與資料表設計（交 TA）。
9. 給 CEO 的手動操作說明文件（N203 §4 第 3 點，需 CEO 核可後另行處理；本入口上線後即不需要）。

## 功能需求（逐條編號）

### 一、名單檢視
- **FR-1**：入口顯示目前名單：每檔代號、狀態（啟用／停止新進場）、批次摘要（planned、open、closed、skipped 各幾批）、是否標為高波動。另顯示「啟用檔數 X／n_targets Y」與「每檔批數 = batches_per_target Z」。
- **FR-2**：列表順序固定為「使用者輸入順序」（或代號升冪，由 TA 與 UI 擇一，但必須固定且不依任何績效、波動、價格指標）。

### 二、首次設定（S-A）
- **FR-3**：僅在批次表為空時可用。使用者提交代號清單，系統用 `params.batches_per_target` 為每檔建立批次，**使用者不輸入批數**（關 N203 風險 4）。
- **FR-4**：提交的檔數必須恰好等於 `n_targets`（關風險 3）。
- **FR-5**：輸入驗證，全部失敗即整批拒絕、零寫入：代號不得重複；須符合台股代號格式；須能取得日線資料（關風險 6）。拒絕訊息只陳述事實（哪個代號、哪項檢查失敗），不提供替代代號。
- **FR-6**：寫入走後端同一個資料庫連線，成功後 `/today` 立即可見，不需重啟（關風險 7）。

### 三、單檔停止新進場（S-C）
- **FR-7**：任何時間可對單一標的「停止新進場」。操作前須二次確認，確認畫面列出該檔 planned 批數與 open 批數。
- **FR-8**：停止後，該檔 planned 批次**不刪列**，不再產生 R1 買進指令（關風險 1、2）。
- **FR-9**：該檔已持有（open）批次照常走 S、P 系列規則，包括停損、停利、EMERGENCY_EXIT。停止新進場不得抑制任何賣出類指令。
- **FR-10**：停止當下已產生、尚待結算的指令照常結算，不取消、不改寫（N172-C11）。畫面須揭露此點。是否與使用者預期一致，列入 Q-T3。
- **FR-11**：停止會使啟用檔數低於 `n_targets` 時，**名額不補**（裁決四）：`n_targets` 與每批金額不變，畫面常駐揭露「名額空缺 N，系統不會補位，實際投入低於計畫」。
- **FR-12**：停止新進場是使用者的決定，與 S2 黑名單（自動暫停、S1 站回 25MA 後恢復）互相獨立。S2 的自動恢復路徑**不得**把使用者停止的標的恢復成可新進場。
- **FR-13**：對已停止的標的再次停止為冪等：不產生副作用，回覆「已是停止狀態」。

### 四、重新加入（S-D）
- **FR-14**：重新加入屬「補名單」，依裁決四只在季度窗口內可做（Q-C2 待 CEO 確認）。
- **FR-15**：該檔仍有 planned 批次時，重新加入 = 回到啟用，續用原 planned 批次，不新增列，不動既有 open、closed 批次。
- **FR-16**：該檔批次已全部 closed 或 skipped 時，重新加入必須讓它**真的產生新的 `batches_per_target` 批 planned**，舊列保持原樣；不得出現「操作成功但沒有任何新批次」的靜默無效（關風險 5）。機制（例如輪次欄位）由 TA 判定，且不得違反 ADR-0035。
- **FR-17**：重新加入後啟用檔數不得超過 `n_targets`。

### 五、季末換標的（S-B）
- **FR-18**：季度窗口內，使用者以「書面提交」方式送出新名單（共 `n_targets` 檔）。系統算出差異並分三組呈現：新增、保留、停止新進場；使用者逐項確認後才寫入。
- **FR-19**：舊名單中有 open 批次、但不在新名單的標的，一律轉為「停止新進場」，**不是移除**；open 批次照常走出場規則。
- **FR-20**：每次提交留存書面紀錄（提交時間、提交前名單、提交後名單、三組差異），事後可查，且不可修改。
- **FR-21**：新增標的最早的 R1 買進指令，不得早於「本次提交成功，且同季 REBALANCE 成功」之後的第一個評估日（建議行為，待 TA 與 CEO 確認，見 Q-T2、Q-C3）。

### 六、順序與互斥
- **FR-22**：標的設定變更（首次設定、停止、重新加入、季度提交、高波動變更中的名單相關寫入）、REBALANCE、confirm-rules 三者**不得同時執行**。任一進行中，另外兩者被拒絕，訊息說明被哪一項擋下，零寫入（關風險 8；風控 REBALANCE 與 confirm-rules 互相干擾的揭露）。
- **FR-23**：並發請求的結果，必須等同其中一個循序執行，不得留下「批次列已改但 TOTAL_DEPLOY 未改」之類半套狀態。
- **FR-24**：confirm-rules（資金確認）執行時，若啟用檔數與 `n_targets` 的關係不符合 FR-25，拒絕並指向標的設定入口。首次流程的正確順序為：設定標的，再確認資金。
- **FR-25**：標的設定與 ADR-0041、ADR-0042 的結算互不破壞：停止新進場不得使進行中或之後的結算失敗，也不得造成「已 claim 未動帳」。

### 七、一致性
- **FR-26**：任何寫入完成後，啟用檔數**不得大於** `n_targets`；啟用檔數**小於** `n_targets` 只允許由停止新進場或 S2 造成，且須揭露空缺（FR-11）。
- **FR-27**：每檔批次數恆等於 `batches_per_target`（每一輪）。若參數事後被改而既有批數不符，畫面揭露不一致，**不自動補列或刪列**；處理方式交 TA。
- **FR-28**：cap-1 揭露句（現寫死「排程台的 5 檔」）改為依實際啟用檔數與 `n_targets` 呈現。字句交風控定稿。

### 八、高波動清單（S-E，併入 N-204）
- **FR-29**：使用者可對名單內的單一標的勾選或取消「高波動」。僅限名單內標的。
- **FR-30**：標記接線到評估流程：下一個評估日起，高波動標的的 P3 門檻為 +20%，其餘為 +15%；取消標記回到 +15%。
- **FR-31**：標記變更不改寫任何已產生的指令列，只影響之後的評估。
- **FR-32**：標記變更前須揭露其效果（停利門檻由 15% 提高為 20%，或相反），字句交風控。
- **FR-33**：標記是使用者自己的判斷。系統不計算、不建議、不顯示任何波動率數字或排行來協助標記。
- **FR-34**：標的停止新進場、重新加入時，高波動標記保留不變。

### 九、紅線與稽核
- **FR-35**：全介面與 API 回應不得出現推薦、排序依據、評分、預填、候選、自動補位。
- **FR-36**：每次寫入產生一筆稽核紀錄（時間、動作、前後狀態），採新增、不修改的方式；寫入失敗不留半套。
- **FR-37**：不得有任何路徑 DELETE `playbook_batches`；不得 UPDATE 或 DELETE 既有指令列（ADR-0035、N172-C11）。

## 驗收條件（每條需求至少一組 Given/When/Then）

以下 AC 預設 `n_targets=5`、`batches_per_target=3`，除非另述。

### A. 首次設定（FR-3～FR-6）
- **AC-01**（FR-3）Given 批次表為空；When 提交 5 個相異且有效的台股代號；Then 建立 15 列 planned（每檔 batch_no 1～3），皆為啟用，且提交表單沒有批數欄位。
- **AC-02**（FR-4）Given 批次表為空；When 提交 4 檔或 6 檔；Then 拒絕、批次表仍為零列，訊息列出需要的檔數 5。
- **AC-03**（FR-5）Given 批次表為空；When 提交含重複代號；Then 整批拒絕、零寫入，訊息指出重複的代號。
- **AC-04**（FR-5）Given 批次表為空；When 提交 `2330.TW`、空字串或非數字代號；Then 整批拒絕、零寫入，訊息指出是哪一個。
- **AC-05**（FR-5）Given 代號格式合法但資料來源取不到該檔日線（測試以 stub 資料來源重現）；When 提交；Then 整批拒絕、零寫入，訊息陳述「取不到日線資料」，不含替代代號。
- **AC-06**（FR-3）Given 批次表已有任何列；When 呼叫首次設定；Then 拒絕、零寫入，訊息說明已有名單，請改走季度換標的。
- **AC-07**（FR-6）Given 首次設定成功；When 立即呼叫 `/today`；Then 回應涵蓋這 5 檔，不需重啟服務。

### B. 停止新進場（FR-7～FR-13）
- **AC-08**（FR-8）Given 某檔有 3 筆 planned、無 open；When 停止新進場並進入下一個評估日；Then 該檔 3 列仍存在且 id 不變，`/today` 沒有該檔的 R1 買進指令。
- **AC-09**（FR-9）Given 某檔有 1 筆 open（觸及 S1 條件）與 2 筆 planned；When 停止新進場並評估；Then 仍產生該 open 批次的賣出指令，2 筆 planned 不出 R1。
- **AC-10**（FR-10）Given 某檔有一張尚待結算的 R1 買進指令；When 停止新進場後執行結算；Then 該指令照常結算，指令列未被改寫，畫面有揭露句。
- **AC-11**（FR-11）Given 5 檔皆啟用；When 停止其中 1 檔；Then 畫面顯示「啟用 4／n_targets 5，名額空缺 1，系統不會補位」，`n_targets` 與每批金額計算結果與停止前相同。
- **AC-12**（FR-7）Given 使用者按下停止；When 尚未二次確認；Then 資料零變更；確認畫面列出該檔 planned 批數與 open 批數；取消則維持原狀。
- **AC-13**（FR-12）Given 某檔被使用者停止，且之後觸發 S2 暫停再達成 S1 恢復條件；When 評估；Then 該檔仍為停止新進場，不出 R1。
- **AC-14**（FR-13）Given 某檔已停止；When 再次停止；Then 無資料變更、不新增稽核紀錄，回覆「已是停止狀態」。
- **AC-15**（FR-1、FR-8）Given 某檔停止後所有批次皆 closed 或 skipped；When 檢視名單；Then 該檔列仍顯示，標示無持有、無待進場，資料列未被刪。

### C. 重新加入（FR-14～FR-17）
- **AC-16**（FR-15）Given 窗口內，某檔已停止且仍有 planned；When 重新加入；Then 狀態回啟用，批次列總數不變，open、closed 批次不變。
- **AC-17**（FR-16）Given 窗口內，某檔 3 批皆 closed；When 重新加入；Then 新增 3 列 planned，舊 3 列欄位逐欄不變，畫面顯示「新增 3 批」。
- **AC-18**（FR-14）Given 窗口外；When 重新加入；Then 拒絕、零寫入，訊息說明補名單只在季度窗口內。
- **AC-19**（FR-17）Given 啟用檔數已等於 `n_targets`；When 重新加入另一檔；Then 拒絕、零寫入，訊息說明名額已滿。

### D. 季度換標的（FR-18～FR-21）
- **AC-20**（FR-18）Given 窗口內且無互斥操作進行中；When 提交含 5 檔的新名單；Then 畫面分「新增、保留、停止新進場」三組呈現，使用者逐項確認前資料零變更。
- **AC-21**（FR-18）Given 窗口內；When 提交名單檔數不是 5；Then 拒絕、零寫入。
- **AC-22**（FR-19）Given 舊名單某檔有 open 批次且不在新名單；When 確認提交；Then 該檔變為停止新進場，open 批次照常評估 S、P，該檔所有列未被刪。
- **AC-23**（FR-20）Given 提交成功；When 查詢書面紀錄；Then 取得提交時間、前後名單與三組差異，且紀錄無修改入口。
- **AC-24**（FR-18）Given 窗口外；When 提交整份新名單；Then 拒絕、零寫入。
- **AC-25**（FR-21）Given 新增標的 X 於本季提交；When 同季 REBALANCE 尚未成功時評估；Then `/today` 無 X 的 R1；REBALANCE 成功後的第一個評估日起才可能出現。

### E. 順序與互斥（FR-22～FR-25）
- **AC-26**（FR-22）Given REBALANCE 執行中；When 提交任一標的設定變更；Then 拒絕、零寫入，訊息指出因 REBALANCE 進行中。
- **AC-27**（FR-22）Given 標的設定變更執行中；When 呼叫 REBALANCE；Then 被拒絕且 TOTAL_DEPLOY 與現金未被改寫，訊息指出原因。
- **AC-28**（FR-22）Given confirm-rules 執行中；When 提交標的設定變更；Then 拒絕、零寫入；反向（設定變更中呼叫 confirm-rules）亦拒絕。
- **AC-29**（FR-23）Given 標的設定變更與 REBALANCE 同時送達（測試以併發重現）；When 兩者完成；Then 最終狀態等同兩者循序執行之一，不存在批次列已改但 TOTAL_DEPLOY 未改（或反之）的半套狀態。
- **AC-30**（FR-24）Given 啟用檔數大於 `n_targets`，或批次表為空；When 呼叫 confirm-rules；Then 拒絕並指向標的設定入口，不寫資金。

### F. 一致性（FR-26～FR-28）
- **AC-31**（FR-26）Given 任一寫入操作（首次、停止、重新加入、季度提交）；When 完成；Then 啟用檔數不大於 `n_targets`；以性質測試對多種操作序列驗證。
- **AC-32**（FR-27）Given `batches_per_target` 被改為 2 而既有每檔為 3 批；When 檢視名單；Then 畫面揭露批數不一致，批次列數不變。
- **AC-33**（FR-28）Given 啟用檔數 4、`n_targets` 5；When 顯示 cap-1 揭露句；Then 字句反映 4 與 5，不再出現寫死的「5 檔」。

### G. 高波動清單（FR-29～FR-34）
- **AC-34**（FR-30）Given 標的 X 標為高波動、Y 未標；When 兩檔皆達 +16% 並評估；Then Y 觸發 P3，X 不觸發；兩檔皆達 +20% 時 X 也觸發。
- **AC-35**（FR-30）Given X 先標後取消；When 下一評估日達 +16%；Then X 觸發 P3。
- **AC-36**（FR-31）Given 已有 X 的指令列；When 變更 X 的高波動標記；Then 既有指令列欄位逐欄不變，新門檻從下一評估日起生效。
- **AC-37**（FR-32）Given 使用者變更標記；When 送出前；Then 畫面揭露門檻由 15% 變 20%（或反向）的文字，未確認前資料不變。
- **AC-38**（FR-29、FR-34）Given 標的不在名單；When 嘗試標記；Then 拒絕。Given X 已標高波動；When X 停止新進場再重新加入；Then 標記仍在。
- **AC-39**（FR-33）Given 高波動設定畫面與其 API 回應；When 檢查內容；Then 不含波動率數值、排行、「建議標記」之類欄位與字句。

### H. 紅線（FR-2、FR-35）
- **AC-40**（FR-2、FR-35）Given 所有入口畫面與 API schema；When 掃描；Then 無 recommend、score、rank、candidate、suggest 類欄位與字句；名單順序為固定規則，改變價格或績效資料不改變順序；輸入框無依績效排序的提示。
- **AC-41**（FR-11、FR-35）Given 名額空缺；When 檢視畫面與跑完整評估；Then 無「建議補入」字樣，且程式中無任何自動補位路徑（以測試證明：空缺存在時，不新增任何 symbol 的批次列）。

### I. 稽核與不變式（FR-25、FR-36、FR-37）
- **AC-42**（FR-36）Given 任一成功寫入；When 查稽核；Then 有一筆含時間、動作、前後狀態；Given 寫入中途失敗；Then 批次與稽核皆無殘留。
- **AC-43**（FR-37）Given 整個程式碼庫；When 以 AST 或 grep 測試；Then `app/` 內沒有 `DELETE FROM playbook_batches`，且沒有對既有指令列的 UPDATE 或 DELETE 新增點。
- **AC-44**（FR-25）Given 有一個結算正在 `claim_and_settle` 中；When 同時對該標的停止新進場；Then 結算結果與沒有停止時相同，不出現已 claim 未動帳的列。

## 風險與依賴

1. **依賴 TA 的設計**：停用語意的表達、重新加入的輪次機制、互斥機制，三者都牽動 ADR-0035 與 ADR-0042 的不變式。
2. **依賴風控定稿字句**：本入口是使用者自己選股的輸入，任何文案都不能變成推薦。
3. **與 REBALANCE 的耦合**：REBALANCE 目前沒有畫面入口（N203 §1.3），季末流程的互斥與先後必須在 API 層守住，不能只靠畫面。若 REBALANCE 的入口之後才做，本單的互斥要先在 API 層可測。
4. **名額空缺的實際影響**：名額不補代表停止一檔後，實際投入低於 TOTAL_DEPLOY 的計畫值；這是裁決四的直接後果，揭露不得省略。
5. **現況未知**：CEO 本機 DB 目前有幾檔、如何寫入、批數多少都未確認（N203 §3）。上線時可能要處理既有資料與新入口的銜接（遷移是否需要，見 Q-C5）。
6. **高波動接線影響既有行為**：接線後，被標記的標的 P3 門檻改變，是行為變更，需 qa 回歸驗證。
7. 沙盒內無 DB，本 PRD 未驗證 CEO 本機實際內容；不讀 `.env`、不碰 `data/*.db`。
