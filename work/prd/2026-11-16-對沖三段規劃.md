# stock-desk 對沖三段規劃 PRD（草案）

- 作者：product-manager｜日期：2026-11-16｜狀態：draft，待 CEO 回答開放問題
- 依據：CEO #151（決策包二補遺）、#144（主力仍在預測核心）、#139（短文件）、ADR-0025 D-12、ADR-0030 D-1～D-8
- 本文件只寫需求，不寫設計與技術選型；不是投資建議。

## 背景與目標

CEO 問：「你認為的預測以及未來風險評估，你要把對沖這件事加入在事件裡面嗎？不然基本上我就只有做多這個選項？」並裁示：「照你的建議做，對沖也要一起規劃」。
目標：讓產品在判斷偏空或不確定時，使用者看到的不只有「持有或買進」；並讓「對沖」有一條先記錄、驗證，再決定是否上線的路。本規劃不插隊到「真實資料驗收 → 正式登記 → 接線」之前（#144）。

## 現況（已查證）

- 動作列舉只有 6 種：`add`、`hold`、`reduce`、`stop_loss`、`take_profit`、`insufficient_data`（`apps/stock-desk/backend/app/advice/engine.py:61`；規則側 `loader.py:54`；字面「加碼參考／減碼參考／停損型減碼參考」見 `limits.py:121-124`）。
- 已能給：減碼、停損型減碼、停利、持有。**coordinator 說「減碼」是新增項，實際上已存在。**
- 「暫停加碼」**不是獨立動作**：只在「加碼被防禦型規則、上限或預設風險預算擋下」時降成 `hold`，文案為「加碼建議改為觀望」（`engine.py:376-406`）。
- 「提高現金比例」**不存在**：`app/advice/book.py:14-26` 明寫產品沒有現金與帳戶資料，只有使用者在設定頁自填的淨值。
- 沒有任何放空、對沖或反向部位的概念。`app/leverage/` 只做槓桿／反向 ETF 的報酬衰減分析，不是對沖建議。
- 行動計畫卡（`app/plan`）、價位 v2（`app/keylevels`）目錄尚不存在。
- 預測核心：事先宣告 v0.32 的範圍只有大盤 TAIEX 的 3 日、5 日兩個 claim；ETF、槓桿與反向 ETF 不在範圍（v0.32 §E-SCOPE-TYPE）。目前沒有任何規則通過驗證，ADR-0025 規定驗證前不得顯示成結論。

## 功能需求與驗收條件

### 第一段：降低曝險選項

- 做：(1-1) 把既有「減碼參考」與被擋下的「觀望」整理成使用者看得懂的「降低曝險」選項，放在既有建議卡；行動計畫卡（Phase 4）上線後同一組選項沿用；(1-2)「暫停加碼」成為可辨識的狀態（不是只有觀望字樣）；(1-3)「提高現金比例」只在使用者已自填淨值時，才以「目前部位占淨值比例」描述，不給目標比例。
- 不依賴未驗證方向判斷的程度：觸發只能用**既有的非方向條件**（持倉上限被違反、防禦型規則命中、停損價觸及、資料不足）。不得以「預測偏空」觸發。因此這一段能做到「風險控管式的降曝險」，做不到「看壞所以降曝險」。
- 不做：不給減碼股數以外的比例建議、不給現金目標值、不顯示預測標籤。
- 驗收：
  1. Given 加碼被防禦型規則或上限擋下，When 產生建議，Then 回應含「暫停加碼」狀態與原因，且不含買進股數。
  2. Given 使用者未填淨值，When 要求現金比例相關資訊，Then 顯示「無法計算」與原因，不用估算值。
  3. Given 預測核心尚無通過驗證的規則，When 任何降曝險選項出現，Then 其觸發條件清單中不含任何預測標籤。
  4. Given 新增或修改的使用者面文字，When 提交，Then 附風控逐字核可紀錄（CLAUDE.md §0.5）。
- 進入條件：CEO 回答 Q1；風控核可字面。不需等預測驗證。排在預測核心接線之後，不插隊。

### 第二段：紙上對沖（先記錄、不顯示）

- 做：在預測紀錄帳新增一項**新的事先宣告項目（新 claim）**，記錄「若當時假想對沖，結果與不對沖相比如何」。需求層級要記錄：假想工具、假想進場與出場時點規則、與「不對沖」基準的並列比較、成本假設。具體定義由 quant 設計。
- 不做：不顯示在任何畫面、API、提醒；不輸出對沖比例建議；不彙總成勝率或「有效」字樣（比照 ADR-0030 D-4.5）。
- 驗收：
  1. Given 紙上對沖已事先宣告並凍結，When recorder 執行，Then 每筆紀錄同時含「對沖」與「不對沖」兩欄，且 `validation_status` 為未驗證。
  2. Given 任何 API 或畫面，When 檢查回應，Then 不出現紙上對沖欄位（測試斷言）。
  3. Given 宣告晚於第一筆對應紀錄，When 檢查，Then 該項不得計入驗證統計（以 git 時間佐證）。
- 進入條件：(a) 真實資料驗收與大盤 claim 正式登記完成；(b) ADR-0030 D-1.2 規定新增前瞻 claim 須先修訂 ADR 並經風控審語意，且計入 m（多重檢定次數），由 tech-architect 提 ADR；(c) 事先宣告含 quant 設計、TA 與風控審過。
- 注意：v0.32 排除反向 ETF，所以假想工具若選反向 ETF 須另定範圍；是否改用指數假想空單屬 quant 設計題（Q-Q1）。

### 第三段：真實對沖工具（只列規劃，不承諾時程）

- 進入條件（可檢查）：(1) 至少一條方向規則依事先宣告通過驗證閘門（狀態為「優於基準」，非驗證中）；(2) 第二段的紙上對沖已累積事先宣告的最低樣本數且報告經 quant 與 qa 審查；(3) CEO 回答 Q2 且有可用工具；(4) 風控審過使用者面字面框架。任一未成立，不進入。
- 各工具需另外回答的問題：

| 工具 | 資料源 | 成本 | 工具特有風險 | 帳戶條件 |
|---|---|---|---|---|
| 融券放空 | 券源、借券費率來源待查 | 利息、借券費、稅 | 被強制回補、除權息、軋空 | 信用戶 |
| 反向 ETF | 價格與指數對映（`app/leverage` 可部分沿用） | 管理費、日度重置損耗 | 長期持有偏離（路徑依賴）、與持股不一致 | 一般證券戶 |
| 期貨／選擇權 | 期交所資料，現無 | 保證金、轉倉、權利金 | 保證金追繳、到期、時間價值 | 期貨戶 |

- 驗收（規劃階段）：Given 進入條件全部成立，When 開第三段 PRD，Then 每個工具至少有上表五欄答案才能排實作；任一欄空白即不排。
- 不做：不承諾時程、不預設哪個工具會做。

## 明確不做

- 不輸出對沖比例的單一數字建議。
- 不保證任何對沖結果，不使用保證性字眼。
- 預測驗證通過之前，不顯示任何對沖建議。
- 不下單、不串接券商。
- 不插隊現行排程（真實資料驗收 → 正式登記 → 接線）。

## 風險與依賴

- 面向使用者、須送風控審（有否決權）：第一段「降低曝險」「暫停加碼」文字與現金比例描述；第三段所有對沖相關說明與風險揭露；第二段不得有任何使用者面文字（若有即違規）。
- 依賴：ADR-0030 修訂（新 claim）、事先宣告新版、m 的計數、第三段的資料源查證。
- 風險：紙上對沖增加檢定次數，會提高多重比較門檻；先記錄後驗證的樣本累積很慢（ADR-0025 估單一標的 5 日展望一年約 50 筆不重疊）。

## 建議順序與依賴

1. 現行：真實資料驗收 → 正式登記 → 接線（不動）。
2. 接線完成後：第一段（不依賴驗證）與第二段的 ADR 修訂、事先宣告並行起草。
3. 第二段凍結並開始記錄 → 累積 → 報告。
4. 第三段在閘門成立後才開 PRD。
