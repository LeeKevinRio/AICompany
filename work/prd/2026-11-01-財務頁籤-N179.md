## 背景與目標

### 背景

- 系統目前**沒有任何基本面資料**：訊號、操作參考卡、警示全部只用日線價量與持倉比重（量化回應 2.4；資料調查 1.2）。
- CEO 想看的是「一家公司的現金怎麼賺進來、又怎麼分出去」：自由現金流、股利與回購、財報摘要（創意企劃）。
- 基本面在 2026-10-26 產品審視中列為凍結。CEO 於 2026-11-01 以 #90 解凍，條件是第一版只做資訊展示。
- 量化回應指出：我們沒有「按公布日留存」的歷史財報，現在無法驗證這些數字對報酬有沒有幫助。所以第一版只展示，同時**從第一天起依公布日留存快照**，為日後驗證打基礎。

### 目標

1. CEO 打開「財務」頁籤，能在約 30 秒內看到所選標的的 FCF、股利與回購、財報摘要，且每個數字都附期間、公布日、來源。（創意企劃的 30 秒目標沿用，作為設計目標而非量測承諾。）
2. 缺的欄位要分清楚是「公司沒有」還是「我們沒抓到」，不讓 CEO 誤判。
3. 全頁只陳述事實：不評價、不排序、不進訊號、不進模型。
4. 從第一天起，每次取得的財報數字依公布日留存，不覆蓋。
5. 骨架台美共用：美股先上線，台股資料源查證後補上，不重做頁面。

### 成功指標

- 範圍內標的的必要欄位，每一格都「有值」或「有明確的缺值分類」，沒有空白、沒有 0 代替缺值。
- 抽樣核對（見 AC-14）：與官方申報一致。
- 快照留存：每一次取得新公布的財報，都有對應的不可覆蓋的留存紀錄（見 AC-12）。

## 使用者與情境

- 使用者：CEO 一人（B1 純自用，沿用 ADR-0025）。懂 FCF 與財測概念，但不是會計師；要的是看得懂的數字，不是報表原檔。
- 情境 S1：收盤後或財報季，CEO 想知道持有的美股最近一季現金流與股利、回購的實際金額。
- 情境 S2：CEO 看到某檔缺資料，想知道是公司沒有，還是系統沒抓到。
- 情境 S3：CEO 擔心這頁數字影響決策卡的建議，想確認兩者無關。
- 情境 S4（後續）：台股財報季，CEO 想看持有台股的現金流與月營收。

### 範圍外（non-goals，明確列出）

1. **財測／guidance：第一版不放。原因（五條，缺一不可）**：
   1. 美股公司的財測寫在財報新聞稿（8-K 附件）與電話會議的文字裡，不在 XBRL 結構化資料內，SEC 沒有統一欄位；免費結構化來源基本上不存在（資料調查 2.3；量化回應 2.5）。
   2. 台股正式財測已非強制，多數公司不提供；有的話也是非結構化文字或口頭展望，沒有結構化來源（同上）。
   3. 分析師共識預估要付費，且爬公開網站有使用條款風險；第三方彙整的預估不可當成公司財測呈現（資料調查）。新增付費源須升級 CEO。
   4. 系統自行推算的預測不做：系統現有預測能力標示為未經歷史驗證（創意企劃）。
   5. 財測每改一次就要保留版本與公布時間戳才有驗證價值（量化回應 2.3），而我們目前沒有這份資料基礎；硬放只會是無法驗證的展示。
   - 附帶：「財測說到 vs 做到」對照（創意企劃的險牌）列第二期以後再議，因其極易被讀成對公司的評分。
2. 任何進訊號、排序、篩選、模型、決策卡、建議卡、警示的用途（量化回應的用途 (b)(c) 全不做）。
3. 估值比率：本益比（P/E）、FCF yield、EV/EBITDA。理由：需要股價、容易被讀成「便宜／昂貴」，列為第二期候選。
4. 公司自訂口徑（adjusted FCF、non-GAAP 數字）：各家定義不同，不可互比（量化回應 2.2）。
5. 評分、排名、跨公司比較、同業比較、好壞配色、趨勢箭頭、自動生成的摘要句（創意企劃的 Rubin 減法）。
6. 全市場掃描、任意輸入代號查詢（範圍限定於持有或自選的標的）。
7. 董事會回購授權額度（非結構化公告；公告不等於已執行，資料調查 2.2）。第一版只展示現金流量表上的實際金額。
8. 台股月營收、庫藏股公告：列入台股版（見 FR-14），不在美股第一版。
9. 個股頁內嵌財務資訊、從決策卡連到財務頁的入口：第一版不做，避免被讀成決策依據。
10. 對外散布資料：沿用 B1 純自用前提；一旦對外提供，資料源條款須重審（資料調查，合規）。

## 功能需求（逐條編號）

### FR-1 頁籤與台美切換

- 新增獨立頁籤，台美共用同一骨架：三個區塊都出現，不因缺資料而隱藏區塊（創意企劃）。
- 市場可切換 TW／US。美股先上線。
- 台股尚未上線期間，使用者**不得看到「看起來可用、實際是空的」台股頁**。台股切換在此期間如何呈現（隱藏、停用、或帶說明）由 art-lead 與風控決定，需求只規定上述不得出現的狀態。字面待風控。
- 導覽列目前五項（總覽、排程台、庫存、回測、設定），加第六項會影響手機版版面，由 art-lead 處理。

### FR-2 標的範圍

- 只顯示「持有」的標的（庫存中的持倉）。系統沒有自選功能，自選的來源見 Q1（待 CEO）。
- 不提供任意輸入代號查詢（避免燒外部資料源額度，也避免擴大未驗證範圍）。
- 多檔標的的排列順序**不得以任何財務數值為鍵**（見 FR-9）。預設沿用庫存頁既有順序或代號順序，由 art-lead 與 tech-architect 對齊。

### FR-3 區塊 A：自由現金流

| 欄位 | 說明 |
|---|---|
| 營業活動現金流量（OCF） | 現金流量表原始揭露的值。 |
| 資本支出（CapEx） | 取購置不動產、廠房、設備的支付金額。標籤在公司間不一致（資料調查 2.1），對照規則由 data-engineer 與 quant-researcher 定。 |
| 自由現金流（FCF） | **依財報計算**：OCF 減 CapEx，標準化算法；不得冒充公司公布值。 |
| 近四季合計（TTM） | **依財報計算**。 |
| 近 4 季單季值（可展開至近 8 季） | **依財報計算**：現金流量表是年初至今累計值（YTD），單季值要自行相減，Q4 = 全年減前三季（資料調查 2.1）。 |

- 口徑說明（FCF 是 OCF 減 CapEx、並非會計準則科目、公司自己公布的 FCF 口徑可能不同）需要讓使用者查得到。呈現位置與字面待風控。
- 負值就如實顯示負值；數字上色不得暗示優劣。
- **缺值規則**：OCF 或 CapEx 任一缺，FCF 就是缺值，**不得以 OCF 代替、不得把缺的 CapEx 當 0、不得內插補值**。

### FR-4 區塊 B：股利與回購

| 欄位 | 說明 |
|---|---|
| 現金股利支付金額 | 現金流量表的實際支付金額，**公司公布**。 |
| 股票回購支付金額 | 現金流量表的實際支付金額，**公司公布**。台股對應「庫藏股票買回」，稱呼用台灣用語。 |
| 兩者合計 | **依財報計算**。 |
| 期間 | 與 FR-3 同樣的單季、TTM 呈現與標示規則。 |

- 只展示實際已支付的金額。**授權額度與實際買回要分開**，第一版不放授權額度（範圍外 7）。
- **不顯示「合計佔 FCF 比例」**（建議值，待 CEO，見 Q4）。理由：FCF 為負或接近 0 時比例無意義；回購可能來自舉債，比例容易被讀成「FCF 夠不夠支撐回購」，這正是資料調查點名的建議性質句型。
- 回購與股利若 XBRL 沒有該項目，**缺的不等於 0**，走 FR-8 的缺值分類。

### FR-5 區塊 C：財報摘要

| 欄位 | 性質 |
|---|---|
| 營收 | 公司公布（損益表） |
| 淨利（GAAP） | 公司公布 |
| 稀釋後每股盈餘（GAAP） | 公司公布 |
| 最近一次財報的公布日 | 申報日（見 FR-6） |

- 只放 GAAP。不放 non-GAAP 或公司調整後數字（範圍外 4）。
- 命名提醒（給 tech-architect）：程式碼中 `EPS` 已被用作數學 epsilon 常數（`dirdef/definition.py:8`、`forecast/band.py:6-8`），每股盈餘的欄位命名必須避開（量化回應 2.4）。
- **下次財報日**：第一版不列為必要欄位。美股沒有免費官方結構化來源；若 spike 查得到可靠來源，再於 Q3 評估。查不到就不放，不放「推估日期」。
- 毛利率、營業利益率、SBC 等候選欄位見 Q3，待 CEO。

### FR-6 每個數字都帶的屬性（出處屬性）

每個顯示的數字（包含依財報計算的數字）都必須能對應到下列屬性，**畫面上能不能全部同時可見，由 art-lead 決定（密度取捨），但使用者隨時可查到**：

| 屬性 | 要求 |
|---|---|
| 期間 | 會計期間起迄，並標明是「單季」「累計（YTD）」「TTM」或「全年」。季度標籤依公司自己的會計年度，不套曆年（美股很多公司非曆年制）。 |
| 公布日 | 該數字所來自申報文件的申報日（美股為 SEC 申報日 filed）。見下方「公布日定義」。 |
| 來源 | 資料來源名稱與可回查的識別（如申報文件編號、標籤名稱）。 |
| 性質 | 「公司公布」或「依財報計算」，二選一，視覺上要清楚區分（創意企劃、art-lead brief）。 |
| 幣別與單位 | 美股 USD；台股 TWD；單位（元、千元、百萬元）明寫。沿用現有幣別與市場對應（`shared/market-currency.json`），不另創。 |
| 取得時間 | 系統取得該筆資料的時間（as_of）。 |
| 是否原始公布值 | 該值是否與首次公布值相同；若後續申報重編，需可辨識（量化回應 2.6）。 |

**公布日定義與已知落差（需 data-engineer、quant-researcher 在 spike 後確認）**：
- 同一期間的數字會出現在多份申報中（後續申報的比較期欄位）。「公布日」要明確規則：顯示的是「首次公布」還是「該顯示值所屬的申報」。建議兩者都留存，顯示該值所屬申報的申報日（見 Q8）。
- 美股財報新聞稿（8-K 附件）通常早於 10-Q／10-K，實際「最早可得時點」可能早於 EDGAR 結構化資料的申報日（量化回應 2.3）。第一版以結構化資料上的申報日為「公布日」，並在需求層面記下這個落差，不宣稱它等於市場最早得知時點。是否要補新聞稿時間，列為第二期評估。

### FR-7 「公司公布」與「依財報計算」的標示

- **公司公布**：原樣取自申報文件的揭露值（如 OCF、現金股利支付、回購支付、營收、淨利、稀釋 EPS）。
- **依財報計算**：由系統從揭露值運算而得（FCF、TTM、單季值、股利與回購合計）。
- 現金流量表原始揭露為累計值；因此「單季」的現金流數字皆屬「依財報計算」，即使其組成項是公司公布。畫面標示以「使用者看到的那個數字」為準。
- 兩者的區分規則與標籤字面待風控（創意企劃第 4 類文案：「公司自己說的」的聲明）。

### FR-8 缺值分類（空狀態的兩種句型）

兩種句型的**用途**（字面全部待風控，PM 不擬）：

| 分類（內部名稱） | 用途 | 使用者要得到的理解 |
|---|---|---|
| 公司未提供 | 告知「來源有，但這家公司的申報文件沒有此項」 | 這是公司的事實，不是系統壞了 |
| 資料來源暫無 | 告知「我們沒抓到或來源目前沒有」 | 這是我們的問題，不代表公司沒有 |

**判定規則（需求，供 data-engineer 與 tech-architect 實作時遵守）**：
1. 只有同時滿足下列三點，才能判為「公司未提供」：(a) 該期申報已成功取得；(b) 我們對該項目的標籤／欄位已有對照規則；(c) 申報內確定沒有此項。
2. 任何無法確認者，一律判為「資料來源暫無」。**寧可說我們沒抓到，也不要誤說公司沒有**（創意企劃要求兩者不可混用）。
3. 取得失敗（網路、限流、來源改版）、對照規則缺漏、尚未輪到抓取，都屬「資料來源暫無」。
4. 缺值不得顯示為 0，也不得留空白。
5. 取得失敗時，**保留上一次成功取得的資料並照原樣顯示其取得時間**，不得以空白取代。
6. 句型後面不得附解讀（例如「這很常見」）。創意企劃已指出這類句子本身是解讀，需風控決定，預設不加。

**第三種情況：不適用**（建議，待 CEO，見 Q2）：
- 金融業（銀行、保險）的現金流結構不同，FCF 對它們沒有意義（資料調查 2.1）。
- ETF（包含庫存內的槓桿 ETF）沒有公司財報。
- 這兩者既不是「公司沒提供」也不是「我們沒抓到」。若只有兩種句型，會被迫歸入其一而誤導。PM 建議新增第三種「不適用於此標的類型」；是否新增是產品決策，待 CEO。

**標的類型判斷**：怎麼判定標的是金融業或 ETF，資料從哪來，交 data-engineer 與 tech-architect 評估；判不出來就走「資料來源暫無」。

### FR-9 不評價、不排序、不進訊號、不進模型（行為邊界）

- 財務資料**不得**被 `signals`、`advice`、`alerts`、`forecast`、`outlook`、排程台、決策卡、建議卡讀取。`advice/context.py:34-58` 的封閉欄位表不新增任何財報欄位。
- 頁面不提供以財務數值排序、篩選的互動，預設順序也不得以財務數值為鍵。
- 不得有買賣類、估值類、預測保證類、評價形容詞類措辭（避開清單見創意企劃「要避開的坑」；最終以風控為準）。
- 不使用紅綠等好壞色語意；數字上色不得暗示優劣（與風控確認，現有中性色規則優先）。
- 不放趨勢箭頭、上升下降的文字標籤。多期數字並列是允許的，但並列本身不加解讀。
- 第一版不放自動生成的摘要句，只放數字。

### FR-10 揭露：基本面資訊未納入操作參考規則

- **用途**：讓使用者明確知道這頁的數字**沒有進入**決策卡、建議卡、警示、排序，避免以為卡片結論有參考財報（量化回應 2.4 (a)）。
- 內容主旨（用途，字面待風控）：基本面資訊未納入操作參考規則。
- 位置與常駐程度：須在頁面上常駐可見，不得只放在摺疊區。具體位置由 art-lead 排版、風控核可。
- **不得修改**既有「規則與價位未經歷史驗證」等固定揭露（`advice/engine.py:64-70`、`alerts/notify.py:65-68`）。這些字面是逐字定稿、前後端有一致性測試，一改就要重送風控；本需求的前提就是它們維持成立。
- 日後若基本面進入篩選／排序／模型（用途 (b)(c)），本揭露須重審，且既有固定揭露須補句。這不在本包。

### FR-11 資料新鮮度與快取原則

財報只在公司公布時才變動，不需要每次開頁面就去抓。需求層面的原則（實作方式由 tech-architect 與 data-engineer 定）：

1. **開啟頁面不得觸發對外部資料源的請求**。頁面只讀本機已取得的資料。
2. 外部資料的更新由背景流程負責，依「新公布」事件導向，加上低頻檢查；檢查頻率不得超過資料源公平使用限制。美股 SEC 要求帶可聯絡的 User-Agent、約 10 req/s 上限（大致確定，需查證現行數字）；聯絡資訊走環境變數，不寫進檔案。
3. 檢查範圍僅限持有（或自選）標的，檢查的目標是「有沒有新公布」，沒有新公布就不重抓全量。
4. 每個區塊（或每檔標的）顯示「資料取得時間」與「最近一次財報公布日」。兩者含義不同，不得混用。
5. 取得失敗不清空既有資料（見 FR-8 第 5 點）。
6. **逾期未更新的標示**：美股 10-Q 在季末後 40 或 45 天內、10-K 在年度結束後 60、75 或 90 天內須申報（確定）。當系統判斷已逾預期申報期限仍未取得新資料時，須有「資料可能不是最新」的狀態。判斷門檻與字面待 tech-architect、quant-researcher、風控。台股對應期限見 FR-14。
7. 快取過期不得連帶刪除快照（快取與快照是兩件事，見 FR-12）。
8. 在 Alpha Vantage 每日額度（約 25 次）不夠用的前提下，本頁**不得消耗 Alpha Vantage 額度**；第一版不顯示股價，也就不需要價格請求。

### FR-12 公布日快照留存

- 從第一天起，每次取得財報數字，依公布日留存快照。
- 留存為**只新增不覆蓋**（append-only）：同一期間、同一項目被後續申報重編時，**新增一筆**，保留首次公布的原值。
- 每筆至少記：標的、項目、會計期間、數值、幣別單位、申報日（公布日）、來源識別、取得時間。
- 每筆須標記取得方式：**即時留存**（在公布後由系統自己抓到）或**回補**（事後從資料源的歷史資料補入）。兩者的證據強度不同，日後做驗證時必須分得開。回補資料能否視為 point-in-time，由 quant-researcher 判斷（見 Q9）。
- 已下市或已從持倉移除的標的，既有快照**不刪除**（存活者偏誤，量化回應 2.3）。
- 快照屬資料基礎，**不在畫面上額外開出入口**；第一版只要求留存，不要求使用者可瀏覽歷史快照。
- 快照所在的資料庫與備份政策由 tech-architect 與 devops-sre 決定；本 PRD 不碰 `data/*.db`。

### FR-13 資料源狀態揭露

- 本頁美股資料源為 SEC EDGAR，**與既有價格鏈（Alpha Vantage／yfinance，標示「資料來源未經真實環境驗證」）是不同的來源**。
- 使用者需要看得到本頁資料源目前的驗證狀態（已實測日期，或未實測）。狀態來自 spike 結果與設定頁資料源狀態，兩邊不得互相矛盾。字面與位置待風控（創意企劃第 5 類文案）。
- spike 未完成前，美股資料源視同未實測，須如實揭露。

### FR-14 台股版（第二階段；資料源查證後補上）

骨架不變，下列為台股版與美股版的差異需求。**每一項都以 spike 結果為前提，spike 前不得開工，也不得視為已確定可得。**

| 項目 | 台股 | 美股 | 影響 |
|---|---|---|---|
| 月營收 | 台股特有，次月 10 日前申報（確定）。納入台股版，作為額外欄位。 | 無法定月營收 | 骨架需容許市場特有欄位；美股版此欄位不出現，而不是顯示缺值 |
| 回購稱呼 | 庫藏股 | 回購 | 用台灣用語 |
| 財報申報期限 | 年報 3 個月內；Q1～Q3 每季結束後 45 日內（確定）；金融業期限不同（需查證）；近年大型公司提前公布規定（需查證） | 10-Q 40／45 天；10-K 60／75／90 天（確定） | 影響 FR-11 逾期判斷 |
| 現金流量表 | IFRS 允許利息收支放營業或籌資（IAS 7，確定），公司間 CFO 口徑不一定一致 | US GAAP | 台股 OCF 需有口徑提醒（用途，字面待風控） |

| 資料源 | MOPS、TWSE OpenAPI、FinMind（免費層，額度未查證） | SEC EDGAR | 由 spike 決定 |
| 單位 | TWD，財報常以千元為單位 | USD | 單位明寫 |
| 財測 | 非強制 | 自願 | 兩邊第一版都不放（範圍外 1） |
| 口語展望 | 法說會口頭展望 | 電話會議 | 不轉成數字；若日後放，只能標「法說會提及（非正式財測）」之類的非數字標示，字面待風控 |

## 驗收條件（每條需求至少一組 Given/When/Then）

> 驗收條件在 PRD 定稿後不得為了讓實作過關而放寬。要改須明寫變更紀錄並通知全部下游。
> 驗收所需的真實資料以 spike 取得的樣本為準；沒有 spike 結果前，AC 的資料面項目（AC-3、4、5、14）無法執行，這是依賴，不是放寬。

**AC-1（FR-1）台美切換與同骨架**
- Given 美股已上線、台股尚未上線；
- When 使用者開啟財務頁籤並切換市場；
- Then 美股視圖顯示三個區塊；
- And 台股視圖不會呈現成「三個區塊全空、看似壞掉」的頁面（呈現方式依 art-lead 與風控定案）；
- And 骨架在台股上線時不需要重做（同一組區塊，缺項保留區塊位置）。

**AC-2（FR-2）標的範圍**
- Given 庫存中有 3 檔美股、另有未持有的美股代號；
- When 使用者開啟財務頁籤的美股視圖；
- Then 只列出這 3 檔，沒有輸入任意代號的欄位；
- And 庫存沒有任何美股時，顯示「沒有標的」這個狀態（字面待風控），不是空白頁。

**AC-3（FR-3）FCF 計算**
- Given 某標的某季 OCF 與 CapEx 都有值；
- When 查看自由現金流區塊；
- Then FCF = OCF − CapEx；
- And 標示為「依財報計算」；
- And 近四季合計等於最近四個單季 FCF 之和；
- And 單季值由累計值相減得出（Q4 = 全年減前三季），並與申報文件逐筆核對一致。

**AC-4（FR-3）CapEx 缺漏不補值**
- Given 某標的 OCF 有值、CapEx 查無對應標籤；
- When 查看該季 FCF；
- Then FCF 顯示為缺值分類（走 FR-8），**不是**等於 OCF，也不是 0；
- And CapEx 本身顯示缺值分類。

**AC-5（FR-4）股利與回購**
- Given 某標的現金流量表有股利支付與回購支付；
- When 查看股利與回購區塊；
- Then 兩項各自顯示實際支付金額，標示為「公司公布」；
- And 合計標示為「依財報計算」；
- And 畫面沒有授權額度，也沒有「合計佔 FCF 比例」（若 Q4 CEO 裁示要放，則依裁示更新本條並通知全部下游）。

**AC-6（FR-4、FR-8）缺不等於 0**
- Given 某標的某期現金流量表沒有回購項目；
- When 查看該期回購；
- Then 顯示缺值分類，**不顯示 0**；
- And 合計欄在其中一項缺值時，也走缺值分類，不以另一項單獨值冒充合計。

**AC-7（FR-5）財報摘要**
- Given 某標的最近一季財報已取得；
- When 查看財報摘要區塊；
- Then 顯示營收、GAAP 淨利、GAAP 稀釋後每股盈餘；
- And 顯示最近一次財報的公布日；
- And 畫面上沒有 non-GAAP 數字，也沒有下次財報日（除非 Q3 裁示變更）。

**AC-8（FR-6、FR-7）出處屬性**
- Given 畫面上任一顯示的財務數字（含依財報計算者）；
- When 使用者查看該數字的出處；
- Then 可查到：期間（含單季／累計／TTM／全年）、公布日、來源識別、性質（公司公布／依財報計算）、幣別與單位、取得時間、是否原始公布值；
- And 「公司公布」與「依財報計算」在視覺上可區分（非僅靠文字小字）。

**AC-9（FR-6）會計年度**
- Given 某標的會計年度非曆年制；
- When 查看季度標籤；
- Then 季度依公司自己的會計年度標示，不被錯置為曆年季度；
- And 期間起迄日期可查。

**AC-10（FR-8）兩種缺值句型的使用**
- Given 某期申報已成功取得、標籤對照已建立，且申報內確定沒有此項；
- When 查看該項目；
- Then 使用「公司未提供」類的缺值句型。
- Given 取得失敗、對照規則缺漏、或無法確認申報內有無此項；
- When 查看該項目；
- Then 使用「資料來源暫無」類的缺值句型，**不得**使用「公司未提供」。
- And 兩種句型在字面與外觀上明確不同；
- And 句型字面均為風控定稿版本，且不附解讀句。

**AC-11（FR-8）取得失敗保留舊值**
- Given 某標的已有一次成功取得的資料，之後一次更新失敗；
- When 使用者開啟頁面；
- Then 仍顯示上一次成功的資料與其取得時間；
- And 另外有明確的狀態表示最近一次更新失敗（字面待風控）；
- And 數字沒有被空白或 0 取代。

**AC-12（FR-12）快照 append-only**
- Given 某標的某期財報已留存一筆快照；
- When 後續申報對同一期間同一項目給出不同數值（重編）；
- Then 新增一筆快照，舊筆**原值不變**；
- And 每筆快照含標的、項目、期間、數值、幣別單位、申報日、來源識別、取得時間、取得方式（即時留存／回補）；
- And 任何程式路徑都沒有更新或刪除既有快照的操作。

**AC-13（FR-12）下市與移除持倉不刪快照**
- Given 某標的已從庫存移除（或已下市）；
- When 檢查快照；
- Then 該標的既有快照仍在；
- And 該標的不再出現在財務頁的標的清單（FR-2）。

**AC-14（FR-3～FR-5）數字正確性抽樣**
- Given spike 取得至少 3 檔美股（含一檔會計年度非曆年者、一檔有回購、一檔無回購或無股利）的樣本；
- When 將頁面數字與官方申報文件逐項人工比對（OCF、CapEx、FCF、股利、回購、營收、淨利、稀釋 EPS 各至少一期）；
- Then 全部一致（單位換算後）；
- And 不一致項目須回報 data-engineer，不得由前端或 PM 調整驗收門檻讓它通過。

**AC-15（FR-9）不評價、不排序**
- Given 庫存中有多檔標的、各檔 FCF 高低不同；
- When 使用者檢視清單；
- Then 預設順序不依任何財務數值；
- And 沒有以財務數值排序或篩選的互動；
- And 畫面上沒有任何評分、排名、跨公司比較、趨勢箭頭、好壞色語意。

**AC-16（FR-9）不進訊號與模型（程式邊界）**
- Given 財務資料已進入本機儲存；
- When 檢查 `signals`、`advice`、`alerts`、`forecast`、`outlook`、排程台的資料輸入；
- Then 沒有任何一個讀取財務資料；
- And `advice/context.py` 的封閉欄位表沒有新增財報欄位；
- And 以測試鎖住（例如欄位表快照測試），避免日後被悄悄接線。

**AC-17（FR-9）措辭**
- Given 頁面上所有使用者可見字面；
- When 逐一比對風控核可清單；
- Then 每一句都是風控逐字核可的版本（或純數字、單位、日期）；
- And 不含買賣類、估值類、預測保證類、評價形容詞類措辭。

**AC-18（FR-10）未納入操作參考規則的揭露**
- Given 使用者開啟財務頁；
- When 頁面載入完成；
- Then 揭露句常駐可見，不需展開任何摺疊區；
- And 其字面為風控核可版本。
- Given 檢查既有決策卡、建議卡、警示的固定揭露字面；
- When 比對本包上線前後；
- Then 完全沒有被修改，既有一致性測試維持綠燈。

**AC-19（FR-11）開頁不打外部**
- Given 外部資料源完全不可用（例如網路中斷）；
- When 使用者開啟財務頁；
- Then 頁面照常渲染本機已有的資料，不等待、不逾時；
- And 測試能證明開頁流程沒有對 SEC 或其他外部資料源發出請求。

**AC-20（FR-11）新鮮度標示**
- Given 某標的資料已取得；
- When 查看該標的；
- Then 同時看得到「資料取得時間」與「最近一次財報公布日」，兩者可區分。
- Given 某標的已逾預期申報期限仍未取得新資料；
- When 查看該標的；
- Then 有「資料可能不是最新」的狀態（字面待風控）。

**AC-21（FR-11）額度與金鑰**
- Given 財務資料更新流程執行；
- When 檢查資源消耗與設定；
- Then 不消耗 Alpha Vantage 每日額度；
- And SEC 聯絡用 User-Agent 來自環境變數，檔案與 commit 中沒有任何祕密或個人聯絡資訊。

**AC-22（FR-13）資料源狀態一致**
- Given spike 已完成並有結果；
- When 比對財務頁的資料源狀態與設定頁資料源狀態；
- Then 兩處對 EDGAR 的實測狀態一致；
- And spike 未完成時，如實呈現為未實測。

**AC-23（FR-8，條件式，若 Q2 裁示新增第三種）不適用**
- Given 標的為金融業或 ETF；
- When 查看 FCF 區塊；
- Then 使用「不適用」類句型，而不是「公司未提供」或「資料來源暫無」；
- And 判不出標的類型時，走「資料來源暫無」。

**AC-24（FR-14，台股版，spike 後）月營收與期限**
- Given 台股資料源已查證、台股版上線；
- When 切到台股視圖；
- Then 三個區塊與美股同骨架，月營收作為台股特有欄位出現，美股視圖不出現該欄位；
- And 幣別為 TWD、單位明寫；
- And 若公布日為保守假設（非實際公布日），須標示。

### spike 需回答的問題（給 data-engineer 設計指令時對照）

1. EDGAR companyfacts：以幾檔代表性美股（含一檔非曆年會計年度、一檔有回購、一檔無回購或無股利、一檔金融股、一檔 ETF），確認 OCF、CapEx、股利支付、回購支付、營收、淨利、稀釋 EPS 的標籤、單位、回應格式。
2. 每個數字是否帶申報日（filed）與所屬申報文件識別；同一期間在多份申報中重複出現時，如何判斷首次公布與重編。
3. CapEx 標籤在樣本中的不一致情形與缺漏率。
4. ticker 對應 CIK 的來源與路徑。
5. 請求限制與 User-Agent 要求的現行數字。
6. 歷史資料可回溯多久；回補資料的申報日是否為真實申報日。
7. 台股：TWSE OpenAPI、FinMind、MOPS 是否有現金流量表、庫藏股買回、月營收的資料集；欄位、公布時間、免費額度。
8. 免費來源是否有可靠的下次財報日。（決定 D-14 去留）
