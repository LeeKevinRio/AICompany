## 背景與目標

CEO 是單人旅客，多半利用週末出遊。目前彈性窗監看與探索都會把每一天當出發日：彈性窗每輪只取樣 12 組輪轉，日期組一多，週末組合被抽到的機率低；探索一次只能看一個月，且每個出發日都耗 1 次額度。使用者真正想看的只有「週五或週六出發」。

目標：
1. 彈性窗監看與探索新增「出發星期」篩選，只展開、只查符合星期的出發日，減少無用查詢，提高週末組合的覆蓋。
2. 探索可選連續多個月（起始月～結束月），一次看跨月的最低價日期；總格數仍有上限，保護額度。
3. 星期篩選在 Telegram、列表、詳情、摘要的條件描述中可見，使用者看得出條件。
4. 收掉三項前批遺留小缺口（FD-9 已知缺口與風控 suggested）。

成功指標（以可驗證行為為準）：
- 星期全選時，所有輸出（展開組合、查詢、文案、`condition_key`、API）與 FD-9 完成時完全相同。
- 只選週五時，彈性窗展開的組合數等於區間內符合的週五出發日數乘上旅程天數範圍數，不多不少。
- 探索選 3 個月＋週五、週六，格數只含符合星期的日子且 ≤31；超過則 422。
- 三項收尾符合驗收條件，其餘既有文案與測試期望值逐字不變。

產品前提（沿用）：價格為查到當下的參考值，實際以訂票網站為準；星期篩選是使用者自選的過濾條件，不是系統推薦哪天出發。**人數固定 1 位成人**（CEO 2026-10-29 指示單人優先）。

## 使用者與情境

- 使用者：CEO 本人，單一使用者，本機，桌機與手機瀏覽器皆會用。
- 情境 A：監看台北到東京，12 月到 2 月任意出發、玩 3～5 天，只想看週五或週六出發的組合。
- 情境 B：探索台北到大阪，只看週五、週六出發，一次看 12、1、2 月，找最便宜的那天。
- 情境 C：探索日曆中未選星期的日子，使用者要看得出是「刻意沒查」，不是沒資料。
- 情境 D：Telegram 發 `/watch` 看到監看條件含「週五、週六出發」，能確認設定正確。
- 情境 E：比價進行中，在 Telegram 發 `/status` 或 `/scan`，看到掃描為何沒動。
- 情境 F：既有監看（未設星期）完全不受影響，行為與價格基準不變。

## 功能需求（逐條編號）

### 一、出發星期篩選（FR-D）

- FR-D1 概念：「出發星期」為週一～週日的多選，預設全選，全選等同不篩選。至少須選 1 個；全部取消回 422（欄位旁顯示「請至少選一個出發星期」）。星期以 Asia/Taipei 日曆日的星期判定（與既有日期口徑一致）。
- FR-D2 監看（彈性窗）：新增表單與編輯表單皆提供「出發星期」。`expand_pairs` 只保留出發日落在所選星期的日期組，回程不篩；旅程天數範圍沿用既有邏輯。固定日期模式不適用：選固定日期時 UI 隱藏該欄位，後端忽略並視同全選。
- FR-D3 取樣：每輪取樣 12 組輪轉（`sample_pairs`）作用在篩選後的集合上；全選時取樣結果與現況逐字相同。篩選後組數 ≤12 時應能一輪涵蓋全部組合（既有行為，不新增保證）。
- FR-D4 空集合：彈性窗區間內沒有任何符合星期的出發日（例如區間只有 3 天且星期都不在內）→ 建立或修改時回 422 並說明「所選日期區間內沒有符合出發星期的日子」，不建立或不儲存。
- FR-D5 條件 revision：星期篩選改變視為條件變更，沿用既有規則換 revision、重置漲跌基準（預設，見開放問題 CEO-1 與 tech-architect-1）。星期從無到全選、或全選到全選視為未改變，不換 revision。既有監看遷移後視同全選，不換 revision、不重置基準。
- FR-D6 探索：探索表單新增「出發星期」多選，預設全選。`month_pairs` 只對符合星期的出發日產生格子；不符合的日子不查、不耗額度。選擇後預覽的「預計查詢次數」即時反映篩選後格數。
- FR-D7 探索日曆：日曆仍顯示整月（跨月時各月分段）；未選星期的日子顯示「未查（星期篩選）」，不是空白也不是無資料；既有狀態（無資料、被擋、未查詢等）文案逐字不變。
- FR-D8 條件摘要：Telegram `/watch`、監看列表、詳情頁、每日摘要、探索結果頁條件摘要，在非全選時顯示星期篩選，格式「週五、週六出發」（依週一至週日順序，頓號分隔）；全選時不顯示任何星期字樣。若所選為連續或特定組合，不另行縮寫（不做「週末」等語意詞，避免與節假日定義混淆）。
- FR-D9 其他：比價（FD-9）、固定日期監看、探索以外的流程不受影響，不顯示星期篩選。

### 二、探索跨多月（FR-M）

- FR-M1 月份範圍：探索表單由單一「月份」改為「起始月份」與「結束月份」，結束預設等於起始（即單月，行為與現況相同）。連續最多 N 個月（N 由 tech-architect 定，預設 3）；結束早於起始、超過 N 個月、或任一月份超出可查日期範圍皆 422。
- FR-M2 日期範圍：每個月內的出發日仍受既有規則限制（不早於今天、不超過今天起 365 天）；起始月為本月時，今天以前的日子不產生格子（沿用現況）。
- FR-M3 格數上限：篩選星期後、各月合計的總格數必須 ≤31（沿用既有上限）。超過 → 422，提示「請縮小月份範圍或減少星期」。預覽顯示格數，超過時按鈕停用並顯示同一提示，後端驗證不得由前端取代。
- FR-M4 額度：沿用探索額度規則（保留 12、可用額度 < 格數整體拒絕 409、同時間僅一個探索或比價）；格數即查詢次數。
- FR-M5 日曆：依月份分段顯示（每月一段、有月份標題）；每格狀態與價格呈現沿用既有；跨月時圖例與免責句仍只出現一次且常駐。
- FR-M6 最便宜前 5：跨所有月份合併排序，同價依出發日早者在前（沿用既有並列規則；若與現況不同以現況為準）；每列顯示完整日期含月份。
- FR-M7 重用：`condition_key` 升為 v2，納入「出發星期集合（正規化後，與選取順序無關）」與「起始月份、結束月份」；全選與未提供星期正規化為同一值。24 小時內 v2 條件相同才重用；v1 與 v2 永不互相重用（即使單月、全選看似同條件）。舊 v1 紀錄照舊可讀、可由歷史清單與網址開啟，不遷移改寫。
- FR-M8 歷史清單與結果標題：列出月份範圍（單月顯示「2026-12」，跨月顯示「2026-12～2027-02」）與星期篩選（非全選時）。
- FR-M9 預填監看：沿用 FD-6 FR-W 從日曆格預填；本批不從探索帶入星期篩選到監看（出發日已是固定日期）。

### 三、Telegram 與其他入口

- FR-T1 Telegram `/watch` 清單回覆含星期篩選描述（FR-D8）。
- FR-T2 Telegram 不新增建立、修改星期的指令（範圍外）；`/explore` 若現有 Telegram 指令存在，不新增星期參數，行為不變。

### 四、三項小收尾（FR-F）

- FR-F1 `/status` 與 `/scan`：比價進行中時，回覆需提到「比價進行中，掃描順延」（FD-9 已知缺口）。無比價進行時文案逐字不變；探索進行中的既有提示不變。
- FR-F2 健康頁「資料維護」各表筆數新增 `comparison` 與 `comparison_cell` 兩列，排序與格式沿用現有列。
- FR-F3 `exploration.html` 內寫死的 stale 備援字串移入 `domain/messages.py`（風控 suggested），頁面輸出逐字不變；不得因此新增或改動任何使用者可見文案。

## 驗收條件（每條需求至少一組 Given/When/Then）

測試通則：自動化測試使用假資料源與假時鐘，不連外網。

### 一、出發星期篩選

- AC-D1 Given 彈性窗監看表單；When 不動預設；Then 七個星期皆勾選，等同不篩選；Given 取消全部星期後送出；Then 422「請至少選一個出發星期」，不建立。
- AC-D2 Given 彈性窗 2026-12-01（週二）～2026-12-31、旅程天數 3～5、星期全選；When `expand_pairs`；Then 結果與 FD-9 完成時逐字相同（組數與每一組內容）。
- AC-D3 Given 同一區間、只選週五；When `expand_pairs`；Then 出發日皆為週五（12/4、11、18、25 共 4 個），每個出發日乘上 3 種旅程天數＝12 組，回程日不篩（可落任何星期）。
- AC-D4 Given 只選週五、週六；Then 出發日為 8 個、組數為 8×3＝24；Given 區間含單日邊界（`window_start` 即週五）；Then 該日被包含。
- AC-D5 Given 區間 12/1（週二）～12/3（週四）、只選週六；When 建立監看；Then 422「所選日期區間內沒有符合出發星期的日子」。
- AC-D6 Given 固定日期模式；When 檢視表單；Then 出發星期欄位隱藏；When 後端收到星期參數；Then 忽略並視同全選。
- AC-D7 Given 既有監看已有價格基準；When 將星期從全選改為只選週五；Then 條件 revision 換新、漲跌基準重置；When 修改其他不影響條件的欄位（如名稱）；Then revision 不變；When 星期改選後又改回全選；Then 視為又一次條件變更（以最終值與目前值是否相同判定，同值不換）。
- AC-D8 Given 遷移後既有監看；When 檢視；Then 星期視同全選、revision 與基準不變、條件摘要不出現星期字樣。
- AC-D9 Given 探索表單、星期選週五與週六、單月 2026-12；When 預覽；Then 預計查詢次數等於該月（今天之後）週五與週六的天數，且日曆上其餘日子顯示「未查（星期篩選）」。
- AC-D10 Given 探索完成；When 檢視日曆；Then 符合星期的日子顯示價格或既有狀態、未選星期的日子顯示「未查（星期篩選）」，不是空白、不是「無資料」，且文字呈現非僅靠顏色。
- AC-D11 Given 探索星期全選；When 檢視日曆與預覽；Then 輸出與 FD-9 完成時相同（無「未查（星期篩選）」字樣）。
- AC-D12 Given 監看含星期週五、週六；When `/watch`、列表、詳情、每日摘要；Then 條件摘要含「週五、週六出發」；Given 星期全選；Then 皆不顯示星期字樣，文案逐字與現況相同。
- AC-D13 Given 星期選週一、週三、週日；Then 摘要依週一至週日順序顯示「週一、週三、週日出發」，與勾選順序無關。
- AC-D14 Given 比價頁與固定日期監看；When 檢視；Then 無星期篩選欄位與字樣。
- AC-D15 Given 彈性窗只選週五、篩選後組數為 12 以下；When 排程掃描一輪；Then 取樣範圍僅在篩選後集合，所有取樣日期的出發日皆為週五；Given 篩選後組數超過 12；Then 輪轉在篩選後集合上循環，全數組合在有限輪次內皆被取樣。

### 二、探索跨多月

- AC-M1 Given 探索表單；When 不動預設；Then 起始與結束月份相同（單月），行為與現況相同。
- AC-M2 Given 起始 2026-12、結束 2027-02、星期週五與週六；When 預覽；Then 格數為三個月內符合星期的日子總數（假定 ≤31），預覽與日曆段落一致。
- AC-M3 Given 起始 2026-12、結束 2027-02、星期全選（約 90 格）；When 提交；Then 422「請縮小月份範圍或減少星期」，不建立探索、不耗額度；Given 單月全選 31 天；Then 允許（31 為邊界）；Given 合計 32 格；Then 422。
- AC-M4 Given 結束月份早於起始、或超過 N 個月（預設 3，即跨 4 個月）；When 提交；Then 422，欄位旁顯示明確訊息。
- AC-M5 Given 起始月為本月；When 展開；Then 今天以前的日子不產生格子，今天含在內（若符合星期）。
- AC-M6 Given 跨月探索完成；When 檢視；Then 日曆依月份分段並有月份標題，免責句與圖例只出現一次。
- AC-M7 Given 跨月結果；When 檢視最便宜前 5；Then 跨所有月份合併排序，同價日期早者在前，每列顯示含月份的完整日期。
- AC-M8 Given 一筆 v1 探索紀錄（舊資料）；When 以相同航線、單月、全選條件再按開始；Then 不重用 v1、視為新探索（走額度規則）；Given v2 紀錄 3 小時前完成且條件相同；Then 直接重用、對外查詢 0 次。
- AC-M9 Given 同條件但星期勾選順序不同；Then `condition_key` 相同、可重用；Given 星期集合或月份範圍任一不同；Then 不重用。
- AC-M10 Given 既有 v1 探索歷史；When 開啟舊結果網址；Then 照舊可讀，頁面不出現星期或月份範圍字樣。
- AC-M11 Given 7 天保留；When 清除作業執行；Then v1 與 v2 紀錄一視同仁依 `created_at` 清除，不影響監看與價格歷史。
- AC-M12 Given 可用額度小於格數；When 開始；Then 409 quota、對外查詢 0 次、不建立探索（沿用）。
- AC-M13 Given 歷史清單；When 檢視；Then 單月顯示「2026-12」、跨月顯示「2026-12～2027-02」，非全選時顯示星期篩選。

### 三、Telegram 與其他入口

- AC-T1 Given 兩個監看（一個有星期篩選、一個全選）；When `/watch`；Then 前者摘要含星期描述、後者逐字不變。
- AC-T2 Given 任一 Telegram 指令；When 檢視全部指令；Then 沒有新增建立或修改星期的指令。

### 四、三項小收尾

- AC-F1 Given 比價進行中；When Telegram `/status`；Then 回覆含「比價進行中，掃描順延」；When `/scan`；Then 同樣提到，且不重複觸發掃描；Given 無比價與探索進行；Then 兩者回覆逐字與現況相同；Given 探索進行中；Then 既有提示不變。
- AC-F2 Given 健康頁；When 檢視資料維護；Then 列出 `comparison` 與 `comparison_cell` 筆數，其他表筆數與格式不變。
- AC-F3 Given `exploration.html` 渲染結果；When 與本批前逐字比對；Then 備援字串輸出完全一致，且原始樣板不再含該寫死字串，文字來源為 `domain/messages.py`。
- AC-F4 Given 全部既有測試；When 執行；Then 除與本批直接相關的期望值（`condition_key` 版本、探索月份欄位／表單欄位、`/status`／`/scan` 比價進行中文案、健康頁筆數列、`expand_pairs` 星期參數預設）外不得修改既有期望值，且既有 1166 項測試其餘全數通過。每一處修改的期望值須在任務單逐條列出。

### 風控與文案

- AC-R1 Given 本批新增使用者文案（「未查（星期篩選）」、星期摘要、422 訊息、「比價進行中，掃描順延」、探索月份範圍文案）；When 檢查；Then 無 ADR C-17 禁用字、無建議或推薦語氣（不得出現「週末最便宜」「建議週五」之類）。**須送 risk-compliance-officer 審查，通過才可進 done。**

## 風險與依賴

- 資料遷移風險（中）：探索表的 `condition_key` 有 `v1|*` CHECK、`month` 欄位為單月；v2 與月份範圍需 migration 0008，若需重建表（SQLite 重建）須保證舊 v1 紀錄、索引與外鍵完整；需 `pre-v8` 備份。見 tech-architect 開放問題。
- 條件 revision 行為（中）：星期改變是否重置基準影響通知邏輯（漲跌比較），需與既有 revision 規則一致；誤判會造成假警報或漏警報。
- 覆蓋率認知風險（低）：只選週五時組數少，12 組取樣一輪可涵蓋，但使用者可能誤以為「週末全看過」；日曆「未查（星期篩選）」與摘要文案須說明是依自選條件。
- 額度壓力（中）：跨月最多 31 格仍等於 31 次查詢，保留 12 後可用額度偏小，常會被 409；預覽顯示格數與可用額度、24 小時重用為緩解。
- 風控閘門：星期標籤與「未查」文案屬事實陳述；任何「週末」語意詞可能被解讀為建議，故不做縮寫（FR-D8）。
- 測試期望值風險（低）：`condition_key` 版本與表單欄位改動連帶既有測試，由 AC-F4 要求逐條列出。
- UI 驗收：星期多選、月份範圍、跨月日曆、375px 閱讀、預覽即時更新，完成前須 qa-e2e 或總經理 e2e；無人值守依 e2e-fallback。真實查價項目由總經理或實作者實跑附結果，其餘用假資料源離線驗證。
- 祕密與遮蔽：本批不新增祕密；錯誤文字沿用既有遮蔽。

## 開放問題（待 CEO 或其他部門回答）

### 待 CEO

1. 【CEO，預設：星期改變換 revision 並重置基準】彈性窗監看修改出發星期後，是否視為新條件、重新計算漲跌基準？預設是（比照其他條件欄位）；若 CEO 想「縮小星期不要重置」請覆議。PM 建議不阻擋開工，由 tech-architect 對照現有 revision 規則確認後落實。

### 待 tech-architect

1. 星期儲存格式：bitmask 整數（0～127，全選 127 或 NULL）vs 逗號字串；PM 傾向可正規化、易比對全選的方式；全選與未設定須正規化為同一值，以免 revision 與 `condition_key` 誤判。
2. migration 0008：`watch` 新增欄位用 ADD COLUMN 是否足夠（含預設值使既有列視同全選）；探索表因 `condition_key` 有 `v1|*` CHECK 與 `month` 為單月欄位，是否需重建表；若重建，舊資料、索引、外鍵、`pre-v8` 備份與回復策略。
3. 探索 `month` 欄位如何擴成範圍：新增 `month_end`（或 `months` 數）欄位、保留舊欄位語意為起始月，還是改存範圍字串；舊 v1 單月紀錄如何讀（月範圍視為起始＝結束）。
4. `condition_key` 版本策略：v2 格式、星期集合正規化（排序與全選）、月份範圍正規化；v1 與 v2 如何確保不互相命中（key 前綴即可？）；比價 `cmp1` 不受影響。
5. 跨月上限 N 的取值（預設 3）與總格數 ≤31 的檢查位置；日曆分段資料結構與前 5 名跨月排序的實作位置。
6. 每輪取樣 12 組在星期篩選後的覆蓋率：`sample_pairs` 輪轉游標在篩選條件改變時是否需重置（與 revision 重置的關係）；星期集合讓組數 ≤12 時是否可保證一輪涵蓋。
7. 日曆顯示：「未查（星期篩選）」是否由 cell 狀態表示（新增 `status`，需改 CHECK）或由顯示層依星期集合推導（不新增列）；PM 傾向不為未查日子建立 cell、由顯示層推導，以免額外儲存與額度誤算。
8. 條件摘要來源：`services/views.py`、`domain/messages.py`、Telegram `/watch` 描述是否共用同一 helper，以確保各處口徑一致。
9. 三項收尾落點：比價進行中的判斷來源（FD-9 `batch_create_lock` 與 active 檢查）、`/status` 與 `/scan` 文案位置、健康頁筆數查詢；是否需增補 ADR-0002。
