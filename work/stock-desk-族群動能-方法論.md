## 0. 先講結論（包括不好看的部分）

1. **做得到的**：用日線建構「官方產業別等權族群指數」，依**近 5 日報酬相對等權全市場的差距**排名。再用 walk-forward 回測，只看樣本外，算出「第 1 名族群在其後 5 個交易日、扣除來回成本後報酬高於基準的次數比例」。這個比例會附上基準率 q、Wilson 95% 區間、樣本數與失效條件。
2. **最可能的結果是降級**。風控的門檻要求：「扣成本後」比例的 95% 下界要高於 q，而且 p − q 至少 5 個百分點。一次來回成本約 0.585%（費率還沒查證），這個成本約會吃掉 8–12 個百分點的比例（依事前假設估計，不是實測）。換算下來，扣成本前的比例大約要到 65% 左右才可能過關。所以**首頁長期停在「近期相對強弱」描述模式是預期中的正常狀態，不是 bug**。見 §6.2。
3. **事前的學術預期偏不利**：產業動能的證據主要出現在 1–12 個月的持有期；週級別常見的是短期反轉。我不預期比例會明顯高於 q，也可能低於 q。如果結果顯示反轉，**不會**事後把訊號翻過來用，那是新假設，要重新登記（§11）。
4. **CEO 說的「記憶體族群」第一階段給不出來**：官方產業別只有「半導體業」這種粗分類。自訂概念股通常是漲了之後才被命名，拿來回測就是 look-ahead（風控 PM-6 同意見）。
5. **窗長和定稿字面有衝突，需要裁定**：風控定稿的標題 chip、成分股表頭、降級句都寫死「近 5 日」。我原本基於事前理由偏好 20 日（雜訊較小、文獻支持較多）。為了符合「線上定義＝回測定義＝畫面文字」（QR-1f、§4.1a），v1 **產品主訊號改用 5 日**，20 日保留為事先登記的第二訊號。如果最後只有 20 日過門檻，畫面上所有「近 5 日」定稿句都要改成「近 20 日」，**必須重送風控**，不能自行替換。這個取捨在看任何資料之前就決定了，不構成事後挑選。
6. **族群內成分股不做任何技術面評價**（風控 QR-5 VETO）。成分股只依族群排名用的同一個已發生變數（近 5 日漲跌幅）列示，性質是「族群的數字是誰貢獻的」，沒有「挑選」的語意，也不附任何歷史比例。原本規劃的技術面評價移到日後另立的方法論（§7.3）。

## 1. 方法摘要

| 項目 | v1 設計 | 為什麼 |
|---|---|---|
| 族群 | TWSE 官方產業別（`t187ap03_L` 兩碼代碼），採 point-in-time | 唯一有公開來源、而且不是事後才命名的分類 |
| 母體 | **第一階段只收上市普通股**，依上市天數與流動性篩選（§2.3）；依風控 §4.5-1 加上 tag「僅上市」 | 上櫃產業別目前是 NULL，不猜著合併 |
| 權重 | **等權**，採「期初等權、期間持有」（§2.2） | 沒有流通股數資料；等權最好解釋，也能實際照著買 |
| 報酬 | 除權息還原，或排除除權息日（§2.4） | 不處理的話，除息旺季高殖利率族群會被系統性壓低 |
| 排名訊號 | **S_A（產品主訊號）**：近 5 日族群報酬 − 等權全市場報酬。**S_B（第二訊號）**：同樣的定義，但用 20 日（§3） | 最簡單、可解釋，事先只登記這兩個進入檢定 |
| 基準 | **B_EW：等權全市場**（同母體、同方法）是判定用的基準；加權指數只供參考（§5.5） | 讓族群和基準一樣用等權，才能把族群效果和「規模效果、台積電權重」分開 |
| 標籤 | t 收盤出訊號 → t+1 開盤進場 → t+5 收盤出場；扣除來回成本後的報酬高於 B_EW 同期報酬，才算一次「高於」 | 使用者收盤後才看得到排行，最早只能在隔天開盤動作 |
| 再排名 | 每 5 個交易日，樣本彼此不重疊 | 對應「一個禮拜左右」 |
| 檢定 | 以基準率 q 為比較對象的 Wilson 區間與 block bootstrap、隨機族群置換檢定、Holm 多重比較校正（§6） | 對應風控 QR-1c 的要求：比較對象是 q，不是 50% |

**與既有設施的關係**（本輪不寫程式，只列接點）：

- 沿用：`app/backtest/costs.py` `CostModel`（費率只從設定取，不寫死）、`app/backtest/splits.py` `walk_forward_splits`、`app/backtest/episodes.py` `wilson_interval`、`app/backtest/event_study.py` `non_overlapping_indices`、`app/backtest/report.py` `PerformanceMetrics`（標準欄位不改名）、`app/dividends/adjust.py`（還原方法與它的 look-ahead 論證）。
- **不引用** `app/advice`、`app/signals` 的評價輸出，也不引用 `five_condition_series`。風控 §4.1d 規定首頁族群卡不得出現規則引擎的輸出；dev-lead §4.7 也寫明 sectors 模組不得 import advice。
- **缺口**：`app/backtest/engine.py` 的 `run_backtest` 只能回測單一資產，族群籃子是多資產，需要一個 point-in-time 的多資產籃子回測器。模組邊界由 tech-architect 在 ADR-0012 決定，我的要求寫在 §8 最後一段。

## 2. 族群指數構建

### 2.1 等權 vs 市值權重

| | 等權 | 市值權重 |
|---|---|---|
| 第一階段可行性 | 可以（只需日線） | **不可以**：沒有流通股數。用成交金額加權當替代也不行，因為成交金額和當期報酬正相關（上漲日量大），權重本身就帶有報酬資訊，會製造出假的動能 |
| 可解釋性 | 「族群內每一檔漲跌幅的平均」 | 需要另外解釋權重來源 |
| 缺點 | 偏重小型股；成分股少的族群容易被單一檔左右 | 半導體業幾乎就等於台積電一檔 |

**建議 v1 採用等權。** 基準也要用同一個母體、同一種等權方法（§5.5）。單一檔主導族群的情況不做 winsorize（那會多出一個可以調的參數），改成輸出「單一成分股最大貢獻比例」：如果超過 50%，就標記 `single_stock_dominated=true`，只做揭露，不影響排名。未來拿到流通股數後，市值權重版本要另外登記成新假設。

### 2.2 算法：期初等權、期間持有

```
R_g(t, L) = mean_{i in C_g(t)} ( P_i(t) / P_i(t−L) − 1 )     # P = 還原後收盤價；C_g(t) = 第 t 日合格成分
```

不採用「每日等權報酬連乘」（等於每天再平衡）。那種算法會因為買賣價差反彈（bid-ask bounce）系統性高估小型、低流動性股票的報酬，而且沒有人真的每天把持股調回等權。期初等權、期間持有，才是「在 t−L 等金額買進、抱到 t」的真實報酬，和 §5 的標籤算法一致。視窗內價格不完整（例如停牌）的成分股，從該視窗排除，並計數揭露。

### 2.3 成分股與覆蓋率門檻（全部只用 ≤ t 的資料判定）

| 門檻 | v1 值 | 理由 |
|---|---|---|
| 證券類別 | 只收上市普通股；排除 ETF／ETN、存託憑證（代碼 91）、特別股、受益證券、權證 | 這些不是產業成員 |
| 其他業（代碼 20） | 不當作族群排名，但成分股**仍計入 B_EW** | 雜項分類沒有族群意義 |
| 上市天數 | ≥ 60 個交易日 | 避開新股前 5 日無漲跌幅限制和蜜月期 |
| 流動性 | 20 日成交金額**中位數** ≥ NT$1,000 萬，且 20 日內有成交的天數 ≥ 18 | 用中位數，單日爆量騙不過；用金額，減資或面額變更造成的股數跳動影響不到 |
| **族群最小成分數** | 合格成分 **≥ 5 檔**（和風控暫定值相同；這裡指的是**通過流動性篩選後**的檔數，比單純計算檔數更嚴） | 等權平均的變異數大約和 1/n 成正比，成分少的族群會同時佔據榜首和榜尾 |
| **族群覆蓋率**（建議值） | **≥ 90%**（風控暫定值是 80%，這裡調嚴） | 見下方說明 |
| **整體覆蓋率**（建議值） | **≥ 98%**（風控暫定值是 95%，這裡調嚴）；未達就整卡降級為「不足」 | 見下方說明 |

**覆蓋率的定義**：分母是第 t 日 point-in-time 母體中、當天應該有交易的股票（扣除依 TWSE 公告暫停交易的股票，這部分另外揭露為「暫停交易 m 檔」；如果拿不到暫停交易名單，就一律算進缺漏，偏向保守）；分子是當天有有效日線的股票。族群覆蓋率用同一個定義，範圍限定在該族群的成員。

**為什麼調嚴**：

- 全市場日線正常情況下是一次取得、整批完整的。缺漏超過 2%（約 20 檔）通常代表抓取或解析出了問題，而這類缺漏往往**不是隨機的**，例如某種特殊列格式整批遺失，或暫停交易的股票正好是有重大消息的股票。非隨機缺漏會讓 B_EW 和族群指數同時偏掉，而且偏誤方向無法事前判斷。
- 族群覆蓋率用 80% 的話，10 檔的族群可以缺 2 檔。如果缺的剛好是當期漲跌最大的那兩檔，族群數字就會失真。改用 90%，5–9 檔的小族群等於要求一檔都不能缺，偏向保守。
- 兩個值都是**建議值**，最後由風控裁定。**規則只能調嚴，不能放寬。**

**小族群偏誤監控**：回測報告要列出第 1 名族群依成分數分組（5–9、10–19、≥ 20 檔）的出現頻率，並和名次隨機時的期望頻率對照。某組超過期望的 2 倍時標紅。之後如果要修正（例如依波動度標準化），要登記成新版本。

### 2.4 除權息、減資與面額變更（QR-4）

**標籤（回測的結果端）一定要還原**：持有人會實際收到股利，不還原就會把「領到的股利」記成損失。這不是 look-ahead，因為標籤本來就是事後觀察的結果。所以回測**需要歷史除權息因子**（D4）。

**訊號與畫面（決策端）有兩種方式，擇一，而且線上和回測必須採用同一種**（QR-1f）：

1. **還原（建議）**：採用 `app/dividends/adjust.py` 的方法，錨點放在最新一根，用乘法因子調整。因為報酬是尺度不變量，第 t 日看到的視窗，只會和「只用 ≤ t 的事件還原」差一個常數倍，所以**不會洩漏未來**（該模組檔頭有證明，§8 T4 用測試釘住）。前提是資料來源的還原方式確實是**乘法因子**；如果是加法調整，這個論證就不成立。
2. **排除除權息日**：成分股在訊號視窗內如果遇到除權息日，該視窗就把這檔排除。只需要知道過去的除權息日期（第 t 日都已知），不需要因子。缺點是 7–8 月高殖利率族群的成分股會被大量排除，可能因此跌破族群覆蓋率門檻、當期不列入排行。這個結果照實揭露。

**減資、面額變更、分割**也會讓價格不連續，處理方式同上，需要事件表。另外加一道保險：成分股在視窗內如果單日報酬超過漲跌幅限制加上容差，就視為有未處理的公司行動，將這檔從該視窗排除並記錄。

**資料缺口**：現行 `TWT48U_ALL` 只列**即將發生**的除權息，沒有歷史資料（`app/dividends/providers.py`）。歷史事件需要 data-engineer 另外找來源（例如 FinMind），並確認還原方式是乘法因子。**D4 沒有到位，§6 的門檻就不評估**（`gate_status=not_evaluated`），首頁固定顯示降級句。

## 3. 排名訊號

### 3.1 候選訊號清單與各自的 look-ahead 風險點（QR-3：全部在這裡事先登記）

所有訊號都在第 t 日**收盤、而且全市場資料齊全之後**才計算。只做**橫斷面**比較（同一天的族群彼此比較），**不做任何時間序列標準化**。用整段期間的平均和標準差做 z-score，是最常見的未來函數。

| 代號 | 定義 | v1 狀態 | look-ahead 風險點 |
|---|---|---|---|
| C1 | R5 相對報酬 = R_g(t,5) − R_EW(t,5) | **進入檢定（S_A）** | ① 用 t 收盤出訊號、又以 t 收盤成交（同一根 bar 偷看自己）；② 用今天的上市名單回推過去的母體（存活者偏差）；③ 還原因子是加法調整；④ 盤中用當天還沒收完的資料更新排行，和回測使用的全日資料不一致 |
| C2 | R20 相對報酬 | **進入檢定（S_B）** | 同 C1；視窗越長，越容易碰到除權息 |
| C3 | 上漲家數比（視窗內報酬 > 0 的成分比例） | 登記，v1 **不檢定**，只作描述性欄位（風控 §4.4-5 要求顯示「上漲 k／n 家」） | 除息日如果沒還原，會被算成下跌；暫停交易的股票會被當成平盤；成分股必須在 t 就決定 |
| C4 | 量能比（族群 5 日平均成交金額 ÷ 20 日平均成交金額） | 登記，v1 **不檢定**，只作描述性欄位 | 要用金額，不能用股數；第 t 日的值必須是盤後全日值，不能用盤中快照 |
| C5 | C1、C2 的橫斷面名次平均 | 登記，v1 **不檢定** | 組合權重如果是看結果決定的就是調參。另外，畫面上沒有合規的方式可以描述這個訊號（「綜合」是 VETO 字），成分股也沒辦法依「同一個變數」排序 |
| C6 | C1～C4 的任意組合 | 登記，v1 **不檢定** | 同 C5 |

**v1 只檢定 S_A 與 S_B。** C3～C6 以後如果要檢定，都必須寫進參數歷程（§11），並且加進 Holm 的比較次數。

### 3.2 為什麼 S_A 是 5 日

- 風控定稿字面寫死「近 5 日」，而 QR-1f 要求線上定義、回測定義和畫面文字三者一致；§4.1a 也要求成分股排序使用「族群排名用的同一個變數」。只有讓 S_A = C1，產品從上到下才會自洽。
- 就統計而言，我事前比較偏好 20 日：5 日報酬的雜訊比較大，比較容易撞上週級別的短期反轉；而且等權組合的週報酬本來就有正的自我相關，部分來自小型股的不同步交易（Lo–MacKinlay 型效果），用收盤到收盤的標籤會高估可以實際交易的優勢。§5.1 採用開盤進場，就是為了壓低這個效果。
- 所以兩個都檢定、用 Holm 校正。**產品預設採用 S_A**。如果只有 S_B 過門檻，要改用 S_B 就必須重送風控，把定稿句改成「近 20 日」。
- 名次同分時依族群代碼升冪排序，完全決定性，不看報酬、不看名稱。

## 4. 訊號與資料輸出定義（給 dev-lead、tech-architect、frontend-engineer）

每個完整交易日、每個族群一列。欄位名稱遵守 QR-6，**不使用** `hit_rate`、`win_rate`、`score`、`rating`：

| 欄位 | 含義 |
|---|---|
| `method_version` | 例如 `sector-rel-return-v1.0-L5`。線上與回測共用同一個版本字串；版本不一致時，`gate_status` 強制為 `not_evaluated`（QR-1f） |
| `as_of` | 最後一個完整交易日（全市場一致，族群之間不混用不同日期，§4.5-1） |
| `market_scope` | `twse_only`（v1 固定值，前端依此顯示「僅上市」） |
| `sector_code` / `sector_name` | 官方產業別 |
| `rank` | S_A 的名次；成分不足或覆蓋率不足時為 null，並在 `excluded_reason` 說明 |
| `sector_return_5d` / `benchmark_return_5d` / `rel_return_5d` | 分開提供，讓使用者看得到相減的兩個數字。**只描述過去** |
| `rel_return_20d` | 描述性欄位 |
| `up_count` / `constituent_count` | 「上漲 k／n 家」（5 日窗） |
| `turnover_ratio_5_20` | 族群 5 日平均成交金額 ÷ 20 日平均成交金額（§5.6 口徑待確認） |
| `coverage_ratio` / `missing_count` / `suspended_count` | §2.3 的覆蓋率 |
| `top_contributor_share` / `single_stock_dominated` | §2.1 |
| `adjustment_method` | `adjusted` / `ex_date_excluded` |
| `gate_status` | `passed` / `failed` / `not_evaluated` |
| `historical_stat` | **所有門檻狀態下都提供**（風控 §4.3：降級時「詳細」要照實列出 k／N、p、q、CI）。內容：`rank_scope="rank_1"`、`beat_count`、`sample_count`、`base_rate`、`ci_low`、`ci_high`、`cost_basis="net_round_trip"`、`benchmark="equal_weight_market"`、`oos_start`、`oos_end`、`computed_at`、`method_version`。前端**只有在 `gate_status=passed` 時**才可以把它放上主視圖 |

## 5. 回測設計

### 5.1 時序規則（唯一版本）

```
第 t 日收盤後：只用 ≤ t 的資料決定母體、門檻、訊號、名次
第 t+1 日開盤：以等金額買進第 1 名族群的合格成分（成分固定為第 t 日判定的名單）
第 t+5 日收盤：全部賣出
excess_net = R_basket(開盤 t+1 → 收盤 t+5) − 來回成本 − R_EW(開盤 t+1 → 收盤 t+5)
「高於」 ⇔ excess_net > 0（剛好等於 0 不算）
下一次：第 t+5 日收盤出訊號 → 第 t+6 日開盤進場（樣本彼此不重疊）
```

- **開盤漲停買不到**：t+1 開盤價 ≥ 參考價 × 1.095 的成分股視為買不到，從籃子剔除（事先登記）。這個處理偏保守。跌停賣不出去的情況不另外模擬，只做揭露。
- **診斷版本**（不作為門檻依據）：另外計算收盤 t → 收盤 t+5 的版本。如果優勢只出現在這個版本，代表優勢主要來自隔夜跳空，使用者實際上拿不到，這個結論要寫進報告。
- **起點相位**：從第幾天開始每 5 日一輪，共有 5 種相位。主結果固定用第一個合格交易日作為相位 0；其他 4 種相位**全部跑、全部列出**，不挑選。

### 5.2 Walk-forward

- 使用 `walk_forward_splits(n, train_size=504, test_size=126, step=126)`，滾動窗（不擴張）：大約 2 年訓練、半年測試，測試窗之間不重疊。
- **誠實說明**：S_A 和 S_B 沒有任何參數是用樣本內資料擬合出來的，所以這裡的樣本內／樣本外是**期間切分與誠實呈現的框架**，不是防止擬合過度的機制。唯一的選擇是「S_A 和 S_B 用哪一個」，已經交給 Holm 校正處理。
- 樣本內是第一個 fold 的訓練窗；樣本外是所有測試窗依序接起來。兩段分開報，**§6 的門檻只看樣本外**（QR-1a）。

### 5.3 成本模型

- 費率一律透過 `CostModel` 從設定檔讀取。目前設定檔的預設值：手續費 0.1425%（買賣都收，法定上限，不含券商折扣）、證交稅 0.3%（一般股，賣出收取），一次來回約 0.585%。**`verified_on=null`，還沒有查證。** 請 data-engineer 查證現行法規後，更新數值、`verified_on` 和來源（D9）。查證完成前，所有報告都附上既有的 `UNVERIFIED_RATES_NOTE`。
- 滑價：主結果用 0 bps；每邊 10 bps 和 20 bps 作為敏感度分析，三組都列出。
- 判定門檻用的歷史比例，**每一個樣本都扣一次完整的來回成本**，當作每次都是新建倉，這是保守做法（QR-1d）。策略層報告（§5.4）則依實際週轉計算成本。
- 量級參考：如果每 5 日完全換一次籃子，一年大約 49 次進出，成本拖累約 28.7%／年。回測要照實報出週轉率。

### 5.4 策略層標準報告（依 backtest-protocol，欄位缺一不可）

策略定義：每 5 日持有第 1 名族群的等權籃子，依實際週轉扣成本。沿用 `PerformanceMetrics` 的全部欄位：CAGR、年化波動、Sharpe／Sortino、最大回撤與起迄日、勝率、盈虧比、交易次數、週轉率。樣本內、樣本外分列，並與所有基準並列。「勝率」是 backtest-protocol 的內部欄位名稱，**不會出現在 API 或畫面上**。

### 5.5 基準：加權指數 vs 等權全市場

| 基準 | 用途 |
|---|---|
| **B_EW：等權全市場**（同一個合格母體，含其他業與成分不足族群的股票；同樣採期初等權、期間持有，同樣的還原方式） | **所有門檻判定與主視圖都用它**，畫面上要寫全名（例如「等權全市場」，最終字面由風控和 creative 決定），不可以只寫「大盤」 |
| B_BH：發行量加權股價**報酬**指數，買進持有（拿不到時用 0050 還原，並清楚標示） | backtest-protocol 要求的 Buy & Hold 對照；沿用 `BUY_AND_HOLD_NOTE`（未計成本的被動基準） |
| B_TAIEX：加權股價指數（價格指數） | 只作參考，另外算一組統計量，不用於判定門檻 |

**等權族群對市值加權指數的結構偏差**（為什麼不能拿加權指數當判定基準）：

1. **規模效果**：等權族群的權重偏重中小型股，加權指數由大型股主導。拿等權族群去比加權指數，差距中有很大一部分是「小型股 vs 大型股」的報酬差，不是族群本身的強弱。
2. **單一個股集中**：台積電在加權指數中的權重極高（實際比例請 data-engineer 提供），「高於加權指數」在很多期間幾乎等於「高於台積電」。在大型權值股領漲的期間（例如 2023–2025 年 AI 行情），幾乎所有等權族群都會低於加權指數，基準率 q 會遠低於 50%，第 1 名的比例也只是在反映這件事。
3. **產業權重不對稱**：半導體業在加權指數中比重很大。等權的「半導體業族群」和加權指數比，實際上是在比「等權半導體股 vs 台積電」。
4. **股利**：加權股價指數是價格指數，不含股利；族群報酬如果有還原，兩者就不是同一種尺度（報酬指數才是同一種尺度）。
5. **B_EW 的好處**：兩邊都是等權、同一個母體、同一種還原方式，規模效果和股利尺度大致互相抵銷，剩下的差距才比較接近「族群本身的效果」。代價是 B_EW 不是一般人口中的「大盤」，所以畫面上一定要寫出基準全名。

回測報告要同時列出以 B_TAIEX 為基準的 q 和第 1 名比例，**讓上面第 2 點的偏差直接用數字呈現**，但這組數字不用於門檻。

### 5.6 描述性診斷（不算額外的假設檢定）

- **分名次區間統計**（QR-2）：第 1、2、……、K 名各自的 `beat_count`、`sample_count`、Wilson 區間、平均超額報酬（扣成本前和扣成本後）。**首頁只使用第 1 名的統計，這點要明確寫出**；其他名次的統計只放在研究報告和「詳細」。名次如果呈現單調關係（第 1 名到最後一名依序遞減），證據力比「只有第 1 名好」強。
- 第 1 名族群的分布，以及**剔除最常出現的族群後重算的比例**。
- 逐年統計，以及高波動期（加權指數 20 日已實現波動落在歷史前 20%）與其他期間分開統計。
- **「均量」口徑**：族群層級只能加總成交**金額**（不同股價的股數相加沒有意義），所以 `turnover_ratio_5_20` 用的是金額。風控核可的字面「均量 x.x 倍」是否適用於金額，請風控或 creative 確認，必要時改成「成交金額」。

## 6. 統計量、檢定與降級門檻（QR-1、QR-2）

### 6.1 核心統計量（全部只用樣本外）

| 統計量 | 定義 |
|---|---|
| `beat_count` k / `sample_count` N | 第 1 名族群的 excess_net > 0 的次數 / 不重疊的 5 日樣本數 |
| p | k / N（扣成本後） |
| **基準率 q**（`base_rate`） | 在同樣這幾週中，**全部合格族群**的「高於」比例平均（先算每週，再平均）。算兩種口徑：q_gross（扣成本前）、q_net（每個族群也都扣一次來回成本） |
| 95% 區間 | Wilson（使用 `wilson_interval`），另外附 block bootstrap 百分位區間 |
| 有效樣本數 N_eff | N × (二項變異數 ÷ block bootstrap 變異數)，用來反映序列相依（QR-1b） |
| 平均與中位數超額報酬 | 扣成本前、扣成本後各一組，附 bootstrap 區間。比例高於 q，但平均超額報酬是負的，這種情況完全可能發生，所以必須並列 |
| 扣成本前的 p_gross | 只在「詳細」揭露，不用來判定 |

### 6.2 檢定

1. **Wilson 區間下界和 q 比較**：這是風控 QR-1c 的主要判定。
2. **Block bootstrap**：circular block，平均區塊長度 4 個樣本（約 4 週），10,000 次，seed 固定並記錄。用來處理「第 1 名族群有持續性」、「市場狀態會群聚」所造成的序列相依。區塊長度 2 和 8 的結果也一律列出。
3. **隨機族群置換檢定**：每一週都從當週合格族群中隨機抽一個取代第 1 名，重複 10,000 次，得到「隨便挑一個族群」時比例的分布，p 值 = 隨機結果 ≥ 實際 p 的比例。這個檢定自動考慮了每週族群數量的變化和基準率。
4. **多重比較**：S_A、S_B 兩個訊號用 Holm 校正（整體 α = 0.05）。之後每登記一個新版本，比較次數就加一。

**檢定力**（樣本獨立的理想情況下；序列相依會讓需要的樣本更多）：單尾 α = 0.025、檢定力 80%，要偵測到「真實比例比對照值高出 Δ」需要的樣本數：

| Δ（相對於 50%） | 需要 N | 約幾年（一年約 49 個樣本） |
|---|---|---|
| +5 pp | 783 | 16 |
| +8 pp | 305 | 6.2 |
| +10 pp | 194 | 4.0 |
| +15 pp | 85 | 1.7 |

| 樣本外 N | 可偵測的最小真實比例 | Wilson 下界要 > 50%，觀察比例大約至少要 |
|---|---|---|
| 60 | 約 68% | 約 63% |
| 150 | 約 61% | 約 58.7% |
| 250 | 約 59% | 約 56.4% |

**結論**：風控暫定的 N ≥ 60，對應的可偵測效果大約要到 18 個百分點，區間非常寬。所以我把樣本數門檻調嚴到 N ≥ 150（見 G1）。

**扣成本的影響（事前估計，不是實測）**：族群 5 日超額報酬的標準差如果在 2%–3% 左右，扣掉 0.585% 的來回成本，大約相當於平移 0.2–0.3 個標準差，比例大約會下降 8–12 個百分點。再加上 p − q_gross ≥ 5 個百分點的效果量要求，**扣成本前的比例大約要到 65% 左右才可能過關**。所以降級是最可能的結果。

### 6.3 顯示門檻（v1 凍結；全部成立才算 `gate_status=passed`，任何一項不成立就降級）

| # | 風控條款 | 本文採用的判定（只調嚴，不放寬） |
|---|---|---|
| G0 | QR-4、§4.5-6 | 使用真實資料（不是 `demo_synthetic`）；D1、D3、D4 已到位；data-engineer 品質檢查通過；§8 的 T1～T9 全部通過 |
| G1 | a、b | 只看樣本外；**N ≥ 150**（風控暫定 60），而且 **N_eff ≥ 60** |
| G2 | c | 以扣成本後的 p 計算：Wilson 95% 下界 **> max(q_gross, 50%)**，而且 block bootstrap（區塊長度 4）95% 下界也 **> max(q_gross, 50%)**，而且置換檢定 p 值經 Holm 校正後 < 0.05 |
| G3 | c（最小效果量，事先訂定） | **p − q_gross ≥ 5 個百分點** |
| G4 | d | 以扣來回成本的版本判定（G2、G3 本來就是用扣成本後的 p）；另外要求扣成本後的平均超額報酬點估計 > 0 |
| G5 | （本文另加） | 樣本外前半段、後半段的 p 都 > q_gross；5 種相位全部 > q_gross；剔除最常出現的族群後，p 仍 > q_gross |
| G6 | e | 最近 12 個月（約 49 個樣本）的樣本外 p ≤ q_gross 時，自動降級；距離上次重算超過 20 個交易日時，也自動降級 |
| G7 | f | `method_version` 在線上和回測兩邊一致；定義一改，就回到 `not_evaluated`，重跑之後才能重新判定 |

**關於 q 的口徑**（請風控確認）：判定時用 **p_net 對 q_gross**，這是最嚴格的組合，因為 q_gross ≥ q_net。主視圖呈現時，p 和 q 必須放在**同一個口徑**上，也就是 p_net 配 q_net，並且共用同一個「已扣成本」標籤，避免把扣過成本的 p 和沒扣成本的 q 並排，讓讀者誤解。這樣做的結果是：主視圖上看到的差距 p − q_net，會比判定用的差距 p − q_gross 大。風控如果認為主視圖應該呈現 q_gross，請直接裁定。

**重算頻率**：每完成一個新的 5 日樣本（每 5 個交易日）就重算一次。降級是自動、立即的；要從 `failed` 回到 `passed`，只能在每季檢視時進行，而且要經過 qa-reviewer 確認，避免狀態在門檻附近來回跳動。

**上線後的前瞻紀錄**：上線之後的資料是唯一真正沒被看過的資料，要分開累積。滿 26 個樣本之後，如果前瞻紀錄的比例和回測的比例有顯著差異（二項檢定 p < 0.05），就自動降級並升級給 CEO。在「詳細」中，前瞻紀錄和回測數字要並列，不合併成一個數字。

**降級時**：依風控 §4.3，主視圖改成定稿降級句，拿掉百分比和 k／N；「詳細」則照實列出 k／N、p、q、區間與「未達門檻」，**不隱藏難看的數字**。

## 7. 族群內成分股列示（依風控 QR-5 改寫）

### 7.1 v1 的做法：只描述，不評價

- **排序變數**：成分股自己的近 5 日（還原後）漲跌幅，和 S_A 是**同一個已發生變數**。族群的 R5 就是這些數字的等權平均，所以這份清單回答的是「族群的數字是誰貢獻的」，不是「該買哪一檔」。
- 如果日後產品改用 S_B（20 日），成分股排序、表頭字面、上漲家數窗也要一起改成 20 日，並重送風控。
- 同分時依代碼升冪排序。**不用**流動性、技術指標或規則引擎的輸出當作 tie-break，任何第二個變數都會讓排序帶有評價。
- 候選範圍：該族群當天的合格成分；缺資料的股票不列入，計入 `missing_count`。
- **風控 §4.1f 的建議（統計上我支持）**：呈現「漲跌幅最大 2 檔＋最小 1 檔」，而不是前 3 檔。原因是它呈現的是族群**內部的離散程度**：如果族群上漲只靠一兩檔撐著，最小的那一檔會直接把這件事顯示出來，比單純列前 3 檔更誠實。
- 成分股列**不附任何歷史比例**（風控 §4.3：「本比例為族群等權指數的統計，不適用於個別成分股。」），也不附任何規則引擎的輸出（§4.1d）。
- **不需要回測**：這份清單不宣稱任何未來性質。成分股層級的歷史比例也**不應該計算後拿來呈現**，一旦算出來放上畫面，就會把「描述」變成「評價」。

### 7.2 誠實揭露給 CEO

依近 5 日漲跌幅排序，排在最前面的必然是「已經漲最多的」，這不代表之後還會漲。個股週級別的報酬，文獻上常見的是短期反轉。這也是風控要求放上定稿句「列示順序僅依近 5 日漲跌幅，不代表任何優先順序。」的理由，本文同意。

### 7.3 待辦：另立方法論（不在本階段）

原本規劃的「依既有觀察條件評估成分股技術面」移出第一階段。日後如果要做，必須符合以下條件：

- **另立任務和方法論文件**，名稱**不得**含「分數、評分、評級、rating」，暫定為「族群成分股觀察條件對照（研究）」，最終名稱交由風控決定。
- 前提條件（風控 §4.1g）：先完成個股層級的驗證，套用和本文 §6.3 **同一套**顯著性門檻，另外送風控審查。
- 技術上必須處理的問題：五條件刻畫的是「上升趨勢中拉回」，和族群動能的方向可能相反；第 6 條依賴持倉狀態，對未持有的股票無法判定；規則引擎的權重是「優先序，非機率」，不能加總成評價值；首頁位置可能蓋過個股頁「本次未支持進場」的否定結論（風控 §4.1-(2)）。

## 8. Look-ahead 與偏誤偵測測試（QR-4；G0 要求全部通過）

| # | 測試 | 做法與判定 |
|---|---|---|
| T1 | **未來擾動不變性**（主測試） | 隨機抽 50 個決策日 t，把 t 之後的價格、成交量、成分股、除權息事件、產業分類全部換成隨機雜訊，重新計算第 t 日的母體、合格名單、族群指數、S_A／S_B、名次、成分股排序。結果必須**逐位元相同** |
| T2 | 向量化計算與逐日計算一致 | 用整段資料一次算出的第 t 列，必須等於只餵 ≤ t 資料算出的最後一列（沿用 `test_five_condition_series_is_trailing_only` 的模式） |
| T3a | **Shift 測試：注入洩漏的正向對照**（backtest-protocol 鐵律 2） | 故意把訊號改用 t+5 的收盤計算（價格往前 shift），比例必須大幅上升（閾值在實作時先用合成資料校準，校準後凍結）。如果沒有上升，代表評估管線對洩漏不敏感，測試本身失效。如果真實訊號的比例已經接近洩漏版，就判定為疑似洩漏 |
| T3b | Shift 測試：延遲 1 日 | 訊號改用 t−1 的資料。預期會溫和變差；如果優勢完全消失，就標記「優勢可能集中在隔夜或微結構」並寫進報告 |
| T4 | **除權息不洩漏** | 分別用「全段還原」和「只用 ≤ t 已知事件還原」兩種方式建構，逐日比較名次，必須相同（沿用 `tests/test_dividends_lookahead.py` 的模式）。測試路徑上必須確實有除權息事件，不能是空測；排除除權息日的方案也要做同樣的測試 |
| T5 | **存活者偏差：必須含已下市個股** | 建一檔會在 t+k 下市的合成股票，它必須出現在第 t 日的母體中。母體要從**當天**的全市場檔建構，不能從今天的 directory 回推。報告要列出每年已下市股票的檔數，以及因為缺少產業分類而被排除的檔數 |
| T6 | **產業分類 point-in-time** | 分類表必須帶生效日期。新代碼在生效日之前不能出現在排名中；個股改類時，生效日之前要算在舊族群。如果只拿得到現行快照，就標記 `classification_pit=false`，G0 不通過，除非風控和 CEO 書面接受這項限制並揭露（§12-1） |
| T7 | 基準一致 | 第 t 日 B_EW 的成分，必須等於同一天的合格母體（包含其他業、成分不足族群的股票） |
| T8 | 安慰劑 | ① 維持各族群大小不變，隨機打亂股票的產業標籤；② 把訊號序列循環平移 k 週。兩種情況下，第 1 名的比例都應該落在 q 的 bootstrap 區間內。如果還是明顯偏高，代表有結構性偏誤（例如小族群效果、成本漏算），而不是族群動能 |
| T9 | 線上與回測一致（QR-1f） | 給同一天的資料，首頁 API 算出的名次和成分股順序，必須和回測器算出的第 t 日結果相同，而且兩邊共用同一個實作與同一個 `method_version`。首頁只用完整收盤日的資料計算，盤中不更新 |

另外，籃子回測器（模組邊界依 ADR-0012 決定）必須在**結構上**保證第 t 日只拿得到 ≤ t 的資料切片（多資產版本的 `iloc[:t+1]`）。碰到未來資料要直接拋出例外，不能只靠審查時細心檢查。

### 11.2 紀錄機制

1. **事先登記**：上表與本文 commit 之後，把 commit hash 寫在參數歷程檔（建議 `work/stock-desk-族群動能-回測紀錄.md`）的第一列。

6. **每次版本變更**都要經過 qa-reviewer 審查，才能更新線上的 `method_version` 和 `gate_status`。

## 12. 已知偏誤與限制

1. **分類 look-ahead**：如果只拿得到現行的產業別快照，用今天的分類回推過去，就會把當時不屬於某族群的股票算進去。T6 會讓 G0 不通過，除非風控和 CEO 書面接受這項限制並加以揭露。
2. **存活者偏差**：D1、D2 如果不含已下市股票，或者已下市股票因為缺少產業分類而被剔除，族群和基準的報酬都會高估；如果下市集中在特定族群，相對報酬也會跟著偏掉。T5 會檢查，並揭露每年被排除的檔數。
3. **小族群偏誤**：見 §2.3 的監控。
4. **檢定力不足**：見 §6.2。「沒過門檻」代表證據不足，不代表沒有效果；「過了門檻」也只是機率與區間層級的陳述。
5. **序列相依**：由 N_eff、block bootstrap、置換檢定處理，但只能緩解，無法完全消除。
6. **成交假設**：以開盤價和收盤價全額成交；跌停賣不出去的情況沒有模擬；滑價只做敏感度分析；手續費用法定上限，沒有反映券商折扣（對使用者而言偏保守）。
7. **費率尚未查證**（`verified_on=null`）。
8. **只用價量資料**：第一階段沒有基本面和消息面，畫面不得暗示這是全面的判斷（風控 ALL-2）。
9. **5 日窗的取捨**：v1 為了讓產品一致而選用 5 日窗，統計上 5 日可能比 20 日更吵，也更容易受到反轉效應影響（§3.2）。這個取捨在看資料之前就已經決定並寫下來。
10. **成分股依已實現漲跌幅列示**：排在最前面的是已經漲最多的股票，不代表之後的走勢（§7.2）。
11. **只含上市**：上櫃族群（包含部分記憶體、IC 設計股）第一階段不在範圍內。
