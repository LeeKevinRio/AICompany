## 0. 先講結論（包括不好看的部分）

1. **第一階段上線的是「排行」，不是「歷史比例」。** 排行只描述已發生的相對強弱：近 5 日族群等權報酬減等權全市場報酬，照常上線。**歷史比例在主視圖和「詳細」都不列示**（風控第二次裁定 §5-4）。原因是目前拿不到三項資料：已下市個股、各時點的產業分類、歷史除權息。用現有資料回推過去，會帶進幅度無法估計的系統性偏誤，而顯著性門檻處理不了系統性偏誤。
2. **想列示歷史比例，要靠時間累積**（路徑 a）：從 ETL 上線日 D0 起逐日保存當時的資料。滿 150 個不重疊的 5 日樣本才判定。對使用者的說法是「約 3 年」（風控定稿）；內部規劃以 3.1 年為下限。這些樣本在參數凍結之後才產生，所以是最乾淨的樣本外資料。第一次判定之前還要經過 `pending_review`（風控書面複審）。
3. **即使累積滿 3 年，最可能的判定結果仍然是 `failed`。** 門檻要求扣成本後的第 1 名比例 p_net 超過 max(q_gross, 50%) 至少 5 個百分點，而且 95% 下界也要高於 max(q_gross, 50%)。一次來回成本約 0.585%（費率尚未查證），事前估計大約會吃掉 8–12 個百分點，換算下來，扣成本前的比例大約要 65% 才過得了。產業動能的文獻證據主要在月級別；週級別比較常見的是短期反轉。所以我對結果的事前預期偏不利。
4. **窗長固定為 v1 的 L=5**，由 `method_version` 靜態決定。L=20 是已登記、但尚未啟用的候選。之後如果要切換，就是新版本：畫面五處同步修改、送風控限縮複審、告知 CEO，並計入 m（Bonferroni 校正，α/m）。**不得因為某個窗長過了門檻就改用那個窗長。**
5. **「記憶體族群」第一階段做不到**，因為官方產業別只有「半導體業」。**族群內成分股也不做任何評價**：只依近 5 日漲跌幅列出，說明族群的數字由誰貢獻（QR-5）。

## 2. 族群指數構建

### 2.1 等權 vs 市值權重

- 市值權重在第一階段**做不到**：沒有流通股數。用成交金額加權當替代也不行，因為成交金額和當期報酬正相關，權重本身就帶著報酬資訊。
- 等權的**好處**：一句話說得清楚，「族群內每一檔漲跌幅的平均」；而且等金額買一籃子就能照做。
- 等權的**代價**：偏重小型股；成分少的族群容易被單一個股左右。
- **v1 採用等權**，基準也用同一種等權方法。
- 不做 winsorize，因為那會多出一個可以調的參數。改為輸出「單一成分股最大貢獻比例」：超過 50% 時標記 `single_stock_dominated=true`，只揭露，不影響排名。
- 市值權重留待第二階段，屬於新假設，要另外登記。

### 2.2 算法：期初等權、期間持有

**兩個集合**（全部只用 `recorded_at ≤ cutoff(t)` 的資料）：

```
E_g(t)    = 第 t 日 PIT 母體中屬於族群 g、通過證券類別／上市天數／流動性門檻的成分（「應計成員」）
            ；若有暫停交易名單，暫停交易者自 E_g 移出並另計 suspended_count
C_g(t, L) = E_g(t) 扣除下列三類（「計算集合」）：
            ① 第 t 日無有效日線，或 (t−L, t] 窗內價格不完整          → missing_count
            ② (t−L, t] 窗內有除權息日（§2.4 選項 2）                   → ex_date_excluded_count
            ③ 窗內單日報酬超過漲跌幅限制加容差（未處理的公司行動保險）  → corporate_action_excluded_count

R_g(t, L) = mean_{i in C_g(t, L)} ( P_i(t) / P_i(t−L) − 1 )
```

**同一集合規則**（風控 §6.2 附帶 required (a)）：以下三者**必須**用同一個 C_g(t,L)，不得各自重算成員：

- 族群報酬 R_g(t,L)；
- 「上漲 k／n 家」，其中 n = |C_g(t,L)|，k = C_g 中 R_i(t,L) > 0 的檔數；
- 成分股列示：從 C_g 中依 R_i(t,L) 排序。

實作上，由同一個函式回傳 C_g，三者都從這個回傳值推導。qa 的斷言：三者的成員集合逐一相等（見 §8 T9）。B_EW 同理，用全體應計成員依同樣三類扣除後的集合 C_M(t,L)。

不採用「每日等權報酬連乘」。那等於每天再平衡，會因為買賣價差反彈（bid-ask bounce）系統性高估小型股的報酬。

### 2.3 成分股與覆蓋率門檻（只用 ≤ t 的資料；覆蓋率門檻依風控 R-E 核可）

| 門檻 | v1 值 |
|---|---|
| 證券類別 | 只含上市普通股。排除 ETF／ETN、存託憑證（代碼 91）、特別股、受益證券、權證 |
| 其他業（代碼 20） | 不作為族群排名，但成分股**仍計入 B_EW** |
| 上市天數 | ≥ 60 個交易日 |
| 流動性 | 20 日成交金額中位數 ≥ NT$1,000 萬，且 20 日內有成交的天數 ≥ 18 |
| 族群最小成分數 | **\|C_g(t,L)\| ≥ 5**：三類排除（缺漏、除權息、公司行動）**都計入**，也就是以計算集合判定，而不是以應計成員判定 |
| 族群覆蓋率 | **\|C_g(t,L)\| ÷ \|E_g(t)\| ≥ 90%**：三類排除**都計入**分子的減項；未達者不列入排行，列在「詳細」 |
| 整體覆蓋率 | **資料完整率 ≥ 98%**：全體應計成員 E_M(t) 中，只扣除第 ① 類（缺漏）後的比例；未達時整卡降級為「不足」（風控核可） |
| 整卡可計算比例 | **\|C_M(t,L)\| ÷ \|E_M(t)\| ≥ 80%（暫定，只能調嚴）**：扣除三類排除後的比例；未達時整卡降級為「不足」。降級原因句由 creative 另外起草送審，**不得**沿用資料缺漏類的句子 |

- **暫停交易**：拿不到暫停交易名單時，暫停交易的股票留在 E 內，算作 ① 缺漏（偏保守）。
- **門檻常數只定義一次**：`{最小數}`（5）、`{門檻}`（90）由 API 輸出，而且和 gate 使用同一個常數。前端不得寫死（風控 §6.2 (c)）。API 另外輸出實際的 `coverage_ratio`。
- **成分股清單不變量**：有排名的族群，|C_g| ≥ 5 > 3，所以列示的「最大 2 檔＋最小 1 檔」一定湊得齊。如果不變量被破壞，表示有 bug，該族群改走排除路徑（原因碼由 tech-architect 補，建議用 `low_coverage`）。

**可計算比例下限的最終值**（等 data-engineer 量測後，由我提出）：

- **量測內容**：過去至少 3 年的每一個交易日，L=5 窗內的 \|C_M\|÷\|E_M\|，以及三類排除各自的佔比，特別是 7–9 月的除息旺季。這一步只看資料的可得性，**不看任何報酬或比例**，所以不算看結果定參數。
- **提案規則**（事先寫下）：
  1. 報告 80%、85%、90% 三個候選值下，每年整卡降級的交易日數與日期分布。
  2. 在「每年整卡降級天數 ≤ 全年交易日的 5%（約 12 天）」的前提下，取**最嚴**的候選值。
  3. 最終值不得低於 80%。
  4. 如果連 80% 都做不到 ≤ 5%，照實回報，由風控裁定，不自行放寬。
- 最終值寫入 `method_version` 凍結，由 API 輸出，並和判定共用同一個常數。

**除權息排除的揭露**（風控 C1-2、C1-3）：

- **全市場除權息排除比例**＝第 ② 類檔數 ÷ \|E_M(t)\|。
- **主視圖常駐 tag**「除權息排除 {m} 檔」：以下任一成立就顯示。
  - 全市場除權息排除比例 ≥ 5%（常數由 API 輸出，與判定共用）；
  - 本次有任何族群因為 `ex_dividend_exclusion` 未列入排行。
- **「詳細」**分列全市場三類排除（缺漏、除權息、公司行動）各自的檔數。

**族群排除原因的歸因順序**（風控 §8-2；**取第一個成立者，不得並列**）：

| 順序 | 原因碼 | 成立條件 |
|---|---|---|
| 1 | `too_few_members` | 結構性不足：\|E_g(t)\| < 最小數（5） |
| 2 | `low_coverage` | 只扣第 ① 類（缺漏）之後，就已經低於門檻：\|E_g\| − 缺漏 < 5，或 (\|E_g\| − 缺漏) ÷ \|E_g\| < 90% |
| 3 | `ex_dividend_exclusion` | 只扣 ① 時兩項都達標，再扣第 ② 類（除權息）與第 ③ 類（公司行動）之後才低於：\|C_g\| < 5，或 \|C_g\| ÷ \|E_g\| < 90% |

- **`ex_dividend_exclusion` 的短語**用風控定稿。其中 {c}＝\|C_g(t,L)\|、{e}＝\|E_g(t)\|，由 API 輸出。
- **qa 需要的案例**：三個原因碼各一個單獨成立的案例，再加一個「缺漏與除權息並存、只看缺漏就已不足 → 取 `low_coverage`」的案例。
- **成分股清單不變量被破壞時**，仍依前文走 `low_coverage`，但要另外寫入錯誤紀錄。

**小族群偏誤監控**：比較第 1 名族群在各成分數組別（5–9、10–19、≥ 20 檔）的出現頻率，和隨機名次的期望頻率。某一組超過期望的 2 倍時，標紅揭露。

### 2.4 除權息、減資與面額變更（QR-4）

- **回看窗（排行，決策端）**：v1 固定採用**選項 2，排除除權息日**。成分股的除權息日如果落在 (t−L, t]，這一檔就從該窗排除。除權息日在第 t 日已經是已知資訊（`TWT48U_ALL` 逐日同步、逐日保存），不會洩漏未來。
  - **代價**：7–8 月高殖利率族群的成分股會被大量排除，族群可能因此跌破覆蓋率或成分數門檻，當期不列入排行。這種情況照實揭露。
  - **上線條件**：`TWT48U_ALL` 的同步紀錄至少要涵蓋最近 L 個交易日，否則無法確認窗內有沒有除權息事件，排行不上線。
- **標籤（持有期的結果端）**：持有人真的會領到股利，所以標籤必須還原，否則會把股利記成損失。這不是 look-ahead，因為標籤本來就是事後觀察的結果。
  - 還原因子取自**前瞻保存**的除權息事件（前收與參考價，或可以換算成乘法因子的欄位），方法沿用 `app/dividends/adjust.py`。
  - 因子必須是**乘法因子**；如果來源是加法調整，報酬就不是尺度不變量，§8 T4 的論證不成立。
- **減資、面額變更、分割**：同樣需要事件表。另外設一道保險：窗內單日報酬超過漲跌幅限制加容差時，視為有未處理的公司行動，把這一檔排除並記錄。

### 3.2 參數拆分：回看窗長 L 與持有期 H

- **L（回看窗長）**：只能是 5 或 20，由 `method_version` 靜態決定，v1 為 L=5。畫面上五處同時跟著 L 走：標題 chip、族群報酬、上漲家數、成分股表頭與排序、降級句。
- **H（持有期）**：v1 為 H=5，和 L **不連動**。例如 L=20 時，H 仍然可以是 5。再排名的間隔等於 H，所以樣本彼此不重疊。
- **禁止動態選窗**：不得依門檻結果（或任何統計結果）在執行期間切換 L。切換 L 或 H 一律視為新版本，必須依照 §11.2 處理：凍結、計入 m（Bonferroni 校正，α/m）、送風控限縮複審、告知 CEO。
- 我事前在統計上比較偏好 L=20，因為雜訊比較小，也比較不會撞上週級別的反轉。但 v1 為了和定稿字面、產品一致，採用 L=5。這個取捨已寫明，而且是在看任何資料之前決定的。
- **多重比較的計數規則**：只要某個版本或訊號在**同一段判定資料**（前瞻資料庫）上算過統計量，就計入比較次數 m，即使那個版本從來沒上過畫面。v1 的 m 從 1 開始。在前瞻資料庫上計算 C2，m 就變成 2，而且之後的每一次判定都要用新的 m。偏誤版內部研究使用的是 D0 之前的資料，和判定資料不重疊，所以不計入 m。

## 5. 回測與判定設計

### 5.1 時序規則（唯一版本）

```
第 t 日收盤後：只用 recorded_at ≤ t 的資料決定母體、分類、排除、訊號、名次
第 t+1 日開盤：等金額買進第 1 名族群的合格成分（名單固定為第 t 日判定結果）
第 t+H 日收盤（H=5）：全部賣出
excess_net   = R_basket(開盤 t+1 → 收盤 t+H) − 來回成本 − R_EW(同期間)
excess_gross = R_basket(同上) − R_EW(同期間)
「高於」 ⇔ excess > 0（剛好等於 0 不算）
下一次：第 t+H 日收盤出排行 → 第 t+H+1 日開盤進場（樣本不重疊）
```

- **開盤漲停買不到**：t+1 開盤價 ≥ 參考價 × 1.095 的成分股，從籃子剔除（事先登記）。跌停賣不出去不另外模擬，只揭露。
- **診斷版本**（不作為判定依據）：另算收盤 t → 收盤 t+H。如果優勢只出現在這個版本，代表優勢來自隔夜跳空，使用者實際上拿不到。
- **起點相位**：共 5 種相位。主結果固定從 D0 之後第一個合格交易日起算，其餘 4 種相位全部列出，不挑選。
- 等權全市場是對照，**不扣成本**；族群一方每個樣本各扣一次來回成本（風控定稿「詳細」句）。

### 5.2 路徑 (a) 前瞻累積（主路徑）

**PIT 快照儲存**（實作歸 tech-architect／data-engineer；以下是我對它的方法論要求）：

| 快照 | 內容 | 規則 |
|---|---|---|
| 上市名單 | 代號、證券類別、上市日、狀態（含暫停交易） | 每個交易日保存一份，附 `recorded_at` 與內容 hash |
| 產業分類 | 每檔的 `t187ap03_L` 代碼 | 同上。分類改變時，照實留下新舊兩筆 |
| 除權息公告 | `TWT48U_ALL` 每日全量 | 同上。除權息日當天或前一天的那份，必須帶有算出乘法因子所需的欄位；如果沒有，要另外保存當天的參考價 |
| 日線 | 全市場開、高、低、收、股數、金額 | 同上 |

- **只增不刪、不覆寫**：更正以新的一列寫入（附 `recorded_at`），不修改舊列。判定時，第 t 日只能讀 `recorded_at ≤ t` 的列。
- **快照缺漏**：某日沒有抓到快照時，沿用前一份（那份在第 t 日確實已知，仍然符合 PIT），並標記 `carried_forward=true`。連續缺漏超過 5 個交易日時，受影響的樣本視為無效，不計入 N，並記錄在執行紀錄中。**不得**用事後抓到的資料回填成當時的快照。
- **不需要回溯的舊資料**：D0 當天的上市名單、分類就是當時的 PIT 資料。這些股票在 D0 之前的日線，在 D0 時已經是已知資訊，可以拿來暖身（上市天數、20 日流動性），不構成存活者偏差，因為母體是在 D0 決定的，不是事後回推。所以樣本從 D0 起就能開始累積。
- **整段視同樣本外**：`method_version` v1 的參數在 D0 之前就凍結並 commit，前瞻資料在凍結之後才產生，沒有任何參數用這些資料擬合過。walk-forward 在這裡沒有訓練窗可言。我仍然用 126 個交易日一段切開報告（沿用 `walk_forward_splits` 的測試窗幾何），供 G5 穩定度檢查與逐段揭露使用。
- **時程**：N ≥ 150。台股一年大約 245 個交易日，約 49 個不重疊的 5 日樣本，所以 150 ÷ 49 ≈ 3.06 年。
  - **使用者看到的句子**：沿用風控定稿的簡化說法「約需 3 年」。
  - **內部規劃（排程、里程碑、對 CEO 的時程承諾）**：一律以 **3.1 年為下限**。
  - 有兩個因素會讓實際時間更長：快照連續缺漏超過 5 日而作廢的樣本，以及 N_eff < 60 時需要更多樣本。所以 3.1 年是下限，不是預估值。
  - 主視圖顯示 `accumulated_samples`，對應風控定稿句中的「目前已累積 {n} 個」。
- **首次轉態**：每個 `method_version` 第一次離開 `not_evaluated` 時，都要先經過 `pending_review`（§6.3）。

### 5.3 已知偏離：backtest-protocol 鐵律 3（待 CEO 核可）

**本設計對 backtest-protocol 鐵律 3（walk-forward 切分）的處理：判定資料為凍結後的前瞻段，整段視同樣本外，不切訓練窗；walk-forward 504/126 只用於偏誤研究。**

- **偏離之處**：鐵律 3 要求「滾動的訓練／驗證窗，不用單次切分」。本案的判定資料**沒有訓練窗**。
- **為什麼仍然站得住**：鐵律 3 的目的，是防止參數在同一段資料上既被選擇、又被評分。本案所有參數都在 D0 之前凍結並 commit；判定資料是 D0 之後才產生的，沒有任何參數用它擬合或選擇過。這比 walk-forward 的樣本外更嚴格，因為樣本外資料在設計當時根本還不存在。多次檢視同一段前瞻資料所造成的選擇偏誤，由 m（Bonferroni 校正，α/m）處理（§3.2、§11.2）。
- **仍然保留的鐵律 3 形式**：前瞻段依 `walk_forward_splits` 的 126 日測試窗幾何逐段列出，供 G5 穩定度檢查；樣本內與樣本外的標示是「樣本內：無；樣本外：全段」，照實寫在報告上。
- **偏誤研究**：用 `walk_forward_splits(train=504, test=126, step=126)` 分開列出樣本內與樣本外，只作管線驗證和量級參考，**不作判定**（§5.4）。
- **狀態**：列為**已知偏離**，**待 CEO 核可**。未核可前，本文件不得視為 done；第一次判定（`pending_review`）也不得啟動。
- **核可後仍須做的事**：CEO 核可後，建議由 skill 維護者評估，是否在 backtest-protocol 補上「前瞻凍結判定」這類等價做法的條文。這屬於員工線的修改，要走 `chore/agent-*` 分支，不在本產品分支處理。

### 5.4 偏誤版回測（只限內部研究）

- **內容**：用現有資料回推 D0 之前的期間。會用到現行分類，而且可能缺少已下市個股與歷史除權息。
- **標示**：每一份輸出、每一張圖、每一列執行紀錄都要標示**「含已知偏誤，不得上畫面」**，並列出三項偏誤各自的預期方向：
  - 存活者偏差：往上高估；
  - 分類 look-ahead：偏向動能；
  - 未還原的除權息：高殖利率族群被低估。
- **隔離**：結果不進 API，也不進 `historical_stat`。由 tech-architect 在 ADR-0012 規定程式邊界，建議加一個測試，證明 API 的統計量只從 PIT 快照儲存計算。
- **不得用來調參**：看過偏誤版結果之後，如果想改參數，就是新版本，必須在前瞻判定前登記；而且因為研究者已經看過相關資料，保守起見也計入 m。
- 結果不論好壞都寫進只增不刪的執行紀錄（§11.2）。

### 5.5 成本模型

- 費率一律透過 `CostModel` 從設定讀取。目前的預設值是手續費 0.1425%（買賣都收，法定上限）、證交稅 0.3%（一般股，賣出時收），一次來回約 0.585%。**`verified_on=null`，尚未查證。** 查證前 `gate_status` 只能是 `not_evaluated`（§6.3 G0）。
- 滑價主結果用 0 bps；敏感度另列每邊 10 bps、20 bps。
- 判定用的比例：每個樣本扣一次完整的來回成本。策略層報告則依實際週轉扣成本。量級參考：如果每週都完全換籃，成本拖累約 28.7%／年。

### 5.6 策略層標準報告（backtest-protocol 欄位缺一不可）

策略定義：每 H 日持有第 1 名族群的等權籃子，依實際週轉扣成本。欄位用 `PerformanceMetrics` 的全部欄位：CAGR、年化波動、Sharpe／Sortino、最大回撤與起迄日、勝率、盈虧比、交易次數、週轉率，並和 B_EW、B_BH 並列。這份報告是給 qa-reviewer 與 CEO 看的研究報告，其中「勝率」這個名稱不會出現在 API 或畫面上。

### 5.7 基準：加權指數 vs 等權全市場

| 基準 | 用途 |
|---|---|
| **B_EW 等權全市場**（同一合格母體；包含其他業、成分不足族群的股票；同一種算法、同一種除權息處理） | 判定用，也是主視圖的基準；畫面寫全名「等權全市場」 |
| B_BH 發行量加權股價報酬指數，買進持有（沒有時改用 0050 還原價，並標示） | backtest-protocol 要求的 Buy & Hold 對照；沿用 `BUY_AND_HOLD_NOTE` |
| B_TAIEX 加權股價指數 | 只放在「詳細」當參考，另外算一組 q |

**等權族群對加權指數的結構性偏差**：

1. **規模效果**：等權偏重中小型股。拿它和加權指數比，差距大多反映的是大小型股的報酬差，而不是族群強弱。
2. **單一個股集中**：台積電在加權指數中的權重極高，「高於加權指數」在很多期間幾乎就等於「高於台積電」。大型權值股領漲的期間（例如 2023–2025 年），幾乎所有等權族群都落後，q 會遠低於 50%。
3. **產業權重不對稱**：用加權指數當基準時，等權的半導體族群實際上是在和台積電比。
4. **股利**：價格指數不含股利，和還原後的族群報酬尺度不同。
5. **B_EW 的處理**：兩邊用同一種權重、同一個母體、同一種還原方式，上述偏差大多互相抵銷。報告會並列以 B_TAIEX 為基準的 q，讓第 2 點的偏差直接用數字呈現。

## 6. 統計量、檢定與三態門檻

### 6.1 統計量（只用判定資料，也就是前瞻段）

| 統計量 | 定義 |
|---|---|
| N（`sample_count`） | 有效、不重疊的 H 日樣本數 |
| k_net、p_net | 第 1 名族群 excess_net > 0 的次數與比例 |
| k_gross、p_gross | 第 1 名族群 excess_gross > 0 的次數與比例 |
| q_net、q_gross（`base_rate_*`） | 同樣那些週裡，**全部合格族群**「高於」比例的平均（先算每一週，再跨週平均）；q_net 是每個族群都扣一次來回成本後的版本 |
| 95% 區間 | Wilson（用 `wilson_interval`），另附 block bootstrap 百分位區間；信賴水準依 m 校正為 1 − 0.05/m |
| N_eff | N ×（二項變異數 ÷ block bootstrap 變異數） |
| 平均與中位數超額報酬 | 扣成本前、扣成本後各一組，附 bootstrap 區間 |
| 分名次統計（QR-2） | 第 1 名到第 K 名，各名次的上述數字；**主視圖只用第 1 名**，其餘名次只放研究報告 |

**呈現口徑**（依風控第二次裁定定稿）：

- **主視圖**：p_net 對 q_net，**兩者都已扣來回成本**。
- **「詳細」**：p_gross、q_gross、p_net、q_net 四個數字都列，並標明口徑。
- **禁止**把 p_net 和 q_gross 並排呈現（VETO）。

### 6.2 檢定

1. **Wilson 下界**：以 p_net 計算，信賴水準 1 − 0.05/m。
2. **Block bootstrap**：circular block，平均區塊長度 4 個樣本，10,000 次，seed 記錄。區塊長度 2 和 8 的結果也要列出。
3. **隨機族群置換檢定**：每週從當週合格族群中隨機抽一個，取代第 1 名；重複 10,000 次。p 值 < 0.05/m 才算通過。
4. **多重比較**：m 依 §3.2 的規則累計，採 Bonferroni 校正，所有判定一律用 α/m。

**檢定力**（假設樣本獨立；序列相依時需要更多樣本）：單尾 α=0.025、檢定力 80%

| Δ（相對於 50%） | 需要的 N | 約幾年（每年約 49 個樣本） |
|---|---|---|
| +5 pp | 783 | 16 |
| +8 pp | 305 | 6.2 |
| +10 pp | 194 | 4.0 |
| +15 pp | 85 | 1.7 |

| N | 可偵測的最小真實比例 | Wilson 下界 > 50% 所需的觀察比例 |
|---|---|---|
| 60 | 約 68% | 約 63.3% |
| 150 | 約 61% | 約 58.7% |
| 250 | 約 59% | 約 56.4% |

**扣成本的影響（事前估計，不是實測）**：假設族群 5 日超額報酬的標準差在 2–3%，來回成本 0.585% 大約是 0.2–0.3 個標準差的平移，會讓比例下降約 8–12 個百分點。再加上 +5 個百分點的效果量，扣成本前的比例大約要 65% 才過得了。

### 6.3 三態判定（v1 凍結）

令 **b = max(q_gross, 50%)**。

**`not_evaluated`**：前提不成立。只要下列任一項成立，就是這一態：

| # | 條件 | reason |
|---|---|---|
| NE-1 | 判定資料不是 PIT：母體不含當時已下市個股（存活者偏差）、分類不是當時分類、除權息沒有當時**可用**的事件紀錄，三項中任一有缺口就成立。偏誤版回測一律屬於這一條。**DE-5 未查證也屬於這一條**（見下方說明） | `pit_history_missing` |
| NE-2 | 前瞻累積的有效樣本 N < 150，或 N_eff < 60 | `accumulating` |
| NE-3 | **D9 費率尚未查證**（`CostModel.verified_on` 為 null） | `fee_unverified` |
| NE-4 | 距離上次重算已超過 20 個交易日 | `stale_recompute` |
| NE-5 | 線上的 `method_version` 和統計量的 `method_version` 不一致 | `version_mismatch` |
| NE-6 | data-engineer 的品質檢查沒有通過（未來日期、重複、覆蓋率） | `data_quality` |
| NE-7 | §8 的 T1～T9 有任一項未通過：runtime 項目在本次判定中失敗或無法執行，或 CI 項目在目前部署的 commit 上不是綠燈（詳見 §8 的對照表） | `lookahead_tests_failed` |
| NE-8 | 資料是 `demo_synthetic` | `demo_data` |
| — | NE-1～NE-8 全部不成立，但本 `method_version` 還沒有 `first_transition_risk` 核准紀錄 | `pending_review` |

**原因碼的優先序**（多個原因同時成立時，`not_evaluated_reason` 只取一個，`not_evaluated_reasons` 列出全部）：

1. **NE-8 永遠最優先**（風控 NR-2）。只要資料來源是 `demo_synthetic`，就用 NE-8 的句子，不套用「取編號最小者」規則；主視圖另外常駐 NE-8 的卡片警告句，由 `data_source` 驅動。
2. 其餘情況取 NE-1～NE-7 中編號最小的一項。
3. `pending_review` 只在 NE-1～NE-8 全部不成立時才會出現，因此優先序永遠最低。

ADR-0012 D-8 與 T-11 原本寫的是「一律取編號最小者」，要依此修正。

**`pending_review` 規則**（風控 §6.4-1 已採用）：

- **觸發時機**：每個 `method_version` **第一次**離開 `not_evaluated` 時都要經過，不管候選結果是 passed 還是 failed。
- **只在 NE-1～NE-8 全部不成立時進入**。其間只要有任一 NE 成立，就改回那個 NE 原因。
- **待審期間 API 不得洩漏候選結果**：候選 gate 結果、`historical_stat`、`gate_checks` 一律回 None。畫面上也看不到判定是 passed 還是 failed，只顯示風控定稿的 `pending_review` 句。
- **核准的寫入方式**：
  - `first_transition_risk` 核准紀錄**只能**由 CEO 或 dev-lead，依風控的**書面 APPROVE**，用 CLI 寫入；
  - `--reviewer` 要附上審查文件的路徑；
  - **任何 agent（包括 quant-researcher）都不得在沒有書面核可的情況下代寫。**
- **核准之後**：依候選結果轉成 `passed` 或 `failed`。之後的轉態依下方「轉態規則」處理，不必每次重走 `pending_review`；但只要 `method_version` 改變，新版本就要重走一次。

**DE-5（`change` 的語意尚未查證）為什麼歸 NE-1，而不是 NE-6**：

- **NE-6 管的是單次資料品質**：未來日期、重複、覆蓋率。這些逐次檢查，這次沒過、下次可能就過了，對應的風控定稿句是「本次檢查未通過」。
- **DE-5 是結構性的來源缺口**：標籤的還原因子要用 `close − change` 當除權息參考價，但 `change` 是否以參考價為基準還沒查證。查證之前，**每一次**判定的除權息因子都不可用，問題不會因為某天的資料比較乾淨就消失。這等同於「除權息沒有當時可用的事件紀錄」，也就是 NE-1 的第三項。
- **歸 NE-1 比較保守**：它的優先序高於 NE-2～NE-7，所以不會被其他原因句蓋過，讓人誤以為只是暫時性的問題。這和 ADR-0012 DE-5 列的「查證前標籤因子不可用（NE-1）」一致。
- **字面已經條件化**（風控 §8-3）：NE-1 的「詳細」改用「句 1 常駐＋句 G 條件式」的寫法。句 G 依 `pit_gaps` 列出**實際還缺的項目**，所以在前瞻累積期，如果只剩 DE-5 沒解決，畫面上只會顯示「除權息還原所需參考價欄位的定義查證」。第四版提到的「比實情更悲觀」的問題，因此解除。

**`pit_gaps` 的判定**（依固定順序輸出；NE-1 成立 ⇔ 清單非空）：

| 項目 | 成立條件 |
|---|---|
| `pit_universe` | 判定期間內，有任何一個決策日沒有有效的 PIT 上市名單快照。缺漏後沿用前一份在 5 個交易日以內仍算有效；尚未有 D0 時，這項必定成立 |
| `pit_classification` | 同上，對象換成產業分類快照 |
| `pit_ex_dividend` | 同上，對象換成除權息公告快照（`TWT48U_ALL`） |
| `de5_unverified` | DE-5（`change` 是否以除權息參考價為基準）尚未查證完成 |

- **一致性要求**：如果判定邏輯認定 NE-1 成立，但 `pit_gaps` 是空的，代表程式本身有矛盾。這時改判 NE-6（`data_quality`），並寫入錯誤紀錄，**不得**輸出一個「NE-1 但沒有缺口」的狀態。
- **`accumulation_start` 為 null**（還沒有 D0）時：前三項一定成立，句 2 改用風控定稿的句 2'。
- **備選方案（v1 不採用）**：在第 t 日就把「持有期內已公告除權息」的成分股排除在籃子外，可以完全不需要因子。但這是新的方法版本（`method_version` 要變、m 要加 1），而且要先確認除權息公告的提前量，所以只記錄、不採用。

**呈現方式**：

- 主視圖和「詳細」都**不列出任何比例數字**；API 的 `historical_stat` 與 `gate_checks` 回傳 null。
- 「未達門檻」這句**不得**用在這一態（風控 §5-4）。
- 各原因句（NE-1～NE-8、`pending_review`）都採用派工單 §5-4 與 §6.1 的風控定稿。

**`failed`**：前提全部成立（NE-1～NE-8 都不成立），已通過 `pending_review`，統計也算過了，但下列任一項不成立：

| # | 條件 |
|---|---|
| G1 | N ≥ 150，而且 N_eff ≥ 60（風控暫定 60，這裡調嚴為 150） |
| G2 | p_net 的 Wilson 下界 > b，**而且** block bootstrap（區塊長度 4）的下界 > b；兩者的信賴水準都是 1 − 0.05/m |
| G3 | **p_net − b ≥ 5 個百分點**（事先訂定的最小效果量） |
| G4 | 置換檢定 p 值 < 0.05/m；扣成本後的平均超額報酬點估計 > 0 |
| G5 | 各 126 日段中，至少前半段與後半段的 p_net 都 > b；5 種相位的 p_net 都 > b；剔除最常出現的族群之後，p_net 仍 > b |
| G6 | 最近 12 個月（約 49 個樣本）的 p_net > b |

- 呈現方式：主視圖用風控定稿的降級句；「詳細」照實列出 k／N、四個數字與區間。

**`passed`**：前提全部成立，已通過 `pending_review`，而且 G1～G6 全部成立。

- 呈現方式：主視圖用風控定稿的歷史句（p_net 對 q_net）；「詳細」列出四個數字、定稿四句、區間、檢定方法、各段結果、成本參數與查證日期，以及 Buy & Hold 對照。
- 極端事件註記只在這一態、只放「詳細」。

**轉態規則**：

- 每完成一個新樣本就重算一次。
- 從 `passed` 變成 `failed` 是自動、立即的。
- 從 `failed` 變成 `passed`，只在季度檢視時處理，並須經 qa-reviewer 確認。
- 每個 `method_version` 第一次離開 `not_evaluated` 時，一律先進入 `pending_review`，拿到風控書面 APPROVE 並經 CLI 寫入核准紀錄之後，才會轉成 `passed` 或 `failed`。
- 任何狀態下，只要 NE-1～NE-8 有任一成立，都立即回到 `not_evaluated`。

## 7. 族群內成分股列示（QR-5）

### 7.1 v1：只描述，不評價

- 排序依據是成分股自己的近 L 日漲跌幅（v1 為 5 日，已依 §2.4 排除除權息），和族群排名用的**是同一個已發生變數**。族群的 R_L 就是這些數字的等權平均。
- 同分時依代碼排列；不使用任何第二變數。
- 支持風控 §4.1f 的建議：列出「漲跌幅最大 2 檔＋最小 1 檔」。這樣呈現的是族群內的離散程度，比只列前 3 檔更誠實。
- 不附歷史比例，也不附任何規則引擎輸出。這份清單不宣稱任何未來性質，所以**不需要回測**。成分股層級的比例**不計算、不呈現**。
- 要讓 CEO 知道：排在最前面的，必然是已經漲最多的股票；個股的週報酬常見短期反轉。這就是定稿句「列示順序僅依近 5 日漲跌幅，不代表任何優先順序」存在的理由。

### 7.2 待辦：另立方法論（不在本階段）

- 暫定名稱為「族群成分股觀察條件對照（研究）」。名稱不得含分數、評分、評級、rating。
- 前提：先完成個股層級的驗證，套用和 §6.3 同一套三態門檻，並另外送風控。
- 已知問題：
  - 五條件刻畫的是「拉回」，和動能可能方向相反；
  - 第 6 條依賴持倉狀態；
  - 規則引擎的權重代表優先序，不是機率；
  - 可能和個股頁「本次未支持進場」的結論衝突。

## 8. Look-ahead 與偏誤偵測測試（QR-4）

### 8.1 NE-7 的範圍（以本方法論為準）

- **NE-7 = T1～T9 任一項未通過。** 「通過」要同時滿足兩個條件：
  1. 標記為 runtime 的部分，在**本次判定**中，於真實前瞻資料上實際執行並通過；
  2. 標記為 CI 的部分，在**目前部署的 commit** 上是綠燈。
- 第 2 點的機制由 tech-architect 決定，例如 build 時寫入 `ci_passed_commit`，執行時比對正在跑的 commit。**比對不到就視為 NE-7。**
- **T10 不屬於 NE-7。** 它是 CI 與 import 邊界門：沒過就不得合併。runtime 發生時改走 fail-closed：寫入端直接拋錯，本次判定中止，不產出新統計；如果一直沒有新統計，最後會變成 NE-4。
- **樣本不足時**：runtime 項目依賴統計量（T3a、T8），在 N < 30 時記為 `skipped_insufficient_n`。這種情況只可能發生在 NE-2 成立的期間；依 §6.3 的優先序，此時對外原因必定是 NE-2 或更高優先的原因。N ≥ 150 之後，所有 runtime 項目都必須實際執行，`skipped` 視同未通過。
- **沒有事件可測時**：T5、T6 在前瞻期間內如果沒有發生任何下市或改類，runtime 項目記為 `vacuous`，不算失敗，由 CI 的合成案例覆蓋；報告中要揭露「前瞻期間無下市／改類事件」。
- **紀錄**：每次判定的 T1～T9 結果（`pass`／`fail`／`skipped_insufficient_n`／`vacuous`、seed、數值）都寫進 `sector_gate_checks` 與參數歷程，只增不刪。

### 8.2 測試定義與執行位置

| 方法論 | 測試 | Runtime（每次判定，在真實前瞻資料上） | CI（合成或固定資料） | 位置 |
|---|---|---|---|---|
| T1 | **未來擾動不變性** | 從已評估樣本中隨機抽 50 個決策日 t（seed 記錄），把 `recorded_at > cutoff(t)` 的所有列（價格、名單、分類、事件）換成雜訊，重算第 t 日的母體、C_g、指數、名次與成分股順序，結果必須**逐位元相同** | 同一邏輯套用在合成面板上；另外驗證 `PointInTimePanel` 存取範圍外的資料時必定拋錯 | **兩者** |
| T2 | 向量化與逐日一致 | v1 **不適用**：依 ADR D1，評估器和線上排行共用同一個純函式，沒有向量化版本 | 結構斷言：評估器與線上排行呼叫的是同一個函式物件（沒有第二份實作）。日後如果引入向量化版本，T2 的逐列相等測試必須在 CI 和 runtime **同批**落地 | **CI** |
| T3a | **Shift：注入洩漏的正向對照** | 在同一批前瞻樣本上，故意改用 close t → close t+H 的相對報酬排名（也就是把未來資訊餵進去），算出 p_leak。通過條件：p_leak − p_real ≥ δ_leak，而且 p_real ≤ p_leak − δ_leak。δ_leak 先在 CI 用合成資料校準，再寫進 `method_version` 凍結 | 在已知無優勢的合成資料上，p_leak 必須大幅高於 p_real；在已知有洩漏的管線上，p_real 必須被判定為疑似洩漏（teeth test） | **兩者** |

| T4 | **除權息不洩漏** | ① 每一個決策日的除權息排除清單，都要能追溯到 `recorded_at ≤ cutoff(t)` 的公告；在 cutoff(t) 之後才記錄的公告，不得讓任何成分股被排除。② 標籤因子只能用當時保存的快照計算，並且要和從全庫重建的結果一致。③ 評估期間必須真的有除權息事件，否則記為 `vacuous` 並揭露 | 合成路徑必須包含除權息事件，排除與因子的邏輯都要被實際執行到 | **兩者** |

## 12. 回補路徑 (b)：偏誤上界估計方法草案（只有方法，本輪不執行）

**適用情境**：data-engineer 已經找到含已下市個股的歷史日線與主檔（D1、D2），也找到了歷史除權息事件（D4），但**歷史產業分類（D3）仍然缺少**。

如果連 D1、D2、D4 也缺，本方法不適用，只能走路徑 (a)。原因是存活者偏差涉及的是「整檔股票消失」，那一檔的報酬本身就未知，無法用有限區間框住。

**目標**：不去猜分類，而是算出「在所有可能的分類下，第 1 名比例會落在哪個區間 [p_min, p_max]」（部分識別，Manski 型邊界），並以最不利的端點判定。

### 12.1 界定「不確定成員」

1. 蒐集所有**有日期的**分類證據，例如：TWSE 公告的產業類別調整（包含新代碼啟用日）、可取得的歷史快照（公開的網頁存檔、第三方資料集附帶的更新日期）、年報等。每一項證據都要附來源與日期，由 data-engineer 整理。
2. 個股 i 在時點 t 的分類：
   - 如果 t 前後兩份有日期的證據一致，就視為**確定**。這依賴一個假設：兩份證據之間最多只改過一次類，不會改過去又改回來。這個假設必須揭露。
   - 如果不一致，或者 t 落在第一份證據之前，i 在 t 就是「**不確定成員**」，它的候選族群集合 S_i(t) 是證據中出現過的所有族群。沒有任何證據的已下市個股，候選集合就是「所有族群」（最寬鬆，也最保守）。
3. 不確定成員一律**計入 B_EW**，因為它是否屬於市場是確定的。受影響的只有族群歸屬。

### 12.2 每週的判定區間

對每個決策日 t：

1. **族群報酬區間**：每個族群 g 的 R_g，在「不確定成員放進或不放進 g」的所有組合下的最小值與最大值。等權平均的極值可以精確計算：由確定成員出發，依報酬由低到高（算最小值）或由高到低（算最大值）逐一加入不確定成員，只要加入後能讓平均往該方向移動就加入。這一步是 O(n log n)。
   族群是否達到最小成分數與覆蓋率門檻，也用兩個極端（全部不確定成員都計入、全部都不計入）分別判斷。只在其中一種極端下合格的族群，視為「可能參與排名」，一併納入下一步。
2. **第 1 名是否確定**：如果某個族群的區間下界，高於所有其他族群的區間上界，第 1 名就是確定的；否則第 1 名不確定。
3. **標籤區間**：對每一個「可能是第 1 名」的族群，用同樣的方法算出 excess_net 的區間。

| 週次分類 | 條件 | 計入 |
|---|---|---|
| **確定高於** | 所有可能的第 1 名，其 excess_net 下界都 > 0 | p_min 與 p_max 都計入 |
| **可能高於** | 至少一個可能的第 1 名，其 excess_net 上界 > 0 | 只計入 p_max |
| 其他 | — | 兩者都不計入 |

q_gross、q_net 用同樣方法求出區間 [q_min, q_max]。

### 12.3 判定與上界

- **偏誤上界**：p_max − p_min，也就是分類不確定性最多能讓比例移動多少。它和抽樣誤差分開報告。
- **保守判定**：用 p_min 對 max(q_max, 50%) 套 §6.3 的 G1～G6，也就是最不利的組合。信賴區間使用 Imbens–Manski 型的「識別區間＋抽樣誤差」合併區間，下界取 p_min 的 Wilson 下界。
- **可行性門檻**（事先訂定）：如果「第 1 名不確定」或「標籤不確定」的週次超過 20%，或 p_max − p_min 超過 10 個百分點，就判定路徑 (b) **不可行**，因為邊界太寬，沒有資訊量。這時只能維持路徑 (a)。
- **驗證**：前瞻累積滿 1 年後，用 PIT 快照實際觀察每年改類的比例，回頭檢查 12.1 的「最多改類一次」假設，以及不確定成員的集合夠不夠大。如果實際改類比例高於假設，路徑 (b) 的結果作廢。
- **送審**：路徑 (b) 的結果（包括區間、不確定週次比例、可行性判定）必須先送風控，才能影響 `gate_status`；首次轉態也要重送風控。在這之前，路徑 (b) 的一切產出都屬於 §5.4 的內部研究，一律標示「含已知偏誤，不得上畫面」。

2. **偏誤版研究的三種偏誤**方向各不相同，幅度也無法估計（§5.4），只能作內部參考。
3. **檢定力有限**（§6.2）。「未過門檻」代表證據不足，不代表沒有效果。
4. **序列相依**：用 N_eff、block bootstrap、置換檢定緩解，但無法完全消除。
5. **成交假設**：以開盤價、收盤價全額成交；跌停不模擬；滑價只做敏感度分析；手續費用法定上限。
6. **費率尚未查證**，所以一律是 `not_evaluated`。
7. **只用價量資料**，也只含上市股票。
8. **選用 L=5 是為了配合產品一致性**；在統計上，它可能比 L=20 更吵（§3.2）。
9. **除權息排除的代價**：除息旺季會有族群因為成分被大量排除而不列入排行。
10. **成分股依已實現漲跌幅排序**，排在前面不代表之後還會漲（§7.1）。
11. **前瞻期間也會碰到制度變更**，可能需要重新設定 D0（§9）。
12. **已知偏離 backtest-protocol 鐵律 3**：判定資料不切訓練窗（§5.3），**待 CEO 核可**。
13. **T8 標籤打亂安慰劑只作診斷**：在真實資料上，個股層級的動能或反轉本來就會讓它不為 0，所以不拿來判定。判定改用時間平移安慰劑。後者抓得到「不論時點都成立」的結構性偏誤，但抓不到「只在特定時點才出現」的偏誤（§8.2）。
14. **整體覆蓋率只計入缺漏、族群覆蓋率計入全部三類排除**：風控已核可（派工單 §8-1）。另加整卡可計算比例下限，暫定 80%，最終值待旺季量測後提出（§2.3）。在那之前，80% 能不能避免旺季整卡頻繁降級，**還不知道**。
