## 目標

以穩定性與既有體驗修補為主，不加新功能面。六項：

1. 查價容錯（最重要）：航班清單中部分無價格（實測 TPE→SHA，4 筆中 2 筆無價格）時，有價格者照常記錄，無價格者略過並在詳情頁「本次取樣」說明欄顯示「略過 N 筆無價格航班」；全部無價格才算 `no_data`；不得誤判資料源異常、不計斷路器失敗。
2. 同一資料庫不得同時跑兩份排程：第二實例須拒絕啟動或只開網頁不開排程，並說明原因。
3. 「立即查價」後自動更新：按鈕顯示查價中，完成後頁面自動更新；逾時（預設 90 秒）顯示「查價仍在進行，稍後重新整理」。
4. 早退的 403（缺自訂 header）與 400（Host 不符）回應帶與一般頁面相同的安全標頭。
5. 修改舊監看時，過期日期欄位旁提示「此日期已過，請更新」，後端規則不變。
6. 下拉無高亮時按 Enter：只有一筆或第一筆代碼與輸入完全相同則直接選取，否則提示「請用上下鍵選取」。

範圍外：Travelpayouts 備援（需 CEO token）、首頁查詢效能、多使用者、匯率。

## 驗收條件

完整 Given/When/Then 見 PRD「驗收條件」章節（AC-T1 至 AC-K4，對應六塊需求）。摘要：

- 混合清單只記錄有價格者，說明欄顯示「略過 N 筆無價格航班」；全部無價格為 `no_data`；兩者皆不計入斷路器失敗、不使資料源變異常；真正無法辨識的內容仍判失敗。
- 同庫第二實例不執行排程並說明原因；原實例結束後可被接手。
- 立即查價：查價中狀態、完成自動更新、失敗顯示原因、90 秒逾時文案、重複觸發有明確說明。
- 403／400 帶一般頁面的安全標頭（含 CSP），狀態碼與訊息不變。
- 過期日期提示出現與消失；未改動的舊日期仍可儲存。
- Enter：單筆、代碼完全相同直接選取；其餘提示「請用上下鍵選取」且不送出表單。

tech-architect 評估關卡需回覆：

1. 無價格航班的判定邊界與容錯做法（涉及第三方套件解析失敗），是否與 ADR-0002 衝突、是否需補 ADR（PRD 開放問題 1）。
2. 單一排程保證機制、殘留狀態處理、第二實例採降級或拒絕啟動（開放問題 2、3）。
3. 立即查價完成通知的做法與逾時設定（開放問題 4）。
4. 評估通過才可推進至 `build`；若認為某需求不可行，須退回 product-manager 並附理由。

待回覆的預設值：PRD 開放問題 2（預設：降級為只開網頁）、4（預設：90 秒、不中止背景查價）、5（預設：沿用既有失敗呈現）。未覆議則照預設。
