# 任務單：FD-6 探索模式（一個月內哪天最便宜）

- 狀態：done（待 CEO 驗收）
- 發起人：總經理（CEO 定調）
- 目前負責：CEO
- 相關文件：`work/flight-deals-FD-6-PRD.md`、`work/flight-deals-PRD.md`（FD-1，FR-B、FR-D）、`work/flight-deals-FD-5-PRD.md`（人數、艙等、航空、時段、總價標示）、`work/tasks/FD-5.md`（底部待辦 FD-6）、`docs/adr/0002-flight-deals-技術棧與資料源.md`（accepted；D-2 全域每小時上限與單一 worker 節流、C-14、C-17、C-30、FD-5 增補 Decision 9a `no_embedded_results` 為約束）、`apps/flight-deals/README.md`

## 目標

1. 新增「探索」頁：輸入出發地、目的地、來回／單程、月份（今天起 12 個月內，台北日曆）、來回旅程天數（單一固定值）、人數／艙等／航空／去程時段（沿用 FD-5）。
2. 對該月每個出發日各查一次（來回為出發日＋固定天數），一次最多 31 次查詢；背景執行，進度「已查 N／共 M」自動更新。
3. 結果以價格日曆（日期、最低總價、航空、直飛／轉機；無價格標原因：無資料／未內嵌結果／被擋／未查詢）與「最低價前 5 個日期」呈現，每格附 tfs 查票連結。
4. 成本控制：額度不足（本小時剩餘 < 預計次數）拒絕開始並顯示剩餘額度，不做部分探索；同條件 24 小時內直接重看不重查；結果保留 7 天後清除；探索進行中排程掃描與立即查價順延並於 UI 說明；探索結果不寫入監看歷史、不發推播。
5. 從探索建立監看：日曆格與前 5 皆有「建立監看」（固定日期預填），另有「以整月建立彈性窗監看」；皆預填不自動送出。
6. 兩個小項：`no_embedded_results` 比例提示（單一監看連續 3 輪；24 小時占比 >= 50% 且 >= 10 筆的健康頁提示，不告警不進斷路器）；表單「來回＋商務／頭等＋多人」靜態提示。

範圍外：多目的地比較、跨月、價格預測、自動建立監看、匯出、部分探索、取消探索與強制重查（預設不做）。

## 驗收條件

完整 Given/When/Then 見 PRD「驗收條件」章節（AC-I1 至 AC-I9、AC-R1 至 AC-R11、AC-S1 至 AC-S10、AC-W1 至 AC-W7、AC-Q1 至 AC-Q9、AC-H1 至 AC-H8）。摘要：

- 啟動：月份、旅程天數、人數等非法值 422；當月只查今天之後；31 天月份恰查 31 次不超過。
- 進度：自動更新、重開頁面接續、單格失敗不中斷、斷路器轉開或額度用盡標「已中斷」保留已查結果、重啟後標中斷。
- 結果：每格資訊與總價人數標示、無價格原因、前 5 排序、查票連結一致、文案無禁用字、375px 可用。
- 建立監看：預填正確、不自動送出、不繞過驗證。
- 額度與保留：額度不足被拒並顯示剩餘 X 次；24 小時內同條件重看 0 次查詢；超過 24 小時或中斷則重查；7 天清除不影響監看。
- 健康與提示：連續 3 輪標示、50%／10 筆邊界、不告警不進斷路器；表單靜態提示（含無 JS）。

## tech-architect 評估關卡需回覆

1. 資料模型與遷移：探索與逐格結果的存放（含條件相等鍵、航空集合正規化）、7 天清除的觸發與不誤傷、migration 與備份回復慣例（沿用 FD-4／FD-5）。
2. 執行模型：探索與排程掃描、立即查價共用單一 worker 時的順延機制（不丟件、不重複、重啟後行為）；節流與 jitter 沿用；單次探索最多 31 次的強制點；健康頁「下次掃描」在順延期間的顯示。
3. 額度口徑：「本小時剩餘額度」與預計次數的比較，與現有 `queries_used_since` 口徑是否一致；中途額度用盡與斷路器轉開的處理；探索查詢是否計入斷路器（預設 blocked／error 計入、no_data／no_embedded_results 不計）。
4. 進度端點：白名單欄位、`no-store`、輪詢間隔與上限（探索可能超過 90 秒，需另定）、無 `innerHTML`（C-30 精神）。
5. 統計來源：`no_embedded_results` 的「連續 3 輪」與 24 小時占比如何取得（`scan_run.query_results` 是否足夠）、列表 SQL 次數約束（C-34）；探索查詢是否納入占比（預設納入）。
6. 預填機制：從探索帶入新增表單的傳遞方式（不建立資料、不繞過驗證、無 JS 可用）；日曆在 375px 的呈現方式。
7. 是否需增補 ADR-0002 或另開 ADR（尤其單一 worker 順延規則、新資料表）。
8. 評估通過才可推進至 `build`；若認為某需求不可行，須退回 product-manager 並附理由。

## 待回覆的預設值
