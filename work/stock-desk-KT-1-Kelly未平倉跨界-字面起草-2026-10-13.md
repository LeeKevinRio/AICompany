## 0. 讀法

### 0.1 先講程式實際怎麼分類（所有字面都以此為準）

樣本外區段 `[start, stop)`，回測整段 n 根，`window_end = dates[n-1]`，`oos_end_date = dates[stop-1]`。尾段根數 r = n − stop。

| 回合型態 | 程式計入 |
| --- | --- |
| 已平倉，進場 ≥ start 且出場 < stop | 完整回合（進入 p、b） |
| 已平倉，出場 ≥ start 且進場 < stop，但不是上一列 | `excluded_boundary_trips`（含：進場在樣本外之前、出場在樣本外內；進場在樣本外內、出場在 stop 或之後；整段橫跨樣本外） |
| 未平倉（到最後一根仍持有），進場 < stop | `open_trip_at_end`（含：進場在樣本外之前） |
| 其餘（進場 ≥ stop，或已平倉且出場 < start） | 兩個計數都不計 |

r = 0 等價於 `oos_end_date == window_end`（兩者都是同一次匯入寫入的同一組日期，bar 日期互不重複）。

### 0.2 兩個我在起草中確認的事實，會影響字面怎麼寫

1. **fr5-7 的標籤不能只寫「到回測資料最後一根仍未平倉」。** 必須同時帶「樣本外區段結束前已進場」。r > 0 時，尾段才進場、到最後一根仍持有的回合，確實是「到最後一根仍未平倉」，但程式計 0。只寫前半句，會讓顯示值 0 與標籤意思不符，正好是現行瑕疵的鏡像。所以 fr5-7 的所有候選都保留進場條件。
2. **fr5-6 的標籤不能只寫「進場或出場不在樣本外區段內的已平倉回合」。** 完全落在樣本內、或完全落在尾段的已平倉回合，也「進場或出場不在樣本外區段內」，但程式不計。所以必須帶「與樣本外區段重疊」。

## 1. (h) 句改寫

- **用途**：KT-R-1.1、1.4。以程式的分類方式描述排除集合；明示「在樣本外區段結束後才平倉」；錨定「回測資料最後一根」；後半段保持原意。

### 主案（(h)-主）

```
本系統計算樣本外（OOS）回合數時，只計入進場與出場都落在樣本外區段內的完整回合。有兩類回合會被排除在外，並分別另行計數：一類是與樣本外區段重疊、但進場或出場不在樣本外區段內的已平倉回合，這一類涵蓋在樣本外區段結束後才平倉的回合；另一類是在樣本外區段結束前已進場、到回測資料最後一根仍未平倉的回合。這個排除方式，會優先排除掉存續時間較長的回合；這對統計結果會造成什麼方向的影響，目前的證據不足以支持任何方向的判斷。
```

- **字數**：約 207 字（41＋20＋54＋34＋58 逐句手算）。
- **對應條款**：KT-R-1.1（兩類排除集合、明示結束後才平倉、錨點）、KT-R-1.4（後半段保持原意）、KT-R-7(1)（寫「結束前已進場」，不縮寫成「在區段內進場」）、KT-R-7(2)（錨定「回測資料最後一根」）、KT-R-3（兩種 r 皆為真，見下）。
- **與 F-11 L-11 用語一致嗎**：
  - 「進場與出場都落在…內的完整回合」：與 L-11n 第一句一致。
  - 「與樣本外區段重疊、但進場或出場不在樣本外區段內的已平倉回合」：與 L-11a 括號內「與本區段重疊，但進場或出場不在本區段內」同構，僅區段名不同。
  - 「在樣本外區段結束前已進場、到回測資料最後一根仍未平倉」：與 L-11b 括號內「本區段結束前已進場，到回測資料最後一根 … 仍未平倉」同構。

## 4. r > 0 時的事實句

- **用途**：KT-R-5。說明樣本外區段迄日與回測資料最後一根之間的日線不屬於樣本外區段，其中的回合怎麼處理。語氣依 KT-R-9.3：只陳述事實；不附正面理由；不引導使用者為了取得更好的數字去調整日期。
- **渲染條件**：僅當 `window_end` 與 `oos_end_date` 都不是 NULL 且兩者**不同**時（＝ r > 0）。r = 0 時不渲染（見下「r = 0 的處置」）。兩個日期都是同一次匯入寫入的欄位，不需要額外儲存 r。
- **為什麼句子裡不寫 r（尾段根數）、也不寫「長度取決於…」**：Kelly 列沒有儲存 r，反推要靠交易日曆，會是 Kelly 不具備的資訊；KT-R-5 也只要求日期與回合處置。F-11 的 L-18a 有 r 與「取決於…」那句，Kelly 側不跟，兩者的差異是資料欄位的差異，不是立場的差異。

**主案**

```
樣本外區段迄日 {oos_end_date} 之後、至回測資料最後一根 {window_end} 為止的日線，不屬於樣本外區段。在這段期間內才進場的回合，既不計入樣本外的完整回合，也不計入兩類被排除的回合。
```

- **字數**：約 96 字（第一句 58，第二句 38；日期以 10 字計）。
- **對應條款**：KT-R-5（日期之間的 bar 不屬於樣本外區段；其中的回合不計入 Kelly 輸入）、KT-R-9.3（語氣）、KT-R-7(3)（日期取自同一次寫入）。

## 7. 需風控特別判斷的點

- **J-1　(h) 後半段與開頭子句逐字保留，算不算「引用現行 (h)」（KT-R-4）？**
  KT-R-1.4 要求後半段「保持原意」，我選擇逐字保留，以避免改字造成原意漂移；開頭子句「本系統計算樣本外（OOS）回合數時，只計入」也同字。若風控認為逐字沿用也算引用，備案 C 把後半段換成 L-11n 的句型（代價：後半段要重審）。
- **J-2　「這一類涵蓋在樣本外區段結束後才平倉的回合」在 r = 0 是否可接受？**
  r = 0 時沒有這種回合，「涵蓋」是範圍定義（空集合上仍真），我刻意不用「包括」「其中有」這類容易被讀成存在宣稱的動詞，也不用 `REJECTED_LITERALS` 禁止的「（若有）」。若風控認為 r = 0 的讀者仍可能讀成「應該有」，唯一不犧牲 KT-R-1.1「必須明示」的做法是讓 (h) 隨 r 切換兩個版本，我不建議（Kelly 逐字定稿變兩份）。
- **J-3　§4 第二句只寫「在這段期間內才進場的回合」，不照 KT-R-5 原文寫「其中的回合不計入 Kelly 輸入」。**
  理由見 §4：樣本外內進場、尾段出場的回合確實被計數。與 F-11 起草 0.3 第 1 點同一個發現。
- **J-4　日期標籤不用「迄日」。** 理由見 §3：使用者選的迄日可能晚於實際最後一根。
- **J-5　r = 0 時 Kelly 側是否顯示「無」句。** 應與回測頁 O-5（L-18b 或省略）的裁示一致，請在同一次裁示中一併定。
- **J-6　`window_end` 為 NULL 的舊列。** `window_start`／`window_end` 在 schema 中與其他欄位一起宣告，且有一份 `ALTER TABLE` 補欄對照（`store.py:99-100`）；這表示很可能存在補欄前寫入、值為 NULL 的列。這些列的 (h) 與 fr5-7 一旦引用「回測資料最後一根」，就沒有日期可顯示，違反 KT-R-5。處置選項：(a) 使用 §3 的 NULL 降級備援句；(b) 這類列不顯示兩個計數與 (h)（後端行為，非字面）；(c) 已確認不存在這類列則忽略。我沒有驗證舊列是否真有 NULL，請 dev-lead 先查。
- **J-7　新 (h) 與 F-11 L-11 共用子句是否可接受**（§5 末段）。
- **J-8　§4 句子的顯著度與位置**（§4 末段）：建議獨立 `text-sm` 段落而非列內 `note`。
- **J-9　fr5-6 去掉「跨界」二字、fr5-7 去掉「期末」二字。** 我認為這是 KT-R-1.3 的正確提案，因為兩個詞都在新定義下不再準確；風控若傾向保留「跨界」作為使用者熟悉的詞，需要給出它在右界跨出時仍為真的定義，我沒有找到不增加字數的寫法。
