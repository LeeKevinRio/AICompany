## 2. 行內修正：兩案比較與推薦

### 2.1 比較

| 面向 | 案 A：點欄位就地編輯（Enter 存、Esc 取消） | 案 B：每列「修改」切換成可編輯列＋「儲存／取消」 |
| --- | --- | --- |
| 找得到嗎（您這次的痛點） | **差**。畫面上沒有任何字說「這裡可以改」，只能靠使用者亂點；與首頁 `▸` 無字入口同一個問題 | **好**。每列有字面按鈕「修改」 |
| 手機 375px | 欄位小、點到的是文字不是輸入框，要靠「點了才變框」；沒有實體 Enter 鍵的情境下，存檔動作不明顯（行動鍵盤的「完成」不一定等於儲存） | 輸入框一次全開、直接是 44px 高的框；「儲存」是明確的大按鈕 |
| 要改兩個以上欄位 | 每個欄位各存一次（後端 PUT 是整筆覆寫，改三個欄位就是三次整筆覆寫，且兩次之間狀態不一致） | 一次儲存、**一次 PUT**，PRD §4 的競態風險只發生一次 |
| 錯誤顯示 | 後端驗證失敗時，是哪個欄位、要不要還原，不直覺 | 留在編輯列，欄位下方顯示後端原文，輸入保留（PRD FR-3） |
| 取消 | 只能 Esc（手機沒有） | 有「取消」按鈕 |
| 誤觸 | 點到就進入編輯，容易誤進 | 要按「修改」才進入 |
| 鍵盤 | Enter／Esc 順 | **同樣支援 Enter 存、Esc 取消**（第 4.3 節），兩案鍵盤體驗相同 |

### 2.2 推薦：案 B，並保留案 A 的鍵盤便利

- 推薦理由三條：**入口有字**（解 CEO「無法修改」）、**一次存**（一次 PUT）、**手機有明確的儲存／取消**。
- 不採案 A 的主因是第一條；它在桌機滑鼠上最快，但這頁的首要使用情境是「CEO 找得到並改得動」。
- 案 B 的代價：進入編輯多點一下「修改」。可接受：持倉修改是低頻動作，且換來防誤觸。

## 3. 版面

斷點 **`lg`＝1024px**（與首頁的 `md`＝768px 不同，理由見 0 節第 3 項與第 9 節 D3）。**320～1920px 都不得出現橫向捲動**；列表容器 `overflow-hidden rounded-md border border-neutral-800`，不加 `overflow-x-auto`、不設 `min-w` 大於容器的值。

### 3.1 桌機（≥ 1024px，內容寬 992px）：6 欄表格

結構沿用首頁 `PositionsTableView` 的作法（`role="table"` ＋ grid 列，不用 `<table>` 也可；由 frontend-engineer 決定，需保留表格語意）。

```
ROW_GRID（lg）：
grid lg:grid-cols-[minmax(150px,1.3fr)_minmax(90px,0.7fr)_minmax(110px,1fr)_minmax(130px,1fr)_minmax(140px,1.4fr)_208px] lg:gap-x-3 lg:items-center
列容器：px-3 py-2.5，並預留 border-l-2 border-transparent（切換編輯態時不位移）
```

| 欄 | 寬 | 對齊 | 顯示模式 | 編輯模式 |
| --- | --- | --- | --- | --- |
| 代號名稱 | `minmax(150px,1.3fr)` | 左 | 第 1 行代號連結、第 2 行名稱（`truncate`） | 不變 |
| 市場 | `minmax(90px,0.7fr)` | 左 | 第 1 行市場、第 2 行幣別代碼 | 不變（純文字，不可改） |
| 數量 | `minmax(110px,1fr)` | 右 | 數值 | 輸入框＋下方提示槽 |
| 平均成本（原幣） | `minmax(130px,1fr)` | 右 | 帶幣別符號的數值 | 輸入框＋下方提示槽 |
| 備註 | `minmax(140px,1.4fr)` | 左 | 文字或「—」 | 輸入框＋下方提示槽 |
| 操作 | 固定 `208px` | 右 | 「修改」「移除」 | 「儲存」「取消」「更多」 |

- 最小合計：`150+90+110+130+140+208＝828px`＋欄距 `5×12＝60px`＋列內距 `24px`＝**912px**；1024px 視窗內容寬 992px 放得下（餘 80px 由 `fr` 分配）。**768～1023px 放不下，所以該區間改用第 3.2 節卡片。**
- 表頭列：`hidden lg:grid bg-neutral-900 text-neutral-400 text-sm font-medium px-3 py-2`，標籤**沿用現有字面**：`代號`、`市場`、`數量`、`平均成本（原幣）`、`備註`；操作欄表頭為 `sr-only`「操作」。**第一階段表頭不可點排序**（PRD 第二階段）。
- 列間 `border-t border-neutral-800 first:border-t-0`；不加斑馬紋、不加 hover 底色（沿用首頁規範 §11 與捲軸規範第 2 節）。
- 列高：顯示模式約 64px（`py-2.5`＋44px 按鈕）；編輯模式約 84px（含提示槽 16px）。（估算）
- 桌機按鈕也維持 `min-h-11`（44px）：與首頁展開列按鈕在桌機降為 `md:min-h-8` 的作法**不同**；這頁按鈕是主要操作，且同一套 class 手機桌機通用，少一個斷點變體。若 CEO 覺得桌機偏大，可降為 `lg:min-h-9`，不影響版面。

### 3.2 手機／平板（< 1024px，以 375px 為基準，內容寬 343px）：每檔一張卡片

不加卡片外框（沿用首頁規範 §2.2）：列與列之間 `border-t border-neutral-800`，卡片 `px-3 py-3`，預留 `border-l-2 border-transparent`。768～1023px 沿用同一套卡片、隨容器變寬，不另做版型。

**顯示模式（由上而下，4 行；估算高約 124px）**

```
行 1（flex，items-start，justify-between，gap-3）
  左（min-w-0）  第 1 行：[2330]（代號連結）  台股 · TWD（text-xs text-neutral-400，與代號同一行）
                 第 2 行：台積電（text-xs text-neutral-400，truncate；查不到就留空）
  右（flex-none）[修改] [移除]   兩顆各 min-h-11、px-4、間距 gap-3（12px）

行 2（grid grid-cols-2 gap-x-3）
  數量                 平均成本（原幣）      ← 標籤 text-xs text-neutral-400
  1,000                NT$880.00            ← 數值 text-sm text-neutral-100，tabular-nums

行 3（單行 flex，gap-2）
  備註   買入原因…或「—」                    ← 「備註」標籤 text-xs text-neutral-400，值 text-sm text-neutral-300，break-words
```

- 左欄在 375px 約得 `343-24(內距)-約140(兩顆按鈕＋間距)-12(欄距)≈167px`，代號＋市場／幣別同行放得下；名稱過長 `truncate`，完整名稱在個股頁。
- 兩顆按鈕**並排在右上**：省一行高度（每檔省約 56px，6 檔省約 340px）。誤觸風險由「移除」的紅框、12px 間距、確認視窗三層擋住（R1）。
- 市場／幣別在手機不開獨立欄，併入代號行；桌機與手機**資訊量相同**。

**編輯模式（估算高約 290px）**

```
行 1：左同顯示模式；右側不放按鈕（顯示 市場 · 幣別 即可，已在左欄）
行 2（grid-cols-2 gap-x-3）
  數量 [ 1,000      ]          平均成本（原幣） [ 880.00    ]
       （提示槽 16px）                          （提示槽 16px）
行 3（整列）
  備註 [ …………………………………… ]
       （提示槽 16px）
行 4（flex gap-3）
  [      儲存      ] [      取消      ]  更多
   flex-1 主按鈕      flex-1 次按鈕       文字鈕 min-h-11 px-2
```

- 輸入框的**可見標籤**手機一律顯示（`<label>` 在 `lg` 以下可見、`lg` 起 `sr-only`）；桌機因為有表頭，標籤隱藏但保留給螢幕閱讀器。
- 輸入框字級手機用 **`text-base`（16px）**、桌機 `lg:text-sm`：iOS Safari 對 <16px 的輸入框聚焦時會自動放大頁面，造成版面跳動；站內其他表單用 `text-sm`，那是既有問題，不在本案範圍，但新輸入框不再重蹈。

### 3.3 新增持倉、CSV 匯入：可收合區塊

兩者共用同一套外觀（做成同一個 `DisclosureSection` 元件，由 frontend-engineer 決定命名）：

```
外框   rounded-lg border border-neutral-800（沿用現有 section 外框）
標題鈕 flex min-h-11 w-full items-center justify-between px-5 py-3 text-left
       h2 字級：text-lg font-semibold text-neutral-100
       右側 ▸ 圖示（沿用首頁展開鈕的 chevron 與 group-aria-expanded:rotate-90、僅動 transform、motion-reduce:transition-none）
內容   p-5 pt-0；收合時用 hidden 屬性（元素仍在 DOM，aria-controls 才解析得到，沿用首頁展開列作法）
```

- 標題鈕：`<button type="button" aria-expanded aria-controls>`，整條可按；`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-400`。
- **新增持倉**：有持倉＝收合；空庫存＝展開（且不放第二顆「新增持倉」按鈕，見第 5.3 節）。標題「新增持倉」；原 `ManualAddForm` 內部的 `<section>` 外框與 `<h2>「手動新增部位」` 移除（由區塊標題取代）；送出按鈕字面「新增部位」→「新增」；欄位、驗證、揭露句、`SymbolCombobox` **一律不動**。
- **頁首「新增」按鈕**（PRD FR-6 的錨點）：按下＝展開「新增持倉」＋捲動到區塊＋游標落在代號輸入框。樣式用站內主按鈕 `min-h-11 rounded-md bg-neutral-100 px-4 text-sm font-medium text-neutral-900 hover:bg-white focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-400`；位置在 h1 同列右側（手機同列，h1 只有 2 字不會擠）。捲動用 `behavior: auto`，不做平滑捲動動畫（`prefers-reduced-motion` 一致）。
- **CSV 匯入**：標題「CSV 匯入」，預設收合（`aria-expanded="false"`）；展開後內容沿用（下載範本連結、檔案選擇器、「上傳並匯入」、錯誤明細表、成功訊息與「回總覽查看」）。**刪除內部說明句**「下載範本並依格式填寫後上傳，即可一次匯入多筆部位。」（PRD FR-10 少字；此句 PRD 未點名，列第 9 節 D5）。

### 4.2 按鈕樣式（全部沿用站內既有 class，**不新增色**）
