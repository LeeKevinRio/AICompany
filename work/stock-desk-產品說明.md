# Stock Desk — 股票訊號與部位決策輔助台 - 產品說明

**本工具為研究與教育用途，不產生投資建議、目標價或操作指引。**

---

## 產品定位

Stock Desk 是一套本機執行、單人使用的投資分析輔助系統，幫助使用者在同一畫面上整合：
- **實際持倉部位**（手動輸入或 CSV 匯入）
- **市場訊號**（技術面指標、風險度量）
- **規則式建議卡**（可解釋、可反駁、附失效條件的行動選項）
- **風險上限檢查**（單一標的佔比、單筆虧損上限等五項上限的三態評估）
- **槓桿 ETF 拆解**（已發生的報酬衰減與情境推估）
- **回測工具**（MA Cross 策略、樣本內外分列、Buy & Hold 對照）
- **警示系統**（價格、訊號、風險上限的自動監測與推播）
- **離線示範模式**（合成資料集，不適用於決策）

**非自動下單系統、非預言機、不保證報酬。**

## 五個頁面與功能區塊

### 第一頁：投資組合總覽 `/`

顯示最近一次查詢的持倉摘要與監測面板：

| 項目 | 說明 |
| --- | --- |
| 投資組合摘要卡 | 總資產（已估值部位市值）、未實現損益、標的貢獻、匯率貢獻 |
| 持倉明細表 | 每筆持倉的標的、市場、成本、現價、市值、P&L、P&L% |
| 風險儀表 | 投資組合級的五項風險上限狀態（總覽頁缺逐檔輸入，五項在此頁皆恆為 not_evaluable，原因各異；逐檔的實際判定在個股頁建議卡） |
| 待處理警示面板 | 未確認警示事件（`unacknowledged=true`），可逐筆確認或標記已處理 |

**資料新鮮度**：
- 首頁只抓取 health 狀態、投資組合摘要、設定、待處理警示事件，不抓建議卡。
- 標註資料時間（`as_of`）與來源（TWSE/TPEx/FinMind/快取）。
- 若標的無可用價格，該筆部位在市值合計中被排除（清楚標註「無法估值」）。

### 第二頁：標的詳情 `/position/[symbol]`

單一標的的深度分析頁面，包含四個區塊：

#### 區塊一：日K線與均線圖表

- **X 軸**：交易日期
- **Y 軸**：收盤價（標的自身貨幣）
- **K 線體**：OHLC 蠟燭圖
- **移動平均線**：5 日、20 日、60 日線（若可計算）

**覆蓋日期**：依後端資料可得性；資料不足時顯示「資料不足」提示與原因。

**資料來源標示**：右上角顯示「資料時間 | 來源」與新鮮度徽章（fresh / backup / cached_stale / unavailable）。

#### 區塊二：建議卡（Advice Card）

規則式評估結果，包含以下欄位（全部欄位都始終存在）：

| 欄位 | 內容 | 讀法 |
| --- | --- | --- |
| **Action** | `add` / `hold` / `reduce` / `stop_loss` / `take_profit` / `insufficient_data` | 主要建議。`insufficient_data` 的實際條件見下方「何時顯示 insufficient_data」——注意防禦型建議在資料不足時仍會輸出，並非一律降為 `insufficient_data`。 |
| **Confidence** | `low` / `medium` / `high` | **非勝率、非機率**。反映規則一致性（matched rules 的權重分布）與資料完整度。高信心 = 多條規則共識且資料充分；低信心 = 證據稀薄或數據缺失。 |
| **Matched Rules** | 規則 id、名稱、權重、說明、反駁點、失效條件 | 實際觸發的規則列表。權重總和最高的建議方向決定最終建議。 |
| **Weight** | 浮點數 | **非機率、非勝率、非預期報酬**。純粹的規則優先序排名；同一建議下權重高表示該規則對應的訊號更強，不表示收益率。 |
| **Counterarguments** | 文字 | 該規則的潛在反駁（例如「但若波動率異常高……」）。 |
| **Invalidation Conditions** | 文字 | 該規則失效的條件（例如「若成交量未創新高」）。 |
| **Limits Check** | 五項風險上限的三態檢查結果 | 下詳。 |
| **Action Weights & Direction Weights** | 詳細的規則分組權重 | 供高手檢查決策過程。 |
| **Quantity Range** | `[下界, 上界]` 股數 及 `restores_compliance` 布林 | **僅為參考**，基於風險上限推導。`restores_compliance` 表示該賣出量是否足以讓超界的上限恢復合規。沒有建議時為 null。 |
| **Disclaimer** | "本工具為研究與教育用途，非投資建議" | 固定文案，隨每張卡片。 |

**重點讀法**：
- **Confidence 不是勝率**：信心 high 只表示規則充分且共識高，不表示建議有 80% 獲利機率。
- **Weight 不是機率**：weight=0.8 不表示 80% 獲利，只表示該規則在排序上優先度為 0.8（相對於其他規則）。
- **假設與限制**：建議卡下方會列出風險預算輸入的假設（總資產以已估值部位為代表、無現金/融資資料、匯率缺失等），必須展開閱讀。

**何時顯示 insufficient_data**：
- 防禦型建議（reduce / stop_loss）即使資料不足 50% 仍會輸出；但 add 建議會停止評估。
- 所有規則都未命中，且評估規則少於 50%。
- 無任何規則被評估。

#### 區塊三：五項風險上限檢查（Limits Check）

建議卡內的表格，每項上限一列。五項上限中**第 2、5 條目前恆為 not_evaluable**；第 1、4 條一律實際生效；**第 3 條在使用者於設定頁輸入「帳戶總淨值（新台幣）」後才實際生效**，未輸入時維持 not_evaluable。全部 passed 不等於部位安全。

| 上限編號 | 上限名稱 | 狀態 | 觀測值 / 閾值 | 備註 |
| --- | --- | --- | --- | --- |
| 第 1 條 | 單一標的佔比上限 | `passed` / `violated` / `not_evaluable` | 現有佔比 / 上限佔比 | 單一標的市值 ÷ 總資產 ≥ 上限時 violated |
| 第 2 條 | 單一產業佔比上限 | — | — | 目前恆 `not_evaluable`（positions 無 sector 欄位） |
| 第 3 條 | 總曝險上限 | `passed` / `violated` / `not_evaluable` | 已估值部位市值合計 ÷ 自報帳戶總淨值 / 上限比例 | 需使用者在設定頁輸入帳戶總淨值；未輸入、輸入滿 30 天未更新、或任一部位無法估值時為 `not_evaluable` |
| 第 4 條 | 單筆最大可承受虧損 | `passed` / `violated` / `not_evaluable` | 該標的最大虧損額（ATR×停損倍數） / 上限額 | 若 `add` 同時有 violated，建議降為 `hold` |
| 第 5 條 | 分數 Kelly 部位上限 | `passed` / `violated` / `not_evaluable` | Kelly 估計部位 / 上限 | Kelly 輸入無來源，通常 `not_evaluable` |

**三態含義**：
- `passed`：觀測值在上限內，該上限不構成障礙。
- `violated`：觀測值達到或超越上限（≥ threshold），預算已用完，不建議 `add`。
- `not_evaluable`：無法計算（缺必要輸入欄位或沒有該數據源）；不作為通過也不作為違反，只說無法評估。

#### 區塊四：槓桿 ETF 專章（若該標的為日度重置型槓桿/反向 ETF）

若持倉標的被標記為 `leveraged_etf` 型式（不含 `futures_etf`），本區塊展示三層資訊：

##### 1. 持有期間統計

| 欄位 | 內容 |
| --- | --- |
| opened_at | 建倉日期（YYYY-MM-DD） |
| first_bar_date / last_bar_date | 建倉後的可用日線起訖 |
| bars_since_opened_at / holding_trading_days / holding_days | 持有的交易日數與日曆日數 |

若建倉日之後沒有 ETF 日線可得，此區塊回報 `insufficient_data`。

##### 2. 報酬衰減拆解（已發生，非預測）

拆解 ETF 實現報酬 vs. 「naive 預期」（指數倍率 × 指數報酬）的差值：

| 項 | 含義 | 讀法 |
| --- | --- | --- |
| actual | ETF 實現報酬 % | 建倉日收盤到當日收盤的報酬率 |
| naive | 預期報酬 % （倍數 × 指數報酬） | 如果 ETF 完美追蹤每日目標倍數，應該的報酬 |
| gap | 實際 - 預期 | 正值 = 正向偏離，負值 = 衰減損失 |
| fee_effect | 費用效應 | −年費 × 交易日數 ÷ 252（線性近似） |
| reset_effect | 日度重置效應（實測）| 純粹因日度重置與波動率導致的衰減 |
| residual | 其他 | 追蹤誤差、融資成本、配息處理、價格來源差異等 |

**必讀假設與限制**（章節開頭明列）：
- 所有數字基於共同交易日的收盤價，不是個人成交價，僅描述基金機制。
- 費用是線性近似，非精確逐日累計。
- 理論近似式 `drag ~= -0.5 * beta * (beta - 1) * sigma^2 * T` 與實測重置效應並列，差異照實呈現，不做調整。
- σ 的穩定度低，觀測數少時此估計極不穩定；`observations` 欄位一併提供。
- 未含使用者端的交易稅費與匯率影響。
- **該欄數字描述的是已經發生的機制，不是預測也不構成操作指引。**

##### 3. 情境推估（假設場景）

若 index bars 可得，進一步模擬「平坦指數」等場景下的衰減。這些是**假設情境**，非預測。

若 index bars 不可得，此區塊回報 `insufficient_data`。

## 回測頁 `/backtest`

單一標的的 MA Cross（均線交叉）策略回測：

### 表單輸入

| 欄位 | 說明 | 約束 |
| --- | --- | --- |
| Symbol | 標的代號 | 必填 |
| Market | TW / US | 選擇市場 |
| Start Date | 回測開始日期 | 必填；需在後端資料可得範圍內 |
| End Date | 回測結束日期 | 必填；≥ Start Date |
| 類型（instrument_type） | 股票 / 一般 ETF / 槓桿型 ETF / 期貨型 ETF | 影響證交稅率（股票 0.3%、ETF 0.1%） |
| 策略 | 固定為均線交叉（MA Cross） | 目前唯一支援的策略，下拉選單不可更改；20/60 日窗口寫死在程式碼，表單無法調整 |
| 起始資金 | 回測起始權益 | 預設 1,000,000 |
| 樣本內天數（train_size） | **交易日根數**，非日期 | 預設 252（約一年）。這是每一折訓練窗的長度，不是分割日期 |
| 樣本外天數（test_size） | **交易日根數**，非日期 | 預設 63（約一季）。這是每一折測試窗的長度 |
| 自訂本次滑價 | 勾選後可覆寫本次回測的滑價 | 不勾選則沿用「設定」頁的費率 |

歷史長度不足以切出至少一折（train_size + test_size）時，後端直接回 `insufficient_data` 並說明所需根數，**不會退而求其次給你一份只有樣本內的報告**——這是刻意的設計，避免把未經樣本外驗證的結果當成回測結論。

### 回測報告輸出

報告為 JSON，分為**樣本內**（in_sample）與**樣本外**（out_of_sample）兩段，每段均包含策略與 Buy & Hold 基準的對照。**Buy & Hold 為未計交易成本的被動基準，策略側已扣除完整成本模型**（台股手續費 0.001425 雙邊、證交稅 0.003／ETF 0.001、美股賣出監管費、滑價可調）。

#### 績效指標

| 指標 | 計算方式 | 讀法 |
| --- | --- | --- |
| observations | 交易日數 | — |
| start_equity / end_equity | 起始/終止淨值 | — |
| total_return % | (end - start) / start | 持有期間完整報酬 |
| CAGR % | 複合年均報酬率 | 年化後的報酬 |
| annualized_volatility % | 日報酬的年化標準差 | 風險度量 |
| Sharpe / Sortino | (年均報酬 - 無風險率) / 年化標準差 | 風險調整後的報酬；Sortino 只計下側風險 |
| max_drawdown % | 最大回撤（負值） | 策略史上最大虧損幅度 |
| max_drawdown_peak_date / trough_date | 回撤的峰值與谷值日期 | 何時開始、何時最低 |
| win_rate % | 獲利筆數 / 平倉筆數 | **平倉交易** 才計入；未平倉持倉不計 |
| profit_factor | 總獲利 / 總虧損 | > 1 表示獲利交易的絕對值較大 |
| num_trades / num_closing_trades | 全部交易 / 平倉交易 | — |
| turnover | 總成交金額 / 平均淨值 | 交易頻率度量 |

#### 樣本內 vs. 樣本外

- **in_sample**：用於優化的歷史數據。**不能用此結果判斷真實未來表現。**
- **out_of_sample**：未曾參與參數選擇的數據。**這才是較不受參數選擇污染的一段。**

**必讀**：
- 所有數字皆自過去，無法預測未來。
- 策略側已計交易成本；Buy & Hold 為未計成本的被動基準，兩者不可直接比較獲利差異。
- 費率（手續費、稅費、規費）尚未經主要來源查證（verified_on 為 null），本報告的成本相關數字應視為待查證狀態。
- 只有一個內置策略（MA Cross）；其他策略暫無。
- 樣本內績效優異不代表樣本外會重複。
- 回測為歷史模擬結果，內含成交假設與費率假設，不代表未來績效。

## 警示系統

自動監測價格、訊號、風險上限，超過閾值時推播事件。

### 四種規則類型

1. **`price_above`（價格高於門檻）**
   - 監測：標的最新收盤價
   - 條件：收盤價 > 門檻（門檻以標的原幣計價）
   - 推播：「<symbol> 最新收盤價 <觀測值> <幣別>，高於設定的門檻 <門檻>」

2. **`price_below`（價格低於門檻）**
   - 監測：標的最新收盤價
   - 條件：收盤價 < 門檻
   - 推播：「<symbol> 最新收盤價 <觀測值> <幣別>，低於設定的門檻 <門檻>」

3. **`signal_condition`（訊號條件）**
   - 監測：技術與風險訊號（例如 `rsi14.last`、`ma20.last`、`drawdown.max_drawdown`）
   - 條件：訊號值 <運算子> 門檻，運算子與建議引擎的規則共用同一套詞彙
   - 推播：「<symbol> 的 <欄位名>（中文說明） 目前為 <觀測值>，符合設定的條件 <運算子> <門檻>」

4. **`risk_limit_breach`（風險上限被觸發）**
   - 監測：五項風險上限
   - 條件：自動監測違反狀態
   - 推播：「<symbol> 觸發風險上限：第 N 條（名稱）。<details>」

### 規則管理

| 操作 | 位置 |
| --- | --- |
| 新增規則 | 設定頁 → 警示規則區塊 → 新增 → 選類型 → 填表 → 保存 |
| 刪除規則 | 設定頁 → 警示規則區塊 → 點擊規則 → 刪除 |
| 設定推播通道 | 環境變數設定（見下） |

### 推播通道

| 通道 | 環境變數 | 備註 |
| --- | --- | --- |
| Discord | `ALERT_DISCORD_WEBHOOK_URL` | 若未設定則跳過 Discord 推播 |
| Telegram | `ALERT_TELEGRAM_BOT_TOKEN`, `ALERT_TELEGRAM_CHAT_ID` | 兩者都需設定才會送出；祕密不寫進設定頁，只來自環境變數 |

### 冷卻時間

同一規則在短時間內重複觸發時，只推播一次；冷卻期間（預設 60 分鐘，可設定）內不再推播。防止「同一訊號持續在閾值邊界抖動」導致推播洪泛。

### 待處理警示

首頁的「待處理警示面板」列出未確認的警示事件（`unacknowledged=true`，預設限制 200 筆），可逐筆點擊確認（標記已處理）。

## 技術細節與限制

### 資料層

**降級鏈**：每次都先試 live provider (TWSE/TPEx/FinMind)，最後一層是 SQLite 本機快取，**即使超過 TTL 仍會返回**。
- TWSE/TPEx：官方、準時、無額度限制（台灣市場）。
- FinMind：備援；需 `FINMIND_API_TOKEN` 環境變數；若未設定該 adapter 明確回傳 unavailable。
- SQLite 快取：標記 `is_within_ttl` 用於顯示新鮮度，但過期仍會使用。
- unavailable：無任何來源時，回傳 200 且標記 status=unavailable（不是 5xx 錯誤）。

**US 市場**：
- 定義上支援 `Market="US"` 與 `Currency="USD"`，但無美股 data provider adapter 實作。
- 嘗試查詢 US 標的會降級至快取，最終回 `unavailable`。
- 預期後續實作。

**FX 匯率**：
- 已實作台灣銀行 USD/TWD 日線匯率 adapter，取得 1 週回溯資料。
- 估值層會自動做幣別換算，將未實現損益拆成「標的貢獻／匯率貢獻」。
- 建議卡層的風控輸入尚未接 FX（位置：`advice/book.py`），故外幣持倉的價格類上限會報 not_evaluable。
- **未查證揭露（與回測費率同一類問題）**：`fx.py` 自身聲明兩點——(a) 端點與 CSV 欄位格式未對照台灣銀行線上實際回應查證（開發環境無外網）；(b) 所謂「當日匯率」是即期買入價與賣出價的**中點模型值**，並非官方收盤匯率。目前無美股價格來源，USD 部位取不到價格，這條路徑尚未產生任何面向使用者的數字；一旦美股 adapter 上線即轉為活躍，屆時須比照回測頁做常駐揭露。

**指數日線**：
- 槓桿 ETF 的情境推估需要「標的指數」的日線（e.g., QQQ 對應 Nasdaq-100）。
- 後端目前無指數 adapter，所以 leverage chapter 的情境推估恆回 insufficient_data。

### 訊號層

所有技術指標：
- **輸入**：至少 N 日的日線收盤價（窗口大小取決於指標）。
- **輸出**：若資料不足，整個指標回 status=insufficient_data，series 為空。
- **無線性插值、無向前填充**：缺漏日期不補；只報既有的數據點。

已內建指標（在規則和警示中可用）：
- MA 系列：5/20/60 日移動平均
- ATR：平均真實波幅（14 日），用於停損計算
- RSI：相對強弱指標（14 日）
- KD：KD 指標（K 值 9 期，D 值平滑）
- MACD：及其訊號線與直方圖
- Bollinger Bands：20 日均線 ± 2σ
- Beta：相對指標的風險係數
- 其他：成交量 Z-score、回撤率、波動率

### 建議引擎

- **規則式**，非黑箱 ML。所有規則以 YAML 檔定義，可 git 版本控制、可 code review、可讀性強。
- 規則條件由「欄位、運算子、閾值」組成；可 AND/OR 組合。
- 每條規則有權重、反駁點、失效條件，隨卡片返回。
- **無目標價**：規則只輸出建議方向（add/hold/reduce/etc），不輸出價格目標。
- 當前規則集版本：1.0.2（12 條規則）。

### 風險上限

五項上限，每項獨立評估：
1. **單一標的佔比**：預設 15% 之總資產。
2. **單一產業佔比**：預設 30%；目前恆 not_evaluable（無 sector 欄位）。
3. **總曝險**：預設 100%（硬上界 150%）；分子為已估值部位市值合計、分母為使用者在設定頁自報的帳戶總淨值。分子由系統計算、分母由使用者自報，兩者來源不同；比率假設持倉清單完整，未登錄的部位不計入分子，會讓曝險看起來偏低。未輸入淨值、淨值滿 30 天未更新、或任一部位無法估值時為 not_evaluable。
4. **單筆虧損**：預設 1% 之投資組合淨值；基於 ATR 與停損距離計算。
5. **Kelly 分數**：預設 0.25（即 25% Kelly）；Kelly 輸入無來源，通常 not_evaluable。

**硬性上界**（修改需程式碼變更與風控、CEO 同意）：
- `max_position_weight` ≤ 0.50（50%；超越此數字單一名稱形同投資組合本身）
- `max_gross_exposure` ≤ 1.50（150%；中度槓桿是合理偏好，超過改變風險特性）

違反上限時，`add` 建議會被降為 `hold`，卡片上明示「第 X 條上限 … 擋下」。

### 槓桿 ETF 分析

- **持有期間拆解**：純算術，無預測。
- **報酬衰減分解**：費用效應 + 日度重置效應 + 殘差；恆等式嚴格成立。
- **只偵測** `instrument_type == "leveraged_etf"`；`futures_etf` 有換倉機制（非每日重置），不觸發本章。
- **情境推估**：需要指數日線；若無，回 insufficient_data。
- **所有假設與限制**在章節開頭明列，必讀。

### 回測

- **MA Cross 策略**：long-only（全倉 or 空倉），20/60 日窗口（不可調）。
- **walk-forward**：樣本內與樣本外嚴格分離；無參數越擬合的後向測試。
- **計交易成本**：策略側扣除手續費、稅費、滑點；Buy & Hold 為未計成本的純價格基準。
- **無配息調整**（台股特別注意）：收盤價未經除權息調整。
- **只有一個策略**：暫無新增或自定義策略功能。

### 排程與推播

後端有獨立排程 process（`scheduler.py`），不由 `app/main.py` 啟動。使用 interval trigger（非 cron）：
- 資料更新：每 1440 分鐘（自排程啟動時刻起算）。
- 警示評估：每 60 分鐘（自排程啟動時刻起算）。

排程不是必須；API 調用時也會即時評估。排程的目的是「即使前端未打開，也能監測並推播」。

## 離線示範模式

### 目的

環境若無外網存取，所有 provider 都回傳 unavailable，四個頁面形同空白。離線示範模式填充合成資料集到既有 cache 與 stores，讓整個堆疊（指標、風險上限、建議卡、警示）都能演示與測試。

### 資料標記與風險揭露

- **所有日線標記** `source="demo_synthetic"`，API 返回時會在 `data.source` 欄位呈現，前端「來源」欄會標示此為示範資料。
- **示範持倉與警示規則**的 note 字段帶有 `[demo_synthetic]` 前綴，清楚標記為虛構。
- **重大風險**：此模式的合成價格會寫進你指定的那顆 DB（cache、positions、alerts），**在示範模式下看到的建議卡是建立在虛構價格上的**。示範期間請把畫面上的任何數字都當成展示，不要據以判斷任何真實部位。
- **不會覆蓋真實資料（守門機制）**：seed 在寫入前會先檢查目標資料庫的示範標的（2330 / 0050 / 00631L）在相同日期上是否已有**非示範來源**的日線。只要有一筆衝突，就整批拒絕執行、不寫入任何東西（日線、示範持倉、示範警示規則都不會建立），並印出衝突明細與處理建議，結束碼為 1。原因是示範日線以 `(symbol, market, trade_date)` upsert 寫入，會直接覆蓋既有列，而 `--reset` 只刪 `source=demo_synthetic` 的列——被覆蓋掉的真實資料無法還原。**守門只比對示範窗口內的日期**；窗口外的既有日線不受影響，但同一顆 DB 仍可能出現真實與合成資料並存於不同日期，指標與建議卡的計算窗口就可能橫跨兩種來源。
- **建議做法**：仍以獨立資料庫執行示範模式（`--db-path ./data/demo.db` 或設 `STOCK_DESK_DB_PATH`），把示範與真實資料徹底隔開；守門是安全網，不是拿來混用兩者的許可。
- **腳本不會替你刪除任何不是它寫的資料**：遇到衝突時要不要清掉那些既有日線，是使用者的決定。
- **CLI 警告**：執行前後都會顯示「這是合成示範資料，不可用於任何真實決策」的警語。

### 用法

**啟動示範模式**（seed 或刷新）：
```bash
uv run python -m app.demo.seed
```

**清除示範資料**（退出示範）：
```bash
uv run python -m app.demo.seed --reset
```

### 示範內容

- 示範持倉 3 筆：2330 (普通股)、0050 (指數型 ETF)、00631L (槓桿 ETF，倍數 2 倍)
- 警示規則 3 條，涵蓋價格、訊號、風險上限類型
- 00631L 的價格由 0050 的日報酬套 2 倍與費用率 1.13% 逐日複利推導
- 所有日線 60 根（交易日），覆蓋約 3 個月

## 常見問題

**Q: Confidence 是勝率嗎？**
A: 否。Confidence 只反映規則的一致性（matched rules 的權重分布有多集中）與資料完整度（多少 % 的規則集可計算）。`high` 信心表示規則證據充分且指向同一方向，不表示 80% 獲利機率。

**Q: 為什麼建議卡突然從 `add` 變成 `hold`？**
A: 可能有三種原因：
1. 同時命中防禦型規則（`reduce` 或 `stop_loss`），建議自動降級。
2. 風險上限被違反（例如該標的已佔 15% 投資組合，而上限正好是 15%），`add` 被上限擋下。
3. 防禦型建議即使資料不足 50% 仍會計算，但 `add` 會停止評估，卡片降為 `insufficient_data`。卡片上會明示理由。

**Q: US 標的為什麼沒有價格？**
A: 美股 data provider adapter 尚未實作。後端定義上支援 Market=US，但無法取得美股日線。預期後續發佈。

**Q: 我可以修改規則嗎？**
A: 規則檔案存在後端的 `app/advice/rules/default.yaml`。修改需要：
1. 編輯 YAML 檔案（遵循模式定義，所有禁用詞檢查，欄位必須在 KNOWN_FIELDS 中）。
2. 重啟後端以重載規則。
3. 前端不需重啟；下次查詢自動取新版本。

**Q: 能自動下單嗎？**
A: 不能。Stock Desk 只輸出建議卡，不執行任何交易指令。所有決策與操作由使用者自行判斷。

**Q: 警示推播不送出？**
A: 檢查：
1. 是否設定了 Discord webhook URL 或 Telegram token/chat_id（環境變數，不在設定頁）。
2. 排程是否啟動（或手動評估警示規則）。
3. 規則是否真的被觸發（可在警示歷史事件查看）。
4. 冷卻期是否正在進行（同一規則 60 分鐘內不會重複推播）。

**Q: 回測報酬為什麼與實際交易不符？**
A: 回測是模擬，無法完全複製現實，主要原因：
1. **費率查證狀態**：手續費、稅費、監管費都是待查證的預設值；實際可能不同。
2. **收盤價成交**：回測假設在每日收盤價成交；實際可能買高賣低。
3. **無配息調整**：台股收盤價未經除權息調整；實際股利繳稅與配息日都會影響。
4. **參數穩健性**：樣本內優化的參數不一定能通用於樣本外。必看樣本外結果。
