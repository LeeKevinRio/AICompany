**定錨**

- **受眾**：看到「資料不足」的持倉人；多數是持有外國掛牌商品或特殊樣式代號的人，不熟交易所代號慣例。
- **限制**：
  1. 風控 F9W-11 (a)～(e)：主句不得預設曾取得價格；子原因涵蓋准入拒絕、W-c、W-c′；句內不得有「；」；不得用「幣別」「紀錄」、不得加更正指引；（suggested）補「非價格或匯率中斷」。

### 與 X-3c、`price_not_queried`、asked 並列時的讀感

陳述順序採 tech-architect 建議：W4（asked）→ W5（`price_not_queried`）→ (b)（X-3c）→ 本組。以下是一本帳同時有四組的樣子（數字為示意，方向子句以 D-a「比率會因此偏高。」為例）：

1. 組合中有 2 筆部位無法估值（缺價格或匯率），未計入總資產；比率會因此偏高。
2. 組合中有 1 筆部位無法估值（本次未向來源查詢，本機尚無可用的價格或匯率），未計入總資產；比率會因此偏高。
3. 組合中有 1 筆部位因幣別與市場不符而無法估值（紀錄不一致，非價格或匯率中斷），可於庫存頁的「更多」視窗更正幣別與平均成本；系統不猜幣別而未計入總資產；比率會因此偏高。
4. 組合中有 3 筆部位無法估值（代號形式不在本系統查詢的範圍內，或日線標示的價格單位與市場所用的單位不同，或日線沒有標示價格單位），未計入總資產；比率會因此偏高。

讀感觀察：

- **1 與 4 同一個開頭**（「組合中有 N 筆部位無法估值（」），差別只在括號。這是 W4／W5 既有的並列方式（三組本來就同開頭），可接受；括號首詞「缺」「本次」「代號」足以區分。

- **語意由「可能自己好」排到「規則性」**：1、2 是資料面（可能恢復）→ 3 是使用者可更正的紀錄 → 4 是系統規則。把 4 放最後，讀完整排最後一句是「系統規則」，與 X-3c「最後陳述」的既有核可順序不衝突。

## 三、T-12　庫存頁新標籤（`MISSING_LABELS` 新 key）

### 推薦字面（10 字）

> 代號或價格單位不採用

- **出現位置**：庫存頁 `PositionsTable.tsx` `PriceCell`（L75-103）的一般分支：價格格顯示「—」＋「資料不足」徽章，下方一行 `text-xs text-neutral-400` 小字顯示本標籤（經 `missingSummary`）。tech-architect 建議新 token 單獨出現（`missing` 剛好一個），因此不會與其他標籤以「、」串接。
- **key 名稱**由實作定（不面向使用者），此處只定顯示文字。

### 為什麼這樣寫

1. **不以「查無」「本次未查」開頭**：符合 `valuationWording.ts` L3-9 語意（第三種形狀，名詞片語，描述「不是缺資料」）。這個標籤與 `currency_market_mismatch: "幣別與市場不符"`（7 字）同屬名詞片語，不屬於「問過沒有」或「這次沒問」。
2. **涵蓋所有子原因**：准入拒絕（代號）、W-c／W-c′／T-15 快取舊列（價格單位）。四種都說得通，沒有一種被誤標成「查無」。
3. **主語是「代號」「價格單位」，不是「價格」**：呼應風控 F9W-11 (a) 的精神，不預設曾取得價格。「日線價格不採用」（alt-1）對准入拒絕（根本沒查）略有預設。
4. **「價格單位」與 F-7 標籤同詞**：F7-R5 規定「價格單位」指畫面價格數字的單位，「計價幣別」指持倉紀錄；本標籤不含「幣別」，與 X-3c 標籤明確區隔。
5. **「不採用」與 W-c「整段都不採用」同詞**，不用「不支援」「暫不」（承諾或暫時性口氣）、不用「錯誤」「無效」（我們不知道資料是否錯）。

### 375 寬可讀性

- 行距估計：375 寬時 `ROW_GRID` 第一欄約 130～150px（扣除 40% 的 pnl 欄與 2.75rem 的展開欄），`text-xs` 中文約 11～12 字一行。10 字可單行容納；12 字（alt-2）貼邊；超過會折行但 `<p>` 可自然換行，不溢位。**這是依 class 估算，未實測**，請 qa-e2e 在 375／1280 驗，並以最長 alt 一併驗。
- 與既有標籤的長度：「查無價格資料」6、「本次未查價格」6、「幣別與市場不符」7。本標籤 10 字，比既有略長但在可接受範圍。

### 可能的誤讀與對策

| 誤讀 | 對策 |

| 以為是自己輸入的代號錯了 | 用「不採用」，不用「錯誤」「無效」「不存在」；主語缺省，不指向使用者 |

### alt 版

## 四、T-13　冷卻期 C′ 版（W-c′ 觸發、無快取）

### 推薦字面（97 字）

> 本機尚無此標的可採用的日線資料。最近一次向來源取得的日線沒有標示價格單位，已於約 {minutes} 分鐘前整段不採用；冷卻期為 {cooldown_hours} 小時，冷卻期內系統不會自動重試；冷卻期結束後的下一次查詢才會重新向來源取得。

- 佔位符：`{minutes}`、`{cooldown_hours}`，與已核可 C 版相同，`{minutes}` 取 `rejection_at`（tech-architect R-24）。
- **出現位置**：與 C 版相同，`/api/bars` 等 `reason` → K 線區 `InsufficientPanel`、操作摘要、首頁風險上限「詳細」。只用於「最近一次嘗試有任一層是 W-c′、沒有任何一層是 W-c、無任何一層取得可用資料，且本機無此標的快取」（tech-architect 標記語意；有 W-c 一律記 `unit_mismatch` 走 C 版）。
- 結構對照 C 版（逐字比對）：
  - 第一句「本機尚無此標的可採用的日線資料。」——與 C 版**完全相同**。
  - 第二句前半「最近一次向來源取得的日線」——與 C 版相同；C 版接「，標示的價格單位與市場所用的單位不同，」（17 字事實），C′ 改接「沒有標示價格單位，」（8 字事實）。
  - 「已於約 {minutes} 分鐘前整段不採用；冷卻期為 {cooldown_hours} 小時，冷卻期內系統不會自動重試；冷卻期結束後的下一次查詢才會重新向來源取得。」——與 C 版**完全相同**，後段逐字沿用已核可句。
  - 因此 C′ 與 C 的差異**只有一處**：中段事實子句。風控審這一處即可。

### 為什麼這樣寫

1. **事實子句不分市場**：「沒有標示價格單位」與市場無關，C′ 不需要像 W-c′ 那樣分美／台兩句，只需一條常數。
2. **不寫「無法確認是否為…」**：W-c′ 原句有，是因為需要一個橋段說明「為什麼沒標示就不採用」；C′ 是冷卻期回覆，重點在冷卻資訊，且 C 版也沒有橋段（單位不同本身即是理由）。省略後仍是兩個事實（沒標示、整段不採用）並列，不含推論。若風控認為「沒標示→不採用」的邏輯需要橋段，見 alt-1。
3. **「最近一次向來源取得的日線」**的主詞不帶 `{provider}`：與 C 版一致；冷卻回覆不是某一次來源回傳的即時句。
4. **不含「暫時」「目前」**：沿用 C 版的處理，冷卻資訊用「冷卻期為…小時，冷卻期內系統不會自動重試」陳述事實。

### 可能的誤讀與對策

| 誤讀 | 對策 |
|---|---|
| 讀成「來源沒有資料」 | 「日線沒有標示價格單位」＋「整段不採用」，點明是「日線有、單位沒標」，而且第一句用「可採用的」而非「的」 |
| 「沒有標示價格單位」讀成「沒有價格」 | 價格是否存在不是本句主張；與 W-c′ 已核可句同詞（「沒有標示價格單位」） |
| 冷卻結束後「才會重新向來源取得」被讀成「到時就會好」 | 逐字沿用已核可句，不加預測；本句也沒有說「到時就可採用」 |
| 混合情境（AV 中斷＋yfinance W-c′）時句子漏掉 AV 的中斷 | 句子陳述的是「最近一次向來源取得的日線」，yfinance 回傳的日線確實沒標示，屬實；與 C 版相同的取捨（C 版同樣不並列其他層原因）。列為已知取捨，請風控知悉 |

### alt 版

- **alt-1（含橋段，112 字）**：「…最近一次向來源取得的日線沒有標示價格單位，無法確認是否為市場所用的單位，已於約 {minutes} 分鐘前整段不採用；…」（+15 字，其餘不變）。多一個推論橋段，已超過 100 字；晶片旁不易讀完。

## 六、T-15　快取舊列幣別不符或空白的 fail-closed 原因句

### 事實盤點（先讀 tech-architect 評估與 ADR-0024 M-8 後確認的，與沒有確認的）

**確認的**（來源：ADR-0024 D-2、R-13 (5)、M-8、C-1）：

- 快取讀出時逐根檢查舊列：任一根宣告幣別非空且不等於預期，或空白，整條序列 fail-closed、**不刪資料**，回 `UNAVAILABLE`、`bars=[]`。
- 涉及 M-8 所稱「五條快取讀出路徑」，其所列讀出點為：(1) layer 0 的三個 `_cached_result` 出口（含 R-8 冷卻期回快取）；(2) `_fall_back_to_cache`；(3) `get_cached_bars`；(4) 增量抓取的合併讀回（`service.py` L191）。（M-8 的「五條」與其列舉的出口數是否一致，我沒有逐點核對，不影響本節結論。）
- 讀 `service.py` 現況確認：`get_daily_bars` 在 layer 0 回傳非 None 時**直接結束**（L159-162），不跑梯子；`_fall_back_to_cache` 是梯子**已跑完**（各層都問過、都沒有可用資料）才進的；`get_cached_bars` 是 cache-only，「沒有來源被問過」（其 docstring）；合併讀回是**來源這次剛回傳成功**之後才讀頭段。

**因此「有沒有向來源查詢」依路徑而不同**：

| 路徑 | 這次有向來源查詢嗎 | 梯子是否會繼續 |
|---|---|---|
| layer 0 三個出口 | 沒有 | 若出口回 `UNAVAILABLE` 則直接結束（L161-162），不再跑梯子 |
| cache-only（`get_cached_bars`） | 沒有 | 不跑梯子（R-1） |
| `_fall_back_to_cache` | **有**，且都失敗或被拒 | 已結束 |
| 增量合併讀回 | **有**，且尾段成功 | 尾段成功但頭段讀回被擋 |

→ 同一句字面不能對四類路徑都說「未向來源重新取得」，也不能說「已向來源重新取得」。**我沒有臆測，字面只寫對所有路徑都屬實的事實**：本機快取中此標的的日線資料，標示的價格單位與市場所用的單位不同或沒有標示，整段不採用。

**沒有確認的（列為待確認，見第九節）**：

1. 快取閘門拒收時，`ProviderResult.rejection` 是否也設為 `unit_mismatch`／`unit_missing`（決定估值器會不會回新 token、整書成因會不會歸入 T-11 那一組）。tech-architect 評估只對 live 層與 layer 0 的標記有明述，快取讀出路徑的 `rejection` 值未載。
2. layer 0 出口被擋後，是回 `UNAVAILABLE` 直接結束，還是視為快取未命中而改走梯子。ADR 的壞處 5 寫「該代號的序列會被拒答，直到運維清理（F-9e）」，傾向前者，但屬 ADR 敘述而非 tech-architect 對 `_cached_result` 具體行為的描述。
3. `_fall_back_to_cache` 內若與其他層原因並列，是否走 `_combine_reasons`（應該是，與 W-c 一致）。
4. 增量合併讀回被擋時，現行會走 `MERGE_READBACK_FAILED_REASON` 的分支（L192-202）；閘門介入後該分支用哪個原因句？T-15 還是既有句？

### 推薦字面（49 字）

> 本機快取中此標的的日線資料，標示的價格單位與市場所用的單位不同，或沒有標示價格單位，整段都不採用。

- 無佔位符（固定常數，不帶 `{provider}`：快取舊列不是某一次來源回傳）。
- **出現位置**：同 W-c／W-a：K 線區 `InsufficientPanel`、`data.reason` 晶片旁的 `<details>`、操作摘要、首頁風險上限「詳細」。cache-only 的估值器不顯示 `UNAVAILABLE` 的 reason（tech-architect），故該路徑畫面看不到本句。

### 為什麼這樣寫

1. **主語是「本機快取中此標的的日線資料」**：事實層級是「存放中的資料」，不是「這次回傳」。W-c 用「這次回傳」是事件，T-15 是狀態，不借用 `{provider}`。
2. **不寫「舊」**：我不知道這些列是舊版 adapter 寫的、手動 seed 的、還是別的來源；「舊」是推論。ADR 說「舊列」，但使用者面不需要。
3. **單位不同與空白合成一句**：「標示的價格單位與市場所用的單位不同，或沒有標示價格單位」兩個分支都屬實，且不需要像 W-c／W-c′ 那樣分兩句（W-c 不能涵蓋空白才分；T-15 的「或」已涵蓋）。用詞逐字沿用 C 版（「標示的價格單位與市場所用的單位不同」）與 W-c′（「沒有標示價格單位」），不發明新說法。
4. **「整段都不採用」**與 W-c 同詞，結尾「。」可與其他層原因由 `_combine_reasons` 並列（它會 `rstrip("。")` 再統一接「。」）。
5. **不寫「未向來源查詢／重新取得」**：見上表，路徑依賴。
6. **不寫冷卻、不寫重試、不寫清理**：T-15 路徑沒有 attempt log 標記（D-9 只由 live 層設定），也沒有「下次再試會好」的承諾基礎；F-9e 是維運動作，不給使用者。不寫「暫時」。
7. **不稱「錯誤」「損壞」**：我們不知道舊列資料是否錯，只知道單位標示與市場所用的不一致或缺漏。

### 可能的誤讀與對策

| 誤讀 | 對策 |
|---|---|
| 讀成本機資料庫壞了 | 「標示的價格單位…不同」「整段都不採用」描述的是單位判斷；沒有「損壞」「錯誤」 |
| 讀成「使用者或系統可以刷新就好」 | 不提重新取得；若實際上 layer 0 直接結束，重試也不會改變結果，字面沒有暗示會好 |
| 與 W-c 混淆（兩者都是「不是這個市場的單位」） | 主語不同（本機快取 vs 這次回傳）；在 `_fall_back_to_cache` 路徑兩者可並列，語意互補：這次來源的資料與快取中的資料都被擋 |
| 「有部分根標示不符」被讀成「整批都不符」 | 同 W-c「任一根不符整段不採用」的既有核可取捨；精確寫法見 alt-1 |
| 讀成「今天有向來源問過，結果被擋」 | 因為沒有時間字詞（今天、剛才、這次），不暗示 |

### alt 版

- **alt-1（精確到「有部分」，52 字）**：
  > 本機快取中此標的的日線資料，有部分標示的價格單位與市場所用的單位不同，或沒有標示價格單位，整段都不採用。

  更貼近 per-root 檢查的實際語意（任一根不符整條拒）。W-c 核可句沒有這個限定，風控若認為 W-c 的取捨可接受，則主案即可；若認為快取「有部分」的情形較常見而需要明講，採本版。
- **alt-2（拆成兩句，分單位不同／空白，39 字與 29 字）**：
  > 本機快取中此標的的日線資料，標示的價格單位與市場所用的單位不同，整段都不採用。
  >
  > 本機快取中此標的的日線資料沒有標示價格單位，整段都不採用。

  與 W-c／W-c′ 的分流一致，但要快取讀出路徑也呼叫 `classify_currency`（tech-architect R-17 已有此函式），多一條常數、多一個測試。主案已涵蓋兩者，我不推薦分兩句。
- **alt-3（市場具體，美股 36 字）**：「本機快取中此標的的日線資料，標示的價格單位不是美元，整段都不採用。」不涵蓋空白，且需分市場，不推薦。
- **alt-4（路徑 1 專用，若風控要求）**：若 tech-architect 確認 layer 0 與 cache-only 確定沒有問來源，可在這兩條路徑加「，本次未向來源查詢」（沿用 `CACHE_ONLY_MISS_REASON` 語感）。需要多條常數，**不推薦**，除非單一句子被風控認為不足。

### W-d 要求（文案面）

T-15 應併入 W-d 的「整組」：**即完整 `reason`；不接 `NO_BARS_REASON`、不走 `with_provider_reason`**。理由：快取閘門擋下時 `NO_BARS_REASON`「主來源、備援與快取皆無」在 `_fall_back_to_cache` 路徑不實（快取有，只是不採用）。與其他層原因並列時走 `_combine_reasons`，並以完全相等的測試釘住（比照 F9W-6）。

## 十、被捨棄的與原因

- **「日線價格未被採用而無法估值」**（舊 64 字句的主句）：預設曾取得價格，(a) 退回。
- **「幣別與市場不符」「紀錄不一致」**（T-11）：撞 X-3c，(d) 禁。
- **「可於庫存頁更正」類指引**（T-11、T-12）：(d) 禁；且 W-c 使用者無從更正。
- **「非價格或匯率中斷」進主案**：混合情境不實（第二節）。
- **標籤「查無…」「本次未查…」開頭**：`valuationWording.ts` 語意，T-12 禁。
- **標籤「不符」**：避免與 X-3c「幣別與市場不符」成為近義對偶。
- **「暫不採用」「暫時不採用」**（T-12）：暗示日後會採用，是承諾。
- **T-15 寫「未向來源重新取得」**：五條路徑中兩條不屬實（第六節）。
- **T-15 寫「舊資料」**：不知道列的來源，「舊」是推論。
- **C′ 改後段文字**：F9W-12 已表明不改已核可句（B 版理由）。
- **T-15 帶清理指令或 F-9e 提示**：維運動作，不屬使用者面。
