# 第一件：CEO 知悉 X-11（RK-4）與 X-12（RK-5）

> 以下可整段併入 R0-2 知悉包。用語刻意不用內部術語。X-11、X-12 與 X-10 是同一組：X-10 講「附的來源說明可能不是實際用的」，X-11 講「已經換算卻沒有來源說明」，X-12 講「總覽的匯率貢獻可能混了兩個來源」。

## X-11：美元計價持倉的推播與決策卡，數字已換算卻沒有匯率來源說明（RK-4，low）

**一句話**：在少數情形下（報價那次查詢失敗但市值那次成功，或同一標的橫跨兩種幣別），風險上限第 1、2、3、5 條的數字已經用匯率換算過，推播與決策卡卻沒有附任何匯率來源說明；卡上只看得到「匯率報價沒有可用數值」，容易被讀成整張卡都沒用到匯率。風險儀表（`/limits`）則完全沒有匯率說明。修正後會補上來源說明；但有兩項殘留：一項是**你要明示接受的永久殘留**（見第 3 點），另一項是**你要知悉的殘留**（風險儀表在報價端出現兩個以上不同來源時不附匯率說明，見第 3 節之二）。

### 1. 修正前（目前上線的狀態，已存在）
- **發生什麼事**：
  - 同一次檢查裡，匯率查了兩次：一次拿價格與 ATR 的報價，一次計算持倉市值（這點與 X-10 相同）。
  - 報價那次查詢失敗、市值那次成功時，第 1、2、3、5 條的數字已經乘了匯率，卻沒有來源說明可附；卡上只剩「匯率報價沒有可用數值」「本次沒有取得任何匯率報價」之類的句子。
  - 同一標的同時有台幣計價與美元計價的持倉時，也是同一個結果：美元那批的市值乘了匯率，卡上沒有來源說明。
- **這是缺漏，不是錯標**：沒有附上錯的來源說明，而是沒有附。風險等級 low，理由是需要「單次查詢失敗」才會發生。**發生頻率沒有量化**：PR-RK2 上線後會記錄此類次數（RK-2 風控 S-4）（警示、決策卡與風險儀表的每次查詢都會記錄，風險儀表每次請求按持有標的逐檔記錄；次數是上界，不等於推播或決策卡實際出現的次數）；上線前沒有記錄，目前也沒有統計結果。
- **風險儀表（`/limits`）**：完全沒有任何匯率說明，連換算說明都沒有。
- **使用者現在怎麼判斷**：卡上沒有說明時，不能靠總覽補。總覽展開後的揭露**只能當參考**，原因見 X-10 第 3 節（另一次查詢的來源、只涵蓋市值那一側、不涵蓋價格與 ATR 的報價）。
- **附帶一項：O-1 格，警示推播上的報價來源說明（風控第 1 項；2026-10-08 依風控審查檔 X11-R1 重寫，風控核對通過；已處理機械更正 X11-R1a）**：
  - **位置**：這是 O-1 格，發生在**警示推播**路徑，**決策卡不會出現**，也不是 2c。標的拿不到可用收盤價時，警示快照（`snapshot.py`）仍會解析匯率報價；決策卡那邊則在收盤價不可用時不解析匯率，直接走 `insufficient_data`（`api/advice.py` 決策卡路由中收盤價不可用的 `insufficient_data` 分支），所以卡上沒有這一格。
  - **現況（已存在）**：報價被「套用」，但收盤價不可用，報價沒有乘進任何數字；推播上附的是**報價來源的方法論句**。假設 PR-RK2 沒有收盤價閘門就上線，市值那次落在另一個來源時，推播會再附 72 字銜接句，聲稱兩個來源「混用」並對應價格與 ATR 的換算，但價格與 ATR 根本沒有換算；**此情形已被 PR-RK2（cf9619e）的收盤價閘門排除**。
  - **已定案的處理（2026-10-08 依 X11-R1a 照實改寫）**：coordinator 已定案，在 PR-RK2 內加收盤價閘門（風控 RK4-R11 的 (b)）。照實是三件事：
    1. **修正後，收盤價不可用時，推播不附任何匯率來源說明**：報價方法論句、估值器來源說明句、72 字銜接句都撤下。
    2. **這時市值已經用估值器那次的匯率換算，推播卻沒有說明，和 2a 一樣屬缺漏、low。** 要等 PR-RK4a 之後，才補上市值那次的來源說明加 W-RK4-1。
    3. **閘門已在 PR-RK2（cf9619e）落地。**
  - **PR-RK4a 之後**：若該標的有已估值的 USD 持倉，推播改附**市值那次**的來源說明，再加 W-RK4-1（即上列第 2 件缺漏在此補上）。
  - **不在這次範圍**：`snapshot.reason` 內的「價格與 ATR 以…換算」（`FX_APPLIED_NOTE`）不會進推播（推播只附 `fx_disclosure`，見 `engine.py` 組 fired 訊息時附加 `snapshot.fx_disclosure` 之處），(A′) 也不移除它，這屬風控 S-3。

### 2. 修正後（PR-RK4a／PR-RK4b 合併、歸屬句經風控逐字核可之後）
- **推播與決策卡**：上述情形會附上**市值那次查詢**的來源說明，並在它之前、緊鄰處加一句歸屬句。歸屬句逐字如下（風控 2026-10-08 核可，41 字；一個字都不能改）：
  > 此處來源說明所指的匯率，只對應持倉市值與總資產中經換算的部分，不含價格與 ATR。
- **同一標的橫跨兩種幣別**：維持「不套用任何報價、不附報價的來源說明」；只有美元那批已估值時，才附市值那次的來源說明與歸屬句。
- **風險儀表**：會彙整來源說明附在說明列。若報價端與全帳市值是兩個不同來源，用 RK-2 已定稿的 72 字銜接句；報價端沒有套用任何報價、只有全帳市值的來源時，附歸屬句；**報價端出現兩個以上不同來源時，該次回應不附任何匯率說明（與修正前相同），只在伺服器記一行警告。**（風控 RK4-C1 接受的退路 (α)，取代原稿「不出貨，退回風控裁定」；列為 CEO 知悉的殘留，見第 3 節之二。）純台幣帳本的回應與現在逐位元組相同，前端不動。
- **銜接句與歸屬句不會同時出現**（互斥，要用測試釘住）。
- **仍然沒有做到的**：畫面不逐條標示「哪一條上限用了哪個來源」，與 X-10 相同。
- **等級**：2a 型（報價失敗、市值成功）、混雜幣別、風險儀表，修正後仍是 low。

### 3. 永久殘留（需要 CEO 明示接受）
- **現象**：**台幣計價標的**（例如 2330）的比率，分母「總資產」含美元持倉的換算，但卡上**不附**來源說明。想知道這個分母的匯率來源，只能到總覽匯率貢獻卡的「詳細說明與依據」找。
- **這個揭露的位置（RK4-R6 指定的寫法）**：**收在總覽匯率貢獻卡的「詳細說明與依據」內、需要點開、而且是另一次查詢**。所以它只能當參考，不能用來確認某一張卡用了哪個來源。
- **為什麼會有這個殘留**：這是 2026-09-19 第二次裁定把揭露摺疊起來的結果。風控當時的條件 (1) 是「不得摺疊」，**風控的書面異議保留**。
- **風控仍接受的三個理由**：
  1. 這項只影響比率的分母。
  2. 替代做法（所有台幣標的的卡都附長說明）風險更高：匯率說明會出現在沒有換算過的台幣數字旁邊，讓人以為那些數字換算過，風控已正式否決。
  3. 「備援匯率」徽章是常駐的。
- **重審觸發**：總覽的揭露或「備援匯率」徽章被移除、再降級，或改成只有滑鼠移過去才看得到。
- **最終責任由 CEO 承擔。**

### 3 之二、另一項殘留：風險儀表在報價來源分歧時不附匯率說明（2026-10-08 依風控 RK4-C1 新增，需要 CEO 知悉）
- **現象**：風險儀表（`/limits`）在**報價端出現兩個以上不同來源**時，該次回應**不附任何匯率說明**（與修正前相同），只在伺服器記一行警告。這種情形下，儀表上的數字有換算，卻沒有任何來源說明。
- **什麼時候會發生**：在匯率快取（ADR-0015 W11）接線之前，目前只會在**台銀有回應的期間**發生；台銀仍被擋時，各檔報價都落到 Yahoo 備援，不會分歧。（台銀是否仍被擋，沒有再查證，同 X-10。）快取接線之後這個前提不再成立：快取命中時來源紀錄是原本那一列的，台銀被擋期間快取裡仍可能留有台銀曾經回應時寫入的列，所以即使台銀被擋，也可能出現分歧。
- **這個訊號看得到嗎**：這行警告只寫進伺服器 log，畫面與推播都看不到，也不會自動通知；PR-RK4b 合併前這個訊號還不存在，重審觸發 1 要有人看 log 才會成立。
- **為什麼接受**：這個輸出和修正前完全相同，不會產生任何未經審查的新字面，等級維持 low。風控也不接受「只附一部分說明」：只附市值那次的說明加歸屬句，會讓人以為價格類上限沒用匯率，方向錯誤；只附多個報價端說明而不加歸屬，會讓人把來源歸錯。
- **重審觸發**：出現下列任一情形，回風控重審，並由 creative-lead 起草專用說明，等級由風控重新判定（並見第 5 節升級條件）：
  1. 正式環境的 log 第一次出現這行警告。
  2. 台銀有回應。
  3. 匯率快取（ADR-0015 W11）接線。
- 這一項與第 3 點的永久殘留是兩件不同的事，CEO 的知悉要分開寫。

### 4. 另一項：資料不足時的回應內部不一致（2c，low，使用者目前看不到）

## X-12：總覽「匯率貢獻」與「未實現損益」，可能把買入日匯率和目前匯率兩個來源的口徑差算進去，畫面沒有說明（RK-5，現況 low）

**一句話**：總覽的「匯率貢獻」是「目前匯率」與「買入日匯率」之差帶來的損益，「未實現損益」也包含這一塊。這兩個匯率如果來自不同來源，兩個來源口徑不同造成的差，就會被直接算進這兩個數字，而畫面沒有任何說明。目前不會發生（前提見下），但匯率快取（ADR-0015 的 W11-5）接線後，混源會**長期存在**，而且常駐的「備援匯率」徽章在快取命中時會**消失**。風控對缺少兩項前置的 W11-5 已**預先否決**。

### 1. 現況（已存在，low）
- **發生什麼事**：
  - 總覽「匯率貢獻」與「未實現損益」可能把買入日匯率與目前匯率兩個來源的口徑差算進去，畫面沒有任何說明。
  - 總覽「詳細說明與依據」裡的揭露只列**目前匯率**的來源，不列買入日匯率的來源。
  - 這份揭露還會列出**沒有估值的持倉**的來源句，雖然那些持倉沒有乘進任何數字。
  - 常駐的「備援匯率」徽章**不看買入日匯率**，而且**也會被沒有估值的持倉觸發**。
- **現況不會發生的理由（建立在與 X-10 同一個未再查證的假設上）**：台銀被擋期間，買入日與目前兩邊都落到 Yahoo 備援，來源一致，不會混源。2026-09-19 查證後台銀是否仍被擋，**沒有再查證**；此項低風險建立在該假設上。
- **等級**：現況 low。

### 2. 修正後（PR-RK5a／5b／5c 合併、總覽混源句經風控逐字核可之後）
- **總覽揭露**：
  - 改為只列**已估值持倉**的來源（修正「列出沒有估值持倉」那一項）。
  - 新增買入日匯率的來源，一起去重列出。
  - 若有任何已估值持倉的買入日匯率與目前匯率來源不同，在清單**最後**附一句混源說明。混源說明逐字如下（風控 2026-10-08 核可，56 字；一個字都不能改）：
    > 至少一筆持倉的買入日匯率與目前匯率來自不同來源，兩個來源的口徑差會算進「匯率貢獻」，因此也會算進「未實現損益」。
- **「備援匯率」徽章**：改為只要任何一筆**已估值**持倉的目前匯率**或買入日匯率**用了備援就顯示；沒有估值的持倉不再觸發。徽章的字面不變。
- **同一個 release**：揭露只列已估值持倉，與徽章只看已估值持倉，必須同一個 release 出貨，否則會出現「有徽章卻沒有對應說明」或反過來。
- **混源說明收在摺疊區，為什麼可以**：目前來源只有兩層（台銀、Yahoo 備援），任何混源必有一邊是備援，常駐的徽章就會顯示；所以徽章涵蓋全部混源情形。**來源超過兩層時要重審。**
- **這次修正沒有做的**：不量化兩個來源的差距（ADR-0011 尚缺事實 3）；混源說明不說哪個較準。

### 3. 匯率快取（W11-5）接線後的風險
- **混源會長期存在**：過去日期的台銀值一旦快取，永久有效，買入日匯率與目前匯率來源不同的狀態不會自己消失。
- **徽章在快取命中時會消失**：徽章只認「備援」；快取命中時狀態不是「備援」，備援的揭露會在使用者面前消失，這是**危險方向**。
- **兩項前置，缺任何一項風控都否決 W11-5 出貨**，**不論 CEO 是否核可 C-24 的 RK-5 前置條件**：
  - **N-2**：徽章要補上快取命中時照樣顯示備援的分支，與 W11-5 同一個 PR，並列入 C-22 表格。
  - **N-3**：ADR-0015 D-4 寫明，快取命中與舊值退回時，匯率來源紀錄是該列**原本的**來源，並用測試釘住。理由：來源紀錄失真，會讓 RK-2 的銜接句與總覽混源句出現**假的「混用」**，或把方法論說明**歸錯來源**。
- **以上均為接線後的推定，未實測**（沿用 ADR-0015 的推定）。

- 在這個狀態下，若台銀曾有回應 → **high**。

### 為什麼用「所指的匯率」而不是「這句說明」
- 失敗句裡本來就有「匯率報價沒有可用數值（…來源 …）」，若寫「這個匯率」而沒有先行詞，讀者會以為是在說那個沒有可用數值的報價。
- 先寫「來源說明所指的匯率」，後面的「這個匯率」就只能指它。

### 為什麼不選替代案
- **替代案 A（41 字）**：最短，且完全不出現「換算」二字，最不容易被讀成「價格與 ATR 另有換算」。代價是「不含價格與 ATR」比約束字面「沒有用這個匯率換算」弱，它說的是「這句說明不涵蓋」，沒有明說「價格與 ATR 沒用這個匯率」。若風控認為 RK4-R3 的「暗示價格類上限有計算」比「字面逐字對齊」更重要，退到 A。
- **替代案 B（50 字）**：把市值放句首，語氣是「只有這部分會用到這個匯率」。代價是「才會用到」帶排他語氣，比「只對應」更強，且 B 的先行詞「此處來源說明所述的匯率」出現在「才會用到」之後，讀起來要回頭看。不推薦。

### 為什麼用「會算進」而不用「可能」

## X-13：F-1b 合併前，只有一個能實際執行的升級偵測，而且它看不到估值本身（F-1b，medium）

**一句話**：F-1b 合併前，只有一個能實際執行的升級偵測：後端 log 裡的一行警告，而且這行警告**可能多計**。它**看不到估值本身**：總覽頁的總資產與持倉市值所用的匯率是 0 或負數時，這行不會記；偏偏這個估值正是缺陷的主要所在。（總覽頁上的風險儀表有涵蓋，沒涵蓋的是總資產與持倉市值的估值，不是整個總覽頁。）匯率為 0 時，風險上限會**靜默錯誤通過**，方向是危險的（數字看起來比實際安全）。log 若沒有保存，結果是「無法觀測」，**不是「零」**。等級維持中等，理由是無法查證。

### 1. 偵測能力的現況（已存在）
- **能用的只有一個**：後端 log 的一行警告（卡片、警示或風險儀表拿到的匯率報價沒有可用數值，而持倉市值卻用了匯率換算時，會記一行）。F-1b 自己的警告要等 F-1b 合併後才存在。
- **什麼算觸發（RN-13）**：只計報價來源不是 none 的行；來源為 none 是兩層都失敗、屬一般取不到匯率，不算。
- **它可能多計**：
  1. 報價其實有回應、但回應裡所有匯率的日期都晚於查詢日時，也會記這一行；這種情形不是 0 或負匯率。
  2. 接上的來源不是備援梯子時，取不到匯率會帶它自己的 id（不是 none），也會被記成這一行；正式環境一律是梯子，所以這是次要來源。
  - 多計的方向是「多升級」，屬保守方向，風控接受。所以這一行出現，只能說「上界」，**不能說已確認有 0 或負匯率**。
- **它看不到估值本身（RN-14）**：總覽頁的總資產與持倉市值所用的匯率是 0 或負數時，這行不會記；這個估值就是缺陷本身，偵測沒有涵蓋這條路。風險儀表（總覽頁上的元件，每個標的都會走同一套帳本計算）是有涵蓋的，所以盲區是估值，不是整個總覽頁。**這行警告是零，不代表估值沒事。**
- **它在這些情形下不記（RN-12，共兩種）**：
