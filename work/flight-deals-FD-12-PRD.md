CEO 原話：「幫我改 UI 排版 太多文字的問題 我不需要看到甚麼『Google 未在頁面內嵌此查詢的結果（多為來回＋商務艙＋多人），無法自動查價；請用查票連結人工查看』這種文案 可以幫我修改? 甚至優化其他部分的排版跟 UI 樣式 我想要更友善使用。再來就是可以跟我講是哪一間 我只知道價格但不知道是哪個航班哪個航空哪個時間 甚至購買網址也可以給我」

## 背景與目標

v0.1.0 已定版，功能齊但頁面文字過量，且只有價格、沒有「是哪一班」。經 PM 讀 code 複核：

1. 各頁已有「航空公司」「出發時刻」欄位，但被重複的長句淹沒；來回查詢時 Google 只列去程航班，價格卻是來回總價，回程班次不在資料裡。
2. 解析器 `sources/google_payload.py` 目前只取每筆行程的航空公司名稱清單與首段出發時刻，沒取航班號碼、抵達時刻、日期、轉機點。這些在 payload 的 segment 內有（位置見附錄 A，需 dev-lead 以 `tests/fixtures/payload_TPE_NRT_BR_06_12.json` 複核）。
3. 沒有逐航班的直接購買網址；現有的是帶日期組合的 Google Flights 精確查票連結（tfs），開到該日期組合的結果頁，使用者可從該頁選航空或旅行社購買。
4. 文字過量實例（皆已在 templates／`domain/messages.py`／`services/views.py` 核實）：
   - 每列重複「（1 人總價）」「Google Flights（即時價）」。
   - `DISCLAIMER` 在詳情頁出現 2 次（最便宜區、舊設定區）；`SAMPLED_ONLY_NOTE` 的語意在詳情頁出現 3 次（最便宜區、價格分布區、舊設定區）。
   - `views.NO_EMBEDDED_LABEL` 長句掛在有價格的監看下方；列表另有「連續 N 輪…」標籤，兩者並列。
   - 本次取樣表直接露出英文診斷（例 `no result section embedded in the page`，來源 `sources/google_flights.py`）。

本批目標：
- G1：從列表、詳情、探索結果、比價結果任一處，一眼看到「哪家航空、哪班（航班號碼）、去程幾點出發幾點抵達、直飛或轉機」，並有一顆按鈕「到 Google Flights 查看並訂票」開到該日期組合的結果頁（非直接訂位）。
- G2：文字量大幅下降，且不刪除任何風控要求的誠實揭露。
- G3：版面改為卡片式與「已查到最低價」主卡，次要表格預設收合。

## 使用者與情境

單一使用者（CEO）自用，1 位成人、經濟艙。多人／兒童的監看仍存在於資料庫，顯示需維持正確（見 FR-8），但不為其優化。

主要情境：
- S1：打開監看列表，掃一眼知道每個監看目前最低價是哪一班、幾點、怎麼買。
- S2：進詳情頁，頂部直接看到「已查到最低價」那一班與「查看並訂票」按鈕。
- S3：探索／比價結果裡，看到每個日期或目的地的最低價是哪一班。
- S4：Telegram 價格通知也要看得出是哪一班。
- S5：某監看 Google 不內嵌結果，只看到簡短「需人工查價」，不被長句打擾。

## 範圍內 / 範圍外

範圍內：
- 航班細節（解析、保存、顯示）：列表、監看詳情、探索結果、比價結果；Telegram 價格通知與 `/watch` 最便宜清單各加航班資訊。
- 文案精簡（見「文案對照表」）、診斷文字不外露。
- 列表卡片化、詳情主卡、次要表格預設收合、探索／比價欄位合併。
- 連結文案由「查票」統一為「到 Google Flights 查看並訂票」（縮寫「查看並訂票」；全站不得單獨出現「訂票」；連結目標不變，仍是 Google Flights 結果頁）。

範圍外（non-goals）：
- 新資料源、Travelpayouts、多人／兒童情境優化。
- 回程班次抓取（需第二次查詢，額度成本另案；見開放問題 Q1）。
- 逐航班的直接購買網址；**不得捏造航空公司官網或旅行社連結**。
- 機型顯示（payload 有，CEO 沒要）。
- 舊資料回填航班細節（舊列維持「—」）。
- Telegram 的 `/list`、每日摘要、`/scan` 結果、`/status` 的版面與文案；Telegram 的免責與取樣聲明不動。
- 設定與健康頁的整體改版（只動下列對照表列出的兩處）。
- 任何建議性、催促性文案（風控紅線）。

## 功能需求（逐條編號）

### A. 航班細節

- **FR-1 解析與保存**：每筆價格觀測（`price_observation`）、探索格（`exploration_cell`）、比價格（`comparison_cell`）要能保存「該最低價對應的那一班」的逐段明細：每段的航空代碼、航班號碼、航空名稱、起訖機場、出發時刻與日期、抵達時刻與日期。新欄位解析失敗或缺漏**不得**使該筆價格被丟棄、改變其分類或讓查價結果變成 blocked；缺的欄位視為未知。儲存形式（欄位或 JSON）與 migration 由 tech-architect 裁定（預期需要新 migration 0009，欄位皆可為 NULL，依慣例附 `pre-v9` 備份）。
- **FR-2 顯示格式**（網頁；所有顯示航班處一致，由單一共用元件／函式產生）：
  - 航空公司：依序列出該行程各段的航空公司名稱，去重後以「、」連接（沿用現有航空公司顯示規則，已知代碼顯示中文名）。
  - 航班號碼：每段「代碼 空格 號碼」（例 `BR 184`），多段以「 → 」連接（例 `BR 198 → JL 99`）。
  - 去程時刻：`出發 → 抵達`，HH:MM，皆為各機場當地時間；主卡以小字標「當地時間」，其他位置於收合說明註明。抵達日與出發日相差 N 天時，抵達時刻後加「+N」（N>0）或「−N」（N<0）；差 0 不加標記。
  - 轉機：直飛顯示「直飛」；轉機顯示「轉機 N 次」並附轉機機場代碼（例「轉機 1 次（HKG）」，多點以「、」連接；機場代碼可附城市名，沿用既有機場名稱表）。
  - 任一欄未知顯示「—」，不顯示空白、不顯示 `None`、不報錯。抵達時刻必須同時有時刻與兩端日期才顯示，否則抵達顯示「—」（避免隔日抵達被誤顯示為當日）。
- **FR-3 舊資料相容**：升級前已存在的列（新欄位為 NULL）顯示：航空公司與出發時刻沿用現有欄位值，航班號碼、抵達時刻、轉機點顯示「—」；同頁新舊並存不得錯位、不得顯示 `None`。不回填。
- **FR-4 來回只標去程**：來回行程的航班資訊區一律標「去程」（例「去程 BR 184　06:50 → 10:30」），價格標「來回總價」；不得出現任何回程航班號碼／時刻，也不得以措辭暗示已知回程班次。回程日期放在「日期組合」行，**不放進航班區塊**。有來回價格的頁面（列表、詳情、探索結果含日曆上方、比價結果）須**一次可見、不收合**（風控 R10，逐字）：「只列去程航班；回程需在 Google Flights 選擇，價格可能因回程不同而改變。」單程行程不加「去程」字樣；單程價格標示全站一致（標「單程價格」或一律無前綴，由 UI 實作者決定後全站同）。
- **FR-5 查看並訂票按鈕**（風控 R1、R3）：每個顯示航班的位置（列表卡片、詳情主卡與前 N 筆、探索日曆格與前 5、比價列）提供「到 Google Flights 查看並訂票」（表格內、日曆格可縮為「查看並訂票」；全站不得單獨出現「訂票」，欄名同）。連結沿用現有精確 tfs 連結（`BookingLinkBuilder`）；新分頁開啟、`rel="noopener noreferrer"`，連結後附「↗」並配 sr-only「（另開新分頁）」。主卡按鈕旁可見提示（逐字）：「開啟 Google Flights 該日期組合的結果頁（非直接訂位），請依航空公司與起降時刻選擇。」外部連結網域**只限 Google Flights**。連結無法建構時退回「只帶航線與日期」連結，**每個備援連結旁**可見：「連結只帶航線與日期；人數、艙等、篩選請在 Google 重選」（Telegram 版維持原句，拆兩個常數）。
- **FR-6 覆蓋範圍**：
  - 列表：每張卡片顯示該監看最低價那一班（FR-2）＋「查看並訂票」按鈕。
  - 詳情：「已查到最低價」主卡、「其他日期組合（依價格）」每列、「最近價格紀錄」每列。「舊設定的價格紀錄」維持現有欄位（僅航空公司），不加航班細節。
  - 探索：價格日曆每個有價格的格（精簡版：價格、`代碼 號碼`、`出發→抵達`、直飛／轉機、查看並訂票）、最便宜前 5 每列完整版。
  - 比價：每個有價格的目的地列完整版。
- **FR-7 Telegram**：
  - 價格通知（`price_alert_message`）（風控 R14）：原「航空公司：X」一行改為「航班：<航空公司> <航班號碼>｜去程 06:50 → 10:30（當地時間，直飛）」（例：「航班：長榮航空 BR 184｜去程 06:50 → 10:30（當地時間，直飛）」）。**單程不加「去程」**；任一欄缺漏則**省略該段**而非印「—」。新欄位全為 NULL 時退回原「航空公司：X」一行。不新增行數、不改其他行。
  - `/watch` 最便宜清單：每組現有的航空公司欄位改為「航空公司 航班號碼 出發→抵達」，來回時在時刻前加「去程」（單程不加），缺欄省略該段、新欄位全 NULL 時退回原寫法（風控短審 C1），其餘欄位不動；頁尾加一句「查到時間為台北時間；航班時刻為各機場當地時間。」（取代原 `COMMAND_TIME_NOTE` 僅用於 `/watch`，**不改** `/list`、`/scan` 共用常數，需拆常數）；仍受 `fit_reply` 長度上限（3800 字）管轄，免責與總價註記不得被截掉。
  - 「查票連結：」標籤維持不變（Telegram 不改連結文案）。

### B. 文案精簡

- **FR-8 人數註記**（C-40 修訂，風控同意，條件 (a)～(e)）：
  - (a) 1 位成人時，網頁價格旁不逐列顯示「（1 人總價）」，但**每個有價格的頁面／卡片的摘要列可見**「1 位成人・艙等」（列表每張卡片、詳情主卡、探索／比價頁首）。
  - (b) 人數 >1（成人＋兒童）時，**每個價格逐一**帶「N 人總價」／「A 大 C 小總價」（沿用既有形式，去括號）；多人預算顯示同樣註明（(e)）。
  - (c) Telegram、每日摘要、通知紀錄頁維持原樣。
  - (d) tech-architect 於 C-40 修訂條文寫入兩組測試：1 人摘要列斷言、多人逐價格斷言。
  - 未完成 C-40 修訂前此項不實作，其餘不受阻。
- **FR-9 來源名稱**（風控 #13）：僅當**整頁**所有價格皆為 Google Flights 即時價，才可在頁面層級說明一次（頁尾或收合說明）；否則**該列顯示來源**。任何一列為「快取價，非即時」或「資料時間未知」時，該列逐列顯示小標籤（重大限定，必須可見）。
- **FR-10 免責與取樣聲明每頁各一次**：
  - `DISCLAIMER`（「價格為查到當下的參考值，實際以航空公司或訂票網站為準。」）**文字不改**（Telegram 共用同一常數），在**所有顯示價格的頁面**（含列表、詳情、探索／比價結果，**含進行中頁面**）可見地出現恰好 1 次：不收合、內文字級（非小字註腳）、**緊鄰該頁第一個價格區塊且同首屏**。逐列限定（快取價、可能已過期、幣別不符）照樣逐列。**不得出現牴觸 `DISCLAIMER` 的句子**。**不得刪除**。
  - **通知紀錄頁例外**：該頁的 `DISCLAIMER` 與 #46 在頁尾，不符「緊鄰第一個價格區塊且同首屏」；風控接受為**只限此頁的明確例外**，其他頁面不得比照。
  - **#46**（risk-gate M2）「價格取自 Google 預設排序的結果；同一航班在 Google「最低價格」分頁可能較低。」在所有顯示價格的頁面可見地出現恰好 1 次：不收合、緊鄰 `DISCLAIMER`；`DISCLAIMER` 不改字。
  - `SAMPLED_ONLY_NOTE` 文字不改，在會呈現取樣結果的頁面（詳情）可見地出現恰好 1 次，**緊鄰主卡**（風控 R7）；價格分布區與舊設定區不再重複。
  - 探索／比價的「參考值，不會寫入監看紀錄／不會推播」說明改為短句（見對照表），免責句仍保持每頁 1 次。
- **FR-11 需人工查價與列表狀態**（風控 R5、#19）：
  - `no_embedded_results` 在使用者介面改為短標籤「需人工查價」（不落到「查詢失敗」）。僅當**該單位**（一個監看；一個探索格；一個比價目的地）沒有任何可顯示價格時才顯示；已有價格者不顯示該標籤與長句。原長句只留在標籤旁的收合「說明」內。**例外**（risk-gate 接受）：詳情「本次取樣的日期組合」表以單一日期組合為單位，該列可顯示「需人工查價」，即使同一監看其他日期已有價格。
  - 有價格、且連續 N 輪（N 取自 `no_embedded_streak_rounds`）未內嵌時，**可見短標籤「近 N 輪未更新」**取代原「連續 N 輪 Google 未內嵌結果，請用查票連結確認」長句；無價格時只顯示「需人工查價」，不重複顯示此標籤。
  - 列表卡片須顯示該最低價的**查到時間**，超過過期門檻時顯示「可能已過期」（與詳情主卡一致）。
  - 監看層級「已結束」（所有日期已過期）以簡短狀態標籤顯示，不附長句（見對照表）。
- **FR-12 診斷文字不外露**：使用者可見處不得出現原始英文／技術診斷字串（例 `no result section embedded in the page`、例外類別名、HTTP 狀態碼原文）。本次取樣表的「說明」欄與各「備註」欄一律改顯示中文標籤（沿用既有 `SKIP_REASON_LABELS`、`EXPLORATION_CELL_LABELS` 等對照；查無對照者顯示「查詢失敗」）。原始訊息仍留在資料庫與日誌供除錯。設定與健康頁的「最近錯誤」原文移入收合的「技術細節」。
- **FR-13 長說明收合**：凡屬操作解釋、計算規則、保留期限、排序規則等非誠實揭露的說明，改為一句短句＋「說明」收合區（HTML `<details>`，無 JavaScript 也可展開）。必須可見（不得收合）的只有：FR-10 兩句、FR-4 的「去程」標示與來回說明句（#43）、FR-5 主卡提示（#44）與備援連結提示、#4 較前一輪短句、「快取價／資料時間未知」標籤、「可能已過期」標籤、「近 N 輪未更新」標籤、「幣別不符」標籤、錯誤與中斷狀態。
- **FR-14 文案對照表與審查**：下節「文案對照表」列出所有會改的使用者可見文案；未列入者不得改。所有新字串須進 `all_static_texts()` 並通過 `BANNED_PHRASES` 政策測試；先送 risk-compliance-officer 審查（有否決權）再實作。

### C. 排版

- **FR-15 列表卡片式**：每個監看一張卡片，由上而下：名稱＋狀態標籤；路線・行程類型・日期設定；**最低價（放大）**＋較前一輪變化；那一班（FR-2）；日期組合與星期；最低價**查到時間**與「可能已過期」標籤（FR-11）；摘要列「1 位成人・艙等」（FR-8 (a)）；「到 Google Flights 查看並訂票」（主按鈕）＋「詳情」；次要操作（修改、停用／啟用、立即查價、刪除）為小按鈕或收進「更多」。價格標「已查到最低價」（風控 R4）。「條件：不限」不顯示；有篩選條件時才顯示一行。從未查過的卡片以簡短標籤「尚未查價」取代價格區；已查過但沒有可顯示價格（需人工查價、已結束、出發日皆過）的卡片改用「目前無可顯示的價格」（#47）。需人工查價的卡片（FR-11）顯示標籤與「到 Google Flights 人工查價」連結。漲跌徽章上升與下降對稱呈現、無動畫、不只高亮下跌（R6）。

## 驗收條件（每條需求至少一組 Given/When/Then）

共同前提：測試用 fixture 為 `tests/fixtures/payload_TPE_NRT_BR_06_12.json`（長榮 BR 184 直飛）；另備「隔日抵達」「一次轉機」「兩段不同航空代碼」「segment[22] 缺漏」「抵達日期缺漏」五種合成 payload。

- Given fixture 的 BR 184 行程，When 解析並寫入觀測，Then 該筆記錄含航空代碼 BR、航班號碼 184、航空名稱、起訖機場 TPE→NRT、出發與抵達時刻與日期。

- Given 直飛 BR 184 06:50→10:30 同日抵達，When 渲染，Then 出現「長榮航空」「BR 184」「06:50 → 10:30」「直飛」，且無「+」「−」標記。

## 風險與依賴

- R1：payload 位置為非官方、逆向取得，Google 可能改版。降低方式：新欄位解析失敗只降級為「—」，絕不影響價格記錄與狀態分類（FR-1）。
- R2：C-40（「價格旁一律帶總價註記」）為 accepted ADR 且各頁有斷言；FR-8 需 ADR 修訂與風控同意，未同意前此項不實作，其餘 FR 不受阻。
- R3：FD-8 的快照讀取與覆蓋索引（列表 180 天穩態 185 ms）可能因新增欄位被破壞；列表查詢須取最低價那一列的航班資訊，tech-architect 需評估索引與查詢方式（FR-15 效能驗收）。
- R4：同一查詢內多班同價時，只能顯示被記錄的那一班；需有確定的取捨規則（建議最早出發），避免每次顯示不同班。
- R5：「查看並訂票」可能讓人以為連結直達該班或可直接付款；以風控裁定的提示「開啟 Google Flights 該日期組合的結果頁（非直接訂位），請依航空公司與起降時刻選擇。」緩解（風控已 APPROVE WITH CHANGES）。結果頁的價格可能與此處不同，已由 `DISCLAIMER` 承擔。
- R6：Telegram 只改兩處；`BOOKING_FALLBACK_NOTE` 與 `DISCLAIMER` 與 Telegram 共用常數，網頁縮短備援提示時須拆分，避免誤改推播。
- R7：改版面積大（四頁＋Telegram），建議拆批實作（依賴順序：資料層 → 共用元件 → 詳情 → 列表 → 探索／比價 → Telegram → 快照重錄）。
- 依賴：tech-architect（migration、儲存形式、C-40 修訂、快照裁定、列表效能）；risk-compliance-officer（對照表審查，有否決權）；dev-lead／frontend-engineer（實作）；qa-reviewer（含 Codex）；qa-e2e（實機）；tech-writer（CHANGELOG）。
