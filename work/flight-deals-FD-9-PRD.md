## 背景與目標

FD-6 的探索回答「同一條航線，哪天最便宜」。CEO 是對目的地彈性的單人旅客，另一個常見問題是「這組日期從台北出發，去哪裡最便宜」，目前只能逐條航線各建一個監看或各跑一次探索。

目標：
1. 新增「多目的地比價」：固定一組日期，對 2～8 個目的地各查一次，結果依總價由低到高排列。
2. 成本可控：N 個目的地恰好 N 次對外查詢，受既有每小時額度與「保留 12 給排程」約束；開始前額度不足則整體拒絕（與探索一致），不拖垮排程。
3. 與探索一致的保存規則：同條件 24 小時重用、7 天清除。
4. 從比價結果一鍵預填「新增監看」（不自動送出），銜接持續監看。
5. 順手完成三項前批遺留的低風險文案小修（風控 recommended、QA low）。

成功指標（以可驗證行為為準）：
- 選 N 個目的地，完成後對外查詢次數恰為 N（額度足夠時），不超過。
- 結果表依總價由低到高、並列有固定次序；每個失敗或未查的目的地都有原因，不顯示空白或 0。
- 24 小時內同條件再比價不重查、不耗額度。
- 三項收尾文案與條件符合驗收條件，其餘既有文案逐字不變。

產品前提（沿用）：價格為查到當下的參考值，實際以訂票網站為準；比價結果是事實查詢結果，文案只作事實陳述，不作建議。**人數固定 1 位成人**（CEO 2026-10-29 指示單人優先），表單不提供人數欄位。

## 使用者與情境

- 使用者：CEO 本人，單一使用者，本機，桌機與手機瀏覽器皆會用。
- 情境 A：12/10 出發、12/15 回程，想從台北比較東京、大阪、首爾、曼谷、新加坡哪裡最低，輸入 5 個目的地，數分鐘後看到由低到高的表。
- 情境 B：只知道「12 月中旬出去玩 5 天」，用「出發日＋旅程天數」輸入，同樣比較。
- 情境 C：表中大阪最低，點「建立監看」帶入表單，改填預算後送出。
- 情境 D：某目的地被擋或無資料，表中仍列出該列並說明原因，不被誤認為沒有航班。
- 情境 E：本小時可用額度不夠查完 8 個目的地，系統整體拒絕並說明可用額度，不查任何一個、不建立比價，保留額度給排程。
- 情境 F：昨天比過同組條件，今天再按一次，直接看到昨天結果。

## 功能需求（逐條編號）

### 一、輸入與驗證（FR-C）

- FR-C1 入口：`/explore` 頁僅放「多目的地比價」入口卡片；表單位於獨立子頁 `GET /explore/compare`，頁面說明「固定一組日期，對每個目的地各查一次」；結果頁為 `/comparisons/{id}`。導覽列不新增項目。
- FR-C2 出發地：單一，沿用機場中文自動完成（含城市代碼，如 TYO、OSA、SEL），預設 TPE。
- FR-C3 目的地：2～8 個，使用機場中文自動完成逐個加入、可逐個移除；已加入的目的地以中文名加代碼顯示。不得重複：同代碼，或城市代碼加其轄下機場（例 TYO＋NRT）視為重複，回 422；同城市的兩個機場（例 NRT＋HND）允許。不得等於出發地。
- FR-C4 行程型態：來回或單程，預設來回。
- FR-C5 日期輸入二選一：
  - 固定日期：出發日；來回另填回程日。
  - 出發日加旅程天數（僅來回）：回程日＝出發日＋旅程天數。旅程天數為正整數，範圍沿用 FD-6 預設 1～30。
  - 單程只填出發日。
- FR-C6 日期範圍：出發日下限為今天（含今天，Asia/Taipei，與既有 `check_not_past` 一致，非今天+1），回程日不得早於出發日，且皆不得超過系統可查日期上限（今天起 365 天，沿用 FD-6）。
- FR-C7 轉機上限：沿用既有監看欄位與驗證（不限／直飛／最多 N 次，以既有選項為準）。
- FR-C8 艙等：沿用既有艙等選項，預設經濟艙。
- FR-C9 人數：固定 1 位成人，表單不顯示人數欄位，後端忽略任何傳入的人數參數並以 1 成人處理（不接受多人）。
- FR-C10 後端驗證：以下一律後端回 422、欄位旁顯示明確訊息，不建立比價、不消耗額度：出發地空白或不在白名單；目的地少於 2 或多於 8；目的地不在白名單；目的地重複；目的地等於出發地；日期格式或範圍不合法；回程早於出發；旅程天數不合法；轉機上限或艙等不合法。前端限制不得取代後端驗證。
- FR-C11 開始前預覽：按鈕旁顯示預計查詢次數 N（等於目的地數）與本小時可用額度（已扣除保留額度）。使用者按「開始比價」才啟動。

### 二、執行、額度與進度（FR-R）

- FR-R1 查詢數：每個目的地恰查 1 次（以指定的日期組合與全部條件），N 個目的地對外查詢恰 N 次。價格口徑為 1 位成人總價，取該次查詢最低價（沿用 FD-6 FR-R3、Decision 9a）。
- FR-R2 背景執行：啟動後立即導向進度／結果頁，查詢在背景序列執行，沿用既有節流與 jitter（ADR D-2），不得繞過。
- FR-R3 額度與保留：沿用探索的額度口徑（`exploration_reserve_for_scans`＝12，即全域每小時上限需保留 12 次給排程）。可用額度＝全域每小時剩餘額度減去保留值（不小於 0）。
  - 可用額度 ≥ N：全部查詢。
  - 可用額度 < N：整體拒絕（HTTP 409，quota），顯示可用額度與所需次數；對外查詢 0 次、不建立比價紀錄、不做部分查詢（與探索一致，總經理裁示）。
  - 執行中途額度被其他查詢用完或斷路器打開：見 FR-R6。
- FR-R4 進度：顯示「已查 N／共 M」與進度條，M 為實際要查的次數；狀態含進行中、已完成、已中斷。自動更新，完成或中斷即停止並載入結果。輪詢沿用 ADR C-30 約束精神（白名單欄位、`Cache-Control: no-store`、無 `innerHTML`）。
- FR-R5 單一目的地失敗不中斷：被擋、錯誤、無資料、未內嵌結果皆記錄該目的地狀態與原因後繼續。狀態沿用探索：`ok`／`no_data`／`blocked`／`error`／`skipped`（未內嵌結果的呈現沿用 FD-6 FR-S2 文案）。錯誤文字須先經既有遮蔽處理。
- FR-R6 斷路器與中途額度用盡：沿用 FD-6 FR-R6／R10。斷路器轉開或額度中途耗盡時，剩餘目的地不再發出查詢，標記為 `skipped` 並說明原因，比價狀態為 failed（頁面顯示「已中斷」），已查結果保留。
- FR-R7 與排程共用 worker：沿用 FD-6 FR-R7／R8（探索或比價進行中，排程與立即查價順延、不丟件、不重複，並顯示順延說明）。比價與探索之間同一時間最多一個在跑：進行中再按開始，條件相同導向進度頁，不同則拒絕並附進度連結。
- FR-R8 服務重啟：進行中的比價重啟後標「已中斷」，已查結果保留，不自動接續。
- FR-R9 不污染監看：比價結果不寫入任何監看價格紀錄、最低價、趨勢、通知、每日摘要；查詢次數須計入全域每小時用量與健康頁用量顯示。

### 三、結果呈現（FR-S）

- FR-S1 結果表：依總價由低到高。每列：目的地（中文名＋代碼）、總價（標「1 人總價」）、航空公司（沿用探索已驗收的 `carrier` 原樣呈現，不另做中文轉換）、直飛或「轉機 N 次」、飛行時長摘要、查到時間、tfs 查票連結、「建立監看」按鈕。
- FR-S2 排序與並列：有價格的列在前，依總價升冪；同價依「目的地輸入順序」。無價格的列（`no_data`、`blocked`、`error`、`skipped`、未內嵌結果）排在有價格的列之後，順序依輸入順序。
- FR-S3 無價格列原因：必須顯示原因，不得空白或 0：無資料、未內嵌結果（請用查票連結人工確認）、被擋或查詢失敗、未查詢（額度不足／已中斷）。無價格列（`skipped` 除外）仍附查票連結。
- FR-S4 條件摘要與免責：頁面頂部顯示出發地、日期、行程型態、轉機上限、艙等、「1 位成人」；固定附既有 `DISCLAIMER` 免責句（沿用，不另擬）；超過 24 小時的結果顯示「價格為 N 小時前查到，可能已變動」。
- FR-S5 文案：只作事實陳述（例「查到 TWD 9,200（1 人總價）」），不得出現「建議」「最佳」「現在買」「划算」「推薦」等語氣與 ADR C-17 禁用字；表頭不得把最低價目的地標示為「推薦」。
- FR-S6 中斷結果：已中斷的比價頂部標示「比價未完成（已查 N／共 M），原因：…」，已查結果照常顯示。
- FR-S7 視覺與可及性：375px 寬度可閱讀與操作（可橫向捲動或改為清單式）；狀態以文字呈現，非僅靠顏色。

### 四、建立監看（FR-W）

- FR-W1 每個有查詢的列（含無價格列，`skipped` 除外）有「建立監看」按鈕，導向新增監看表單並預填：出發地、該列目的地、行程型態、固定日期（出發日，來回另含回程日）、轉機上限、艙等、人數 1 成人。預算與名稱不預填；不自動送出。
- FR-W2 預填可修改，送出走既有後端驗證，不繞過；表單頂部顯示「已由比價帶入條件，請確認後送出」；放棄不留殘留資料。

### 五、重用、保留與歷史（FR-K）

- FR-K1 重用：同一組條件（出發地、目的地集合、行程型態、日期、轉機上限、艙等）在 24 小時內已有「已完成」的比價，按「開始比價」直接顯示該結果，不查詢、不消耗額度、不受額度檢查影響，頁面註明「顯示 N 小時前的比價結果」。目的地集合以代碼集合比較，與輸入順序無關。已中斷的比價不適用重用。
- FR-K2 超過 24 小時視為新比價（走 FR-R3），舊結果保留至清除。
- FR-K3 保留：自 `created_at` 起算保留 7 天後自動清除（與探索一致）；清除不影響任何監看與其價格歷史。已清除網址顯示「比價已過期或不存在」說明，不是錯誤頁。
- FR-K4 歷史清單：比價區塊列出保留期內的比價（出發地、目的地數、日期、完成時間、狀態、最低價與其目的地），可點入重看。

### 六、三項收尾（FR-F）

- FR-F1 `/scan` 失敗輪次文案：目前失敗輪次顯示「本輪取樣 N 組日期，對外查詢 0 次」（`domain/messages.py` 掃描結果文案）。當一輪對外查詢 0 次時改顯示「本輪排定 N 組日期」；有對外查詢時維持現有文案逐字不變。
- FR-F2 詳情頁空狀態：監看詳情頁在「所有已查到的價格其出發日都已過」的情況下，空狀態文案須與「尚未查到價格」區分，改述為事實（例「已查到的價格，其出發日皆已過，無可顯示的最新價格」；最終字句由實作者擬，需符合 C-17）。尚無任何價格紀錄時維持「尚未查到價格。」逐字不變。
- FR-F3 `/watch` 旅程天數：彈性窗的最短＝最長旅程天數時，顯示「旅程 N 天」而非「旅程 N–N 天」；不同時維持「旅程 A–B 天」。此規則一併檢查網頁列表與詳情摘要（`services/views.py` 的彈性窗描述）是否同口徑，若網頁也顯示「N–N」則一併修正並視為本條範圍。

## 驗收條件（每條需求至少一組 Given/When/Then）

測試通則：自動化測試使用假資料源與假時鐘，不連外網。

### 一、輸入與驗證

- AC-C1 Given `/explore` 頁；When 檢視；Then 有「多目的地比價」入口與說明；導覽列未新增項目。
- AC-C2 Given 比價表單；When 不動預設值；Then 出發地 TPE、來回、艙等經濟艙；無人數欄位。
- AC-C3 Given 目的地欄；When 以自動完成加入東京、大阪、首爾並移除大阪；Then 清單為東京、首爾（各含代碼）。
- AC-C4 Given 比價表單；When 分別提交 (1) 目的地 1 個 (2) 目的地 9 個 (3) 目的地重複 (4) 目的地等於出發地 (5) 目的地代碼不在白名單 (6) 回程早於出發日 (7) 出發日為昨天 (8) 日期超過今天起 365 天 (9) 旅程天數 0 或 31；Then 皆回 422、欄位旁顯示對應訊息，不建立比價、不消耗額度。
- AC-C5 Given 以「出發日 12/10＋旅程天數 5」提交；When 檢視結果條件摘要與查詢日期；Then 回程日為 12/15；單程時不顯示也不接受旅程天數。
- AC-C6 Given 請求帶 `adults=3`；When 提交；Then 後端以 1 位成人處理，結果標「1 人總價」，不報錯亦不採用 3。
- AC-C7 Given 選 5 個目的地；When 檢視預覽；Then 顯示預計查詢 5 次與本小時可用額度。

### 二、執行、額度與進度

- AC-R1 Given 額度充足、5 個目的地；When 開始比價；Then 立即顯示進度頁，背景執行，全程對外查詢恰 5 次。
- AC-R2 Given 比價進行中；When 停留；Then 「已查 N／共 M」與進度條自動增加，完成後自動顯示結果表；進度端點僅回白名單欄位且 `Cache-Control: no-store`；關閉分頁後重開進度接續顯示。
- AC-R3 Given 全域上限 60、最近一小時已用 40（可用額度＝60−40−12＝8）、8 個目的地；When 開始；Then 8 個皆查。Given 已用 45（可用額度 3）、8 個目的地；Then 回 409 quota，顯示可用額度 3 與所需 8，對外查詢 0 次、不建立比價紀錄。
- AC-R4 Given 可用額度恰等於 N；Then 允許開始（邊界）；Given 可用額度為 N−1 或 0；Then 409，查詢 0 次、不建列。
- AC-R5 Given 第 2 個目的地被擋、第 3 個無資料；When 比價跑完；Then 仍完成，該兩列分別標「被擋或查詢失敗」「無資料」，其餘照常有結果；錯誤文字經遮蔽處理。
- AC-R6 Given 比價執行中斷路器轉開，或額度被其他查詢用完；When 發生；Then 剩餘目的地不再發出查詢、標 `skipped`，比價狀態 failed（顯示「已中斷」），已查結果保留。
- AC-R7 Given 全部結果為未內嵌結果；When 結束；Then 資料源連續失敗計數不增加、斷路器維持關閉、無 Telegram 告警（沿用 Decision 9a）。
- AC-R8 Given 比價進行中排程掃描時間到；When 時間到；Then 掃描順延到比價結束後執行（不丟件、不重複），頁面顯示順延說明。
- AC-R9 Given 比價或探索任一進行中；When 以相同條件再按開始；Then 導向進度頁；When 以不同條件按開始；Then 被拒並附進度連結，不建立新項目。
- AC-R10 Given 比價進行中服務強制關閉；When 重啟；Then 標「已中斷」，已查結果保留，不自動接續。
- AC-R11 Given 某監看有價格歷史；When 比價完成；Then 該監看價格紀錄、最低價、趨勢、通知、每日摘要皆不變，Telegram 無任何比價推播；健康頁最近一小時用量包含比價的查詢次數。

### 三、結果呈現

- AC-S1 Given 5 個目的地價格分別為 9,200／7,800／11,000／無資料／被擋；When 檢視結果表；Then 順序為 7,800、9,200、11,000，其後無資料、被擋；每列有目的地中文名＋代碼、「1 人總價」、航空（`carrier` 原樣）、直飛或轉機次數、時長、查到時間、查票連結、建立監看。
- AC-S2 Given 兩個目的地同價 8,000，輸入順序為 B 在 A 之前；When 檢視；Then B 排在 A 之前。
- AC-S3 Given 各種無價格列；When 檢視；Then 各列顯示無資料／未內嵌結果／被擋或查詢失敗／未查詢（額度不足或已中斷）之一，不出現空白或 0；除 `skipped` 外皆有查票連結。
- AC-S4 Given 查票連結；When 點擊；Then 開啟 Google Flights，出發地、目的地、日期、轉機上限、艙等、1 位成人與條件一致（沿用 tfs）。
- AC-S5 Given 結果超過 24 小時；When 開啟；Then 顯示「價格為 N 小時前查到，可能已變動」；任何狀態皆附既有 `DISCLAIMER` 免責句。
- AC-S6 Given 比價頁全部文案（樣板、JS、錯誤訊息）；When 檢查；Then 不含 ADR C-17 禁用字，且無「建議」「最佳」「現在買」「划算」「推薦」；表頭或最低價列不帶推薦語氣。**此項須送 risk-compliance-officer 審查，通過才可進 done。**
- AC-S7 Given 已中斷比價（已查 3／共 8）；When 檢視；Then 頂部標示「比價未完成（已查 3／共 8），原因：…」，已查結果照常顯示。
- AC-S8 Given 375px 寬度；When 檢視結果表；Then 可閱讀與操作，狀態以文字呈現。

### 四、建立監看

- AC-W1 Given 結果表大阪列（來回、12/10～12/15、直飛、經濟艙）；When 點「建立監看」；Then 新增監看表單預填 TPE→大阪、來回、固定日期 12/10～12/15、轉機上限、經濟艙、1 成人，預算與名稱為空，未自動送出，監看列表無新增。
- AC-W2 Given 預填表單；When 清空目的地後送出；Then 回 422 並顯示既有訊息；When 填預算後送出；Then 成功建立；When 關閉頁面不送出；Then 無殘留資料；頂部顯示「已由比價帶入條件，請確認後送出」。

### 五、重用、保留與歷史

- AC-K1 Given 同條件 3 小時前已完成的比價；When 再按開始；Then 直接顯示並註明「顯示 3 小時前的比價結果」，對外查詢 0 次，即使可用額度為 0 仍可重看。
- AC-K2 Given 同條件但目的地輸入順序不同；Then 視為同條件，直接重用。Given 目的地集合、日期、轉機上限、艙等任一不同；Then 視為新比價，走額度規則。
- AC-K3 Given 同條件最近完成已 25 小時前，或最近一次為已中斷；When 按開始；Then 視為新比價並重新查詢，舊結果仍在歷史清單。
- AC-K4 Given 一個完成 7 天又 1 分鐘的比價；When 清除作業執行後；Then 不在歷史清單，網址顯示「比價已過期或不存在」說明；未滿 7 天者保留；任何監看與價格歷史不受影響。
- AC-K5 Given 比價區塊；When 檢視歷史清單；Then 列出保留期內比價（出發地、目的地數、日期、完成時間、狀態、最低價與其目的地），可點入重看。

### 六、三項收尾

- AC-F1 Given `/scan` 一輪對外查詢 0 次且排定 12 組日期；When 回覆；Then 顯示「本輪排定 12 組日期」，不含「對外查詢 0 次」；Given 一輪對外查詢 5 次；Then 維持「本輪取樣 N 組日期，對外查詢 5 次」逐字不變。
- AC-F2 Given 監看已有價格紀錄但所有出發日皆已過；When 開啟詳情頁；Then 空狀態文案為「已出發」類事實陳述，與「尚未查到價格。」不同；Given 完全沒有價格紀錄；Then 仍為「尚未查到價格。」逐字不變。
- AC-F3 Given 彈性窗最短＝最長＝4 天；When `/watch` 回覆；Then 顯示「旅程 4 天」，不含「4–4」；Given 最短 3、最長 5；Then 顯示「旅程 3–5 天」；網頁若有同一描述亦同口徑。
- AC-F4 Given 全部既有測試；When 執行；Then 除 AC-F1／F2／F3 直接相關的期望值外不得修改既有期望值，且既有 957 項測試其餘全數通過。

## 風險與依賴

- 資料源風險（中高）：N 個目的地為 N 個不同航線，被 Google 節流或封鎖的機率與一般探索相近但分散在不同航線；因應：沿用節流、斷路器、保留額度，結果清楚區分「被擋」「無資料」「未內嵌」（ADR D-2）。
- 額度壓力（中）：8 個目的地約佔 8 次；保留 12 後可用額度偏小，部分目的地標 `skipped` 會降低使用者感受；因應：預覽顯示可用額度、FR-R3 明確原因、24 小時重用。
- 與探索共用資料模型的耦合風險（中）：若重用 `exploration`／`exploration_cell`，需避免探索歷史清單、清除作業與「單一探索進行中」判斷互相誤傷；見 tech-architect 開放問題 1、5。
- 數據誤讀風險（中）：不同目的地的價格口徑一致（1 位成人、最低價），但航程條件（時長、轉機）不同，表中需同時顯示以免只看價格；不作「哪個划算」的判斷。
- 風控閘門：結果表為事實查詢，但「依價格由低到高」的列表有被解讀為推薦的風險；FR-S5、AC-S6 要求全部新文案過 risk-compliance-officer（有否決權）。三項收尾文案亦併送。
- 收尾連帶風險（低）：FR-F1／F3 修改既有文案與測試期望值，需確認不影響其他引用處（如 Telegram 回覆樣板測試）。
- UI 驗收：涉及進度輪詢、自動完成、結果表、375px，完成前須 qa-e2e 實機驗收；無人值守環境依 e2e-fallback。依賴真實查價的項目（AC-R1 的 N 次、AC-S4 連結一致）由總經理或實作者實跑並附結果，其餘可用假資料源離線驗證。
- 祕密與遮蔽：失敗訊息沿用既有遮蔽；本批不新增祕密。
