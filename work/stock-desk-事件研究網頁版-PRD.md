# stock-desk 事件研究網頁版 — PRD

> 來源：CEO 指令（2026-09-12）「把五項觀察條件事件研究的五張圖從 CLI 搬進網頁」。
> 撰寫：product-manager。技術選型與實作方式留給 tech-architect／實作者。

## 背景

CLI（`app/backtest/event_study.py` + `event_study_charts.py`）已能算出「五項觀察條件同時成立」事件的前瞻報酬分布，並輸出五張已過風控（R1～R10）的 SVG 圖與固定字面（頁首範圍句／demo 警告／免責句／產出時間／除權息行／圖例、頁尾六句說明）。網頁版只是「把同一份輸出搬到瀏覽器」，不是重新設計。

## 目標

讓 CEO／內部使用者不必跑 CLI，就能在 stock-desk 網頁上看到與 CLI 完全一致（字面逐字、視覺編碼一致）的五張事件研究圖。

## 非目標

- 不新增互動（無 tooltip、無縮放）：企劃已明定 HTML 版固定 960px、無 script。
- 不重寫任何已核可字面（SCOPE_NOTICE／DEMO_DATA_WARNING／FOOTNOTES／圖例／讀圖說明）。
- 不在個股頁「六項觀察條件」面板新增任何東西（見放置位置決策）。
- 不新增第六條件（防禦型規則）的計算或顯示。
- 不做行動裝置優化、不做多標的比較、不做匯出。

## 放置位置決策

**採用 (a)：`/backtest` 頁，策略選「五項觀察條件」（`five_conditions`）且回測有結果時，在既有「樣本內／樣本外」表格之後新增一節「事件研究」。**

否決 (b) 個股頁「六項觀察條件」面板下方：
個股頁是面向**持倉者**的建議脈絡（`work/stock-desk-進場觀察條件-PRD.md` 風控 R-09：成立數與時序不得離開個股頁）。把「歷史上五條成立後怎麼走」放在使用者正在看「這檔股票現在幾條成立」的面板旁邊，極容易被讀成「現在成立 → 之後會怎樣」的因果暗示，即使字面本身沒有問題，**版面鄰接關係本身就是暗示**，違反 R-02／R-09 的精神。此外六項觀察條件面板刻意不呈現時間序列、不做跨標的比較，事件研究的路徑圖／分布圖與此設計原則直接衝突。

否決 (c) 新頁 `/event-study/[symbol]`：
需要另建一份 symbol／market／start／end 輸入表單（重複 `/backtest` 已有的表單），且脫離「回測」入口後更容易被之後的功能（例如個股頁導覽列）連去，等於把研究脈絡的頁面暴露在建議脈絡的動線上，管理成本高於效益。`/backtest` 是研究脈絡的頁面（回測報告本身帶「歷史統計描述，不代表未來會重演」常駐句；策略為 `five_conditions` 的成功報告另帶 `FIVE_CONDITIONS_NOTE`），是現成的最低風險落點；事件研究節自身仍須逐字帶入 `SCOPE_NOTICE` 與 `RESEARCH_USE_NOTICE`（風控 REQ-W13：不得把不存在於頁上的揭露當成既有保護）。

## 圖的呈現方式（建議，交 tech-architect 定案）

**建議：後端 API 直接回傳 `event_study_charts.py` 既有函式產出的 SVG 字串，前端原樣內嵌顯示，不用 React 重畫座標軸／圖形。**

理由：
1. **單一事實來源**：五張圖與其上的每一句字面（含樣本數格式、圖例、讀圖說明）已個別過風控審查並被測試逐字釘住（`tests/test_event_study_wording.py`）。若前端用 React／canvas 重畫，等於在第二個地方重新實作同一份視覺編碼與文字，任何一次微調都要兩邊分別過風控、兩邊分別寫測試，維護成本與審查成本都乘二，也製造「兩份輸出各自對不上」的風險。
2. **審查成本**：企劃本身明定 HTML 版不做互動；既然不需要 tooltip、不需要縮放，前端重畫換不到任何使用者可感知的好處，只多一份要審的程式碼。
3. **互動需求**：企劃「C. 不做什麼」第五點已明寫「HTML 不做互動」，網頁版沒有理由比 CLI 版本多做。

需 tech-architect 決定的實作細節（非本 PRD 範圍）：新增的 API 端點形狀、是否重用 `render_html` 的區塊或另切一個「回傳元件而非整頁」的函式、SVG 字串內嵌到 React 時的處理方式（如 `dangerouslySetInnerHTML`）與對應的安全檢視。

## 參數

- 沿用 `/backtest` 表單既有欄位：`symbol`／`market`／`start`／`end`。除權息還原沿用事件研究 CLI 的預設行為（嘗試還原並在畫面上顯示實際結果句，同 `event_study.py._adjust_for_dividends` 的三種結果句），不新增使用者可切換的開關（表單本已無此開關，不擴大範圍）。
- **獨立按鈕，不隨回測自動觸發**：「執行回測」按鈕之外，新增「顯示事件研究」按鈕（策略為 `five_conditions` 時才顯示），使用者需另外按下才會計算與顯示。理由：(1) 事件研究與回測是兩種不同的分析（一個是有成本的策略績效、一個是無成本的價格分布），自動合併顯示容易讓使用者誤以為是同一份結果的兩個面向；(2) 明確的使用者動作對齊 CLI 版本「`--html` 是額外旗標，不是預設行為」的設計；(3) 避免每次回測都多打一次資料鏈，增加不必要的 provider 用量。

## 空狀態與降級

- 快取／資料鏈查無資料：沿用 `/backtest` 既有的「資料不足」呈現方式（見 `BacktestReportView.tsx` 的 `insufficient_data` 分支），不新造一套文案。
- 某期間（全期／前半／後半）五條同時成立事件數為 0：沿用 CLI／HTML 版既有字面（`本段五條同時成立事件數為 0，長條僅顯示基準。`／`…此圖僅顯示基準，不繪製事件序列。`），逐字重現，不改寫、不用新句。
- 使用的是 `demo_synthetic` 示範資料：逐字顯示 `DEMO_DATA_WARNING`，與回測頁既有的 demo 揭露並列，不得互相矛盾或省略任一句。
- 除權息無法還原（本機未同步 / 查無紀錄）：逐字顯示對應的三句提示之一，比照 CLI 行為。

## 風控前提（必須沿用 / 禁止事項）

- 必須逐字重現：`SCOPE_NOTICE`、`RESEARCH_USE_NOTICE`、`DEMO_DATA_WARNING`（有 demo 資料時）、`FOOTNOTES` 六句、除權息行、產出時間句、資料來源列、切點列、全域圖例三句。任何一句都不得被截斷、改寫或省略。
- 顏色與視覺編碼不得更動：事件＝藍 `#3987e5`／圓形／實線，基準＝黃 `#c98500`／菱形／虛線；`#c98500` 僅為分類色，不得與產品既有 amber 警示色統一使用，也不得承載任何警示或價值判斷。不得將正報酬塗綠、負報酬塗紅。
- 全頁不得出現：「進場點」「時機」「買點」「訊號」「條件成立」「建議」「目標價」「上看」等 `shared/forbidden-terms.json` 與 `work/stock-desk-進場觀察條件-PRD.md` 已列管的禁用詞；不得替讀者下「顯著／不顯著」「會漲／會跌」的結論；不得畫預測延伸線或目標線。
- 此區塊只能出現在 `/backtest` 頁、且只在策略為 `five_conditions` 時顯示；不得連結、內嵌或以任何形式出現在 `/position/[symbol]` 頁面或其面板。

## 功能需求

- FR-1：`/backtest` 頁在策略選單選到「五項觀察條件」且回測已成功回傳結果（`status !== "insufficient_data" && report.report !== null`）時，於回測報告 section **之外、同層後置**新增節「五項觀察條件 事件研究」（風控 REQ-W1／W3），節內先有區隔句（REQ-W2），再有按鈕「顯示五項觀察條件事件研究」。
- FR-2：按下按鈕後，前端呼叫 `POST /api/event-study`（沿用 `/api/backtest` 同一條 `MarketDataService` 資料鏈），以**畫面上回測報告所用**的 `symbol`／`market`／`start`／`end` 取得結果並渲染五張圖與全部頁首／頁尾字面；表單與該報告參數不一致時按鈕停用並顯示提示句（風控 REQ-W5）。
- FR-3：五張圖與其字面必須與 CLI `--html` 輸出的內容一致（同一組函式產出，見「呈現方式」章節），不得有第二套實作各自維護文字或配色。
- FR-4：五張圖的呈現順序固定為：事件後路徑圖 → 正報酬率區間圖（全期）→ 正報酬率區間圖（前半）→ 正報酬率區間圖（後半）→ 中位數與四分位圖，與企劃 A.3 一致。
- FR-5：資料不足、事件數為 0、demo 資料、除權息未還原等狀態，依「空狀態與降級」章節逐字呈現，不新增未經風控審查的文案。
- FR-6：策略非 `five_conditions` 時，不顯示「顯示事件研究」按鈕，也不得殘留上一次的事件研究結果。
- FR-7：切換表單任一參數（`symbol`／`market`／`start`／`end`）、切換策略、重新執行回測或回測結果物件更換後，畫面上已顯示的事件研究結果一律**清除**（風控 REQ-W4：清除，不標示）。

## 驗收條件

- AC-1（放置與觸發）
  Given 使用者在 `/backtest` 頁選擇策略「五項觀察條件」並成功執行回測
  When 頁面渲染完成
  Then 樣本內／樣本外表格之後出現「顯示事件研究」按鈕，且個股頁 `/position/[symbol]` 任何位置都看不到此按鈕或事件研究內容。

- AC-2（字面一致）
  Given 使用者按下「顯示事件研究」並取得結果
  When 比對網頁顯示的 `SCOPE_NOTICE`／`RESEARCH_USE_NOTICE`／`DEMO_DATA_WARNING`（若適用）／`FOOTNOTES` 六句／除權息行／產出時間句
  Then 每一句都與 CLI `--html` 輸出逐字相同，無增刪改寫。

- AC-3（視覺編碼一致）
  Given 同一個 `symbol`／`market`／`start`／`end`／除權息狀態
  When 分別用 CLI `--html` 與網頁版產生五張圖
  Then 兩者的顏色（事件藍／基準黃）、形狀（圓形／菱形）、線型（實線／虛線）、實心空心規則完全一致。

- AC-4（策略切換不殘留）
  Given 使用者已顯示過事件研究結果
  When 使用者把策略切成非「五項觀察條件」（例如均線交叉）
  Then 「顯示事件研究」按鈕與先前顯示的事件研究內容都不再出現於畫面上。

- AC-5（事件數為 0）
  Given 事件研究的某一期間（全期／前半／後半）五條同時成立事件數為 0
  When 該期間對應的圖表被渲染
  Then 畫面逐字顯示「本段五條同時成立事件數為 0，此圖僅顯示基準，不繪製事件序列。」，且不繪製事件序列的線／點/範圍條。

- AC-6（demo 資料）
  Given 本次資料來源為 `demo_synthetic`
  When 事件研究結果被渲染
  Then 畫面上出現逐字的 `DEMO_DATA_WARNING`，且此警告出現在頁首、標題與 SCOPE_NOTICE 之後、圖表之前，與 CLI HTML 版順序一致。

- AC-7（禁用詞掃描）
  Given 事件研究區塊的完整渲染輸出（含所有圖上文字與頁首頁尾）
  When 跑禁用詞掃描（比照 `componentWordingScan.test.ts` 的模式，涵蓋 `shared/forbidden-terms.json` 與六項觀察條件既有禁用詞清單）
  Then 掃描結果為零命中。

- AC-8（參數變更即清除）
  Given 使用者已顯示事件研究結果，之後修改了表單的 `start` 日期
  When 檢視畫面上的事件研究區塊
  Then 已顯示的事件研究結果已被清除，按鈕停用並顯示「事件研究僅按目前回測報告的參數計算，請先重新執行回測。」。

- AC-9（圖不縮放、揭露字級）
  Given 事件研究結果已顯示
  When 於 1280px 與 390px 視窗量測
  Then 五張 SVG 的渲染寬度等於其 `width` 屬性（不等比縮放；窄視窗以水平捲動呈現），且所有揭露段落的計算字級 ≥ 14px（風控 REQ-W6／W7）。

- AC-10（同頁資料來源對稱）
  Given 回測報告與事件研究同在頁上
  When 資料來源為 `demo_synthetic`
  Then 回測報告的 notes 逐字含 `DEMO_DATA_WARNING`，且回測報告與事件研究各自顯示自己的資料來源與新鮮度徽章（風控 REQ-W10／W11）。

## 開放問題

### 逐項表態

| # | 議題 | 表態 |
|---|---|---|
| 1 | 放在回測報告**之後** | **可，且優於放在權益曲線之前／之中**。理由：含成本的策略績效先讀、無成本的價格分布後讀；若插在權益曲線前，讀者先看到沒扣成本、看起來更漂亮的分布，再看含成本結果，會形成「成本只是扣一點」的錯覺順序。**但 FR-1 現在的寫法不可**：`BacktestReportView.tsx` 的兩張表就在根 `<section>` 結尾（`/home/user/AICompany/apps/stock-desk/frontend/app/backtest/BacktestReportView.tsx:265-277`），「表格之後」直接 append 會把事件研究包進 h2「回測報告」、包進該節右上角的「產出時間：{as_of}」、包進「本回測報告呈現的所有數字皆屬歷史統計描述」那句——容器鄰接＝同一份結果，正是你們自己用來否決個股頁的那條理由。必須是同層後置兄弟節點（REQ-W1）。另不得與曲線圖並列同一視覺群組。 |
| 2 | 按鈕字面「顯示事件研究」 | **字面可過**（無禁用詞、無「進場」、非指令語氣）。但不得是**裸標籤**——這與 2026-09-09 REQ-3（Kelly 匯入不得只顯示裸標籤）同一條原則：控制項在建議／績效語境裡，意義由周邊決定。需搭 REQ-W2 區隔句，且節標題保留「五項觀察條件」限定（REQ-W3）。 |
