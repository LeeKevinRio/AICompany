# PRD：stock-desk 個股頁與首頁「一眼一句」簡化

- 對應頁面：`apps/stock-desk/frontend/app/position/[symbol]/page.tsx`（個股頁）、首頁儀表
  板（`RiskGauge.tsx`、`PendingAlertsPanel.tsx`）；另涉 `OperationSummaryPanel.tsx`、
  `KeyLevelsPanel.tsx`、`TechnicalIndicatorsPanel.tsx`、`AdviceCardView.tsx`、
  `LeverageChapterView.tsx`、`app/data/providers/tpex.py`。
- 派工來源：`work/stock-desk-一眼一句簡化-派工單.md`，CEO 2026-09-19 原話（見下）。
- 狀態：**spec**（CEO 已裁定方向，本 PRD 不再問「要不要簡化」，只展開為可驗收規格；僅
  第 5 節列出需 CEO 再裁決的取捨題）。

---

## 背景與目標

### 問題定義

CEO 原話（節錄）：「我點進個股，你應該要先顯示技術分析，且文字依舊太多……又臭又長，
雖然詳細但實在沒人會一個字一個字看……技術分析、建議卡、關鍵價位參考、依據都有，你要幫
我簡單扼要簡化出重點」；「首頁下方風險儀表超級長」；「待處理警示長期為空，看起來很
怪」；「你們 QA、開發、創意、美術都沒察覺嗎？」

**上一輪為何失敗**（`work/stock-desk-個股頁減負-PRD.md`、
`work/stock-desk-揭露下沉頁尾-CEO裁定與方案.md`）：

1. **量化目標訂得太寬鬆，達成也等於沒解決問題。** 「關鍵價位參考」1,871 字降到
   ≤1,777 字（95%）、「技術分析」1,765 字降到 ≤1,589 字（90%）——機械驗收全綠，使用者
   看到的仍是 1,500～1,700 字的區塊，跟「又臭又長」沒有實質差距。驗收條件本身沒對準問
   題，不是執行有落差。
2. **只做位置搬移與去重，沒做主視圖收斂。** 分層與頁尾下沉處理的是「這句話出現幾次、
   在哪裡」，但「預設視圖」（不點任何展開就看到的內容）從未被限縮，單一區塊預設仍有
   150～600 字。沒有人被要求把畫面收起來。
3. **重複段落 bug 兩輪都沒抓到。** `quantity_range.basis` 同時被 `quantityRangeText`
   與防禦型動作分支的 `restoresComplianceWarning` 各自完整渲染一次，逐字快照測試只守
   「不缺席」，沒守「不重複」。
4. **首頁儀表板從未在範圍內**，兩輪 PRD 都限定個股頁，屬於未被派工而非做壞。

**本輪方向（CEO 裁定）：** 「一眼一句」——每區塊預設視圖只留一個主視覺／主數字、至多
一句白話結論、一個「詳細」展開；字面不改，只改出現層級。本 PRD 用**絕對字數上限**取代
上一輪的相對百分比，作為機械判準。

## 使用者與情境

延續上一輪 PRD 設定：使用者要「先給我一句結論／一個數字」，進階使用者細看依據時才點
「詳細」。新增情境：使用者開首頁想快速掃過風險狀態與待處理事項，而非讀完五條風險上限
完整敘述與資料來源清單。

## 功能需求（逐條編號）

### FR-1　個股頁區塊順序

新順序：標題列 → **技術分析** → **操作摘要** → **關鍵價位參考** → **六項觀察條件** →
**建議卡（預設收合）** → **槓桿專章（若有）** → **頁尾揭露區**（既有位置不動）。

**Given** 使用者開啟 `bars.status="ok"` 的個股頁 **When** 頁面完整載入 **Then** 六個主
要區塊（不含頁尾揭露區）垂直順序與上述一致，技術分析在操作摘要之前、操作摘要在關鍵價
位參考之前。

---

### FR-2　每區塊預設視圖收斂

每區塊預設只顯示：一個主視覺／主數字＋至多一句白話結論／狀態摘要＋一個「詳細」按鈕。

| 區塊 | 預設留 | 收進「詳細」 |
|---|---|---|
| 技術分析 | K 線＋均線圖；指標速覽 chips 一列 | 七張指標卡片、風險量測數值 |
| 操作摘要 | 結論大字＋信心等級 chip＋股數區間一行＋一句主要依據＋一句免責（`disclaimer` 縮為同列小字） | 反面論點、失效條件、`confidenceMeaning`、既有警示句 |
| 關鍵價位參考 | 價位階梯＋停損／停利兩個大字 | 三張小卡內文與各限定句 |
| 六項觀察條件 | 六個圓點＋「6 條中成立 N 條」 | 六列逐條明細、E-1～E-4 |
| 建議卡 | 預設收合，標題列顯示「命中 N 條／方向占比條」 | 展開後規則明細（既有內容不動） |
| 槓桿專章 | 既有頂部一句導讀＋核心數字 | 既有 `<details>` 假設清單（機制不動） |

**Given** 使用者未點任何「詳細」／未展開建議卡 **When** 量測預設視圖可見文字（比照上
一輪 Playwright 稽核方法：初始渲染、未展開狀態下的可見 DOM 文字節點）**Then** 各區塊字
數符合第 3 節「量化 AC」上限。

**Given** 使用者點擊「詳細」或展開建議卡 **When** 展開後渲染完成 **Then** 上線前該區
塊存在的每一句風控鎖定字面仍完整可見（子集合守門，沿用上一輪 PRD AC-4）。

---

### FR-3　操作摘要重複段落修正

修正 `quantity_range.basis` 被 `quantityRangeText` 與 `restoresComplianceWarning`
（`restores_compliance=false` 分支）各自完整渲染一次的缺陷。只調整渲染次數與位置，
`basis` 字串本身不可增刪一字。

**Given** 該筆建議屬於防禦型動作且 `restores_compliance=false` **When** 頁面完整渲染
操作摘要（含預設視圖與展開後內容合計一次渲染範圍）**Then** `quantity_range.basis` 完
整字串在該次渲染中恰出現 1 次。

---

### FR-4　首頁風險儀表五列一行式

五條風險上限改「一行一條」：名稱｜狀態 chip｜細進度條｜觀察值/上限，同一行內。
`detail` 完整敘述、未納入標的清單、假設與限制清單、各標的資料來源清單，全部收進一個共
用「詳細」展開。

**Given** 使用者未展開風險儀表「詳細」 **When** 量測預設視圖 **Then** 可見行數 ≤10
行、可見字數 ≤200 字。

**Given** 使用者展開「詳細」 **When** 渲染完成 **Then** 上線前存在的五條 `detail`、假
設清單、資料來源清單全部仍完整可見（子集合守門，同 FR-2）。

---

### FR-5　首頁待處理警示三態

改為狀態列（不再與風險儀表並排各占版面一半），前端呼叫 `GET /api/alerts`（規則清單）
與既有事件查詢結果判斷三態：

1. **無規則**（規則清單為空）：「尚未設定警示規則」＋「去設定」連結。
2. **有規則、無未確認事件**：「N 條規則啟用中，目前沒有待處理警示」＋最近評估時間。
3. **有未確認事件**：展開為清單（沿用現行 `PendingAlertsPanel` 樣式）。

**Given** `GET /api/alerts` 回應規則清單長度為 0 **When** 首頁載入 **Then** 顯示狀態一
文案，不顯示舊有「目前沒有待處理的警示」句。

**Given** 規則清單長度 >0 且未確認事件為空 **When** 首頁載入 **Then** 顯示狀態二，版
面不再與風險儀表各占一半（風險儀表全寬在上，警示狀態列在下）。

**Given** 未確認事件非空 **When** 首頁載入 **Then** 顯示狀態三，行為與現況一致。

---

### FR-6　字面不改，只改層級

風控已核可的既有字面（`KeyLevelsPanel.tsx`、`TradingViewChartPanel.tsx`、
`adviceWording.ts` exported 常數、既有導讀／指引句）一字不動。本輪所有 FR 只調整字面預
設是否可見、出現在第幾層。任何全新文案（如建議卡收合列樣板、警示三態新句）需
creative-lead 成稿、風控逐字核可後才可落地，不得由 dev 自行編寫上線。

**Given** 批次自稱「純層級調整」 **When** qa-reviewer 檢查 diff **Then** 對三個鎖定檔
案的既有字串常數（含標點）不得有字元變更；有變更則一律改標「需風控重審批次」。

---

### FR-7　上櫃資料（TPEx）驗收條件

`tpex.py` 改打 TPEx 新站端點，由 data-engineer 另案實作與提出 CEO 本機驗證腳本；本
PRD 只定上線後應觀察到的行為。

**Given** data-engineer 完成新端點對接，CEO 本機驗證腳本執行成功 **When** 使用者開啟
上櫃股票（如頎邦 6147）個股頁且近期有交易資料 **Then** `bars.status` 不因 TPEx 步驟失
敗變 `UNAVAILABLE`，K 線與技術分析正常顯示。

**Given** TPEx 新端點暫時異常 **When** 資料梯子降級至 FinMind **Then** 現行冷卻機制
（ADR-0009 D-8，TW 冷卻 1 小時不重試）維持不動，縮短冷卻時間需另案評估。

## 量化 AC（可機械量測）

**AC-1** Given 操作摘要完成 FR-2 收斂 When 量測預設視圖可見文字（不含標題）Then 字數
≤120 字（含標點）。

**AC-2** Given 技術分析、關鍵價位參考、六項觀察條件、建議卡（收合態）完成 FR-2 收斂
When 量測各區塊預設視圖可見文字（不含標題）Then 各區塊字數 ≤80 字（含標點）。

**AC-3** Given 首頁風險儀表完成 FR-4 收斂 When 量測預設視圖 Then 可見行數 ≤10 行、可
見字數 ≤200 字（含標點）。

**AC-4（紅線，沿用上一輪 AC-4）** Given 任一批次已上線 When 比對上線前後、「詳細」展
開後的頁面文字快照 Then 上線前存在的每一句風控鎖定字面在展開後仍至少完整出現 1 次，
呈現樣式不劣化；缺席一律 BLOCKING_ISSUES。

**AC-5** Given FR-3 已上線 When 對防禦型動作、`restores_compliance=false` 的資料渲染
操作摘要 Then `quantity_range.basis` 完整字串在單次渲染中恰出現 1 次。

**AC-6** Given 批次宣稱「純層級調整」When qa-reviewer 檢查 diff Then 三個鎖定檔案字串
常數無字元變更，僅涉及 JSX 結構／className／展開收合邏輯，符合者不需重新送風控。

**AC-7（實測環境限定）** Given data-engineer 完成對接、CEO 本機驗證腳本成功 When 於
CEO 本機（非本沙盒）開啟頎邦（6147）個股頁 Then `bars.status="ok"`，不落到
`UNAVAILABLE`。

## 風險與依賴

- FR-2 收斂範圍需 tech-architect 評估拆分方式（`<details>` 或既有摺疊元件）與既有逐字
  守門測試的共存方式，本 PRD 只定行為規格。
- FR-3 屬缺陷修正，需 dev-lead／tech-architect 確認修正不連帶影響其他分支的既有行為。
- FR-7 驗證環境受限：本沙盒對 `www.tpex.org.tw` 出站被擋（CONNECT 403），只能由 CEO
  本機驗證，時程不可控，AC-7 標記「實測環境限定」。
- 風控最低常駐線尚未回覆（派工單 §2.3）：若回覆內容與本 PRD 第 3 節「預設留」欄位有
  出入，對應區塊量化 AC 上限需配合上修，屬已知規格微調風險，不影響先行進 build 準備。
- 上一輪開放問題「操作摘要／建議卡去重方向 A/B」不重開：CEO 本次直接裁定建議卡預設收
  合，等於選擇了「操作摘要維持摘要層級、建議卡收斂為明細層級」的方向，視為已回答。

## 觀察報告（product-manager，可貼入派工單 §3.7）

我們為什麼沒早發現：上一輪 PRD 把「減負」定義成相對百分比（95%／90%）與逐句去重次
數，機械驗收全綠，卻沒有訂「預設視圖字數上限」這種對齊使用者實際感受的指標——驗收條
件本身沒有失敗，是驗收條件從一開始就沒對準問題。

我現在看到的問題：兩輪工作只做了位置搬移與去重，沒有人被要求把預設畫面「收起來」，基
準值訂得太寬鬆，等於合規但沒解決。

我這次要做什麼：本輪 PRD 改用絕對字數上限取代相對百分比，逐區明訂預設留什麼、收什
麼，並把「上一輪目標訂太鬆」列為本部門檢討項目寫入 PRD 供全公司對照。
