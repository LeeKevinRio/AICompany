### [RC-548] RC-524 修訂（required，即日起，日後同類文件沿用）

**第 5 條改讀為：** 在 CEO 平常的程式目錄（repo 內）裡執行會安裝或同步依賴的指令，包括：
- `uv sync`、`pip install`；
- 任何形式的 `uv run`，包括 `uv run --with`，也不論有沒有帶 `--frozen`、`--locked`、`--no-sync`。

除非 devops-sre 書面確認某一種帶參數的寫法不會改動環境；在那之前一律算進來。
- 理由〔事實〕：F-3 README 第 156 行、X-3 README 第 154 行自己寫明「不用 `uv run`，避免觸發 venv 同步」。
- 〔推論，依 uv 一般行為〕`--frozen` 只是不更新 lock，不等於不同步。我不採用帶參數就排除的寫法。
- 第三節第 2 題的答案：**涵蓋。** N-118、V-1、實測、規則集-1.1.0、phase8 都適用。

**新增第 7 條：** 叫人在 repo 裡執行 git 寫入或同步動作，例如：
- `git pull`、`git fetch` 之後合併、`git add`、`git commit`、`git push`；
- `git checkout`／`git switch`、`git stash`、`git reset`、`git worktree add`／`remove`；
- 或叫人把檔案 commit、push。

理由：
- `dev-up.bat` 自己會 `git pull`，手動另外做會牴觸 #156；
- 本機多出 commit，〔推論〕可能讓下一次 `dev-up.bat` 的 pull 失敗；
- CEO 直接 push 到 product，會繞過 qa 審查（章程第 3 節）。

唯讀的 `git log`、`git rev-parse` 不算，由檔頭涵蓋。

**不溯及既往：** P2 五份不因第 5 條、第 7 條重開。spike 第三節的 `git worktree` 也一樣；〔推論〕它不會改動 CEO 目前的分支，由檔頭涵蓋。日後這五份因為別的原因要改時，我再一併判定。
