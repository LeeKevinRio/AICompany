# 唯讀角色權限邊界失效 — devops-sre 查證紀錄(事件一手證據)

- **日期**:2026-08-24
- **事由**:security-engineer 審查 `chore/agent-adr0007-accepted` 時判 CRITICAL,懷疑 `Bash(codex:*)` 可能允許以 `;` 接續任意指令;devops-sre 受命查證
- **結論**:**security 判定成立,且實情更嚴重**——「唯讀職能僅可持有非變更性且可窮舉的 scoped Bash」這句話**在執行層從未成立過**
- **查證者**:devops-sre(未修改任何檔案,`git status` 全程乾淨)

## 兩層失效(疊加,非單一原因)

### 第一層:`tools:` frontmatter 的 `Bash(pattern)` 語法從一開始就無效

官方 `sub-agents.md` 定義 `tools:` 是**工具粒度**白名單(Bash / Read / Write / …),文件中所有範例的 Bash 項目一律寫裸 `Bash`,**找不到任何一個把 `Bash(pattern)` 寫在 `tools:` 裡的官方範例**。更直接的證據是文件自己給的 Database query validator 範例:

> "This example shows how to use `PreToolUse` hooks for **conditional validation when you need finer control than the `tools` field provides**."

等於官方明講 `tools:` **做不到**命令級限制。另 `permissions.md`:

> "Permission rules are enforced by Claude Code, **not by the model**. Instructions in your prompt or `CLAUDE.md` shape what Claude tries to do, but they don't change what Claude Code allows."

**存在期間**:自 `qa-reviewer.md` 建立(2026-06-28,commit `ef7a31b`)起,**與裸 Bash 加不加無關**。

### 第二層:`settings.json` 的裸 `"Bash"` 使 scoped allow 完全冗餘

官方 `permissions.md`:

> "Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, **and rule specificity doesn't change the order**."

即「任一規則匹配即放行」,**不取最具體規則**。裸 `"Bash"` 已涵蓋 `Bash(codex:*)`/`Bash(git diff:*)` 的全部範圍,後兩者是無效字串。

**存在期間**:2026-08-09 commit `bdde359`(「權限設定改全自動放行,取消 commit/push/codex 逐次詢問」)引入。此前 qa-reviewer 對非 scoped 指令至少會落到「無匹配規則」而觸發詢問;此後該防線亦消失。

## 關於 security 原本的疑慮:permissions 層其實很嚴謹

`permissions.md` 對 Bash 比對規則寫得具體:**複合指令會被拆解逐段比對**——

> "Claude Code is aware of shell operators… The recognized command separators are `&&`, `||`, `;`, `|`, `|&`, `&`, and newlines. **A rule must match each subcommand independently.**"

另會剝除 `timeout`/`time`/`nice`/`nohup`/`stdbuf`/`command`/`builtin`/zsh `noglob`/裸 `xargs` 等包裝;並明確警告 `direnv exec`/`devbox run`/`mise exec`/`npx`/`docker exec` **不在**剝殼清單內。

**所以「可窮舉」不是語意有漏洞,是判準被寫在錯誤的層級**(frontmatter `tools:`,該層從不解析 parenthetical scope)。

四個唯讀角色中**只有 qa-reviewer 實際暴露**,因為只有它在 `tools:` 寫了 `Bash(pattern)`。另三者 frontmatter 完全未列 Bash,逐 session 查證:

| 角色 | session 數 | Bash 呼叫 |

| `risk-compliance-officer`(**有否決權**) | 14 | **0** |

**但性質是架構性的**:任何未來新增的唯讀角色只要照抄 `Bash(pattern)` 這種寫法,就會複製同一個假象。

## 處置(CEO 2026-08-24 三項裁決)

1. **ADR-0007 維持 `proposed` 不合併**;章程 §4 改為**如實描述**(規範性要求保留 + 明文揭露執行層未強制)。
2. **PreToolUse hook 強制機制現在建置**(`chore/agent-readonly-hook`,devops-sre 主辦)——`settings.json` 裸 Bash/Write/Edit **不動**,實作角色維持零詢問;hook 依 `agent_type` 分流,唯讀角色 Write/Edit 一律 deny、Bash deny-by-default 且逐子命令比對白名單。**由 security-engineer 主導審查、tech-architect 協審**(不得由 qa-reviewer 審——它審的正是限制自己的機制)。
3. **三次事件寫進 ADR-0007 Context 正式留痕**。

## 誠實揭露的殘餘風險(devops-sre 自陳)

hook 腳本是自製 parser,複雜度遠低於 Claude Code 內建引擎(不處理 glob 萬用字元、環境變數剝殼等邊角),需仔細測試分隔符拆解與子命令比對,否則可能被精心構造的字串繞過。**這支腳本本身必須被獨立審查才能信任。**
