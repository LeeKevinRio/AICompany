# 第一件：「請執行一次 `dev-up.bat`」的請求

## 本次結論

**APPROVE_WITH_CONDITIONS。要預先定稿，共兩則。**
- R1：接線合併後的第一次。這是預定的請求，不是異常。
- R2：事後由 devops-sre 書面判定需要重新執行時才送。

1. **B 第 111 行不夠，要改（替換 B1）。**
   - 原句說「下一次那樣啟動，就會開始記錄」，這有兩個問題：
     - CEO 一直開著 stock-desk 時，不會有「下一次啟動」；
     - 「就會開始記錄」是保證語氣。`.env` refusal、Yahoo 抓不到資料、`git pull` 失敗時，都不會開始記錄。
   - B1 要在 B 交給 CEO 之前套用，併入 RC-330 的單項確認。只列為接線 PR 合併的前置不夠，理由和 RC-381 的 E3 相同：B 比接線合併更早交出。
2. **要寫「回答 Y」，而且範圍要比原先想的大。**
   - CEO 開著 stock-desk 時，畫面會依序出現最多三次 Y/N 提示：port 8000、port 3000 各一次 `Stop the old process? [Y/N]`，再一次 `Stop the old scheduler? [Y/N]`。
   - 第一次回答 N，就會在檢查 scheduler 之前結束，舊 scheduler 留著，這就是情形 D。
   - 前面回答 Y、後面回答 N，stock-desk 會被關掉，卻不會重新開啟。
   - 所以要寫「每一次都按 `Y`」。其他 Y/N 問題（例如切換分支 `Switch to ...? [Y/N]`）一律按 `N`，按 N 會在更新程式之前停下來，什麼都不改。
3. **RC-342 固定句要逐字附上，另外補一句**，涵蓋 `[STOP]`、`[FAILED]`、`[TIMEOUT]`、`[FAIL]` 與「Reboot and try again.」。`dev-up.bat` 第 252 或 256 行那一句會叫 CEO 重新開機，和「不要重新啟動」直接衝突。
4. 和 H、L、U 系列的關係要在訊息中講明：R 系列是 coordinator 明確請求的那一次例外，其他時候照舊不要自己重新啟動。
5. 不需要 CEO 事先決定。
