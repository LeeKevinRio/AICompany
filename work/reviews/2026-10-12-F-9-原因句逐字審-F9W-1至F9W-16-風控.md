# F-9 原因句逐字審（F9W-1～F9W-16）

- 審查者：risk-compliance-officer（唯讀；coordinator 轉錄，2026-10-12）
- 待審檔：`work/copy/F-9-日線幣別閘門原因句-提案-2026-10-12.md`（creative-lead）
- 背景：`work/dispatch/2026-10-08-任務單-F-9-日線上游幣別未核對.md`、`docs/adr/0024-stock-desk-日線價格幣別閘門與代號准入.md`（proposed）

## 判定

**APPROVE WITH CONDITIONS（無否決）。**
- 逐字核可：W-a（採 alt-1）、W-b（第二句採 alt-2）、W-c 美股／台股、W-c′ 美股／台股、W-d（不另立基底句、不加「來源回報：」前綴）、冷卻期 C 版。
- 退回 creative-lead 修改：第八節整書成因 64 字候選句。
- 不採：冷卻期 B 版。
- 裁示題一：另立成因組（新 missing token＋庫存頁標籤），不沿用「缺價格或匯率」。
- 裁示題二：採 C 版；A 版只在 W-c／W-c′ 不可能觸發的期間（F-9c 合併前）暫時接受。
- 最重要新發現：W-c 不得與快取價格同時出現（F9W-4）。

## 逐字核可字面（含標點、全形括號；`{provider}` 為唯一佔位符，C 版另有 `{minutes}`、`{cooldown_hours}`）

**W-a（美股，alt-1）**
> 本系統只查詢這種形式的美股代號：1 至 5 個英文字母，可接單一字母的類別字尾（如 BRK.B）；此代號不在其內，未向任何來源查詢。帶其他字尾的代號可能是外國交易所的掛牌（價格單位未必是美元），也可能是特別股等美國商品，系統無法逐一分辨。

**W-b（台股，第二句 alt-2）**
> 此台股代號是「數字後接英文字母 K」的形式，本系統不處理這種形式，未向任何來源查詢。這類代號可能是以外幣計價的掛牌商品，價格單位未必是新台幣。

**W-c（美股）**
> {provider} 這次回傳的日線，標示的價格單位不是美元（美股日線以美元為準），整段都不採用。

**W-c（台股）**
> {provider} 這次回傳的日線，標示的價格單位不是新台幣（台股日線以新台幣為準），整段都不採用。

**W-c′（美股）**
> {provider} 這次回傳的日線沒有標示價格單位，無法確認是否為美元，整段都不採用。

**W-c′（台股）**
> {provider} 這次回傳的日線沒有標示價格單位，無法確認是否為新台幣，整段都不採用。

**冷卻期 C 版（只用於「最近一次嘗試有任一層是 W-c」）**
> 本機尚無此標的可採用的日線資料。最近一次向來源取得的日線，標示的價格單位與市場所用的單位不同，已於約 {minutes} 分鐘前整段不採用；冷卻期為 {cooldown_hours} 小時，冷卻期內系統不會自動重試；冷卻期結束後的下一次查詢才會重新向來源取得。

**W-d**：上列各句（含 C 版與待送審的 C′ 版）即完整 `reason`；不接 `NO_BARS_REASON`、不走 `with_provider_reason`。提案第四節保守退路「{market} {symbol} 的日線資料未能採用。」**未核可**，若要用須另送審。

## 條件

- **F9W-1【creative-lead → dev-lead，required】** W-a 採 alt-1：推薦版只列「外國交易所掛牌」一種解釋、省略已知誤擋（特別股、權證、單位），屬隱藏不確定性。`BRK.B` 為格式範例、非推薦，保留。
- **F9W-2【required】** W-b 第二句採 alt-2：「交易單位」在台灣常指一張＝1000 股的交易量單位，易誤讀；「掛牌商品」包在「可能是」內，不構成斷言。
- **F9W-3【dev-lead，required】W-c／W-c′ 分流**：宣告值非空且不等於該市場幣別 → W-c；None、空字串或只有空白 → W-c′；同批任一根非空且不符即 W-c。D-6 原值照存、不轉大寫——上游若回大小寫變體（例 `usd`），W-c「不是美元」即不屬實；F-9c 重錄真實 fixture 須確認 USD／TWD 實際寫法，發現變體回風控。`{provider}` 只填 adapter 自己的 `source_id`。
- **F9W-4【tech-architect → dev-lead，required，F-9c 合併前須落地】W-c 不得與價格並存**：
  - 理由：美股主來源 AV、備援 yfinance（`deps.py` L102-107）；單一字母外國字尾（`.L`、`.T`）通過准入；其舊快取列由寫死幣別的 adapter 標為 `USD`，D-2 快取閘門只比對宣告幣別、看不出錯；F-9c 後 yfinance 誠實回報（例 `GBp`）觸發 W-c，`_fall_back_to_cache`（`service.py` L521-561）即把單位錯誤的舊列送上畫面，並掛 F-7「價格單位：美元」標籤，估值器與 alerts snapshot（`snapshot.py` L121-166）亦會用該價格計算。
  - 要求：任一 live 層判定 W-c，該次回覆（含估值器 live 路徑）一律不得改用快取回價格；冷卻期內同一序列也不得以 `RECENT_ATTEMPT_FAILED_REASON` 回快取（`service.py` L366-385、L414-426）。需 attempt log 多記一個標記（與 C 版同機制）。F-9b 合併時 W-c 不可觸發，測試須釘住。W-c′ 不套用此條。CEO 若要放寬須明確同意並附 tech-architect 實證。
- **F9W-5【coordinator】** W-c′ 收進 F-9b 範圍——同意。
- **F9W-6【dev-lead／qa-reviewer，required】W-d 落實**：適用 W-a、W-b、W-c、W-c′、C、C′ 整組；不接 `NO_BARS_REASON`、不加 `PROVIDER_REASON_PREFIX`；任一層是 W-c 或 W-c′ 即不接 `NO_BARS_REASON`；W-c 與其他層原因並列時走 `_combine_reasons`（AV 既有原因句各可單獨成立，已核對）。測試以完全相等釘住 `LoadedBars.reason`：W-a 單獨、W-b 單獨、W-c 單獨、W-c＋AV 原因句、W-c′、冷卻期 C 版。
- **F9W-7【dev-lead，required】** W-a／W-b 只能由服務層在 layer 0 前的准入發出；AV adapter 扣額度前的縱深檢查不得產出 W-a／W-b（「未向任何來源查詢」可能不屬實），該路徑若需使用者面字面須用既有核可句或另送審。
- **F9W-8【dev-lead；F-9d 回風控，required】** 准入 regex 須與「數字後接英文字母 K」逐字對應並以測試釘住；F-9d 實證若「數字＋K」非外幣計價或有其他樣式，規則與 W-b 回風控重審。
- **F9W-9【tech-architect，required】** W-c／W-c′ 不適用指數路徑（`services/index.py` L265、L385 會接指數版 `NO_BARS_REASON` 並加前綴）；指數幣別檢查真正觸發前，指數用字面須另送審。
- **F9W-10【qa-reviewer／qa-e2e，required】消費端核對**：PR 須列出 W-a 在每個消費者最終顯示字串（bars、signals、advice、portfolio limits sources、alerts snapshot 與 engine、backtest、event_study、leverage、diagnose）；任何把 `loaded.reason` 包進框架句者回風控。qa-e2e 以最長的 W-a alt-1 在 375／1280 驗三處：K 線區、操作摘要、首頁風險上限「詳細」——不溢位、不截斷、不出現價格單位標籤。
- **F9W-11【裁示題一，required，F-9b 合併前】另立成因組**：
  - 理由：(1) `valuationWording.ts` L3-9 明定「查無…」＝系統問過、沒有資料；沿用會讓被准入擋下（根本沒查）的持倉顯示「查無價格資料」，語意相反；(2) W-a／W-b 為確定性、持續性拒絕，「缺價格或匯率」讀似暫時中斷；(3) 先例 X-3c KX-A10。
  - 範圍：新 token 涵蓋准入拒絕、W-c、W-c′；不得計入 `asked`；與 X-3c 計數優先序須明定；庫存頁新標籤字面由 creative-lead 起草送風控；此牴觸 ADR-0024 D-7，須 tech-architect 修訂 D-7。
  - 64 字候選句要求修改後重審：(a) 主句不得預設曾取得價格；(b) 子原因須涵蓋 W-c′；(c) 句內不得有「；」（與 `UNVALUED_NOTE_TEMPLATE` 分隔衝突）；(d) 不得用「幣別」「紀錄」、不得加更正指引；(e) suggested：補「非價格或匯率中斷」。
  - 唯一例外：tech-architect 評估新 token 無法隨 F-9b 落地，**且** F-9a 於 CEO 本機盤點「准入不通過的持倉」為 0，才可暫時沿用至 F-9c 合併前——屬放寬，須 CEO 書面同意。
- **F9W-12【裁示題二，required，F-9c 合併前】採 C 版**：W-c′ 觸發的冷卻期須另起 C′ 版送審（C 版「單位不同」對 W-c′ 不屬實）。標記語意：最近一次嘗試「至少一層是 W-c（或 W-c′）且無任何一層取得可用資料」時設定；`{minutes}` 取該次時間；有快取時同樣回 C 版、不回快取（配合 F9W-4）。suggested：C 版比照 W-c 按市場分兩句。A 版僅在 F-9c 合併前可接受（觸發後冷卻句會變成「（主來源、備援與快取皆無）。來源回報：…未成功…」，與 W-d 論證矛盾，且會以 `RECENT_ATTEMPT_FAILED_REASON` 送出可疑舊列）。B 版不採（冷卻期內無回傳，「這次回傳」不屬實，且改動已核可句）。
- **F9W-13【tech-architect／tech-writer，required，記錄】**
  - X-3c 方向子句：`_symbol_direction`／`_book_direction`（`book.py` L1009-1076）只看估值狀態、產業、是否本標的，不看成因；被 F-9 撤下的列進入同一未估值集合後由既有規則挑出 D-a／D-P／D-d1／D-d2，「偏高」只在 D-a 時成立、非一律成立。任務單表述須更正，並加測試：被撤下列進入 `unvalued` composition。
  - X3-F7：同意補前提，用詞「已估值列的日線價格單位與市場一致」（不用「價格幣別」，F7-R5）；此前提在 F9W-14 殘留情形下不保證成立，須 CEO 知悉。
- **F9W-14【tech-architect，required】F7-R12 (ii) 殘留只部分關閉**：
  - F-9b 後關閉：2 字母以上字尾美股代號；台股「數字＋K」（未實證）。
  - F-9c 後（且 F9W-4 落地）關閉：yfinance 新抓、宣告不符的資料。
  - 仍未關閉：AV 供應的單一字母外國字尾代號（AV 寫死 USD）；寫死幣別 adapter 寫入的舊快取列；准入未涵蓋的其他樣式。
  - ADR-0024 D-6「經 admission 保證之值」說過頭，須更正。F-7 提案「殘留與前提」段於 F-9b 合併後由 creative-lead 更新紀錄，交 CEO 知悉（紀錄更正，不涉畫面字面）。
- **F9W-15【tech-architect，suggested】** F-9a 盤點增列「通過准入但帶單一字母、非常見類別字尾的序列與持倉」清單，交 CEO 逐一人工確認（D-2 看不出、F-9e 清不到）。
- **F9W-16【dev-lead／qa-reviewer，required】** 各常數依 C-9 註明風控核可出處並引用本裁定；PR 說明引用本裁定並延伸引用 F7-R10；改任何字、分流條件或與快取並存規則，皆回風控重審。

## 第 6 題（核可是否只是 F-9b 合併前提）

部分同意：W-a～W-d 逐字核可是 F-9b（及 F-9c）合併前提，不是 ADR-0024 核可前提；但本裁定改動 ADR 內容，ADR-0024 轉 accepted 前須納入 F9W-4（D-2 範圍）、F9W-11（牴觸 D-7）、F9W-14（D-6 用語過頭）、F9W-13（X3-F7 前提）。即 T-5～T-9 裁示結果是 ADR 核可前提；T-1～T-4 字面不是。
