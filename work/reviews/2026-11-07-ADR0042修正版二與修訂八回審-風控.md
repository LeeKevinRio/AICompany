**(3) A-4 C9 (b) 的執行方式與內容雜湊舉證：回 TA 改寫。**
- 執行與判斷分離的方向，我接受。以下三處要補（required）：
  - (a) **證明該 commit 確實含有風控的審查紀錄。** 現稿只證明「PR 說明寫得出某個 40 碼，而且它在 remote 上可達」，但沒有證明這個 commit 的 tree 裡有那份審查紀錄。隨便列一個較舊的 commit 也能過關。
    - 要求：(ii) 的執行者用唯讀的 git 查詢，原樣貼出「該 commit 的 tree 中含有該審查紀錄路徑」的輸出，以及該路徑在這個 commit 的 blob 雜湊。實際指令由 devops-sre 指定。
    - 同一份紀錄再貼出該路徑在 (ii) 讀取當下、remote 版本的 blob 雜湊。兩者不同就判 BLOCKING：審查紀錄在 PR 建立之後被改寫，等於事後補。
  - (b) **「在 remote 上可達」要指名 ref。** 要寫完整 ref 名，而且只能是禁止 force push 的分支（`origin/product/stock-desk` 或 `origin/main`）。以 `--is-ancestor` 舉證，附 `exit=` 行。
  - (c) 「獨立性同修訂六 1.4」，改為引用 (7) 改寫之後的版本。
- 「證明不了 push 的時點」這項殘留，我接受。
  - 理由：R10 的本意是審查發生在 PR 建立之前。commit 由內容決定，再加上編輯歷史證明那串 40 碼在建立當下就已列出，就足以證明審查紀錄的內容在 PR 建立之前已經存在。
  - 我 R10 (1)「已 push」那一半，因此降為「審查時已在 remote 上可達」，殘留照 TA 的寫法登錄。
- 改寫完成之前，這項標記保留。這段期間 qa 拿不到編輯歷史，依 (4) 判 BLOCKING，所以是 fail closed。

**(4) A-9 部署前的事實核對：確認。**

**(6) 修訂八第 1 節「合入綁定 `<head>`」：回 TA 改寫。**
- 方向接受，而且有必要：它補上「qa 給 PASS 之後到合入之間」的窗口。以下三處要補（required）：
  - (a) **合入之後的核對，兩條路徑都要做。** 由 (ii) 的執行者用唯讀的 git 查詢記錄：merge commit 的完整 40 碼，以及它的第二個 parent。第二個 parent 必須等於 `<head>`。
    - C7 要求以 merge commit 合入，所以這一點一定查得到。
    - 不相等就是事件：已經合入了未經審查的 commit。要立即回報風控與 CEO。不得 force push product，處理方式由 TA 訂（例如 revert，或補審差異）。處理完之前，不部署。
  - (b) **退路「無法綁定時，合入前再讀一次 (γ)」的使用條件。** 只有在 devops-sre 書面查證「無法綁定」之後才能走退路。而且要揭露殘留：讀取與合入之間仍然有窗口，要靠 (a) 事後補抓。
  - (c) 合入者不得是 (ii) 的執行者以外、又無法留下紀錄的角色。合入者是誰、用的指令原文與輸出，都記入同一份審查紀錄。
- 這一項在規格檔，不在 ADR-0042，不擋 ADR 落檔。

**(7) 修訂八第 2 節，1.4 改為兩份紀錄互核：回 TA 改寫。**
- 用兩份 git 紀錄取代「qa 讀頁面」，方向接受。commit 清單由 `<head>` 的內容決定，在四個值相等的前提下，兩份紀錄互核足以把清單綁定到審查對象。
- 但「(ii) 的執行者出現在作者或 `Co-Authored-By` 裡就判 BLOCKING」這一句**無法判定**：
  - 本 checkout 的 reflog 身分一律是 `Claude <noreply@anthropic.com>`（.git/logs/HEAD）；
  - 依本 session 的 attribution 設定，所有 agent 的 `Co-Authored-By` 也都是同一個模型標記。
  - 結果是：照字面讀，任何 agent 當執行者都「出現在作者裡」，每次都判 BLOCKING；換一種讀法，git metadata 又完全分不出角色，這句話就沒有作用。
  - 修訂六 1.3 (ii) 的聲明「不是任何 commit 的作者，也不是 `Co-Authored-By`」，有同樣的問題。
- required：
  - 獨立性改為以「角色」判定。
    - (ii) 的紀錄寫明執行者的角色。
    - coordinator 的派工紀錄（`work/`）逐一列出 `<base>..<head>` 每個 commit 是哪個角色下的 git commit，以及 (i) 由哪個角色執行。
    - qa 比對角色名稱：(ii) 的執行者不得出現在其中。
  - 兩份清單互核保留，作用是綁定內容。
  - 修訂六 1.3 的聲明同步改寫。
  - 揭露殘留：git metadata 證明不了角色，獨立性靠派工紀錄與自我聲明。
- 這一點同樣適用於 N196-C8、N197a-C8。
