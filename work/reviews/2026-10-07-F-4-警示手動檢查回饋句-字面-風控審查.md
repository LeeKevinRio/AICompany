## 逐條
- 主句：兩個並列計數取代舊口徑，「略過 0 條」為肯定事實，R-B2 假保證解除。核可。
- 冷卻句 required 修正理由：手動檢查只寫事件不推播，「未發出」會讓人以為已觸發者都「發出（推播）」或 suppressed 有被記錄；改「觸發」與第一句同詞，讀者可直接看懂 P 未算進 F。
- B 不採用（略過 0 時與「功能沒出現」分不出、新增「未評估」詞、分支多）；C 不採用（不需明寫母數，(f) 已處理「啟用中」範圍；偏長）。
- 裁量 1 **required 兩項**：(i) CEO 知悉清單寫「舊『已評估』含被略過的規則」與「新口徑排除略過，有 W-2 舊規則／載入失敗／缺匯率者看到的數字會比以前小，前後不可直接比較」；(ii) release note 加一句揭露「此版本之前，手動檢查顯示的『已評估』含被略過的規則」，creative-lead 起草送審，**與 F-4 同版同時上線不得事後補發**，不得安撫語。
- 裁量 2：「符合條件」用於 risk_limit 不過寬（crossed 只在有 violated 時成立，規則表描述亦為「{上限} 被觸發」）；補失效條件：新增規則類型或 suppressed 成立條件改變時重審。
- 裁量 3：全略過時保留「本次觸發 0 筆事件」可（同句已有「已評估 0 條」）。
- 裁量 4：(f) 核可。
- 顏色：略過數與冷卻數必須以文字傳達、不得只靠顏色（A 案文字獨立成立，已滿足）；色值由 art-lead 定（已定 neutral-300）。
- 「最新」另案（F-4-R1，low）：`engine.py:404/408`「沒有可用的最新收盤價。」只在 API JSON，前端不渲染不推播，無暴露；任何 `outcomes.reason` 進 UI／推播前逐類送風控一併處理。事件訊息 `engine.py:169`「{代號} 最新收盤價 …」與欄位標籤為既有核可字面，不列管。
- 範圍外 suggested：`evaluateMutation.isError` 未渲染（靜默失效，F-4-S1 / F-5）；「查看略過原因」交 PM（F-4-S2）。

## 核可字面總表（逐字；變數全部從 `outcomes` 計數，不用 API 的 evaluated／fired）
- `{E}`＝status 為 fired／quiet／suppressed 的筆數；`{S}`＝`outcomes.length − {E}`（skipped＋任何未知 status，保守方向，E+S 恆等於 outcomes.length）；`{F}`＝fired 筆數；`{P}`＝suppressed 筆數。阿拉伯數字、不加千分位、半形空格比照模板。

| 編號 | 字面（逐字） | 顯示條件 |
|---|---|---|
| T1 | 已評估 {E} 條規則、略過 {S} 條，本次觸發 {F} 筆事件。 | `outcomes.length > 0` 恆顯示 |
| T2 | 已評估的規則中，{P} 條符合條件但在冷卻中，本次未觸發事件。 | `outcomes.length > 0` 且 `{P} > 0`，直接接在 T1 之後（不加空格），同一 `role="status"` 內 |
| T3 | 目前沒有啟用中的規則，本次未評估任何規則。 | `outcomes.length === 0` 時取代 T1／T2 |

展開例（測試期望值，逐字）：
- (a) 已評估 5 條規則、略過 0 條，本次觸發 1 筆事件。
- (b) 已評估 3 條規則、略過 2 條，本次觸發 0 筆事件。
- (c) 已評估 0 條規則、略過 5 條，本次觸發 0 筆事件。
- (d) 已評估 3 條規則、略過 2 條，本次觸發 1 筆事件。已評估的規則中，1 條符合條件但在冷卻中，本次未觸發事件。
- (e) 已評估 5 條規則、略過 0 條，本次觸發 0 筆事件。已評估的規則中，5 條符合條件但在冷卻中，本次未觸發事件。
- (f) 目前沒有啟用中的規則，本次未評估任何規則。
