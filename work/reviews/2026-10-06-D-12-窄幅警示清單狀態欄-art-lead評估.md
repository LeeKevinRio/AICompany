## 1. D-12 分析

### 事實（含新看到的截圖）
- NBETAV 單列：條件欄「beta.value 大於（>） 1.5」在 375 勉強可見。
- NALL 七列：條件欄文字被容器右緣切掉。例如 `beta.value 大於（>` 的門檻數字不見了、`drawdown.max_dra…`、`單一標的佔比上限 被…` 同樣被切；容器無任何捲動提示。
- 也就是說，窄幅初始看不到的不只「狀態」：**條件欄門檻數字與「操作」（編輯／刪除）欄也看不到**。D-12 只描述了症狀之一。

### 各選項
- **(a) 狀態欄前移為第二欄：不建議。**
  1. table cell 無法用 CSS 只在窄幅重排欄序，只能永久改欄序，桌機也變。
  2. 在「條件」之前多塞約 70px，把真正有價值的條件欄（含門檻數字）推得更遠，淨效果是變差。
  3. 現有測試釘死 `cells[3]` 為狀態、欄序為 代號／類型／條件／狀態，要連動改。
- **(b) 第一欄副標顯示狀態：建議。** 狀態文字與 W-3 同欄並列，W-3 既有版位（第一欄、代號下方 2px）完全不動，
  e2e 第二十輪已驗的幾何不被破壞。需配合窄幅隱藏獨立狀態欄，避免同一畫面重複讀兩次（螢幕閱讀器也只讀一次，因 `display:none`）。
- **(c) 維持現狀：可接受，非 required。** 理由：L-16 的適用範圍是個股頁／槓桿專章三張表（風控重開條件明列欄位或欄寬 class 變更才重開），
  設定頁表格不在範圍；DataSourcesSection `min-w-[480px]` 同型做法一直被接受；W-3 本身已在初始視窗內。
  但「啟用中／已停用」是規則清單的主要區辨資訊（一條已停用但顯示『不會觸發』的規則更需要看到狀態），(b) 成本低，值得做。

### 為什麼不直接照抄 LeverageChapterView 的 `w-full sm:w-auto sm:min-w-[480px]`
那張表只有 2 欄（列標＋數值），299px 內可折行。警示清單 6 欄塞進 299px，每欄約 50px，
「建立時間」「編輯／刪除」會爆。該做法不適用，除非像 D-13 那樣隱藏欄位。

## 2. 註記 d：斷行

關鍵事實：notice rect 實測寬 78.53～106.02px，**遠小於 `max-w-[9rem]`＝144px**。也就是說 `max-w` 在 375／390 根本不是約束，
限制來自第一欄被 table-auto 分配到的欄寬（`min-w-[620px]` 的 table 中，條件欄需要寬，第一欄被擠窄）。因此：
- **改 `max-w-[11rem]`：無效**（上限更高但約束不在它），不處理。
- **想讓 notice 單行就得加 `min-w`**：全文約 132px（11 字 × 12px）＋左框 2px＋`pl-1.5` 6px，需要約 140～152px 欄內寬，
  第一欄會變成約 170～190px，再加類型欄約 84px，條件欄在 299px 容器內幾乎完全被推出初始視窗，
  **會讓 D-13 的問題惡化**。不建議。
- **`break-keep`（`word-break: keep-all`）：不建議。** 整串 11 字若被視為不可斷詞，最小內容寬度變成約 132px，
  效果等同上面的「撐寬第一欄」；且括號前是否仍可斷行取決於瀏覽器實作，我無法在這邊驗證。
- **`text-balance`（`text-wrap: balance`）：可選 nit。** 不改盒寬，只改行內平均分配；3 行情境推論會變成約「不會觸發／（欄位不／提供）」，
  不再有「供）」孤字。Chromium 114+、Safari 17.5+ 支援，不支援時退回現狀，無害。**此為推論，須 e2e 目視；若沒有比現狀好就移除。**
- 不得改字面、不得斷字插 `<wbr>`（既有測試以 `>不會觸發（欄位不提供）<` 精確比對，且文字須逐字不變）。

「供）」單獨成行僅在 7 條全資料集的條件欄很寬時出現，完整可讀、未裁切，維持第二十輪「可接受」判定。

## 3. 給 frontend-engineer 的規格（D-12 (b)＋註記 d 的 `text-balance`）

檔案：`apps/stock-desk/frontend/app/settings/AlertRulesSection.tsx`（`AlertRulesTable`）。不新增任何字面。

1. 在 `<tr>` 內抽出一個常數，避免重複字面：`const statusText = rule.enabled ? "啟用中" : "已停用";`
2. 第一欄 `<td>`：**W-3 區塊保持原位與原 class（`max-w-[9rem]` 等一個都不拿掉）**；
   在 W-3 區塊**之後**（不是之前，維持 W-3 與代號 div 距離 2px）加入：
   `<div className="mt-1 text-xs text-neutral-300 sm:hidden">{statusText}</div>`
   - 不得暗於 neutral-400、不得 tooltip、不得只靠顏色。
   - 「啟用／停用」兩態不得以顏色區分（沿用單一 neutral-300，字面即是區辨）。
3. 「狀態」欄：`<th>` 與 `<td>` 都加 `hidden sm:table-cell`（斷點 `sm`＝640px，與 LeverageChapterView 一致）。
   - `<th>` 範例：`className="hidden px-3 py-2 font-medium sm:table-cell"`；`<td>` 範例：`className="hidden px-3 py-2 text-neutral-300 sm:table-cell"`，內容用 `statusText`。
   - 欄序、其他欄 class 不動；table 保持 `min-w-[620px]`（先不引入未實測的新數值）。
4. （可選）W-3 區塊 class 末尾加 `text-balance`；其他 class 不動。
5. 單元測試調整：
   - 保持：`cells[3]` 為 `status`、`cells[0]` 含 W-3、W-3 僅出現 1 次、`min-w-[620px]`、`overflow-x-auto`、W-3 class 清單（含 `max-w-[9rem]`）。
   - 新增：第一欄含 `sm:hidden` 的狀態 div 且文字等於狀態；狀態 `<th>`／`<td>` class 含 `hidden`、`sm:table-cell`；`<th>` 文字仍為「狀態」。
   - 注意測試的 `>${status}<` 比對會因新 div 多一次命中，仍通過；若有 `occurrences` 類計數請改成針對 W-3 字面，不要針對狀態字面。

### 驗收條件（qa-e2e，`next build`＋`next start`，沿用第二十輪資料集 BETAV／BETAREF／POSW／NALL，375／390 各一組，另加 640／768／1280）
1. 375／390、`scrollLeft=0`：每列第一欄的狀態文字存在、文字等於該規則啟用狀態、`rect.right ≤ 容器可視右緣`、完整不裁切。
2. **W-3 不回歸**：notice 仍在第一欄代號下方、與代號 div 距離 2px、`scrollWidth==clientWidth`、`scrollHeight==clientHeight`、
   computed color `rgb(255, 185, 0)`、無 ellipsis、無 overflow hidden、初始可視範圍內完整可見。若欄寬因隱藏狀態欄而重分配，記錄新 rect 與行數即可，不要求與第二十輪相同行數。
3. 每列在畫面上恰好 1 個可見狀態文字（<640 為第一欄副標、≥640 為狀態欄），無重複；<640 狀態 `th`／`td` 為 `display:none`；≥640 副標 `display:none`、「狀態」欄標題與儲存格可見。
4. `docScrollWidth == innerWidth`（375／390）；表容器仍可水平捲動，不新增捲動提示。
5. 640／768 量測狀態欄是否在初始水平可視範圍；若不在，視為與現況相同、非回歸，但請記錄。
6. 若採 `text-balance`：NALL 375／390 附 W-3 三列截圖，目視無孤字「供）」或至少不比現況差；否則移除該 class。
7. 風控須知悉：W-3 文字、位置與 class 未變，狀態文字仍並存保留。

## 4. 風險
- 第一欄每列在窄幅多 1 行（NALL 共 +7 行）；第一欄高度增加屬可接受。
- 隱藏狀態欄後 table 欄寬重分配，W-3 的欄寬與折行數可能改變（可能更好、也可能更差），需 e2e 重拍，不能沿用第二十輪數據。
- 同一資訊在 DOM 出現兩次（以 `display:none` 互斥）；測試與日後維護者需知道兩處要同步，因此以 `statusText` 常數統一來源。
- `text-balance` 與 `break-keep` 的效果我無法在無瀏覽器環境驗證；`text-balance` 風險低，`break-keep` 有撐寬欄位風險故不建議。
- 這次改動不解決 D-13；不要把 D-12 完成誤認為窄幅清單已達「核心資訊皆可見」。
