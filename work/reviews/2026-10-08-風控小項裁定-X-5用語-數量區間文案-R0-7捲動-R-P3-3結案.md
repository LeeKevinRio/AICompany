#### 2. 既有數量區間文案歸因：維持

理由：
- `QUANTITY_RANGE_ABSENCE_TEXT`（`frontend/app/lib/adviceWording.ts:209`）「此建議未附帶數量區間（無法從風險上限推導）。」在 own>0 時字面成立。own>0 時，第 1、4、5 條依 6A-03 被排除，第 2、3 條也過不了閘門，`caps` 一定是空的，`suggest_quantity_range` 回傳 None（我在第五段 P-5 的裁定，`work/reviews/2026-10-07-上限分子不完整-非對稱判定-揭露字面-風控審查.md:155`）。所以「無法從風險上限推導」是真的。
- 這句的歸因確實籠統，但不會導向錯誤處置。它不像 X-3 1b 那樣把成因錯指成「匯率中斷」，讓使用者去等匯率恢復。沒有區間屬保守方向，不會誘導加碼。具體成因同一頁就有揭露：W-a1 或 W-a2 的 detail，加上 D-d1 的 context note（e2e 驗收檔 L64、L66）。
- 依 `adviceWording.ts:202-207`，要改成依成因區分的句子，本來就必須走 AC-2.2 的逐字審。這是既定的列管項，不是新缺陷。
- 導引句 `ADVICE_CARD_XREF_TO_SUMMARY`（`lib/sectionTaglines.ts:34-36`）在區間為 null 時也成立。操作摘要確實列出了「建議數量區間」這一項，只是內容是「沒有」：主視圖股數格顯示「未提供股數」（`DecisionCard.tsx:334`、`adviceWording.ts:217`），全句「此建議未附帶數量區間…」也有渲染（`operationSummary.ts:287`、`OperationSummaryPanel.tsx:239, 323`）。使用者照導引往上找，看到的是明確的「未提供」，不會看到任何數字。e2e 也確認頁面上沒有區間數值（L67）。
- 對照 ADR-0023 R-P5-1（`docs/adr/0023-…md:446`；我審查檔 L194）：要求的是卡上「沒有數量區間、沒有『未參與計算』」。這兩句是「沒有區間」的聲明，不是區間，符合要求。R-P5-2（L447、L195）講的並列情境在 own=0、第 3 條 violated 的 6-b，跟這兩句無關。

**suggested 約束（給 creative-lead，等下次起草 AC-2.2 依成因區分的未提供區間句時一起處理，不另開急件）**
- own>0 的成因句要寫明「本標的有持倉無法估值」，不得寫成泛稱的資料中斷或匯率中斷。
- 不得暗示「區間為 0」或「可以自行加碼」；要保留「系統這次不提供股數」的意思。
- 導引句若要改，只能補上「或其未提供的說明」這類限定，不得刪掉任何一個列舉項目。改了就要重新逐字審，`componentWordingScan.test.ts:962` 的釘住測試要同步更新。
- 失效條件：own>0 的卡上若出現任何區間數值，或 6-b 第 3 條閘門從「加上」改成「改為」（R-P5-3），本項維持裁定失效，須重審。

#### 3. R0-7 在 375 寬需要卡內捲動：接受

理由：
- R0-7 的原文是「同時出現在同一張卡上，並附截圖」（PR-0 任務單 L228）。目的是讓成因補充能在同一張卡內讀到，不必離開卡片或另開視窗，並沒有要求兩句落在同一個視窗內。e2e 實測結果：兩句在同一個 `<details>` 內，展開一次就都可見，`insideCardElement`／`withinCardRect`＝true（驗收檔 L73-75）；兩寬 `outsideViewportChars`／`clippedByAncestorBoxChars`＝0（L77）。
- 閱讀順序有利：FX note 的 top 是 3355，第 4 條是 4327，使用者往下讀會先看到成因、再看到「缺少 ATR(14)」。
- 第 4 條是 not_evaluable，方向保守，原本就列 low（PR-0 裁定 4，L186）。

**不要求調整版面。失效條件**（任何一項發生，R0-7 須重驗，並由我重審）：
- FX note 或混雜 note 被移出建議卡，或被放進另一個預設收合的巢狀 `<details>`、分頁、tooltip。
- 兩句的閱讀順序反轉，而且中間隔了需要再展開的區塊。
- FX note 的視覺權重被降到低於第 4 條原句，例如字級更小或被淡化。

art-lead 若之後改這張卡的版面，可自行考慮讓兩句靠近，但這不是要求。

#### 4. R-P3-3 結案方式：接受，附一項 required 更正
