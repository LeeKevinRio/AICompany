## 二、各部門回報（逐條意見）

**1. 方案 C 的否決理由**
- 違反紅線「不放行隱藏風險、誘導性表述」：「命中率」會讓讀者把歷史比例讀成當前判斷的準確度，這正是 PV-14 要防的事。
- 它也直接推翻我在 2026-10-16 FT-9 已核可的「比 PV-14 更嚴」。
- 詞級例外還會外溢到其他頁面、匯出和 API 字串。
- 這一點列入書面否決紀錄。

**2. 不採方案 B**

**3. 禁字表要加在哪裡（required，更正 3.3）**
- `/home/user/AICompany/apps/stock-desk/shared/forbidden-terms.json` 只收 `guarantee` 與 `price_target` 兩類，連「命中率」都不在裡面；它的 `_meta` 也把範圍限定為這兩類。所以新詞**不加在 shared json**。
- 正確位置有兩處：
  - `/home/user/AICompany/apps/stock-desk/frontend/app/lib/adviceWording.ts` 的 `FRONTEND_FORBIDDEN_TERMS`「機率洗白」段，接在 L433–435 之後；

**4. 示例句 3.1：方向核可，3 項 required**
- (a) 這不是「LM-32 逐字」。開頭的「本展望：」被換成「3 日展望（歷史重放）：」，所以它是新字串，要在重放區塊逐字批另編號送審。
- (b) 「不影響驗證狀態」要改成已核可的「結果不改變驗證狀態」（LM-142／RS-4 用語），避免同一件事出現兩種說法。
- (c) n＝0 的處理要另寫。LM-32 是「n＝0 時不渲染」，但 §4.7 L1401 規定段內 n＝0 時照列，記「不適用（n＝0）」。重放區塊要照 §4.7，不得靜默消失。全期列與各相位列在 n＝0 時的逐字，要一併起草。
- suggested：同區塊列出快照的取得日期（資料時間戳），也可以在日曆核對揭露裡併列。

**5. 改 1、改 2 的修改理由**
- 改 1 原稿說「符合次數與 n（即本文件的命中率）」，但符合次數不等於比例，寫法不精確。另外：
  - 依 PV-14 的「期間、區間」，加列期間；
  - 依 LM 3-c VETO，寫明不列單獨的點估計百分比。
- 改 2 原稿直接取代原文，不合本檔「〔註〕＋本列原文不改」的慣例，所以改成接字。範圍也要補足：
  - 寫明涵蓋畫面、匯出、推播、提醒與 API 顯示字串；
  - 寫明兩種寫法是同一個量（k／n），防止被讀成兩個指標；
  - 逐項點名其餘各處的「命中率」都適用。這樣 3.2 說的「其餘各處由對照句統一涵蓋」才成立。

**給 dev-lead 的測試要求：在 3.3 原有四項之外，另補 8 項 required**
1. **掃描涵蓋所有渲染狀態**：正常、n＝0、尾段、各相位、只有失敗、取數嘗試 0 次。重放區塊有匯出或推播時一併掃。
2. **點估計百分比**：區塊內每個 `\d+(\.\d+)?%` 只能是「95% 信賴區間（Wilson）」的 95%，或 `{lo}%～{hi}%` 成對出現的兩端；其餘一律失敗。
3. **後端顯示字串**：重放 API 的顯示字串，要比照 `test_rules_invalidation_wording.py` 的 `load_frontend_forbidden_terms()`，對**完整**的前端清單掃描，不用手抄的子集鏡像。API 欄位名可以保留 `hit_rate` 這類內部名，但前端不得渲染欄位名，也不得渲染未經核可的後端字串。
4. **LM-91 可見性**：「符合」出現時，LM-91 定義必須在同一區塊的 DOM 內直接可見，不得放進折疊區、tooltip 或 hover。
5. **比較詞與概括詞**：區塊內不得出現「優於」「高於」「低於」「較佳」「最好」「最差」「各段一致」「表現穩定」（L1402、L1431）。
6. **逐字釘住**：重放區塊每一句都以常數加 pin 測試釘住，改字就要回風控重審。
7. **新增五詞的存在性斷言**：前端清單與後端 `_FRONTEND_TERMS` 都要有。
8. **n＝0**：照列「不適用（n＝0）」，不刪列、不併段，逐字等第 4 點 (c) 核可後再釘。
