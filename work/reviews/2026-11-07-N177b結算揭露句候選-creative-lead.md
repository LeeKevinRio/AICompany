## 0. 前置說明與一處名稱差異

- **名稱差異**：任務單把 N2 稱為 `SETTLEMENT_EXIT_RECONCILE_NOTE`。目前 checkout 的 `apps/stock-desk/backend/app/playbook/wording.py:950` 沒有這個名稱（全 repo 的 `.py` 也 grep 不到），N2 的實際常數是 **`SETTLEMENT_EXIT_NOTHING_MOVED_NOTE`**，項目格式是 `SETTLEMENT_EXIT_ITEM`（:956）。本檔以這兩個為準比對。若有另一個尚未合入的同名常數，請 coordinator 指給我。
- N2 原文（比對基準）：

  「本次判定成交的出清賣出指令中，有 {count} 筆在判定時該批次在帳冊已無持股，帳冊股數與現金都未因這幾筆變動：{exit_items}。帳冊中這幾批只依另一筆賣出指令減少一次股數，判定的日期與價格可能與你實際賣出的不同；實際成交結果以你的券商回報為準。」

- 共用佔位符只有 `{count}` 與 `{items}`。`{items}` 由項目格式組成、以「、」連接（比照 N2）。
- 既有 G1 句（`SETTLEMENT_BATCH_ALREADY_FILLED_NOTE`）已核可的「若已買進且成交……S/P 系列不會評估它們的停損停利，全部出清也不會涵蓋它們」是 buy 句的語氣先例，候選 B1 沿用同一骨架。

## 1. 項目格式（兩個常數）

可用欄位：symbol、batch_no、shares、execution_date、rule_id。`batch_no` 為 None 時不得印出「第 None 批」（RC-8 已指出 N2 的項目格式有這個問題），所以拆成兩個變體，由 service 依 `batch_no is None` 擇一。

| 識別名（暫定） | 字面 |
|---|---|
| `SETTLEMENT_UNBOOKED_ITEM` | `{symbol}第 {batch_no} 批 {shares} 股（規則 {rule_id}，預定執行日 {execution_date}）` |
| `SETTLEMENT_UNBOOKED_ITEM_NO_BATCH` | `{symbol}（指令未帶批次編號）{shares} 股（規則 {rule_id}，預定執行日 {execution_date}）` |

說明：
- 骨架比照 `SETTLEMENT_BATCH_ALREADY_FILLED_NOTE` 的「{symbol}第 {batch_no} 批買進 {shares} 股（規則 {rule_id}，預定執行日 {execution_date}）」，使用者在同一份 warnings 裡看到的寫法一致。
- 不含 action：句子主體已經分 buy／sell，不在項目上重複。
- 規則 ID 放在項目裡，讓使用者看得出是 R 系列、S1 還是 P 系列，不需句子再分述。
- Q-c 句的批次一定存在（`batch_no` 為整數），只用第一個變體；sell 句理論上也只會是整數或（若有未預期路徑）None，所以兩個變體都保留。
- 禁用詞自查（兩個項目格式）：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。

## 2. 句 1：buy 句 `SETTLEMENT_UNBOOKED_BUY_NOTE`

### 候選 B1（雙分支，沿用 G1 骨架）

「本次判定成交的買進指令中，有 {count} 筆在帳冊找不到所屬批次的紀錄，帳冊股數與現金都未因這幾筆變動：{items}。本系統不下單，無法得知你是否已依這幾筆在券商買進：若在券商已成交，這些股數不在帳冊內，S/P 系列不會評估它們的停損停利，全部出清也不會涵蓋它們；若未下單或未成交，帳冊不受這幾筆影響。實際持股以你的券商回報為準。」

- 為真的情況：
  - 這幾筆是 `status == executed`、action 為 buy 的指令，且 `batch_no` 為 None 或 `get_batch` 回 None；
  - `settle` 沒有動股數也沒有動現金（規格第 5 節「帳冊行為不變」）；
  - 「S/P 系列不會評估、全部出清不會涵蓋」為真，是因為 S/P 只評估帳冊中 open 且有股數的批次，EMERGENCY 的目標取自現存批次（RC-8 已核對 `service.py:417-420`）；沒有批次列就不在這兩個範圍內；
  - 「若未下單或未成交，帳冊不受影響」為真，因為帳冊本來就沒動。
- 優點：雙分支對稱，沒有預設使用者已買進或沒買進；與 G1 句同構，風控已核可過同一型態。
- 缺點：最長（約 190 字）；整句只有一個冒號後接兩個分支，閱讀負擔略高。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 備註：「你是否已依這幾筆在券商買進」不構成「你已買進」；
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次、「全部出清也不會涵蓋」1 次。

### 候選 B2（短版，風險句前置）

「本次判定成交的買進指令中，有 {count} 筆在帳冊找不到所屬批次的紀錄，股數與現金都未因這幾筆變動：{items}。這些股數若在券商已成交，就不在 S/P 系列的評估範圍內，全部出清也不會涵蓋它們。本系統不下單，無法得知你在券商是否有成交；實際持股以你的券商回報為準。」

- 為真的情況：同 B1 的第一、二、三點；B2 沒有寫「若未下單或未成交」那一支，因為句子只講「若已成交」的後果，並用「無法得知你在券商是否有成交」交代兩種可能。
- 優點：約 130 字；風險句放在第二句，最先被看到。
- 缺點：只有已成交那一支有後果描述，另一支只靠「無法得知」帶過，對稱性比 B1 弱；風控 A-1 通知句的先例是兩種可能對稱陳述。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次、「全部出清也不會涵蓋」1 次。

## 3. 句 2：逐批 sell 句 `SETTLEMENT_UNBOOKED_SELL_NOTE`

### 候選 S1（骨架與 buy 句一致）

「本次判定成交的逐批賣出指令中，有 {count} 筆在帳冊找不到所屬批次的紀錄，帳冊股數與現金都未因這幾筆變動：{items}。本系統不下單，無法得知你是否已依這幾筆在券商賣出；實際持股以你的券商回報為準。」

- 為真的情況：
  - 這幾筆是 `executed`、action 為 sell、非 S2（`is_s2_fill` 為假）、非 EMERGENCY（service 已排除，Q-b 接受）；
  - 批次列不存在（`batch_no` 為 None 或 `get_batch` 回 None）；
  - `settle` 沒有動股數與現金。
  - 「逐批賣出指令」涵蓋 S1、P1、P2、P3，也涵蓋日後任何非 S2、非 EMERGENCY 的逐批賣出，所以字面不寫「停損停利」，避免 S3 等路徑出現時變成不實陳述。
- 優點：與 B1 同一骨架，最短；沒有推測使用者行為。
- 缺點：sell 句沒有像 buy 句那樣描述「在券商已賣出」的後果。理由：風控 A-2 對 sell 只要求陳述「找不到批次、未變動」這個事實，不要求後果句；加後果句會超出裁示範圍。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次。

### 候選 S2（補一句「帳冊沒有可扣減的股數」）

「本次判定成交的逐批賣出指令中，有 {count} 筆：帳冊找不到所屬批次的紀錄，帳冊裡沒有可扣減的股數，股數與現金都未因這幾筆變動：{items}。本系統不下單，不判斷你在券商是否已賣出；實際持股以你的券商回報為準。」

- 為真的情況：同 S1；「沒有可扣減的股數」為真，因為批次列不存在即無 remaining 可減。
- 優點：說明「為什麼沒動」，使用者不會誤以為是系統漏算。
- 缺點：「沒有可扣減的股數」與 Q-c 句「已無持股」在字面上有相近處，兩句同時出現時可能被誤讀為同一件事（S2 說的是找不到批次，Q-c 說的是批次存在但已無持股）。這是 S1 優於 S2 的主因。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次。

## 4. 句 3：Q-c 句，識別名提議 `SETTLEMENT_BATCH_EMPTY_SELL_NOTE`

命名理由：與既有 `SETTLEMENT_BATCH_ALREADY_FILLED_NOTE`（G1）、`SETTLEMENT_EXIT_NOTHING_MOVED_NOTE`（N2）同屬「批次狀態」命名系；`BATCH_EMPTY` 直接對應「批次已空」這個事實，與 `UNBOOKED`（批次列不存在）區隔。項目格式沿用 `SETTLEMENT_UNBOOKED_ITEM`（批次一定存在，只用有 batch_no 的變體）。

### 候選 Q1（明示與 N2 的範圍不同）

「本次判定成交的逐批賣出指令（不是全部出清產生的賣出指令）中，有 {count} 筆在判定時該批次在帳冊已無持股，帳冊股數與現金都未因這幾筆變動：{items}。本系統不下單；實際持股以你的券商回報為準。」

- 為真的情況：
  - 這幾筆是 `executed`、action 為 sell、非 EMERGENCY、非 S2，批次存在，而且判定當下 remaining 為 0；
  - 因此 `settle` 的 `moved = min(0, shares) = 0`、現金 +0（規格 4.10）；
  - 句子只陳述帳冊在判定當下的狀態，不說原因（可能是另一筆賣出、S2 已關閉等），也不推測使用者有沒有賣。
- 優點：
  - 括號明示「不是全部出清產生」，與 N2（只涵蓋出清賣出）在字面上互斥，同一份 warnings 兩句並存時不會被讀成重複；
  - 前半句沿用 N2 已核可的「在判定時該批次在帳冊已無持股，帳冊股數與現金都未因這幾筆變動」，風控已看過這個說法；
  - 最短，只有事實。
- 缺點：沒有提醒「帳冊不等於券商」的一般性提示，只靠最後一句「實際持股以你的券商回報為準」。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次。

### 候選 Q2（加一句帳冊與券商的關係）

「判定成交的逐批賣出指令（不含全部出清產生者）有 {count} 筆：判定當下，所屬批次在帳冊已無持股，股數與現金都未因這幾筆變動：{items}。本系統不下單，帳冊紀錄不一定等於你的券商持股；實際持股以你的券商回報為準。」

- 為真的情況：同 Q1；「帳冊紀錄不一定等於你的券商持股」為真，因為帳冊只記本系統判定的結果，價格與日期相同時才可能相等，這是風控在 RC-4 用過的「不一定等於」型態。
- 優點：多一句一般性提示，與 buy 句、sell 句的語氣更一致。
- 缺點：開頭省略「本次」，與前兩句的起頭不一致；「不一定等於」在 Q-c 的情境下是否會被讀成暗示「使用者可能已賣出」，這點要風控判斷（我認為不會，但這是風控 RC-7「不推測使用者是否已賣出」的邊界）。
- 禁用詞自查：需0 應0 建議0 務必0 盡快0 否則0 安全0 已取消0 已撤單0 你已買進0 對應0。
  - 必含句：「本系統不下單」1 次、「實際持股以你的券商回報為準」1 次。

## 5. 與 N2 同列一個 warnings 清單的相容性檢查

| 檢查項 | 結果 |
|---|---|
| 同一筆指令是否可能同時進兩句 | 不會。buy 句與 sell 句要求批次列不存在；Q-c 句要求批次列存在且 remaining 為 0；N2 只收 EMERGENCY。S2、missed、非下單列都被排除。 |
| 句間是否重複 | 不重複。N2 是「出清賣出」，Q-c 是「逐批賣出（不是出清）」，兩者以 rule_id 是否為 EMERGENCY 互斥；Q-c 的括號文字把這個範圍寫在字面裡。 |
| 句間是否矛盾 | 不矛盾。N2 的「帳冊中這幾批只依另一筆賣出指令減少一次股數」只針對 EMERGENCY 的那幾批；Q-c 不說明批次為何已空，所以不與它衝突。buy／sell 句說「找不到批次」，N2 與 Q-c 說「批次存在但已無持股」，是兩種不同的帳冊狀態。 |
| 順序 | 依風控 RC-7 暫定：N2 → buy 句 → sell 句 → Q-c 句；最終順序隨風控定稿。 |
| 同時出現的重複詞 | 「本系統不下單」「實際持股以你的券商回報為準」會在多句重複，這是風控要求每句必含，不屬重複揭露。 |

## 6. 給風控與 TA 的備註

1. **Q-c 的判定來源**：RC-7 說明判定來源是 `settle` 回傳結構化結果。Q-c 需要 `SettleOutcome` 再加一個布林（例如「批次存在但判定時 remaining 為 0」），由 TA 在規格中補欄位名稱。若改成 service 結算前先讀（比照 N2），會有規格第 2 節否決的「兩份判定、可能漂移」問題。
2. **sell 句是否涵蓋 S3**：字面刻意寫「逐批賣出指令」而非「停損停利」。若風控希望寫成「停損停利賣出」，S1 與 S2 的前半句各改一處即可，不影響其他句。
3. **batch_no 為 None 的 sell 項目**：目前引擎只有 S2 會產生 `batch_no=None` 的 sell（RC-8 已核對），所以 `SETTLEMENT_UNBOOKED_ITEM_NO_BATCH` 在 sell 句裡走不到；仍保留變體，以免日後出現可達路徑時印出「第 None 批」。
4. **N2 的項目格式問題**：N2 的 `SETTLEMENT_EXIT_ITEM` 遇到 `batch_no=None` 會印出「第 None 批」，RC-8 已接受走不到，本檔不處理。
5. 本檔所有候選都屬面向使用者的揭露字面，**待 risk-compliance-officer 審並逐字定稿**；PR 比對依 N177b-C5。

## 7. 推薦組合

**B1 + S1 + Q1**

- B1：buy 句是唯一有真實後果的一句（S/P 不評估、出清不涵蓋），雙分支對稱，沿用風控已核可的 G1 骨架。
- S1：只陳述事實，與 B1 同一骨架，也沒有超出風控 A-2 的範圍；比 S2 少一個與 Q-c 混淆的風險。
- Q1：括號寫明與 N2 的範圍界線，前半句沿用 N2 已核可的說法，最少推測。
- 如果風控希望三句更短，備選是 B2 + S1 + Q1，代價是 buy 句的對稱性下降。
