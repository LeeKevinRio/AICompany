## 1. 正向形狀規則

```python
# Applied with re.fullmatch on the raw string. No strip, no upper-casing, no suffix stripping.
TW_SYMBOL_SHAPE = re.compile(
    r"[1-9][0-9]{3}[A-JL-Z]?"      # (A) ordinary stock / preferred / 4-digit DR
    r"|00[0-9]{2,4}[A-JL-Z]?"      # (B) ETF: 0050, 00878, 006208, 00631L, 00679B, 00981A
    r"|91[0-9]{4}"                 # (C) 6-digit DR (TDR)
)
```

說明：
- 只用 `[0-9]`、`[A-Z]`，不用 `\d`（Python 的 `\d` 會放行全形數字）。判定一律用 `fullmatch`，不用 `$`（`$` 會放行尾端換行）。
- 字母後綴排除 `K`：沿用現行 `TW_SYMBOL_RULE` 的設計，`K` 是外幣計價交易單位（如 `00625K`），不屬於台幣計價標的，這與 N-207 的 FR 是否收外幣標的無關，由 PM 另行裁示。
- 只收大寫。小寫（`2330k`、`00631l`）拒絕，不自動轉大寫（FR-5 不自動正規化）。

### 1.1 分類與依據

| 類別 | 形狀 | 例（repo 內出現或常見） | 公開來源查證 |
|---|---|---|---|
| 上市／上櫃普通股 | 4 位數字（首位 1-9） | `2330`、`6488` | 未查證（無法連網） |
| 特別股 | 4 位數字＋1 個大寫字母 | `2882A`、`2891B` | 未查證 |
| ETF（舊式） | `00` 開頭 4 位 | `0050`、`0056` | 未查證 |
| ETF（5 位、6 位數字） | `00` 開頭 5 或 6 位 | `00878`、`006208` | 未查證 |
| 槓桿 ETF（L）、反向 ETF（R） | 5 位數字＋L／R | `00631L`、`00632R` | 未查證；repo 內 `admission.py` 註解與 `tests/test_f9a_admission.py` 有用到，屬專案內證據 |
| 期貨 ETF（U） | 5 位數字＋U | `00635U` | 未查證；同上 |
| 債券 ETF（B） | 5 位數字＋B | `00679B`、`00720B` | 未查證；同上 |
| 主動式 ETF（A） | 5 位數字＋A | `00981A` | 未查證；`tests/` 內出現，非交易所依據 |
| 存託憑證（TDR） | `91` 開頭 4 位或 6 位 | `9103`、`910322` | 未查證 |
| 外幣計價交易單位（K） | 數字＋K | `00625K`、`2330K` | 要排除；排除依據是現行 `admission.py:125-136` 的設計說明，非交易所文件 |

### 1.2 明確排除的形狀

| 形狀 | 例 | 排除原因 |
|---|---|---|
| `.TW`／`.TWO`／`.US` 等後綴 | `2330.TW` | FR-5 不自動正規化，直接拒絕；台股資料源皆不吃後綴（第 2 節） |
| 空字串、純空白 | `""`、`"  "` | 不是代號 |
| 前後空白、內含空白、尾端換行 | `" 2330"`、`"2330\n"` | 不正規化；`fullmatch` 不放行 |
| 全形字元 | `２３３０`、`００５０` | 只收 ASCII `[0-9]` |
| 小寫字母 | `2330k`、`00631l` | 只收大寫，不轉換 |
| 權證 | `030001` 一類 `0[3-8]xxxx` | 不是排程台標的；形狀規則不收（`00` 前綴才收 ETF） |
| 位數不對 | `233`、`23300`、`1234567` | 不符任一類 |
| 兩個以上字母後綴、字母夾在中間 | `2330AB`、`2330A1` | 不符 |
| 外幣單位 K | `00625K`、`2330K` | 見 1.1 |
| 指數、美股 | `^TWII`、`AAPL` | 不是台股代號 |

### 1.3 已知殘留（誠實揭露）

- 形狀規則只管「長得像」，管不到「真的存在」。`0000`、`9999`、`1000` 這類形狀合法但不存在的代號會通過形狀檢查，由 FR-5 第三項（取得日線）擋下。這是設計分工，不是漏洞。
- 6 位數字 `91xxxx` 只憑記憶，沒有依據，查證後可能要調整或刪除 (C)。
- 興櫃、創櫃、`T`／`P` 等其他字母後綴是否存在於日線資料源，未查證，規則一律不收。若查證發現合法且資料源有日線，再擴充 `[A-JL-Z]` 以外的處理。
- 我用本機 Python（`python3 -I`）對 1 節的 regex 跑過第 4 節全部案例，結果見第 5 節。

## 2. 與現有資料源的相容性

### 2.1 排程台日線用的 adapter

- 組裝處：`apps/stock-desk/backend/app/api/deps.py:125-127`，`tw_service = MarketDataService(primary=TwseAdapter(), backups=[TpexAdapter(), FinMindAdapter()], ... scope="equity", admission=admit_equity_daily_bars)`。順序：TWSE（上市）→ TPEx（上櫃）→ FinMind。
- 代號格式（三者一致，都是裸代號，原樣放進請求）：
  - `TwseAdapter`：`stockNo=<symbol>`（`data/providers/twse.py:100`）。
  - `TpexAdapter`：`code=<symbol>`（`data/providers/tpex.py:221`）。
  - `FinMindAdapter`：`data_id=<symbol>`（`data/providers/finmind.py:113`）。
- 三者都沒有處理 `.TW` 後綴；`2330.TW` 送進去只會變成「查無資料」，不會被轉成 `2330`。所以拒絕 `.TW` 與資料源行為一致。
- 美股走 `AlphaVantageAdapter`，不在本規則範圍。

### 2.2 規則放行的代號，資料源能不能查日線

**不能保證，未驗證。** 證據層級：
- 普通股 `2330`：TWSE 與 FinMind 已於 2026-08-16 由 CEO 本機實測（`data/providers/twse.py` 檔頭、`work/research/驗證結果-2026-08-16.md`）。
- 帶字母的 ETF／特別股、6 位數字、DR：repo 內沒有實測紀錄，只有 fixture 測試。這是資料源對這些代號是否收的**未知**，不是已知可行。
- TPEx adapter 自己的檔頭也標未驗證。
- 因此 FR-5 第三項（取得日線）與 AC-05 不可省，它是形狀規則放行但資料源不收時的唯一防線；形狀規則不得被當成「能查到日線」的保證。

### 2.3 正規化放哪一層

- N-207 的 FR-5 已明定「不自動正規化」，所以**本規則不含任何正規化**：不 strip、不轉大寫、不剝後綴。這點與 `leverage/detect.py:50-51` 剝除 `.TW`／`.TWO`／`.US` 的行為相反，該段不得沿用。
- 規則放在**名單模組**（TA 依 ADR-0024 列已定，`:380`），不放進資料層 `app/data/admission.py`。資料層現行的 K 後綴黑名單維持原狀，繼續當第二道防線。
- 若 PM 日後改成要正規化（例如 UI 貼上時去空白），只能放在 API 邊界（request schema 的 validator），在形狀規則**之前**做，且須回顯正規化後的值給使用者確認；不得放進 adapter，也不得放進 `admit_symbol`（它的設計是純函式、不正規化）。
- 目前前端 `ALLOWED_SYMBOL_PATTERN`（`tradingViewSymbol.ts:43`）與後端 `SYMBOL_PATTERN`（`api/event_study.py:121`）都放行 `2330.TW`，與本規則不同。這兩處是其他功能用的，**本規格不要求改**；N-207 的名單提交 API 要用自己的 validator，不得 import 這兩個 pattern。

## 3. AC-04 改寫建議（交 PM）

現行（PRD :257）：

> **AC-04**（FR-5）Given 批次表為空；When 提交 `2330.TW`、空字串或非數字代號；Then 整批拒絕、零寫入，訊息指出是哪一個，且不自動正規化。

問題：「非數字代號」會把 `00631L`、`00679B`、`00981A`、`2882A` 等合法代號一併拒絕，也與 B、L、R、U 後綴合法的既有判斷衝突。

建議改寫：

> **AC-04**（FR-5）Given 批次表為空；When 提交的代號含不符台股代號形狀者（例如 `2330.TW`、空字串、含前後空白、全形數字、小寫字母、位數不對）；Then 整批拒絕、零寫入，訊息指出是哪一個代號不符形狀，且不自動正規化、不提供替代代號。
> **AC-04b**（FR-5）Given 批次表為空；When 提交含帶字母後綴的合法形狀代號（例如 `00631L`、`00679B`、`2882A`）且資料來源取得到日線；Then 不因形狀被拒絕。
