## 二、逐項審查

**1. 範圍：OK。**
- `git diff --name-only` 只列出 `apps/stock-desk/backend/tests/test_r2_first_run.py`。
- 沒有動 `app/`、`scripts/`、`.bat` 或其他測試。

**2. 遮罩 regex：夠窄。** regex 是 `(?P<key>sha256\w*=)[0-9a-f]{64}(?![0-9A-Za-z])`，替換成 `\g<key><masked>`。
- 只替換 64 位雜湊值本身，鍵名保留，同一行與相鄰內容不會被遮掉。
- `\w` 不含換行，所以不會跨行。同一行有多個欄位時，各自獨立匹配、不重疊。
- 鍵名開頭沒有邊界限制，`xsha256foo=<64hex>` 也會被遮。但只遮值，而且值必須是 64 位小寫十六進位，所以不會誤放行代號。
- 負向前瞻正確：
  - 後面接字母或數字（含 65 位）時不遮。因為 `{64}` 是固定長度，回溯也救不了，所以 65 位不會被切成 64 位後遮掉。
  - 後面接 `_` 時，雜湊遮掉，但 `_` 之後的內容仍可見，仍能抓到洩漏。
  - 大寫、63 位同樣不遮。

**3. 保護有沒有變弱：幾乎沒有，殘餘如交件所述。** 我逐一判斷各種洩漏形式：

| 洩漏形式 | 新檢查抓得到嗎 |
|---|---|
| 獨立 token、`=` 之後、逗號串列、行尾、黏在文字中 | 抓得到，沒有 sha256 鍵，完全不遮 |
| sha256 鍵的值是 `2330`（非 64 位） | 抓得到 |
| 大寫 64 位，或 63／65 位 | 抓得到 |
| 雜湊後緊接代號（同行或下一行） | 抓得到，只遮雜湊本身 |
| 64 位小寫十六進位且內含代號數字 | **抓不到**，與巧合無法區分 |

最後一種殘餘，我讀被測腳本的結果如下：
- `n177_n190_backtrack_probe.py:2249-2251` 印出的三個欄位，值來自 `script_fingerprint()`（第 406 行 `hashlib.sha256`）和 `sha256_file()`（第 417 行 `hashlib.file_digest`）。
- 腳本沒有任何路徑能把代號寫進這三個欄位。
- `r2_first_run.py` 的 `filter_probe_stdout`（第 236-247 行）只留下完整符合 `PROBE_LINE_PATTERNS` 的行。
- 同一組格式被 `PROBE_LINE_PATTERNS`（r2 第 44-45 行）和測試的 `ALLOWED`（測試檔第 162-163 行）鎖成 `[0-9a-f]{64}`。後者由 `test_normal_flow_paste_back_is_whitelisted_and_clean` 透過 `_assert_whitelisted` 強制，所以格式白名單有人把關。
- 非 64 位小寫的假值會被 `test_probe_lines_are_matched_whole_and_bad_ones_dropped_and_counted` 的 `BAD_PROBE_STDOUT`（測試檔第 509-511 行）鎖成「丟棄並計數」。
