## 2. tooltip 問題

- 現象：徽章顯示「匯率 資料不足」，hover 卻浮出實際來源的方法論句（例如 Yahoo Finance 或台銀模型值說明），等於在說明一個沒有被拿來換算的匯率。違反 `fx_notes.source_note` docstring 原則（風控 2026-09-19 suggested 4）與 RK2-R1「方法論句只描述實際採用的匯率」。
- 性質：不是隱藏風險，但與徽章本身說法矛盾，構成輕度不實揭露。
- 範圍：後端揭露路徑（`summary.fx_disclosures_for`、`book._converted_by_valuator`、`book._valued_rates`）都已排除 UNAVAILABLE；外露的只有前端 tooltip（`FxStatusBadge.tsx`，由 `PositionsTable.tsx` 渲染）與 API JSON 的 `fx.source_note`／`fx_open.source_note`。
- F-1b 之前只出在「rates 全晚於 target」罕見分支；F-1b 之後每一筆不可用匯率都會走到，故列為合併前置。
- 方向：採 (ii)，不選 (i)；(iii) 只作 suggested 縱深防禦（只改前端時 API 合約仍帶不實欄位）。

- **F1b-R13（required，coordinator 寫入任務單 CEO 知悉清單）**，建議字面：
  > **F-1b 上線後的使用者可見變化**
  > 1. 外幣持股取到的匯率為 0、負值或非有限值時，該筆不再以市值 0 或負值計入。它會列為「資料不足」：列表顯示「查無即期匯率」或「查無建倉匯率」（現在也涵蓋「有取到但數值不可用」，與 F-1 收盤價的處理相同），匯率徽章顯示「匯率 資料不足」且不帶日期。系統不會改用較早的匯率頂替。
  > 2. 因此總覽合計會標為「部分」；淨值量尺不含這一筆；已填淨值時，其他標的建議卡的總曝險上限（第 3 條）會從「通過」改為「無法評估」。修正前，匯率為 0 會讓這條上限靜默錯誤通過；修正後方向更保守，代價是在資料恢復前這條上限不給結論。
  > 3. 匯率為負時，建議卡、上限總覽、儲存淨值設定在部分情況下原本會出錯（500、不給建議），現在改為正常回應，並依第 1、2 點標示資料不足。
  > 4. 「匯率 資料不足」徽章不再浮出來源方法論說明，因為沒有被採用的匯率不做來源揭露（F1b-R10）。
  > 5. 新的 WARNING log `unusable fx rate dropped from valuation:` 就是升級觸發 1，一旦出現就升 high 並交 CEO 判斷。log 沒保存時要回報「不可觀測」，不能當成零。等級目前維持 medium，原因是無法查證。
