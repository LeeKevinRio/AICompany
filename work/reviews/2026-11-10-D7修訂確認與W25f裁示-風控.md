#### 逐條意見

**RC-75：D7 第 1～3 點修訂（2-A、2-B、2-F）→ 符合 RC-56 驗收標準 1～4，另附 4 項 required**

- **驗收標準 1（結構保證）成立。** 我自己推了一次：
  - 新增一列的 `changed_on` 記為 c。對任何 on ≤ c，這一列都不滿足 `changed_on < on`，所以不在適用列內，E(on) 不變。
  - 第 3 點 (d) 的三種取法，c 都不早於 `today_tpe`：一般情形是 `today_tpe`；標記取 max；取消取 `today_tpe`。所以只要「本次寫入時讀到的台北日」不晚於資料日，評估都不受影響。
- **E、T 兩個純函式**：
  - 定義正確，只依 id 排序，判定不需要日曆。
  - 「`changed_on` 早於 data_date」等價於「變更日之後第一個交易日起適用」，前提是 data_date 都是交易日。這個前提成立。
- **較嚴退回**：
  - 補充檔 2-F 取代 2-A 的「名單頁讀取視為失敗」，我同意。我原本擔心整頁失敗會擋住「停止新進場」這個減險操作，2-F 改成一律回 0、不 raise，這個疑慮已經消失。
  - value 無法解析時逐列回 0。我確認這是「只在無法判定時取較嚴」：
    - 壞列只有在它是 on 的 id 最大適用列時才會影響 E，這時 E = 0，是所有可能解讀中最嚴的；
    - 其他情形，不論壞列原意是什麼，E 都一樣。
  - `changed_on` 無法解析時，整檔 T = E = 0，更嚴，同意。
- **時鐘倒退時的寫入規則**：在「偵測得到的倒退」（today_tpe 早於最新一列）下成立。
- **required-1（單一定義）**：補充檔 2-F 的 `parse_high_volatility_flag(raw) -> int` 和修一檔 N207-C21 的 `high_volatility_marked(raw) -> bool`，規則相同，卻是兩個函式。
  - 只能保留一個定義，名稱擇一，另一份規格改成引用它。
  - AST 檢查要能證明，app/ 內 `type(raw) is int and raw == 1` 這個判定只出現一次。
- **required-2（寫入路徑的壞資料）**：2-A 第 3 點 (a)～(d) 沒有規定：鎖內讀到該檔歷程有無法解析的 `changed_on` 時，(d) 要怎麼比較。
  - 要補：這種情況下，高波動標記操作一律拒絕、零寫入，預覽也拒絕。
  - 理由：評估端已經是 E = 0（15%）。拒絕標記，維持 15%；拒絕取消，E 原本就是 0。兩者都不會變寬。
  - 拒絕用什麼字面，另送 creative-lead 擬、我定稿。字面沒定稿前，可以先走既有的一般失敗分支，但不得寫成「已取消」或「已標記」。
- **required-3（時鐘落後的殘留）**：2-A 第 3 點 (d) 只處理得了「today_tpe 早於最新一列」這種偵測得到的倒退。
  - 時鐘落後真實日期，但歷程中沒有較晚日期的列時，標記會以較早的 `changed_on` 寫入。資料日落在 (today_tpe, 真實日期] 之間的評估，就會改用 20%。這違反 FR-30「變更當日仍用舊門檻」，方向較寬。
  - 「不比以 `today_tpe` 寫入寬」這句以 `today_tpe` 為比較基準，字面是對的，但不能讀成精確保持 FR-30。
  - Consequences 要列為殘留（比照 ADR-0044 的 R-c），寫明方向是較寬、而且偵測不到。
  - suggested（交 TA）：標記時的 `changed_on` 改取 `max(today_tpe, 最新一列 changed_on, 鎖內可讀到的最大 roster_log.taipei_date)`，可以把偵測範圍擴大到「曾經有過任何名單寫入的日期」。
- **required-4（2-B 連動句的方向要寫明）**：2-B 新加的「壞處與代價」那一點，「落差……會改變形態」寫得太模糊，要改成寫明兩件事：
  - (i) **L6**：標籤寫「尚未適用」，今日頁用 20%，方向較寬；
  - (ii) **L4**：W-25f 第三子句不實，方向較嚴。
  - 句末「由風控裁示」改為「風控 RC-77 裁示改擬（F2）」。
  - 2-B 其他連動句（D4 第 3、4 點、D9 第 1 點、「被約束」、待決）我核對過，正確。D3 第 7 點沒有改動。
- **閘**：上述四項併入後，D7 第 1～3 點視為風控確認，可以隨 ADR-0043 的 CEO 核可轉 accepted。四項不必回送我，由 qa-reviewer 逐條核對。W-25f 的閘另見 RC-77。

**RC-77：W-25f 第三子句 → 採 F2；RC-58 的定稿在修訂版 D7 下暫停**

- **理由**
  - 字面不實，即使方向保守，也不能放行。我在 ADR 確認檔 RC-55 撤回 W-27 舊第二句，用的是同一個標準。
  - **我另外找到一個比 L4 更嚴重的例子（L11）**：
    - B = 0；週五 11-13 標記，週日 11-15 取消；today_tpe = 11-15。
    - T = 0，E(11-15) = 1，所以顯示 W-25f，M/D = 11/16。
    - 但可能的資料日最晚是 11-13，E(11-13) = 0；下一個資料日 11-16 起，取消已經適用。
    - 也就是說，這個標記**從來沒有適用過**。「今日仍用高波動門檻」在任何資料日下都不成立，加上「可能」「一般情形」也不能改成真話。
  - 名單頁拿不到 data_date（RC-21、Q-C14），所以沒有任何顯示條件能保證這個子句成立。F1 等於明知字面為假還照樣上線。
- **擬稿條件（required，交 creative-lead）**
  1. **範圍**：只改第三子句。前段「高波動標記已取消：{M} 月 {D} 日起適用（依系統日曆推算）」不變；{M}/{D} 依 W25f-3′，不新增佔位符。
  2. **在所有顯示情形下都為真**：W25f-1′ 的所有狀態（T = 0 且 E(today_tpe) = 1），對任何不晚於 today_tpe 的資料日都要成立。至少要涵蓋 L3、L4、L8、L11、E14（時鐘倒退後取消）、E18（壞值列）、多次變更。字面不得依賴資料日。
  3. **不得陳述或暗示今日或 M/D 之前實際用哪個門檻**，包括加上「可能」「一般情形」「通常」修飾的寫法（L11 下都不成立）。
  4. **不得用會被讀成「高波動」的指代**：例如「取消前的標記」「原設定」「先前的設定」。L4、L11 中，「取消前」在某些資料日適用的其實是 B = 0。若要指涉，只能寫成「依各資料日當時適用的設定」或等義的說法。
  5. **可以接受的方向（擇一）**：
     - (i) 只陳述取消的適用範圍，例如「資料日在 M/D 之前的評估，不受本次取消影響」；
     - (ii) **刪除第三子句**。FR-1、AC-65 都不要求這一句，而且 W-25f 出現時 W-27 一定會顯示，門檻規則與落差由 W-27 承載。

  6. **用語**：
     - 用「資料日」，與 W-22、W-27 一致；
     - 用「適用」，不用「生效」「待生效」（FR-49、R-18）；

  7. **送審時附自查表**：逐列說明條件 2 所列各情形下的真偽。我收到後逐字定稿，任何改動都要再送我。

**RC-78：L6 → 揭露足夠，不新增顯示條件**

- **足夠的理由**
  - L6 一定有一列帶 W-25e，所以 W-27 一定顯示。W-27 第二句「資料日早於台北今日時，今日頁使用的門檻可能與標籤所示不同」正好涵蓋這種情形，而 W-22 第二行常駐兜底。
