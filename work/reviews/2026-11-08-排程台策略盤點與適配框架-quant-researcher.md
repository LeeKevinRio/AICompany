## 1. 本次結論

1. **策略本體**：這是一套「5 檔台股、等權、每檔分 3 批、最多投入總資產 70%」的機械式紀律規則，由 CEO 自己寫成（原文見 `work/stock-desk-快市排程-企劃.md:271`，CEO 裁決見同檔 `:275-291`）。進場只在週二、四依前一日收盤排定；出場是固定百分比的停損停利，再加上一個大盤月線開關。它的設計目的寫在裁決六：用規則取代恐慌日想全砍、暴漲日想全押的情緒（`企劃.md:282`）。它要做的是紀律，不是預測市場。
2. **證據**：**沒有證據顯示這套規則在歷史上的報酬、回撤或勝率，也沒有跟 Buy & Hold 比過。** `app/backtest/` 從來沒有回測過 playbook（全目錄 grep `playbook` 零筆；策略註冊表只有 ma_cross、rsi_reversal、breakout、five_conditions，`app/backtest/strategies.py:477-480`）。已經做過的回測和事件研究對象都是「五條件」，用的是 demo_synthetic 示範資料；族群動能只有方法論，沒有實測數字。跟排程台有關、而且確實存在的證據只有一種：**規則有照寫的方式被執行**（驗收測試 T1～T9，`tests/test_playbook_acceptance.py`）。這證明程式正確，不證明策略有效。
3. **適配（推論）**：這套規則比較適合「想用事先寫死的規則取代臨場判斷，而且每個交易日收盤後能看一次、隔天開盤 30 分鐘內能下單」的人。它比較不適合三種人：每週只能看一兩次盤的人；目標是長期跟上或贏過大盤的人；想高周轉的人。**CEO 舉的例子「適合每週只能看兩次盤的人」，依程式來看大致相反**：進場雖然只在週二、四，但停損停利每個交易日都可能觸發，而且只有打開頁面時才會評估（見 §2.6-A）。
4. **需要 CEO 回答的問題**：共 6 題（§5）。其中「投資目標是紀律、降回撤，還是贏大盤」和「每週能花多少時間」兩題，最能決定這套策略能不能照現狀用。

## 2. 策略本體（白話版，附程式位置）

### 2.0 一張圖看全貌

```
每個交易日收盤後（前提：有人打開排程台頁面，見 2.6-A）
  ├─ 先看大盤（M1、快市）
  ├─ 再看組合：新倉的未實現損益有沒有跌破 -8%（S3）
  ├─ 逐檔：整檔停損 S2 → 逐批：S1 停損 → P3 過熱減碼 → P1 → P2 → 移動停利
  └─ 如果是週二或週四，而且模式正常：每檔買「下一批」（R1，要先過 R2、R3 的檢查）
       └─ 最後套用鐵律①：買進後現金不能低於 30%，否則縮減股數
隔天開盤（T+1）：照指令執行；停損是市價單，其他是限價單（±2%），超出限價就記 MISSED，不追價
```

### 2.1 鐵律①～⑤

| 鐵律 | 白話 | 程式位置 |
|---|---|---|
| ① 現金 30% 不可破 | 任何買進都不能讓現金低於總資產的 30%。超過就縮減這一批的股數，縮到 0 股就取消，並發警示。這條**只管買進**：賣出不受限，價格下跌也不會強制賣出。 | `app/playbook/engine.py:1020-1083`（`_apply_cash_floor`）；參數 `app/playbook/models.py:85`；字面 `app/playbook/wording.py:208-211, 323-324` |
| ② 指令明確，禁止模糊詞 | 每筆指令只會是「買進／賣出／順延／跳過／無動作」，附股數、規則編號、依據資料日、預定執行日、參考價，不會出現「可考慮」這類詞。 | 指令組裝 `engine.py:83-121`；動作字面 `wording.py:152-158`；措辭原則 `wording.py:7-18` |

### 2.2 進場：R1～R4、分批、TOTAL_DEPLOY

| 規則 | 白話 | 程式位置 |
|---|---|---|
| TOTAL_DEPLOY | 確認規則集時，用當時輸入的資本 × 70% 算出可投入的總額，整季鎖定不變。期中賺到的錢回到現金池，不會放大下一批的金額（裁決一：避免連勝後在過熱期押最大注）。 | `service.py:1987-2035`（`confirm_rules`，`:2031` 的 `capital × deploy_ratio`）；`models.py:86-87` |
| 分批 | 每檔金額 = TOTAL_DEPLOY ÷ 5，每批再 ÷ 3。股數 = floor(每批金額 ÷ 收盤價)，最少 1 股；最後一批吸收零頭。以預設值算，**每批約佔確認時總資產的 4.67%，每檔約 14%**。 | `engine.py:186-215`（`planned_batch_shares`）；`models.py:88-89` |
| R1 排程日進場 | 依據資料日是週二或週四，而且是交易日、模式正常、大盤資料可用時，每檔只買「下一批」，一天最多一批。 | `engine.py:982-1017`；可進場的條件 `:1186`；排程日 `app/data/calendar.py:52, 87-89`；`engine.py:738-750` |
| R2 不追價煞車 | 當天漲幅超過 3%，或 BIAS25（收盤偏離 25 日均線的百分比）超過 +10%，這一批就順延。 | `engine.py:907-980`；`models.py:92-93` |
| R3 順延上限 | 同一批累計順延 3 次就跳過，跳過的批**之後不會再買**。T+1 沒成交（MISSED）累計 3 次也一樣跳過。 | `engine.py:845-905, 919-957`；`models.py:94` |
| R4 凍結／暫停不進場 | 防守、S3 凍結、EMERGENCY 凍結期間，以及 S1 暫停或 S2 黑名單中的標的，都不跑 R 系列。 | `engine.py:1186, 1277-1282`；字面 `wording.py:181, 316` |

### 2.6 依程式看到、會影響策略性質的現況（事實）

- **A. 評估不會自動執行。** `app/scheduler.py` 沒有任何 playbook 的 job（grep `playbook` 為 0 筆）。評估只在 `GET /api/playbook/today` 被呼叫時才跑（`api/playbook.py:581-611`）。沒人打開頁面的那天，停損停利就沒有評估；之後再打開，也只看最新一根收盤，不會回補中間漏掉的觸發。N-190 的回溯清單（`scripts/n177_n190_backtrack_probe.py`）處理的正是這個缺口。
- **B. 每一批一生只買一次，出場後不會回補。** 批次以 `INSERT OR IGNORE` 建立，之後永遠不會重置（`app/playbook/store.py:858-868`、`:1540-1542`）。已出清或已跳過的批次，資金會留在現金裡。另外，`ensure_batches`（建立標的與批次的函式）在 `app/` 裡沒有正式的呼叫點，只出現在 tests 和 scripts。**目前 CEO 是透過什麼方式把 5 檔標的放進排程台，我沒找到，需要 dev-lead 或 product-manager 確認。**
- **C. 高波動清單沒有接線。** `build_market_snapshot` 的 `high_volatility` 預設是 False（`service.py:148-176`），而 `evaluate_today` 呼叫時沒有傳這個參數（`service.py:2185-2193`）。DB 雖然有這個欄位（`store.py:124`），但讀不進引擎，所以 P3 的門檻實際上固定是 +15%。
- **D. 只支援台股。** `PLAYBOOK_MARKET = "TW"`（`service.py:95`），M1 用的是加權指數。
- **E. 價格沒有還原。** playbook 內沒有任何除權息處理（grep `dividend`、`adjust` 為 0 筆）。成本、25 日均線、BIAS25 和停損都用原始日線計算，所以除息缺口會被當成下跌。
- **F. 帳冊不含費用。** 結算時以開盤價記錄成本和現金變動，沒有扣手續費與證交稅（`store.py:1580-1640`）。只要開盤價落在限價帶內，就視為已成交（`engine.py:1354-1364`），實際成交仍以券商回報為準。
- **G. 參數來源。** 所有門檻都來自 CEO 原始規則集（`企劃.md:271`）。我沒找到任何統計推導、最佳化或敏感度分析的紀錄。好處是沒有過擬合；代價是這些門檻也沒有經過驗證。

## 4. 適合與不適合哪一類使用者（全部是【推論】）

推論的依據是 §2 的規則機械性質和 §2.6 的程式現況，沒有用歷史資料驗證。

### 4.1 比較適合

| 類型 | 推論依據 |
|---|---|
| 想用事先寫死的規則取代臨場情緒判斷的人 | 這就是設計目的（裁決六，`企劃.md:282`）。鐵律④讓盤中沒辦法改規則，EMERGENCY_EXIT 是唯一的逃生門，而且有代價：20 個交易日不能買進 |
| 每個交易日收盤後能看一次頁面，隔天開盤 30 分鐘內能下單的人 | 停損停利每個交易日都可能觸發（`engine.py:1257-1275` 不受排程日限制），而評估要打開頁面才會跑（§2.6-A） |
| 能接受集中持有 5 檔台股個股、等權、最多投入 70% 的人 | 參數 `models.py:85-89`；只支援台股（§2.6-D） |
| 重視「下跌時有明確出口」勝過「上漲時抱到最後」的人 | 停損是市價單、無條件執行；停利分 +20%、+35% 兩段了結，剩下的部位用移動停利 |
| 能接受停損後股價反彈、自己卻已出場的人 | S1 賣出後要等站回 25 日均線才恢復買進，而且只會買「下一批」，已經賣掉的那批不會回補（§2.6-B） |

### 4.2 比較不適合

| 類型 | 推論依據 |
|---|---|
| 每週只能看一、兩次盤的人 | 只有進場是週二、四；出場可能發生在任何交易日。沒打開頁面的那天就不評估，之後也不回補（§2.6-A）。這類使用者的停損會延遲或漏掉，§2.5 的損失邊界會失效 |
| 目標是長期跟上或贏過大盤 B&H 的人 | 最多只投入 70%；+20% 和 +35% 時各賣掉原始股數的 1/3；出場或跳過的批次不會回補；名額也不補（§2.6-B）。所以在持續上漲的期間，曝險只會隨時間下降，很可能落後 B&H。這點**沒有回測過** |
| 想高周轉、做短線或當沖的人 | 每檔一生最多買 3 次，而且只在週二、四進場；R2 遇到急漲會順延 |
| 主要交易槓桿 ETF 或高波動股的人 | -10%、-15% 是固定百分比，沒有依波動度調整；高波動清單也沒接線（§2.6-C）。觸發頻率可能明顯高於低波動股 |
| 以高股息存股為主的人 | 價格沒有還原（§2.6-E），一次 5% 的除息就會吃掉 S1 一半的空間 |
| 想在盤中依新資訊自己覆寫指令的人 | 鐵律④禁止；目前也沒有改規則的路由（§2.1）。唯一的出口是「全部出清」 |
| 需要美股的人 | 不支援（§2.6-D） |
