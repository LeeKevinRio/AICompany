## 本次結論

1. **這個衝突在 v1 真的會發生，證明不了不可能，所以不能只靠防禦性斷言收斂。** 重放可以產生證據不足的列。這種列可以缺 `threshold_snapshot`。它能不能作廢，只看 T+h 那根 bar，和預測端完全無關。三個條件都有路徑可以同時成立。照 ADR-0027 現行的「`diag_last_close` 非 null ⇔ `status ≠ resolved`」，這種列會被拒寫，整次重放就做不完。
2. **我具名推薦 (c)：「(a) 加閉集合加有標籤守衛」。**
   - V22-07 明文在重放中照用。
   - 重放結果列的 `diag_last_close` 只允許三種情形，是閉集合。
   - 有標籤而缺項的預測，在算出任何結果欄位之前就讓整次重放不執行。
   - 編號 V25-01，另加固定項 V25-02、V25-03；附錄 C 新列 LG-38。不碰 V24 和 LG-35～37。
3. **擋點表態：**
   - 不擋 D-9。
   - 不以 D_v 為擋點，但必須在 `dirdef-v1.0` 凍結 commit 之前落檔。
   - 擋重放執行閘門 (d)。
4. **另外發現兩個缺口，也擋重放執行：**
   - (1) T 日收盤本身不可用（X1）的重放列，ADR 現行字面寫不出合法的 `start_price_json`。
   - (2) `E-PIT-UNVERIFIED` 在重放中怎麼適用，沒有寫。照字面，每一筆重放預測都會是證據不足。
   - 兩項都不在 V25-01 範圍內，建議另開追蹤項。

## 各部門回報

### quant-researcher

#### 一、重放能不能產生證據不足的列

- 【事實】§4.7 寫明重放只做大盤（事先宣告 L1292）。預測端「有觀察日、沒有 bar：缺值，不插補」，有效日報酬與下限依 `SIGMA_MIN_VALID` 與 §5.2（L1332）。
- 【事實】§6.3 V16-01 的決策日條件 (iv) 是「[S, T] 內的**觀察日數**不少於 N_req」，數的是 O，不是 bar 數（L1627）。O 只看日曆查詢，有觀察日、沒有 bar 的日子照樣是觀察日（L1625–1626）。
- 【事實】V16-04 寫「T 日 bar 收盤本身不可用時，依 §5.2 `E-PRICE-UNUSABLE` 處理」（L1627、L1638）。這是條文直接點名的一條證據不足路徑。
- 【推論】大盤可以出現的缺項代碼：
  - `E-PRICE-UNUSABLE`；
  - `E-VOL-SHORT`：σ 窗的 61 個觀察日中，只要有 3 個以上分散的日子沒有可用收盤，有效日報酬就可能少於 55；
  - `E-BARS-SHORT`：(iv) 數觀察日，bar 可能比較少；
  - `E-VOL-DEGENERATE`；
  - `E-PIT-UNVERIFIED`：見第六節第 2 點。
- 【推論】大盤不會出現的缺項代碼：
  - `E-ADJ-*`：大盤用價格指數；
  - `E-CORP-ACTION`：依 V10-01 不適用指數；
  - `E-INDEX-MISSING`、`E-SECTOR-COVERAGE`、`E-SCOPE-*`：適用對象不是大盤；
  - `E-BARS-STALE`：(ii) 要求 T 日有 bar，預測端只用 T 以前的 bar。
- 【推論，前提未查證】如果 S 早於 yfinance `^TWII` 歷史的起點，前段沒有 bar（§4.7 L1356 已點出這種可能）。那麼 yfinance 起點之後的頭幾個 T，(iv) 由觀察日滿足、σ 窗內卻幾乎沒有 bar，必然是 `E-VOL-SHORT` 加 `E-BARS-SHORT`。
- 結論：可以，而且條文本身就點名了一條路徑。

#### 二、重放能不能出現 `threshold_snapshot` 缺項

- 【事實】缺項只由 `threshold_inputs()` 判定：`K_h`、`EPS`、`sigma_d` 任一項沒有，或 `sigma_d` 不是正的有限值（ADR L295）。證據不足而缺項的列，「其餘鍵照預測端實際算得的值存，算不出的記 null」（ADR L299）。
- 【事實】`forecast_replay`「結構與 `forecast_record` 相同」（ADR L540）。但 `band_def` 的寫入驗證與「適用範圍與缺項」有沒有適用到 `forecast_replay`，沒有寫明。
- 【推論】`K_h`、`EPS` 是常數，只會因程式缺陷而缺。`sigma_d` 會缺的情形：
  - 前述「頭幾個 T」：0 個日報酬，算不出 σ，一定缺項；
  - 其他 `E-VOL-SHORT` 或 `E-BARS-SHORT` 的列：會不會缺，取決於 `volatility.py` 在有效數不足時回傳值、NaN 還是 None。TA 也列為【未查證】（TA 檔 L217）。
- 結論：可以出現，條文排除不了，實際頻率【未查證】。

#### 三、衝突可不可達，以及證明為什麼走不通

- 衝突列要同時符合：(A) 證據不足、(B) 缺項、(C) 作廢。
- (C) 的條件：
  - 【事實】重放的作廢只有兩種：T+h 是有觀察日、沒有 bar 的日子（`missing_bar_after_wait`，L1641），或 P(T+h) 的收盤本身不可用（`index_bar_confirmed_erroneous`，L1637）；
  - 【事實】兩者都只讀 T+h 的 bar，判定不讀 label（L1585、L1630）。
- 證明「不可能」需要 ¬(A∧B∧C)，條文裡找不到：
  - (iv) 保證的是觀察日數，不保證 55 個有效日報酬；
  - (v) 只保證 T+h ≤ E，不保證 T+h 有 bar。
- 【推論】資料上，(A∧B) 和 (C) 都來自快照缺 bar，兩者是正相關。
- 所以「v1 不可能發生」的證明走不通，第 3 項後半（只用防禦性斷言收斂）不適用。
- 【事實】時序：`forecast_replay_outcome` 是 TA 2026-10-18 寫的（ADR L632），V22-07 是 2026-10-19 v0.22 才加的。這條 ⇔ 是先後順序造成的，不是刻意排除。TA 引的 L641 在現行檔中是 L649。

#### 四、候選規則比較

**(a) V22-07 明文適用重放，ADR 驗證依 label 與完整性分開適用**
- 方向：相對事先宣告是「不變（消除歧義）」。相對 ADR 字面有放寬面：原本被拒寫的列，改為記 null 寫入。
- 可操縱性：
  - 走 null 的條件只來自預測端存下的欄位，在知道結果之前就固定了；
  - null 的欄位不進 n、命中率、W 或任何判定；
  - 重放不影響驗證狀態（§4.7）；
  - 重放的 W「定義同 §4.2」（L1644），證據不足而後作廢的列依 V23-01 照樣放回；
  - 所以沒有可以操作的槓桿。
- 與「照用」的一致性：一致。
  - §4.7 對 §6.3 的寫法是先照用，再列出重放的差異。現行字句是「X1、X4 照用；X2 依……；X3 不適用」（L1336）；「X1、X2、X4 照用」是 v0.15 被取代的原文，模式相同。
  - V22-07 不在差異清單裡。
  - 前瞻在完全相同的情形下照常寫入、記 null（ADR FL-72 (c)，L2599）。
- 缺點：沒有寫有標籤而缺項時重放怎麼辦，null 的情形也不是閉集合。

**(b) 寫入端擋下「證據不足而缺項」的重放列**
- 方向：表面上是收緊，實際上是放寬。
  - 拒寫這類預測，涵蓋率的分母就少了，抵觸 §5.1 第 4 點，也抵觸 §4.7 閘門「不得剔除個別日期」；
  - 只在作廢時才拒寫，作廢列就從 W 消失，W 變寬鬆；
  - 整次中止，重放可能永遠跑不了。
- 可操縱性：高。
  - 只在作廢時拒寫，等於依結算端的資料挑樣本；
  - 執行中才中止，等於多了一個「中止再重跑」的槓桿；
  - 如果發生在部分結果算出之後，修正就落入「看過結果後修改」，m 加 1，也不能再稱樣本外。
- 與「照用」的一致性：不一致。在前瞻已經測試過的情形上，重放走反方向。
- 不採用。

**(c) (a) 加閉集合加有標籤守衛（推薦）**
- 內容：
  - V22-07 照用；
  - `diag_last_close` 限三種情形：(i) `resolved` 記 null；(ii) 作廢而門檻完整，非 null；(iii) 作廢、證據不足、缺項，記 null。新增其他 null 情形視同改定義；
  - 有標籤而缺項時，在算出任何結果欄位之前讓整次重放不執行。這一步只讀預測端，所以中止時沒有任何結果被算出，修正程式後依同一登記執行，不消耗「只能重放一次」；
  - T 日收盤本身不可用的列另案處理。
- 方向：補定義（兩面），內容見下文 V25-01 列。
- 可操縱性：同 (a)，另外把 null 路徑封口。
- 與「照用」的一致性：同 (a)。
- 也考慮過但不採用的兩個做法：
  - 證據不足時照樣用不到 55 個日報酬算 σ_d：這是 §5.1 第 3 點禁止的替代估法；
  - 驗證只留「`resolved` ⇒ null」：太寬，程式缺陷造成的 null 會被默默吞掉。

#### 八、另外發現（不在 N-53 範圍內，建議 coordinator 另開追蹤項）

1. **T 日收盤本身不可用的重放列**（擋重放 (d)）：
   - 【事實】V16-04 寫「在 T：依 §5.2 `E-PRICE-UNUSABLE`，不產生作廢列」（L1638）。
   - 【事實】前瞻對 P(T) 收盤確認有誤、取不到正確值的情形記 `index_bar_confirmed_erroneous`（ADR L1211）。
   - 【推論】ADR 寫入驗證規定：`close_source = snapshot` 時該 bar 不能有 `close_erroneous`，`independent_source` 必須有 `correct_close_obtained`，只有 T+h 有 `bar_missing` 的寫法（ADR L637、L645–646）。所以這種 P(T) 寫不出合法的 `start_price_json`，重放會被拒寫而做不完。
   - 即使改成可以寫，`realized_log_return` 和 `diag_last_close` 都算不出來。另外，前瞻把這種列記作廢、放回 W，重放卻記 `resolved`，兩邊不一致。
   - 建議由 quant 和 TA 一起登記。
2. **`E-PIT-UNVERIFIED` 在重放中的適用**（擋重放 (d)）：
   - 【事實】`forecast_replay` 與 `forecast_record` 結構相同（ADR L540）；PIT 證明的規則是「超過 cutoff 就輸出 insufficient」（ADR L742）。
   - 【事實】重放快照在 F 之後才取得（§4.7 L1327）。
   - 【事實】兩份文件都沒有寫重放怎麼適用這條（我用 grep 確認過）。
   - 【推論】照字面，每一筆重放預測都是證據不足，n 為 0。
   - 這是規則登記的事，要具名提出、送風控，不是程式自行豁免。
3. **證據不足時存不存 σ_d**（低嚴重度）：ADR L299「照預測端實際算得的值存」讓實作有一個自由度：`E-VOL-SHORT` 的列存不存 σ_d，會改變缺項出現的次數。它只影響證據不足列的診斷欄位，不影響任何判定。建議 dev-lead 查證 `volatility.py` 時（TA 的未查證項）一併釘死。
