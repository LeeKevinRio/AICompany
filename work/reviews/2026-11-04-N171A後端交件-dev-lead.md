### 給 frontend-engineer 的 API 說明（`GET /api/playbook/today`）
- **`pending_exit_block: PendingExitBlock | null`**（optional）
  - 只在 `today.isSuccess` 且非 null 時渲染；null 或缺鍵時畫面上什麼都不出現
- **區塊**：`{ title, lead_template, sections[], closing_notes[] }`
  - 渲染順序：`title` → `lead_template` → 各 section 依陣列順序 → `closing_notes` 依陣列順序
- **section**：`{ kind: "covering"|"stale"|"unclassified", label: string|null, lead, rows[] }`
  - 渲染順序：`label`（非 null 才渲染）→ `lead` → `rows`
- **row**：`{ symbol, batch_no, shares, coverage, batch_has_covering: bool|null, execution_dates: string[], text, notes: string[], entry_before_exit_note: string|null }`
  - 同列順序固定：`text` → `notes` 依陣列順序 → `entry_before_exit_note`（非 null 才渲染；N-168 之前恆為 null）
  - 後端已排好、已組好文字；前端不重排、不篩選、不自撰文字
- **`{read_at}`**
  - 只在 `lead_template` 裡出現一次
  - 前端用同一份回應的 `formatDateTime(data.as_of)` 代入，恰好一次；後端不代入
- **`pending_exit_directives`** 是原始資料，三類的列都有，不得用來渲染任何文字（C22、T27）
- **型別**：`types.ts` 已有 `PlaybookPendingExitBlock`／`PlaybookPendingExitSection`／`PlaybookPendingExitRow`／`PlaybookPendingExitCoverage`
- **NB-6**：鏡射 `EXIT_FAILURE_WORDING.body[1]` 已在 commit 5 換成第二版，前端不需再改

   - 第一版剛好就是第二版的第一句，照字面做子字串 grep 不可能為 0。
