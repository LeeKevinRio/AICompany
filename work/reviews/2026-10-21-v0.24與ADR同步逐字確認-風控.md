## 二、各部門回報（risk-compliance-officer）

### 審查結論
APPROVE WITH CONDITIONS。

### 逐條意見

**A. (a) V24-01～V24-03**

- **V24-01**
  - quant 的論證成立：W 是對以 n 計的第 0 相位主樣本做最壞情境。把其他相位的作廢列放回這個樣本，算出來的不是任何可實現樣本的最壞情境，連續作廢也會被重複計約 h 次【推論，與 quant 同】。
  - 但相對字面讀法（§4.5 第 1 點不分相位），W 放回的列較少，是放寬面。這符合我 2026-10-19 (h) 的規則，所以要明確同意。
  - 殘餘風險，以揭露為條件接受：
    - 第 0 相位格點可以事先算出。不過其他相位的預測本來就不在 n 樣本裡，作廢判定也不讀 label，所以沒有挑樣本的管道。
    - 保護機制是兩件事：其他相位全部列出（`phase_disclosure`），以及格點改變時依 `grid_changed` 處理。
  - **required（RQ-5）**：Q-2 第 1 點寫「第 0 相位格點在 D_v 與 h 確定時就已固定」。X2 確認或未觀察平日登記會讓觀察日集合改變、格點跟著移動，所以這句要補上 `grid_changed` 的限定。不補的話，這句不全然屬實。
- **V24-02**
  - N-29 (b) (i) 的字面是「不計入 n，也不計入命中率、W 與 §4.3 的任何判定」，(e)(f) 都包含在內。
  - 待重算集合只依序號與作業紀錄機械決定，不讀 label 或結果。
  - checkpoint 列上，一般的待重算列會讓閘門等待；沒有期限的那一類會讓正面結果不認列。所以「作廢前不在分子內」這一面，只可能減弱負面結果，不會幫助正面結果。知悉即可。
- **V24-03**
  - 這種日子在 W 裡記成一整日的「模型 0、基準 1」，(c) 的每日差值是 −1。
  - 我推算過：在可能通過的區間（平均差值 > 0），加入這種日子會讓平均下降、標準誤上升，下緣只會變低【推論，未窮舉證明】。
  - (a) 仍以 n 判定，W 的樣本日數不能撐大樣本數。收緊成立。
- **F-1 屬實**：V24-03 的字面寫死「第 0 相位決策日」。改採不分相位時，每個有作廢對象、但不在 n 樣本內的決策日都會成為 W 的樣本日，W 的樣本日數最多約增為 h 倍【推論】，效果明顯變嚴。所以 Q-8 (ii)「V24-02、V24-03 不受影響」不屬實，照 RQ-7、RQ-8 改。V24-02 的實質確實不綁相位，只是和 V24-01 合寫的〔v0.24 註〕要刪去相位字樣。

**B. (b) LM-87**
- 判定甲：屬實。LM-87 原句是「連續兩個檢查點（n＝{X0}、n＝{X}）……其中作廢比例超過 5% 的檢查點，依最不利情境（作廢的預測全數視為不符）計算」，見 ADR L2067。
  - 「作廢比例」和「作廢的預測」都附在「檢查點（n＝{X}）」之下。V24-01 讓兩者用同一個範圍：第 0 相位格點上、不在待重算集合。
  - 這個範圍內的作廢預測，依 V23-01 不論 label 全數放回並記為不符。
  - 其他相位的作廢預測不在這個檢查點的樣本內，就像其他相位已結算的預測也不在 n 內一樣。
- 事先宣告 L1074 寫「LM-87……在本點下屬實」，V24-01 之後要有對應的一句，補在 RQ-5。
- suggested（交 creative-lead／frontend-engineer，不擋）：日後畫面若在 LM-87 旁邊呈現作廢筆數，要標明它是以哪一組樣本計的，避免使用者拿全部相位的作廢數去對照 5%。

**C. (c) 發現 (1)～(3)**
- **(1)**
  - 【事實】ADR L1369 的 U 和 L1366 的 `unbounded_pending` 都不分相位，和事先宣告 §4.5 第 2、4 點一致。
  - TA 指出 U 不分相位另有保護作用：checkpoint 列只寫一次，其他相位的揭露必須等其他相位終局才完整。我同意。
  - 照現行字面，不擋 D_v。改成只計第 0 相位是放寬，須 quant 具名提出並經 CEO 明確同意，而且只能在 D_v 之前；D_v 之後照現行字面。
- **(2)**
  - §6.3 N-29 (b) (i)（V17-02，已經風控確認）寫「待重算的預測**比照等待中的預測**，不計入 n，也不計入命中率、W 與 §4.3 的任何判定」。這句的前提是等待中的預測不計入 (e)。所以不計入是字面讀法，不是放寬。
  - 這樣涵蓋率也和命中率用同一組已終局的列，「優於基準」所依據的樣本和它的涵蓋率說的是同一群預測。
  - 另一面（照實並陳）：最近 h 個觀察日左右的證據不足，要等結算後才進涵蓋率，降級可能晚幾天，恢復也一樣晚【推論】。
  - daily 列從 D_v 起每天寫一次，事後不補寫，所以要在 D_v 之前明文登記，並且擋 daily 列 (e) 的實作（TA 2-② 已經這樣寫）。
- **(3)**
  - 涵蓋率定義是「有標籤的筆數 ÷（有標籤＋證據不足）」，沒有 status 條件；「有標籤」依 V9-06 指預測端 label。
  - 字面讀法是計入作廢列。TA 的對偶論證成立：涵蓋率只讀 label、不讀 status；作廢率只讀 status、不讀 label（V23-01）。
  - 改成不計入的話，涵蓋率會隨結算結果變動。若證據不足而後作廢的列比較多，排除它們會抬高涵蓋率，是放寬面。
  - 本體目前沒有明文，要和 (2) 一起在 D_v 之前登記。測試期望值已經依字面讀法寫好，所以不擋 checkpoint 列 (e) 的實作。(k) 格要加。

### 給 CEO 的句子

**決策包 #47（V24-01，需要您明確同意）**
> quant 登記：判斷模型是否「優於基準」時，作廢比例、涵蓋率和「最不利情境」這三項，只用正式樣本那一批日子的預測計算。正式樣本日是從起算日起，每 h 個交易日固定取一天（3 日判斷每 3 天、5 日判斷每 5 天）。這些日子在看到任何資料之前就已決定，事後不能挑。其他日子的作廢照樣逐日算出、全部揭露，但不進判定。
>
> 這比「所有日子的作廢都放進最不利情境」寬：放進去的作廢大約只剩三分之一或五分之一，模型在最不利情境下比較不容易被判為不如基準，所以需要您明確同意。另一面，樣本變小以後，作廢比例和涵蓋率的起伏會變大，可能偏高，也可能偏低。
>
> 您若不同意，就改成所有日子都算，但「當天沒有一筆可以判定、只有作廢」那一條規則也必須一起改寫。那時每個非正式樣本日只要有作廢，都會在最不利情境裡記成一整天「模型全錯、基準全對」，最不利情境的天數最多會變成 3 倍或 5 倍，結果會比現在嚴很多，整批要重寫、再送風控。
>
> 不論同意與否，都要在開始累積正式資料之前定案，之後不能改。

**V24-02（知悉）**
> 還在重算中的預測（例如結算所用的日子事後被確認不是交易日、要重新結算的），在重算完成之前，不算進作廢比例、涵蓋率和最不利情境；重算完或到期作廢之後再照常計入。這是照既有規則的字面，不是放寬。代價是：之後才會作廢的這類預測，在作廢之前不會拉高每日的作廢比例；正式檢查點則會等它們有結果才判定。

**V24-03（知悉）**
> 同一天有多檔預測、但當天沒有一檔可以判定、只有作廢時，這一天在最不利情境裡仍算一天，記成「模型全錯、基準全對」，不會因為當天其他預測證據不足就被拿掉。這是往保守方向補定義；代價是當天只有一筆作廢時，這一整天就由那一筆決定。

**預告（下一版登記時才需要您知悉，現在不需操作）**
> 每日涵蓋率只算已經有結果的預測（照既有規則的字面），所以近幾天的證據不足要等結算後才反映，降級可能晚幾天，恢復也一樣晚。作廢的預測照它當初有沒有下判斷計入涵蓋率，不看結算結果，避免涵蓋率隨結算結果變動。
