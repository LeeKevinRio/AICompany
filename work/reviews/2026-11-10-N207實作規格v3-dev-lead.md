```python
def effective_high_volatility(*, base: int, history: Sequence[HighVolChange], on: date) -> int: ...
def target_high_volatility(*, base: int, history: Sequence[HighVolChange]) -> int: ...
```

  - E(on)：`history` 中 `changed_on < on` 的列裡，取 **id 最大者**的 value；沒有就取 base。
  - T：`history` 有列時取 id 最大者的 value；沒有就取 base。
  - 兩者都只依 id 排序，不依 `changed_on` 排序，也不需要日曆。
  - 模組位置，以及 `plan_change` 處理高波動操作時要用到 T，與「roster.py 不 import store」之間的衝突，見待 TA 第 2 項。
- **`portfolio_frozen` 的不變式**（〔v2補遺-6〕第 1～5 點）：
  - `frozen` 為真，等價於兩個值中有一個不為 None 而且 ≥ `today_tpe`；也等價於 `until is not None`；這時 `until` 等於兩個非 None 值的最大值。
  - `today_tpe` 在鎖內取自唯一一次時鐘讀取（D4 第 3 點 (b)），API 預檢則取自 service 注入的時鐘；兩者與 D8 第 6 點同一個來源。
  - `emergency_until`、`freeze_until` 在 store 內用與 `portfolio_state()` 相同的 parse helper 解析；解析失敗就 raise，依 C-11 ROLLBACK，零寫入。
  - `plan_change`：首次設定、重新加入、開新輪、季度提交在 `frozen.frozen` 為真時回 `RosterRefusal("portfolio_frozen", until=frozen.until)`；停止新進場與高波動標記不看 `frozen`；`plan_change` 不得直接讀 `emergency_until`、`freeze_until`。
  - 名單路徑（`roster.py`，以及名單的 store、service、API 方法與名單前端）不讀也不回傳凍結種類；名單 API 回應的 schema 不含 `mode_reason`。
- `RosterFacts` 只含不隨時間變動的事實（〔原〕）：
  - 範圍內各檔的 `entry_stopped`；
  - 高波動事實：〔依 D7 修訂（待風控確認／CEO 拆單裁示）〕v2 的「高波動三欄」改為基準值 B 加上該檔在歷程表的全部列（依 id）（〔D7修〕2-A 第 3 點 (a)；2-B D4 第 3 點 (a)）；
  - `(batch_no, batch_round, status)` 的有序清單；
  - `n_targets`、`batches_per_target`；
  - 啟用檔數。
- 範圍：首次設定與季度提交是整份名單；其他操作是該檔加上全域計數（〔原〕）。
- `symbol_shape_ok` 的規則取自 `work/reviews/2026-11-10-N207台股代號形狀規則-data-engineer.md`：fullmatch `[1-9][0-9]{3}[A-JL-Z]?|00[0-9]{2,4}[A-JL-Z]?|91[0-9]{4}`，不 strip、不轉大寫、不剝後綴；`verified=False`（PRD FR-5、AC-04、AC-04b）。
- **`symbol_k_suffix`**（〔v2補遺-7〕第 1 點；補擬四句風控檔 RC-50）：
  - 本體恰好是 `return symbol.endswith("K")`，判定最後一個字元是否為 ASCII 大寫 `K`（U+004B）。
  - 本體不得有任何 strip、upper、lower、casefold、replace、`unicodedata`、`re` 呼叫，以 AST 檢查；判定前不做任何正規化。
  - data-engineer 的 regex 本來就讓所有 K 結尾字串不符形狀。K 檢查排在前面，形狀分支就不會對 K 結尾的代號觸發（AC-91）。`symbol_shape_ok` 的函式層反例（N14、N15）維持不變。

## 待 TA（共 13 項；本檔不裁決）

1. **高波動解析函式的命名與回傳型別**：
   - 〔v2修一-4〕N207-C21 寫 `high_volatility_marked(raw) -> bool`，本體恰好是 `return type(raw) is int and raw == 1`；〔D7補〕2-F 寫 `parse_high_volatility_flag(raw) -> int`，回 1 或 0。兩者指同一個函式（coordinator 確認）。
   - 依 coordinator 指示擇一：v3 用 `parse_high_volatility_flag`。理由是〔D7補〕較晚出，範圍涵蓋 B 與歷程列，而且和 E、T 一樣回 int。
   - 名稱一換，回傳型別與 C21 的「本體恰好是…」就無法同時成立：bool 版的本體就是 C21 那一行；int 版需要條件式。另外，`build_market_snapshot(high_volatility=…)` 收 bool，E 回 int，轉換寫在哪裡、怎麼寫，都沒有定（C21 對 `bool(` 的禁止只限函式本體）。
   - 請 TA 定：名稱（確認或改回）、回傳型別、函式本體的 AST 規則，以及 int 轉 bool 的位置。
2. **E、T 的模組位置與 roster.py 的 import 限制**：〔D7修〕2-A 第 2 點把 `effective_high_volatility`、`target_high_volatility` 放在 `store.py`；v2 §2 把 `effective_high_volatility` 列在 `roster.py`，而 `roster.py` 不得 import store。高波動標記操作的冪等判定（新值等於 T）與 `changed_on` 取值（2-A 第 3 點 (c)(d)），若由 `plan_change` 負責，roster.py 就需要 T，卻不能 import store。請 TA 定：E、T 放在 store、roster 或 models；高波動操作的計畫由 `plan_change` 或 store 鎖內負責。
3. **預覽摘要含 `changed_on`，與 N207-C11 衝突**：〔D7修〕2-A 第 3 點規定高波動標記操作的摘要含「預覽時算出的 `changed_on`」，跨台北日期就拒絕；N207-C11 規定摘要只由 `roster_digest(op, facts)` 產生、不含時間戳記與窗口狀態，而 `RosterFacts` 只含不隨時間變動的事實。`changed_on` 是由時鐘導出的。請 TA 定：C11 對高波動操作加例外；或改以別的方式在鎖內比對 `changed_on`，例如由 `RosterOp` 帶入預覽日期。
4. **`SymbolState` 在 D7 修訂下的欄位**：〔D7補〕2-G 只說 v2 :52 的欄位「改依 D7 修訂版第 2 點」，但〔D7修〕2-A 沒有列出 `SymbolState` 的欄位。名單頁標籤需要 T、E(today_tpe) 與最新一列的 `changed_on`（W-25e、W-25f 的 M/D），engine 需要 E(data_date)。`symbol_states(on)` 一次只算一個 `on`。請 TA 列出 `SymbolState`（或名單專用型別）的欄位與型別，並說明名單頁是否另外呼叫 `symbol_states(today_tpe)`。
