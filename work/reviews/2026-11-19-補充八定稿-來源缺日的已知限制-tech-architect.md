1. **讀法**
   - (a) `dropped_rows_json` 只記「`app.services.index` 有回傳、但沒有進快照」的列，原因只有 `not_final`（補充二第 2 點 (b)）。adapter 或快取層沒有回傳的列，不屬於它；這些列不在 `dropped_rows_json` 裡，不構成違反。
   - (b) D-5 第 1 點的「該筆計算讀過的每一根 bar」，以取數函式的回傳值為準。來源缺列時，快照少了這一天，依本點仍是完整的快照，不是 F-3。
   - (c) 核心按位置計算，lag k 是「快照中第 k 根 bar」，不讀交易日曆（v0.32 附錄 B.1 §2.1 L2780-2781；V32-03 L1113）。缺日時特徵跨過缺口，屬已登記的定義，不是程式偏離宣告。
   - (d) 本 ADR 56、301 行已接受的「缺日原因無法補記」，涵蓋兩件事：來源回 null 與來源沒有該列，兩者無法區分；被丟列的值，帳內也沒有。
   - (e) 開盤值不進入任何計算，核心只讀收盤價。開盤值為 0 或其他異常值時，照原樣保存在快照與 `content_sha256` 中，與 D-5 一致。開盤值的品質規則，由第二段（紙上對沖）的事先宣告與其 ADR 處理。

2. **已知盲點（知悉，核心期間不處理）**。影響範圍依 `work/reviews/2026-11-19-缺日機制分析-quant.md`：
   - (a) **一次缺日的影響期**：之後約 120 筆紀錄的特徵受影響，B2 約 314 筆（L41）。不會觸發任何缺項代碼（L40）。
   - (b) **缺的是 T 本身**（L42-46）：T−1 會被當成最新一天。
     - T−1 已有紀錄時，記 `no_new_session`；沒有紀錄時，補寫一筆 `late = 1` 的 T−1 紀錄。不會記 `inputs_not_ready`。
     - 實質上等於 D-3 第 2 點禁止的「改用前一天」，只是沒人察覺。`late = 1` 不進入任何統計，所以結果是失去一個格點，依 v0.32 §4.1 L1275 不得補位。
   - (c) **F-2 分子偏低**：補充五第 1 點 (d) 以快照中定案 session 的聯集計數。來源永久缺席的 session 不會出現在任何快照，所以永遠不進分子。性質與補充五第 1 點 (h) 相同。
   - (d) **`Phase0Grid` 錯相**：某一天若在每一份快照中都缺，之後的格點全部錯開一個相位（L47，quant 標為推論）。
   - (e) **暫定對照的 `session_gap`**：它只比對「各快照聯集」，某一天若在每一份快照中都缺，它測不到，T+h 會悄悄變成第 h+1 個交易日（L52-56）。暫定對照的結果不寫入任何表（D-5 第 5 點），帳不受影響。

3. **禁止事項**（須修訂本 ADR 才能解除）
   - (a) recorder、`app/outlook/**`、`app/forecast/**` 不得以「快照日期不連續」或開盤值作為分支、拒收、改變 outcome 或改變 `label`、`band_def`、`baseline_predictions_json`、`missing_json` 的條件。
   - (b) 以下都不得新增：
     - `DropReason` 的值；
     - `MISSING_CODES` 的成員（補充五附記；v0.32 §5.2「新增代碼視同改定義」）；
     - `forecast_run_end.outcome` 的值；
     - 任何表或欄位（K-5、K-12）。
   - (c) `app/` 內不得新增交易日曆或休市日資料。`app/data/session_calendar.py` 只實作 `is_final`（D-1 第 3 點）。
   - (d) 接線 PR 對缺日只加 `tests/` 內的特性測試（S-18a 第 2 項）。adapter 快取路徑略過 null 列時加一行 WARNING log，可以另開 PR，不併入接線 PR：
     - log 只含 symbol、`session_date` 與 null 欄名，不含價格與標籤；
     - 不改變回傳的 bars。
   - (e) 不得以「快照只要含缺口就拒寫」作為修補方向：一次缺日會讓之後約 120～314 筆紀錄寫不出來（quant 第一份報告 L113）。

4. **驗證層 ADR 的義務**（依 D-8 第 5 點起草時必須納入）
