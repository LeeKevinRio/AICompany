## 一、本次結論

**前提說明**
- 本次只提案。我沒有改任何檔案、沒有 commit、沒有讀 `.env` 或 `*.db`、沒有看任何資料或結果。
- 修訂列編號改用 **v0.14（V14-01～V14-03）**。原因是 V13-06～V13-08 已由風控 v0.13 審查（commit `aa68fd3`）的 R-12、R-13、R-16 占用，而且風控把 O-1、N-14、V10-08 列為「另案，各自具名送風控」。
- 文中「v0.12 L」行號一律指已 commit 的 v0.12 `871e602`。工作樹裡目前有別人正在套用、尚未 commit 的 v0.13，行號大約往後移 3～4 行。我沒有動它。
- **新的限制條件**：風控 v0.13 審查的 R-4 已經替 O-1 定了 (a)～(c) 三個定案條件，R-11 也定了 N-4 的 `settle_source_run_max`（用序號比較的甲法）。下面三案都以這些條件為準。

**1. N-13（O-1）：推薦 (a)，方向是放寬，不能算不變。**
- 內容：等待期間才補到的 bar 可以用來結算。PIT 改用「判定視圖」來守：每次評估讀一次市場 DB 的序號上限 R，存成 `settle_source_run_max`，結算只讀 `run_id ≤ R` 的列。
- 相對於 v0.12 L1159 與 ADR-0027 D-9.1 第 2 點、D-9.2 的字面，這是**實質放寬**：結算可以讀 `recorded_at` 晚於 cutoff(T+h) 的資料。相對於 L1188、L1233，則是讓已經宣告的路徑走得到。
- 理由（都是結構理由）：
  - 結算端晚到的資料流不進預測端。特徵、label、σ_d(T) 都固定在 cutoff(T)。
  - 結算端本來就在用 cutoff(T+h) 之後的資料：§6.4 更正、L1233 第五值的等待、X2 順延都是。
  - (b) 會讓作廢與否取決於擷取時點，而不是對象本身的狀態。
- 這個做法滿足風控 R-4 的 (a)～(c)，也同時補上兩個連帶缺口（兩案都需要）：
  - **O-1b**：D-7 在 T+h 當晚 22:10 結算，早於 cutoff(T+h)＝23:59:59。事後以 cutoff(T+h) 重算，可能讀到評估當下還不存在的資料，結果無法重現。
  - **O-1c**：大盤 T+h 資料晚於 cutoff(T+h) 才寫入時，觸發條件永遠不成立，這筆預測永遠不結算、也不作廢。
- **量的照實揭露**：data-engineer 查證，現行管線不回填，加上 `_already_ok_today` 的冪等略過，個股與族群成員幾乎不會有隔日才補到的 bar。所以兩案對個股、族群的 n 與作廢率差異預期接近 0。差異主要出現在大盤 `^TWII` T+h bar 晚擷取的情形（例如主機停擺後補跑），以及將來新增的回填路徑。

**2. N-10（V10-08）：推薦「該成員比照停牌排除」。**
- 方向標**補定義（兩面）**。
  - 作廢面：ADR-0027 D-9.3（A-32）的字面最接近「整筆作廢」。相對這個讀法，本案是**實質放寬**。
  - W 面：收緊。被排除的成員用最後可得收盤放回診斷籃子；主標籤與診斷標籤不一致的列，在 W 中按「模型未命中、各基準命中」計。

**3. N-14：推薦擴及跨缺 bar 的報酬，門檻按跨越的觀察日數 g 逐日複利換算。**
- 上界 (1+c)^g − 1，下界 (1−c)^g − 1，c ＝ `SPLIT_SUSPECT_ABS_RETURN`。
- g＝1 時與現行規則逐位相同，也不新增常數。
- 方向是**收緊**。
- 不採固定 11%。原因：缺 bar 有可能是資料缺漏、該股其實有交易。固定門檻會把連續兩根跌停（約 −19%）判成分割，而整日缺 bar 時會同時作用在全部個股上。被排除的就會集中在大幅波動期，這和 V10-01 對指數的顧慮相同。
- 依據只有結構理由，沒有參考任何結果。

## 二、逐項提案

### 提案 1：N-13（O-1）

**矛盾在哪裡（條文）**
- ADR-0027 D-9.1 第 2 點（L596）：「該日資料的 `recorded_at ≤ cutoff(T+h)`」。D-9.2（L597）：個股用 `as_of(T+h)` 的 PIT 視圖。
- D-9.3（L600）：「T+h 無 bar，再等 5 個觀察日仍無」。事先宣告 v0.12 L1188：「期間內補到當日資料就結算」。L1233（第五值）：「期間取得正確值就照常結算」。
- 事先宣告 L1159 的觸發條件也寫了 cutoff(T+h)。L471 定義 cutoff(T)＝T 日 23:59:59。
- 定案下限 A-78 要求 `recorded_at ≥ final_after`（TW 是 15:00，ADR-0028 VS-4，`freshness.py:110`）。所以一根 bar 要同時「已定案」又「早於 cutoff」，只能在當天 15:00～23:59:59 之間寫入。
- 風控 R-4 的定案條件：
  - (a) 等待期滿時，每一筆都恰為 `resolved` 或作廢之一；
  - (b) 等待期間寫入、卻不能用的 bar，必須落入結算，或落入 N-4 的晚到判準；
  - (c) 「T+h 無 bar」指「沒有可用於結算的 bar」，包含只有定案前 run 的情形（N-16）。

**選項**

| 選項 | 內容 | 方向 |
|---|---|---|
| **(a) 推薦** | 等最多 5 個觀察日。每次評估以判定視圖 `run_id ≤ R` 讀資料；期間任一次看得到可用的 T+h 資料就結算；D_5 結束後的第一次評估仍沒有，就作廢。R 存成 `settle_source_run_max`，之後的 run 依 N-4 只進診斷 | **放寬**（相對 L1159、D-9.1 第 2 點、D-9.2） |
| (b) | 刪除「期間補到就結算」。T+h 已觀察到之後的第一次評估，視圖裡（另加 `recorded_at ≤ cutoff(T+h)`）沒有可用的 T+h 資料，就一律作廢、不等待。`settle_source_run_max` 取視圖內最大的 run_id，之後的 run 一律算 N-4 晚到 | **收緊**（相對 L1188、L1233；相對 D-9.1 字面不變） |
| (c) 不採 | 全部結算一律延到 cutoff(D_5) 才做 | 每筆結果晚 5 個觀察日才出來。§6.4 更正最後本來就會讓鏈尾收斂到同一份資料，多等換不到統計上的好處 |
| (d) 不採 | 窗內 T+1～T+h−1 用 cutoff(T+h)，只有 T+h 那根 bar 可以晚到 | 一筆結算混用兩個視圖，T+h−1→T+h 的分割比對跨在兩個視圖之間，稽核更複雜 |

**為什麼推薦 (a)（結構理由）**
1. **預測端沒有前視風險。** 晚到的資料只進結算端，特徵、label、σ_d(T)、`threshold_snapshot` 都固定在 cutoff(T)（§1.4）。結算端的 PIT 要防的是兩件事：無法重現，以及依結果挑選資料。存下序號上限、全量機械掃描、等待與否不讀 label，就能同時守住。
2. **系統本來就在結算端使用 cutoff(T+h) 之後的資料：**
   - §6.4 的來源更正；
   - L1233 第五值的等待；
   - X2 確認後的順延；
   - D-8.1 (i) 沒有 `recorded_at` 上限。
   在 (b) 之下，「T+h bar 晚一天才首次寫入」要作廢、只進診斷；「準時寫入、隔天才被更正」卻可以結算。兩者對 P(T+h) 的資訊量一樣，差別待遇沒有統計依據。
3. **(b) 會讓作廢由營運事件決定。** 一個擷取延遲日，會讓該日為 T+h 的所有 claim 一起作廢。不重疊主樣本每 h 日一個格點，延遲日就直接失去格點。同時作廢率會因此逼近 §4.3 (f) 的 5% 門檻，而這和模型品質無關。
4. **(b) 不能只刪一句：**
   - L1233 第五值的「等待期間取得正確值」要另外處理：保留的話與 (b) 的理由不一致，刪除的話第五值的結算前確認路徑與字面清單 L2338 的事實敘述都要改。
   - `missing_bar_after_wait` 的說明「再等 5 個觀察日仍無」（ADR L600、字面清單 L1005）也會不成立。

**(a) 的 PIT 怎麼守（要寫成可檢查的約束）**
- ① **判定視圖用序號界定。** 每次評估只讀一次市場 DB 的 `MAX(run_id)`＝R，結算只讀 `run_id ≤ R` 的個股與成員日線、除權息列。
  - 定案下限 A-78、來源優先序照舊；`_hindsight_view` 仍然禁止。
  - R 與寫入的 `settle_source_run_max` 必須是**同一次讀值**。否則判定之後、寫入之前插入的 run，會變成既沒用到、又不算晚到，違反 R-4 (b)。
- ② 大盤 bar 與主 DB 的確認、查證紀錄，同樣以評估當下已存在的為準，由 TA 定存值方式。
- ③ 以存下的視圖重算，結果必須逐位相同。這也同時解決 O-1b。
- ④ 一次評估涵蓋全部未結算的預測，不由人工對個別預測觸發。等待與否只看可用的 T+h 資料在不在，不讀 label、`hit`、基準命中（AST 檢查）。
- ⑤ 任何將來新增的回填路徑，都必須以 session 或全市場為單位，不得依預測挑選標的。
- ⑥ §4.2 新增「等待後結算」揭露，讓晚到資料若與結果相關時能被看出來。

**§6.3「觸發」（L1159）整點取代**

> **觸發**（v0.14，V14-01 改寫；quant-researcher 具名提出）：每個交易日的資料擷取完成後，排程（ADR-0027 D-7）對所有尚未結算的預測做一次評估；一次評估涵蓋全部未結算的預測，不逐筆挑選，也不由人工對個別預測觸發。
> - **判定視圖**：每次評估只讀一次市場 DB 的序號上限 R ＝ `MAX(run_id)`。結算所讀的個股與族群成員日線、除權息事件，一律只取 `run_id ≤ R` 的列（定案下限依 ADR-0027 A-78，來源優先序照舊；不得使用 `_hindsight_view`）。大盤 `^TWII` 的 bar、主 DB 的確認與查證紀錄、觀察日，同樣以該次評估當下已存在的為準，存值方式由 tech-architect 在 ADR-0027 定。R 寫入該列的 `settle_source_run_max`（ADR-0027 N-4），與判定所用的是同一次讀值。以存下的視圖重算，結果必須逐位相同。
> - **可用於結算的 T+h 資料**：個股是該股在判定視圖中定案、通過品質檢查的 T+h bar；大盤是定案的 `^TWII` T+h bar（§1.1）；族群是依 §1.2 排除成員後，覆蓋 ≥ 90%。只有定案前 run 的 bar 不算可用（ADR-0027 A-78；後續追蹤清單 N-16）。
> - **條件**：判定視圖中已觀察到第 h 個交易日 T+h、有可用於結算的 T+h 資料，而且預估的 `valid_until_session` 已過（AV-18），就在該次評估結算。
> - **等待**：沒有可用於結算的 T+h 資料時，不寫入任何 outcome，等下一次評估，期限見下文作廢規則第 1 點。等待與否只依可用的 T+h 資料是否存在，不讀 label、`hit`、基準命中或任何驗證統計。
> - **預測端不受影響**：特徵、label、σ_d(T)、`threshold_snapshot` 仍只用 `recorded_at ≤ cutoff(T)` 的資料（§1.4）；本點只規定結算端。
> 〔v0.14 取代（V14-01）：原寫「**觸發**：每個交易日的資料擷取完成後，排程掃描所有尚未結算的預測。條件是：大盤日線上已觀察到第 h 個交易日 T+h，該日資料的 `recorded_at ≤ cutoff(T+h)`，而且預估的 `valid_until_session` 已過（AV-18）。」〕

**作廢規則第 1 點（L1188）整點取代**

> - **對象在 T+h 沒有可用於結算的資料**（停牌，或只有定案前 run 等，見上文「觸發」）：等 5 個觀察交易日。期間任一次評估的判定視圖中出現可用的 T+h 資料，就在該次評估結算；等待期間才寫入的資料可以使用（v0.14，V14-01）。T+h 之後第 5 個觀察交易日 D_5 結束後的第一次評估（評估當下的 store 時鐘晚於 cutoff(D_5)；D_5 以該次評估可見的觀察日判定，寫入該列），如果仍然沒有，就記 `unresolvable_missing_data`（`missing_bar_after_wait`），`diag_last_close` 以同一個判定視圖計算。所以等待期滿時，每一筆都恰為 `resolved` 或作廢之一。作廢列寫入時已存在的 run 都在判定視圖內；之後才寫入的 run（`run_id` 大於該列的 `settle_source_run_max`），依 §6.4「作廢後才補到資料」與 ADR-0027 N-4 只進診斷。〔v0.14 取代（V14-01）：原寫「- **對象在 T+h 停牌、無 bar**：等 5 個觀察交易日。期間內補到當日資料就結算；補不到就記 `unresolvable_missing_data`，並填 `diag_last_close`。」〕

**推薦 (B) 的結構理由**
1. **與既有成員規則一致。** 成員因子不可用時已經是排除該成員（L436）。分割推定與因子不可用同屬 `excluded_corporate_action`，都是「該成員的序列無法正確還原」。同一類問題，一個排除、一個讓整筆作廢，沒有結構上的理由。
2. **族群 claim 衡量的是族群，不是單一成員。** 在 (A) 之下，整筆作廢的機率是 1 − (1 − p)^N，隨成員數 N 與窗長 h 上升。大族群會因為某一檔的公司行動或資料錯誤，整筆退出樣本。作廢率由族群大小決定，而不是由族群行情決定。
3. **截尾偏誤有反制機制。** 推定的分割若其實是真實行情，排除會截掉尾端。依 §1.2 v0.3 第 1、2 點，被排除的成員會用最後可得收盤放回診斷籃子；主標籤與診斷標籤不一致時，在 W 中按「模型未命中、各基準命中」計，並計入翻轉數。所以截尾若改變了標籤，會直接反映在 W。

**推薦的結構理由（不依任何結果）**
1. **門檻本來就是「每個交易日的漲跌幅限制加容差」。** 跨 g 個觀察日的報酬，在每日限制下能達到的最大幅度，就是逐日複利。換算只用既有常數 c 與 g，不新增常數。
2. **我們分不出缺 bar 的成因。**
   - 停牌：實際只走了一個漲跌幅步。
   - 資料缺漏：該股其實有交易。data-engineer 查證，ok run 的覆蓋門檻是 0.98，最多 2% 的標的缺 bar，而且之後不會補；N-16 會造成整日沒有定案後 run。ADR 待決的 `fetch_failed` 也還沒有來源。
   - 複利門檻在兩種成因下，都不會把漲跌幅限制內的真實行情判成分割。固定 c 在資料缺漏時會判錯，而整日缺 bar 會同時作用在全部個股上，被排除的就集中在大幅波動期（和 V10-01 對指數的理由相同）。
3. **台股的減資、面額變更通常伴隨停止買賣**【推論，待 data-engineer 依規章查證】。跳動正好落在跨缺 bar 的報酬上，現行字面判不到。

**換算後的門檻（算術）**
- g＝2：+23.21%／−20.79%
- g＝3：+36.76%／−29.50%
- g＝4：+51.81%／−37.26%
- g＝5：+68.51%／−44.16%

**限制（照實並陳）**
- g 大時門檻寬。例如減資 30%（價格約 +42.9%），跨 g ≥ 4 就偵測不到；1:2 分割（−50%）在 g ≤ 5 都偵測得到。所以 §4.2 另外分列揭露。
- 停牌期間實際的步數比 g 少，敏感度因此偏低。
- 若有某些交易日沒有漲跌幅限制，換算的前提就不成立。
