## 各部門回報（逐條意見）

### 特別要查 1：bat 守衛區塊（`apps/stock-desk/dev-up.bat` 第 10-20 行）
- **「整個 if 區塊預先解析，call 回來後不再讀磁碟」成立。**
  - cmd 會把括號區塊整段讀入後才執行，區塊內所有 `%var%` 在解析時就已展開。
  - `call` 回來後只剩已解析的 `exit /b !errorlevel!`，最後一條指令也在區塊內，所以 parent 之後不會再讀檔。
  - 區塊之後的第 21 行起，parent 完全不會執行到。
- **`exit /b !errorlevel!` 正確。**
  - 檔頭已有 `enabledelayedexpansion`，`!errorlevel!` 在執行時才展開，取得的是 child 的退出碼。
  - 若寫成 `%errorlevel%`，會在解析時展開成 0，這裡沒有踩到。
  - child 的 `exit /b 0` 和 `exit /b 1` 都能正確傳回。
- **變數傳遞沒問題。**
  - `call` 一支 .bat 是在同一個 cmd 程序內執行，會繼承 parent 的環境變數，所以 child 看得到 `DEVUP_SRC_DIR`。
  - parent 的 `setlocal` 在 child 執行期間仍有效，child 自己的 `setlocal` 是巢狀，不衝突。
  - child 的 `%~dp0` 會變成 `%TEMP%\`，`%~f0` 會變成副本路徑。
- **路徑含空白或 `)` 時沒問題。**
  - `set "..."`、`copy "%~f0" "..."`、`call "..."` 都有加引號，區塊內也沒有未跳脫的 `)` 或裸露的 `%~dp0`。
- **副本不再引用 `%~dp0`。** 我 grep 了整個 repo，`%~dp0`、`%0` 只剩第 11 行（守衛內，parent 用）和 REM 註解。副本的 `%~dp0` 是 TEMP，但沒人用它，pull 之後也沒有任何地方引用。

### 特別要查 3：sh 版（`apps/stock-desk/dev-up.sh`）
- **`main "$@"; exit $?` 寫在同一行足夠。**
  - bash 一次解析一個完整的指令列，所以整行讀完才執行，`exit` 之前不會再回頭讀檔。
  - `set -e` 下 main 失敗時會直接以該狀態退出，`exit $?` 只是保險。
- **函式外的程式碼都在 main 之前。**
  - `set -euo pipefail`、變數、`cleanup`、兩個 `trap`、`probe`、`wait_for` 都在第 10-64 行，pull 之前就已讀完。
  - main 內沒有 `local`，所以 `BACKEND_PID` 等仍是全域變數，`cleanup` 看得到。
  - main 結尾的 `wait || true` 之後，EXIT trap 的行為不變。
