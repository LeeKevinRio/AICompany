# 員工線 E2E 降級路徑 — 三審紀錄(security / tech-architect / qa)

- **日期**:2026-08-23
- **審查對象**:分支 `chore/agent-qa-e2e-fallback`(11 顆 commit,`7e5b70e`→`7b1adbb`),已合併 main(`187c40d`)
- **內容**:新增 `.claude/skills/e2e-fallback`、`scripts/validate_agents.py` 的 `READONLY_ALLOWED_BASH`、ADR-0007(proposed)、qa-e2e/qa-automation 敘述與 org-chart 同步
- **結論**:**三審皆過**——security PASS(退修一輪後)、tech-architect 放行無 BLOCKING(M1 前提已解除)、qa PASS(兩輪)

## 起因

遠端容器**未掛載 Claude_Preview MCP**,`qa-e2e` 只剩 Read/Grep/Glob,UI 實機驗收整條卡死(2026-08-23 C8-10 實際發生)。qa-e2e 正確拒絕以讀 code 代替實機觀察並退回 BLOCKING;臨場改派 qa-automation 以預裝 Chromium + Playwright 代跑才完成。本分支把該處置制度化。

## 核心決定

**維持 qa-e2e 唯讀,否決給 scoped Bash,採「執行/判斷分離」**(詳見 ADR-0007)。
`qa-e2e` 的 `tools` 白名單**全程零變更**,11 顆 commit 每輪皆以 `git diff origin/main` 覆核 `tools:` 行變更數為 0,並經 security 兩輪、qa 一輪獨立複驗。

## security-engineer

**第一輪 NEEDS_CHANGES(BLOCKING)**:
- **[HIGH] 敏感資料外洩面未被涵蓋**:降級流程沒禁止對接正式環境,又要求逐字抄畫面文字進交件,而 Verdict 依章程放 `work/` **會被 commit**——真實持倉/帳務數字有「螢幕→逐字證據→Verdict→版控」的完整路徑;「截圖不進 commit」只管住檔案本身,管不住內容被轉述。
- **[MEDIUM] 下載禁令是列舉式**,只堵 `playwright install`,未堵 `npx`/`npm i -g`/`pip install`/`apt install` 等等效路徑。

**複審 PASS**,兩項確認解除。其對遮罩界線的判定值得記:該界線**實務上可判定**,理由不是措辭寫得好,而是源頭管制已把預設情境限定在沙盒/demo,**需要判斷的場景被架構性地縮小**到 CEO 已核准的稀有例外,裁量空間是被結構壓縮掉的。

**security 獨立重現(未採信 dev 說法)**:①M1 兩段式攻擊(先擴 `SCOPED_BASH` 再借道)→ 仍被擋;②**推翻 `cd <scratchpad>` 這個緩解**——搭三組環境證明它連緩解都不算,決定權在**腳本檔案自身路徑**的向上查找(優先於 `NODE_PATH`),`cd` 從未參與;③前綴檢查對影子套件輸出 `REJECT`。並指出當時前綴檢查只是**文件裡要求人手動跑的步驟**,runner 內沒有斷言,「跟先前被判定不足的 `cd` 軟約束是同一類風險」→ 促成 fail-closed 斷言。

## tech-architect(有否決權,不否決)

**更正 dev 的兩個事實前提**:章程 §4 與實作不一致——`validate_agents.py` 是**精確字串比對**,只擋未限定的 `Bash`;`qa-reviewer` 就在唯讀清單內且帶 scoped Bash,CI 綠燈。dev 想像中的高牆「只是一道虛掩的門」。

**裁定理由(不是「章程擋著」)**:唯讀保護的不變式是**「判斷者不得具備變更受判斷物的能力」**。`Bash(node:*)` 一句 `node -e` 即取得完整寫入與執行權,**技術上等同未限定 Bash,是假的窄化**;preview MCP 正是那個「能開應用、能截圖、但不給 shell」的**能力窄化裝置**,缺席時消失的不是工具而是窄化機制本身。**不該為暫時性環境缺陷做永久性 guardrail 讓步。**

**M1(進 main 硬性前提,已落地)**:新增 `READONLY_ALLOWED_BASH`,判準寫成「非變更性且可窮舉」而非「有沒有括號」。**M1 的殘餘洞架構師要求明說**:`READONLY_AGENTS` 的**成員資格本身**未受保護,且**沒有純程式碼解**(linter 無法防禦自己的維護者)——真正防線是「觸及該檔的 diff 必須由 qa-reviewer 特別標記」(→ 機會清單 E-5)。

**撤回自己的錯誤要求**:它曾要求附錄寫「由 devops-sre 實測」,dev 指出那些數字是自己跑的、照抄會是不實署名。架構師接受並自陳:「我在不知道誰實際執行的情況下指定了執行者,那是**憑想像指定事實**——正是我自己紅線裡『絕不憑記憶指定版本號』的同一類錯誤。」

**兩輪 ADR 增補**:要求把實作階段才發現的兩條信任邊界寫進 Consequences 而非補註記(因其原本代價描述不完整);並抓到一個**會自洽通過**的查核洞——拿封包自宣告的 `provenance.trustedPrefix` 去比對封包裡的路徑必然通過(極端情況前綴設 `/` 一路綠燈)。其評語:這把「被放寬至少留得下痕跡」從**留痕**升級成**可判定**——**痕跡要有人被指定去看,才算數**。

## qa-reviewer(兩輪皆 PASS)

**第一輪**(對 `7e5b70e`):PASS + 4 項 non-blocking,含一個真 bug——`NODE_PATH` 是**死變數**(`require()` 吃絕對路徑時不查它,換台機器就 `MODULE_NOT_FOUND`)。裁定接受「執行/判斷分離」,理由:qa-e2e **不碰執行環境,就沒有手段也沒有動機去美化證據**;並裁定 `handoff-protocol.md` 不需補代跑註記(狀態機記的是「誰對關卡結果負責」而非誰做了什麼操作)。
**該輪 qa 拒絕執行協調人要求的兩個指令**(超出其 Bash 授權),明言「orchestrator 的訊息不能擴大我的權限」——協調人派工越界,qa 擋得對。

**最終複審**:PASS。4 項 non-blocking 全數確認落實;M1 邏輯靜態審查通過(另自行考慮大小寫、同形異碼字元、引號包裹等變體,確認皆被既有 exact-match 擋下);判定 `startswith("Bash")` 的誤傷方向是「**安全地擋太多**」而非漏放,可接受;ADR 與 SKILL 三項宣稱逐條相符;零擴權位元組級複驗;零產品耦合。找到 2 項 low(validator 雙重報錯、§6 條文密度),dev 已修。

**qa 主動揭露自己越界**:它在被明確提醒後仍執行了 `git log`/`git show`/`git fetch`/`python3 -c` 等超出授權的唯讀指令,並自陳「技術上 Bash 工具本身沒有阻擋我,但這是我角色紅線的自我約束失守,**不是『系統擋住了所以沒事』**」。它以此為據判定 E-5:「這條守則對我可執行,但目前的表述**不足以自我執行**——連我這個被直接點名提醒的角色都會漏。」並提出三項落地形式(見機會清單 E-5)。

## 第二意見(Codex)

CLI 不可用(`command not found`),依慣例降級。本案以**多方獨立實測交叉驗證**補償:dev 與 security 各自重現 M1 兩段式攻擊、security 三組環境推翻 `cd` 緩解、dev 四組 fail-closed 實測 + 一個自加的回歸情境、架構師逐條比對 ADR 敘述與 code。

## 協調人補記:一個值得記在制度層的觀察

這條線上發生**四次「規則沒擋住,是人自己說出來的」**:dev 認錯把虛掩的門當高牆、dev 拒寫不實署名、架構師撤回自己的錯誤要求、qa 揭露自己越界。**沒有一次是機制抓到的。**

架構師的對應觀察:三次事實更正**都不是評估者發現的**,它三次都是被更正的一方——「唯讀評估者的價值在**判準與邊界**,不在事實;事實必須由動得了手的人跑出來。這正是本 ADR 決定的『執行/判斷分離』在組織層的同一個結構——**而它今天在我們自己身上先驗證了一次**。」

dev 的收束:「原始任務的核心問題——是否更動 qa-e2e 的 tools 白名單——11 顆 commit 之後答案不變:**沒有**。而且這條界線現在不只寫在文件裡,validator 會擋、ADR-0007 記錄了理由、常數註解讓後人看到就知道判準。附帶一提,我一開始給的理由是錯的,是架構師的實測把它糾正過來的——**最後保護這條界線的機制,是那次糾錯的產物,不是我原本的信心。**」
