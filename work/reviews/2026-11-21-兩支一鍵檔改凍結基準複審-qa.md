### 3. 凍結基準的處理

- **LF／CRLF 等價**
  - 舊測試切 `\r\n`，新測試先在記憶體把 `\n` 換成 `\r\n` 再切，兩者在以下條件下序列相同：檔內沒有裸 `\r`（測試先斷言過），而且沒有裸 `\n`（由 `replace` 全轉換保證）。
  - 檔尾：凍結檔以 `\n` 結尾，轉換後以 `\r\n` 結尾，`split` 後末尾多一個空字串，與舊版 CRLF checkout 的行為一致（40 個元素，其中最後一個是空字串）。
  - 空行、最後一行：沒有邊界差異。
  - 差異測試中 `len(new) == len(old) + 1` 的斷言與這個等價性相容。
  - 前提：`.bat` 在 checkout 上是 CRLF；如果有人在 `eol` 設定不同的環境把它變成 LF，`_bat_lines(BAT)` 本來就會失敗，這與改基準無關。
- **`-text` 與三個 `.gitattributes`**
  - `tests/fixtures/.gitattributes` 只有一行 `pipeline_acceptance_bat_frozen.txt -text`。
  - `-text` 取消 text 屬性，`core.autocrlf=true` 的 Windows checkout 不會轉換該檔，足以達成目的。
  - 根目錄只管 `*.bat` 與 `*.sh`，`.txt` 不命中；`backend/.gitattributes` 只管 `uv.lock`。三個檔沒有重疊或衝突。
  - 既有測試 `test_the_backend_attribute_file_pins_uv_lock_to_lf` 比對的是 `backend/.gitattributes` 的位元組，`test_the_root_attribute_file_is_not_changed_by_this_work` 比對根目錄那份，兩者的檔案都沒被動，**不會失敗**。
  - 這兩個測試用的臨時 repo 也只複製 `backend/.gitattributes`，不受巢狀檔影響。
- **新增的兩個測試**
  - sha256 測試：不是恆真。它比對的是檔案實際位元組，常數與 `.bat` 的雜湊對應；缺點是只能擋住「被改過」，不能擋住「常數與檔案一起被改」，但這正是釘雜湊的一般限制。
  - `git check-attr` 測試：斷言 `text: unset` 且 `eol: unspecified`，不是恆真。若有人改成 `text` 或加 `eol=crlf`，會紅。這一條只有在斷言的是 `unset` 與 `unspecified` 時才有意義，現狀沒有過寬。
  - 沒有 git，或在非 git 目錄（例如 tarball）執行時，`subprocess.run(..., check=True)` 會丟 `FileNotFoundError` 或 `CalledProcessError`，測試以錯誤結束而不是跳過。既有的 `test_git_checks_the_bat_out_with_crlf` 與 `test_pipeline_acceptance_real_eol` 也是同樣處理，所以與現有慣例一致，我列為可接受（N5）。
- **註解的性質**：兩支的註解寫明了凍結自 `d6816eb9`（product tip 在 fetch 當下）的 `apps/stock-desk/pipeline-acceptance.bat`、blob id、LF 位元組。也寫明只作比對基準、全產品線一份、不得更新、不代表任何現存工具、不得用來取回工具。第 5 點 (c) 的要求都有涵蓋。
- **補充十二第 5 點 (a) 的字面落差（只陳述事實）**
  - 該句寫「位元組等於 `git cat-file blob <G_acc>:…`，CRLF 也一起保留」。
  - blob 本身是 LF，沒有 CRLF（來源 `.bat` 在 index 裡本來就是 LF，CRLF 只出現在 checkout）。實作是「存進 git 的 blob 相等」，CRLF 只在測試的記憶體內還原。
  - 實作符合該點的意旨：基準檔與 G_acc 的 blob 位元組相同、不被 checkout 轉換、比對時等同於舊測試讀到的 CRLF 序列。落差只在字面。
  - 這一句交 tech-architect 更正。
- 另一點事實：註解寫的來源 commit 是 `d6816eb9`（product tip），不是 `G_acc` 本身，也不是 `8b22c114`。devops-sre 的交件說明兩者 blob 相同（`8b22c114..tip` 對該路徑的 log 為空，轉述）。我無法用 `git log` 或 `git cat-file` 自行驗證；而補充十二 (a) 與 S-21 要求的是「等於 G_acc 的 blob」，這點需要由有權限的人再確認一次（N2）。
