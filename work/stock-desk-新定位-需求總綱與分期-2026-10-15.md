## 0. 讀者先看這五點

1. **新定位真正改變的是「輸出什麼」，不是「怎麼算」。** 既有的 point-in-time、成本、樣本門檻、不自動下單、不用黑箱 ML 直接產生動作等原則維持（CEO 決策紀錄 L35）。與 ADR-0004「無目標價」、phase8 風控定調 §1.3／§4、七則初審 PX-4／PX-5／PX-25 等衝突的部分，待 ADR-0025 核可後以新 ADR 為準；在那之前**現行字面與程式不動**（決策紀錄 L36）。
2. **盤點揭露的缺口中，有一批與定位無關、現在就是 bug 或風險**（全缺價顯示 NT$0、CSV 匯入重複計入、刪除無法復原、程式不讀 `.env` 導致族群動能從沒有榜單）。這批不必等 ADR-0025，應先做。
3. **最大的工程量不在畫面，在「可核對依據的價位」與「展望的驗證機制」。** 目前的價位多為固定百分比（停損 `max(A−2ATR, 0.92A)`、觀察帶 MA20±3%，盤點 L344-345），原文明文禁止「用任意固定百分比包裝成 AI 建議」（原文 L77）。展望（3／5 日偏多／震盪／偏空）在程式裡**完全不存在**（盤點 L59-65），驗證所需的「保存當時預測」也不存在（盤點 L413）。這兩塊必須先於面向使用者的呈現。
4. **三層族群與題材分類需要新資料（人工整理或新來源），而且推翻既有 PRD 紅線**（族群動能 PRD 明文「不做自訂概念股分組」，盤點 L177-182）。這是 CEO 要決定資料源取捨的地方。
5. **基本面與消息面目前沒有任何資料源，且舊裁示是「無合規免費源就不做」**（機會清單 C7、盤點 L277-288）。CEO 這次認可含消息面的 prompt，等於推翻該裁示的前提；但「資料從哪來」仍是未解問題，卡在 CEO 本機執行 spike 腳本（機會清單 C12，逾三週未推進）。

### 1.2 新定位聲明草案方向（**只列方向，不定稿字面**）

逐字字面另交 creative-lead 起草、風控逐字審（章程 §0.5）。PM 提出下列方向供其參考，**不是可上線字面**：

1. 聲明應說明：本工具提供**條件式的投資建議與價位參考**，供 CEO 本人決策；不下單、不保證準確、不保證成交。
2. 應取代現行常駐頁尾「本工具為研究與教育用途，非投資建議」（盤點 L27，`FE/layout.tsx:20`）、README 開頭、`work/stock-desk-產品說明.md:3` 三處，並一併檢查設定頁、回測頁、決策卡內的「非預測模型」「非建議」類字面（盤點 L61，`FE/lib/adviceWording.ts:234-236`）是否與新定位自相矛盾。
3. 應與護欄並列：不承諾準確率、證據不足時說明缺什麼、區分事實／推論／未確認、附失效條件、樣本不足直說。
4. 「純自用」前提是否寫入聲明，由風控與 CEO 定；PM 建議**內部文件寫明、使用者面不必強調**（理由：使用者即 CEO 本人）。
5. 聲明改動與「建議輸出」功能必須**同一個發布批次**上線；不得出現「頁尾已改、功能還是舊護欄」或反過來的過渡狀態（推論：過渡狀態會讓字面與行為自相矛盾，重蹈 KT-1 所處理的跨畫面矛盾）。

  - Given 金融股；When 查看基本面；Then 使用金融業指標組，不套用通用分數。
  - Given 無資料；When 查看；Then 顯示「基本面資料來源尚未接入」與缺什麼，不顯示空表。

#### NP-D6 消息面

- 現況：**未實作**。無新聞公告資料源；舊裁示「無合規免費源就本期不做」（機會清單 C7；盤點 L282-288）；連占位揭露句都沒落地。
- 缺口：資料源、去重、重要性判斷、「是否已反映」判斷、法說歷次比較。
- 依賴與難點（分開看）：
  - 依時間列出官方公告（來源、發布時間、事件時間）：**可規則化，不需 LLM**（推論；官方重大訊息的取得方式待 data-engineer 查證，我未驗證）。
  - 「去除重複標題與舊聞」：標題相似度規則可做，品質需驗證。
  - 「為何重要、可能影響什麼」：需要語意判斷，**規則式只能以事件類型模板**；若要自然語言，須 LLM（另案 ADR，§5 決定 D-3）。
  - 「市場是否可能已反映」：可用事件前後價量反應當作**事實量**呈現，結論標為推論。
  - 法說歷次比較：需法說資料源，**建議列 Phase 4**。
- 風險：最容易編造；必須符合「不能把推測當事實」（原文 L72）。
- 驗收：
  - Given 一檔標的近 7 日有 3 則官方公告，其中 2 則同一事件；When 查看消息面；Then 去重後列 2 則，各附來源、發布時間、事件時間。
  - Given 無可用消息源；When 查看；Then 顯示「本產品目前未接入消息面資料來源」，不顯示空白或「無重大消息」（後者會被讀成確認沒有消息）。
  - Given 事件的市場反應解讀；When 顯示；Then 標為「推論」並與事實欄位視覺分開。

#### NP-D7 事實／推論／未確認的統一區分

- 現況：**部分**，散落各處，使用者端沒有統一標籤（盤點 L290-297）。
- 缺口：統一的三類標籤元件與資料契約（後端回傳每個證據項的類別）。
- 依賴：tech-architect（API 契約）；creative-lead（標籤字面）→ 風控。
- 驗收：
  - Given 任一建議或展望的證據清單；When 後端回傳；Then 每一項都帶類別欄位（事實／推論／未確認），**缺類別的項目測試失敗**（防止漏標）。
  - Given 前端渲染；When 檢視；Then 三類在視覺上可分辨，且不只靠顏色（無障礙，見機會清單 D10）。

### 2.6 原文三.E 持股行動計畫

#### NP-E1 進場觀察區、失效／停損價、分批停利、加碼條件，每個價位有可核對依據

- 現況：**部分，且與原文衝突**。觀察區是 MA20 ±3% 固定百分比；停損是 `max(A−2×ATR14, 0.92A)`，其中 0.92A 是固定 −8%；分批停利在個股頁只有單一 2R 與 1.2A，真正的分批階梯只在排程台且是使用者自訂規則；算式在前端，與回測兩套實作；`risk_budget_stop_reference`（風控 phase8 §4 C7 規格）從未實作（盤點 L344-347）。
- 缺口：後端統一的價位產生器，每個價位帶「依據型別」與「可重算的輸入」。
- 依賴：
  - ADR-0018（後端化、統一 1.2A、移動停利，仍 proposed）與 ADR-0025 的取捨：tech-architect。
  - 「可核對依據」的判準：**ATR 倍數是否算「可核對依據」還是仍屬任意參數，PM 沒有答案**，須 quant 與風控共同裁定（§6 開放問題 Q-3）。PM 的建議：價位優先取自**可觀察的市場結構**（前波低點、均線、觸價密集帶），參數型緩衝（如 ATR 倍數）必須揭露參數與其歷史檢驗結果。
  - 風控新護欄（待編號），特別是 phase8 §4 C5／C6／C7 與 PX-4 的重訂。
  - 目標價／合理價／上看：**CEO 這次的清單與原文 E 節都未列入**（決策紀錄 L25；原文 L74-82）。本總綱**不納入**，列為範圍外，除非 CEO 明示。
- 風險：最高之一。價位若無依據就是「編造價位」。
- 驗收：
  - Given 一檔持股與足夠日線；When 查看行動計畫；Then 顯示進場觀察區、失效價、至少一個分批停利價、加碼條件，**每個價位旁可展開看到**：依據型別、輸入值、算式、資料截至日。
  - Given 某價位只能以固定百分比得出；When 產生計畫；Then 該價位**不顯示**，改顯示「缺乏可核對依據」（原文禁止以固定百分比包裝）。
  - Given 同一標的、同一資料日；When 重算；Then 價位逐位相同（確定性，測試釘住），且前端不再自行計算價位。
  - Given 現價已越過失效價；When 查看；Then 顯示「已越過失效價」狀態（沿用既有「已越過水位」字面機制，字面需過風控）。

#### NP-E2 納入持股量、成本、每筆最大風險、可用現金、總部位風險、手續費與稅費

- 現況：**部分**。持股量、成本、每筆最大風險有；**可用現金在建議卡未實作**（排程台有手填現金）；整書彙總只取最差單檔，沒有整書停損風險加總；手續費稅費只用於回測，費率未查證（`verified_on=None`）；每筆最大風險的分母是已估值部位市值而非總資金（盤點 L348-353）。
- 缺口：現金欄位進建議；整書停損風險加總；費稅進入股數區間與單筆虧損；費率查證。
- 依賴：
  - 現金的資料來源：使用者手填（沿用自報淨值模式，已有風控六個前置問題定案，`work/stock-desk-phase8-風控定調.md`）；券商 API 為 P2 長期項（機會清單 C6）。
  - 台股費率查證：data-engineer 連網（總評 L58）。
  - 整書停損風險加總的公式：quant 提案、風控審（ADR 現行文字「不發明整書公式」，盤點 L351，須由 ADR-0025 明確鬆綁）。
- 驗收：
  - Given 使用者填入可用現金 C、每筆最大風險 r；When 查看某標的加碼計畫；Then 建議上限不超過 C 與 r 所允許者，且顯示計入的手續費與證交稅。
  - Given 現金欄位未填；When 查看加碼計畫；Then 顯示「缺可用現金」，不以 0 或總資產代替。

#### NP-E3 分開顯示「從現價回撤的風險」與「相對成本的損益」

- 現況：**已實作**（盤點 L354）；但「現價」一詞被 VETO。
- 缺口：用語；新計畫面板沿用。
- 驗收：Given 持股成本 100、現價 90、失效價 85；When 查看；Then 兩個數字分兩列：相對成本 −10%、距失效價約 −5.6%，且互不引用對方的分母。

#### NP-E4 加碼必須有價格、量能、趨勢、預算條件，不因下跌自動建議攤平

- 現況：**部分**。引擎加碼規則看均線、MACD、RSI 且在 MA60 之上；命中防禦規則或任一上限 violated 就不得加碼；**不含量能**；排程台 R1 是「時間到就買」，下跌但未觸 S1 仍照排程買（盤點 L355）。
- 缺口：量能條件；預算條件；排程台 R1 與原文「不能因為下跌就自動加碼」的關係（排程台是 CEO 自訂規則的機械執行器，歸屬語為「非本系統的判斷」；新定位下該歸屬語是否保留，由 ADR-0025 與風控決定，PM 不預設）。
- 驗收：
  - Given 價格下跌但量能與趨勢條件不成立；When 查看加碼條件；Then 不建議加碼，並說明哪幾項條件未滿足。
  - Given 全部條件成立但預算（現金或風險上限）不足；When 查看；Then 顯示「條件成立但預算不足」，不顯示可加碼。

#### NP-E5 停損可能無法成交的揭露；不自動下單

- 現況：不自動下單**已實作**；無法成交的揭露只有排程台有，個股頁決策卡與關鍵價位面板沒有（盤點 L356-357）。
- 缺口：個股頁與行動計畫補揭露（字面過風控）。
- 驗收：Given 任一顯示停損／失效價的畫面；When 檢視；Then 同畫面可見「可能因跳空或流動性無法成交」類揭露；全站無任何下單 API 呼叫（既有性質，列為回歸）。

#### NP-U3 清楚區分尚未分析、分析中、來源失敗、資料過期、樣本不足

## 3. 分期排序

### 3.0 排序原則與對原文順序的詮釋

- 依原文 L119 與 CEO 決策紀錄：**資料正確性 → 庫存安全 → 分析可靠性 → 日常操作 → 擴充功能**，對應 Phase 0～4。
- 額外原則（推論，供 CEO 否決）：
  1. **現存缺陷優先於新能力。**
  2. **驗證機制先於展望呈現。** 「預測紀錄」每天不存就永遠補不回來（歷史重放可驗證規則，但「當時實際輸出」只能向前累積）；因此 NP-V5 應盡早啟動，即使畫面尚未上線。
  3. **每期結束都是可使用的狀態**，不出現半套定位。
  4. **在途工作不因新定位中斷**，除非與 ADR-0025 衝突（§3.6 列出）。
- 分期的「預估影響的既有在途工作」欄是我的判斷，已盡量標明依據；個別任務單最新狀態以任務單為準，我只讀了狀態行。
