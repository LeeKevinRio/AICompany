## 句 1(R-D5②-3:`trading_days_behind` 為 null 時「無法向交易日曆確認」句)

### 情境重述(供風控核對觸發條件)

畫面已顯示 as-of 日期(`buildAsOfStatement(dateIso)` 正常輸出,`lastBarDate !== null`),
但 `trading_days_behind` 為 `null`——目前這個組合下 `staleDataNotice` 靜默回傳 `null`,
讀者看到日期卻看不到任何「是否過舊」的訊息,可能誤讀為「沒有警語=不舊」。
句 1 要補的正是這個誠實揭露:系統其實**無法**判斷,不是「判斷後說不舊」。
根據前置分析,此組合在 CEO 實際情境(advice 端點)結構上不可達,句 1 屬防禦性揭露
(涵蓋測試/開發 harness、時鐘偏移等殘餘邊角),依裁決 7 走「補句」不改列管。

### 主案

> **本次無法向交易日曆確認資料是否過舊。這並非資料已確認為最新的表示。**

**逐條自檢:**

| 檢核項 | 結果 | 說明 |
| --- | --- | --- |
| 否定層次 ≤2 | 過 | 全句僅兩個否定詞:「無法」(第一句)、「並非」(第二句),分屬兩個獨立句子,不巢狀疊加(不是「不代表…並未…」的雙重否定包夾)。 |
| 不得提及 UI 元件名稱 | 過 | 全句未指涉任何提示框/面板/元件;只陳述「系統無法向交易日曆確認」這個實質限制本身,不影射「原本該有個提示但沒顯示」。 |
| 標點範圍照 required 界定 | 過 | 改用兩個獨立句號分句,不使用「因此」、不使用分號——直接消除原案「因此+分號」造成的三段邏輯階層作用域歧義。 |
| 「無法向交易日曆確認」為真且不指名成因(一般性 required 保留) | 過 | 逐字保留「無法向交易日曆確認」;全句未提及成因(不寫「因為缺少日曆來源/因為 null」等)。 |
| 不替系統背書 / 不做未來承諾 / 措辭=行為 | 過 | 沒有「已驗證」「保證」等肯定語;第二句是否定句(澄清「不是確認為最新」),沒有做任何承諾。 |
| 落地條件 1-8(觸發精確分支、禁與 FULL_STATEMENT 併存、resolveAsOfStatement 單一字串、同槽渲染、四分支測試、no_price/no_action 範圍限制列管) | 過(設計面滿足,細節見下方落點) | 見下方「預計落點」逐項對應。 |

**預計落點:**

- 新增常數(建議命名,dev-lead 可調整):`adviceWording.ts` 內
  `TRADING_DAYS_BEHIND_UNKNOWN_STATEMENT = "本次無法向交易日曆確認資料是否過舊。這並非資料已確認為最新的表示。"`。
- 串接方式:比照 `AS_OF_DATE_UNKNOWN_FULL_STATEMENT` 的單一字串模式,在
  `operationSummary.ts` 的 `resolveAsOfStatement`(或其呼叫端)新增第三分支——
  當 `lastBarDate !== null && tradingDaysBehind === null` 時,回傳
  `buildAsOfStatement(dateIso) + TRADING_DAYS_BEHIND_UNKNOWN_STATEMENT`(單一字串,
  非兩個渲染節點),同槽、同字級、不可摺疊。
- 分支互斥:此分支要求 `dateIso !== null`,天然與「日期未知」的
  `AS_OF_DATE_UNKNOWN_FULL_STATEMENT` 分支互斥,不會併存。
- 四分支對照:①日期未知(FULL_STATEMENT)②日期已知+gap 已知+未過舊(僅
  `buildAsOfStatement`)③日期已知+gap 已知+過舊(`buildAsOfStatement` +
  既有 `staleDataNotice`)④日期已知+gap 為 null(`buildAsOfStatement` + 本句)。
- 範圍限制(列管,非本次 required):`asOfStatement` 只存在於 `RequiredElements`
  (held/candidate 卡),`NoPriceSummary`/`NoActionSummary` 沒有這個欄位,本句因此
  天然不觸及 no_price/no_action 畫面——與 D3③ 當初把 `staleDataNotice` 擴面到這兩種
  畫面是兩件事,本批不主動擴面,列為後續列管項供風控知悉。

### 備案

> **本次無法向交易日曆確認資料是否過舊，這並不代表資料已確認為最新。**

**逐條自檢:**

| 檢核項 | 結果 | 說明 |
| --- | --- | --- |
| 否定層次 ≤2 | 過 | 「無法」+「不代表」共兩個否定詞,單一逗號連接的一個句子內,平行並列、不巢狀。 |
| 不得提及 UI 元件名稱 | 過 | 同主案,不指涉任何 UI 元件。 |
| 標點範圍照 required 界定 | 過 | 用一個全形逗號連接兩個分句、句號收尾;無「因此」、無分號,語意範圍單一不歧義。 |
| 「無法向交易日曆確認」為真且不指名成因 | 過 | 逐字保留,未提成因。 |
| 通則(背書/承諾/措辭=行為) | 過 | 同主案。 |
| 落地條件 1-8 | 過(設計面同主案) | 差異僅在標點與句子數,串接方式、分支觸發、互斥性、範圍限制與主案完全相同。 |

**預計落點:** 與主案相同插槽,常數同名替換字面即可
(`TRADING_DAYS_BEHIND_UNKNOWN_STATEMENT` 改為此句)。

**主案 vs 備案的差異與建議:** 主案用兩個獨立句號分句,備案用單一逗號句。主案更直接
回應「因此+分號造成三段歧義」的退修理由(用最明確的句界消除歧義),為**建議採用**;
備案較精簡、適合版面緊縮情境,語意與合規結果等價,留供風控選字時比較。

## 句 3(TradingView 補句:與既有揭露句銜接)

### 情境重述(供風控核對觸發條件)

`TRADINGVIEW_CHART_DISCLOSURE_STATEMENT`(2026-08-16 二輪 CONFIRMED,逐字定稿)
**一字不動**;句 3 是接在其後的獨立新常數,兩個呼叫點(`TradingViewChartPanel.tsx`
第 141 行 invalid-symbol 分支、第 167 行正常渲染分支)共用同一組合字串。原案的缺陷是
把新句接在「載入需要網路連線。」句尾,用裸「因此」把「需要網路連線」說成「價量可能
不一致」的原因——這是假因果(真正原因是兩條資料鏈各自獨立,不是網路連線與否)。

### 主案

> **兩條資料鏈各自獨立；此圖表顯示的價格與成交量，可能與本系統其他頁面所引用的資料不一致，本系統不會將兩者互相校正。**

**逐條自檢:**

| 檢核項 | 結果 | 說明 |
| --- | --- | --- |
| 「價量可能不一致」為真且保留 | 過 | 明確陳述「價格與成交量…可能…不一致」。 |
| 不得用裸「因此」製造虛假因果 | 過 | 全句不含「因此」「故」「所以」「因為」等因果連接詞;第一分句與第二分句以分號並列,靠語序(先重述「各自獨立」這個既有事實,再陳述其自然結果)傳達關聯,不是靠連接詞硬接假因果。 |
| 獨立常數附加,既有字串不動 | 過 | 本句設計為附加在 `TRADINGVIEW_CHART_DISCLOSURE_STATEMENT` 之後的**新增獨立常數**,原逐字定稿句不含任何改動。 |
| 承接詞須自帶回指「兩條資料鏈各自獨立」 | 過 | 開頭直接重述「兩條資料鏈各自獨立」——原句已用「各自獨立的兩條路徑」表達同一件事,此處呼應回指同一事實,而非另起新理由。 |
| 不得使用自我指涉的連接詞 | 過 | 全句不使用「承上」「如前所述」「因此」等指涉自身或前句的連接詞;用分號連接兩個各自完整的獨立子句,語意由內容本身承載。 |
| 標點慣例對齊(分號/「本頁」vs「本系統」) | 過 | 用分號銜接,與既有揭露句「…是各自獨立的兩條路徑，本系統未查證…；本系統無法標示…；圖表內容僅供檢視…」的分號用法一致;主詞採「本系統」,與既有揭露句三處主詞(「本系統未查證」「本系統無法標示」)一致,不換用「本頁」造成同段落主詞飄移。 |
| 通則(背書/承諾/措辭=行為) | 過 | 「本系統不會將兩者互相校正」是陳述系統實際不做的事(措辭=行為),非承諾語氣,無「已驗證」等背書字眼。 |

**預計落點:**

- 新增常數(建議命名,dev-lead 可調整):`TradingViewChartPanel.tsx` 內
  `TRADINGVIEW_CHART_DATA_INDEPENDENCE_NOTE`,值為本句。
- 組合方式:新增
  `TRADINGVIEW_CHART_DISCLOSURE_FULL_STATEMENT = TRADINGVIEW_CHART_DISCLOSURE_STATEMENT + TRADINGVIEW_CHART_DATA_INDEPENDENCE_NOTE`
  (單一字串,不是兩個 `<p>`),兩個呼叫點(第 141、167 行)原本渲染
  `TRADINGVIEW_CHART_DISCLOSURE_STATEMENT` 的地方改渲染這個 FULL 常數。
- 測試面:`componentWordingScan.test.ts` 現有逐字釘住
  `TRADINGVIEW_CHART_DISCLOSURE_STATEMENT` 的三個 it block(banned terms /
  即時denial / verbatim match)不動;需為新常數與 FULL 常數各加一組同款
  逐字釘住測試(dev-lead 落地時處理,不在本提案範圍)。

### 備案

> **此圖表顯示的價格與成交量，可能與本頁「本地圖表」頁籤顯示的資料不一致；兩者本就是各自獨立的兩條資料鏈，本系統不會將兩者互相校正。**

**逐條自檢:**

| 檢核項 | 結果 | 說明 |
| --- | --- | --- |
| 「價量可能不一致」為真且保留 | 過 | 同主案。 |
| 不得用裸「因此」製造虛假因果 | 過 | 同主案,無因果連接詞;順序改為先陳述不一致的現象,再以分號補上「各自獨立」的既有事實作依據,依然是並列陳述而非因果詞連接。 |
| 獨立常數附加,既有字串不動 | 過 | 同主案。 |
| 承接詞須自帶回指「兩條資料鏈各自獨立」 | 過 | 第二分句「兩者本就是各自獨立的兩條資料鏈」明確回指同一事實。 |
| 不得使用自我指涉的連接詞 | 過 | 同主案,無自我指涉連接詞。 |
| 標點慣例對齊(分號/「本頁」vs「本系統」) | 過(改採「本頁」,見下方說明) | 用分號銜接;比較對象具體點名「本頁『本地圖表』頁籤」——此頁籤名稱已見於同檔既有定稿句
`TRADINGVIEW_CHART_FALLBACK_MESSAGE`(「…或可改用『本地圖表』頁籤」),非本句新創的 UI 指涉,風控此前已核可同款指名方式。收尾主詞仍用「本系統」,與既有句尾主詞一致,僅比較對象改具體化。 |
| 通則 | 過 | 同主案。 |

**預計落點:** 與主案相同插槽與組合方式,差異僅在常數字面。

**主案 vs 備案的差異與建議:** 主案的比較對象是抽象的「本系統其他頁面所引用的資料」,
不點名特定頁籤,措辭較保守、與既有揭露句的抽象層級(「本系統自有的行情資料鏈」)更貼合,
為**建議採用**;備案具體點名「本地圖表」頁籤,對讀者更好理解「不一致」具體是跟誰比,
但多了一個可能隨頁籤改名而漂移的具體指涉,若風控偏好具體化可選此案。
