## 三個步驟

1. **雙擊 `apps\stock-desk\dev-up.bat`**，讓本機拉到最新版。確認三個 stock-desk 視窗正常開起來後，**把這三個視窗都關掉**（backend、scheduler、frontend）。
   - 這次拉到的只有盤點腳本、一鍵檔與文件；`app/` 沒有變動，產品行為不變。
2. **雙擊 `apps\stock-desk\r2-probe.bat`**。視窗會顯示英文說明，確認三個視窗都關了之後，**按一次 Enter**。
3. **記事本會自動跳出 `paste-back.txt`**。按 Ctrl+A 全選、Ctrl+C 複製，貼回給 coordinator。之後就可以照平常再雙擊 `dev-up.bat` 啟動。

整個過程大約 2 到 3 分鐘。

## 它替您做了什麼

- 檢查 8000 埠沒有程式在聽（確認 backend 已關）。
- 把資料庫的三個檔複製到您使用者資料夾下的 `stock-desk-n208\<時間戳>\`（在 repo 之外），逐檔比對雜湊，確認複本與正本相同。
- 對**複本**做 N-208 現況計數與 R2 偵測。正本只被讀取與複製，不會被寫入。
- 把要回傳的內容寫進 `paste-back.txt`。裡面只有計數、雜湊、時間與固定文字，**不含股票代號、金額、路徑**。

## 注意事項

- **只貼記事本裡的內容**，不要截整個黑色視窗給任何人（視窗裡可能有本機路徑）。例外：視窗顯示 `ERROR: unexpected failure` 或 `.bat` 本身報錯時，先看過畫面沒有您不想給的資訊，再截圖給 coordinator。
- `stock-desk-n208\<時間戳>\probe-report\report.md` 含持股與現金，**只留在您本機**，不要貼給任何人，也不要放進 repo。`gate_affected_symbols` 大於 0 時，您自己開這個檔看逐檔內容。
- `stock-desk-n208` 資料夾整個保留，不要刪；第二次執行會用到。
- backend 或 scheduler 若是用 NSSM 或 Windows 工作排程器常駐（不是用 `dev-up.bat` 開的），先不要跑，告訴 coordinator。

## 如果它停下來（視窗顯示 `STOP:`）

記事本一樣會跳出來，內容只有兩行。照樣全選貼回即可，coordinator 會告訴您下一步。常見的幾種：

| 訊息 | 意思 |
|---|---|
| `STOP: something is listening on port 8000 …` | backend 還開著。關掉三個 stock-desk 視窗後重新雙擊 |
| `STOP: the database changed while copying …` | 複製期間資料庫有變動，代表還有服務在跑。關掉後重新雙擊 |
| `STOP: STOCK_DESK_DB_PATH is set …` | 您的資料庫不在預設位置。貼回這一行，coordinator 改用備用流程 |
| `STOP: stock-desk.db not found at the default location` | 預設位置找不到資料庫。貼回這一行 |

## `paste-back.txt` 裡幾個行的意思

- `gate_affected_symbols=`：N-177 部署閘門的受影響標的檔數。
- `n199_a_rows=`、`n199_b_rows=`、`n199_c_rows=`：三項事後檢查命中的列數。
- `script_sha256_lf=`：偵測工具本身的雜湊。coordinator 會核對它等於 `7ab9e89053a765a8abe1957a786cde06235fd1204626ce052a5a78abaa63faad`（第 2 版）。
- `probe_lines_dropped=`：偵測工具輸出中格式不符、被丟掉的行數，正常是 0。
- `probe_exit=`：偵測工具的結束碼，正常是 0。
- `N208_COUNT_RESULT=`：計數的結束碼，正常是 0；21 代表複本不是資料庫檔。
- `NON_INTEGER`：規則參數的值不是整數時顯示的固定文字（不會印出原值）。

## 回傳之後

- `gate_affected_symbols=0`：coordinator 開始準備 R2 的合併（N-177a 加 N-195），準備好之後通知您做第二次執行。
- `gate_affected_symbols` 大於 0：依風控 A-1 條件 1，N-177a 部署前由您逐檔在 (A)、(B) 之間選擇。coordinator 會把選項說明送給您；逐檔內容只在您本機的 `report.md`。
- `n199_*_rows` 任一個大於 0：coordinator 通知風控，並請您以券商對帳單核對對應的批次。這是事實核對，不是處置建議。
