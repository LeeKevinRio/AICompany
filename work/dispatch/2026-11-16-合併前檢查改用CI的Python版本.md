# 合併前檢查改用 CI 的 Python 版本

- 整理：devops-sre，2026-11-16。適用：product/stock-desk 的合併程序（修訂八「M 上 CI 等效檢查」）。

## 一、這次紅燈的原因

- 一鍵檔合併後，GitHub Actions run 314 的 backend job 失敗（`11997 passed, 1 failed`）。
- 失敗的是 `tests/test_pipeline_acceptance_real_bars.py::test_the_isolated_import_is_silent_and_loads_no_forbidden_module`，子行程結束碼 3。
- CI 用 Python 3.12（`.github/workflows/stock-desk.yml` 的 `python-version`），本機 venv 與歷次「CI 等效檢查」用 3.13。
- 3.12 的 `pathlib` 在模組頂層 `import urllib.parse`，3.13 不會；3.12 的 `email.utils` 也會載入 `socket`，3.13 不會。測試的執行期檢查把整個 `urllib` 與 `socket` 列為禁用，所以只在 3.12 失敗。
- 這是測試過嚴，不是腳本有網路呼叫。修法見 `fix/nm5-oneclick-py312-isolated-import`：執行期只禁會做網路 I/O 的模組，腳本原始碼的 AST 檢查不放鬆。

## 二、規則

修訂八的「M 上 CI 等效檢查」，一律用 CI 設定檔寫的 Python 版本，不得用本機預設的版本。只在別的版本通過，不算 CI 等效。

## 三、從 CI 設定檔讀出版本（不要抄死數字）

在 repo 根目錄執行：

```
PYV=$(grep -m1 'python-version' .github/workflows/stock-desk.yml | sed -E 's/.*"([0-9]+\.[0-9]+)".*/\1/')
echo "$PYV"
```

目前印出 `3.12`。若印不出數字（設定檔改了寫法），停下來人工看 `.github/workflows/stock-desk.yml`，不要沿用舊版本。

## 四、建環境與跑檢查（逐字）

在 `apps/stock-desk/backend` 下執行。`<ENVDIR>` 換成一個不在 worktree 內的目錄，不要覆蓋預設 `.venv`。

```
export UV_PROJECT_ENVIRONMENT=<ENVDIR>/venv-ci
uv sync --frozen --python /usr/bin/python3.12
"$UV_PROJECT_ENVIRONMENT/bin/python" -V
uv run --frozen --python /usr/bin/python3.12 ruff check .
uv run --frozen --python /usr/bin/python3.12 ruff format --check .
uv run --frozen --python /usr/bin/python3.12 mypy app tests
uv run --frozen --python /usr/bin/python3.12 pytest --cov=app --cov-report=term-missing --cov-fail-under=90
```

- 第三步 `-V` 必須印出與第三節 `PYV` 相同的 minor 版本。
- 解譯器路徑要跟 `PYV` 一致（`PYV` 改成別的版本時，把 `/usr/bin/python3.12` 換成對應路徑，例如 `/usr/bin/python$PYV`）。
- 四個指令與 `.github/workflows/stock-desk.yml` 的 backend job 一致；日後該 job 的步驟有變，這裡要同步。
