## 一、整體流程：兩段

1. **第一段：預檢檔 `cg2-preflight.bat`。** 它只讀取，不寫入任何東西到正式資料庫。您把它產生的回貼內容貼給 coordinator，由 coordinator 核對。
2. **第二段：登記檔 `cg2-register.bat`。** 要等 coordinator 核對完預檢回貼、通知您之後才執行。它會重跑全部預檢（含禁詞比對），核對最近一次的預檢回貼和這次的程式版本相符，然後依序：取得兩份備份並確認兩份完全相同、請您鍵入一個 0 或 1、呼叫登記程式，最後產生回貼內容。**整個登記流程裡，只有這一段的登記程式會寫入您的正式資料庫**（建立登記用的資料表並寫入兩列登記）；預檢檔不會寫入。

兩個檔都沒有上網的動作。

## 二、第一段：預檢，三個步驟

1. **收到 coordinator 通知之後，先雙擊 `apps\stock-desk\dev-up.bat` 一次**，讓本機更新到最新版並安裝需要的套件。確認三個 stock-desk 視窗正常開起來後，**把這三個視窗都關掉**（backend、scheduler、frontend）。
2. **雙擊 `apps\stock-desk\cg2-preflight.bat`**。視窗會要您確認三個視窗都關了（`Close the stock-desk backend, scheduler and frontend windows, then press Enter.`），**按一次 Enter**。
3. **記事本會自動跳出回貼檔。** 按 Ctrl+A 全選、Ctrl+C 複製，貼回給 coordinator。**只貼記事本裡的內容**。

回貼檔放在您使用者資料夾下的 `stock-desk-cg2-registration\paste-backs\preflight-<時間戳>.txt`（在 repo 之外）。登記檔會讀取這份檔案來核對，請不要修改、刪除、移動或改名 `paste-backs` 資料夾裡的任何檔案。

**預檢之後、登記完成之前，請不要執行 `dev-up.bat`。** `dev-up.bat` 會更新程式並重新啟動 stock-desk，登記時的程式版本就可能和 coordinator 核對過的預檢不同。這段期間若您需要使用 stock-desk 而執行了 `dev-up.bat`，請告訴 coordinator；登記之前要先把三個視窗關掉、重跑預檢並把新的回貼貼給 coordinator，等 coordinator 再次核對、通知之後才登記。

backend 或 scheduler 若是用 NSSM 或 Windows 工作排程器常駐（不是用 `dev-up.bat` 開的），先不要跑，告訴 coordinator。

## 三、第二段：登記，三個步驟

**先等 coordinator 通知。** 通知前請不要執行 `cg2-register.bat`。從預檢到這裡，請不要執行 `dev-up.bat`（見第二節）。

1. **確認三個 stock-desk 視窗都已關掉**（做法同上）。
2. **雙擊 `apps\stock-desk\cg2-register.bat`**，視窗會先要您確認視窗都關了，**按一次 Enter**。程式接著重跑預檢、核對最近一次的預檢回貼、做兩份備份，過程中不需要您操作。
3. **程式會請您鍵入「登記前是否看過暫定對照」**（畫面上的英文提示是：`Before this registration, have you seen any provisional comparison (whether any market outlook call turned out right or wrong, or how it compared with the baseline), from any source? Type 1 if you have, or 0 if you have not, then press Enter:`）。**只能鍵入 `1` 或 `0`，再按 Enter**：`1` 是看過，`0` 是沒看過。鍵入其他任何內容（包括多打的空白、空白行）程式都會停下來，不會登記。這個答案只問一次，沒有預設值。要填哪一個，請您自己依下面的說明如實判斷；coordinator 和其他任何人都不會替您決定。

### 登記時「是否看過暫定對照」（風控定稿）

> 正式登記時，程式會請您自己鍵入「登記前是否看過暫定對照」。暫定對照指任何一筆大盤判斷（偏多、偏空、震盪、證據不足）事後對不對，或和基準比較的結果。只看過這次一鍵檔的通過或失敗、失敗種類、執行次數、雜湊與環境檢查，不算看過暫定對照。但只要您從任何地方看過任何一筆判斷或對照（包括暫存資料夾裡的檔案、別人的轉述或其他報表），就請如實填「看過」，並告訴 coordinator。依目前的登記規則，填「看過」不會擋住登記，只會在日後的報告中照實揭露。

上面引文裡的「這次一鍵檔」，指先前的真實資料管線驗收一鍵檔。這次預檢檔與登記檔畫面上和回貼檔裡的內容（指紋、計數、檢查結果、時間），也都不算暫定對照。

鍵入之後程式會呼叫登記程式。完成時記事本會自動跳出回貼檔，按 Ctrl+A 全選、Ctrl+C 複製，貼回給 coordinator。**只貼記事本裡的內容**。回貼檔放在 `stock-desk-cg2-registration\paste-backs\register-<時間戳>.txt`。

登記完成之後不能再登記第二次：再執行登記檔會在預檢停下來。

## 四、備份放在哪裡、要怎麼處理

- 登記檔在呼叫登記程式**之前**，會先取得正式資料庫的兩份備份，放在您使用者資料夾下的 `stock-desk-cg2-registration\backups\`：`stock-desk-before-cg2-<時間戳>.db` 與 `stock-desk-before-cg2-<時間戳>-verify.db`（在 repo 之外；`stock-desk-cg2-registration` 和之前管線驗收用的 `stock-desk-pipeline-acceptance` 是兩個不同的資料夾）。程式會確認兩份完全相同才繼續；不同就停下來，不會登記。
- 這兩份備份是登記前的還原點。**程式不會刪除它們，您也請不要刪除、移動、改名、開啟或傳給任何人。** 它們含有您資料庫的完整內容（含持股與現金）。
- 回貼內容裡只有備份的指紋 `backup_sha256=`，沒有備份檔的位置。備份位置只寫在這份說明裡。coordinator 之後會把這個指紋與備份位置記下來（接線 PR 的 CG-3 備份也會用到）。
- 預檢檔不產生備份；只有登記檔會。登記檔若在備份之後停下來，備份仍然留在原處，畫面最後會多印一行 `backup_sha256=`，請一併告訴 coordinator。
- 若您的使用者資料夾整個放在 OneDrive 等雲端同步資料夾裡，備份可能做不成，備份檔也可能被同步上傳到雲端。請在執行預檢之前先告訴 coordinator，由 coordinator 提供做法；請不要為此自己關閉同步、防毒軟體或修改任何設定。

### 還原方式（只描述；請不要自己動手）

若日後需要回到登記前的狀態，會用備份取代目前的正式資料庫。還原必須在 stock-desk 的所有視窗與常駐服務都停止時進行，而且會讓資料庫回到備份當下的內容：登記之後您在 stock-desk 裡新增或修改的任何資料（含持股與現金的異動）都不會保留。還原時還要處理資料庫旁的暫存檔，做錯可能讓資料不一致，所以這裡不列步驟。要不要還原、用哪一份、怎麼還原，一律由 coordinator 與 tech-architect 決定，由 coordinator 先用回貼內容裡的 `backup_sha256=` 核對備份檔沒有變過，再一步一步告訴您。您不需要、也請不要自己還原。

## 五、讀資料庫的方式

預檢，以及登記檔在登記之前的檢查與備份，只用唯讀連線讀取資料庫：不寫入資料、不刪除、不改名，也不計算資料庫檔本身的雜湊。資料庫旁若原本就有 `-wal` 暫存檔，唯讀讀取時 SQLite 可能在旁邊另外產生一個 `-shm` 暫存檔；這是 SQLite 讀取時的正常行為，不是寫入資料，請不要刪除它。真正寫入資料庫的只有第二段裡的登記程式。登記程式即使拒絕登記，資料庫主檔的位元組也可能改變（見第六節的引文），所以請不要用檔案雜湊判斷資料庫有沒有被改動。請不要刪除或改動資料庫旁的任何檔案。

以下引文為風控定稿（RC-182）：

> 若登記被拒絕（結束碼 3 或 4），登記指令不會在資料庫裡新增、修改或刪除任何資料。但它在拒絕之前可能已經開過一次資料庫連線；關閉連線時，SQLite 可能把暫存檔（`-wal`）的內容併回資料庫主檔，所以主檔的位元組與雜湊值可能和執行前不同，資料內容不變。請不要用檔案雜湊判斷資料庫有沒有被改動。執行前取得的備份不受影響。被拒絕時請依一鍵檔畫面上的 STOP 指示處理，不要自行刪除或改動資料庫旁的任何檔案。

本節適用於上表那一行、第八節表格中寫著 `Do not run this again` 的每一行，以及「鍵入 0 或 1 並按 Enter 之後，視窗在出現任何結尾文字之前就消失或被關掉」（包括您按了 Ctrl+C 或關掉視窗）的情況。這些情況表示登記可能已經開始，但一鍵檔無法確認登記的結果：可能是登記程式已經寫入、但寫入之後的自我核對沒有通過；可能是一鍵檔無法核對登記程式的輸出；也可能是登記程式啟動之後發生錯誤、被中斷，或超過時間沒有結束。這時正式資料庫可能已經寫入登記內容，也可能沒有；一鍵檔無法判斷，所以不會告訴您資料目前是好是壞。您不需要自己判斷是哪一種情況。登記前做好的備份不受影響，仍然留在原處，是回到登記前狀態的還原點。

1. 不要再執行登記檔，也不要用任何其他方式重試。登記只能有一次，重跑會讓情況更難釐清。
2. 不要自己開啟、修改、移動、刪除或還原資料庫、資料庫旁的任何檔案、備份資料夾和回貼資料夾，也不要修改任何設定。在 coordinator 通知之前，先不要啟動 stock-desk，也不要執行 `dev-up.bat`。

## 八、如果它停下來：STOP 與 ERROR 對照表

視窗上若出現 `STOP:` 或 `ERROR:` 開頭的一行，表示程式停下來了：`STOP:` 是程式依設計主動停下，`ERROR:` 是預期之外的錯誤或中斷。請把下列各行照實告訴 coordinator：`STOP:` 或 `ERROR:` 開頭的每一行英文；之後若出現的 `refusal_reason=` 與 `backup_sha256=` 那幾行；以及最後 `[NOTE] The tool ended with code` 那一行裡的數字。然後照下表的「您要做的事」處理。最後的「請按任意鍵繼續」是固定的結尾文字，不必理會。**每一種情況都請不要自己修改任何設定或檔案**，包括環境變數、`.env`、git、Windows 服務、資料庫、備份資料夾和回貼資料夾，也不要自己安裝或更新任何程式。若那一行寫著 `Do not run this again`，請照第七節處理，**在 coordinator 通知之前先不要啟動 stock-desk**。其他情況停下來之後，若需要使用 stock-desk，可以照平常雙擊 `dev-up.bat` 啟動；但只要執行過 `dev-up.bat`，下次登記之前就要先重跑預檢並回貼（見第二節）；要重跑任何一個檔時，都先把三個視窗關掉。若出現的是 `[MISSING]` 或 `[ERROR]` 開頭的一行（中括號、沒有冒號），表示程式還沒開始執行，沒有讀取或寫入資料庫：請告訴 coordinator，不要依那一行的英文自己安裝任何程式。

## 九、預檢回貼檔裡各行的意思

- 第一行 `cg2_oneclick version=1` 是這支程式的版本，第二行 `mode=` 是 `preflight` 或 `register`。
- `script_sha256_lf=`、`git_head=`、`code_digest=`、`frozen_prereg_sha256=`、`frozen_c8_sha256=`、`frozen_h3_sha256=`、`frozen_h5_sha256=`、`definition_sha256=`、`definition_logic_sha256=`、`rules_sha256_h3=`、`rules_logic_sha256_h3=`、`rules_sha256_h5=`、`rules_logic_sha256_h5=`：用來核對程式、四個凍結檔案、定義與規則版本的指紋，coordinator 會核對。
- `git_clean=yes`、`core_autocrlf=`、`head_published=yes`、`app_unchanged=yes`、`eol_check=ok`、`attr_check=ok`、`hashes_pinned=ok`：程式版本與換行格式的檢查結果。
- `env_db_path=unset`、`db_location=default`、`port_8000_listening=no`、`ledger_objects=none`：資料庫與環境的檢查結果。
- `banned_phrase_scan_h3=`、`banned_phrase_scan_h5=`：禁詞比對的結果與比對的字串數、禁詞數。
- `preflight_result=PASS`：預檢的項目都成立。這只代表預檢的項目成立，不代表任何判斷規則準確或有效。
- `done_at_utc=`：這支程式跑完的時間（UTC）。

## 十、登記回貼檔裡各行的意思

- 開頭到 `ledger_objects=none` 的各行，意思同第九節。
- `backup_integrity=ok`、`backup_ledger_objects=none`：備份的完整性檢查結果，以及備份裡沒有 `forecast_` 或 `plan_` 開頭的物件。
- `backup_sha256=`：兩份備份相同的指紋。
- 接著是登記程式輸出的 16 行，由 `bootstrap=ok` 開始、`post_commit_check=ok` 結束：
  - `banned_phrase_scan_h3=`、`banned_phrase_scan_h5=`：登記程式自己做的禁詞比對；程式會核對這兩行和預檢算出的相同。
  - `registered_rows=2`：登記表的列數。
  - `frozen_commit=`、`prereg_doc_sha256=`：登記所用的程式版本與事先宣告的指紋。
  - `definition_sha256=`、`definition_logic_sha256=`、`rules_sha256_h3=`、`rules_logic_sha256_h3=`、`rules_sha256_h5=`、`rules_logic_sha256_h5=`：登記的定義與規則的指紋。
  - `registered_at_h3=`、`registered_at_h5=`：兩列登記寫入的時間。
  - `provisional_results_seen=`：您在第三節鍵入的 0 或 1。
  - `post_commit_check=ok`：寫入之後的核對結果。
- `register_result=DONE`：登記程式結束，且它的輸出和預期相符。這只代表兩列登記已寫入並通過格式與內容的核對，不代表任何判斷規則準確或有效，也不代表日後的判斷會對。`register_result=UNCONFIRMED` 表示登記的結果沒有確認，見第七節。
- `done_at_utc=`：這支程式跑完的時間（UTC）。

回貼內容只有固定文字、計數、指紋、程式版本與時間；沒有任何檔案位置，也沒有登記項目的識別代號。
