## 一、這是什麼

這是一項**另一項檢查，不是管線驗收**。它要回答一個問題：您電腦裡已經存下來的大盤日期，**少了哪幾個交易日**。

為什麼要做：預測紀錄帳的核心不會偵測「資料來源整天缺席」。在接上排程之前，先知道現有快取缺了哪些交易日。

它會碰到什麼：

1. 先檢查您的資料庫有沒有還在使用中；若在使用中，工具會停下來。沒有在使用，才把資料庫**複製一份**。複製期間資料庫若被改動，工具會停下來，見第十一節。
2. 複本裡有持股與現金，所以工具讀完日期，**馬上刪掉複本**，之後才上網。
3. 只從複本讀出**大盤的交易日期**，什麼都不多讀。不讀價格，不讀其他表。
4. 刪掉複本之後，才連到**證交所網站（`www.twse.com.tw`）**，下載官方交易日曆。**對外只連這一個網站。** 它每個月份連一次，最多 17 次，每次至少隔 8 秒。
5. 比對兩邊的日期，把結果印在畫面上，同時存成 `paste-back.txt` 並用記事本打開。

它不會做什麼：

- 不修改您的資料庫，不寫入快取。
- 不看任何預測、判斷或對照。
- 不補資料。

這一步在**正式登記完成之後**才會做。**執行時機由 coordinator 通知，沒收到通知之前請不要執行。** 執行前 coordinator 會另外正式請您確認幾件事；這份說明不取代那一次確認。

## 二、先讀這五點（對應 RC-224）

1. 這是**資料來源完整性檢查**，不是績效，也不代表規則好壞。
2. 查到缺日，**不需要您處理**。不要重抓資料、不要刪除快取、不要調整記錄時間。
3. 查到缺日，**照常開始記錄**。
4. 缺日之後的一段時間，那些紀錄日後**可能被判作廢**，並以不利於模型的方向計算。
5. 只檢查了部分月份時，**不代表資料完整**。

〔待風控定稿：以上五句字面。RC-224 要求風控核可後逐字套用。〕

## 三、步驟

**執行前**

1. 確認 coordinator 已通知可以執行。
2. 雙擊 `apps\stock-desk\dev-up.bat`，讓本機拉到最新版（要含這支工具）。〔待確認：`dev-up.bat` 在這支工具合併前，能不能讓您的電腦拿到它，我沒有確認。若不能，請改成 coordinator 提供的更新方式。沒更新到的話，工具會停在 `STOP: this code version is not on origin/product/stock-desk.`，見第十一節。〕
3. 三個 stock-desk 視窗（backend、scheduler、frontend）開起來之後，**把三個都關掉**。工具只偵測得到 backend 還開著，scheduler 與 frontend 它看不到，所以請您自己確認三個都關了。

backend 或 scheduler 若是用 NSSM 或 Windows 工作排程器常駐（不是用 `dev-up.bat` 開的），先不要跑，告訴 coordinator。

**執行**

4. **雙擊 `apps\stock-desk\gap-check.bat`。**
5. 畫面會出現這一句英文：

   `Close the stock-desk backend, scheduler and frontend windows, then press Enter.`

   意思是「請關閉三個 stock-desk 視窗，然後按 Enter」。三個視窗都關了，就**按一次 Enter**。
6. **接下來要等約 3 到 5 分鐘（尚未實測，可能更久）。** 工具要向證交所一個月一個月地抓日曆，每次之間至少隔 8 秒。**這段時間畫面不會有任何新的輸出，也沒有進度提示，畫面停著不動是預期的情形。請不要關視窗，也不要按任何鍵。** 您的資料庫複本在這段時間裡已經刪除。〔待風控定稿：等待說明的字面。〕
7. 抓完、比對完之後，畫面會印出結果，**記事本會自動跳出 `paste-back.txt`**。

## 四、結束後要做的事

1. 在記事本按 Ctrl+A 全選、Ctrl+C 複製。
2. **整段貼回給 coordinator。** 只貼記事本裡的內容，不要截圖，也不要貼整個黑色視窗。
3. 資料夾不要動。暫存資料放在您使用者資料夾下的 `stock-desk-gap-check\<時間戳>\`（在 repo 之外），程式跑完只會留下 `paste-back.txt`。**這個資料夾裡的任何東西，請都不要開啟、搬動或刪除。**（只有第十二節那一句 STOP 出現時，才依該節處理。）
4. **畫面上看到 `result=`，就代表資料庫複本已經刪除。** 只有看到「複本刪不掉」那一句 `STOP`（第十二節），才需要處理複本。工具不會另外顯示「已刪除」的訊息；它清掉前一次殘留的複本時，也不會顯示任何訊息。
5. 每一次執行，都要貼回完整內容，不管結果是哪一個代號。每次執行會新開一個資料夾，不會覆蓋舊的。
6. 貼完之後，就可以照平常再雙擊 `dev-up.bat` 啟動 stock-desk。

**如果記事本沒有自動跳出來**：請直接告訴 coordinator「記事本沒有自動打開」，不要自己去找檔案。要不要開啟並貼回，由 coordinator 告訴您。

視窗裡可能出現少數不是這支工具印出的系統文字，例如您按 Ctrl+C 時出現的「^C」或「要終止批次工作嗎 (Y/N)?」。這些不是檢查結果。要貼回的只有記事本裡的內容。

## 五、四個結果代號的意思（最後一行 `result=`）

結果代號由程式依固定順序判定，取第一個成立的。**四個代號都不是用來評分的，也不是績效。**

### `no_gaps_found`

- **代表**：檢查期間的**每一個月**都取得了官方日曆；快取涵蓋範圍內，兩邊的日期完全對得上；而且「快取未涵蓋」那一組是空的。
- **不代表**：
  - **不代表資料正確。** 這項檢查只比日期，沒有看任何價格。
  - 不代表規則好壞，也不代表之後不會缺日。
  - 不代表可以省略其他檢查。
- 之後：照常進行，沒有需要您做的事。

### `no_gaps_in_checked_months`

- **代表**：已檢查的月份裡，沒有找到缺日；但**有一些月份沒檢查到**，或**有一些日期落在快取涵蓋範圍之外**（見第六、七節），或兩者都有。
- **不代表**：**不代表沒有缺日。** 沒檢查到的月份、落在涵蓋範圍之外的日期，這次比對都沒有辦法判斷。**也不代表資料完整。**
- 之後：照常進行。您不需要自己補檢查、補抓或重跑。`months_unchecked=` 後面若不是 `none`，是否再跑一次由 coordinator 判斷，見第八節。

### `gaps_found`

- **代表**：下面兩組日期**至少有一組不是空的**：
  - `official_not_in_cache_*`：官方日曆有、快取沒有的日期；
  - `cache_not_in_official_*`：快取有、官方日曆沒有的日期（這一組不一定是缺日，見第七節第 1、2 點）。
- **不代表**：不代表您需要處理；不代表規則有問題；不代表缺日一定是您的操作造成的；也不代表只檢查到這些，因為未檢查的月份仍然沒有結果。
- **之後會發生什麼**：
  - **照常開始記錄。不要手動補資料，不要重抓、刪除快取，也不要調整記錄時間。**
  - coordinator 會把代號、缺日天數與日期登錄成「知悉事項」。
  - 缺口之後，約 120 筆紀錄的輸入會跨過缺口，日後可能被判作廢，計入作廢率，並以不利於模型的方向計算。〔待確認：此句是依 RC-225 與 RC-224 ④ 改寫，不是逐字；見備註 (3) 第 1、2 項。〕
  - 這個結果不重跑。
  - 在任何地方，都不會把這份資料描述成「資料完整」。

### `calendar_unavailable`

- **代表**：每一個月的官方日曆都沒取到（例如連不上證交所網站，或網站的回應工具讀不懂），所以**沒有做比對**。
- **不代表**：它對您的資料沒有說任何事，缺日或沒缺日都無從得知。
- 之後：這一次的結果照樣貼回，照樣存檔。**是否再跑一次，由 coordinator 判斷，您不要自己決定**，見第八節。

## 六、畫面與回貼檔的每一行

畫面與 `paste-back.txt` 內容逐行相同，共 17 行，順序固定。差別只有：畫面第一行多印一句提示語，`paste-back.txt` 沒有。日期清單是一長行，用逗號分隔；沒有就印 `none`。

| `git_head=` | 您電腦上程式版本的指紋（40 碼），coordinator 核對用，您不需要理解 |
| `script_sha256_lf=` | 工具內容的指紋，同上 |

| `months_checked=` | 成功取得官方日曆的月份 |

## 七、讀結果時要注意的五件事

〔待風控定稿：本節五點的字面。意思取自 data-engineer 資料面審查第九節，我改寫成給 CEO 讀的話，沒有改變意思。〕

1. **`cache_not_in_official`（快取有、官方沒有）不等於缺日。** 它是快取比官方多出來的日期。可能的原因之一，是資料來源在休市日多給了一列（這是推測，沒有實測過）。如果這份清單只有檢查期間最後一天（`period_end`）這一個日期，也可能是官方當月資料還沒有含那一天。只要這份清單不是空的，結果代號就會是 `gaps_found`，請不要因此把它讀成缺日。如果只有最後一天，coordinator 會在回覆中註明「可能是官方當月資料還沒有含那一天」；結果代號照原樣，也不會因此請您再跑。
2. **兩份清單成對出現、日期相差一天，可能不是真的缺那麼多天。** 如果「官方有、快取沒有」與「快取有、官方沒有」兩份清單都不是空的，而且日期都彼此相差一天，可能是資料來源的日期整段偏移了一天（這是推測，沒有實測過）。這不是缺了那麼多天。
3. **快取頭尾沒有涵蓋到的日子，算在「快取未涵蓋」，不算缺日。** 其中**尾端**（最近幾個交易日）若沒有涵蓋，會影響之後的記錄。尾端有沒有被涵蓋，看 `cache_range_end=` 是不是早於 `period_end=`；coordinator 會在回覆中另外寫明。頭端同理，看 `cache_range_start=` 是不是晚於 `period_start=`。
4. **快取完全沒有這段期間的資料時，所有官方交易日都會列在「快取未涵蓋」，缺日清單是空的，這不代表沒有缺日。** 此時結果代號可能不是 `gaps_found`。
5. **執行要等幾分鐘。** 約 3 到 5 分鐘，期間畫面沒有任何新輸出，見第三節步驟 6。

## 八、要不要再跑一次（重跑規則）

〔待風控定稿：本節字面。意思取自補充十第 7 點 (d)。〕

**要不要再跑一次，由 coordinator 判斷，您不要自己決定。** 沒收到 coordinator 請您再跑的通知，請不要自己再雙擊 `gap-check.bat`，也不要因為結果不如預期而再跑。

只有下面兩種情形，coordinator 才可能請您再跑：

- 結果是 `calendar_unavailable`；
- `months_unchecked=` 後面不是 `none`。

其他結果（包括 `gaps_found`）都不重跑。

再跑時有這些界線：

1. 兩次有結果的執行之間，**至少隔 1 小時**。
2. **最多跑出 3 次結果。**
3. **每一次的結果都會被逐字存檔，後一次不會取代前一次。** 前一次列出的日期，不會因為後一次沒有列出而不算。
4. 以 `STOP` 或 `ERROR` 結束、而且沒有 `result=` 的那幾次，**不算在這 3 次內**。排除原因後可以再執行；怎麼排除，照第十一節。畫面上同時有 `ERROR` 句與 `result=` 的，因為有結果，算一次。
5. 再跑的目的只是補齊沒取到的月份，不是跑到出現比較好的結果為止，見第九節。

## 九、這次結果不會被用來做什麼

結果只用來讓大家知道現有快取缺了哪些日期。**不得**用在：

- 手動重抓、修改或刪除快取；
- 延後、提前或挑選第一筆紀錄的時點，包括延後或提前接線的合併；
- 修改規則、定義或事先宣告；
- 重跑到出現比較好看的結果為止。

正常排程照常運作。〔待風控定稿：以上是補充八第 5 點 (h) 與 RC-228 的白話改寫，非逐字。〕

這一步是接線前的前置條件；**任何一個結果代號（包括 `calendar_unavailable`）都不會擋住接線。**
