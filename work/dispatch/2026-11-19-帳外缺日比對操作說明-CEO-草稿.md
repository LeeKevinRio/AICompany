### (3) 仍然拿不準的地方與替代寫法

**coordinator 定案，請風控確認（CEO 可推翻）：**

1. **取得 `gap-check.bat` 的方式。** 寫「coordinator 會另外通知您何時可以執行；收到通知後先照平常的方式更新程式（`dev-up.bat`），再執行」，〔待確認〕標記保留到工具合併為止。

3. **複本刪不掉時：先告訴 coordinator，等 coordinator 確認先前各次的內容都已存檔，再刪除整個資料夾。** 舊的回貼檔會一起被刪，所以第四節要求每次結束後立刻貼回，不要累積。
   - 我的疑慮：這個順序讓含持股與現金的複本在磁碟上多留一段時間，也與固定句（`Remove the whole work folder without opening it, do not send it to anyone, and tell the coordinator.`，先刪、再告訴）及前例 11-16 的順序相反。複本在 CEO 自己的電腦上，不在外部，所以我不認為必須擋，但請風控判斷。

## 一、這是什麼

這是一項**另一項檢查，不是管線驗收**。它要回答一個問題：您電腦裡已經存下來的大盤日期，**少了哪幾個交易日**。

為什麼要做：預測紀錄帳的核心不會偵測「資料來源整天缺席」。在接上排程之前，先知道現有快取缺了哪些交易日。

它會碰到什麼：

1. 先檢查您的資料庫有沒有還在使用中的跡象；有的話，工具會停下來。沒有偵測到這類跡象，才把資料庫**複製一份**。複製期間若偵測到資料庫被改動，工具也會停下來，見第十一節。這些偵測不保證抓得到所有情形，所以仍請您先關閉三個 stock-desk 視窗。
2. 複本裡有持股與現金，所以工具讀完日期，**馬上刪掉複本**，之後才上網。
3. 只從複本讀出**大盤的交易日期**，什麼都不多讀。不讀價格，不讀其他表。
4. 刪掉複本之後，才連到**證交所網站（`www.twse.com.tw`）**，下載官方交易日曆。**對外只連這一個網站。** 它每個月份連一次，依執行日不同，共連 17 或 18 次，每次至少隔 8 秒。
5. 比對兩邊的日期，把結果印在畫面上，同時存成 `paste-back.txt` 並用記事本打開。

它不會做什麼：

- 不修改您的資料庫，不寫入快取。
- 不看任何預測、判斷或對照。
- 不補資料。

這一步在**正式登記完成之後**才會做。**執行時機由 coordinator 通知，沒收到通知之前請不要執行。** 執行前 coordinator 會另外正式請您確認幾件事；這份說明不取代那一次確認。

## 二、先讀這五點（對應 RC-224）

1. 這是**資料來源完整性檢查**，不是績效，也不代表規則好壞。
2. 查到缺日，**不需要您處理**。不要重抓資料、不要刪除快取、不要調整記錄時間。
3. 查到缺日，**照常開始記錄**。
4. 缺口如果落在近期，開始記錄後一段時間內寫下的紀錄，日後**可能被判作廢**，並以不利於模型的方向計算：這些作廢只會讓日後的驗證結果看起來比較差，不會讓它看起來比較好。
5. 只檢查了部分月份時，**不代表資料完整**。



## 三、步驟

**執行前**

1. **coordinator 會另外通知您何時可以執行。** 沒收到通知之前，請不要執行。
2. 收到通知後，**先照平常的方式更新程式（雙擊 `apps\stock-desk\dev-up.bat`），再執行。** 〔待確認：`dev-up.bat` 在這支工具合併前，能不能讓您的電腦拿到它，尚未確認；工具合併之前保留此標記。沒更新到的話，工具會停在 `STOP: this code version is not on origin/product/stock-desk.`，見第十一節。〕
3. 三個 stock-desk 視窗（backend、scheduler、frontend）開起來之後，**把三個都關掉**。工具只偵測得到 backend 還開著，scheduler 與 frontend 它看不到，所以請您自己確認三個都關了。

backend 或 scheduler 若是用 NSSM 或 Windows 工作排程器常駐（不是用 `dev-up.bat` 開的），先不要跑，告訴 coordinator。

**執行**

4. **雙擊 `apps\stock-desk\gap-check.bat`。**
5. 畫面會出現這一句英文：

   `Close the stock-desk backend, scheduler and frontend windows, then press Enter.`

   意思是「請關閉三個 stock-desk 視窗，然後按 Enter」。三個視窗都關了，就**按一次 Enter**。
6. **按 Enter 之後，畫面通常有約 3 到 5 分鐘沒有任何新文字，這是正常的；網路不順時會更久。** 這段時間工具主要在向證交所一個月一個月地抓日曆，沒有進度提示。**請不要關閉視窗，也不要按 Ctrl+C。** 工具在開始抓日曆之前，就已經刪除資料庫複本；刪不掉時會停下來，並顯示第十二節那一句。
7. **等到畫面出現 `result=` 那一行，或出現 `STOP:`、`ERROR:` 開頭的一行，才算結束。** 按 Enter 之後超過 15 分鐘仍沒有任何新文字時，**不要自己關閉視窗或重跑，請告訴 coordinator，等它回覆。** 15 分鐘不是工具保證的完成時間，只是請您告訴 coordinator 的時點。出現 `result=` 時，記事本應該會自動打開 `paste-back.txt`；沒有打開時，見第四節。

## 四、結束後要做的事

1. 在記事本按 Ctrl+A 全選、Ctrl+C 複製。
2. **整段貼回給 coordinator。** 只貼記事本裡的內容，不要截圖，也不要貼整個黑色視窗。
3. 資料夾不要動。暫存資料放在您使用者資料夾下的 `stock-desk-gap-check\<時間戳>\`（在 repo 之外），程式跑完只會留下 `paste-back.txt`。**這個資料夾裡的任何東西，請都不要開啟、搬動或刪除，也不要自己刪除或改動資料庫旁的任何檔案。**（只有第十二節那一句 STOP 出現時，才依該節處理。）
4. **畫面上看到 `result=`，而且之後沒有 `STOP:` 開頭的行，才代表資料庫複本已經刪除。** 結果之後若出現「複本刪不掉」那一句，以那一句的指示為準（第十二節）。工具不會另外顯示「已刪除」的訊息；它清掉前一次殘留的複本時，也不會顯示任何訊息。
5. **每一次執行結束後，都要立刻把記事本內容貼回給 coordinator，不要累積到下一次。** 不管結果是哪一個代號，都要貼回完整內容。每次執行會新開一個資料夾，不會覆蓋舊的。
6. **每一次出現的 `STOP:`、`ERROR:` 行，都要告訴 coordinator，即使之後再執行成功也一樣。** 因為停下來的那一次不會產生回貼檔，coordinator 要靠您告訴它才能存檔。
7. 貼完之後，就可以照平常再雙擊 `dev-up.bat` 啟動 stock-desk。

**如果記事本沒有自動跳出來**：請直接告訴 coordinator「記事本沒有自動打開」，不要自己去找檔案。要不要開啟並貼回，由 coordinator 告訴您。

視窗裡可能出現少數不是這支工具印出的系統文字，例如您按 Ctrl+C 時出現的「^C」或「要終止批次工作嗎 (Y/N)?」。這些不是檢查結果。要貼回的只有記事本裡的內容。

## 五、四個結果代號的意思（最後一行 `result=`）

結果代號由程式依固定順序判定，取第一個成立的。**四個代號都不是用來評分的，也不是績效。**

### `no_gaps_found`

- **代表**：檢查期間的**每一個月**都取得了官方日曆；快取涵蓋範圍內，兩邊的日期完全對得上；而且「快取未涵蓋」那一組是空的。
- **不代表**：
  - **不代表資料正確。** 這項檢查只比日期，沒有看任何價格。
  - 不代表規則好壞，也不代表之後不會缺日。
  - 不代表可以省略其他檢查。
- 之後：照常進行，沒有需要您做的事。

### `no_gaps_in_checked_months`

- **代表**：已檢查的月份裡，沒有找到缺日；但**有一些月份沒檢查到**，或**有一些日期落在快取涵蓋範圍之外**（見第六、七節），或兩者都有。
- **不代表**：**不代表沒有缺日。** 沒檢查到的月份、落在涵蓋範圍之外的日期，這次比對都沒有辦法判斷。**也不代表資料完整。**
- 之後：照常進行。您不需要自己補檢查或補抓。`months_unchecked=` 後面若不是 `none`，coordinator 會依第八節請您再跑；跑到第 3 次之後仍有未檢查的月份，就不再跑，**未檢查不代表沒有缺日**。

### `gaps_found`

- **代表**：下面兩組日期**至少有一組不是空的**：
  - `official_not_in_cache_*`：官方日曆有、快取沒有的日期；
  - `cache_not_in_official_*`：快取有、官方日曆沒有的日期（這一組的讀法，見第七節第 1 點）。
- **不代表**：不代表您需要處理；不代表規則有問題；不代表缺日一定是您的操作造成的；也不代表只檢查到這些，因為未檢查的月份仍然沒有結果。
- **之後會發生什麼**：
  - **照常開始記錄。不要手動補資料，不要重抓、刪除快取，也不要調整記錄時間。**
  - coordinator 會把代號、缺日天數與日期登錄成「知悉事項」。
  - 缺口若落在近期，開始記錄後一段時間內寫下的紀錄，輸入會跨過缺口，日後可能被判作廢、計入作廢率，並以不利於模型的方向計算。受影響的筆數依缺口的位置而定，可能多達數百筆，目前無法事先確定。
  - `months_unchecked=` 若是 `none`，這個結果不重跑；若不是 `none`，見第八節。
  - 在任何地方，都不會把這份資料描述成「資料完整」。

### `calendar_unavailable`

- **代表**：每一個月的官方日曆都沒取到（例如連不上證交所網站，或網站的回應工具讀不懂），所以**沒有做比對**。
- **不代表**：它對您的資料沒有說任何事，缺日或沒缺日都無從得知。
- 之後：這一次的結果照樣貼回，照樣存檔。coordinator 會依第八節請您再跑；跑到第 3 次之後仍取不到，就不再跑，**未檢查不代表沒有缺日**。

## 六、畫面與回貼檔的每一行

畫面與 `paste-back.txt` 內容逐行相同，共 17 行，順序固定。差別只有：畫面第一行多印一句提示語，`paste-back.txt` 沒有。日期清單是一長行，用逗號分隔；沒有就印 `none`。

| 行首鍵名 | 意思 |
|---|---|
| `gap_check version=1` | 這支工具的版本。這一版輸出的所有計數與日期，讀的都是您電腦裡**快取的現況** |
| `git_head=` | 您電腦上程式版本的指紋（40 碼），coordinator 核對用，您不需要理解 |
| `script_sha256_lf=` | 工具內容的指紋，同上 |
| `calendar_source=` | 官方日曆的來源代號，固定是 `twse_mi_5mins_hist`（證交所） |
| `period_start=`、`period_end=` | 檢查期間：執行日前 500 天，到執行日的前一天 |
| `months_checked=` | 成功取得官方日曆的月份 |
| `months_unchecked=` | 沒取到官方日曆的月份。照實列出，不推估，也不用別的來源補。這些月份**沒有被檢查**；不論原因是連不上網站，還是工具讀不懂網站的回應，都**不代表那幾個月沒有缺日** |
| `cache_range_start=`、`cache_range_end=` | 檢查期間內，您的快取裡大盤最早與最晚的交易日；沒有就是 `none` |
| `cache_not_covered_count=`、`cache_not_covered_dates=` | 「快取未涵蓋」的筆數與日期。**這一組不算缺日，但也不代表沒有缺日**，見下一段與第七節 |
| `official_not_in_cache_count=`、`official_not_in_cache_dates=` | 官方日曆有、快取沒有的日期（限快取涵蓋範圍內） |
| `cache_not_in_official_count=`、`cache_not_in_official_dates=` | 快取有、官方日曆沒有的日期（只比對已檢查的月份），讀法見第七節第 1 點 |
| `result=` | 結果代號，見第五節 |

**「快取未涵蓋」為什麼不算缺日**：這組日期是官方有交易、但落在您快取的最早與最晚日期之外。原因可能是快取還沒抓到那一段（例如最近幾天），也可能是來源缺日，**程式沒有辦法分辨**。所以這一組單獨列出，**不會讓結果變成 `gaps_found`**。這也**不代表它沒有問題**，只代表這一次無法判斷。

## 七、讀結果時要注意的五件事



1. **`cache_not_in_official`（快取有、官方沒有）不是「快取少了某一天」，而是快取比官方多出來的日期；日後驗證時，它和缺日一樣處理。** 可能的原因之一，是資料來源在休市日多給了一列（這是推測，沒有實測過）。如果這份清單只有檢查期間最後一天（`period_end`）這一個日期，也可能是官方當月資料還沒有含那一天；coordinator 會在回覆中註明「可能為官方當月資料尚未含該日」。這些都只是可能的原因，不是結論：這些日期照常列在計數與日期中，不會被扣除，也不能當成可以忽略。只要這份清單不是空的，結果代號就會是 `gaps_found`，請不要自己判斷它是什麼原因。結果代號照原樣，也不會因為只有最後一天而請您再跑。
2. **兩份清單成對出現、日期彼此相差一天時。** 如果「官方有、快取沒有」與「快取有、官方沒有」兩份清單都不是空的，而且日期都彼此相差一天，可能是資料來源的日期整段偏移了一天（這是推測，沒有實測過）。這不代表問題比較小：兩份清單照常列在計數與日期中，原因由 coordinator 與 data-engineer 判斷，請不要自己判斷。
3. **快取頭尾沒有涵蓋到的日子，算在「快取未涵蓋」，不算缺日，但「未涵蓋」不是「沒有缺日」。** 其中**尾端**（最近幾個交易日）若沒有涵蓋，那幾天是沒有被檢查的，可能影響之後的記錄。尾端有沒有被涵蓋，看 `cache_range_end=` 是不是早於 `period_end=`；coordinator 會在回覆中另外寫明。頭端同理，看 `cache_range_start=` 是不是晚於 `period_start=`。**請不要為了讓快取更新而開啟 stock-desk 再重跑；那不是第八節允許的重跑，coordinator 也不會請您這麼做。**
4. **快取完全沒有這段期間的資料時，所有官方交易日都會列在「快取未涵蓋」，缺日清單是空的，這不代表沒有缺日。** 此時結果代號可能不是 `gaps_found`。
5. **執行要等幾分鐘。** 通常約 3 到 5 分鐘沒有任何新文字，網路不順時可能更久，見第三節步驟 6。

## 八、要不要再跑一次（重跑規則）



**要不要再跑，由 coordinator 通知，您不要自己決定。** 沒收到 coordinator 請您再跑的通知，請不要自己再雙擊 `gap-check.bat`。本節講的是畫面已經出現 `result=` 之後的再跑；停在 `STOP:` 開頭的一行時，依第十一節那一句的「您要做的事」處理。

只有下面兩種情形，才會請您再跑：

- 結果是 `calendar_unavailable`；
- `months_unchecked=` 後面不是 `none`。

其他結果（包括沒有未檢查月份的 `gaps_found`）都不重跑。

**符合上面兩種情形時，coordinator 一律會請您再跑，不是看了已列出的日期之後才決定要不要跑。** 會一直請您跑，直到沒有未檢查的月份，或有結果的執行達 3 次為止。您若決定不跑，coordinator 會照實記錄。

再跑時有這些界線：

1. 兩次有結果的執行之間，**至少隔 1 小時**。
2. **最多跑出 3 次結果。**
3. **第 3 次之後仍有未檢查的月份（含 `calendar_unavailable`），就不再重跑，也不會換其他日曆來源或工具。** 未檢查的月份照實列為未檢查，**未檢查不代表沒有缺日**。接線的時點不會因此改變。
4. **每一次的結果都會被逐字存檔，後一次不會取代前一次。** 前一次列出的日期，不會因為後一次沒有列出而不算。**coordinator 不會把幾次結果合起來另外給一個結論**，只會逐次列出每一次的結果代號。
5. 以 `STOP` 或 `ERROR` 結束、而且沒有 `result=` 的那幾次，**不算在這 3 次內**，排除原因後可以再執行；但每一次的 `STOP:`／`ERROR:` 行都要先告訴 coordinator（第四節第 6 點）。畫面上同時有 `ERROR` 句與 `result=` 的，因為有結果，算一次。
6. 再跑的目的只是補齊沒取到的月份，不是跑到出現比較好的結果為止，見第九節。

## 九、這次結果不會被用來做什麼

結果只用來讓大家知道現有快取缺了哪些日期。**不得**用在：

- 手動重抓、修改或刪除快取；
- 延後、提前或挑選第一筆紀錄的時點，包括延後或提前接線的合併；
- 修改規則、定義或事先宣告；
- 重跑到出現比較好看的結果為止。



這一步是接線前的前置條件；**任何一個結果代號（包括 `calendar_unavailable`）都不會擋住接線。**

## 十、存檔與「是否看過暫定對照」

coordinator 會把您貼回的內容**逐字存檔**，不會丟棄、覆蓋或只挑一份；重跑會另開新檔。存檔時會附一行固定說明：

> CEO 看過帳外缺日比對的日期與計數，不含標籤或暫定對照，不構成 D-1 第 2 點的看過暫定對照。

白話：這次畫面與回貼檔上只有日期與計數，沒有任何預測、判斷或對照，所以這次的內容本身不算暫定對照。您是否從其他地方看過任何一筆判斷或對照，仍請如實告訴 coordinator；日後若有需要回答「是否看過」的問題，請依您自己的實際情況回答。

## 十一、如果它停下來：STOP 與 ERROR 對照表

視窗上若出現 `STOP:` 或 `ERROR:` 開頭的一行，表示工具停下來了。`STOP:` 是工具依設計主動停下，`ERROR:` 是預期之外的錯誤或中斷。**只要畫面上沒有 `result=`，就沒有完成比對，不會產生回貼檔，記事本也不會跳出來。** 接在後面的 `[NOTE] The tool ended with code` 那一行與「請按任意鍵繼續」是固定的結尾文字，不必理會。若出現的是 `[MISSING]` 或 `[ERROR]` 開頭的一行（中括號、沒有冒號），表示工具還沒開始執行，沒有讀取您的資料庫：請把那一行告訴 coordinator，**不要依那一行的英文自己安裝或更新任何程式**。

**請把 `STOP:` 或 `ERROR:` 開頭的每一行英文都告訴 coordinator，即使之後再執行成功也一樣**，並照下表的「您要做的事」處理。有時會連續出現兩行；只要其中有 `STOP: the database copy could not be deleted` 開頭的那一行，代表您電腦上還留著資料庫的完整複本（含持股與現金），請先照第十二節的做法處理，另一行要您做的事（包括重新雙擊 `gap-check.bat`）先不要做，等 coordinator 回覆。

**每一種情況都請不要自己修改任何設定或檔案**，包括環境變數、`.env`、git、Windows 服務、資料庫、資料庫旁的任何檔案與暫存資料夾，也不要自己安裝或更新任何程式；本說明明確請您做的事除外。也不要開啟您使用者資料夾下的 `stock-desk-gap-check` 資料夾。停下來之後，可以照平常雙擊 `dev-up.bat` 啟動 stock-desk；要再執行時，先把三個視窗關掉。

下表共 16 句。

| 視窗上的那一行 | 意思 | 您要做的事 |
|---|---|---|
| `STOP: STOCK_DESK_DB_PATH is set in the environment.` | 環境變數 `STOCK_DESK_DB_PATH` 有設定，資料庫位置可能不是預設位置，工具無法確定要讀哪一個檔。 | 告訴 coordinator，由 coordinator 提供其他做法；不要自己刪除或修改這個環境變數。不要自己修改任何設定或檔案。 |

## 十二、出現「資料庫複本沒能刪除」那一句時

> 這個資料夾裡有您資料庫的完整複本（含持股與現金）。程式沒能把它刪掉。請不要開啟，也不要傳給任何人。若這一次記事本已經自動打開了 `paste-back.txt`，請先照第四節把記事本裡的內容整段貼回給 coordinator；然後直接刪除整個資料夾，再告訴 coordinator。



要刪除的是您使用者資料夾下的整個 `stock-desk-gap-check` 資料夾（裡面的時間戳子資料夾一併刪除）。**舊的回貼檔會一起被刪，所以請每一次執行結束後都先把記事本內容貼回給 coordinator（第四節），不要累積。** 做法：在檔案總管開啟您的使用者資料夾，選取 `stock-desk-gap-check` 資料夾本身（不要點進去），按 Shift+Delete 永久刪除，不要只丟進資源回收筒；若已經丟進資源回收筒，請清空資源回收筒。刪不掉時，不要再嘗試其他方式，直接告訴 coordinator。

## 十三、尚未實測的事項

下列部分**沒有實測過**：

- **等待時間。** 「約 3 到 5 分鐘」與「超過 15 分鐘就告訴 coordinator」都是依程式裡的常數推算的，沒有在真實網路上量過。一般情況的算式是「每次間隔 8 秒，共 16 或 17 個間隔，再加每次請求本身花的時間」。抓日曆這一段，若假設每次請求最多花 30 秒，最壞約 14 分鐘；但工具對整次執行沒有設總時限，所以沒有一定會結束的時間。
- `gap-check.bat` 本身（視窗執行、`pause`、找 `uv`）。
- 自動開啟記事本。
- Windows 上刪除複本時的檔案鎖定與防毒軟體行為。

- 證交所網站的**真實回應格式與限流狀況**：data-engineer 只做過 5 次請求，沒有跑過連續 17 或 18 次、間隔 8 秒的情形。工具的設計是：實際回應與預期不同時，該月份列為「未檢查」，不當成缺日；這一點沒有在真實網站上驗證過。
