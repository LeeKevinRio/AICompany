# 任務單 F-8：未持有標的個股頁每次產生 console 404（2026-10-08，coordinator 立案）

- **狀態**：spec（低優先；2026-10-12 tech-architect 評估完成，採方案 (a)）
- **起因**：第三十一輪 qa-e2e 偏差 4（`work/reviews/2026-10-08-第三十一輪-RK4c報價呈現判斷-e2e驗收.md`）；第三十輪亦見。
- **事實**：未持有標的的個股頁（例 `/position/AAPL?market=US`）每次載入發出 `/api/leverage/AAPL?market=US`，後端無持倉時回 404（`apps/stock-desk/backend/app/api/leverage.py` 約 L92，設計如此）；前端 `position/[symbol]/page.tsx` 約 L97-101 以 `leverageNotFound` 當安靜備註處理，畫面無錯誤，但瀏覽器記為 console error。
- **影響**：使用者畫面無影響；但使 UI 驗收的「console 乾淨」判準失真（每輪 e2e 須逐案判讀）。
- **可選解法**（須 product-manager 或 tech-architect 評估，可能動 API 契約）：(a) 前端對未持有標的略過 leverage 查詢；(b) 後端改回 200＋空狀態（契約變更，須 tech-architect 出 ADR 判斷）。
- **流程**：product-manager／tech-architect 評估 → 實作（frontend-engineer 或 dev-lead）→ qa-reviewer → qa-e2e。不涉使用者字面則不需風控。

## tech-architect 評估（2026-10-12，唯讀；coordinator 轉錄）
- **結論：採 (a) 前端依 positions 判定持有後才發 leverage 查詢**；不採 (b)（後端改 200／204 屬契約變更須 ADR，且推翻 `leverage.py` docstring 明載設計）；(c1) 讓 404 不記為 console error 在頁面 JS 層不可行（Chromium 網路層自行輸出，無法攔截；Firefox／WebKit 未驗證）；(c2) e2e 白名單會使判準失真，不採；(c3) 以 `advice.data.held` 為閘門口徑無證據一致，不採。
- 不需 ADR（契約不變）、不需風控（404 路徑原無使用者面字面，本案零新字面）。
- **畫面影響**：最終畫面零變化；持有頁槓桿專章出現時間晚一個 positions 往返（本機 SQLite，量級小）。
- **現況要點**：`page.tsx` L101 無條件發 `useLeverageChapter(symbol, market, true)`，與 L97 `usePositions(true)` 並行；404 時不渲染任何東西（L576、L579、`PageFooterDisclosures.tsx` L50 過濾空組），後端 detail 字串未被渲染。前端無測試釘住 404 分支；後端 `test_api_leverage.py` L177-180 釘 404。
- **關鍵風險**：持倉判定口徑須鏡像後端 `_pick_position`（`leverage.py` L61-77：代號 trim＋大小寫不敏感、market 嚴格相等、不看數量／成本／幣別）。**不得沿用 `resolveKeyLevelsAnchor`**（大小寫敏感、幣別不符回 `close-unknown`，會使持有者誤失專章）。
