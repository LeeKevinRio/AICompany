## 風險判斷
1. **D2 實際風險**：close=0 時估值仍 `ok` → `book_fully_valued=True`；**總曝險上限分子被低估可能錯誤通過**（book.py 規則 3「絕不能錯的方向」）；同產業產業佔比分子低估亦可能錯誤通過；其他標的佔比偏高（保守）但無揭露。
2. **負值 close 影響更大**：負市值拉低 `total_equity_twd`，若 < 0 則**任何標的** advice 皆 500、警示全部標的 load failure。
3. **B′ 範圔**：`_resolve_price` 遇最新 bar close 不可用 → 回傳與「沒有 bar」完全相同 `(None, None, missing_token, None)`；不可退用前一根 bar（同否決 C 理由）。一處修好五個使用端受益：`/api/portfolio/summary`、`/limits`、`/api/advice`、警示 snapshot、設定頁 FR-9 淨值檢核（`settings.py:350`）；`book_limits._split_by_valuation` 自動列入 unvalued 並附既有 `SYMBOL_UNVALUED_NOTE`。
4. **A 仍需要（縱深）**：估值器（`get_daily_bars` 回看 10 天）與 `load_bars` 兩條路徑最新 bar 可能不同；`build_book_context` 對 close／atr 同一判斯，不可用兩者皆 None；保持純函式（ADR-0005 決策 5），不加新註記。
5. **advice 另處理**：訊號在 `build_book_context` 前已算；比照 A′，close 不可用時走既有 `latest is None` 的 `insufficient_data` 分支、不呼叫 `compute_signals`、`reason=None`（不沿用 `loaded.reason`，避免 R-B1 型錯誤歸因）；前端 `InsufficientPanel` 顯示既有「資料不足，無法計算。」。`portfolio.py` 不用改。
6. **單一定義與 import 方向**：`usable_price` 現在 `app/alerts/engine.py:166`，engine import `app.advice.*`；`app.portfolio.valuation` 不得反向 import → 下移到 `app/data/` 葉模組（不 import `app.*`，支援 float 與 Decimal）；`engine.usable_price` 保留名稱轉呼叫；`snapshot.py` 不動。ADR-0020 K-3 不受影響；新增 import-graph 守門：`app.portfolio.*` 不得碰 `app.alerts`／`app.advice`。
7. **既有 ADR 無衝突**：ADR-0016 F1（`price_change.py:288` `value <= 0` 當無價格，修後由 `price_info is None` 觸發，結果同，不改）；ADR-0010 D-1 missing token 沿用；ADR-0019 K-9／F-2 只在使用端判斷不丟列；ADR-0021 advice 走 insufficient_data 不評估規則；`PortfolioContext` 驗證保留為最後契約。
8. backtest／demo 無影響（backtest 不用估值器；demo 價格 `exp(log_price)` 恆 > 0）。殘留歸 F-2：視窗內較早壞 bar、`/api/signals` 與走勢圖。

**代價**：壞 bar 來歷不再出現在持股列（price None）；一檔持股最新 bar 不可用 → 整本帳總曝險 `not_evaluable`（以前可能錯誤 passed）；監看總曝險的 risk_limit 規則由 quiet 變 skipped 或 S-B2 型 quiet；其他標的佔比附「比率會因此偏高」揭露。
