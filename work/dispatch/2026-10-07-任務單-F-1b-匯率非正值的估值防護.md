- 日期：2026-10-07　狀態：**spec**（tech-architect 評估已落檔，見文末；待風控裁定 D6／(b)；待 CEO 排優先序）　等級：**medium**（風控 2026-10-07；F-3 查到非零升 high）

## 缺陷
匯率 ≤ 0（或非有限值）完全未防護：
- `FxRate.rate: Decimal` 無驗證器（`app/data/providers/fx.py:82-99`）。
- 台銀 CSV 解析取買賣中價，無正值檢查（`fx.py:280-298`）；yfinance 退路（`fx_yfinance.py`）同樣未見檢查（待 tech-architect 讀碼確認）。
- 估值器 `valuation.py:_lookup_fx`（`:469-491`）取 `latest.rate` 直接回傳；`_resolve_fx`（`:424-446`）只在 `None` 時記 `fx_now`／`fx_open` missing。
- 結果（依 tech-architect 更正）：**匯率為 0** → 外幣持股以 `ok` 狀態帶市值 0（`market_value_twd = q*close*fx`，`:371`），與 F-1 D2 同型——總曝險、產業佔比的分子被低估可能**靜默錯誤通過**；FR-9 偏低的量尺會被持久化到 `valued_book_twd_at_report`。**匯率為負** → 現況不是數字錯而是 **500**：`limits.py:629-635` 的 `total_equity_twd`／`position_market_value_twd`／`gross_exposure_twd` 皆 `ge=0`，`/api/advice`、`/api/portfolio/limits`、`PUT /api/settings`（填淨值時，`settings/models.py:160` `ge=0`）都會回 500；同時破壞 ADR-0022 W1／D-d1「會偏低」前提（失效條件 5）。
- **已有防護的一層（不動）**：`app/advice/book.py:_resolve_fx`（`:725-752`）對 `fx.rate <= 0.0` 已回 `None` 並附 `FX_UNAVAILABLE_NOTE`，所以決策卡的價格／ATR 上限在匯率非正時已不計算；缺口只在估值器（組合總額、`/limits` 分子、`book_fully_valued`）。

## 風控要求（2026-10-07，逐字轉錄為約束）
- **(a)** 不可用的匯率，比照 B′ 等同「沒有匯率」：沿用既有 token（`fx_now`／`fx_open`）與 note（`NO_FX_QUOTE_NOTE`／`FX_UNAVAILABLE_NOTE` 走哪一句由 tech-architect 讀碼定、風控審）；**不退用較早的匯率**；**不新增 token**；要新增 token 先送審。
- **(b)** 等級維持 medium；F-3 腳本若能順便統計本機 cache 中匯率 ≤ 0 的筆數，請一併輸出；查到非零就升為 high，並交 CEO 判斷是否成為部署前置。
  - **coordinator 讀碼揭露**：ADR-0011 與 `fx.py:313、325` 明寫**沒有本地 FX 快取層**（`FxRateLadder` 每次向台銀／yfinance 取、不落 SQLite），`app/data/` 下也無 fx 資料表。因此 (b) 的「掃本機 cache 匯率 ≤ 0」**在現況無法執行**，F-3 腳本沒有可掃的對象。替代做法待風控裁定：(i) 以「來源歷史上是否出現過非正匯率」為升級依據（需 data-engineer 查證台銀 CSV 與 yfinance 的欄位契約，不連網時只能讀碼與 fixture）；或 (ii) 直接視為「無法查證」，等級維持 medium、不升不降，部署前置不受 F-1b 影響。
- **(c)** 單一定義放在同一 `app/data/price_guard` 層（`usable_rate`），不得散在 provider 與估值器各寫一份。

## 目標
任一外幣持股在估值日（或開倉日）取到的匯率 ≤ 0 或非有限值時：該筆不以 0 或負市值進入估值，而以既有 `fx_now`／`fx_open` missing token 列為未估值；組合不被當成完整帳本（`book_fully_valued` 不為 True）；`/api/portfolio/summary`、`/limits`、`/api/advice`、警示 snapshot 不回 500、不出現負總資產。

### 一、評估摘要（結論先講）

1. **採用「使用端判斷」（方案 C）**：`FxRate` 不加驗證器，provider、ladder、adapter 都不改。否決「provider 整批丟例外」（A）和「provider 逐列丟棄」（B）。B 等於讓估值器退用較早的匯率，直接違反風控 (a)。

   - `portfolio/summary.py:fx_disclosures_for`。
   - 前端 `FxStatusBadge.tsx`：只讀不改。

### 二、方案比較（問題 2：防護放在哪一層）

**pydantic 行為（問題 1，讀碼推定）**：
- `FxRate` 的 `ConfigDict` 只設 `frozen=True`（`fx.py:85`）。
- pydantic 只在明確設定時才把 `allow_inf_nan` 傳進 core config（`.venv/.../pydantic/_internal/_config.py:207`）。
- Decimal schema 的預設是 `allow_inf_nan: False`（`.venv/.../pydantic_core/core_schema.py:759`；`_generate_schema.py:1080-1081` 呼叫 `decimal_schema()` 時沒有帶參數）。
- 因此 `FxRate(rate=Decimal("NaN"/"Infinity"))` 與 `PriceBar(close=NaN)` 應該會丟 ValidationError；0 與負值則可以通過。

這代表現況下 NaN／inf 已經有隱性的 provider 層行為：
- 台銀：CSV 格子是 `NaN` 時，ValidationError 穿出 adapter，ladder 改走備援。
- yfinance：`json(parse_float=Decimal)`（`yfinance.py:300`）會把 JSON 的 NaN 字面值轉成 float nan，再變成 `Decimal('NaN')`。`PriceBar` 驗證失敗丟出 ValidationError（它是 ValueError 的子類），在 `_parse_result:355` 被接住，整列略過，結果就是退用較早一天。

這是既有行為，不在 F-1b 範圍內，列為殘留 R2、R3。

### 三、決策（可貼入任務單的「tech-architect 評估」段）

> **tech-architect 評估（2026-10-07，讀碼基準 d66183e）**
>
> **D1 防護層級**：採使用端判斷。`FxRate`、`FxRateResult`、`FxRateLadder`、`BankOfTaiwanFxAdapter`、`YFinanceFxAdapter`、`yfinance.py` 零改動。provider 層整批丟例外（會讓一天壞值變成整段 UNAVAILABLE 或改走備援）與逐列丟棄（等於退用較早匯率，違反風控 (a)）都否決。
>
> **D2 `usable_rate`**：放在 `app/data/price_guard.py`，模組名稱不改。改名會動到 F-1 既有測試（`test_unusable_close_f1.py:137-141`），而且風控 (c) 已逐字指定這個模組；匯率本身就是貨幣的價格，語意上說得通。實作方式：抽出私有 `_positive_finite(value)`，`usable_price` 與 `usable_rate` 兩個公開函式各自呼叫它、各有 docstring。簽名 `usable_rate(value: float | Decimal | None) -> bool`。不用 `usable_rate = usable_price` 這種別名，否則 grep 與 traceback 分不出兩者。模組 docstring 改成涵蓋「收盤價與匯率」。葉模組約束不變。
>
> **D3 `_lookup_fx`**：先選出 `latest = max(candidates)`，接著若 `not usable_rate(latest.rate)`，記一筆 WARNING，回傳與「無匯率」分支**同一個建構式**產生的結果：`(None, FxInfo(pair, as_of=None, source=result.source, data_status=UNAVAILABLE, source_note=source_note(result.source), reason=result.reason))`。兩個分支要抽成共用 helper，避免日後各改各的。
> - 不沿用 `result.status`／`as_of` 的理由：`summary.fx_disclosures_for`（`summary.py:105-114`）的契約是「實際採用的匯率」，判斷依據是 `data_status != UNAVAILABLE`；前端 `FxStatusBadge.tsx:79-83` 只要 `as_of` 不是 null 就顯示「MM/DD 匯率」（「找到匯率」的意思）。沿用的話，一筆沒有採用的匯率會帶著日期與來源揭露上畫面。
> - 與 F-1 的對稱是原則層級的對稱（「與無資料分支完全相同」），不是欄位逐一對稱：F-1 的「無價格」表示為 `price=None`；FX 的「無匯率」依 `FxInfo` docstring（`valuation.py:176-179`）必須是 UNAVAILABLE 的 `FxInfo`。
> - `reason` 沿用 `result.reason`，與「無匯率」分支一致。前端只在 `cached_stale` 讀它，對 UNAVAILABLE 不顯示。
>
> **D4 不退用較早匯率**：`candidates` 不得事先用 `usable_rate` 過濾，只判斷 `latest`。較早的壞值不影響結果（最新一筆正常就照用）。fx_open 經同一個 `_lookup_fx`，自動適用。memo 會把 `(None, info)` 記住，同一輪內不重查。
>
> **D5 `book._resolve_fx`**（`book.py:747`）：改成 `fx.rate is None or not usable_rate(fx.rate)`。**這不是「語意不變」**：0 與負值的 `(rate, note)` 逐位元組不變（`FX_UNAVAILABLE_NOTE`，status／as_of 帶的是報價本身的值）；NaN、±inf 從「NaN 經 `PortfolioContext.fx_to_twd gt=0`（`limits.py:649`）回 500、+inf 被當成有效匯率並印出 `FX_APPLIED_NOTE` 的 inf」收緊為 `FX_UNAVAILABLE_NOTE`。+inf 可以從極大的有限 Decimal 經 `float()`（`services/fx.py:107`）產生，所以這條收緊有實際作用。
>
> **D6 note 走向**（交風控審）：建議卡、警示、`/limits` 三條路徑走 `FX_UNAVAILABLE_NOTE`（「報價有到，但沒有可用數值」，`book.py:183-189`），不走 `NO_FX_QUOTE_NOTE`（那句只用在根本沒有報價，即 `fx is None`）。對 0 與負值而言，這就是現況輸出，F-1b 不改變任何卡面字面。摘要頁的 `FxInfo` 是 UNAVAILABLE，徽章顯示「匯率 資料不足」（既有字面）；卡片 note 的「資料狀態」則是報價本身的 status（例如 fresh）。兩者指的對象不同（一個是「採用的匯率」，一個是「收到的報價」），都屬實；這個差異要讓風控知悉。
>
> **D7 `resolve_fx_quote` 零改動**：它只負責解析，不做判斷，判斷交給 `book._resolve_fx`。如果在這裡也判斷，會產生第二份定義，還會讓 0 與負值的卡面 note 從「fresh／日期」變成「unavailable／未知」，等於改了使用者可見的輸出。
>
> **D8 不需要 ADR**：沒有新邊界、新 token、新模組或新字面，沿用 F-1 判例。ADR-0022／0023／0015 只加註記（見第六點）。
