# 任務單 F-1b：組合估值對非正值匯率的防護（`usable_rate`）

- 日期：2026-10-07　狀態：**draft**（待 tech-architect 唯讀評估補實作規格；待 CEO 排優先序）　等級：**medium**（風控 2026-10-07；F-3 查到非零升 high）
- 來源：tech-architect 於 6-b 評估時發現（`work/dispatch/2026-10-07-任務單-6-b-…md:15`）；風控對 6-c 與 F-1b 的裁定（`…任務單-產業上限…md:121`）；風控 F-1 後端單項核對第 6 項「F-1b 另開單：同意」（`…任務單-F-1-…md` 檔尾）。
- 負責：dev-lead。審查：qa-reviewer（Codex 不可用時註明）。risk-compliance-officer：FX 歸因字面走向需獨立審查（見「風控要求」）。
- 關聯：F-1（f25c90d，`app/data/price_guard.py` 的 `usable_price`）；ADR-0011（FX 垂直、無本地 FX 快取）；ADR-0023 Consequences 2（「市值非負」「匯率 > 0」前提在 code 上沒有強制）；ADR-0022 失效條件 5。

## 缺陷
匯率 ≤ 0（或非有限值）完全未防護：
- `FxRate.rate: Decimal` 無驗證器（`app/data/providers/fx.py:82-99`）。
- 台銀 CSV 解析取買賣中價，無正值檢查（`fx.py:280-298`）；yfinance 退路（`fx_yfinance.py`）同樣未見檢查（待 tech-architect 讀碼確認）。
- 估值器 `valuation.py:_lookup_fx`（`:469-491`）取 `latest.rate` 直接回傳；`_resolve_fx`（`:424-446`）只在 `None` 時記 `fx_now`／`fx_open` missing。
- 結果：外幣持股可能以 `ok` 狀態帶 0 或負市值（`market_value_twd = q*close*fx`，`:371`），與 F-1 D2 同型——總曝險、產業佔比的分子被低估可能錯誤通過；匯率為負時總資產 E 可能 < 分子 A，破壞 ADR-0022 W1／D-d1「會偏低」前提（失效條件 5）。
- **已有防護的一層（不動）**：`app/advice/book.py:_resolve_fx`（`:725-752`）對 `fx.rate <= 0.0` 已回 `None` 並附 `FX_UNAVAILABLE_NOTE`，所以決策卡的價格／ATR 上限在匯率非正時已不計算；缺口只在估值器（組合總額、`/limits` 分子、`book_fully_valued`）。

## 風控要求（2026-10-07，逐字轉錄為約束）
- **(a)** 不可用的匯率，比照 B′ 等同「沒有匯率」：沿用既有 token（`fx_now`／`fx_open`）與 note（`NO_FX_QUOTE_NOTE`／`FX_UNAVAILABLE_NOTE` 走哪一句由 tech-architect 讀碼定、風控審）；**不退用較早的匯率**；**不新增 token**；要新增 token 先送審。
- **(b)** 等級維持 medium；F-3 腳本若能順便統計本機 cache 中匯率 ≤ 0 的筆數，請一併輸出；查到非零就升為 high，並交 CEO 判斷是否成為部署前置。
  - **coordinator 讀碼揭露**：ADR-0011 與 `fx.py:313、325` 明寫**沒有本地 FX 快取層**（`FxRateLadder` 每次向台銀／yfinance 取、不落 SQLite），`app/data/` 下也無 fx 資料表。因此 (b) 的「掃本機 cache 匯率 ≤ 0」**在現況無法執行**，F-3 腳本沒有可掃的對象。替代做法待風控裁定：(i) 以「來源歷史上是否出現過非正匯率」為升級依據（需 data-engineer 查證台銀 CSV 與 yfinance 的欄位契約，不連網時只能讀碼與 fixture）；或 (ii) 直接視為「無法查證」，等級維持 medium、不升不降，部署前置不受 F-1b 影響。
- **(c)** 單一定義放在同一 `app/data/price_guard` 層（`usable_rate`），不得散在 provider 與估值器各寫一份。

## 目標
任一外幣持股在估值日（或開倉日）取到的匯率 ≤ 0 或非有限值時：該筆不以 0 或負市值進入估值，而以既有 `fx_now`／`fx_open` missing token 列為未估值；組合不被當成完整帳本（`book_fully_valued` 不為 True）；`/api/portfolio/summary`、`/limits`、`/api/advice`、警示 snapshot 不回 500、不出現負總資產。

## 範圍（待 tech-architect 確認，coordinator 初稿）
1. `app/data/price_guard.py` 新增 `usable_rate(value: float | Decimal | None) -> bool`（與 `usable_price` 同語意：非 None、有限、> 0；可共用內部實作但兩個公開名稱分開，便於 grep 與語意區分）。葉模組約束不變：不 import `app.*`、無繁中。
2. `valuation.py:_lookup_fx`：`latest.rate` 不可用 → 回傳與「無匯率」完全相同的 `(None, info)`；**不退用 candidates 中較早的 rate**；warning log 只記 pair／date／rate／source（無祕密）。`FxInfo` 的 `data_status`／`reason` 走哪個值由 tech-architect 定（傾向沿用 `result.status`、`reason` 不改，與 F-1 的 `PriceInfo` 處理對稱）。
3. `FxRate` 模型**不加**驗證器（避免 provider 解析時整批丟例外、把一天壞值變成整個區間 UNAVAILABLE——與 F-1 否決 (C) 同理）；由使用端判斷。若 tech-architect 認為應在 provider 層丟列，須說明對 ladder 退路與 `FxRateResult.status` 的影響。
4. `book.py:_resolve_fx` 的 `fx.rate <= 0.0` 改為呼叫 `usable_rate`（語意不變，單一定義；`FX_UNAVAILABLE_NOTE` 逐位元組不變）。
5. 不動：token 名稱、`MISSING_LABELS`、任何使用者可見字面、前端。
6. 測試：`tests/test_unusable_fx_f1b.py`（新；`tmp_path` 或純 fake provider，不碰 `backend/data/*.db`）——匯率 0／負／NaN／inf × `fx_now`／`fx_open` × live／cache_only；斷言 position status 為 insufficient_data、missing 含對應 token、`book_fully_valued is not True`、總資產不含該筆、`/limits` 第 3 條 not_evaluable（或依 6-b 落地後為 violated）、無 500；`_lookup_fx` 不退用較早 rate（candidates 含較早正值仍回 None）。既有測試零修改。
7. import-graph 守門沿用 F-1：`app.portfolio.*` 不得 import `app.alerts`／`app.advice`。

2. grep：無新 token、`MISSING_LABELS` 未動、`NO_FX_QUOTE_NOTE`／`FX_UNAVAILABLE_NOTE` 逐位元組不變、新增檔與註解無繁中。
