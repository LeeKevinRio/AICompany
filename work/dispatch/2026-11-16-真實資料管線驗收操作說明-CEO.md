## 一、這一次會看到什麼（風控定稿）

> 這一次是用您電腦裡已經存下來的大盤歷史資料，檢查預測紀錄的程式能不能從頭到尾正確跑完。它只檢查程式流程，不是績效證據，不計入任何驗證統計，也不代表任何判斷規則準確或有效。
> 這支程式在畫面上印出的內容，以及要請您貼回的內容，只有：每組檢查通過或失敗、失敗種類的英文代號、每種執行結果各跑了幾次、一串串雜湊碼（用來核對程式與資料版本的指紋），以及環境檢查的結果。
> 不會出現任何偏多、偏空、震盪或證據不足的判斷，不會出現判斷對不對、筆數、比例或日期。完整的檢查明細跑完就刪除，不存檔，也不會交給任何人。
> 另外，視窗裡可能出現少數不是這支程式印出的系統文字，例如您按 Ctrl+C 時出現的「^C」、「要終止批次工作嗎 (Y/N)?」，或程式異常結束時的系統錯誤訊息。依設計，這些文字不含任何判斷、對錯、筆數或日期，也不是檢查結果。要貼回的只有 Notepad 裡的內容，請不要截圖或貼上整個視窗。若視窗出現系統錯誤訊息、而且沒有開出 Notepad，請直接告訴 coordinator「沒有產生回貼檔」，不必抄錄或截圖錯誤訊息。

## 二、三個步驟

1. **雙擊 `apps\stock-desk\dev-up.bat`**，讓本機拉到最新版。確認三個 stock-desk 視窗正常開起來後，**把這三個視窗都關掉**（backend、scheduler、frontend）。
2. **雙擊 `apps\stock-desk\pipeline-acceptance.bat`**。視窗會要您確認三個視窗都關了，**按一次 Enter**。
3. **記事本會自動跳出 `paste-back.txt`**。按 Ctrl+A 全選、Ctrl+C 複製，貼回給 coordinator。**只貼記事本裡的內容**。貼完之後，就可以照平常再雙擊 `dev-up.bat` 啟動。

整個過程大約幾分鐘。暫存資料放在您使用者資料夾下的 `stock-desk-pipeline-acceptance\<時間戳>\`（在 repo 之外），跑完只留下 `paste-back.txt`。

backend 或 scheduler 若是用 NSSM 或 Windows 工作排程器常駐（不是用 `dev-up.bat` 開的），先不要跑，告訴 coordinator。

## 三、「失敗種類」是什麼（風控定稿）

> 「失敗種類」是程式自我檢查的項目名稱，用英文代號表示。它只說明是哪一類檢查沒過，不說明是哪一天、哪一筆，也不含任何判斷或對錯。這些代號是給工程師修程式用的，您不需要理解它的意思，也請不要自行查找或推敲，照原樣貼回即可。顯示「無」表示所有檢查都通過。
> 失敗只代表程式需要修正，修好後會請您再跑一次；它不是投資訊號，也不代表規則好壞。工程師查錯時會用自己準備的資料重現，不會向您轉述任何判斷、對錯、日期或筆數。

## 四、「通過」的意思（風控定稿）

> 「通過」只代表這一次程式流程在您的資料上跑通，是正式登記前的必要條件之一；它不代表大盤判斷規則準確、有效或值得參考。這一次每根資料的時間是程式代填的，所以也沒有驗證真實情況下資料何時可用、何時定案。

## 五、出現 `cleanup=FAILED` 時（風控定稿）

> 若回貼內容出現 `cleanup=FAILED`，表示暫存資料夾沒有刪乾淨，裡面可能有含判斷結果的檢查明細。請不要開啟該資料夾或其中任何檔案，直接告訴 coordinator，由 coordinator 提供刪除步驟。正式登記前必須再跑一次，直到出現 `cleanup=ok`。若您已經開啟過其中的檔案，請如實告訴 coordinator；這時登記時「是否看過暫定對照」可能就不能填「沒看過」。

## 六、登記時「是否看過暫定對照」（風控定稿）

> 正式登記時，程式會請您自己鍵入「登記前是否看過暫定對照」。暫定對照指任何一筆大盤判斷（偏多、偏空、震盪、證據不足）事後對不對，或和基準比較的結果。只看過這次一鍵檔的通過或失敗、失敗種類、執行次數、雜湊與環境檢查，不算看過暫定對照。但只要您從任何地方看過任何一筆判斷或對照（包括暫存資料夾裡的檔案、別人的轉述或其他報表），就請如實填「看過」，並告訴 coordinator。依目前的登記規則，填「看過」不會擋住登記，只會在日後的報告中照實揭露。

## 七、如果它停下來：STOP 與 ERROR 對照表

視窗上若出現 `STOP:` 或 `ERROR:` 開頭的一行，表示程式依設計停下來了。**這種情況不會產生回貼檔，記事本也不會跳出來。** 請把那一行英文告訴 coordinator，並照下表的「您要做的事」處理；不要自己修改任何檔案、設定或 git。

| 視窗上的那一行 | 意思 | 您要做的事 |
|---|---|---|
| `STOP: STOCK_DESK_DB_PATH is set in the environment.` | 您的資料庫位置是用環境變數指定的，不在預設位置。 | 告訴 coordinator，由 coordinator 提供其他做法。 |
| `STOP: STOCK_DESK_DB_PATH is set in the .env file of the app.` | 您的資料庫位置是寫在 `.env` 裡指定的，不在預設位置。 | 告訴 coordinator，不需要貼出 `.env` 的內容。 |
| `STOP: stock-desk.db was not found at the default location.` | 預設位置找不到資料庫檔。 | 告訴 coordinator。 |
| `STOP: something is listening on port 8000; close the stock-desk windows and run again.` | backend 還開著。 | 關掉三個 stock-desk 視窗後，重新雙擊 `pipeline-acceptance.bat`。 |
| `STOP: the work folder would be inside a git work tree.` | 暫存資料夾的位置落在 git 版控資料夾裡面。 | 告訴 coordinator。 |
| `STOP: git could not be used on the code folder.` | 程式碼資料夾無法使用 git（例如沒裝 git，或資料夾不是 git 版控）。 | 告訴 coordinator。 |
| `STOP: the code folder has uncommitted changes.` | 程式碼資料夾有未提交的變動，這一次檢查的程式版本就不確定。 | 告訴 coordinator，先不要自己還原或刪除任何東西。 |
| `STOP: this code version is not on origin/product/stock-desk.` | 您電腦上的程式版本不是已發布的版本。 | 先雙擊 `dev-up.bat` 更新，再重跑一次；仍然停下來就告訴 coordinator。 |
| `STOP: line endings of a pinned file differ from the repository. Tell the coordinator; do not change anything yourself.` | 有一個鎖定檔案的換行格式和版控內的不一樣，程式版本就無法核對。 | 告訴 coordinator，由 coordinator 提供修復步驟；不要自己改 git 設定或檔案。 |
| `STOP: the database changed while copying; a service is still running.` | 複製資料庫期間內容有變動，代表還有服務在跑。 | 確認三個 stock-desk 視窗都關了（含常駐服務），再重新雙擊；仍然停下來就告訴 coordinator。 |
| `STOP: the refusal guard self-check failed.` | 程式自我檢查「不會碰正式資料庫」的保護沒有通過。 | 告訴 coordinator。 |
| `STOP: the cache copy holds no TWII rows.` | 資料庫複本裡沒有需要的大盤歷史資料。 | 告訴 coordinator。 |
| `STOP: a TWII row of the cache copy cannot be read.` | 資料庫複本裡有一筆大盤歷史資料讀不出來。 | 告訴 coordinator。 |
| `STOP: a TWII row of the cache copy comes from the demo seeder.` | 大盤歷史資料裡有來自示範資料的列，不是真實資料。 | 告訴 coordinator。 |
| `STOP: a TWII row of the cache copy is not from the expected source.` | 大盤歷史資料裡有來源不是預期的列。 | 告訴 coordinator，由 coordinator 升級給 tech-architect。 |
| `STOP: the cache copy holds too few TWII sessions before today.` | 大盤歷史資料的天數不夠。程式不會上網補資料。 | 告訴 coordinator，由 coordinator 與 data-engineer 另行處理。 |
| `STOP: the database copy could not be deleted, so the check did not continue. Remove the whole work folder without opening it, do not send it to anyone, and tell the coordinator.` | 資料庫複本沒能刪除，所以沒有繼續檢查。**這一句要特別處理，見下方。** | 照下方風控定稿的中文說明做：直接刪除整個資料夾，不要開啟，也不要傳給任何人，然後告訴 coordinator。 |
| `ERROR: unexpected failure; no paste-back file was made. Tell the coordinator.` | 程式發生預期之外的錯誤，沒有產生回貼檔。 | 告訴 coordinator「沒有產生回貼檔」。不必抄錄或截圖其他錯誤訊息。 |
| `ERROR: interrupted; no paste-back file was made.` | 您按了 Ctrl+C，或程式被中斷，沒有產生回貼檔。 | 要重跑就再雙擊一次；之前沒有刪乾淨的暫存會在下次啟動時自動清掉。 |

### 「資料庫複本沒能刪除」那一句的中文說明（風控定稿）

> 這個資料夾裡有您資料庫的完整複本（含持股與現金）。程式沒能把它刪掉，所以沒有繼續檢查。請直接刪除整個資料夾，不要開啟，也不要傳給任何人，然後告訴 coordinator。

資料夾位置是您使用者資料夾下的 `stock-desk-pipeline-acceptance\<時間戳>\`。

## 八、`paste-back.txt` 裡各行的意思

- 前兩行是固定的標示文字，說明這是管線驗收。
- `script_sha256_lf=`、`harness_sha256_lf=`、`git_head=`、`code_digest=`、`lockfile_sha256=`、`definition_sha256=`、`definition_logic_sha256=`：用來核對程式與定義版本的指紋，coordinator 會核對。
- `git_clean=yes`、`core_autocrlf=`、`eol_check=ok`、`db_location=default`、`port_8000_listening=no`、`copy_check=`、`refusal_guard=ok`、`cache_depth=sufficient`：環境檢查的結果。
- `bars_sources=`、`bars_sha256=`：輸入資料的識別，不含任何價格。
- `管線驗收 P-0`、`管線驗收 P-1` 兩組：每組有通過或失敗、各執行結果的次數、失敗種類、以及兩串雜湊。
- `acceptance_result=`：兩組都通過才是 `PASS`。
- `cleanup=`：暫存資料有沒有刪乾淨，見上方第五節。
- `summary_lines_dropped=`：被過濾掉的行數，正常是 0。
- `done_at_utc=`：完成時間（UTC）。

## 九、注意事項

- **只貼記事本裡的內容**，不要截整個黑色視窗給任何人。
- 暫存資料夾裡如果還留有 `p0`、`p1` 或 `copy` 子資料夾，不要開啟；下次啟動會自動清掉。
- 一鍵檔不會上網、不會寫入您的正式資料庫；它只用 `rb` 方式讀取資料庫檔，把位元組複製一份，之後只讀複本，複本在跑檢查之前就刪掉。
- 在 `pipeline-acceptance.bat` 之外，請不要自己執行裡面的 Python 腳本。
