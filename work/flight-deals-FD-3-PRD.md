## 背景與目標

FD-1 與 FD-2 上線後，實際使用發現數個穩定性與體驗缺口，本批以修補為主，不新增功能面：

1. 部分航線（實測 TPE→SHA 上海虹橋，2026-10-26 查得 4 筆航班中 2 筆無價格，皆為廈門航空經 XMN 轉機）的航班清單含無價格項目，資料源套件解析時整批失敗，被判為資料源被擋（`blocked`），導致該監看永遠查不到價，並累積資料源斷路器的失敗次數，可能讓健康狀態誤報異常。
2. 兩個實例以不同 port 共用同一顆資料庫時，會各自跑排程，造成重複掃描與重複推播。
3. 「立即查價」按下後只回 202，使用者須自行重新整理才看得到結果。
4. 部分早退的 403／400 回應缺少安全標頭，與一般頁面不一致。
5. 編輯日期已過期的舊監看時，日期欄位呈現超出最小值的怪異狀態，無提示。
6. 出發地／目的地下拉未高亮任何項目時按 Enter，行為不明確。

成功指標（以可驗證行為為準）：
- TPE→SHA 這類混合清單可正常記錄有價格的航班，不再被判為資料源異常。
- 同一資料庫不可能同時有兩份排程在跑。
- 按「立即查價」後無須手動重新整理即可看到結果或明確的逾時說明。

## 使用者與情境

- 使用者：CEO 本人，單一使用者，桌機與手機瀏覽器。
- 情境 A：監看 TPE→SHA，清單中部分航班無價格，期望仍看到有價格者的最低價。
- 情境 B：舊的 dev-up 還開著，又用另一個 port 開了新實例，期望第二個不會重複掃描。
- 情境 C：在詳情頁按「立即查價」，等待後頁面自己更新。
- 情境 D：修改一個出發日期已過的監看，看到日期過期的提示。
- 情境 E：在目的地欄位輸入完整代碼後直接按 Enter。

## 功能需求（逐條編號）

### 查價容錯（最高優先）

- FR-T1 部分航班無價格：當查價結果清單同時含有價格與無價格的航班時，有價格的航班須照常記錄（價格歷史、最低價、通知條件判斷與一般結果相同）；無價格的航班略過，不記錄、不當作錯誤。
- FR-T2 略過數量說明：該次查價有略過無價格航班時，監看詳情頁「本次取樣」的說明欄須顯示「略過 N 筆無價格航班」（N 為實際略過筆數）；沒有略過時不顯示此句。
- FR-T3 全部無價格：清單有航班但全部無價格時，該次查價結果判為 `no_data`（無資料），不是 `blocked`；詳情頁沿用 FD-1 FR-D6 空狀態說明，說明欄可呈現略過筆數。
- FR-T4 不誤判資料源異常：上述 FR-T1 與 FR-T3 情境不得計入資料源連續失敗次數（FD-1 FR-B6）；不得因此將資料源標示為「異常」，也不得觸發異常告警。真正的被擋或格式改變（無法辨識的回應）仍須維持原本的失敗判定與計數。
- FR-T5 既有行為不變：清單航班全部有價格的情境，行為與結果與修改前完全一致。

### 單一排程保證

- FR-S1 同庫單排程：同一顆資料庫同一時間只能有一個實例執行排程掃描。
- FR-S2 第二實例的處理：第二個實例啟動時偵測到同庫已有排程在跑，須明確拒絕啟動，或只開網頁、不開排程；兩種擇一由 tech-architect 評估（預設：只開網頁不開排程，見開放問題 2）。不得靜默地一起掃描。
- FR-S3 說明原因：被拒絕或被降級時，須讓使用者知道原因（啟動訊息／日誌與網頁上的狀態皆可），內容須說明「此資料庫已有另一個實例在執行排程」。
- FR-S4 持有者結束後可接手：原排程實例正常結束或異常終止後，下次啟動的實例須能取得排程資格，不得因殘留狀態而永久被擋。

### 立即查價自動更新

- FR-R1 查價中狀態：按下「立即查價」後，按鈕須進入「查價中」狀態並停用，避免重複觸發。
- FR-R2 完成後自動更新：查價完成後，頁面須自動更新顯示新結果（價格、上次查價時間、說明欄），不需使用者手動重新整理；按鈕恢復可用。
- FR-R3 逾時提示：等待超過逾時時間（預設 90 秒）仍未完成時，停止等待並顯示「查價仍在進行，稍後重新整理」；按鈕恢復可用。逾時只影響畫面等待，不中止背景查價。
- FR-R4 失敗呈現：查價結束但失敗時，頁面須自動更新並顯示失敗原因（沿用 FD-1 既有失敗呈現），不得停在「查價中」。
- FR-R5 沿用既有約束：仍受 FD-1 FR-B3 查詢次數上限與 FR-B7 防重入約束；防重入造成拒絕時，須顯示明確說明而非靜默無反應。

### 安全標頭一致

- FR-H1 403 帶標頭：缺少自訂 header 而回 403 的回應，須帶與一般頁面相同的安全標頭（含 CSP 等）。
- FR-H2 400 帶標頭：Host 不符而回 400 的回應，須帶與一般頁面相同的安全標頭。
- FR-H3 內容不變：兩者的狀態碼與錯誤訊息語意維持原樣，僅補標頭。

### 過期日期提示

- FR-E1 過期提示：修改監看時，若日期欄位目前值早於今天，須在該欄位旁顯示「此日期已過，請更新」。
- FR-E2 後端規則不變：未改動的舊日期仍可保留並儲存；新輸入的過去日期照 FD-1 FR-A4 拒絕。
- FR-E3 提示消失：使用者把欄位改為今天或之後的日期時，提示即消失。

### 下拉 Enter 行為

- FR-K1 單筆自動選取：出發地／目的地下拉未高亮任何項目時按 Enter，若結果只有一筆，直接選取該筆。
- FR-K2 代碼完全相同：結果有多筆但第一筆的 IATA 代碼與輸入完全相同（不分大小寫）時，Enter 直接選取第一筆。
- FR-K3 其餘情況：不選取，狀態區提示「請用上下鍵選取」；Enter 不得送出表單（沿用 FD-2）。
- FR-K4 已有高亮時：已有高亮項目時，Enter 仍選取該高亮項目（沿用 FD-2 FR-F6）。

## 驗收條件（每條需求至少一組 Given/When/Then）

### 查價容錯

- AC-T1 Given 查價回傳 TPE→SHA 4 筆航班，其中 2 筆有價格、2 筆無價格；When 完成該次查價；Then 2 筆有價格者被記錄，最低價與價格歷史反映這 2 筆，查價結果不是 `blocked`。
- AC-T2 Given 上述混合清單；When 開啟該監看詳情頁；Then 「本次取樣」說明欄顯示「略過 2 筆無價格航班」；When 另一次查價所有航班皆有價格；Then 說明欄不顯示該句。
- AC-T3 Given 查價回傳 3 筆航班且全部無價格；When 完成查價；Then 結果為 `no_data`，不是 `blocked`，詳情頁顯示空狀態說明，且不產生價格紀錄。
- AC-T4 Given 資料源目前連續失敗次數為 N；When 發生一次混合清單（AC-T1）與一次全無價格（AC-T3）的查價；Then 連續失敗次數不增加，資料源狀態不因此變為「異常」，也不發出異常告警。
- AC-T4b Given 查價回傳無法辨識的內容（非「部分航班無價格」的真實格式錯誤或被擋）；When 查價；Then 仍判為失敗並計入連續失敗次數。
- AC-T5 Given 一個清單全部航班皆有價格的查價；When 完成查價；Then 記錄筆數、最低價、通知判斷與修改前一致，說明欄無略過句。

### 單一排程保證

- AC-S1 Given 實例 A 已用某資料庫啟動並在跑排程；When 以不同 port 用同一資料庫啟動實例 B；Then B 不會執行排程掃描，且同一時間內該資料庫只有一份排程產生查價與推播。
- AC-S2 Given 實例 B 被拒絕或降級；When 檢視啟動訊息或網頁狀態；Then 看得到「此資料庫已有另一個實例在執行排程」類說明。
- AC-S3 Given 實例 A 已被關閉（含強制終止）；When 啟動實例 C；Then C 可正常取得排程資格並開始排程，不被殘留狀態擋住。
- AC-S4 Given 單一實例正常使用；When 啟動並運作；Then 行為與 FD-2 一致（排程照常，無額外提示）。

### 立即查價自動更新

- AC-R1 Given 監看詳情頁；When 按下「立即查價」；Then 按鈕立即顯示「查價中」且不可再按。
- AC-R2 Given 查價中；When 查價完成；Then 頁面自動更新顯示新結果與最新查價時間，無須手動重新整理，按鈕恢復可用。
- AC-R3 Given 查價中；When 超過 90 秒仍未完成；Then 顯示「查價仍在進行，稍後重新整理」，按鈕恢復可用，背景查價不被中止。
- AC-R4 Given 查價中；When 查價以失敗結束；Then 頁面自動更新並顯示失敗原因，不停在「查價中」。
- AC-R5 Given 該監看已有查價在進行；When 再按「立即查價」；Then 顯示明確的「已有查價進行中」類說明，不靜默。

### 安全標頭一致

- AC-H1 Given 對會變更資料的端點送出缺少自訂 header 的請求；When 收到 403；Then 回應帶有與一般頁面相同的安全標頭（含 CSP）。
- AC-H2 Given 請求的 Host 與允許值不符；When 收到 400；Then 回應帶有與一般頁面相同的安全標頭。
- AC-H3 Given 上述兩種回應；When 檢查狀態碼與訊息；Then 與修改前相同。

### 過期日期提示

- AC-E1 Given 一個出發日早於今天的既有監看；When 開啟修改頁；Then 該日期欄位旁顯示「此日期已過，請更新」。
- AC-E2 Given 同上；When 不動日期只改預算並儲存；Then 後端接受，日期維持原值。
- AC-E3 Given 同上；When 把日期改為今天或之後；Then 提示消失；When 改成另一個過去日期；Then 提示仍顯示，且依 FD-1 規則被拒絕儲存。

### 下拉 Enter 行為

- AC-K1 Given 目的地輸入的片段只命中一筆且未高亮；When 按 Enter；Then 該筆被選取（欄位值為其 IATA 代碼並顯示中文名），表單不送出。
- AC-K2 Given 輸入「TYO」使結果含 TYO 與其底下機場多筆，第一筆代碼為 TYO、未高亮；When 按 Enter；Then 選取 TYO。
- AC-K3 Given 輸入「東」命中多筆，第一筆代碼與輸入不同、未高亮；When 按 Enter；Then 不選取，狀態區顯示「請用上下鍵選取」，表單不送出。
- AC-K4 Given 下拉已高亮某項；When 按 Enter；Then 選取該高亮項目（與 FD-2 相同）。

## 風險與依賴

- 容錯過寬風險（中）：把「無價格」一律略過，可能掩蓋真正的解析異常。因應：僅「價格欄位缺漏」視為可略過，其他無法辨識的內容仍判失敗（FR-T4、AC-T4b）。判定邊界由 tech-architect 評估。
- 上游套件依賴（中）：解析失敗發生於第三方套件內部，容錯方式可能涉及繞過或包裝該套件；是否與 ADR-0002 的資料源決策衝突由 tech-architect 判斷，必要時補 ADR。
- 排程鎖殘留風險（中）：強制終止後的殘留狀態不得永久擋住啟動（FR-S4）。
- 自動更新與防重入的互動（低）：FR-R5 與 FD-1 FR-B7 同時成立，須避免畫面狀態與後端狀態不一致。
- 實測可重現性（低）：SHA 混合清單為 2026-10-26 實測，Google Flights 內容會變；驗收以離線重現的固定樣本為主，實機查價為輔。
- UI 驗收：涉及網頁互動（立即查價、過期提示、Enter），完成前須 qa-e2e 實機驗收；無人值守環境依 e2e-fallback。
- 風控閘門：本批為事實性狀態文案，不屬建議類，不適用；仍須遵守 C-17 禁用字。
- 依賴：此批修補依賴 FD-1／FD-2 既有程式，無外部新依賴需求。

## 開放問題（待 CEO 或其他部門回答）

1. 【tech-architect】無價格航班的判定邊界：僅「價格欄位缺漏」可略過，其他格式異常仍算失敗，是否可行；解析容錯做法（包裝套件或自行處理）是否需補 ADR。
2. 【tech-architect，預設：只開網頁、不開排程】第二實例是「直接拒絕啟動」還是「降級為只開網頁」；預設為降級，因為使用者仍可瀏覽。若技術上降級成本高，可改拒絕啟動，須回報原因。
3. 【tech-architect】單一排程保證的機制選擇與殘留狀態處理（FR-S4）。
4. 【tech-architect，預設：不中止背景查價】「立即查價」完成通知的技術做法（輪詢或推送）及逾時值是否可設定。預設逾時 90 秒、不可設定。
5. 【總經理，預設：沿用 FD-1 既有失敗呈現】查價失敗時頁面顯示的原因文案是否需調整。
6. 【qa-e2e】過期日期、立即查價、Enter 行為的實機驗收路徑；無人值守時依 e2e-fallback。
7. 【dev-lead】「本次取樣」說明欄現有版面能否容納略過句，以及 SHA 混合清單的固定測試樣本由誰準備。
