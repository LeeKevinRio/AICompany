# 項目一：動作標籤 `stop_loss` 與「停損參考」格標題同名

## 1.0 定錨

- 目標：讓同一張決策卡上，「規則給的動作名稱」與「算式算出的價位格名稱」不再是同一個詞，風控指出的「動作說停損參考、揭露行卻說規則未讀停損參考」的自相矛盾讀感消失。
- 受眾：個股頁第一張卡的一般使用者，掃一眼讀大字，不會去讀頁尾；另一位讀者是風控，逐字核可。
- 限制：
  - 與其他動作標籤同構，不得暗示建議、必然或執行指令（風控 §1.2：標籤須是名詞形式、不帶承諾）。
  - 全文須過 `FRONTEND_FORBIDDEN_TERMS`（`adviceWording.ts` L360–L461，約 90 條）與 `shared/forbidden-terms.json`。
  - 後端 `limits.py` 的 `RANGE_ACTION_LABELS` 與前端 `HELD_ACTION_LABELS` 有跨語言契約，測試會讀 TS 原始碼比對，兩邊必須同值。

## 1.1 盤點到的事實

**動作標籤全表**（`HELD_ACTION_LABELS`，`adviceWording.ts` L40–L47）：

| action | 現行字面 | 形式 |
|---|---|---|
| add | 加碼參考 | 動作名詞＋參考 |
| hold | 續抱參考 | 動作名詞＋參考 |
| reduce | 減碼參考 | 動作名詞＋參考 |
| take_profit | 分批獲利了結 | 動作短語，**沒有「參考」** |
| stop_loss | 停損參考 | 動作名詞＋參考 |
| insufficient_data | 資料不足 | 狀態 |

**候選模式沒有一張對應表。** 任務單提到的 `CANDIDATE_ACTION_LABELS` 不存在；候選模式只有 `CANDIDATE_HEADING_LABEL`「進場評估」加 `CANDIDATE_NOT_SUPPORTIVE_TEXT`「本次未支持進場」，所有非 add 的結果都收成這一句（風控 §3.2：候選模式禁用減碼／停損／停利動詞）。所以「停損」動作字面只會在持有模式出現，本項只動 held 側。

**既有命名邏輯（兩條，這是推薦案的依據）：**

1. **價位／數字格 = 「X參考」**：停損參考、停利參考、股數參考（`decisionCardWording.ts` L17–L19 明寫「與停損參考停利參考同一命名慣例」）。
2. **動作名 ≠ 價位格名已有先例**：take_profit 的動作叫「分批獲利了結」，格叫「停利參考」，兩者本來就不同詞。stop_loss 是**唯一**動作與格同名的一組。所以修動作側是「補齊對稱」，修格側是「動到命名家族」。

**stop_loss 動作在系統裡的實際內容：**

- 目前唯一發出 stop_loss 的規則是 `deep_drawdown_stop`（name「目前回撤深於三成」，`default.yaml` L167–L169）。
- 它的股數區間與減碼共用同一套算法（`test_advice_limits.py` L1740 `test_stop_loss_and_take_profit_share_the_reduce_sizing`），區間下緣可以只是部分持股，上緣才可能是全部持股。**所以「出清」「退出」這類字面對範圍講過頭**（見 1.3）。
- 排程台 `/playbook`（`backend/app/playbook/wording.py`）已把「出清」用在「全部出清」這個真的會送出指令的功能上，建議頁不借用同一個詞。

## 1.2 三視角發想（Ogilvy＋Young＋Rubin，命名類標準組合）

**Ogilvy（核心提問：讀者在三秒內怎麼讀這個詞？）**
- 讀者看的是動作大字，下面緊接一格「停損參考 ¥xx」。只要大字也叫停損參考，他就會把兩者當成同一件事。大字要讓人一眼知道「這是動作那一層」。
- 風控已核可的 `股數參考` 先例顯示：每加一個限定語，裸詞就少一分被擴讀的風險。

**Young（舊元素新組合）**
- 現成的舊元素：「減碼參考」（已核可）＋ 「停損」（已核可的動作名）。組合成「停損型減碼參考」，不發明任何新詞。
- 另一組：「停損」＋「動作」＋「參考」，把「這是動作層」寫成字。

**Rubin（減法：最純粹的版本長什麼樣？）**
- 動作大字要說「這是哪一種賣出」，而不是再造一個價位詞。拿掉「停損」就和減碼分不開，拿掉「參考」就變指令。留下「停損」＋「參考」，中間補一個把它分類的字。

### 發想清單與 Braintrust 互評（只指問題、不給解法）

| 候選 | Ogilvy 的 note | Young 的 note | Rubin 的 note |
|---|---|---|---|
| A 停損型減碼參考 | 七個字，大字略長 | 「型」是新增的分類字，需確認不被讀成「規則類型」以外的意思 | 仍帶「停損」，與格標題在字面上有共同字根 |
| B 停損減碼參考 | 兩個動作詞並排，可能被讀成「停損加減碼」兩件事 | 結構最短，但分類關係沒寫出來 | 比 A 少一個字，也少一個分類訊息 |
| C 停損動作參考 | 「動作」是後設詞，其他標籤沒有 | 與「加碼參考」不同構 | 「動作」拿掉後又回到停損參考，這個字只是補丁 |
| D 出清參考 | 一眼最懂，但懂的是「全部賣掉」 | 與排程台「全部出清」同詞，不同功能 | 範圍講過頭，不是減法是改義 |
| E 退出參考 | 「退出」像離場指令，語氣比其他標籤重 | 無既有先例 | 同 D，範圍過頭 |
| F 停損評估 | CEO 2026-09-19 已明說看不懂 | 舊字面，仍保留在「詳細」 | 回頭路 |
| G 改格標題：停損水位參考 | 與「停利參考」「股數參考」不成家族，需連動改停利 | 「水位參考」與已核可的「此參考水位」語序相反 | 動到 6 處以上已核可字面，其中一句今天才核可 |

## 1.3 推薦案

### 主案 S-1：**停損型減碼參考**

為什麼：
- **同構**：結尾是「減碼參考」，與 add／hold／reduce 同為「動作名詞＋參考」，仍是名詞形式，沒有對使用者說話的動詞，沒有「應」「建議」「立即」。
- **不再與格同名**：動作大字「停損型減碼參考」、格標題「停損參考」，字面一眼可分。同卡「停損參考」從最多四處降為兩處（格標題、揭露行），而且兩處都指同一個東西（那一格）。
- **與卡上其他字一致**：同卡的「股數參考」格，數字就是「賣出 X ~ Y 股」的減碼區間，動作說「減碼」與下方股數格講的是同一件事，不會出現「大字說停損、股數格卻沒說賣什麼」的落差。
- **範圍不講過頭**：沒有「出清」「退出」「全部」。
- **保留資訊**：與 reduce 的差別仍看得見（「停損型」），使用者不會問「減碼參考與這個有什麼不一樣」。

適用情境：held 模式、規則引擎聚合結果為 stop_loss 時。

殘餘風險（請風控一併裁示）：
1. 標籤仍含「停損」二字，與格標題仍有字根重疊。真正把兩者切開的是既有揭露行「上方動作由規則判斷，規則未讀取停損參考與停利參考」（今天已核可，不動）。
2. 「型」字是分類字，不是承諾字；若風控認為「停損型」會被讀成「規則會在停損價出手」，退到備案 S-3。

### 備案 S-2：**停損減碼參考**

為什麼：六個字，與「分批獲利了結」同長，大字更不擠。代價：「停損」與「減碼」並排，分類關係沒寫出來，有被讀成「停損與減碼」兩個動作的風險（Ogilvy note）。

### 備案 S-3：**停損動作參考**（任務單例）

為什麼列為備案：完全不碰「減碼」二字，若風控認為標籤不應綁定賣出量算法，這案最保守。代價：「動作」是後設詞，其他標籤沒有，同構性最差；「停損…參考」與格標題只差中間一個詞，字面仍然很近，同名問題只緩解不消除。

### 不採用

- **出清參考／退出參考**：範圍講過頭（股數區間下緣可以是部分持股）；「出清」另與排程台的「全部出清」指令撞詞；「退出」語氣像離場指令，比其他標籤重。
- **停損評估**：CEO 2026-09-19 的提問就是看不懂這個詞，舊字面已移進「詳細」，不回頭。
- **防守減碼參考／風控減碼參考**：「防守」與已禁的「防守價」同字根，也與排程台的防守模式（M1）撞詞；「風控」在這個產品裡是公司職能名，使用者面前不該出現。
- **險牌（改格標題）**：「停損水位參考」。為什麼不推：見 1.4，牽動面約為動作側的三倍，且停利格必須連動改成「停利水位參考」才不失衡。僅供否決紀錄。

# 項目二：T3 個股頁補「目前回撤」顯示列

## 2.0 定錨

- 目標：使用者在個股頁能看到規則 1.1.0 實際用的那個數字，並能讀懂「最大回撤 -42%、目前回撤已回到 -5%、卡片卻是加碼參考」不是矛盾。
- 受眾：打開個股頁、逐一看技術與風險卡的使用者；風控逐字核可。
- 限制：
  - 欄位標籤風控核可版為「最新收盤價相對區間最高收盤價的回撤」（`context.py` L45），新字面詞彙要與它一致。
  - 不得把回撤說成損益；不得出現「即時」裸詞；不得有 `FRONTEND_FORBIDDEN_TERMS` 命中。
  - `TechnicalIndicatorsPanel.tsx` 整檔被 `componentWordingScan.test.ts` 掃描（禁語、方向性符號 ▲▼↑↓、紅綠色票、裸即時），新字面與 class 都要在這個框內。

## 2.1 盤點到的事實

1. 現行 `DrawdownCard`（L495–L511）：卡標題「最大回撤」；description「觀察區間內高點到低點之最大跌幅，屬歷史統計描述，不代表未來會重演。」（**已被 `componentWordingScan.test.ts` L986 逐字釘住**）；內容一行 `{formatPercent(max_drawdown)}（高點 {peak_date ?? "—"} → 低點 {trough_date ?? "—"}）`。
2. 因為卡標題與 description 已被釘住，**直接在這張卡裡塞一列「目前回撤」會出現「標題寫最大回撤、內容有一列目前回撤」的語意錯位**，且動標題或 description 會連動釘住測試。所以版面建議見 2.2。
3. null 字面慣例：
   - `status === "insufficient_data"` → 整張卡顯示 `InsufficientNote`「資料不足，可用天數不足以計算。」
   - 單一欄位為 null → 印「—」（`formatPercent`／`?? "—"`）。
   - 少於 2 根日線時後端 `status` 為 insufficient，走第一種；`status` 為 ok 但 `current` 缺（舊版快取 payload 沒有新欄位）才會走第二種。
4. `types.ts` 的 `DrawdownResult`（L396–L405）尚無 `current`／`current_peak_date`，frontend-engineer 需補成可選欄位（`current?: number | null`、`current_peak_date?: string | null`），舊 payload 才不會出現 `undefined`。
5. 「最高收盤日」是**最近一次**出現最高收盤價的日期（`risk.py` L69–L70：回到同一高點，日期往後更新），且與最大回撤卡的「高點」不一定同一天。
6. 後端沒給「區間最高收盤價」本身，只給 `current` 與 `current_peak_date`。使用者要自己核對百分比時，拿得到日期、拿不到價格；字面不應暗示可以對上某個價位。
7. 既有已核可的字面可直接重用：「與此部位的未實現損益無關」（回撤規則 explanation，已核可）、「非持倉損益」（2026-10-04 越過水位頁尾 qualifier，已核可）、「資料截至 {日期}」（`buildDataAsOfBadge`）。

## 2.3 三視角發想（Ogilvy＋Young＋Rubin）

**Ogilvy（讀者在乎什麼？）**
- 讀者拿到的疑問是「規則說回撤超過三成，但我看到的最大回撤才二成，哪個對？」或反過來。答案要是一個事實：兩個數字回答不同問題。說明句要用數字的定義，不用形容詞。
- 標籤沿用規則卡「依據：目前回撤深於兩成」同一個名詞，使用者能把規則名稱和這個數字對上。

**Young（舊元素新組合）**
- 標籤：已核可的規則名詞「目前回撤」＋已核可的欄位詞「區間最高收盤價」。
- 說明句：已核可的定義「最新收盤價相對區間最高收盤價的回撤」＋既有卡的「最大回撤＝區間內最深一段」。
- 免責：已核可的「與此部位的未實現損益無關」改用「非持倉損益」（未持有標的也能讀）。

**Rubin（減法）**
- 說明句只留一個差別：一個隨最新收盤改變，一個是區間內最深一段。拿掉「所以規則…」「因此卡片…」這類因果句，因果句會讓回撤數字變成建議的理由。
- 不放顏色、不放 chip（風控已否決狀態燈讀法），不做「新高」特別標記。

### Braintrust（問題型 note）

| 候選 | 對方 note |
|---|---|
| 標籤「目前回撤」 | 與風控 VETO 過的 L-2、L-0 共用「目前」；若用在警示句的標籤位置會與「目前為」疊字 |
| 標籤「最新收盤價相對區間最高收盤價的回撤」 | 作為卡標題偏長，掃讀時像一句話 |
| 標籤「目前回撤（相對區間最高收盤價）」 | 括號補語把基準寫進標籤，但風控曾指出「相對…」語尾不穩 |
| 日期標籤「區間最高收盤日」 | 同一最高收盤價出現多次時，只印最近一次，讀者可能以為只出現一次 |
| 說明句含「會隨最新收盤改變」 | 「改變」若被讀成「會變好」，有方向暗示的風險 |

## 2.4 推薦案

### 卡標題／列標籤

**主案 C-1：目前回撤**

為什麼：
- 與規則卡「依據：目前回撤深於兩成／三成」同一個名詞，使用者能直接對上。
- 風控 VETO L-2、L-0 的理由是**欄位標籤**要放進警示句（「…目前為 -0.25」疊字）與巢狀括號；本案是獨立卡標題，後面不接「目前為」，也沒有括號，這兩個原因都不成立。仍請風控裁示。
- 基準由說明句承擔，詞彙與核可標籤一致。

**備案 C-2：最新收盤價相對區間最高收盤價的回撤**

為什麼：就是風控核可的欄位標籤原句，一字不改，核可風險最低；代價是當卡標題偏長（18 字），且與規則卡的「目前回撤」名稱對不上，使用者要自己連結。

**備案 C-3：目前回撤（相對區間最高收盤價）**

為什麼：標題同時有規則名詞與基準。代價：括號補語與「最新收盤價相對區間最高收盤價」不是同一個片語，與核可標籤只共用一半詞。

### 數值列與基準高點日標籤

數值列格式（沿用 `最大回撤` 卡的括號句型）：

> **-25.12%（區間最高收盤日 2026-08-12）**

- 主案 C-4：日期標籤「**區間最高收盤日**」。為什麼：與核可標籤的「區間最高收盤價」同詞根；刻意不用「高點」，因為最大回撤卡的「高點」是另一段下跌的起點，日期可能不同，共用詞會讓讀者以為是同一天；不用「前高」「歷史高點」（區間外更早的高點會讓字面講過頭）。
- 備案 C-5：「**區間最高收盤日（最近一次）**」。為什麼：把「同一最高收盤價出現多次時取最近一次」寫進標籤。代價：多四個字，括號套括號（整列在全形括號內）。
- 日期格式沿用該卡既有的 ISO 日期（YYYY-MM-DD），不用 `buildDataAsOfBadge` 的月-日縮寫。

### 說明句

**主案 C-6**（放在 description 位置，一個意思）

> 最新收盤價相對區間最高收盤價的回撤，會隨最新收盤改變；最大回撤是區間內曾出現的最深一段回落，兩者是不同的數字。

為什麼：
- 第一段重述核可的欄位定義，沒有新術語。
- 第二段只說最大回撤的定義，與同頁最大回撤卡的「觀察區間內高點到低點之最大跌幅」同義。
- 「兩者是不同的數字」直接回答「為什麼最大回撤 -42%、卡片卻是加碼參考」的第一個疑問，但沒有寫成因果句，不暗示哪個數字支持哪個動作。
- 「會隨最新收盤改變」只說「改變」，不說「回升」「改善」，避免方向暗示。

**備案 C-7**

> 目前回撤只看最新收盤價相對區間最高收盤價的位置；最大回撤看區間內曾出現的最深一段回落，兩者可能相差很多。

為什麼：用「只看」「看」對稱句型，白話度更高。代價：「位置」一詞在這個專案已用於「區間位階」，可能與位階混淆；「可能相差很多」是弱量化詞，風控曾對類似語感嚴格。

**建議同時上線的第二句 C-8**（沿用核可的免責語意，你要的「不得把回撤說成損益」的明文化）

> 該數字描述價格自身的回落幅度，並非持倉損益。

為什麼：前半句是回撤規則 explanation 已核可的原句；後半句改用 2026-10-04 越過水位頁尾已核可的「非持倉損益」詞彙。不用原句的「與此部位的未實現損益無關」，因為個股頁也會開在未持有標的上，「此部位」會指到不存在的東西。

**備案 C-8b**：「該數字描述價格自身的回落幅度，與此部位的未實現損益無關。」逐字取自已核可 explanation，核可風險最低，但未持有標的頁的「此部位」不成立。

說明句長度：C-6＋C-8 共兩句，約 80 字，高於其他指標卡的一句 description；若風控或 art-lead 認為過長，可只留 C-6，把 C-8 移到頁尾揭露區（`buildTechnicalFooterItems`），但那樣就離開了數字所在位置，我不建議。

# 風險點

1. **（項目一）前後端同版本部署**：`HELD_ACTION_LABELS` 與 `RANGE_ACTION_LABELS` 必須同值，測試會擋，但部署空窗期間 UI 大字與 basis 句字面會暫時不一致。
2. **（項目一）取代已逐字核可的契約**：2026-09-19／09-26 核可的 stop_loss 字面「停損參考」會被取代；風控請連同 basis 派生句一起重核。
3. **（項目一）「停損」二字殘留**：S-1／S-2 仍含「停損」，字面上與格標題有共同字根；真正的隔離依賴既有揭露行。若風控要求連字根都不重疊，只剩「完全不提停損」一條路，那會與 reduce 無法區分，我不推薦。
4. **（項目一）語意延伸**：現行唯一發出 stop_loss 的規則是「目前回撤深於三成」，該規則 explanation 明講「與此部位的未實現損益無關」，但動作名「停損」本身帶有損益實現的聯想。這是既有命名問題，不是本案引入，建議列管，由 CEO 與風控另案評估是否整個動作更名。
5. **（項目二）卡標題與 description 已被測試釘住**：所以主案是新增一張卡，而不是改現有卡。若 art-lead 堅持同卡內加列（備案 B），卡標題「最大回撤」下出現「目前回撤」列的語意錯位要先過風控。
6. **（項目二）-0.00% 顯示**：`formatPercent` 對極小負值會印「-0.00%」，與決策卡 `fmtSigned`（四捨五入為 0 時印 0.0%）慣例不同。這是顯示邏輯不是字面，請 frontend-engineer 一併處理。
7. **（項目二）基準價缺席**：後端沒回傳區間最高收盤價本身，使用者只能對日期不能對價格；字面刻意不暗示可對價。若 CEO 要讓使用者能核算，需 backend 另增欄位，屆時字面要補送審。
8. **（項目二）說明句長度與字級**：IndicatorCard description 現為 `text-xs text-neutral-500`，風控 2026-10-03 對決策卡揭露行設的下限是 `text-xs text-neutral-400`；請風控裁示技術面板是否適用同一下限。
9. **（項目二）此頁面也開在未持有標的上**：所有字面避開「此部位」「你的持倉」。
10. **（附帶發現，不屬本案）** `format.ts` L454–L475 的 `SIGNAL_FIELD_OPTIONS` 說明自己鏡像後端 `FIELD_LABELS`，但沒有 `drawdown.current`；若日後警示規則要能選目前回撤，這張表要補，且標籤用風控核可版。
