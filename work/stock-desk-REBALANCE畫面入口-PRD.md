## 背景與目標

**現況**：REBALANCE（季末重算 TOTAL_DEPLOY）目前沒有畫面入口，只能直接呼叫 `POST /api/playbook/rebalance`（風控 2026-11-07 更正版通知）。N-207 的「待生效」戳記閘要靠 TOTAL_DEPLOY 重算才解開（CEO #121、#123），若使用者只能用 API 呼叫，N-207 上線後新標的的解開方式不可用，也不符合「名單變動必須是有意識的動作」的紀律。

**目標**：在排程台頁提供一個正式入口，讓 CEO 能手動觸發 REBALANCE，送出前有二次確認與並發提醒，送出後清楚呈現三種結果，且全程不變成對 REBALANCE 時機的建議。

**成功指標**：
1. 不需手寫 API 呼叫即可完成一次 REBALANCE。
2. 確認畫面列出目前的 TOTAL_DEPLOY 與設定時間，使用者看過才送出。
3. 並發提醒、R-10(b) 的說明、三種結果字面都經風控逐字定稿。
4. N-209 先於 N-207 上線（R-17），且不違反風控 R-5′「N-197a 上線前新增 REBALANCE 入口須先回風控」。

## 使用者與情境

唯一使用者：CEO（單人使用，本機部署）。

| 情境 | 描述 |
|---|---|
| S-A 手動執行 | 使用者自己決定要重算 TOTAL_DEPLOY，在排程台頁按入口，確認後送出 |
| S-B 結果為不足資料 | 後端回 `insufficient_data`（`REBALANCE_BLOCKED`），未寫入任何值 |
| S-C 結果為被取代 | 執行期間 TOTAL_DEPLOY 已被另一項操作改寫，後端回 `superseded`（`REBALANCE_SUPERSEDED`；N-197a 合入後才會出現） |
| S-D 解開 N-207 的待生效 | 提交名單後，使用者以此入口重算 TOTAL_DEPLOY（解開方式見 N-207 FR-21） |

## 範圍內 / 範圍外

**範圍內**
1. 排程台頁上的 REBALANCE 入口（按鈕與說明）。
2. 二次確認畫面（含目前 TOTAL_DEPLOY 與設定時間、並發提醒、R-10(b) 說明）。
3. 三種結果的呈現，以及「結果不明」（逾時、網路錯誤）的呈現。
4. 與 N-195、N-196、N-197a、N-207 的先後與相依。

**範圍外（non-goals）**
1. **任何形式的 REBALANCE 時機建議**：不提示「現在適合」、不倒數、不依日期高亮或啟用入口、不推播提醒。這是紅線（見功能需求 FR-11、FR-12）。
2. 自動或排程執行 REBALANCE。
3. REBALANCE 演算法、`RebalanceResult` 欄位、既有 `REBALANCE_BLOCKED` 字面的修改（N-196、N-197a 的範圍）。
4. 資金確認（confirm-rules）的畫面入口，或確認之後改資金的入口。若日後要加，須先回風控（R-5′）。
5. 在入口輸入任何數值（資本額、比例）；入口只觸發重算，不收參數。
6. 結果歷史清單、稽核查詢頁（v0 只呈現當次結果，見 Q-5）。
7. 技術選型與 API 契約設計（交 TA 與實作者）。
8. N-207 的標的設定畫面（另案）。

## 功能需求（逐條編號）

### 一、入口位置與觸發
- **FR-1**：入口放在排程台頁。其他頁面不設入口。
- **FR-2**：入口常駐可見，**不依日期、季度窗口、名單狀態而啟用、停用或高亮**（紅線，見 FR-11）。若後端目前無法執行（例如規則集尚未確認），畫面只陳述事實與原因類別，不以隱藏入口代替。（後端行為見 Q-3。）
- **FR-3**：按下入口先開二次確認畫面；未在確認畫面按下「確認執行」前，不得呼叫 REBALANCE。取消即關閉，資料與畫面狀態不變。

### 二、二次確認
- **FR-4**：確認畫面須列出**目前的 TOTAL_DEPLOY**（金額取後端，格式 `.2f`）與**其設定時間**。設定時間須明確標示時區（Asia/Taipei），不得直接貼 ISO 原始字串（比照風控對 N-197a 的要求）。
- **FR-5**：若目前讀不到 TOTAL_DEPLOY（鍵不存在），畫面陳述「目前沒有 TOTAL_DEPLOY 紀錄」，**不得以 0 代入**。
- **FR-6**：確認畫面須附**並發提醒**，事實逐字依風控 2026-11-07 更正版通知，不得增刪或改寫其事實（原文見下方「並發提醒事實來源」）。
- **FR-7**：確認畫面（或入口旁的說明，兩處擇一或並列，由風控定）須寫明（R-10(b)）：**重送資金確認會用提交的數字覆寫現金，TOTAL_DEPLOY 不看持股，所以不能用來代替 REBALANCE。**
- **FR-8**：送出後，確認按鈕立即鎖定，直到結果回來為止；同一次確認只送出一次請求，不自動重試。

### 三、結果呈現
- **FR-9**：依後端回傳呈現三種結果，字面一律取自 API 回應或風控定稿字面，前端不自行改寫：
  - **ok**：陳述已重算，列出新的 TOTAL_DEPLOY（`.2f`）與寫入時間（標明時區）。不加評價、不暗示「已最佳」或「可放心」。
  - **insufficient_data**（`REBALANCE_BLOCKED`）：沿用既有字面，第一個子句須讓人看出「季末 REBALANCE 未執行」；說明未寫入任何值。
  - **superseded**（`REBALANCE_SUPERSEDED`，**N-197a 合入後才會出現**）：須符合風控 2026-11-07 第 3(c) 點：開頭與 `REBALANCE_BLOCKED` 一致；明說本次沒有寫入任何值（TOTAL_DEPLOY 與現金都沒有被本次變更）；原因只陳述「執行期間 TOTAL_DEPLOY 已被另一項操作改寫」，不點名操作；給出目前 TOTAL_DEPLOY（`.2f`）與寫入時間（標明時區）；下一步只寫「若要以目前的資金與持股重算，請再執行一次 REBALANCE」，不承諾重跑一定成功，不用「不影響」「無風險」「已自動處理」；不暗示目前 TOTAL_DEPLOY 依持股算出。
- **FR-10**：**結果不明**（逾時、網路錯誤、非預期回應或未知結果類型）時，畫面不得宣稱成功或失敗，只陳述「結果未確認」並顯示目前讀到的 TOTAL_DEPLOY 與設定時間，請使用者以此核對；前端不得自動重送。N-197a 合入前，後端不會回 `superseded`；前端遇到未知類型一律走本條，不得誤判為成功。
- 完成後，排程台頁上的 TOTAL_DEPLOY 相關顯示須與結果一致，不需重啟或手動重新整理。

### 四、紅線
- **FR-11**：入口、確認畫面、結果畫面不得出現任何 REBALANCE 時機建議，包括「建議」「適合」「現在是執行時機」「該重算了」「別忘了」之類字樣，也不得有依日期變化的樣式或提醒。
- **FR-12**：畫面上出現「季末」時，**只做事實陳述**，限於說明此操作的名稱與性質（例如「季末 REBALANCE：以目前資金與持股重算 TOTAL_DEPLOY」）或沿用既有結果字面；不得把「季末」用作時機判斷（例如「已進入季末」「季末將至」「建議於季末執行」）。

### 五、先後與相依
- **FR-13**：N-209 的 base 須含 N-195（REBALANCE 不再寫 cash，改用 `set_total_deploy`）與 N-196（REBALANCE 讀取時點：同一個讀交易內重讀批次與現金）。理由：入口一上線，REBALANCE 就從「只有 API 呼叫」變成日常可按，N-195、N-196 修的是 REBALANCE 與結算、資金確認的交錯，應先於入口合入。
- **FR-14**：**N-197a 上線前新增 REBALANCE 入口，須先回風控**（風控 R-5′，ADR-0041）。本 PRD 預設 N-209 排在 N-197a 之後上線（順序：R2 → N-196 → N-197a → N-177b → N-198 → N-209 → N-207）。若要提早，須由 coordinator 回風控取得同意，且並發提醒維持有效（更正版通知「本補充在 N-197a 上線前有效」）。
- **FR-15**：N-209 須先於 N-207 上線（CEO #124、風控 R-17）。N-207 的字面在 N-209 合入前不得提「REBALANCE 入口」。
- **FR-16**：N-209 不改變 N-197a 的契約：`superseded` 分支由 N-197a 提供，N-209 只負責呈現；N-197a 合入前該分支在畫面上不可能出現。

1. **N-195（依賴）**：REBALANCE 不再寫 cash、改用 `set_total_deploy`；N-195 與 N-177a 同批合入（R2）。N-209 base 必須含（FR-13）。
2. **N-196（依賴）**：REBALANCE 讀取時點修正，spec 要求 base 含 N-177a 與 N-195。N-209 base 必須含（FR-13）。
3. **N-197a（相依，風控 R-5′）**：戳記比對、不一致拒寫並回 `superseded`。N-197a 上線前新增入口須先回風控；N-209 預設排在其後（FR-14）。`REBALANCE_SUPERSEDED` 字面要送風控逐字定稿。

5. **N-207（被依賴）**：N-207 待生效閘要靠 TOTAL_DEPLOY 重算解開；N-209 先上線（R-17、CEO #124）。
