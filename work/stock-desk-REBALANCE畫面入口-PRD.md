## 背景與目標

**現況**：REBALANCE（季末重算 TOTAL_DEPLOY）目前沒有畫面入口，只能直接呼叫 `POST /api/playbook/rebalance`（風控 2026-11-07 更正版通知）。N-207 的「待生效」戳記閘要靠 TOTAL_DEPLOY 重算才解開（CEO #121、#123），若使用者只能用 API 呼叫，N-207 上線後新標的的解開方式不可用，也不符合「名單變動必須是有意識的動作」的紀律。

**目標**：在排程台頁提供一個正式入口，讓 CEO 能手動觸發 REBALANCE，送出前有二次確認與並發提醒，送出後清楚呈現三種結果，且全程不變成對 REBALANCE 時機的建議。

**成功指標**：
1. 不需手寫 API 呼叫即可完成一次 REBALANCE。
2. 確認畫面列出目前的 TOTAL_DEPLOY 與設定時間，使用者看過才送出。
3. 並發提醒、R-10(b) 的說明、三種結果字面都經風控逐字定稿。
4. N-209 先於 N-207 上線（R-17），且不違反風控 R-5′「N-197a 上線前新增 REBALANCE 入口須先回風控」。

## 使用者與情境

唯一使用者：CEO（單人使用，本機部署）。

| 情境 | 描述 |
|---|---|
| S-A 手動執行 | 使用者自己決定要重算 TOTAL_DEPLOY，在排程台頁按入口，確認後送出 |
| S-B 結果為不足資料 | 後端回 `insufficient_data`（`REBALANCE_BLOCKED`），未寫入任何值 |
| S-C 結果為被取代 | 執行期間 TOTAL_DEPLOY 已被另一項操作改寫，後端回 `superseded`（`REBALANCE_SUPERSEDED`；N-197a 合入後才會出現） |
| S-D 解開 N-207 的待生效 | 提交名單後，使用者以此入口重算 TOTAL_DEPLOY（解開方式見 N-207 FR-21；規則集尚未確認時此入口不會執行，見 S-E） |
| S-E 規則集尚未確認 | 後端在任何寫入之前回 `unauthored`，未寫入任何值（CEO #126 甲案，FR-25） |
| S-F 現金鍵不存在 | 規則集已確認、但現金沒有紀錄，後端拒寫並回現金未記錄 status（RC-25，FR-26） |

## 範圍內 / 範圍外

**範圍內**
1. 排程台頁上的 REBALANCE 入口（按鈕與說明）。
2. 二次確認畫面（含目前 TOTAL_DEPLOY 與設定時間、並發提醒、R-10(b) 說明）。
3. 三種結果的呈現，以及「結果不明」（逾時、網路錯誤）的呈現。
4. 與 N-195、N-196、N-197a、N-207 的先後與相依。

**範圍外（non-goals）**
1. **任何形式的 REBALANCE 時機建議**：不提示「現在適合」、不倒數、不依日期高亮或啟用入口、不推播提醒。這是紅線（見功能需求 FR-11、FR-12）。
2. 自動或排程執行 REBALANCE。
3. REBALANCE 演算法、`RebalanceResult` 欄位、既有 `REBALANCE_BLOCKED` 字面的修改（N-196、N-197a 的範圍）。
4. 資金確認（confirm-rules）的畫面入口，或確認之後改資金的入口。若日後要加，須先回風控（R-5′）。
5. 在入口輸入任何數值（資本額、比例）；入口只觸發重算，不收參數。
6. 結果歷史清單、稽核查詢頁（v0 只呈現當次結果，見 Q-5）。
7. 技術選型與 API 契約設計（交 TA 與實作者）。
8. N-207 的標的設定畫面（另案）。

## 功能需求（逐條編號）

### 一、入口位置與觸發
- **FR-1**：入口放在排程台頁。其他頁面不設入口。
- **FR-2**（v1.3 依 CEO #126 甲案、RC-28、RC-34 修訂）：入口常駐可見，**不依日期、季度窗口、名單狀態、規則集確認狀態而啟用、停用或高亮**（紅線，見 FR-11），**唯一例外見下方 (b)**。
  - (a) **甲案後的後端行為（CEO #126）**：規則集尚未確認時，後端在任何寫入之前回新 status `unauthored`、不寫入任何值（FR-25）；規則集已確認但現金鍵不存在時，回現金未記錄 status、不寫入任何值（FR-26）；批次表為空時仍回 200 `ok`（TA 2026-11-09 評估 Q-3(a)）。**入口在未確認模式下不停用**（風控 2026-11-10 RC-34 撤回 S-5）：未確認時按下入口，會得到 `unauthored` 結果畫面，其字面已說明原因與該去哪裡；入口在任何情況下都同樣可按（除 (b)），畫面不得假設「未確認時會被擋」而在前端自行判斷、自行停用。
  - (b) **唯一例外（RC-28）**：FR-21 前提失效條款觸發，並發提醒必須撤下，而又沒有風控定稿的更新版時，入口須**在同一次 push 中停用**，不得讓入口在沒有提醒的狀態下繼續可用。停用狀態須顯示一句預先定稿的事實句，內容限於兩項事實：入口暫停使用；暫停期間，待生效的標的維持待生效。不推測原因，不提示何時恢復。字面由 creative-lead 現在就擬，與 N-209 其他字面一併送風控逐字定稿，PM 不擬。停用須由後端旗標驅動，前端不得自行推斷。此期間 N-207 的閘解不開，屬保守方向，風控已接受。
  - (c) **日後要在其他條件下停用入口**，必須同時符合兩點：由後端旗標驅動；附上原因的事實句並經風控定稿（RC-34）。不符合者視為違反本條。
  - 若後端回覆為事前無法執行的狀況，畫面只陳述事實與原因類別，不以隱藏入口代替。
- **FR-3**：按下入口先開二次確認畫面；未在確認畫面按下「確認執行」前，不得呼叫 REBALANCE。取消即關閉，資料與畫面狀態不變。

### 二、二次確認
- **FR-4**：確認畫面須列出**目前的 TOTAL_DEPLOY**（金額取後端，格式 `.2f`）與**其設定時間**。設定時間須明確標示時區（Asia/Taipei），不得直接貼 ISO 原始字串（比照風控對 N-197a 的要求）。
- **FR-5**：若目前沒有 TOTAL_DEPLOY 紀錄（鍵不存在），畫面陳述「目前沒有 TOTAL_DEPLOY 紀錄」，**不得以 0 代入**。「沒有紀錄」**由後端欄位 `total_deploy_recorded` 明示**（N-209b 提供，見 FR-19），前端不得以 `total_deploy === "0"` 推斷。（現況後端在鍵不存在時會回 `"0"`，且 ok 訊息會寫「由 0.00 重算」。CEO #126 採甲後：規則集未確認、現金鍵不存在兩種情況改為拒寫（FR-25、FR-26）；「現金存在、TD 鍵不存在」仍回 ok，改用「先前沒有紀錄」變體句（FR-24）。）
- **FR-6**：確認畫面須附**並發提醒**，事實範圍依**風控 2026-11-09 裁示（F-1～F-3，排除 X-1～X-4）**，不再要求逐字依照 11-07 更正版通知（事實範圍見下方「並發提醒事實範圍」）。**不列入「結算」**（X-1）。F-1 中「確認規則集並設定資本額」按鈕一項，依 CEO #126 甲案**不列入**（未確認時 REBALANCE 一律被閘擋下，列入等於陳述不存在的非保守風險；F-1 按鈕不列入並發提醒）。
- **FR-7**：確認畫面（或入口旁的說明，兩處擇一或並列，由風控定）須寫明（R-10(b)）：**重送資金確認會用提交的數字覆寫現金，TOTAL_DEPLOY 不看持股，所以不能用來代替 REBALANCE。**
- **FR-8**：送出後，確認按鈕立即鎖定，直到結果回來為止；同一次確認只送出一次請求，不自動重試。明列兩點（TA 實作約束 F-2、F-3，見 TA 2026-11-09 評估）：(a) **離線時暫停、恢復連線後自動送出（networkMode 預設 `online` 的行為）屬禁止範圍**，要求該 mutation 設 `networkMode:"always"`；(b) **連點送出兩次須以同步鎖防止**（不得僅靠按鈕重新渲染後才鎖定）。

### 三、結果呈現
- **FR-9**（v1.3：原三種結果加 `unauthored` 與現金未記錄 status，共五種；本 PRD 其他處的「三種結果」一律含這兩種，AC-13 的掃描範圍亦同）：依後端回傳呈現結果，字面一律取自 API 回應或風控定稿字面，前端不自行改寫：
  - **ok**：陳述已重算，列出新的 TOTAL_DEPLOY（`.2f`）與**本次寫入時間**（標明時區）。現況 ok 回應沒有寫入時間，此欄位**需後端小單 N-209b 提供**（見 FR-19）；金額與時間取後端算好的欄位，前端不再格式化。不加評價、不暗示「已最佳」或「可放心」。
  - **insufficient_data**（`REBALANCE_BLOCKED`）：沿用既有字面，第一個子句須讓人看出「季末 REBALANCE 未執行」；說明未寫入任何值。
  - **superseded**（`REBALANCE_SUPERSEDED`，**N-197a 合入後才會出現**）：須符合風控 2026-11-07 第 3(c) 點：開頭與 `REBALANCE_BLOCKED` 一致；明說本次沒有寫入任何值（TOTAL_DEPLOY 與現金都沒有被本次變更）；原因只陳述「執行期間 TOTAL_DEPLOY 已被另一項操作改寫」，不點名操作；給出目前 TOTAL_DEPLOY（`.2f`）與寫入時間（標明時區）；下一步只寫「若要以目前的資金與持股重算，請再執行一次 REBALANCE」，不承諾重跑一定成功，不用「不影響」「無風險」「已自動處理」；不暗示目前 TOTAL_DEPLOY 依持股算出。
  - **unauthored**（CEO #126 甲案、RC-19；規則集尚未確認）：字面由 creative-lead 擬稿、風控逐字定稿（`REBALANCE_UNAUTHORED`，N209b-A3，N-209b 合併前完成）。內容限於事實：本次未執行、未寫入任何值、原因為規則集尚未確認，並指向「確認規則集並設定資本額」。不得出現金額，不得出現「已執行」「重算」，不得有時機建議（RC-19）。
  - **現金未記錄 status**（RC-25；status 名稱待 TA 定，風控例示 `cash_unrecorded`）：字面由 creative-lead 擬稿、風控逐字定稿（N-209b 合併前完成）。內容限於三項事實：未執行；沒有寫入任何值；原因是現金沒有紀錄，無法陳述總資產。不得推測原因，不得有金額（含 0.00），不得有「已執行」「重算」，不得指向畫面上不存在的入口，不得有時機建議。
- **FR-10**：**結果不明**時，畫面不得宣稱成功或失敗，只陳述「結果未確認」並顯示目前讀到的 TOTAL_DEPLOY 與設定時間，請使用者以此核對；前端不得自動重送。結果分類依 TA 約束 F-4：以執行期的封閉集合判定（N-209 在 N-197a 之後上線；v1.3 依 CEO #126 與 RC-25，集合為 `{ok, insufficient_data, superseded, unauthored, 現金未記錄 status}`，後兩者 status 名稱以 TA 定案為準，否則會落入本條「結果不明」），**其餘一律走本條，絕不判為「失敗」**，包括：未知 status、缺欄位、網路錯誤（`ApiError` status 0）、任何非 2xx（含 500；500 可能發生在寫入 commit 之後）。前端沒有 timeout 機制且不加（TA F-5），故本條不含「逾時」情境；client 斷線不會中止後端，後端可能仍已寫入，只能視為結果不明。
- 完成後，排程台頁上的 TOTAL_DEPLOY 相關顯示須與結果一致，不需重啟或手動重新整理。
