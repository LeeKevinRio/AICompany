# N-118 查證指令：除權息預告表是否在除息日前持續列出事件，以及擷取紀錄 row_count 是否與實際寫入列數一致（給 CEO 本機執行）

- 日期：2026-10-24
- 對應：後續追蹤清單 N-118（ADR-0027 D-3「晚到資料的觸發」第 10 點 (10) (c)、(e)）；風控單項確認 `work/reviews/2026-10-24-N17因子修訂觸發單項確認-風控.md`
- 腳本：`apps/stock-desk/backend/scripts/n118_dividend_persistence_probe.py`
- 性質：唯讀離線查證，不屬持倉資料鏈（ADR-0012 C-7）。本雲端環境沒有市場 DB 的真實資料，**必須在存有市場 DB 的機器上跑**。不需網路、不涉祕密、不需付費。

## 一、怎麼跑

```bash
# 路徑用變數，請依您的機器調整
REPO=<您的 AICompany checkout 路徑>
export STOCK_DESK_MARKET_DB_PATH="$REPO/apps/stock-desk/backend/data/stock-desk-market.db"   # 或您實際使用的市場 DB

cd "$REPO/apps/stock-desk/backend"

# 1) 只輸出彙總計數（請把完整 stdout 貼回）
uv run python scripts/n118_dividend_persistence_probe.py --db-path "$STOCK_DESK_MARKET_DB_PATH"

# 2) 選用：只在第 (c) 段 vanished_gone 或 vanished_returned 大於 0 時再跑。
#    --detail 的值要不小於 vanished 事件總數（第 1) 步輸出中 vanished_gone 與 vanished_returned
#    的 closed 加 open 合計），才能全部列出供 TWSE 公告對照
#    （代號、除息日、run id；不含名稱、價格、原始列）。下例以 200 為例，請依實際總數調整
uv run python scripts/n118_dividend_persistence_probe.py --db-path "$STOCK_DESK_MARKET_DB_PATH" --detail 200
```

- `--db-path` 省略時依序用環境變數 `STOCK_DESK_MARKET_DB_PATH`，再退回 `./data/stock-desk-market.db`。
- 檔案以 SQLite `mode=ro` 開啟並下 `PRAGMA query_only=ON`；檔案不存在就拒絕（exit 2），不會新建。只印 stdout，不寫任何檔、不改任何 DB。
- 只選 run 編號、`session_date`、`content_hash`、`row_count`、key、代號、除息日；**不選 `raw_json`、不選名稱、不讀價格**。
- 唯一副作用來自 SQLite 本身：讀 WAL 模式資料庫時，旁邊可能出現 `-wal`／`-shm` 輔助檔，資料庫檔本身位元組不變。想更保守，可先把 `.db`、`.db-wal`、`.db-shm` 三個檔一起複製到別處再跑。
- 後端服務可以照常運行，腳本只讀、不取寫鎖。
- 只用標準函式庫，不 import `app.*`。
- 退出碼：0 成功；2 表示讀不到 DB、表不存在或沒有任何 `dividend_announce` run。

## 二、輸出各段的意思

| 段落 | 內容 |
| --- | --- |
| Sample | 可用 ok run 數、不同內容數、`session_date` 範圍、同一 session 多個 ok run 的數量（含不可用的 ok run，屬輸入完整性條件）、相鄰 ok run 相隔超過 4 天的次數、事件數（closed／open／已在第一個 run 就列出的） |
| (c) Persistence classes | 事件分類：`persistent`（除息日前每個 run 都列出）、`vanished_gone`（消失後沒再出現）、`vanished_returned`（消失後又出現）、`single_observation`（只有一個 run，無法檢驗）、`first_seen_on_or_after_ex`（首見時已不早於除息日）。`vanished_gone` 再分改期候選、同代號還有其他既有事件、同代號完全消失。每項都分 closed／open |
| (c) Early disappearance | 相鄰兩個可用 ok run 之間：相鄰對總數、可檢驗對數 N_pair（前一個 run 未到期 key ≥ 30）、提前消失總數（前一個 run 有、後一個沒有、而且除息日晚於後一個 run 的 `session_date` 的 key）、單批最大提前消失數、整批掉出對數（提前消失 ≥ 3 且 ≥ 0.10 × 未到期 key 數，所有相鄰對都計入）。另有 M 與其補數：已結束、屬可檢驗類別（`persistent`、`vanished_gone`、`vanished_returned`）、而且**尾段間隔** ≤ 3 天的事件數，以及尾段間隔 > 3 天而不計入 M 的事件數。尾段間隔 = 除息日減去除息日前最後一個可用 ok run 的 `session_date`，以日曆天計；腳本沒有交易日曆，遇連假的事件會被排除在 M 之外（寧可少算） |
| (c) row_count change | 相鄰 ok run 的 `row_count` 差值分布（最小值、p25、中位數、p75、最大值）、最大跌幅與占比。`row_count` 也會因合法原因變動，這是估計單批不完整頻率的參考，不是結論。標為 descriptive，不構成判讀門檻。 |
| (e) row_count vs rows stored | 各 ok run 的 `row_count` 與實際寫入列數是否一致；`stored < row_count` 代表該批有 key 撞號（同代號同日期被覆蓋）；`stored > row_count`、`stored == 0`、ok 但無 hash、ok 但 `row_count <= 0` 都屬異常 |
| Registered reading rule | 風控 2026-10-25 登記（`work/reviews/2026-10-25-N118判讀門檻確認-風控.md`），執行前定案，執行後不得更動。依序五步（第 5 步由風控判讀），前四步印出數字與 met / not met：(1) 輸入完整性：`stored > row_count`、有 hash 但 `stored == 0`、ok 但 hash 為 NULL、ok 但 `row_count <= 0`、ok 但不可用、同一 session 多個 ok run，任一大於 0；(2) 反例：`vanished_returned`（closed 加 open）≥ 1，或整批掉出對 ≥ 1；(3) 樣本：S < 60、N_pair < 60 或 M < 60；(4) 未解釋消失：已結束的 `symbol_gone` 加 `symbol_relisted_existing` ≥ 1。第 5 步（以上皆未命中）與最終結論由風控依數字判讀，**腳本不印最終結論**。本列為摘要；判讀以 `work/reviews/2026-10-25-N118判讀門檻確認-風控.md` 第二節第 3 點原文為準。 |
| Conclusion-format fields | 供風控確認用：依據的可用 ok run 數、S（不同 `session_date` 數）與期間、N_pair 與相鄰對總數、M、已結束且可檢驗的事件數、`events_closed`、`vanished_returned`（closed 加 open）、整批掉出對數、未解釋消失數、`reschedule_candidate`（closed）、3/N_pair 與 3/M（零反例時單次回應不完整機率的 95% 上界，**僅零反例時有意義**）、執行日期（取自執行機器的 `date.today()`）；並固定印「樣本不足或未完成一律視為不成立；成立與否須送風控確認。」 |

## 三、請 CEO 回傳

1. 腳本完整 stdout（請直接貼上，不必存檔）。
2. 市場 DB 開始每日抓取的日期（若與輸出的 `session_date` 範圍起點不同，請說明）。
3. 若有 `vanished_*` 事件，是否知道原因（例如該日 TWSE 預告表改版、更正、公告撤銷）。
4. 執行時 repo 的 commit：在 repo 目錄執行 `git rev-parse HEAD`，把輸出貼回，用來核對跑的是已登記常數的版本。

## 四、這份輸出不能做什麼

- 消失是被計數，不是被解釋：真撤銷與來源單批回應不完整，在 DB 內看起來一樣。要區分需要對照 TWSE 公告，由有網路的人做。
- 沒有 ok run 的交易日看不到；腳本沒有交易日曆。
- 每個 session 只保留第一筆 ok run，同一 session 內的修訂看不到。
- 沒有 `Code` 的列在擷取時就被略過，`row_count` 與寫入列數都不含它們。
- 成立與否由風控確認；樣本不足或未完成一律視為不成立。門檻已於 2026-10-25 由風控登記（`work/reviews/2026-10-25-N118判讀門檻確認-風控.md`），執行後不得更動。
