# L-10g：槓桿章節「日線取得時間」兩行的替代——payload 分析（dev-lead，2026-10-04）

> 主會話轉錄；只讀碼與 grep，未改檔、未跑測試。

## 現況
- `LeverageChapterView.tsx` L185（`drag.as_of`／`drag.index_as_of`）、L243–L244（`erosion.as_of`）以「日線取得時間」顯示 `provenance()` 列層 `as_of`，與 ADR-0019 D-5 衝突。
- drag payload（`backend/app/leverage/drag.py` L179–L182）：`as_of`、`source`、`index_as_of`、`index_source`；`window.start_date`／`end_date`（兩序列共同交易日對齊後起訖，僅 ok 有值）。erosion（`erosion.py` L103–L104）：只有 `as_of`、`source`，**無任何日期欄**。
- ETF 最後日線日期已有兩處：`chapter.holding.last_bar_date`（`service.py` L91／L103／L113）、envelope `data.last_bar_date`（`api/leverage.py` L139）。**指數最後一根日線日期在整個 payload 都沒有**；`window.end_date` 不等於指數自身最後一根。風控「不可直接刪」正確。
- 三個 `as_of` 皆為 `PriceBar.as_of`（最大日期那根的列層取得時間）；drag 與 erosion 共用同一份 `index`（`service.py` L189／L220／L243），`drag.index_as_of` 與 `erosion.as_of` 依構造相等。後端 app 內無消費者；**建議保留欄位、只拿掉顯示**（D-5「機器可讀出處」；刪除為破壞性 API 變更）。

## 最小方案
**後端（附加欄位、預設 None、`YYYY-MM-DD`）**
- `signals/frame.py` 新增 `last_bar_date(bars) -> str | None`（`max(b.date).isoformat()`，空清單 None），與 `provenance()` 取同一根 bar。
- `drag.py`：模型加 `last_bar_date`、`index_last_bar_date`；L315–L316 旁計算；`_insufficient` 與 ok 路徑傳入。
- `erosion.py`：模型加 `last_bar_date`（或 `index_last_bar_date`，欄名交 tech-architect）；L161 計算、L177／L241 傳入。
- `service.py`／`api/leverage.py` 不用改（`model_dump` 自動帶出；unmapped 時 None）。
**前端**
- `types.ts` `DragDecomposition` 加兩欄、`ErosionEstimate` 加一欄；`LeverageChapterView.tsx` 兩行改讀新欄並以「資料截至」家族字面顯示（creative-lead 起草、風控審）；日期格式沿用 E-4 `formatDataAsOfDate`（需 export 或抽共用、行為不變）；`formatDateTime` import 保留（L252 `generated_at` 仍用）。
- 零後端替代只能解 drag 行（`window.end_date`，語意「計算截至」），erosion 無替代，不建議半套；可作字面選項供 creative-lead 考慮。
