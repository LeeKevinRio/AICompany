# V-1 查證指令：TWT48U_ALL 除權息列出前置天數（給 CEO 本機執行）

- 日期：2026-10-04
- 對應：ADR-0016「待查證參數」V-1（`MIN_ANNOUNCE_LEAD_DAYS`，`app/dividends/coverage.py`，目前預設 `1`，狀態「待查證」）
- 腳本：`apps/stock-desk/backend/scripts/v1_announce_lead_probe.py`
- 性質：唯讀離線查證。不屬持倉資料鏈，不違反 ADR-0012 C-7；本雲端環境沒有市場 DB 的真實資料，**必須在存有市場 DB 的機器上跑**。

## 一、怎麼跑

```bash
cd apps/stock-desk/backend
uv run python scripts/v1_announce_lead_probe.py --db-path ./data/stock-desk-market.db
```

- `--db-path` 省略時依序用環境變數 `STOCK_DESK_MARKET_DB_PATH`、再退回 `./data/stock-desk-market.db`。
- `--top N`（預設 30）限制「依 ℓ 由小到大」列出的事件數；`--all` 全列。
- 檔案以 SQLite `mode=ro` 開啟、不存在就拒絕（exit 2）而不是新建；只印 stdout，不寫任何檔、不寫任何 DB。
  唯一的副作用來自 SQLite 本身：讀 WAL 模式資料庫時，旁邊可能留下 `-wal` / `-shm` 輔助檔，資料庫檔本身位元組不變。
- 後端服務可以照常運行中；腳本只讀、不取寫鎖。
- 只用標準函式庫，不 import `app.*`，因此不會碰到任何應用程式接線或 `app.data.market_panel`。
- 退出碼：0 成功；2 表示讀不到 DB、表不存在或沒有任何 ok 的 `dividend_announce` run。

## 二、它依 V-1 判準算什麼

資料來源：`pit_snapshot_runs`（`kind='dividend_announce'`、`status='ok'`）與 `pit_dividend_announce_rows`（以 `content_hash` 對應）。

| V-1 判準 | 輸出段落 | 算法 |
| --- | --- | --- |
| 1. 每事件 ℓ | `-- Events by ascending l --`、`min(l)` | 事件 (symbol, E) 的 ℓ = ⌊(E 當日 00:00 Asia/Taipei − 首次列出該事件之 ok run 的 `recorded_at`) ÷ 1 日⌋。ℓ 可能 ≤ 0（E 當天才被列出）。 |
| 2. 持續性 | `-- Persistence anomalies --` | 自首次列出至 E 00:00（Taipei）之前的**每一個** ok run 都必須列出該事件；沒列的逐筆（事件、run）印出，並標明該代號是「完全沒出現」或「改以其他日期列出」。ok 但沒有任何列的 run 視為「什麼都沒列」，會浮現成異常，不會被略過。 |
| 3. 樣本 | `-- Sample --` | ok run 數、事件數、run 期間、缺 run 的平日、6～9 月旺季是否完整落在 run 期間內（起日 ≤ 6/1 且迄日 ≥ 9/30）。 |
| 4. 新值上限 | `-- What the data allows --` | 新值 ≤ min(ℓ) − 1。 |

### 判讀時要注意的三件事

1. **左設限（censored）**：第一次 ok run 就已列出的事件，真實首次列出時點早於樣本起點，算出的 ℓ 只是下界。輸出另列 `min(l), appearing events`（只算樣本期間「看到它出現」的事件）。只靠 censored 事件撐出來的 `min(l)` 證據很弱。
2. **量化誤差方向**：實際首次列出可能早於「第一次看到它的 run」，所以算出的 ℓ 永遠是真實前置天數的下界，會讓建議上限偏小，不會偏大。
3. **缺 run 的平日**：腳本沒有交易日曆，列出的缺漏平日可能是休市日；請自行對照。缺 run 本身不會被腳本補值或內插。

## 三、輸出不會做的事

- 不會說「請把 V-1 改成 N」。只印資料允許的上限與「仍須具備」的條件（持續性異常須逐筆說明、需有完整 6～9 月旺季、規章佐證等）。
- 依 ADR-0016 D-5.6，調高 `MIN_ANNOUNCE_LEAD_DAYS` 須具備 V-1 判準所列證據、修訂 ADR-0016 V-1 列、經 tech-architect 覆核，不得以 hotfix 處理；若當時 `SHOW_WHEN_COVERAGE_UNKNOWN` 為 `False`，另須 CEO 核可。
- 判準 5（官方規章佐證，有網路者取得名稱、條次、URL、取得日期、原文摘錄）不在腳本範圍；規章下界小於判準 4 的值時取較小者。
