- 日期：2026-10-26
- 對應：後續追蹤清單 N-152；風控裁定 `work/reviews/2026-10-26-信任缺陷結案確認-風控.md` 第 3 點 (c)
- 腳本：`apps/stock-desk/backend/scripts/unfinished_bar_probe.py`（分支 `feat/stock-desk-unfinished-bar-probe`）
- 性質：**唯讀**離線檢測。本雲端環境沒有真實的價格 DB，**必須在存有 `stock-desk.db` 的機器上跑**。不涉祕密、不需付費、不讀 `.env`。
- 網路：腳本本身不連網。但第一次在新 worktree 用 `uv run --frozen` 時，uv 會建立 `.venv` 並同步依賴，需要網路或 uv 快取（見第三節）。

## 一、這支腳本唯讀，不會改資料

- DB 以 SQLite `mode=ro` 開啟，並下 `PRAGMA query_only=ON`；檔案不存在就拒絕（exit 2），**不會新建**。
- 全程只送 `PRAGMA query_only=ON` 與一條 `SELECT`（讀 `price_bars_cache` 的 symbol、market、trade_date、source、fetched_at）；不讀價格欄位，不寫任何檔，輸出只到 stdout。
- 沒有 INSERT / UPDATE / DELETE / DDL。測試有逐項驗證：對該連線下寫入語句會失敗，跑完後 DB 檔的 SHA-256 與資料列不變。
- 唯一副作用來自 SQLite 本身：讀 WAL 模式資料庫時，**可能新增 `-wal`／`-shm` 輔助檔；資料庫檔本身位元組不變**。想更保守，可先把 `stock-desk.db`、`stock-desk.db-wal`、`stock-desk.db-shm` 三個檔一起複製到別處，對複本執行。
- 腳本只用標準函式庫，不 import `app.*`。
- 不做清理。就算有輸出列，腳本也不會動任何資料；清理屬於寫入動作，須另案經您明確同意。

## 二、判定規則

一列被列出，當且僅當：

```
fetched_at  <  該列 trade_date 在該市場收盤時刻（換算成 UTC）
```

| 市場 | 收盤時刻 | 時區 |
| --- | --- | --- |
| TW | 13:30 | Asia/Taipei（無日光節約） |
| US | 16:00 | America/New_York（換算 UTC 隨 DST 變動：夏令 20:00Z、冬令 21:00Z） |

- 收盤時刻逐列用 `zoneinfo` 依該列自己的 `trade_date` 換算，不寫死 UTC 偏移。
- `fetched_at` 剛好等於收盤時刻：**不列出**（與資料服務判斷一致，`freshness.py` 以 `local.time() >= session_close` 視為已收盤）。
- 腳本沒有交易日曆，只依日期判定。
- `fetched_at` 在 upsert 時會被更新（`cache.py:228`），所以列出的是「最後一次寫入發生在收盤前」的列。

## 三、停哪些程序、跑哪條指令（Windows PowerShell）

### 1. 停程序（建議，非必要）

腳本只讀，後端不停也能跑。但為了讓輸出是**單一時間點的靜止快照**（避免跑的當下剛好有 upsert 改了 `fetched_at`），建議先停後端 API 與排程。停法依您的啟動方式而定：

- **用 `dev-up.bat` 啟動（Windows）**：它會另開獨立視窗，在 dev-up 視窗按 Ctrl+C **不會**收掉它們。請到下面兩個視窗**各自**按 Ctrl+C，確認視窗內程序已結束：
  - 標題 `stock-desk backend`（`uvicorn app.main:app`）
  - 標題 `stock-desk scheduler`（`python -m app.scheduler`）
- **用主機部署手冊的方式啟動**（API 與 scheduler 各一個 PowerShell 視窗）：同樣到那兩個視窗各自按 Ctrl+C。
- **用 `dev-up.sh` 啟動（Git Bash / Linux / macOS）**：在原視窗按 Ctrl+C 一次，它會一併收掉 backend、scheduler、frontend。
- **用 docker compose**：在 `apps\stock-desk` 目錄執行 `docker compose stop`。

前端不碰 DB，不用停。**跑完再照平常方式啟動。**

### 2. 取得腳本（獨立 worktree，不動您目前的分支）


### 3. 執行

```powershell
# DB 路徑請依您的實際位置（主機部署手冊的範例為 C:\stock-desk\data\stock-desk.db）
$env:STOCK_DESK_DB_PATH = "C:\stock-desk\data\stock-desk.db"

Set-Location ..\AICompany-n152\apps\stock-desk\backend
uv run --frozen python scripts\unfinished_bar_probe.py
```

- 也可以不設環境變數，改用參數：`uv run --frozen python scripts\unfinished_bar_probe.py --db-path "C:\stock-desk\data\stock-desk.db"`。
- `--db-path` 與環境變數都省略時，預設是 `.\data\stock-desk.db`（相對於目前目錄）。在新 worktree 裡這個預設路徑不存在，會 exit 2，所以**務必設環境變數或給 `--db-path`**。
- **必須用 `uv run --frozen`**：
  - `--frozen` 讓 uv 不重新解析、不改動 worktree 內的 `uv.lock`。
  - 新 worktree 第一次執行會建立 `.venv` 並依 `uv.lock` 同步依賴，**需要網路或 uv 快取**。之後再跑不用。
- **不要用系統 Python 或 `--no-project` 執行**：Windows 沒有系統時區資料庫，`zoneinfo` 靠 `tzdata` 套件；它只在專案環境裡才有。缺少時腳本會印出說明並 exit 2，不會讀 DB。
- docker compose 部署的 DB 在具名 volume 內（容器內路徑 `/app/data/stock-desk.db`），請先把該檔連同 `-wal`、`-shm` 複製出來，再對複本執行。
- DB 若放在映射網路磁碟機，Windows 解析路徑時可能變成 UNC 路徑，SQLite 會拒絕開啟並 exit 2、訊息會寫明；遇到請改用本機磁碟上的複本。
- 退出碼：0 成功（含「0 筆」）；2 表示讀不到 DB、沒有 `price_bars_cache` 表，或缺少時區資料庫。

## 四、輸出各段的意思

| 段落 | 內容 |
| --- | --- |
| 檔頭 | 腳本名、實際讀取的 DB 路徑、執行時間（UTC） |
| Rule | 判定規則與兩個市場的收盤時刻、時區 |
| Counts | 掃描總列數；每個市場的總列數、`fetched_before_close`（符合規則的筆數）、其中 `is_latest_bar` 與 `not_latest_bar` 各幾筆；若有 TW、US 以外的市場值，另印其列數；無法判定的列數與原因分項 |
| Rows with fetched_at before close | 逐列：market、symbol、trade_date、`fetched_at`（DB 內原值）、該日收盤時刻（UTC）、`is_latest_bar`（yes／no）、該 symbol 在表內最新的 trade_date、source |
| Rows that could not be judged | 規則套不上的列，原值照列：`unknown_market`、`unparseable_trade_date`、`unparseable_fetched_at`、`timezone_naive_fetched_at`。這些列不會被略過，也不會被猜測 |

`is_latest_bar = yes` 的意思：該列的 `trade_date` 等於同一 `(symbol, market)` 在表內最新的 `trade_date`。

輸出只有事實：計數、列、規則。腳本不印結論，也不印任何建議。

## 六、這份輸出不能做什麼

- 它只能說「這一列最後一次寫入發生在該日收盤前」，**不能說明為什麼**。該列的 close 值是否與最終收盤價不同，輸出看不出來，腳本不讀價格欄位。
- 沒有交易日曆：落在週末或休市日的列，只依日期判定。
- `fetched_at` 被後續 upsert 更新過的列，會顯示最後一次寫入時間，早先的盤中寫入看不到。
- 如何處理（若有輸出列）由風控與 tech-architect 依輸出判讀；清理須 CEO 明確同意。
