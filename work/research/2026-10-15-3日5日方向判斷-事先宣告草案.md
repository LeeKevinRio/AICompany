## 0. 先講結論（包括不好看的部分）

1. **標籤以波動單位定義。** 令 z ＝ 未來 h 日的還原對數報酬 ÷（T 日前 60 日的日報酬標準差 × √h）。z ≥ +0.43 為偏多，z ≤ −0.43 為偏空，其餘為震盪。採絕對報酬，不扣基準。3 日與 5 日各用一組獨立常數。0.43 ＝ Φ⁻¹(2/3)，是事前選定的值，不是用真實資料調出來的。
2. **基準有五個。** 延續法、多數類別法兩個是共同必備；個股與族群另加大盤延續，個股再加族群延續；大盤展望照抄只當診斷用。所有基準在發布當下就和預測一起寫進紀錄帳，事後不能改定義。
3. **「優於基準」的門檻很嚴。** 以不重疊樣本計，Wilson 下緣必須高於每一個必備基準的命中率，配對檢定也要通過。顯著水準依宣告數 × 檢查點數做 Bonferroni 校正，只能在事先宣告的檢查點上判定。
4. **最不好看的事實：只靠前瞻紀錄，大盤展望要很多年才可能拿到「優於基準」。** 單一指數的 5 日不重疊樣本一年約 49 個。假設真實命中率比基準高 10 個百分點，在 α≈0.05/30 下要約 330～350 個樣本，5 日約 7 年，3 日約 4 年【合成／算術】。真實優勢若只有 3～5 個百分點，前瞻驗證在可預見的時間內不可能通過。這是預期中的結果，不是設計失誤。CEO 需要知道，展望在很長一段時間內都會掛「未驗證」或「驗證中」。
5. **Q-8 的答案：不是還原價。**【事實】現行所有技術指標、建議引擎、警示、前端關鍵價位都吃**未還原**的日線。只有回測與事件研究會還原（§1.5）。要做 3／5 日展望，指標輸入必須改走還原價，估值與風險上限則照舊用原始收盤。
6. **Q-3 的答案：ATR 倍數「可以算」可核對依據，但要附帶條件。**
   - 條件：ATR 定義統一、倍數事先登記並版本化，而且揭露歷史觸及率。
   - 它和固定百分比的差別在於隨波動縮放、輸入可重算，**不在於它比較客觀**。倍數本身仍是人選的參數，這點要照實寫出來。
   - 另外發現兩個問題：前後端的 ATR 是兩種算法；現行停損以平均成本為錨，牴觸 PV-17（§7）。

## 1. 對象與發布時點

### 1.1 大盤

- **對象**：臺灣加權股價指數（TAIEX，價格指數）。
- **來源**：【事實】現行來源是 yfinance `^TWII`（`apps/stock-desk/backend/app/services/index.py:303`；ADR-0005 決策一第 4 點）。它是非官方來源，可得性與欄位查證仍待辦（ADR-0005 約束 P-2）。
- **與 PV-7「價格基準：還原價」的偏離（待風控裁定，見 §9 R-1）**：價格指數在除息時會因成分股除息而下跌（股利拖累），所以它不是「還原價」。
  - 【推論】使用者說「大盤偏多」，指的是報價上看到的指數水準，而這種下跌確實發生在指數上。因此我建議 v1 標籤以**價格指數**結算，並揭露「除息旺季（約 6～9 月）偏空標籤會因股利拖累而系統性偏多」。
  - 若 data-engineer 能查證「發行量加權股價報酬指數」的可用來源（【推論】TWSE 有編製此指數，但來源、欄位、授權我都沒查證），每筆結算就**另外記一個診斷用的報酬指數標籤**，不取代主標籤。
- **v1 輸入只用指數自身的日線。**
  - 市場寬度（漲跌家數、站上均線比例）沒有 D0 之前的 PIT 名單，歷史重放會有存活者偏誤。因此寬度只能在 D0 之後前瞻加入，屬 v2 範圍。
  - 【事實】ADR-0012 D-2 的 PIT 快照從 D0 起累積（ADR-0012 L33、L86）。

### 1.2 族群

- **對象**：ADR-0012 定義的上市族群（TWSE 官方產業別代碼），母體與覆蓋率規則沿用 `SectorMomentumDefinition` v1。

- **價格序列**：族群等權籃子。T 日收盤時以等權建倉、持有到 T+h 收盤（買入持有，不每日再平衡；理由同族群方法論 §2.2）。成分股價格用乘法還原（`app/dividends/adjust.py`）。

### 1.4 發布時點與涵蓋期

| 項目 | 定義 |
|---|---|
| 決策日 T | 最近一個已取得完整日線、且通過品質檢查的交易日 |
| 輸入截止 | 只用 `recorded_at ≤ cutoff(T)` 的資料。cutoff(T) ＝ T 日 23:59:59（Asia/Taipei），沿用 ADR-0012 的 `cutoff` |
| 發布 | T 日收盤後由排程產生，寫入紀錄帳的時間記為 `created_at` |
| 逾時 | 排程預測的 `created_at` 晚於 **T+1 日 08:30（Asia/Taipei）** 時標 `late`，**不計入主統計**（防止盤前資訊進入）。臨時查詢不受此限，但本來就不計入主統計 |
| 涵蓋期 | T+1～T+h，h ∈ {3, 5}，以**交易日數**計，不以日曆日計 |
| 結算日 | 大盤指數日線上**實際觀察到的**第 h 個交易日 |

- **結算日一律用觀察到的交易日。**
  - 【事實】`TradingCalendar.is_trading_day` 對已知範圍之外的日期改用週一至週五規則（`app/data/calendar.py:74-85`），所以發布時顯示的「涵蓋至 X 日」只是預估值，颱風假或臨時休市會讓它不準。
  - 結算不得使用這個退回規則，只能用 `observed_days_after` 那一類只認觀察日的邏輯（`calendar.py:139-154`）。
  - 個股在結算日停牌、但大盤有開市時，該筆記為 `void_missing_bar`（§6.3）。

### 1.5 價格基準與 Q-8：現行技術指標輸入是否為還原價？

**結論：不是。現行技術指標的輸入全部是未還原的原始日線。**【事實，讀碼】

**影響（【推論】）**：除權息日原始收盤的下跌，會讓均線交叉、MACD、RSI 出現假訊號；當天的真實波幅（true range）也會包含這段除息缺口，使 ATR 被墊高。對 3／5 日展望而言，T 日附近若有除權息，特徵與標籤都會被扭曲。

**本文件的規定**：

1. **標籤（結算端）**：一律用還原價。
   - 【事實】乘法還原對「T 日到 T+h 日」這類比值不受後續事件影響。對每根可見的 bar，未來事件只乘上同一個常數 K(t)（`app/dividends/adjust.py:48-75`），所以結算時用完整序列算出的比值，等同於 PIT 序列算出的比值。
2. **特徵（決策端）**：展望規則的價格類輸入（均線、報酬、σ、ATR、擺動點、缺口）一律用還原價。
   - 用法限制：只能用比值、報酬，或以 ATR／σ 為單位的距離。**不得以還原價的絕對水準設門檻**（`adjust.py:68-72` 已明文）。
3. **估值與風險上限**：照舊用原始收盤，本文件不改這條邊界。
4. **成交量**：維持原始值（`adjust.py:109-112`）。若規則用到量能，它不受配股影響這件事要另外揭露。
5. **已知的還原缺口**：
   - 【事實】股票股利（配股）事件拒算因子（`app/dividends/models.py:50-63`）。
   - 【事實】除權息來源是預告表 `TWT48U_ALL`，只列未來事件，已過的事件不會留在表上（`app/dividends/coverage.py:10-13`）。所以同步開始之前的歷史無法還原。
   - 【事實】分割、減資、面額變更沒有事件來源，只有「單日漲跌超過漲跌幅限制加容差」這道保險（`app/sectors/definition.py:68-71`）。
   - 這三種情形依 §5 輸出「證據不足」，或依 §6.3 作廢該筆結算。

## 2. 標籤定義

### 2.1 公式（3 日與 5 日分開；常數各自獨立）

令 P\* 為對象的還原收盤價（大盤用價格指數，見 §1.1），h ∈ {3, 5}：

```
r_h(T)    = ln( P*(T+h) / P*(T) )                        # absolute log return, no benchmark subtracted
sigma_d(T) = sample std (ddof=1) of daily log returns over the 60 sessions ending at T (inclusive)
z_h(T)    = r_h(T) / ( sigma_d(T) * sqrt(h) )

label_h(T) = 偏多  if z_h(T) >= +K_h
             偏空  if z_h(T) <= -K_h
             震盪  otherwise
```

| 常數 | 值 | 理由 |
|---|---|---|
| `H3` / `H5` | 3 / 5 個交易日 | 外部 prompt L89、PV-7 |
| `SIGMA_WINDOW` | 60 個日報酬 | 約一季。比 20 日穩、比 120 日貼近當下；事前選定 |
| `SIGMA_MIN_VALID` | 60 個日報酬中至少 55 個有效 | 容許少量停牌；不足就證據不足 |
| `SIGMA_FLOOR` | σ_d < 0.1% 視為退化 | 長期停牌或平盤填值會讓 z 爆大；碰到就輸出證據不足（`E-VOL-DEGENERATE`） |
| `K3` | 0.43 | Φ⁻¹(2/3)：常態且 σ 已知時三類各佔 1/3 |
| `K5` | 0.43 | 同上；**常數分開存放**，改一個不影響另一個（NP-V1 驗收） |
| 邊界 | `>=` 與 `<=` 歸入偏多／偏空；比較時容差 1e-12 | 事前固定，避免浮點誤差翻轉標籤 |

**為什麼用報酬標準差，而不是 ATR？**

- ATR 量的是含跳空的日內波幅，不是收盤到收盤的離散程度。兩者的比例在不同個股之間不一樣，跟漲跌停、檔位也有關係。
- 【事實】現行還有兩套 ATR 算法（§7.2）。
- 標籤衡量的是收盤報酬，所以用同一種量去縮放最一致。ATR 保留給價位類依據使用（§7）。

**合成資料檢查**【合成；GARCH(1,1)＋t(5) 雜訊，約 400 個合成年，腳本見附錄 A】：

| h | K | 偏多／震盪／偏空 佔比 | 延續法命中（虛無下） | 多數類別法命中（虛無下） |
|---|---|---|---|---|
| 3 | 0.43 | 0.344／0.366／0.289 | 0.347 | 0.350 |
| 3 | 0.50 | 0.317／0.419／0.264 | 0.360 | 0.407 |
| 3 | 0.75 | 0.229／0.582／0.189 | 0.447 | 0.582 |
| 5 | 0.43 | 0.354／0.361／0.285 | 0.348 | 0.346 |
| 5 | 0.50 | 0.326／0.412／0.262 | 0.358 | 0.391 |

- 【推論】K 越大，「震盪」越多，多數類別法（幾乎全報震盪）的命中率也跟著升高。這正是 PV-12 要防的情形。
- K=0.43 在厚尾、波動群聚的合成資料下大致三分，基準最難靠單報一類取勝。
- **這張表只用來檢查定義是否合理，K 值沒有拿真實資料調過。** 真實台股的類別佔比可能不同（漂移、厚尾程度、σ 估計誤差都會影響）。上線後的實際佔比照實揭露，**不得據此回頭調 K**；要改 K 就是新定義版本（§2.4）。

**門檻換算成百分比的示意**【推論，以假設的波動代入，非實測】：

- 指數 σ_d≈1.1%：3 日門檻約 ±0.82%，5 日約 ±1.06%。
- 個股 σ_d≈2%：3 日約 ±1.49%，5 日約 ±1.92%。
- 個股門檻都高於來回成本 0.585%（【事實】`app/backtest/costs.py:47-48`，費率 `verified_on=None`，L55，未查證）。所以偏多不會是「漲幅還不夠付成本」的雜訊。

### 2.2 絕對報酬或相對基準

- **主標籤**：三種對象都採**絕對**（總）報酬，不扣大盤或族群。理由是外部 prompt 問的是「會偏多、偏空嗎」（L11），不是「會不會贏大盤」。
- **個股與族群的相對面**：不改標籤，改由基準處理。§3 的 B3／B4 檢驗「個股規則是否只是在跟大盤」。
- **診斷標籤**：另外對個股計算一個相對標籤（超額報酬 ÷ 追蹤誤差波動），**只進研究報告，不上畫面**。

### 2.3 「震盪」的意義（PV-12）

- 「震盪」在這裡的意思是：**期末淨變動落在 ±K_h 個波動單位內**。它不描述期間內的路徑。期間內大漲後大跌、最後收平，也算震盪。
- 以路徑定義（例如期間最大振幅）的版本會多出參數，v1 不採用。
- 這層意思要寫進字面（交 creative-lead；見 §9 R-2），否則使用者會把「震盪」讀成「上下劇烈波動」。

### 2.4 版本化

- **定義版本** `dirdef-vMAJOR.MINOR`：涵蓋 §1、§2、§3、§4、§5、§6.3 的全部常數與規則。
  - 改任何會影響標籤、基準或判定的常數，都升 MAJOR。
  - 只改文字、不改數值，升 MINOR。
- **規則版本** `rules_version`（例如 `outlook-index-v1.0-h3`）：展望規則本身。改規則就升版。
- **舊預測不得回寫**：每筆預測存的是當時的 `definition_version` 與當時的閾值快照（K、σ_d、門檻的百分比值）；結算一律依**該筆自己的定義版本**進行。
  - 已發布的定義版本以常數物件凍結，並列入「已發布清單」，比照 `SectorMomentumDefinition` 的 `PUBLISHED_DEFINITIONS` 作法（`app/sectors/definition.py:24-30`、`:230`）。
- **新版本的驗證計數從 0 開始**。舊版本的紀錄保留，在畫面上分開列。
- **每登記一個新版本，多重比較的 m 就加 1**（§4.4），比照族群方法論 §3.2 的 m 累計規則。用意是防止「換版本直到某一版看起來好」。

## 3. 基準（PV-11）

所有基準只用 T 日（含）以前已實現的資料。基準的預測值**在發布當下就和主預測一起寫入紀錄帳**（§6.1 的 `baseline_predictions`），事後不得重算或改定義。

| 代號 | 名稱 | 適用 | 計算方式 | 是否必備 |
|---|---|---|---|---|
| B1 | 延續法 | 全部 | 以「(T−h, T] 這段已實現視窗」的標籤作為預測。計算時用 σ_d(T−h)、同一個 K_h：`z = ln(P*(T)/P*(T−h)) / (sigma_d(T−h)·√h)` | 必備 |
| B2 | 多數類別法 | 全部 | 在**已實現**的標籤（決策日 T′ 須滿足 T′+h ≤ T）中取最近 250 筆的眾數。同票時依 震盪 > 偏多 > 偏空。已實現標籤不足 120 筆時，此基準記為「不可用」 | 必備 |
| B3 | 大盤延續 | 族群、個股 | 預測值 ＝ 同一 T、同一 h 的大盤 B1 標籤 | 必備 |
| B4 | 族群延續 | 個股 | 預測值 ＝ 該股所屬族群籃子的 B1 標籤（用籃子自己的 σ）。族群覆蓋不足時記為「不可用」 | 必備（只在可用子集上比較） |
| B5 | 大盤展望照抄 | 族群、個股 | 預測值 ＝ 本系統同日、同 h 的大盤**已發布**預測；大盤為證據不足時記為「不可用」 | 診斷用，非必備 |
| B0 | 均勻隨機 | 全部 | 理論命中率 1/3 | 只作參考線 |

- 【合成】在虛無假設下，K=0.43 時 B1 命中約 0.35，B2 約 0.35（§2.1 表）。真實資料的基準命中率以實測為準，並且一定和主預測並列（PV-11）。
- 【推論】B3／B4 是個股展望最重要的基準。個股規則若贏不過「照抄大盤或族群最近 h 日的走勢」，就代表它沒有提供個股層級的資訊。
- B5 用來量「個股規則比照抄本系統大盤判斷多了什麼」。它不列為必備，因為大盤規則本身未經驗證時，B5 只是一個很弱的基準。

## 4. 驗證標準（PV-10、PV-12、PV-13、PV-45、PV-46）

### 4.1 統計單位與不重疊計數（PV-13）

- **主樣本（不重疊）**：
  - 從版本啟用日 D_v 起，以觀察到的交易日計，取第 0 相位的決策日：D_v、D_v+h、D_v+2h、……。這些日子的 h 日視窗互不重疊。
  - 其餘 h−1 個相位**全部計算、全部列出，不挑選**（比照族群方法論 §5.1 與 `sector_eval.py:28-31`）。
- **單一對象（大盤）**：n ＝ 主樣本中有標籤的決策日數。
- **多對象合併（族群、個股）**：
  - 同一天的多檔預測受同一個市場因子影響，彼此不獨立。統計單位改為**決策日**：每個決策日算一個「當日命中比例」，n ＝ 不重疊的決策日數。
  - 「股日數 k/N」照列，但明文標示它會高估證據量。
- **全樣本（每日、重疊）**：作次要揭露。附有效樣本數 N_eff ＝ N ×（二項變異數 ÷ circular block bootstrap 變異數），區塊長度取 h，抽 10,000 次並記錄 seed（同族群方法論 §6.1）。

### 4.2 指標（3 日與 5 日分開；每項都附 n）

| 指標 | 定義 |
|---|---|
| 命中率 | 預測標籤 ＝ 實現標籤的比例。以「過去 n 次中 k 次」呈現，附 Wilson 95% 區間（`app/backtest/episodes.py:417-437`） |
| 各類別精確率 | 預測偏多時，實際也是偏多的比例；偏空、震盪同理 |
| 各類別召回率 | 實際偏多時，預測也是偏多的比例；其餘同理 |
| 預測頻率與實現頻率 | 三類各自佔多少，兩組並列 |
| 混淆矩陣 | 3×3 主矩陣，另加一列「證據不足」的筆數 |
| 反向錯誤率 | （預測偏多、實際偏空）＋（預測偏空、實際偏多），除以 n。單獨列出，因為這是最傷的錯誤 |
| 平均召回率（macro recall） | 三類召回率的平均。永遠報震盪的話，這個值只有 1/3 |
| 涵蓋率 | 有標籤的筆數 ÷（有標籤＋證據不足）。防止「挑好判斷的日子才出手」 |
| 作廢數 | `void_*` 的筆數與原因（§6.3） |
| 基準並列 | 每個基準的命中率、Wilson 區間、平均召回率，**一律在同一組樣本上計算** |
| 開盤基準診斷 | 用 T+1 開盤到 T+h 收盤重算一次。若優勢只出現在收盤基準，代表優勢來自隔夜跳空，使用者拿不到。只進研究報告 |

### 4.3 「優於基準」的判定（PV-46）

對某一宣告 c（例如「大盤 5 日」）在檢查點 j，**以下五項全部成立**，才可以稱「優於基準」：

- **(a) 樣本數**：不重疊樣本 n ≥ 檢查點 n_j（§4.5）。
- **(b) 區間下緣**：對每一個必備基準 B，模型命中率的單尾 Wilson 下緣（水準 α\*）都高於 B 在同一組樣本上的命中率。
  - 這是 PV-46 字面例示的條件。
- **(c) 配對檢定**：對每一個必備基準 B 都要通過。
  - 單一對象：做精確單尾 McNemar 檢定（只看兩者不一致的樣本，用二項檢定），p < α\*。
  - 多對象合併：對「每日模型命中比例 − 每日基準命中比例」做 circular block bootstrap（區塊 4，另列 2 與 8；10,000 次；記錄 seed），差值的單尾下緣要大於 0。
  - 【推論】(b) 把基準當成沒有誤差的固定值，偏樂觀；(c) 把基準本身的抽樣誤差也算進去。兩者都要求。
- **(d) 防灌水（PV-12）**：模型的平均召回率，高於 1/3，也高於每個必備基準的平均召回率（比點估計）。
- **(e) 涵蓋率**：排程日的涵蓋率 ≥ 80%。證據不足太多時，不得宣稱優於基準。

**必備基準有多個時採交集聯集檢定（intersection-union）**：必須同時贏過全部必備基準。這種檢定本身就保守，基準數不再另外校正。

### 4.4 多重比較與多次檢查

- α\* ＝ 0.05 ÷（m × K），單尾。
  - m ＝ 已登記的宣告數。v1 是 {大盤、族群、個股} × {3 日、5 日} ＝ 6；之後每登記一個新規則版本就加 1。
  - K ＝ 每個宣告的檢查點數：大盤與個股 6 個，族群 3 個（§4.5）。
  - v1 大盤與個股的 α\* ＝ 0.05 ÷ 36 ≈ 0.0014。
- **為什麼要除以 K**：前瞻紀錄每天都在增加，每天檢查一次「有沒有優於基準」，等於反覆偷看。只要看得夠多次，遲早會碰巧過關。所以「優於基準」**只能在事先宣告的檢查點上判定**，兩個檢查點之間不得因統計值變好而升級。
- 這比 PV-46 字面例示的條件嚴格。理由見上，是否接受交 CEO 與風控（§9 R-4、C-3）。
- 其他三態（未驗證、驗證中、未優於基準）不構成正面主張，可以每天更新。

### 4.5 檢查點、狀態對照與檢討點（PV-10、PV-11、PV-45）

**檢查點**（以不重疊樣本 n 計）：

| 對象 | 檢查點 n_j |
|---|---|
| 大盤、個股（合併） | 30、60、100、150、250、500 |
| 族群（合併；PV-39 的 150 閘門） | 150、250、500 |

**驗證狀態四選一**（PV-10），3 日與 5 日各自判定：

| 狀態 | 條件 |
|---|---|
| 未驗證 | n < 30（族群：n < 150） |
| 未優於基準 | n 已達門檻，且模型命中率的點估計 ≤ 任一必備基準 |
| 驗證中 | n 已達門檻，點估計高於全部必備基準，但最近一個檢查點沒有通過 §4.3 |
| 優於基準（附區間） | 最近一個檢查點通過 §4.3 |

**檢討點**（事先宣告；回應 PV-11 的建議項）：

1. **n＝60**（族群：n＝150）：若為「未優於基準」，展望撤出首層（若原本在首層），並由 quant 寫檢討紀錄。檢討只能分析，不得原地改規則；要改規則就開新版本，計數從 0 開始，m 加 1。
2. **n＝150**（族群：n＝250）：若不是「優於基準」，這個規則版本**退出顯示**。紀錄帳照記，詳細頁可以查。
3. **隨時預警**（不改狀態，只觸發檢討）：n ≥ 30 且反向錯誤率超過 B1 反向錯誤率的 1.5 倍。

### 4.7 歷史重放（只限大盤；與前瞻紀錄分開）

- **範圍**：只做大盤。指數沒有存活者偏差，v1 輸入又只用指數自身日線（§1.1）。族群與個股的歷史重放有存活者偏差，除權息紀錄也只從同步開始那天起才有，只能當內部研究，標「含已知偏誤」，不上畫面（比照族群方法論 §5.4）。
- **程序**：
  - 規則與定義先 commit 凍結，再跑重放，並記錄凍結 commit 的 hash。
  - 以 `walk_forward_splits` 的 126 個交易日為一段，逐段報告（`app/backtest/splits.py:49-97`），全部列出。
  - 規則沒有擬合任何參數，所以「樣本內」為無，整段視為樣本外。這和族群方法論 §5.3 是同一種已知偏離，需要 CEO 核可。
- **每個候選規則只能重放一次。**
  - 看過結果後修改的規則，算新版本，m 加 1。
  - 新版本的重放結果要標「已看過前一版結果後修訂」，不得再稱為樣本外。
- **呈現**：放在「歷史方向回顧（樣本外重放，非前瞻紀錄）」，和前瞻紀錄分區顯示（PV-10）。
- **資料來源**：`^TWII` 的歷史長度與品質沒有查證（ADR-0005 P-2）。

### 4.8 與策略績效的區分（NP-V6、外部 prompt L96）

- 方向命中率不是交易，不扣成本，也不用 backtest-protocol 的策略欄位。
- 若有人把展望轉成交易策略（例如「偏多時持有 0050」），那是另一份策略回測。它要走 backtest-protocol 的完整欄位、成本模型與買入持有對照，不在本文件範圍內。
- 經校準的機率不在 v1 範圍。依 PV-14，要另出 ADR 並通過前瞻校準之後，才能掛「X% 機率」。

## 5. 證據不足判定（PV-4）

### 5.1 原則

1. 證據不足是第四種輸出，和偏多、震盪、偏空並列。它**只**由「輸入缺漏或品質不合格」觸發。
   - 規則本身算出中性結果時，輸出是「震盪」，不是證據不足。
   - 驗證樣本不足是**驗證狀態**（未驗證）的事，不是單筆預測的證據不足。兩者不得混用（§9 R-5）。
2. 輸出證據不足時，`missing` 清單**必須非空**；輸出其他標籤時，`missing` 必須為空。用測試釘住（PV-4）。
3. 不得退回用替代估法補資料（PV-6、PV-25）。例如缺 60 日 σ 時，不得改用 20 日 σ。
4. 證據不足的預測也寫入紀錄帳，並計入涵蓋率（§4.2）。

### 5.2 缺項代碼（`dirdef-v1.0`；新增代碼視同改定義，要升版）

| `E-SCOPE-OTC` | 上櫃標的 | — |
| `E-SCOPE-TYPE` | 非普通股（ETF、槓桿或反向 ETF、存託憑證等） | 證券類別 |
| `E-INDEX-MISSING` | 個股或族群規則需要大盤輸入，但大盤 T 日資料缺 | — |
| `E-SECTOR-COVERAGE` | 族群成分 < 5 檔，或覆蓋率 < 90%（沿用 `CoverageRules`） | 需／現有 |
| `E-PIT-UNVERIFIED` | 輸入資料的 `recorded_at` 晚於 cutoff(T)，或無法證明它早於 cutoff(T) | 最晚的 `recorded_at` |

### 5.3 缺項清單格式

`missing` 欄位是陣列，每一項的格式如下：

```json
{"code": "E-BARS-SHORT", "item": "還原日線", "required": 121, "available": 87,
 "source": "twse_snapshot", "as_of": "2026-10-15", "detail": "上市日 2026-06-02"}
```

- 呈現時依 `code` 轉成固定句型，例如「缺：還原日線（需要 121 根，目前 87 根）」。逐字由 creative-lead 起草、送風控審。
- 前端不得自行組句，只能依代碼對照表輸出。

### 6.1 `direction_forecasts`（只增不改）

| 欄位 | 說明 |
|---|---|
| `forecast_id` | 唯一識別（ULID 之類可排序的 ID） |
| `created_at` | 寫入時間（UTC） |
| `run_id` | 排程執行批次 |
| `trigger` | `scheduled` 或 `on_demand`（歷史重放**不寫進這張表**，見 §6.5） |

| `evidence_snapshot` | 每項輸入的名稱、數值、公式、資料截至日、來源（PV-8 的命中證據項），完整存下來 |
| `counter_arguments` | 至少一條反方論點，附數值（PV-8） |
| `invalidation_conditions` | 至少一條期間內可觀察的失效事件，用結構化描述，例如 `{type: "close_below", level: ..., basis: ...}`，供結算時自動判定是否被觸發 |

| `late` | 排程預測的 `created_at` 晚於 T+1 日 08:30（台北）時為 true |

**為什麼要存完整的證據快照？**【事實】現行日線快取以 `(symbol, market, trade_date)` 為主鍵，遇到衝突就覆寫（`app/data/cache.py:52`、`cache.py:219`），不保留當時的版本。所以事後**無法**從快取重建「當時看到的數字」。證據一定要在發布當下存下來。

### 6.2 只增不改

- 不得 UPDATE，也不得 DELETE。用 SQLite trigger 擋下，比照 ADR-0012 對 `sector_rank_stats` 的作法（ADR-0012 L351-354：`RAISE(ABORT, 'append-only')`）。
- 測試要直接對資料表下 UPDATE 與 DELETE，斷言被拒絕（PV-43）。

### 6.3 自動結算：`direction_settlements`（只增不改）

**觸發**：每個交易日的資料擷取完成後，排程掃描所有尚未結算的預測。條件是大盤日線上已觀察到第 h 個交易日 T+h，而且該日資料的 `recorded_at ≤ cutoff(T+h)`。

**每筆結算的欄位**：

| 欄位 | 說明 |
|---|---|
| `settlement_id`, `forecast_id`, `settled_at` | — |
| `settlement_date` | 觀察到的 T+h |
| `start_price` / `end_price` | 原始價與還原價；結算窗 (T, T+h] 內套用的除權息事件與因子 |
| `realized_log_return`, `realized_z`, `realized_label` | 依**該筆預測**的 `definition_version` 與 `threshold_snapshot` 計算（σ 用預測當時存下的 σ_d(T)，不重算） |
| `hit` | `realized_label == label`；證據不足的預測記為 null |
| `baseline_hits` | B1～B5 各自是否命中 |
| `diag_open_based` | T+1 開盤到 T+h 收盤的診斷標籤 |
| `invalidation_triggered` | 失效條件在期間內是否被觸發，以及首次觸發日 |
| `index_return_diag` | 只限大盤：若報酬指數來源可用，另記一個報酬指數標籤 |
| `status` | `settled`、`void_missing_bar`、`void_corporate_action`、`void_adjustment_unusable` |
| `supersedes_id` | 更正用 |

**作廢規則**：

- **對象在 T+h 停牌、無 bar**：等 5 個觀察交易日。期間內補到當日資料就結算；補不到就記 `void_missing_bar`。
- **結算窗內有除權息但因子不可用**：記 `void_adjustment_unusable`。
- **結算窗內有單日超過漲跌幅限制加容差的變動**：記 `void_corporate_action`。
- 作廢的筆數依宣告分別揭露。**作廢超過 5% 時**，報告第一行就要寫出來，因為作廢可能不是隨機的（【推論】例如配股多半發生在特定產業與季節）。

**缺日**：

- 排程某個交易日沒有執行，就寫一筆 `forecast_gaps(date, reason, detected_at)`。
- **不補造**（NP-V5 驗收第 4 條）。缺日不算進 n，但要揭露。

### 6.4 更正方式

- **預測端**：
  - 只能新增一列，填 `supersedes_id` 與 `correction_reason`，舊列不動。
  - **驗證統計一律用原始那一筆**，也就是當時使用者看到的內容。更正列只能列為「更正 n 筆」。
  - 【推論】若讓更正列取代原始列計分，等於事後修改預測。
- **結算端**：
  - 結果是事實，應該用最正確的資料。來源事後更正 bar 時，新增一筆結算並填 `supersedes_id`，統計改用最新的那一筆。
  - 每筆結算更正都要留下原因與前後數值，在報告中列出筆數。

### 6.5 與歷史重放、行動建議的關係

- **歷史重放**寫進另一張表 `direction_replays`，結構相同，另加 `freeze_commit` 欄位。它**永遠不與前瞻紀錄合併計算**（PV-10）。
- **行動建議**（PV-44）用平行的 `action_recommendations` 表，同樣只增不改。每筆記錄：
  - 行動、觸發與失效條件、有效期；
  - 每個價位的類型、數值、依據、公式、輸入值；
  - 規則版本。
- 行動建議的結算另記：
  - 停損或失效價是否被觸及（以日線最低價判定，並註明盤中路徑未知）、首次觸及日；
  - 3／5／10／20 日後的報酬；
  - 期間最大不利與最大有利幅度。
- 細節另案定義，不在本文件凍結範圍內。

## 7. 可核對依據的判準（Q-3）與固定百分比的替代算法（PV-24）

### 7.1 判準：什麼叫「可核對」

一個價位依據，要同時滿足以下六項，才算可核對：

| # | 判準 | 不符合的例子 |
|---|---|---|
| V1 | **公式公開而且具確定性**：同樣的輸入，第三方算得出一模一樣的數字 | 前端與後端各算一套，結果不一致 |
| V2 | **輸入是可觀察的市場資料**，附日期與截至日，並在 PIT 下取得 | 引用未標日期的「近期低點」 |
| V3 | **參數有出處**，只能是下列三種之一：①市場結構事實（擺動點的日期、均線的定義）；②使用者自己設定，標「你設定的 X%」；③事先登記的系統參數，附版本與選定理由，而且不是事後最佳化出來的 | 不附理由的「−8%」 |
| V4 | **會隨波動縮放**：同一個參數，對高波動股與低波動股代表的風險量級相近 | 固定百分比：−8% 對高波動股約 1 個 ATR，對低波動股可能是 5～6 個 ATR |
| V5 | **缺輸入就缺席**，不退回其他估法（PV-25） | ATR 不可得時改用 ×0.92 |
| V6 | **揭露歷史行為**：系統參數型依據要附歷史上「價格在 N 日內觸及該水位」的比例，寫成「過去 n 次中 k 次」並附 Wilson 區間 | 只給水位，不給它通常多常被碰到 |

### 7.2 Q-3 的回答：ATR 倍數算不算？

**算，但必須附條件。** 單有「×2 ATR」不夠，要同時滿足 V1～V6。具體揭露項目：

1. **ATR 定義統一。**
   - 【事實】後端 `technical.atr` 用 Wilder 平滑，需要 15 根 bar（`app/signals/technical.py:295-327`）。
   - 【事實】前端 `keyLevels.ts` 用最近 14 個真實波幅的**簡單平均**（`frontend/app/lib/keyLevels.ts:125-133`）。
   - 同一檔股票會有兩個不同的 ATR(14)，違反 V1。要統一成後端版本，並由後端產生（與 ADR-0018 後端化的方向一致）。
   - 兩者目前都吃原始價（§1.5），除權息日的缺口會墊高 ATR。新版要改用還原 OHLC。
2. **倍數事先登記。** 寫明「×m：規則集 vX 事先設定，非由歷史資料最佳化」。換倍數就升版。
3. **公式與數值並列**，例如「收盤 X − 2 × ATR(14) Y（截至 T）＝ Z」。
4. **附歷史觸及率**（V6）。
5. **照實揭露**：ATR 倍數比固定百分比好，好在 V4（隨波動縮放）。**倍數本身仍是人選的參數**，不得宣稱它比較「客觀」或「科學」。

固定百分比之所以不行，是因為它違反 V4，而且現行實作又違反 V3、V5。不是因為「百分比」這個形式本身不行：使用者自己設定的百分比，在 PV-24 是允許的。

### 7.3 各依據類型的「可核對」定義（全部用還原 OHLC）

| 依據 | 定義（事先登記的參數） | 揭露 |
|---|---|---|
| ATR 倍數 | Wilder ATR(14)，倍數 m | ATR 值、m、截至日 |
| 擺動低點／高點 | 第 i 根是擺動低點，若 low_i 嚴格小於 [i−3, i+3] 內其他每一根的 low（窗寬 m=3）。**要到 i+3 才確認**，所以第 T 日只能使用 i ≤ T−3 的擺動點；回看 120 根 | 擺動點日期、**確認日**、價位、當日成交量 |
| 均線 | 還原收盤的 SMA(20)／SMA(60)（沿用 `MA_WINDOWS`，`technical.py:43`） | 窗長、數值、截至日 |
| 跳空缺口 | 向上缺口：low_i > high_{i−1}，缺口區間為 [high_{i−1}, low_i]；之後任一日 low ≤ high_{i−1} 就算回補。向下缺口反之。**必須用還原價**，否則除息日會出現假的向下缺口 | 缺口日期、上下緣、是否已回補 |
| R 倍數 | R ＝ 進場參考價 − 停損／失效價；nR 價位 ＝ 進場參考價 ＋ n × R | R 本身的依據（停損依據可核對，R 倍數才可核對）、n |
| 支撐區／壓力區（PV-26） | 回看 120 根內的擺動點，彼此相距 ≤ 0.5 × ATR(14) 的歸為同一群；同一群觸及 ≥ 2 次才成立。區間為群內最低到最高 | 每次觸及的日期、價位、量能；觸及次數 |

- **擺動點的確認延遲**是最容易出現未來函數的地方：第 i 根要等到看見 i+1～i+3 才知道它是不是擺動點。
- look-ahead 測試要直接斷言：第 T 日的輸出中，不存在確認日晚於 T 的擺動點（附錄 C 的 LA-5）。

### 7.4 現行三個固定百分比的替代候選（PV-24）

| 現行 | 位置【事實】 | 問題 | 替代候選（依優先順序） |
|---|---|---|---|
| **0.92A**（固定 −8% 停損） | `frontend/app/lib/keyLevels.ts:82`、`:138-142`；`stopSuggested = max(A−2×ATR, 0.92A)`，ATR 不可得時直接用 0.92A | 違反 V3、V4、V5。另外錨點 A 在持有時是**平均成本**（`keyLevels.ts:135-136`），以成本定停損牴觸 PV-17 | ① **結構式**：最近一個已確認的擺動低點 − 0.5 × ATR(14)，限於距收盤 ≤ 3 個 ATR 時使用。② **波動式**：收盤 − 2 × ATR(14)，錨點改成收盤而不是成本。③ 使用者自設百分比，標「你設定的 X%」。①②都不可得就**缺席** |
| **MA20 ±3%**（進場觀察區） | `frontend/app/lib/entryObservation.ts:29`、`:147`；回測的五條件也用同一個門檻（`app/backtest/strategies.py:206-207`） | 違反 V4：±3% 對不同波動的股票代表的意義不同 | ① MA20 ± 0.5 × ATR(14)。② 在 [最近已確認的擺動低點, MA20] 之間，限於兩者相距 ≤ 1.5 個 ATR 時使用。觀察區一律是區間（PV-23） |

- **以成本為錨的問題**要請風控裁定是否屬於 PV-17 的範圍（§9 R-6）。【推論】是。

## 8. Q-4 的回答

PM 原問題（總綱 §6 Q-4）：「3／5 日方向標籤如何定義（門檻是否以波動率標準化、進場基準日）？基準候選有哪些？展望規則用哪些輸入？統一的『證據不足』政策？」

1. **門檻是否以波動率標準化**：是。單位是 T 日前 60 日的日報酬標準差 × √h，門檻是 ±0.43 個單位；3 日與 5 日各自一組常數（§2.1）。不用 ATR 定標籤，理由見 §2.1。
2. **進場基準日**：主標籤是 **T 日收盤 → T+h 日收盤**，對應「T 收盤後發布，涵蓋 T+1～T+h」（PV-7）。T+1 開盤 → T+h 收盤只作診斷，用來判斷優勢是不是來自使用者拿不到的隔夜跳空（§4.2）。
3. **基準候選**：B1 延續法、B2 多數類別法（必備）；族群與個股加 B3 大盤延續；個股再加 B4 族群延續（必備）；B5 大盤展望照抄（診斷）；B0 均勻隨機（參考線）。見 §3。
4. **展望規則用哪些輸入**（v1 只用第 1 期已有的資料）：

| 類別 | 輸入（全部用還原價，PIT） | 大盤 | 族群 | 個股 |
|---|---|---|---|---|
| 趨勢 | 收盤與 MA20、MA60 的相對位置（以 σ 為單位）；MA20 的 5 日斜率 | ✓ | ✓ | ✓ |
| 中期動能 | 20 日報酬的 z 值 | ✓ | ✓ | ✓ |
| 短期過度延伸 | h 日報酬的 z 值，用作反轉票 | ✓ | ✓ | ✓ |
| 動量指標 | RSI(14)、MACD 柱狀體的正負號 | ✓ | — | ✓ |
| 波動狀態 | σ20 ÷ σ120 | ✓ | ✓ | ✓ |
| 量能 | 量 z 分數（原始量；配股不還原，須揭露） | — | — | ✓ |
| 相對強弱 | 個股 20 日報酬減族群籃子、減大盤 | — | 對大盤 | ✓ |
| 大盤狀態 | 大盤自己的展望輸入與標籤 | — | ✓ | ✓ |
| 市場寬度 | 漲跌家數、站上 MA20 的比例 | v2（D0 後前瞻） | — | — |

- **不納入**：消息、基本面、法人籌碼（第 2 期才有資料源）、LLM（PX-1），以及**只看當日漲跌**的輸入（PV-9）。
- 規則必須至少有一項回看 ≥ 20 日的輸入。測試要斷言：其他輸入固定、只改 T 日單日報酬時，不得單獨把標籤從偏多翻成偏空。
- 規則形式維持**規則式、可展開**（ADR-0002／0004 的「不用黑箱 ML 直接產生動作」不變）。附錄 B 有一個 v1 骨架候選，**未凍結**。

5. **統一的證據不足政策**：見 §5。另外有兩個「門檻」，不得混用：
   - 證據不足：單筆預測的輸入缺漏；
   - 未驗證：驗證樣本 n < 30（族群 n < 150）。
   - 現行其他門檻維持各自獨立，不受本文件影響：顯示門檻 30、Kelly 20（CEO 已裁決）、族群 150（PM 總綱 NP-V4 現況說明）。

## 9. 已知限制與開放問題

### 9.1 已知限制

1. **檢定力**：大盤只靠前瞻紀錄，需要多年（§4.6）。歷史重放可以補充，但必須分開呈現。
2. **還原資料缺口**：
   - 除權息只從同步開始那天起才有，所以個股展望要等同步累積滿特徵窗長度之後才會有標籤，之前都是證據不足；
   - 配股拒算；分割、減資沒有事件來源；上櫃全部缺（§1.5）。
3. **大盤用價格指數**：除息旺季有股利拖累。我建議接受並揭露，待風控裁定（R-1）。
4. **K 值**：只做了合成資料的合理性檢查，真實類別佔比未知。上線後不得依佔比回頭調 K。
5. **個股範圍是使用者自選的**：庫存與自選股不是隨機樣本，合併命中率不能推廣到「台股個股」。
6. **合併統計以決策日為單位**：同一天多檔之間的相關，靠區塊 bootstrap 處理，但只是近似。
7. **歷史重放的資料**：`^TWII` 走 yfinance，來源非官方，歷史長度與品質都沒有查證。
8. **作廢**：作廢可能不是隨機發生，超過 5% 時要寫進報告第一行。
9. **3 日與 5 日高度相關**：同一套輸入產生的兩個標籤會高度相關。報告要列出兩者的一致率；兩個都「優於基準」時，不能當成兩份獨立證據。

## 附錄 B：v1 規則骨架候選（**不在凍結範圍內**；凍結前要另行送審）

以大盤為例，四張票，每張取 −1、0 或 +1：

1. **趨勢**：收盤 > MA20 > MA60 投 +1；收盤 < MA20 < MA60 投 −1；其餘 0。
2. **中期動能**：20 日 z > +0.5 投 +1；< −0.5 投 −1。
3. **短期過度延伸（反轉）**：h 日 z > +1.5 投 −1；< −1.5 投 +1。
4. **波動狀態**：σ20 ÷ σ120 > 1.5 時，把前三票的總和減半，並向 0 取整。

判定：總和 ≥ +2 為偏多，≤ −2 為偏空，其餘為震盪。3 日與 5 日只有第 3 票的 h 不同，常數分開存放。

- 所有參數都是事前選定的，**沒有用任何真實資料擬合**。
- 【推論】這個骨架很可能贏不了基準。保留它的理由是它簡單、可展開、可以重放，而且每一票都能對應 PV-8 的證據項與反方論點。
