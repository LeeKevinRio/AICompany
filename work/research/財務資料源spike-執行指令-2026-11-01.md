- 依據：`work/reviews/2026-11-01-美股財務提問資料調查-data-engineer.md`（下一步第 1 點）、`work/reviews/2026-11-01-ADR0038基本面資料型別-tech-architect.md`（第五節 P 項）。該調查是在沒有外網的沙盒寫的，所有外部來源的描述都沒實測過，這份 spike 就是補實測。
- 腳本：`apps/stock-desk/backend/scripts/fundamentals_spike.py`（分支 `feat/stock-desk-fundamentals-spike`，版本 2）

## 一、這支腳本做什麼、不做什麼

- 只發 **GET**，只用 Python 標準函式庫，不 import 產品程式（`app.*`），不連資料庫，不寫檔，輸出只到主控台。
- 不重試：碰到 403／429 就如實記錄，不會硬打。
- 金鑰、token、User-Agent、email 在輸出中一律遮成 `***`（測試逐項驗證過）。
- **總請求數上限 30（程式內強制，超過會停）。** 沒填持股時預期 22 次；填滿 3 檔持股、且對照檔第一個路徑失敗時最壞 26 次：

| 來源 | 預期請求數 | 內容 |
| --- | --- | --- |
| SEC EDGAR | 10（最壞 14） | ticker 對照檔 1；AAPL、AMZN、INTC 各取一次 companyfacts 共 3；外國發行人樣本 TSM 的 companyfacts 1；AAPL 申報清單 1，再用 ETag／If-Modified-Since 重發同一個請求 1；ETF 樣本 SPY 的申報清單 1 與 companyfacts 1；SEC 公開的存取規範頁面 1。另外：對照檔第一個路徑失敗才多打備用路徑 1；每填一檔持股多 1（最多 3）；若 AAPL 的第一次回應沒有 ETag 也沒有 Last-Modified，重發那 1 次會省略 |
| TWSE OpenAPI | 4 | swagger 目錄 1；最多 3 個樣本資料集 |
| TPEx OpenAPI | 3 | swagger 目錄 1；最多 2 個樣本資料集 |
| FinMind | 4 | GitHub 上 FinMind 用戶端的 dataset 名稱表 1；額度查詢 1；現金流量表（上市 2330、上櫃 6488 各 1）2 |
| Alpha Vantage | 1 | 美股 AAPL 日線 `compact`，只打 1 次 |
| 合計 | 22 | 不含持股；最壞 26 |

- **ADR-0038 的 P 項不另外發請求**：輸出第 5 節的判定，全部由上面 SEC 那 10 次左右的回應算出來。
- 間隔：SEC 兩個網域合計每次至少間隔 0.25 秒（每秒不超過 4 次，遠低於 SEC 公告的 10 次／秒）；其他網站每次至少間隔 1 秒。整支跑完大約 1～3 分鐘（視網速而定），主要時間花在下載 SEC 的 companyfacts（每檔數 MB）。
- 要驗證的項目：
  1. SEC：ticker 對照檔路徑；三檔公司的營運現金流、資本支出、回購、股利、股票薪酬（SBC）、流通股數標籤，單位，期間（`fp`、`fy`、`form`），申報日 `filed` 的格式。
  2. TWSE／TPEx：有哪些財報類資料集，有沒有現金流量表、庫藏股資料集。
  3. FinMind：現金流量表 dataset 的欄位、有沒有庫藏股相關 dataset、免費額度。
  4. Alpha Vantage：美股日線實測一次（補上對美股價格鏈的最新一次實測）。
  5. ADR-0038 的 P-1～P-9、P-12：見第四節的「P 項對照表」。每一項輸出都是 `HOLDS`（成立）／`NOT_HOLD`（不成立）／`PARTIAL`（部分成立）／`MEASURED`（只量測、沒有成立與否）／`INCONCLUSIVE`（這次的資料不足以判斷），並附證據行。

## 二、事前準備：有哪些環境變數

| 變數 | 必要性 | 沒設會怎樣 |
| --- | --- | --- |
| `SEC_USER_AGENT` | SEC 部分必要 | SEC 部分整段略過（`SKIPPED`），**不發任何 SEC 請求** |
| `FINMIND_API_TOKEN` | 建議 | 以匿名額度跑，額度較低；額度查詢略過 |
| `ALPHA_VANTAGE_API_KEY` | 建議 | Alpha Vantage 略過，不發請求 |
| `SPIKE_US_HOLDINGS` | 選填 | 您目前持有的美股代號，最多 3 檔、逗號分隔（例 `NVDA,TSLA`）。不填，P-12 只能用外國發行人樣本回答「這類公司存在」，判定為 `INCONCLUSIVE`；填了才能回答「您的持股裡有沒有」。代號不是祕密，會出現在輸出裡 |

腳本**不讀 `.env`**，所以後兩個要在視窗裡自己設（用您平常產品在用的同一組值）。

## 三、步驟（Windows PowerShell）

### 1. 新開一個 PowerShell 視窗，確認 `UV_ENV_FILE` 為空

**請開新視窗**，不要沿用跑過 `dev-up.bat` 的視窗：`dev-up.bat` 會設定 `UV_ENV_FILE`，沿用時 `uv run` 可能把 `.env` 載入程序環境，與「不讀 `.env`」的前提不符。

```powershell
echo $env:UV_ENV_FILE
# 應為空白。若有值，關掉這個視窗再開一個新的。
```

### 2. 設定環境變數

```powershell
# SEC 規定每個請求要帶「可聯絡的身分」，格式是「姓名 email」，中間一個空格。
# 範例（假的，請換成您自己的）： Your Name your@email.com
$env:SEC_USER_AGENT = "Your Name your@email.com"

# 這兩個值從您平常存放金鑰的地方複製過來（例如您的 .env），貼在引號中間。
$env:FINMIND_API_TOKEN = "<您的 FinMind token>"
$env:ALPHA_VANTAGE_API_KEY = "<您的 Alpha Vantage key>"

# 選填：您目前持有的美股代號（最多 3 檔，逗號分隔；AAPL、AMZN、INTC、TSM 已內建，不必填）。
# 填入這個，P-12 才能判斷「您的持股裡有沒有非美元或 IFRS 申報的公司」。
$env:SPIKE_US_HOLDINGS = "<代號1>,<代號2>,<代號3>"
```

- **請不要把含 email 的那一行（`$env:SEC_USER_AGENT = ...`）貼回給我們**，也不要貼這三行的任何一行。回傳時只貼第 5 步的腳本輸出。
- 腳本的輸出本身不會顯示這三個值（會遮成 `***`），但您在視窗裡打的指令列會留在畫面與 PowerShell 歷史裡，貼的時候請從第 5 步開始選取。
- 這些值只存在這個視窗的程序記憶體，關視窗就消失，不會寫進任何檔案。
- 持股代號可以用點號寫法（例 `BRK.B`），腳本會自動試對應的連字號寫法。

### 3. 用 `git worktree` 取出腳本（不動您目前的分支）

```powershell
# 路徑請依您的機器調整
$REPO = "C:\<您的 AICompany checkout 路徑>"
Set-Location $REPO
git fetch origin feat/stock-desk-fundamentals-spike
git worktree add ..\AICompany-fspike origin/feat/stock-desk-fundamentals-spike
```

### 4. 進入後端目錄

```powershell
Set-Location ..\AICompany-fspike\apps\stock-desk\backend
```

### 5. 執行

```powershell
uv run --frozen python scripts\fundamentals_spike.py
```

- **必須用 `uv run --frozen`**：`--frozen` 讓 uv 不重新解析、不改動 worktree 內的 `uv.lock`。新 worktree 第一次執行會建立 `.venv` 並同步依賴，**需要網路或 uv 快取**；之後再跑不用。
- 腳本本身不需要任何額外套件（只用標準函式庫），但用 `uv run` 可以確保用的是專案指定的 Python 版本。
- 執行期間畫面會陸續印出每個 `GET ...` 與結果，不是卡住。單一請求逾時是 30 秒。
- 退出碼永遠是 0（腳本只陳述事實，成敗看每項的 `[EXISTS]`／`[MISSING]`／`[ERROR]`／`[SKIPPED]`）。

### 6. 核對版本

在 `..\AICompany-fspike\apps\stock-desk\backend` 目錄內執行：

```powershell
git log -1 --format=%H -- scripts/fundamentals_spike.py
git rev-parse HEAD
```

第一條的**預期值**（最後一次修改腳本的 commit）：

```
f125ea2b29cee5fdf2c7101c8fd74f5107d3a339
```

另外，輸出第三行 `script_sha256_lf:` 的**預期值**（腳本內容的雜湊，已把換行統一成 LF，不受 Windows 換行轉換影響）：

```
5fd195028a1ee1c404c31b36ae8d705e7deed161a1b6ad3e124b10af9ebc3daf
```

兩者任一與預期值不同，代表您跑的不是這個版本的腳本，請回報而不要採用輸出。第二條 `HEAD` 會隨後續文件 commit 而不同，只需如實貼回，不必與預期值相同。

### 7. 直接從主控台複製輸出

- **直接從 PowerShell 視窗選取、複製、貼上**，不要用 `>`、`Out-File` 或管線導向檔案：導向檔案時 Windows 可能改用 cp950 編碼，中文字（例如台灣證交所資料集名稱）會變成亂碼或跳脫碼。
- 輸出較長（SEC 的 AAPL 會列得很詳細，加上第 5 節的 P 項，約數百行）。請往上捲到第一行 `Fundamentals data source spike` 開始複製，到最後的 `== Summary ==` 整段為止。若視窗捲回行數不夠，可先在視窗屬性把「螢幕緩衝區高度」調大再跑。
- 若中途被截斷，至少要貼 **`== 5. ADR-0038 P items`** 與 **`== Summary ==`** 這兩段：前者是每個 P 項的證據，後者是每項的判定與請求總數。

## 四、看到什麼代表什麼（白話）

先看最後的 `== Summary ==`：`requests used: N / 30` 沒填持股時應該是 22 左右；下面每一行是一項的判定。ADR-0038 的 P 項判定另有專章，見本節最後的「P 項對照表」。

### 判定標籤

| 您看到 | 白話意思 |
| --- | --- |
| `[EXISTS]` | 這項東西有，而且回應內容符合預期 |
| `[MISSING]` | 來源有回應，但裡面沒有我們要找的東西（例如這個資料集不存在，或這家公司沒有這個欄位） |
| `[ERROR]` | 請求失敗或回應看不懂（逾時、403、429、不是 JSON 等），**不代表資料不存在**，只代表這次沒拿到 |
| `[SKIPPED]` | 沒設環境變數，所以沒發請求 |

P 項另有自己的判定標籤（`HOLDS`、`NOT_HOLD`、`PARTIAL`、`MEASURED`、`INCONCLUSIVE`），在「P 項對照表」說明。

### SEC EDGAR（美股，免費、官方）

| 您看到 | 白話意思 |
| --- | --- |
| `SEC/ticker-map ... path confirmed` | 股票代號對照 CIK（SEC 的公司編號）的檔案路徑可用，這個路徑可以寫進正式程式 |
| `SEC/ticker-map ... [ERROR] ... HTTP 403` | 多半是 `SEC_USER_AGENT` 格式不對或被 SEC 擋。確認格式是「姓名 email」。腳本會自動改試備用路徑 |
| `built-in CIKs (NOT verified by this run)` | 兩個對照檔路徑都失敗，改用內建的三家公司編號繼續測；這次對照檔路徑**沒有**被驗證 |
| `SEC/AAPL/OCF` 等六項 `[EXISTS] primary tag present` | 官方財報 API 有蘋果這項的標準標籤（營運現金流 OCF、資本支出 CapEx、回購、股利、SBC、流通股數），可以拿來算自由現金流（FCF = OCF − CapEx）和回購 |
| `[EXISTS] ... primary missing, alternate(s): <另一個標籤>` | 這家公司沒用標準標籤，改用別的標籤。**代表程式不能只認一個標籤名，要準備備用標籤清單**。這正是為什麼多抽 AMZN、INTC |
| `[MISSING] ... no candidate tag present` | 這家公司在我們列的候選標籤裡都沒有這項。可能是公司真的沒有（例如沒配息、沒回購），也可能是用了我們沒列到的標籤；後者要看輸出裡的「not present」清單再補 |
| `units={'USD': 120}` | 單位是美元；股數是 `shares`。看到非預期單位（例如外幣）要特別記下來 |
| `forms=... fp=...` | `form` 是申報類型（10-K 年報、10-Q 季報）；`fp` 是期間（FY 全年、Q1～Q3 季）；`fy` 是會計年度。**注意：沒有 Q4**，第四季要用全年減前三季自己算 |
| `period_length={'~3m': .., '~6m': .., '~12m': ..}` | 這是現金流量表的重點：**10-Q 的現金流是「年初累計」**，第二季的數字涵蓋 6 個月、第三季涵蓋 9 個月，不是單季。如果看到 `~6m`、`~9m` 就確認了這點，單季值要用累計相減 |
| `entries=N distinct_periods=M`（N 比 M 大很多） | 同一個期間被重複報在多份申報裡（後面的年報會把去年的數字再列一次）。程式要去重，取「最後申報」的那筆 |
| `filed=2025-11-01` 之類 | 申報日。格式是 `YYYY-MM-DD` 才能直接排序、拿來判斷「這個數字何時才看得到」，避免回測偷看未來 |
| `SEC/<代號>/date-format [ERROR]` | 有日期不是 `YYYY-MM-DD`，會列出幾筆，需要額外處理 |
| `STALE(tag not used recently)` | 這個標籤最近已經沒在用（公司換了標籤），只能當歷史參考，不能當最新值 |
| `latest FY` 與 `latest interim` 那兩行 | 各取最新一筆年報、最新一筆季報當樣本，讓我們看到真實的欄位長相 |
| `SEC/AAPL/Revenue`、`NetIncome`、`DilutedEPS` | 營收、淨利、稀釋後每股盈餘的標籤。營收的替代標籤比較多（`Revenues`、`RevenueFromContractWithCustomer...`），看到 `primary missing, alternate(s)` 就是這家公司用了替代標籤 |
| `SEC/conditional-request [EXISTS] ... HTTP 304` | 用第一次回應給的 ETag／Last-Modified 重發同一個請求，SEC 回 304（沒變）。代表之後每天檢查「有沒有新申報」可以幾乎不耗流量 |
| `SEC/conditional-request [MISSING] ... HTTP 200` | SEC 不理會條件式請求，每次都整份回傳；檢查新申報就得整份下載 |
| `SEC/SPY/companyfacts [MISSING] ... HTTP 404` | ETF（SPY）沒有財報 fact，這是預期中的結果；正式接入時 ETF 會被辨識成「不適用」，而不是當成抓取失敗 |
| `SEC/fair-access-page ... limit=10` | 從 SEC 官方存取規範頁面讀到的流量上限（每秒請求數）與 User-Agent 規定；頁面若改版讀不到，會印 `limit=None` |
| `SEC/TSM/...-brief`、`SEC/<您的持股>/...-brief` | 只看「用哪個會計準則（us-gaap 還是 ifrs-full）」和「用什麼幣別」，不印完整的標籤明細。`non-USD units=['TWD', ...]` 就是這家公司的數字不是美元 |

### TWSE／TPEx（台股上市／上櫃，官方 OpenAPI）

| 您看到 | 白話意思 |
| --- | --- |
| `TWSE/swagger [EXISTS] N datasets, M with 't187ap'` | 證交所開放資料目錄可讀，共有 N 個資料集，其中 M 個是 t187ap 系列（公開資訊觀測站的財報類資料） |
| 一長串 `t187ap...` 資料集清單 | 這就是財報類資料集的完整名單，含中文名稱與欄位數，請整段貼回 |
| `[EXISTS] TWSE/cash flow statement` | 官方 OpenAPI 有現金流量表資料集 |
| `[MISSING] TWSE/cash flow statement -- no dataset-level or field-level match` | 官方 OpenAPI 沒有現金流量表。台股要算自由現金流就得靠 FinMind 或其他來源 |
| `[MISSING] ... treasury stock -- no dataset-level match; N dataset(s) only carry it as a column` | 沒有獨立的「庫藏股買回」資料集；但有 N 個資料集（通常是資產負債表）把「庫藏股票」當成其中一個欄位。這只是**期末庫藏股金額**，不是「這季買回多少」 |
| `[EXISTS] ... treasury stock -- N dataset(s) by path/summary` | 有庫藏股專屬資料集，樣本會接著列出欄位與一兩筆資料 |
| `sample row: {...}` | 真實回應的前兩筆（只列前 8 個欄位），用來看欄位命名與資料新鮮度（有沒有年度、季別、出表日期） |
| `[ERROR] ... SSL` 或憑證相關字樣 | 證交所網站的憑證偶爾與 Python 新版本驗證規則不合。**腳本不會關閉憑證驗證**，如實回報即可，我們再評估 |
| `[EXISTS] TPEx/...` | 櫃買中心（上櫃）OpenAPI 的對應資料集；判讀方式與 TWSE 相同 |

### FinMind（台股備援，我們已在用來抓價格）

| 您看到 | 白話意思 |
| --- | --- |
| `dataset names parsed: N` 與 `keyword matches` | 從 FinMind 官方 GitHub 的用戶端程式碼讀到 N 個 dataset 名稱，並列出與現金流、庫藏股、股利、財報相關的名稱。**這是用戶端程式碼裡的名單，不是官方完整清單**，所以「沒找到」不等於 FinMind 絕對沒有 |
| `[MISSING] FinMind/treasury dataset name` | 名單裡沒有庫藏股／買回相關的 dataset |
| `quota fields: {'user_count': .., 'api_request_limit': ..}` | 這個 token 目前已用次數與每小時上限（只印額度相關欄位，其他欄位只印欄位名稱、不印內容） |
| `[SKIPPED] FinMind/quota` | 沒設 token，沒查額度，後面現金流量表以匿名額度跑 |

### P 項對照表（ADR-0038 草案第五節 D-9，P-10 台股與 P-11 下次財報日不在本次）

在輸出的 `== 5. ADR-0038 P items` 那一節，每個 P 項有一段「證據行」加一行 `[判定]`；全部判定也會重複列在最後的 `== Summary ==`。判定都是**電腦依證據自動算出來的字面結論**，不是我們的解讀；每一項成立或不成立，輸出就直接寫了。

| P 項 | 它在問什麼 | 證據行看什麼 | `HOLDS`（成立） | `PARTIAL`／`NOT_HOLD`／其他 |
| --- | --- | --- | --- | --- |
| P-1 | companyfacts 每筆 fact 是否都帶 `filed`、`accn`、`form`、`start`、`end`、`fy`、`fp`、`frame`；`fy`、`fp` 是不是申報文件的屬性，而不是那筆期間的屬性 | `field coverage` 每個欄位的占比；`start present on period (flow) facts`；`accn whose facts carry more than one (fy, fp)` | 8 個欄位每筆都有，而且每份申報只對應一組 `fy`／`fp` | `PARTIAL`：`accn`、`filed`、`form`、`start`、`end`、`fy`、`fp` 都 100%，只有 `frame` 不是每筆都有（`frame` 只標在部分 fact 是 SEC 資料常見的樣子，結論是「`frame` 不能當鍵」，其他鍵沒問題）。`NOT_HOLD`：缺 `accn` 或 `filed`（結構性問題，ADR 要修訂才能開工），或同一份申報有多組 `fy`／`fp`（代表 `fy`、`fp` 不是申報層級） |
| P-2 | 舊申報（含比較期）的值有沒有保留，能不能重建「第一次公布時的值」 | `reported by more than one filing`（同一期間被幾份申報報過）；`original 10-K kept`（已結束滿一年以上的年度，最早那筆是不是在期末後 130 天內申報的原始年報）；`value changed across filings`（重編的例子） | 原始年報保留比率 90% 以上，且確實有期間被多份申報報過 | `PARTIAL`：比率 50%～90%（部分年度只剩比較期，原始值重建不了）。`NOT_HOLD`：沒有任何期間被兩份以上申報報過，或比率低於 50%（舊值被覆蓋）。`INCONCLUSIVE`：抽到的公司沒有已結束滿一年以上的年度可測 |
| P-3 | 各項目的標籤白名單（含資本支出、股利、回購、營收的替代標籤）與「已驗證」清單 | 每個項目一行：`n/N` 家公司有已驗證標籤、各家用哪個標籤、`[alternate]` 代表用了替代標籤；「已驗證」＝標籤最近還在用（沒有過期）且至少有 3 個會計年度的全年資料 | 每個項目、每家公司都有已驗證標籤 | `PARTIAL`：有些公司某項目沒有。要看是公司真的沒有（例如不配息、不回購）還是我們沒列到那個標籤（輸出有 `present but not verified` 或 `no candidate tag present` 可區分）。`NOT_HOLD`：某個項目所有公司都沒有 |
| P-4 | ticker→CIK 的對照來源；類股代號（`BRK.B`）與 ETF 查不到的情形 | 對照檔路徑與筆數；`AAPL`、`BRK.B`、`GOOG`、`GOOGL`、`SPY`、`TQQQ` 各自查得的 CIK、是原樣查到還是換了寫法、有幾個代號共用同一個 CIK；`ZZZZNOTREAL` 查不到（確認查不到的情形看得出來） | `AAPL` 查得到，且 `BRK.B` 照原樣就查得到 | `PARTIAL`：`BRK.B` 只用 `BRK-B` 查得到，代表產品的點號代號寫法要先轉成連字號才能對照。`NOT_HOLD`：`AAPL` 查不到，或類股任何寫法都查不到。`INCONCLUSIVE`：對照檔沒抓到（只用了內建 CIK）。另外看 `SPY ... companyfacts status`：404 代表 ETF 沒有財報，正式接入時要當「不適用」處理 |
| P-5 | 現行流量限制與 User-Agent 格式 | `documented limit`（官方頁面寫的上限）；`statuses seen`（這次 SEC 回的狀態碼）；`rate-limit headers`；`page says` 引用的官方原句 | 讀到官方上限，且我們以每秒不超過 4 次、用「姓名 email」格式的 User-Agent，沒有任何 403／429 | `NOT_HOLD`：被 403／429 擋（格式或速度被拒）。`INCONCLUSIVE`：沒被擋，但官方頁面讀不到上限（頁面改版） |
| P-6 | 申報清單端點有哪些欄位；是否支援條件式請求；companyfacts 在申報後多久更新 | `filing list columns present`；`conditional request`（重發是否得到 304）；`companyfacts behind by N day(s)`（單次快照：0 代表目前同步，正數代表 companyfacts 比申報清單落後 N 天，可證明有延遲但量不出分布） | 欄位（`accessionNumber`、`filingDate`、`acceptanceDateTime`、`form`）齊全，而且重發得到 304 | `PARTIAL`：欄位齊全但重發仍回 200（不支援條件式請求，每次檢查都要整份下載）。`NOT_HOLD`：缺欄位。`INCONCLUSIVE`：AAPL 申報清單沒抓到 |
| P-7 | 每個 issuer 的回應大小 | 每家：解壓縮後大小、傳輸時（壓縮）大小 | 不適用：這項只給 `MEASURED`＋數字，沒有成立與否 | 要不要另存壓縮後的原始回應由 tech-architect 對照數字決定 |
| P-8 | SIC、實體類型能不能取得；ETF 怎麼辨識 | 一般公司與 SPY 各自的 `sic`、`entityType`、`category` | 一般公司有 `sic` 與 `entityType`，且 ETF 的組合與一般公司不同（可用來辨識 ETF） | `PARTIAL`：都有，但 ETF 看起來跟一般公司一樣（要另想辦法辨識）。`NOT_HOLD`：一般公司缺 `sic` 或 `entityType`。`INCONCLUSIVE`：沒抓到 SPY 申報清單 |
| P-9 | 會計年度結束日能不能取得 | `fiscalYearEnd`（四位數月日，例 `0928`）與 companyfacts 最新全年期間的結束日 | 有 `fiscalYearEnd`，且月份與 companyfacts 最新全年期間一致 | `PARTIAL`：有，但月份對不上或沒資料可對照。`NOT_HOLD`：沒有或格式不是四位數 |
| P-12 | 持股中有沒有以非美元申報、或採 IFRS 的公司 | 每家公司一行：`ifrs-full=yes/no`、`non-USD units=[...]`、白名單標籤用的單位 | **注意方向：`HOLDS`＝「有這類公司」**，依 ADR 這些持股要走 `source_unavailable`（幣別不符），不顯示數字 | `NOT_HOLD`：您填的持股裡沒有。`INCONCLUSIVE`：沒填 `SPIKE_US_HOLDINGS`，只能用 TSM 看「這類公司在 SEC 資料裡是什麼樣子」（預期是 IFRS 與台幣，以輸出為準），沒辦法回答您的持股 |

判讀小提醒：

- 這些判定是 **AAPL、AMZN、INTC（加上您填的持股）的抽樣**，不是全體美股；`PARTIAL` 多半代表「要寫容錯處理」，不代表資料源不能用。
- `INCONCLUSIVE` 不是壞消息，是「這次的資料不足以判斷」，輸出會寫缺什麼。
- 其中 P-1、P-2、P-3 的細節量大，若只想先看結論，看 `== Summary ==` 最後那 10 行 `ADR-0038/P-n` 即可。

## 六、這份輸出不能做什麼

- 它只抽樣：SEC 只看三家公司、台股只看一檔上市一檔上櫃，不能證明「所有公司都有」。覆蓋率要等正式接入後用全體代號統計。
- 它不評斷資料品質好不好，也不下接入決策；只陳述有沒有、長什麼樣。資料源選型由 tech-architect 看輸出後出 ADR，CEO 裁示。
- 它不是財報數字的核實：樣本值只拿來看欄位格式，沒有拿去和公司公告逐筆對帳。
- FinMind 的 dataset 名單來自用戶端程式碼，不是官方完整清單；TWSE／TPEx 的「有沒有」是依資料集名稱、摘要、欄位名稱比對關鍵字，看不到的內容不會被發現。
- 台股的財測、法說會展望、分析師共識預估不在這次範圍；ADR-0038 的 P-10（台股來源與公布時間戳）與 P-11（下次財報日）也不在這次。
- P 項是「抽樣下的字面判定」：樣本只有 3 家公司加您填的持股（最多 3 檔）。P-7 的大小是這幾家的量測值，不是最壞情況；P-6 的「companyfacts 落後」只是單次快照。
- P-12 在您沒填持股時無法回答您的持股，只能證明這類公司存在。

## 七、單元測試

測試在 `apps/stock-desk/backend/tests/test_fundamentals_spike.py`，所有 HTTP 回應都是假的，不連網、不碰資料庫、不用真實金鑰。涵蓋：

- 遮蔽：金鑰、token、User-Agent 整串與其 URL 編碼形式、email、`token=`／`apikey=`／`Bearer` 字樣；完整跑一次後，輸出中不得出現任何一個假金鑰，同時確認這些值確實有被拿去發請求（遮蔽才是唯一擋住它們的東西）。
- SEC 解析：主標籤存在、只有備用標籤、全缺、日期格式錯、過期標籤、畸形資料；兩種 ticker 對照檔格式；備用路徑與內建 CIK 的流程。
- TWSE／TPEx 解析：Swagger 2.0 與 OpenAPI 3 兩種格式、資料集層級與欄位層級的關鍵字比對、樣本挑選。
- FinMind：dataset 名稱表解析、現金流量表項目比對、額度欄位只印白名單。
- 失敗行為：全部來源斷線、HTTP 429／403、不是 JSON、Alpha Vantage 三種廠商訊息、單一區段拋例外不影響其他區段、請求數達上限即停。
- 限速：SEC 間隔 0.25 秒、其他網站 1 秒；請求數超過上限一定會被擋下。
- 原始碼斷言：不含 `sqlite3`、不 import `app`、只 import 標準函式庫、沒有任何檔案寫入或建立的呼叫、唯一的檔案讀取是讀自己（算雜湊）、只有 GET（沒有 POST／PUT／DELETE、沒有 `data=`）、原始碼不含 email 或金鑰字面值。
- ADR-0038 的 P 項：每個 P 項的各種判定都有測試（成立、部分成立、不成立、資料不足），例如缺 `accn` 的 fact 會判 P-1 不成立、較早的比較期缺原始申報會判 P-2 部分成立、點號類股代號只能用連字號查到會判 P-4 部分成立、SEC 回 429 會判 P-5 不成立、重發請求回 200 會判 P-6 部分成立；另測持股清單解析（上限 3 檔、去重、拒絕不合法代號）、回應標頭只保留驗證器與限流欄位（不保留 cookie 與授權標頭）、重發請求確實帶了第一次回應給的 ETag。
- 命令列入口：有 `__main__` 保護；以 `Popen(start_new_session=True)` 啟動 `--help` 驗證可獨立執行且不連網。
