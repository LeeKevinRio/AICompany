# 決策卡「停利參考低於最新收盤」評估（3037 欣興，2026-10-04）

- 撰寫：quant-researcher（唯讀分析，本文未改任何程式）
- 分支：`product/stock-desk`；規則集 `default.yaml` 1.0.3
- 觸發：CEO 本機個股頁 3037，資料截至 10-02（快取）——結論「減碼參考／依規則／信心 中」、最新收盤 1,305.00、
  停損參考 945.08（距最新收盤 −27.6%）、停利參考 1,191.62（距最新收盤 −8.7%）、股數參考 72～170 股、
  失效條件之一「價格回到前波高點附近，或回撤幅度收斂至 -10% 以內。」、基準價（持倉平均成本）。
- 限制：本沙箱沒有 3037 的快取日線與持倉（`data/stock-desk.db` 查無 3037），對外行情連線被擋（TWSE 403），
  因此第 2 節「現價相對前波高點」無法實算，只能給推論與核對方法。

## 0. 給 CEO 的白話說明

卡片上的「停損參考」與「停利參考」不是跟著股價移動的價位，而是用你的**買進平均成本**（反推約 1,027 元）
套固定公式算出來的「進場當下的計畫」：成本往下 8% 叫停損參考（945），往上 16% 叫停利參考（1,192）。
股價已經漲到 1,305，比這個計畫的停利點還高 27% 對 16%，所以停利參考落在現價下面，畫面寫「−8.7%」。

**合理的地方**：數字本身沒算錯，而且照「進場計畫」來看，它其實在告訴你「當初設定的停利點已經被越過了」。
**不合理的地方**有三個：
1. 卡片沒有「已越過」這個狀態，只寫一個負的距離，讀起來像「停利點在下面、還沒到」，意思被反過來讀。
2. 停利、停損都不會隨著股價上漲往上調。現在停損參考 945，等於要讓你把 +27% 的帳面獲利全部吐回、再虧 8% 才算到；
   這對已經大賺的部位沒有保護意義。
3. 「減碼參考」**不是**因為你賺很多才出現，而是因為規則看的是「過去約一年半內**曾經**跌超過兩成」。
   這個數字在股價創新高後也不會消失，所以就算股價早已回到前波高點，卡片還是會說減碼——
   而卡片自己寫的失效條件正是「價格回到前波高點附近」。若 1,305 已在前波高點附近，這張卡就是自己跟自己矛盾。

「減碼參考」和「已越過停利參考」方向剛好一致（都偏保守），但這是巧合，兩者的來源毫無關聯。

## 1. 停損參考 945.08／停利參考 1,191.62 怎麼算的

### 1.1 計算位置與公式

全部在前端，不經後端規則引擎：

- `apps/stock-desk/frontend/app/lib/keyLevels.ts` `computeKeyLevels(bars, avgCost)`
- `apps/stock-desk/frontend/app/position/[symbol]/DecisionCard.tsx`：停損格取 `levels.stopSuggested`、停利格取 `levels.target2R`、
  距離 `(水位 − 最新收盤) / 最新收盤 × 100`（`buildDecisionCardDistance`）

| 項目 | 公式 |
|---|---|
| 基準價 A | 持有且成本可得 → 持倉平均成本；否則最新收盤（試算） |
| ATR(14) | 近 14 根 TR 的簡單平均（非 Wilder） |
| 停損參考 `stopSuggested` | `max(A − 2×ATR14, A × 0.92)`（取較緊、較高者） |
| 停利參考（決策卡大字）`target2R` | `A + 2 × (A − stopSuggested)` |
| 固定停利 `targetFixedPct`（面板次列） | `A × 1.20` |

由定義可推得：`target2R = 3A − 2×stopSuggested`，且因 `stopSuggested ≥ 0.92A`，**`target2R ≤ 1.16A` 恆成立**
（決策卡永遠顯示兩個停利數字中較低的那個）。

### 1.2 用畫面數字反推平均成本

由 `A = (2×停損 + 停利) / 3`（與走哪個停損分支無關）：

- A = (2×945.08 + 1,191.62) / 3 = **1,027.26**
- 945.08 / 1,027.26 = **0.9200** → 停損落在 −8% 固定分支，意即 2×ATR(14) ≥ 82.18、ATR(14) ≥ 41.09（約為收盤的 3.1%）
- 驗算：1.16 × 1,027.26 = 1,191.62 ✓；(945.08 − 1,305)/1,305 = −27.58% → −27.6% ✓；
  (1,191.62 − 1,305)/1,305 = −8.69% → −8.7% ✓
- 面板次列固定停利 1.2A = 1,232.71（距最新收盤 −5.5%），同樣已被越過
- 目前帳面報酬 1,305 / 1,027.26 − 1 = **+27.0%**，以 R（A − 停損 = 82.18）計約 **+3.4R**

**請 CEO 確認 3037 的持倉平均成本是否約 1,027 元**；若是，公式驗證成立，數字沒有算錯。

## 2. 為何觸發「減碼參考」

### 2.1 是哪一條規則

決策卡失效條件取自 `pickRuleForAction(matched_rules, "reduce")`（同動作中權重最高、同權重取規則檔較前者）。
`reduce` 規則中權重 0.6 的有 `downtrend_ma_stack`（較前）與 `drawdown_protection`。畫面顯示的是
`drawdown_protection` 的失效條件 → 可推定：

- `drawdown_protection`（區間回撤超過兩成，reduce 0.6）**命中**
- `downtrend_ma_stack`（空頭排列）**未命中**（否則會被選中顯示）——與股價強勢一致
- 動作是 `reduce` 而非 `stop_loss`：要嘛 `deep_drawdown_stop`（−30%，0.8）未命中，要嘛 reduce 權重合計 ≥ 0.8

### 2.2 關鍵發現：規則看的是「區間**最大**回撤」，不是「目前回撤」

- 條件：`drawdown.max_drawdown < −0.2`
- `drawdown.max_drawdown` 來自 `app/signals/risk.py::drawdown()`：對**整段觀察區間**（`app/api/advice.py` 取
  `DEFAULT_LOOKBACK_DAYS = 540` 日曆日，約 370 根日線）的收盤路徑求 `min(close / running_peak − 1)`。
- 這是一個**歷史極值**：只要區間內曾出現一段 > 20% 的回落，在那段走出 540 日視窗之前，數值都不會變；
  股價創新高、目前回撤為 0，規則照樣命中。
- 但規則的失效條件寫「價格回到前波高點附近，或回撤幅度收斂至 -10% 以內」——**這兩件事程式都不會檢查**：
  回到前波高點不會改變 `max_drawdown`；「收斂至 −10% 以內」只會在舊的那段回落滾出視窗時發生。
- 結論：這是**規則文字與算法不一致**（explanation 寫的是歷史統計，正確；invalidation 卻用「目前回撤」的語意）。
  `deep_drawdown_stop` 的失效條件「回撤幅度收斂至 -20% 以內」同樣有此問題。

### 2.3 現價 1,305 相對前波高點

本沙箱無 3037 資料，無法實算。核對方法（CEO 本機、後端啟動中）：

```
curl -s "http://localhost:8000/api/signals/3037?market=TW" | python -c "import sys,json;d=json.load(sys.stdin);print(d['risk']['drawdown'] if 'risk' in d else d)"
```

看 `max_drawdown`、`peak_date`、`trough_date`；再從同頁「位階（近 N 根）」或 `/api/bars/3037` 取區間最高收盤，
算 `1,305 / 區間最高收盤 − 1`。個股頁位階若顯示「區間上緣」且接近 100%，即可確認「已回到前波高點附近」而規則仍命中的矛盾。

## 3. 核心判斷：(a) 算法、(b) 呈現、還是 (c) 兩者

**判斷：(c) 兩者都有，而且還多一個 CEO 沒點名的規則問題。**

### 3.1 呈現問題（立即、確定）

- 決策卡設計時只預想「停利在現價上方 → 距離為正」（`work/stock-desk-決策卡-文案稿.md` §2：
  「停利參考在現價上方 → 距離為正，字面帶『+』」），沒有「已越過」狀態。
- 對停損已考慮過反向情形（面板有 `KEY_LEVELS_STOP_S5_NEUTRAL_NOTE`「可能高於也可能低於最新收盤」，測試也有
  「停損距離必為正號」案例），但**停利的對稱情形沒有任何字面或狀態**，決策卡上也沒有那句中性說明。
- 「距最新收盤 −8.7%」在數學上正確，但語意上被讀成「停利點在下方 8.7% 處等著」，是誤導性呈現。

### 3.2 算法問題（設計缺口，不是算錯）

- 停損／停利是**以成本錨定的靜態括號（bracket）**：只描述「進場那一刻的計畫」，沒有生命週期。價格一旦走出括號，
  兩個數字都失去操作意義：停利已越過、停損離現價 −27.6%（等於回吐全部獲利再虧 8%）。
- 本產品自己的回測（`app/backtest/strategies.py::_replay_with_stop_levels`）把 `close ≥ entry × 1.2` 當作**出場事件**——
  在回測的世界裡，這個部位早已在越過停利時出場；決策卡卻繼續把一個「已觸發的出場價」當成待到達的水位顯示。
- 附帶發現：決策卡大字用 `target2R`（≤ +16%），回測出場用 `× 1.2`（+20%），**卡上顯示的停利與回測衡量的停利不是同一個數字**。

### 3.3 規則問題（「減碼參考」的來源）

見 §2.2：`drawdown_protection` 以歷史最大回撤觸發、失效條件卻以目前回撤描述，程式不檢查失效條件所描述的事。

### 3.4 「減碼參考」與「已越過停利參考」是否自洽

- **方向上巧合一致**：兩者都偏保守，讀者會以為「因為賺夠了所以減碼」。
- **因果上毫無關聯**：減碼來自後端規則引擎的歷史回撤統計；停利參考來自前端成本公式；規則集中沒有任何規則讀
  `position.unrealized_pnl_pct` 或停利水位（ADR-0004 §4「無目標價」本就讓規則不碰價位）。
  反例：若同一檔股票過去 540 日沒有 > 20% 回落，卡片會變成「續抱參考／加碼…」配上一個「低於現價的停利參考」，矛盾立刻浮現。
- **潛在自相矛盾**：若 1,305 已在前波高點附近，卡上同時出現「減碼參考」與它自己的失效條件「價格回到前波高點附近」——
  依卡片自己的說法，這條規則此刻應已失效。

## 4. 修法選項

### 案 A：只改呈現——加入「已越過」狀態（不改算法）

- 當 `close ≥ target2R`：停利格保留數字 1,191.62，距離小字改為狀態句（例：「最新收盤已高於此水位 +9.5%」，
  分母改為水位本身：(1,305 − 1,191.62)/1,191.62）；`close ≤ stopSuggested` 對稱處理停損格。
- 規則引擎：不動。
- 風控字面：新增 2 句狀態字面 + 頁尾 `KEY_LEVELS_BASIS_CLOSE_DISTANCE` 要補一行「越過時距離分母改為水位」——須風控逐字核可
  （`DECISION_CARD_DISTANCE_PREFIX` 已釘死，不可就地改）。「已達停利」這類字面風控可能視為指令語氣，建議以「最新收盤已高於此水位」這種純事實句送審。
- 回測／look-ahead：無影響（只用同一根最新收盤比較）。
- 優點：小、快、無方法論風險。缺點：只把「已越過」講清楚，沒有給出「越過之後看哪裡」；停損 −27.6% 的無意義問題原封不動。

### 案 B（推薦的目標態）：兩階段生命週期——越過後切換為「移動停利參考」

- 第一階段（持有以來最高收盤 < 成本停利參考）：維持現行成本錨定公式，不變。
- 第二階段（持有以來最高收盤 ≥ `target2R`）：停利格改顯示「移動停利參考」
  `= max(P − 2×ATR14, P × 0.92)`，P = `opened_at` 以來的最高收盤；**參數沿用現有停損公式**，不新增可調參數
  （避免為了好看去挑參數；CEO 快市排程的 P2 用「波段高 × 0.88」，可作為對照但不建議兩套並存）。
  原成本停利 1,191.62 降為附註「（成本停利參考 1,191.62，已越過）」。
- 可選：第二階段停損格亦可改用 `max(成本停損, 移動停利參考)`，避免顯示 −27.6% 的停損——但會改動「停損參考」語意，建議與 CEO 確認後再納入。
- 規則引擎：不動（價位仍是顯示層衍生數字；ADR-0004 §4 不受影響——移動停利在現價**下方**，屬保護水位而非上檔目標價）。
- 資料依賴：需要 `opened_at`（`positions` 表已有）與涵蓋持有期的日線。缺 `opened_at` 或持有期早於日線視窗時須 fail-closed：
  退回案 A 狀態呈現並揭露「最高收盤僅計入可得日線範圍」。多批買進的加權成本下，`opened_at` 取最早一批。
- 風控字面：新增「移動停利參考」標題與算式行；**既有字面 `KEY_LEVELS_TARGET_ROW_TRAILING_NOTE` 與 `KEY_LEVELS_BASIS_TARGET`
  寫明「系統並未另行計算移動停利水位」，案 B 落地即讓這兩句變成不實**，必須同批改寫送審。
- 回測／look-ahead：P 只用 `≤ t` 的收盤，point-in-time 安全；但五條件回測的出場規則（`× 1.2` 全數出場）須同步加入
  「越過後轉移動停利」分支並重跑，**新舊兩版樣本外結果並列呈現，不得擇優**；順便把卡片大字（2R）與回測出場（×1.2）統一。
  需補 look-ahead 測試：截斷未來 K 線後第 t 日的 P 與移動停利值不得改變。

### 案 C：越過時把基準改為最新收盤（不推薦）

- 實作最簡單（沿用「未持有試算」的錨點），但基準會隨價格**下跌而下移**，不是真正的移動停利；
  且與「基準價（最新收盤，試算）＝未持有」既有語意衝突，會讓持有者看到未持有的標籤。

### 附帶修正（建議與上案並行，屬規則集變更）：`drawdown_protection`／`deep_drawdown_stop`

- 方案 D1：新增欄位 `drawdown.current`（最新收盤 / 區間最高收盤 − 1）至 `FIELD_LABELS`，兩條規則改看目前回撤；
  失效條件即與程式一致。屬 ratio 欄位，不觸及 R19 價格欄位白名單。
- 方案 D2：保留歷史最大回撤，但改寫失效條件為程式真正會發生的事（「造成此回撤的區段移出觀察區間」）。
- 兩者都要升規則版本（1.1.0 / 1.0.4）並過 qa-reviewer + risk-compliance-officer；D1 會改變命中頻率，
  需提供改前改後在既有標的上的命中差異。我推薦 D1（規則語意與讀者直覺一致）。

## 5. ADR 層級與待決事項

- 案 A、D2：**非 ADR 層級**（字面／規則版本變更，走風控逐字核可與 qa 審查）。
- 案 B：**ADR 層級**，建議新立 ADR（暫名「關鍵價位（停損／停利參考）的生命週期與計算歸屬」），而非修訂既有 ADR——
  目前沒有任何 ADR 涵蓋關鍵價位公式（`keyLevels.ts` 註解自承正式歸屬應在後端、列為後續）。新 ADR 需定：
  兩階段狀態機、`opened_at` 依賴與 fail-closed、前後端計算歸屬、與五條件回測出場規則一致化；並在 ADR-0004 §4 補交叉引用，
  說明移動停利屬保護水位、不違反「無目標價」。
- D1：新增欄位屬 ADR-0004 規則式框架內的擴充，不需修 ADR，但規則集版本升級須完整審查。

需 CEO 決定：
1. 股價越過停利參考後，卡片要「只標示已越過」（快，下一批就能上），還是要再進一步改成「跟著持有期間最高價往上移的移動停利參考」
   （較完整，要寫 ADR、改回測、重送風控）？我的建議：先上前者止血，後者排入下一輪。
2. 「減碼參考」目前是看「過去一年半內曾經跌超過兩成」，股價創新高後也不會消失。要改成看「現在離高點跌了多少」嗎？我的建議：要。
