## 背景與目標

### 問題陳述

目前 `/backtest` 頁對每個區段（樣本內、樣本外）只呈現彙總指標。使用者看得到總報酬、最大回撤、勝率、完整回合數、獲利因子，但看不到這些彙總是由哪幾筆往返組成：

1. 沒有逐筆清單，使用者無法核對「完整回合數」那一格背後是哪幾段持有期間、各賺賠多少。
2. 沒有報酬最低的幾筆，看不到單次最差經歷有多深，只能從最大回撤間接推測。
3. 沒有連續虧損的長度。同樣的勝率，連續虧損三筆與連續虧損十筆，持有人的實際感受與資金壓力差很多。
4. 平均獲利與平均虧損沒有分列。獲利因子（金額基準）與 Kelly 使用的比值（回報率基準）是兩種不同的量，現行頁面只露出前者，且兩者沒有各自的明確定義。
5. 沒有在場時間比例。策略多數時間空手時，與 Buy & Hold 並列的報酬率差距主要反映「沒有持有」，而不是進出場的好壞。
6. 回合數少的區段，數字照樣以同樣版面呈現。使用者對可靠度的判斷幾乎全靠樣本數（C8 批審項 5 已指出此偏誤方向對使用者不利），目前除「完整回合數」一格外，沒有任何樣本不足的提示。

這些缺口都屬於「既有資料已經算出、但沒有呈現」或「呈現了但缺少定義與樣本量脈絡」的報告層問題，不需要新資料源、不需要新策略。

### 目標

1. 讓使用者在同一頁看見每個區段的往返明細、最糟幾筆、最長連敗、平均獲利／虧損、兩種比值與在場時間，並知道這些數字各是怎麼算的。
2. 樣本量不足時明確標示，同時所有數字照列、不隱藏；樣本量達到門檻時，不因此宣稱統計上足夠或有優勢。
3. 不改變任何既有數字（含 Kelly 匯入讀到的 p、b、n）；只新增欄位與區塊。

### 成功指標

- 每個有完整回合的區段，其往返清單筆數恆等於該區段「完整回合數」一格（單一來源，可由測試機械驗證）。
- 清單損益加總恆等於同區段彙總所用的已實現損益加總（對帳不變式）。
- 新增字面 100% 經風控逐字核可、100% 通過禁用詞掃描；零個外部素材措辭（PX-2）。
- 既有 Kelly 匯入端點對同一輸入的輸出與改版前逐欄相同（回歸測試）。

## 使用者與情境

主要使用者：CEO／內部自用者（風控前提：純自用，B1 (b-1)）。若日後對外分享或商業化，本 PRD 須重審（風控初審 B1 前提）。

情境（以自選的單一標的與自選的內建策略為前提，不涉及跨標的）：

- **S1：核對彙總數字的組成。** 使用者跑完一次回測，看到樣本外「完整回合數」為若干筆。他想知道這幾筆各是哪段期間、各自賺賠多少，以及彙總是否被少數幾筆帶動。
- **S2：評估自己撐不撐得住。** 使用者想知道歷史上最糟的幾次單筆經歷與最長一段連續虧損，用來對照自己的資金與心理承受範圍；他需要的是可驗證的事實，不是對「該不該用這個策略」的判斷。
- **S3：判斷這份數字有多少參考性。** 回測樣本外只有很少幾筆時，使用者需要被明確告知「筆數太少」，並仍能看到全部數字（協議紅線：不隱藏難看結果）。
- **S4：與 Buy & Hold 對照時分辨「沒持有」與「持有但表現不同」。** 使用者需要看到策略在場時間占比。
- **S5：區辨兩個比值。** 使用者看到「獲利因子」與另一個比值時，需要知道它們各自的定義、為何數字不同。

本 PRD 不預設使用者會依這些數字採取任何行動；頁面不提供任何行動建議、不判定策略好壞。

## 功能需求（逐條編號）

### A. 計算口徑（資料與計算定義）

以下口徑是需求的一部分，實作不得自行變更；數值或細節標示「待 quant」者，由 quant-researcher 在方法論文件登記後回填本節。

- **D-1 單位為完整往返。** 往返＝從空手進場到再度空手的一段持有期間，沿用 `app/backtest/episodes.py` 的 `extract_episodes`，不是 fill（K-3）。引擎每日再平衡產生的微額賣出成交不得被當成獨立交易。使用者面字面沿用現行已核可詞彙「回合」（如「完整回合數」），避免同頁出現「往返」「回合」「交易」三種名詞混用。
- **D-2 區段歸屬。** 沿用 `attribute_round_trips` 的「完全包含」規則：進場與出場都落在區段內才計入；跨界回合與期末未平倉回合不入清單與統計，另行計數（見 FR-8）。樣本內＝第一折訓練窗；樣本外＝所有折測試窗銜接。清單、彙總與 Kelly 讀取的回合集合必須是同一份。
- **D-3 往返報酬。** 沿用 `Episode.return_on_entry_equity`＝該往返已實現損益 ÷ 進場前一根 bar 的權益。這是權益基準的報酬率，不是標的價格漲跌幅；使用者面須讓讀者分辨這一點（字面交 creative-lead）。已實現損益含該往返內所有 fill，買賣兩端的手續費、稅費與滑價皆已計入（含成本）。
- **D-4 持有日數。** 出場 bar 序號減進場 bar 序號，單位為交易日（bar 數）。進出日期取該 bar 的日期。（待 quant 確認以交易日或日曆日呈現。）
- **D-5 獲利／虧損／平局。** 報酬 > 0 為獲利回合，< 0 為虧損回合，= 0 為平局（計入回合數，但不屬獲利也不屬虧損），與 `RoundTripStats` 現行語意一致。
- **D-6 平均獲利回合報酬、平均虧損回合報酬。** 分別為獲利回合報酬的算術平均、虧損回合報酬的算術平均（負值）。某一側沒有回合時顯示「—」（未定義，不得顯示 0 或補值），並於旁邊顯示該側回合數。
- **D-7 payoff ratio。** ＝ 平均獲利回合報酬 ÷ 平均虧損回合報酬的絕對值。數值上必須等於既有 `round_trip_payoff_ratio`（Kelly 的 b），同源，不得重算。任一側為空時顯示「—」。
- **D-8 profit factor。** ＝ 獲利回合已實現損益（金額）加總 ÷ 虧損回合已實現損益絕對值（金額）加總。數值上必須等於既有 `profit_factor`。沒有虧損回合時顯示「—」。
- **D-9 兩比值的關係。** payoff ratio 以回報率平均為基準，profit factor 以金額加總為基準，兩者在進場前權益不相等時數值不同，且不可互換（ADR-0006 Context 事實 2）。頁面不得把兩者並稱為同一個名稱，不得沿用含糊的「損益比」「盈虧比」單一稱呼；各自的定義寫入使用者面字面（FR-5）。
- **D-10 最糟 N 筆。** 區段內完整回合依報酬由小到大排序取前 N 筆；報酬相同者依進場日由早到晚。回合數不足 N 時全部列出並標示總筆數，不補足、不推估。因為是依報酬排序，若區段內全部為獲利回合，清單中也會出現正報酬，標題與字面須與此事實相符（不得預設都是虧損）。N 值待 quant。
- **D-11 最長連敗。** 依進場時間順序，連續報酬 < 0 的最長回合數；報酬 = 0 或 > 0 的回合會中斷連敗；不跨樣本內／樣本外邊界；同長度並列時取最早一段。同時給出該段首筆進場日與末筆出場日。回合數 = 0 時顯示「—」（不顯示 0，避免把沒有交易讀成沒有虧損）；回合數 > 0 而無虧損回合時顯示 0。平局處理待 quant 確認。
- **D-12 在場時間比例。** ＝ 區段內收盤後目標權重 > 0 的 bar 數 ÷ 區段 bar 數（以回測結果的 `weights` 判定）。Buy & Hold 欄依定義為全程持有，顯示 100%（待風控確認，見 Q8）。注意：策略暖身期無部位，也計入分母；此限制須在口徑說明中如實呈現（待 quant 確認是否扣除暖身期）。
- **D-13 樣本量與樣本不足。** 樣本量 n＝該區段 `RoundTripStats.n`（即現行「完整回合數」一格的值）。樣本不足 ⇔ n < `N_MIN_DISPLAY`。`N_MIN_DISPLAY` 為本 PRD 的符號常數，值待 quant（見 D-14）。判定單位為區段：樣本內與樣本外各自判定、各自標示。
- **D-14 `N_MIN_DISPLAY` 與 Kelly 閘門 20 的關係（需求，非數值）。**
  - 兩者語意不同：Kelly 閘門是「寫入 Kelly 輸入前的拒收條件」（CEO 2026-08-19 裁決，屬風險偏好決策，不得為過關而調降）；`N_MIN_DISPLAY` 只是回測頁的揭露標示，不拒絕任何東西、不影響任何計算。
  - F-11 不得修改、重用或讀取 Kelly 的任何門檻常數；`N_MIN_DISPLAY` 須是獨立命名的常數，單一定義處，不得宣告在 `app/kelly/sample_gate.py`（該模組依 ADR-0006 約束 37 不得 import `app.backtest`，反向亦應避免互相綁定）。
  - 若 quant 提出的值不等於 20（候選：20、30；風控 PX-17 的固定句以 30 為例，K-4 則要求不得未經說明直接沿用 30），則畫面上會同時存在「回測頁標示不足」與「Kelly 仍接受匯入」的區間，使用者面字面與風控審查須明確處理此情況，且須讓 CEO 知悉兩套門檻並存（Q1、Q14）。
  - 門檻數字若出現在使用者面字面內，須與常數同源，並有守門測試釘住（比照 C8-3、C8-11 的單一來源作法）。

### B. 功能需求

- **FR-1 逐筆往返清單。** 每個區段（樣本內、樣本外分別）列出該區段全部完整回合，依進場時間由早到晚。欄位：進場日、出場日、持有日數、報酬、已實現損益（含幣別）。清單筆數必須等於該區段「完整回合數」；清單損益加總必須等於該區段回合歸屬物件的已實現損益加總。
- **FR-2 報酬最低 N 筆。** 每個區段各自列出報酬最低的 N 筆（D-10）。欄位只允許：進場日、出場日、持有日數、報酬、已實現損益，以及「同期指數報酬」（僅在 tech-architect 確認可得時，見 Q6）。不得有任何自由文字欄位，不得有新聞或事件說明（PX-19、K-6）。區塊須帶一句固定的邊界說明，講清楚本表只含系統可由價格資料驗證的欄位、不含當時新聞或事件說明，且列出的是已發生的觀測，不是未來損失的上限（字面見 L-13）。
- **FR-3 最長連敗。** 每個區段各自顯示最長連敗回合數與起迄日（D-11），以完整回合為單位計，不得以 fill 計（K-3）。
- **FR-4 平均獲利／平均虧損分列。** 每個區段各自顯示平均獲利回合報酬、平均虧損回合報酬（D-6），各自附該側回合數。兩者分列於兩個獨立列，不合併成單一比值。
- **FR-5 payoff ratio 與 profit factor 分名並列。** 兩者在同一個區段表內相鄰呈現、各自一列、各自有名稱與定義（D-7、D-8、D-9）。「獲利因子」現行標籤已由風控核可「維持零改動」；是否補定義句或如何命名 payoff ratio，屬新字面，須經風控（C8 批審 L-C8-2 在兩者同屏時轉為 required）。兩者的數值只能取自既有欄位，不得在前端或 `report.py` 重新計算（C8 規則：回合的抽取與歸屬只在 `episodes.py`）。
- **FR-6 在場時間比例。** 每個區段顯示策略欄的在場時間比例，Buy & Hold 欄依 D-12。
- **FR-7 樣本不足標示。**
  1. n < `N_MIN_DISPLAY` 的區段，在該區段的所有回合層統計上方，顯示一句固定句（單一字面、單一渲染點），表達「筆數少於門檻，以下回合層統計不具推論意義」之意；字面由 creative-lead 起草、風控逐字審（PX-17）。
  2. 觸發時，所有數字照列：清單、最糟 N 筆、連敗、平均值、兩比值、在場時間一概不隱藏、不灰階、不折疊、不加刪除線、不以「—」取代已算出的值（協議紅線、PX-17）。
  3. n ≥ `N_MIN_DISPLAY` 的區段，該固定句不出現；同時頁面任何位置不得出現「具統計意義」「顯著」「足夠」「充足」「可靠」「有優勢」「沒有優勢」「曲線擬合」「過度擬合」等結論或充足性用語（PX-17、PX-21）。達門檻時是否需要一句中性提醒（例如「筆數達門檻不代表足夠」），交風控決定（Q9）；PM 建議需要，以免「句子消失」被讀成「已通過」。
  4. 判定以區段為單位，樣本內與樣本外各自判定，不以全期合計判定。
  5. 樣本不足的標示是結構化旗標由後端下發，前端只負責渲染，不自行比較 n 與門檻（K-4；前端不反推、不重算）。
  6. 該旗標只用於揭露，不得進入任何計算，也不得被 Kelly 模組讀取（對應 ADR-0006 約束 34 的精神）。
- **FR-8 回合歸屬揭露。** 每個區段顯示被排除的跨界回合數與期末未平倉回合數（事實計數），並附一句固定說明（字面為新字面，不得續引 Kelly 側的 `KELLY_BOUNDARY_TRIP_EXCLUSION`，C8 批審項 2 的明文禁令）。理由：F-11 在本畫面新增 payoff ratio（即 Kelly 的 b），觸發 L-C8-1(c)；且 ADR-0006 已記載排除跨界回合會優先移除存續較長的回合（實測約 1.73 倍），是須如實揭露的已知限制。此需求須回風控審，並同步更新 C8 批審的列管狀態。
- **FR-9 成本、資料與揭露承載。**
  1. 所有新數字都是含成本的數字，並如實反映該次回測使用的成本模型（手續費、稅費、滑價）。畫面須在新區塊內以一句固定句說明報酬已扣除哪些成本；該句在滑價設定為 0、費率尚未查證的現況下仍須為真，不得宣稱「已完整計入真實成本」類內容（PX-14、K-5）。
  2. 費率未查證（`rates_verified` 為 false）時，頁面既有的費率警示維持原位原樣，F-11 不得移動、降級或取代它；新區塊不得在警示缺席時單獨渲染。`verified_on` 狀態照實揭露，不修改（PX-14）。
  3. 新區塊（往返明細）自帶一行「資料截至」與來源，沿用現行回測頁來源列的版式與資料（`report.data`），不另創語意（PX-6）。
  4. 頁面既有的常駐免責句、產出時間戳、Buy & Hold 與除權息還原揭露均不得被新增內容下移出首屏、降級字級或收合（C8-8 判例）。
  5. 樣本內、樣本外分列呈現；並列於相鄰位置，F-11 不計算、不顯示兩段之間的「落差」衍生值，也不加任何關於落差意義的句子（PX-14、PX-21；是否另需衍生值見 Q10）。
  6. 一律並列 Buy & Hold 欄；回合層列在 Buy & Hold 欄顯示「—」（沿用 C8 的三態語意：無回合歸屬物件顯示「—」，有歸屬而無回合顯示 0）。
- **FR-10 空狀態。** 區段內完整回合數為 0 時：清單與最糟 N 筆以一句固定空狀態句取代；平均、兩比值、最長連敗顯示「—」；在場時間比例與回合歸屬計數照常顯示。空狀態須區辨三種情況並各有可辨識的呈現：區段內沒有任何部位；有部位但回合因跨界或期末未平倉被排除（此時被排除計數 > 0）；該欄不適用（Buy & Hold）。不得出現「勝率為『—』而完整回合數 > 0」之組合（C8-7）。
- **FR-11 單一來源與不變式。**
  1. 回合的抽取、歸屬與統計只在 `app/backtest/episodes.py`；新增欄位由其擴充供給，`report.py` 與前端不得自行重新推導（C8 規則、K-3）。
  2. 平均獲利回合報酬 ÷ |平均虧損回合報酬| 必須等於 payoff ratio；清單筆數必須等於完整回合數；清單損益加總必須等於回合歸屬物件損益加總。三者均須有測試釘住。
  3. 所有既有欄位的值與欄位順序不變（additive 變更）。
- **FR-12 Kelly 匯入行為不變。** `POST /api/kelly-inputs/{symbol}/import-backtest` 的輸入判定、寫入值（p、b、n、n_win、n_loss、f* 區間）、422 條件、`low_sample_warning` 語意、回應內容，對同一輸入與改版前逐欄相同；新增的清單與旗標不得出現在該端點的回應與落地欄位中（比照 `curves` 不外洩的作法）。

## 驗收條件（每條需求至少一組 Given/When/Then）

下列例子的數字為構造資料，用來釘住計算口徑，不描述任何真實標的。涉及 `N_MIN_DISPLAY`、`N_WORST` 時以符號表示，實測值待 quant 登記後填入。

**AC-1（FR-1 逐筆清單與對帳）**
Given 一次成功的 walk-forward 回測，樣本外區段有 12 個完整回合
When 檢視樣本外往返明細
Then 清單恰有 12 列、依進場日由早到晚；每列含進場日、出場日、持有日數、報酬、已實現損益；清單筆數等於該區段「完整回合數」一格；清單已實現損益加總等於回合歸屬物件的損益加總（容許浮點誤差）；樣本內另列一組，兩段不混合。

**AC-2（FR-2 最糟 N 筆不含敘事）**
Given 樣本外有 12 個完整回合
When 檢視報酬最低 N 筆
Then 列出報酬最小的 `N_WORST` 筆，由小到大排序、同值依進場日由早到晚；每列欄位只有進場日、出場日、持有日數、報酬、已實現損益（及可得時的同期指數報酬）；API 回應與渲染後 DOM 中，該區塊除日期、數值、幣別與固定標籤外沒有任何自由文字欄位，沒有任何新聞、事件、原因敘述；區塊帶有邊界說明句（L-13）。

**AC-3（FR-2 不足 N 筆）**
Given 某區段只有 3 個完整回合且 `N_WORST` 大於 3
When 檢視報酬最低 N 筆
Then 列出 3 筆並標示該區段共 3 筆，不補足、不推估；若 3 筆全為獲利回合，仍照報酬排序列出，標題不稱之為虧損。

**AC-4（FR-3 連敗以往返計）**
Given 一個區段的完整回合報酬依序為 +2%、−1%、−3%、−0.5%、+1%、−2%、0%、−1%，且該次回測產生的 fill 筆數遠大於 8（因每日再平衡的微額賣出）
When 計算最長連敗
Then 最長連敗為 3（第 2～4 筆）、起日為第 2 筆進場日、迄日為第 4 筆出場日；0% 的回合中斷連敗；結果與 fill 筆數無關，改變再平衡產生的 fill 數量不改變此值。

**AC-5（FR-4、FR-5 兩比值分名、定義與數值）**
Given 一個區段有四個完整回合，進場前權益與損益依序為：1,000,000／+30,000（+3.00%）、1,030,000／−10,300（−1.00%）、1,019,700／+10,197（+1.00%）、1,029,897／−20,598（−2.00%）
When 檢視該區段指標表

## 風險與依賴

### 風險

1. **L-C8-1(c)、L-C8-2 已被觸發。** F-11 在本畫面新增 payoff ratio（Kelly 的 b）並與獲利因子同屏，依 C8 批審須回風控並補回合歸屬揭露；若漏掉，會在審查時被擋下。已列入 FR-5、FR-8。
2. **兩套門檻並存。** 若 `N_MIN_DISPLAY` 不等於 20，使用者可能看到「回測頁說筆數不足、Kelly 仍可匯入」的情況，被讀成自相矛盾。需 quant 說明、風控審字面、CEO 知悉（D-14、Q1、Q14）。
3. **樣本不足的句子消失被讀成已通過。** 達門檻後固定句不再出現，使用者可能解讀為「夠了」。需風控裁定是否加中性提醒（Q9）。
4. **權益基準報酬被讀成價格漲跌。** `return_on_entry_equity` 以進場前整體權益為分母，與持倉的價格報酬在部位未滿倉時不同。字面須讓讀者分辨（L-02）。
5. **在場時間比例分母含暖身期。** 暖身期無部位，會拉低比例；若不扣除，須如實說明（D-12、L-08、Q2）。
6. **跨界排除造成的偏誤。** 被排除的跨界回合平均存續較長（ADR-0006 記載約 1.73 倍），清單與統計偏向短持有；以 FR-8 揭露承擔，不能宣稱保守。
7. **回合集中於少數市況。** 單一標的的回合會群聚於同一段行情，有效獨立樣本小於名目筆數；單一標的回合不會互相重疊，故沒有「不重疊子樣本」可另報。這一點是否需要在字面中提及，由 quant 與風控判定（Q1）。
8. **回應增長。** 逐筆清單隨回合數增加，回測數十至上百筆屬常態，需 tech-architect 確認回應大小與前端渲染可接受。
9. **同期指數報酬的資料與 IO。** 目前回測管線只載入單一標的日線，未載入基準指數；若要顯示同期指數報酬，牽涉 ADR-0010 的 IO 預算與 ADR-0024 的閘門。不可得時不阻擋出貨（Q6）。
10. **漂移風險。** 新增大量中文字面若前後端各自持有，易發生漂移；以後端單一定義處下發與逐字釘住測試降低（C 節）。
