## 背景與目標

### 問題陳述

目前 `/backtest` 頁對每個區段（樣本內、樣本外）只呈現彙總指標。使用者看得到總報酬、最大回撤、勝率、完整回合數、獲利因子，但看不到這些彙總是由哪幾筆往返組成：

1. 沒有逐筆清單，使用者無法核對「完整回合數」那一格背後是哪幾段持有期間、各賺賠多少。
2. 沒有報酬最低的幾筆，看不到單次最差經歷有多深，只能從最大回撤間接推測。
3. 沒有連續虧損的長度。同樣的勝率，連續虧損三筆與連續虧損十筆，持有人的實際感受與資金壓力差很多。
4. 平均獲利與平均虧損沒有分列。獲利因子（金額基準）與盈虧比（回報率基準，即既有 `round_trip_payoff_ratio`）是兩種不同的量，現行頁面只露出前者，且兩者沒有各自的明確定義。
5. 沒有在場時間比例。策略多數時間空手時，與 Buy & Hold 並列的報酬率差距主要反映「沒有持有」，而不是進出場的好壞。
6. 回合數少的區段，數字照樣以同樣版面呈現。使用者對可靠度的判斷幾乎全靠樣本數（C8 批審項 5 已指出此偏誤方向對使用者不利），目前除「完整回合數」一格外，沒有任何樣本不足的提示。

這些缺口都屬於「既有資料已經算出、但沒有呈現」或「呈現了但缺少定義與樣本量脈絡」的報告層問題，不需要新資料源、不需要新策略。

### 目標

1. 讓使用者在同一頁看見每個區段的往返明細、最糟幾筆、最長連敗、平均獲利／虧損、兩種比值與在場時間，並知道這些數字各是怎麼算的。
2. 樣本量不足時明確標示，同時所有數字照列、不隱藏；樣本量達到門檻時，不因此宣稱統計上足夠或有優勢（並以常駐提醒句避免「句子消失」被讀成「已通過」，F11-R-10）。
3. 不改變任何既有數字（含 Kelly 匯入讀到的 p、b、n）；只新增欄位與區塊。

### 成功指標

- 每個有完整回合的區段，其往返清單筆數恆等於該區段「完整回合數」一格（單一來源，可由測試機械驗證）。
- 清單損益加總恆等於同區段彙總所用的已實現損益加總（對帳不變式）。
- 新增字面 100% 經風控逐字核可（含 L-06p，已全部定稿）、100% 通過禁用詞掃描與 F-11 專屬掃描；零個外部素材措辭（PX-2）；F11-W-16 已否決字面在出貨原始碼零出現。
- 既有 Kelly 匯入端點對同一輸入的輸出與改版前逐欄相同（先行 commit 的 golden 回歸，F11-A-26）。
- F-11 須連同回合歸屬揭露（L-11）與兩比值定義（L-06、L-07）一起落地才可標記 done，不得拆批出貨（F11-R-1）。

## 使用者與情境

主要使用者：CEO／內部自用者（風控前提：純自用，B1 (b-1)）。若日後對外分享或商業化，本 PRD 須整體重審（風控裁示前提提醒）。

情境（以自選的單一標的與自選的內建策略為前提，不涉及跨標的）：

- **S1：核對彙總數字的組成。** 使用者跑完一次回測，看到樣本外「完整回合數」為若干筆。他想知道這幾筆各是哪段期間、各自賺賠多少，以及彙總是否被少數幾筆帶動。
- **S2：評估自己撐不撐得住。** 使用者想知道歷史上最糟的幾次單筆經歷與最長一段連續虧損，用來對照自己的資金與心理承受範圍；他需要的是可驗證的事實，不是對「該不該用這個策略」的判斷。
- **S3：判斷這份數字有多少參考性。** 回測某區段只有很少幾筆時，使用者需要被明確告知「筆數太少」，並仍能看到全部數字（協議紅線：不隱藏難看結果）。筆數達門檻時，也需要被提醒筆數多寡不代表結果可延續。
- **S4：與 Buy & Hold 對照時分辨「沒持有」與「持有但表現不同」。** 使用者需要看到策略在場時間占比。
- **S5：區辨兩個比值。** 使用者看到「獲利因子」與「盈虧比」時，需要知道它們各自的定義、為何數字可能不同。

本 PRD 不預設使用者會依這些數字採取任何行動；頁面不提供任何行動建議、不判定策略好壞。

## 功能需求（逐條編號）

### A. 計算口徑（資料與計算定義）

以下口徑是需求的一部分，實作不得自行變更。v0.2 已依 quant 回覆回填數值與細節（登記處：quant 回覆 §6）。

- **D-1 單位為完整往返。** 往返＝從空手進場到再度空手的一段持有期間，沿用 `app/backtest/episodes.py` 的 `extract_episodes`，不是 fill（K-3）。引擎每日再平衡產生的微額賣出成交不得被當成獨立交易。使用者面字面沿用現行已核可詞彙「回合」（如「完整回合數」），避免同頁出現「往返」「回合」「交易」三種名詞混用。
- **D-2 區段歸屬。** 沿用 `attribute_round_trips` 的「完全包含」規則：進場與出場都落在區段內才計入；跨界回合與期末未平倉回合不入清單與統計，另行計數（見 FR-8）。樣本內＝第一折訓練窗；樣本外＝所有折測試窗銜接。清單、彙總與 Kelly 讀取的回合集合必須是同一份歸屬結果。**不得改動 `attribute_round_trips` 的歸屬條件**（改動即觸發 L-C8-1(d)，須回風控，F11-R-6）。
  - **已知限制（既有行為，非 F-11 引入，quant §5.7、§5.8）：** 最後一折放不下時 walk-forward 停止，尾端剩餘 r ＝ (n − 訓練窗) mod 測試窗 根（預設幾何下 0～62 根）不屬於任何區段，引擎仍對整個 frame 回測，故尾段內有成交與回合，但不入任何清單與統計；尾段內才進場的回合也不計入任何排除數。**此限制已由 KT-R-9 升為揭露義務，見 FR-17。**
  - **歸屬分類（讀碼事實，風控 KT-R 事實核對 2）：** 已平倉、與區段重疊但未被完整包含的回合計入「跨界」（含跨出區段右界者）；未平倉回合只要 `open_entry_idx < stop` 即計入「未平倉」（含在區段開始前就進場者）；進場點已在 stop 之後的回合兩個計數都不計。r = 0 時「跨出右界」不可能發生；r > 0 時，樣本外進場、到樣本外最後一根仍持有、之後在尾段平倉的回合計入跨界，不計入未平倉。
- **D-3 往返報酬。** 沿用 `Episode.return_on_entry_equity`＝該往返已實現損益 ÷ 進場前一根 bar 的權益。這是權益基準的報酬率，不是標的價格漲跌幅；使用者面須讓讀者分辨這一點（字面交 creative-lead）。已實現損益含該往返內所有 fill，買賣兩端的手續費、稅費與滑價依該次回測的成本設定計入（含成本）。
- **D-4 持有日數（quant 已登記）。** ＝ `exit_idx − entry_idx`，最小值 1，單位為**日線根數（bar 數）**，不提供日曆日。進出日期取該 bar 的日期。資料若有缺 bar，該數字是日線根數、可能少於實際交易日，使用者面字面（L-02）須以「日線根數」這類可驗證的說法呈現。持有日數同時等於該回合期間持股大於零的區間數（與 D-12 同單位，須有對帳測試）。
- **D-5 獲利／虧損／平局（quant 已登記）。** 依 `return_on_entry_equity` 與 0.0 做嚴格浮點比較，不設 epsilon，與 `stats_from_returns` 的 `n_win`、`n_loss` 同一判定式：報酬 > 0 為獲利回合，< 0 為虧損回合，= 0 為平局（計入回合數，但不屬獲利也不屬虧損）。**平局會中斷連敗。** 若日後要設 epsilon，須在 `episodes.py` 統一改。
- **D-6 平均獲利回合報酬、平均虧損回合報酬。** 分別為獲利回合報酬的算術平均、虧損回合報酬的算術平均（負值），用與 `stats_from_returns` 相同的切分與 `statistics.fmean` 計算（F11-A-17、A-18，不得改用 `np.mean`）。某一側沒有回合時顯示「—」（未定義，不得顯示 0 或補值），並於旁邊顯示該側回合數。
- **D-7 盈虧比（技術名 payoff ratio）。** ＝ 平均獲利回合報酬 ÷ 平均虧損回合報酬的絕對值。數值上必須**位元相等**於既有 `round_trip_payoff_ratio`（Kelly 的 b），同源，不得重算（前端直接讀既有欄位；測試用 `==`，F11-A-18）。任一側為空時顯示「—」。
- **D-8 獲利因子（profit factor）。** ＝ 獲利回合已實現損益（金額）加總 ÷ 虧損回合已實現損益絕對值（金額）加總。數值上必須等於既有 `profit_factor`。沒有虧損回合時顯示「—」；有虧損回合而無獲利回合時為 0（照實顯示）。
- **D-9 兩比值的關係與命名（v0.2 依 F11-R-2、quant §5.3 更正）。**
  - **更正 v0.1 前提：** C8 批審**從未**要求「盈虧比」零出現。C8 批審的零出現要求只針對已撤銷的「勝率（依結算筆數計）」；C8-10 實機驗收紀錄曾查「盈虧比零出現」，只是用來偵測 L-C8-2 是否已觸發，不是禁令。L-C8-2 現已觸發，該偵測點隨之作廢。
  - **命名：** head noun 沿用「盈虧比」（全產品對 b 已核可的唯一中文名，Kelly 各句亦用之；兩畫面講同一個數，同名才讓使用者看得出來）。**但不得直接沿用 Kelly 那條標籤的原字**（`KELLY_PAYOFF_RATIO_LABEL`）：該標籤在 C5 列管 L10 下以「平均獲利/虧損」措辭，回測頁同屏有金額欄（已實現損益）與金額基準的獲利因子，會被讀成金額平均。回測頁的盈虧比標籤或定義必須是**新字面**，受詞明確限定為「獲利回合報酬（率）的平均」對「虧損回合報酬（率）平均的絕對值」。
  - **定稿（風控 F11-W 修訂版，L-06）：** 標籤採裸「盈虧比」（L-06a）；括號限定的備案不採用，列入已否決清單（C.3 第 8 條）。理由：回測頁與 Kelly 各處已用裸「盈虧比」稱同一個數，F11-R-2 的同名原則靠 head noun 成立，加第三種括號變體反而增加「兩個不同東西」的訊號；受詞限定改由相鄰的 L-06d 承擔（FR-5.3 允許「標籤或定義」二擇一）。條件 86 的精神（「依…計」掛在比值上可能被讀成回合數之比）兩案都沒有觸及。
  - **禁止寫法：** 任何「依…計」掛在比值上的形式（條件 86；`盈虧比（依完整回合計）` 已列於 `REJECTED_LITERALS`）、單獨的「損益比」、「賠率」、以同一個名稱並稱兩個比值。
  - **差異來源（更正 v0.1 的不完整說法）：** 盈虧比以回報率平均為基準，獲利因子以金額加總為基準，兩者不可互換。數值不同有**兩個來源**：一是獲利與虧損的**筆數比**（即使各回合進場前權益全相等，獲利因子＝盈虧比 × 獲利筆數 ÷ 虧損筆數，例如勝率 0.4、盈虧比 1.5 時獲利因子為 1.0）；二是各回合進場前權益不同所造成的金額加權。v0.1 所寫「進場前權益不相等時數值不同」暗示權益相等時兩者相等，是錯的；起草 L-06／L-07 時不得沿用該句當理由。
  - **顯示四捨五入：** 讀者拿兩個顯示的平均值相除，可能與顯示的盈虧比在第二位小數差 1，屬四捨五入，不是錯誤；前端不得自行相除（F11-A-24）。**定稿：不放四捨五入差異句**——creative 起草的 L-06r 已被風控 VETO（F11-W-6，量化誤差上限不是對所有資料為真），見範圍外第 18 點。
- **D-10 最糟 N 筆（`N_WORST = 5`，quant 已登記）。** 區段內完整回合依 `return_on_entry_equity` 由小到大排序取前 5 筆；報酬相同者依 `entry_idx`（進場 bar 序號，不用日期字串）由小到大。不依金額排序（金額排序會系統性把晚期權益較大的回合排前面）。回合數不足 5 時全部列出，呈現格式統一為「列出 k 筆／共 n 筆」（k＝min(5, n)），不補足、不推估；即使與全部清單重複仍照列，因排序本身就是資訊。因為是依報酬排序，若區段內全部為獲利回合，清單中也會出現正報酬，標題與字面須與此事實相符（不得預設都是虧損）。**不得附名次或序數標籤**（例如「最差第 1」），以免排序被讀成評等（F11-R-22）。
- **D-11 最長連敗。** 依 `entry_idx` 順序，連續報酬 < 0 的最長回合數；報酬 = 0 或 > 0 的回合會中斷連敗；不跨樣本內／樣本外邊界；同長度並列時取最早一段（以 `entry_idx` 判定）。同時給出該段首筆進場日與末筆出場日。
  - 回合數 = 0 時為 `null`，顯示「—」（不顯示 0，避免把沒有交易讀成沒有虧損）；回合數 > 0 而無虧損回合時顯示 0。
  - 不變式：`n > 0` 時 `0 ≤ 最長連敗 ≤ n_loss`，且最長連敗 = 0 若且唯若 `n_loss = 0`。
  - **同長度並列時只列最早一段**：L-04n 須讓讀者知道列的是最早一段，不致誤讀為唯一一段（PM 決定：第一版不另下發「同長度出現幾段」，見範圍外第 16 點）。
  - **連敗只在單一區段內計算**：橫跨區段邊界的回合被兩段都排除，一段剛好跨界的連敗會被切斷、兩段各自看到的長度偏短。此事實由 **L-04n** 揭露（風控 F11-W-1：字面須說出方向——「一段連續虧損若與被排除的回合相鄰，顯示的長度可能短於把該回合一併計入時的長度」；被排除的回合只會出現在區段兩端，所以「相鄰」涵蓋兩側；「可能短於」不斷言一定較短，對未平倉回合也成立）。L-11n 不涵蓋連敗截斷。
  - **L-04n 必須緊鄰錨點列（F11-W-11）**：L-04n 是「最長連續虧損回合數」列在 DOM 中的下一個兄弟 `<tr>`，為四個定義列錨點之一（F11-A-53）。理由：值格只顯示長度與起迄日，「單位是完整回合」「只列最早一段」「被排除的回合造成偏短」是讀這個值的必要條件，分開放就失去作用。
- **D-12 在場時間比例（v0.2 依 quant §2.4、F11-A-12 改寫；更正 v0.1 的 `weights > 0` 與分母）。**
  - **判定：持股判定，與回合同一條空手線。** 第 t 根收盤後「在場」，若且唯若 t 落在某個回合的持有跨度 `[entry_idx, exit_idx)`，或落在期末未平倉回合的 `[open_entry_idx, 最後一根]`（持股大於 `POSITION_EPSILON`）。由回合跨度直接導出，放在 `episodes.py` 的新純函式。
  - **分母：報酬區間數 n−1。** 區段 `[s, e)` 共 n＝e−s 根 bar，對應 n−1 個日報酬區間；分子在 `[s, e−1)` 上數在場區間，分母為 e−s−1。e−s < 2 時為 `null`（顯示「—」）。如此才與旁邊的總報酬等同一組日子（v0.1 的「區段內權重 > 0 的 bar 數 ÷ bar 數」分子多算最後一根、分母多算一根）。
  - **不扣除暖身期。** 理由：此比例用來和 Buy & Hold 並列、解釋報酬差，暖身期間 Buy & Hold 有持有、有賺賠；且樣本內總報酬、CAGR 本來就含暖身期。暖身期只影響樣本內（API 強制訓練窗不短於暖身期，樣本外沒有暖身期）。
  - **另下發樣本內暖身空手區間數 `warmup_flat_intervals`**（樣本外恆為 0）＝`|[s, e−1) ∩ [0, W−1)|`，W 取自該策略的暖身根數；這些區間內權重與持股恆為空手（測試釘住）。L-08n 以占位處 `{warmup_flat_intervals}` 呈現此數（句型已由風控逐字定稿）；**樣本外照常顯示同構句，值為 0**（風控 O-4：句子為真，維持兩段列序與句型相同〔F11-R-13.1〕，不得為了省略而讓兩段句型不同）。W 由 `execute_backtest` 傳入 `walk_forward_round_trip_detail(result, folds, *, warmup_bars)`，`report.py`、`episodes.py` 不得 import `strategies` 或 `STRATEGY_WARMUP_BARS`（F11-A-41）。以暖身根數 60 的策略為例，樣本內 251 個區間中有 59 個結構性空手，在場比例上限約 76.5%。
  - **Buy & Hold 欄：** 100% 是 Buy & Hold「自區段第一根收盤起全程持有」的**定義值，不是量測值**，由後端依定義下發，前端不得硬寫 100%；B&H 序列為空（區段無 bar 或 `close[s] ≤ 0`）時為 `null`，顯示「—」，不得顯示 100%（F11-R-9、F11-A-13(b)）。n = 1（無報酬區間）時，策略欄與 B&H 欄皆為 `null`。兩欄分母為同一組 n−1 個報酬區間，口徑句須對兩欄同時為真；日後若改為扣除暖身期，B&H 欄須扣除同一組區間並以測試斷言分母相等。
  - **平均曝險權重不需要：** 現行四個策略權重只有 0 或 1。須有守門測試斷言每個內建策略只輸出 {0.0, 1.0}；日後新增分數權重策略時該測試轉紅，屆時須補平均曝險並重審「在場比例」名稱。
  - **兩種判定的差異情境與測試（v0.3 依 F11-A-39 取代原 A-32 的「目前相同」說法）：** 持股判定與 `weights > 0` 在下列情境是**已定義的差異**，不是「目前相同」：(a) 收盤價 ≤ 0；(b) |delta| ≤ 1e-12 不成交；(c) 平倉殘餘超過 `POSITION_EPSILON`。測試分三層：
    - **等價鎖（雙向）：** 每個 `STRATEGY_IDS` 在標準 fixture 與預設 `initial_cash` 下，對所有 t ∈ [0, n) 都要 `held[t] ⇔ weights[t] > 0`（quant 的不變式 1 只驗回合跨度內，抓不到「權重 > 0 卻沒有成交」發生在跨度外的情況）。「目前相同」只指這一條。
    - **特性測試：** 情境 (a)(b)(c) 各一個 fixture，斷言在場比例跟隨持股判定而不是 `weights`，並斷言持有日數與在場區間的對帳仍成立；情境 (c) 以合成 trades 直接構造殘餘，不依賴極大帳本的浮點路徑。
    - **守門測試：** 內建策略權重只取 {0.0, 1.0}，涵蓋權益趨近 0 等其他差異情境。
  - `initial_cash` 無上限的既有限制**列為另案，不阻擋 F-11**（F11-A-47）：殘餘是否超過 epsilon 取決於持有股數（約「本金 ÷ 股價」），單純替 `initial_cash` 加上限不是正確修法；建議由 quant 先量測，有必要再修訂 ADR-0006。F-11 的在場判定與回合用同一條空手線，即使錯位也是一致的錯位，不會放大問題。
- **D-13 樣本量與樣本不足（`N_MIN_DISPLAY = 30`，quant 已登記）。** 樣本量 n＝該區段 `RoundTripStats.n`（即現行「完整回合數」一格的值）。樣本不足 ⇔ n < 30（**含 n = 0**）。判定單位為區段：樣本內與樣本外各自判定、各自標示。取值理由（quant §1.1，K-4）：統計寬度、產品內既有「不判定」下限慣例（C-36，單位不同故只算慣例一致、不同源）、錯誤成本不對稱（多標示的代價只是多一句）、與 Kelly 閘門的風險偏好語意分離。**門檻是揭露慣例，不是統計分界**，30 不代表足夠，PRD 與字面均不得把它描述成統計標準或最低要求（F11-R-16.3）。

### B. 功能需求

- **FR-1 逐筆往返清單。** 每個區段（樣本內、樣本外分別）列出該區段全部完整回合，依進場時間由早到晚。欄位：進場日、出場日、持有日數、報酬、已實現損益（含幣別）。清單筆數必須等於該區段「完整回合數」；清單損益加總必須等於該區段回合歸屬物件的已實現損益加總。列的鍵集合恰為 5 個語意欄位，不得有價位、自由文字、fill 明細或指數欄位（F11-A-21）。欄位標題與說明句為 L-02a～e、L-02n；**已實現損益儲存格必須帶幣別前綴**（以 `formatMoneyNumber(value, currency)` 格式化，渲染測試斷言；F11-W-15）。

### 觀察項（v0.4 新增；PM 結論，不立需求，不需 CEO 作答）

**UX 疑問：展開完整清單後，在筆數少（n ≤ k，k ＝ min(5, n)）時，「報酬最低的幾筆」預覽表與完整清單看起來重複。是否另立 UX 需求？**

**PM 結論：不另立 UX 需求，列為觀察項；現行行為維持。** 理由：
1. **風控已裁示無揭露疑慮，且鎖定現況**（F11-W-36）：筆數由 L-03「列出 k 筆／共 n 筆」與 L-16「展開全部 n 筆」明示，重複的列不會灌水筆數；重複的是報酬最低的幾筆，偏誤方向保守；展開時隱藏預覽表反而會讓下檔摘要在展開狀態消失。
2. **這是 PRD 既有的刻意設計，不是漏洞**：D-10 已寫明「即使與全部清單重複仍照列，因排序本身就是資訊」；兩張表排序不同（預覽依報酬由低到高，完整清單依進場時間），且完整清單預設收合，只有使用者主動展開才會並排看到。
3. **任何消除重複的改法都會讓版面隨資料改變**：n ≤ k 時省略其中一張表，等於讓呈現依 n 切換，與 F11-R-8「展開狀態與呈現不得隨 n、績效而變」的精神相悖，並增加 AC 與測試分支；合併兩張表、展開時隱藏預覽表則被 W-36 列為須送審項。
4. **唯一不涉及版面改動的緩解是加一句說明（例如「筆數少時，下方清單包含這幾筆」）**，但那是新使用者面字面，須走 creative-lead → 風控逐字審，且屬版面方位指涉（F-11 對版面方位詞已多處收緊），PM 判斷成本高於收益，不建議。
5. 任何改動（含上述加句、省略、合併、改筆數呈現）一律先送風控（W-36）；不得併入一般需求變更。
