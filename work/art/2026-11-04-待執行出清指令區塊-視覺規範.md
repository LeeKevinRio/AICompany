## 1. 版面結構

### 1.1 頁面層級順序（`/today` 為 success）

```
<NavBar>                                  （非 sticky）
<ModeStatusBar>                           （sticky，唯一）
<main>
  h1 列                                   <h1>排程台</h1>（success 時只有 h1）
  <div role="status">                     橫幅槽位，常駐、同一個 DOM 節點
     橫幅（出清成功後才有）
  </div>
  ★ 待執行出清指令區塊（本規範）           ← 新增，今日指令帳冊之前的第一塊
  attribution（page 層歸屬語）
  page_summary
  warnings
  Cap1 揭露 / RuleSetConfirmPanel
  今日指令帳冊（DirectiveLedger）
  部位快照 → 結算
</main>
[對話框 portal]
```

- `/today` 為 pending 或 error 時，**區塊不渲染**（整個元件不掛載，連標題都沒有；V-33 的 h1 列、V-32 的順序、V-36 的「無 sticky」都維持不變）。因此區塊與 N-170 後備觸發鈕（只在非 success 時出現於 h1 列）**永遠不會同時存在**，沒有兩者的相對位置問題；§6 仍把這一點寫成可量測的條款（VP-19）。
- 渲染條件由 `pending_exit_block` 的資料決定（`today.isSuccess` 且非 null 且小節的行合計 ≥ 1），本規範不重述；null、缺鍵、行數為 0 時**不渲染任何東西**，頁面版面必須與沒有這個功能時逐像素相同（VP-20）。

### 1.2 區塊內部結構

```
<section  data-testid="pending-exit-block"  aria-labelledby={h2.id}>          區塊根
  <h2>                         ← title（A-1）
  <p>                          ← lead_template（A-2，{read_at} 已代入）
  <section data-kind=…>        ← 每個小節一個，依陣列順序
    <h3>                       ← label（非 null 才渲染）
    <p>                        ← lead
    <ul>
      <li data-testid="pending-exit-row">     ← 每個批次一行
        <p>                    ← text
        <p>…                   ← notes[]（0..n 則，依序）
        <p>                    ← entry_before_exit_note（非 null 才渲染）
      </li>
    </ul>
  </section>
  <p data-testid="pending-exit-closing">…   ← closing_notes[]（依序，A-14）
</section>
```

- 這是**單一容器**：A-2（歸屬語、「本系統不下單」）與各行在同一個 `<section>` 內、在各行之前、不摺疊，滿足風控 F-1 的四個條件。
- 前端不重排、不篩選、不合併、不自撰任何一個字；沒有值的欄位**不渲染空元素**（空 `<p>`、空 `<li>`、空 `<h3>` 都不行，`entry_before_exit_note` 在 N-168 之前恆為 null，不得預留空位，AC-N171-21）。
- `data-testid` 與 `data-kind` 是測試用屬性，不是可見字面，允許。**禁止**加 `aria-label`、`title`、`aria-describedby`（那是新的使用者可讀字串）。

### 1.3 建議的 class 骨架（load-bearing，數值以此為準）

```tsx
<section
  data-testid="pending-exit-block"
  aria-labelledby={titleId}
  className="mb-6 mt-6"
>
  <h2 id={titleId} className="text-lg font-semibold text-neutral-100">{block.title}</h2>
  <p className="mt-2 break-words text-sm text-neutral-300">{leadWithReadAt}</p>

  {block.sections.map((s) => (
    <section
      key={s.kind}
      data-kind={s.kind}
      aria-labelledby={s.label !== null ? labelId(s.kind) : undefined}
      className={s.kind === "stale" ? "mt-6 border-t-2 border-neutral-500 pt-4" : "mt-4"}
    >
      {s.label !== null && (
        <h3 id={labelId(s.kind)} className="text-sm font-semibold text-neutral-100">{s.label}</h3>
      )}
      <p className={`${s.label !== null ? "mt-1 " : ""}break-words text-sm text-neutral-300`}>{s.lead}</p>
      <ul className="mt-2 divide-y divide-neutral-800 border-y border-neutral-800">
        {s.rows.map((r) => (
          <li key={`${r.symbol}-${r.batch_no}`} data-testid="pending-exit-row" className="py-3">
            <p className="break-words text-sm text-neutral-100">{r.text}</p>
            {r.notes.map((n, i) => (
              <p key={i} className="mt-1 break-words text-sm text-neutral-300">{n}</p>
            ))}
            {r.entry_before_exit_note !== null && (
              <p className="mt-1 break-words text-sm text-neutral-300">{r.entry_before_exit_note}</p>
            )}
          </li>
        ))}
      </ul>
    </section>
  ))}

  {block.closing_notes.map((c, i) => (
    <p key={i} data-testid="pending-exit-closing" className="mt-4 break-words text-sm text-neutral-300">{c}</p>
  ))}
</section>
```

- `mb-6` 是必要的：相鄰兄弟的上下 margin 會**取較大者**（collapse），下一個區塊多半是 `mt-4`（16px），若區塊自己不給 `mb-6`，間距會只有 16px。
- `<ul>` 要靠 Tailwind preflight 的 `list-style: none`；不得加 `list-disc`、`list-decimal`（項目符號、編號都算多餘的可見字元，VP-6）。
- 標題層級：`h1`（排程台）→ `h2`（本區塊，與 `DirectiveLedger` 的 `h2` 平行）→ `h3`（小節標籤）。
- **【r2 新】日期 token 包裝（只適用於 `r.text`；骨架中的 `{r.text}` 改為「把 `\d{4}-\d{2}-\d{2}` 的每個命中切出，包成行內 `<span className="whitespace-nowrap">…</span>`，其餘文字原樣」）。** 約束：① 只切分 text node，`textContent`／`innerText` 與 API 值逐字相同（不改字、不插入任何字元；**不得**以 U+2011 非斷行連字號取代 `-`，那會改字面）；② span 只有 `whitespace-nowrap` 這一個 class，無其他樣式、無 `title`／`aria-*`、不加色、不加粗；③ `<p>` 本身維持 `white-space: normal`；④ 其他欄位（`lead`、`notes[]`、`entry_before_exit_note`、`closing_notes[]`）本身若含 ISO 日期，同樣處理，規則不變；⑤ 不改任何面向使用者的字面，不需新字面。

## 2. 各層字級、色階、間距

底色：區塊**不設任何背景**，直接落在頁面底色上。**【r2 改】** 下表色階對比以實際底色 `rgb(10,10,10)`（body computed）計，用 sRGB 相對亮度公式實算：`neutral-100`（#f5f5f5）約 18.2:1、`neutral-300`（#d4d4d4）**13.36:1**（實測值，qa-e2e）、`neutral-500`（#737373）約 4.2:1（只用於粗線，不用於文字）。r1 以純黑計（neutral-300 為 14.17）的數字作廢。

| 層 | 元素 | 字級／行高 | 字重 | 文字色 | 其他 |
|---|---|---|---|---|---|
| L1 | 標題 `h2`（A-1） | `text-lg`（18px／28px） | 600 | `neutral-100` | 與 `DirectiveLedger` 的 `h2` 同款；無底線、無圖示 |
| L2 | 導言 `p`（A-2） | `text-sm`（14px／20px） | 400 | `neutral-300` | `mt-2`（8px）；整段完整顯示 |
| L3 | 小節標籤 `h3`（A-7／A-8；`label` 非 null 才有） | `text-sm`（14px／20px） | 600 | `neutral-100` | 小節的第一個子元素 |
| L4 | 小節導言 `p`（A-3／A-9／A-4） | `text-sm` | 400 | `neutral-300` | 有標籤時 `mt-1`（4px） |
| L5 | 行本文 `p`（`text`：A-5 或 `EMERGENCY_EXIT_STALE_ITEM`） | `text-sm` | 400 | `neutral-100` | 一行裡最亮的字，因為它是使用者要拿去券商核對的事實 |
| L6 | 行附註 `p`（`notes[]`：A-6／A-11／A-12／A-15；`entry_before_exit_note`） | `text-sm` | 400 | `neutral-300` | 每則 `mt-1`（4px） |
| L7 | 末尾說明 `p`（`closing_notes[]`：A-14） | `text-sm` | 400 | `neutral-300` | `mt-4`（16px），在所有小節之後、**不在任何 `<li>` 內** |

- **全區塊只有兩種字級：18px（標題）與 14px（其餘）。** 沒有 `text-xs`，沒有 `text-base`。
- **字重只有 400 與 600。** 不用 `font-bold`、`font-medium`、`italic`、`underline`、`uppercase`、`tracking-*`。
- **字色只有 `neutral-100` 與 `neutral-300`。** 下限（`page_summary`）是 `text-sm` + `neutral-300`，本區塊所有文字都 ≥ 這個下限（風控第四節第 4 點）。
- 行本文用 `neutral-100`、附註用 `neutral-300` 是**資訊層級**，不是重要性高低：附註含「請勿就同一批重複下賣單」「以券商回報為準」等防超賣句，`neutral-300` 的對比是 13.36:1（以實際底色 `rgb(10,10,10)` 計），足夠，且高於風控要求的下限。若風控認為附註應與本文同色，改成 `neutral-100` 不影響版面，見 §10 之 R-2。
- `{read_at}`：純文字代入，**不加粗、不加底線、不包 `<span>`／`<time>` 樣式**。

## 3. 與其他元素的相對位置與間距

| 對象 | 規範 | 理由 |
|---|---|---|
| **h1 列** | 區塊在 h1 列之下。無橫幅時，h1 列下緣到區塊上緣 24px。success 時 h1 列只有 `<h1>`，高度與區塊存在與否無關（V-36：h1 列高度 32px ±1）。 | |
| **N-170 後備觸發鈕** | 觸發鈕只在非 success 時出現在 h1 列；區塊只在 success 時渲染。**兩者不同時存在。** 轉為 success 時觸發鈕卸載、區塊掛載，狀態列接手觸發鈕，三者交替不重疊。 | 區塊不得「補位」觸發鈕離開後留下的空位；h1 列不因區塊而變高。 |
| **狀態列（sticky）** | 區塊在 `<main>` 流內，不 sticky、不 fixed，**不改變狀態列的高度、位置、內容**（V-1、V-2 的量值前後差 0）。`scrollY = 0` 時區塊上緣 > 狀態列下緣。 | AC-N171-13 |
| **回執橫幅** | 橫幅下緣到區塊上緣 24px（大於橫幅與 attribution 之間原本的 16px，**刻意加大**）。橫幅是有框的底色盒，區塊是無框無底色的排版，兩者在視覺語言上就不同；多出的 8px 與標題 `h2` 一起構成「這是另一塊、不是橫幅的延伸」。區塊不在橫幅子樹內、不在 `role="status"` 容器內（不是 live region）。 | 風控：外觀不得像回執橫幅；PRD A-1「與橫幅有清楚的標題分隔」 |
| **attribution／`page_summary`／warnings／Cap1／帳冊** | 在區塊之下，區塊下緣到它們 24px。這些元素的 class 與位置**除了被往下推之外一律不動**。 | 風控「位置」段：區塊必須在頁面層級句子之前 |
| **出清對話框** | 對話框是 portal，與區塊無關；開啟時區塊維持在遮罩之下的原位，不卸載、不位移。 | |

對既有橫幅捲動規則（出清畫面規範 §4）的影響：區塊在橫幅**之下**，區塊的出現或消失不改變橫幅上緣的位置，所以 V-9／V-10／V-11／V-12／V-47 的量值**不受影響**（VP-18 以實測確認）。

## 4. 三類小節的區分方式

### 4.1 設計原則

不得用紅綠、不得用圖示（風控第四節第 3 點）。彩色一律不用，**也不用 `neutral` 的明暗去暗示好壞**：三類的行本文都是同字級、同色階，使用者在券商的實際風險（重複賣出或少賣）在三類之間沒有輕重之分，**不得把 stale 做得「比較不顯眼」**，因為 A-9 明說這些指令「並未被取消」。

### 4.2 三類的視覺編碼

| 類別 | 出現路徑 | 標籤 `h3` | 小節上緣 | 行本文／附註 |
|---|---|---|---|---|
| `covering`（仍涵蓋） | authored | 後端 `label` 非 null 才渲染（只在 stale 也存在時，A-7）。**前端不自行判斷何時顯示，完全看 `label` 是否為 null。** | `mt-4`，無線 | 標準 |
| `stale`（已不再涵蓋、仍未結算） | authored | `label` 恆非 null（A-8），`h3` 渲染 | `mt-6` + **`border-t-2 border-neutral-500`** + `pt-4` | 標準（與 covering 完全相同） |
| `unclassified`（未分類） | unauthored | `label` 為 null，**不渲染 `h3`**（A-4 作為小節導言） | `mt-4`，無線 | 標準 |

- 區分來源：**文字標籤（後端字面）＋ stale 的 2px 粗線**。粗線是單純的「另一組」分隔，用 `neutral-500`，不是警示色；它的語意只是「下面是另一個小節」，不是「這組比較糟」。
- 為什麼不用虛線／點線：虛線在慣例上等於「作廢、未啟用」，會把 stale 讀成「已取消」，與 A-9「這些指令並未被取消」直接牴觸。**不採用。**
- 為什麼不用縮排、左色條：左色條是帳冊列（`border-l-4`）的語言，用了會讓區塊被讀成帳冊的一部分（風控 A-2：「它們不列入指令帳冊」）。**不採用。**
- 為什麼不用不同字色／字重：見 4.1，三類不分輕重。
- 三類不會同時出現三種：authored 只有 covering、stale 兩種（可單獨或並存），unauthored 只有 unclassified。因此畫面上最多兩組。
- 小節順序完全照後端陣列，前端不排序（covering 在前、stale 在後是後端排好的）。

## 5. 行內附註的呈現

- 附註（A-6、A-11、A-12、A-15）與 `entry_before_exit_note`（W-B2L，N-168 之後才有值）都放在**所屬行的 `<li>` 內**，順序嚴格等於後端陣列順序（風控 A-15 的同列順序：`text` → `notes` → `entry_before_exit_note`）。
- 每則一個 `<p>`，`mt-1`（4px），左邊緣與 `text` 對齊（**不縮排**），`text-sm text-neutral-300`，無底色、無邊線、無圖示、無標籤前綴、無項目符號。
- 為什麼不縮排、不加左線：任何縮排或左線都會被讀成「次要資訊」，而附註含防超賣句，風控要求它與行同列、不降級。
- 為什麼堆疊在下方而不是接在 `text` 後面成同一段：附註長（A-15 約 180 字），接在同一段裡會讓 `text`（標的、批次、股數、日期）被淹沒；各自成段、4px 緊貼、行與行之間 25px，可同時滿足「同列」與「可掃讀」。「同列」在本規範的實作定義是「**同一個 `<li>`、相鄰、中間沒有分隔線、間距小於行間距**」，見 §10 之 R-1 請風控確認。
- 所有附註**一律完整顯示**：不摺疊、不 tooltip、不截斷、不「顯示更多」。
- 值為 null 或空陣列時不渲染（無空 `<p>`、無預留高度）。

## 6. 響應式（375 與 1280）

**單一版型，沒有斷點。** 區塊及其子孫的 class 不含任何斷點前綴（`sm:`、`md:`、`lg:`、`xl:`、`2xl:`），VP-15 以 class 掃描驗收。

| | 375×812（含 375×667） | 1280×900 |
|---|---|---|
| `<main>` 內容欄寬 | 343px（375 − 2×16） | 992px（`max-w-5xl` 1024 − 2×16） |
| 區塊左右邊緣 | 與 `<h1>`、橫幅、attribution 同一條欄線 | 同左 |
| 版型 | 單欄、全部堆疊 | 單欄、全部堆疊（**不做雙欄、不做表格、不做 grid／flex**） |
| 14px 每行約可容納字數 | 約 24 個全形字 | 約 70 個全形字 |
| 導言 A-2 約行數 | 約 14 行 | 約 5 行 |
| 行本文（A-5） | 約 2～3 行 | 多為 1～2 行 |
| 字級、間距、色階 | 同 §2 | 同 §2 |

- 理由：資訊要素必須「完整可見、不摺疊」（AC-N171-13），任何會在窄寬度重排或隱藏欄位的版型（表格→卡片、grid 欄位消失）都增加漏看風險；單欄堆疊在兩個寬度下結構完全相同，qa 只需比兩個寬度的欄寬。
- 不限制導言的最大行寬（不加 `max-w-*`）：與橫幅、attribution、`page_summary` 同欄寬，頁面只有一條欄線（出清畫面規範 §2.3 的同一原則）。
- 已知取捨：375 寬時，導言加上一兩個小節導言與行，區塊總高可達數個螢幕高（粗估 1,200～2,000px），**會把 attribution、`page_summary`、帳冊往下推很遠**。這是風控「位置」段指定區塊必須在這些頁面層級句子之前的直接後果，art-lead 不能在順序內改動；也不得為此加錨點連結、「跳到帳冊」按鈕或摺疊（風控：不得放按鈕、連結或 CTA，不得摺疊）。列入 §10 之 R-4 請風控知悉。
- 最小寬度：**【r2 改】** 320px 除 VP-14（日期 token 不拆行，必驗）外不屬驗收範圍；VP-13 建議一併量（suggested）。320 寬時內容欄寬 = 288px，日期 token 實測約 85px，不會撐出水平捲軸。

## 9. 可機械驗收的 V 條款

### 9.0 共同條件

- 環境：headless Chromium。視窗：**375×812、375×667、1280×900** 各跑一輪（VP 條款沒特別註明者皆三個都要過）。
- 命名：本檔條款用 `VP-n`，與出清畫面規範的 `V-n` 不衝突。需要引用該規範的條款時以 `V-n` 稱呼。
- 選擇器：區塊 `[data-testid="pending-exit-block"]`、小節 `section[data-kind]`、行 `[data-testid="pending-exit-row"]`、末尾說明 `[data-testid="pending-exit-closing"]`；橫幅槽位 `main > div[role="status"]`；h1 列 `main > div:has(> h1)`。
- **色值解析（必做，因為 Tailwind 4 的 computed color 可能不是 `rgb()`）**：把 computed 字串設給一個 1×1 canvas 的 `fillStyle`、`fillRect`、`getImageData`，取 sRGB 的 `[r,g,b,a]`，以下稱 `rgba(el, prop)`。容差：各通道 ±2。
- 參考色（hex，Tailwind neutral 色階）：`neutral-100 = (245,245,245)`、`neutral-300 = (212,212,212)`、`neutral-500 = (115,115,115)`、`neutral-800 = (38,38,38)`。
- **【r2 新】頁面底色**：實際底色是 body 的 computed `background-color`（實測 `rgb(10,10,10)`，非純黑）。以下稱 `pageBg`，量測時以 `rgba(document.body, "backgroundColor")` 取得，不得寫死 (0,0,0)。
- 量測用 `getBoundingClientRect()`，`scrollY = 0` 除非另行註明；間距容差 ±1px。
- 情境 fixture（依賴 API 回應 mock，欄位見 dev-lead 交件）：
  - **F1**：authored，只有 covering 小節，1 行，無附註。
  - **F2**：authored，covering ＋ stale 並存；stale 含一行 A-11 與一行 A-12；某行有 A-6 與 A-15。
  - **F3**：authored，只有 stale。
  - **F4**：unauthored，`unclassified` 小節，含 A-6、A-15，多日期。
  - **F5（壓力，【r2 改】拆成兩組）**：A-9 屬 authored、A-13 屬 unauthored，在真後端上互斥，無法於同一 fixture 出現，所以：
    - **`f5`**（authored，含 A-9）：F2 加 §7 的最長情境（A-2＋A-9＋A-15＋A-6＋A-11＋A-12，8 日期列，20 字元 `symbol`）。
    - **`f5u`**（unauthored，含 A-13）：A-2＋A-4＋A-13＋A-15＋A-6，同一批 8 日期列與 20 字元 `symbol`。
    - 本檔凡寫「F5」者，指 `f5` 與 `f5u` **各跑一輪，兩者都要過**。
  - **F6**：F2 加上存在的回執橫幅（長橫幅：attribution、warnings 皆非空）。
  - **F7**：`pending_exit_block` 為 null；**F8**：缺鍵；**F9**：小節皆空。
  - **F10**：`/today` pending；**F11**：`/today` error；**F12**：背景重新取得失敗。

### 9.1 條款

- [ ] **VP-1 位置與 DOM 順序。** F2、F6：區塊是 `main` 的直接子元素，且是橫幅槽位 `div[role="status"]` 的**下一個兄弟**（`previousElementSibling` 即該槽位）。其後依序為 attribution、`page_summary`、warnings、Cap1／`RuleSetConfirmPanel`、帳冊、snapshot、settlement（存在者）。`compareDocumentPosition` 驗證區塊先於它們全部。區塊的任一祖先都不是：狀態列、`role="status"` 槽位、`[role="dialog"]`、`RuleSetConfirmPanel` 根、`DirectiveLedger` 根、warnings 容器。

- [ ] **VP-2 間距。** 依 §2.1 間距表逐項量測，F1、F2、F5、F6 各一輪：
  - 區塊上緣 − 前一個兄弟下緣 = **24**（F6 前一個兄弟是橫幅槽位，其下緣 = 橫幅下緣；無橫幅時 = 槽位下緣 = h1 列下緣）。
  - 區塊下緣 − 下一個可見兄弟上緣 = **24**。
  - 導言 − `h2` = 8；`h3` − 導言前 = 4；`ul` − 小節導言 = 8；行內 `text` → 附註 = 4；附註 → 附註 = 4；相鄰兩行 = 25；末尾說明之間 = 16。
  - stale 小節：上邊框寬 `2px`、`rgba(border-top-color)` = neutral-500；`h3` 上緣 − 小節上緣 = 18。

- [ ] **VP-3 欄線與狀態列。** 區塊 `left`、`width` 與 `<h1>` 的 `left`、`<main>` 內容欄寬各差 ≤ 1px（375：343；1280：992）。`scrollY = 0` 時區塊 `top` > 狀態列 `bottom`。區塊 `right ≤ innerWidth`。

- [ ] **VP-4 無盒（不像橫幅、不像狀態列、不像帳冊）。** 區塊根與**所有子孫**：
  - `rgba(backgroundColor)` 的 alpha = 0（透明）；
  - `border-radius` 全為 0；
  - `border-left-width` 與 `border-right-width` = 0（無左色條，無整圈邊框）；
  - 根容器 `padding` 四邊 = 0、`border` 四邊 = 0；
  - `box-shadow: none`、`outline-style: none`、`backdrop-filter: none`；
  - 允許存在的邊線**只有兩種**：`ul` 的上下 1px（`neutral-800`）與其 `li` 之間的 1px 分隔線、stale 小節的上緣 2px（`neutral-500`）。
  - 像素取樣：在導言與第一個小節之間的空白帶（高 ≥ 8px 處）水平置中取一點，`getImageData` 的 RGB **等於 `pageBg`（body 的 computed 背景色）各通道 ±1**（**【r2 改】** r1 寫死 (0,0,0)，實機 body 底色是 `rgb(10,10,10)`，該假設不成立；本條的本意是「區塊沒有自己的底色」，以 `pageBg` 比對才準確）。

- [ ] **VP-5 不 sticky、不 fixed、不 absolute。** 區塊根與所有子孫的 computed `position` 皆為 `static`；`z-index` 皆為 `auto`；`float` 為 `none`。捲動 0／中段／底部，區塊相對文件的 `top`（`rect.top + scrollY`）不變。

- [ ] **VP-6 無徽章、無圖示、無符號。**
  - 子孫中 `svg`、`img`、`canvas`、`video`、`i`、`[class*="icon"]`、`[aria-hidden="true"]` 數量 = 0；
  - 沒有 `display: inline-flex` 或 `inline-block` 且有邊框或底色的元素（徽章判準）；
  - 沒有寬高皆 ≤ 16px 的元素（圓點判準）；
  - `ul` 與 `li` 的 `list-style-type` = `none`，`li::marker` 不產生內容；
  - 區塊 `innerText` 中，剔除後端欄位內容（以 API 值逐段移除）之後，剩餘字元必須全為空白（即前端沒有加任何裝飾字元、編號、冒號、破折號）；
  - 區塊 `innerText` 不含 `\p{Extended_Pictographic}`，也不含 U+2713、U+2714、U+2705、U+2611、U+2717、U+274C、U+26A0。後端欄位本身的內容不在此限，但已有風控的禁用詞檢查。

- [ ] **VP-7 無彩色、無紅綠。** 區塊根與所有子孫的 `color`、`border-{top,right,bottom,left}-color`、`background-color`、`outline-color`、`text-decoration-color`，解析成 sRGB 後 `max(r,g,b) − min(r,g,b) ≤ 3`（無彩色）。另做 class 掃描：子孫 class 不含 `(text|bg|border|divide|ring|outline|decoration|fill|stroke)-(red|rose|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink)`。

- [ ] **VP-8 字級與對比不低於 `page_summary`。** 區塊內每個含文字的元素：
  - `font-size ≥ 14px`；
  - 文字色三個通道皆 ≥ 210（≥ neutral-300 的 212 − 容差 2）；
  - 與 `pageBg`（實際底色，實測 `rgb(10,10,10)`）的 WCAG 對比 ≥ 7:1（**【r2 改】** 一律用實際底色計算；`neutral-300` 實測 13.36，`neutral-100` 約 18.2；r1 以 (0,0,0) 計的 14.17 作廢）。
  - 若 fixture 內有 `page_summary` 段落，另以其 computed `font-size` 與解析後色值當動態基準，區塊內任一文字的 `font-size` 不得小於它、亮度不得低於它（容差 ±2 通道）。

- [ ] **VP-9 字級／字重／色階分層（§2 表）。** 逐元素斷言：
  - `h2`：18px／行高 28px／字重 600／色 neutral-100；
  - `h3`：14px／20px／600／neutral-100；
  - 導言、小節導言、附註、`entry_before_exit_note`、末尾說明：14px／20px／400／neutral-300；
  - 行本文：14px／20px／400／neutral-100；
  - 全區塊 `font-size` 的集合 = {14, 18}；`font-weight` 的集合 ⊆ {400, 600}；`font-style` 全為 `normal`；`text-decoration-line` 全為 `none`；`text-transform` 全為 `none`。

- [ ] **VP-10 內容順序與完整性。** 以 `f5` 與 `f5u` 各自為準，區塊內的文字依序等於：`title`、`lead_template`（`{read_at}` 以 `formatDateTime(as_of)` 代入且僅一次）、各小節依陣列順序的 [`label`（非 null）、`lead`、各行的 `text`、`notes[]` 依序、`entry_before_exit_note`（非 null）]、`closing_notes[]` 依序。逐段與 API 值嚴格相等（不 trim、不改寫）。`<li>` 的數量 = 各小節 `rows.length` 的總和。

- [ ] **VP-11 附註同列。** 每個 `<li>`：
  - 子元素順序 = `text`、`notes[]`、`entry_before_exit_note`，與 API 陣列順序一致；

  - 分組：`note.top − 前一個 p.bottom` = 4 ±1，且 < 相鄰兩行之間的距離（25 ±1）；

  - `<li>` 高度公式：`height = Σ(p 高度) + 4 × (p 數 − 1) + 24 (+ 1 若非第一行)`，容差 ±2（用以確認沒有預留高度）。

- [ ] **VP-12 完整顯示：不摺疊、不截斷、不 tooltip。** 區塊及所有子孫：

  - 不存在 `details`、`summary`、`[hidden]`、`[inert]`、`[title]`、`[aria-describedby]`、`[aria-label]`、`[data-tooltip]`；

  - 每個文字欄位用 `Range.getClientRects()` 取得矩形，每個矩形 `right ≤ 區塊.right + 0.5`、`bottom ≤ 文件高度`，且該欄位 `textContent` 與 API 值完全相等。

- [ ] **VP-13 無水平溢出。** 全部 fixture（含 F5）：`document.documentElement.scrollWidth ≤ innerWidth`；區塊 `scrollWidth ≤ clientWidth + 1`。建議另跑 320×640（suggested，不阻擋）。

- [ ] **VP-14 長字面換行。** `f5` 與 `f5u` 各一輪；視窗 **375、1280，另加 320×640（【r2 改】必驗，不再是 suggested）**：

  - 每個 `p` 的 `getBoundingClientRect().width` = 內容欄寬 ±1，且 `height` 為 20 的整數倍 ±1（`h2` 為 28 的整數倍）；
  - 375 寬：A-2 導言的行數（`height ÷ 20`）≥ 10；1280 寬同一段 ≤ 7；兩者都完整顯示（VP-12）；
  - 20 字元 ASCII `symbol` 那一行，所有 `Range` 矩形 `right ≤ 區塊.right + 0.5`；
  - **【r2 新】** 區塊內每個符合 `\d{4}-\d{2}-\d{2}` 的 token 都被一個行內 `span` 完整包住（span 的 `textContent` 恰等於該 token）；該 span 的 computed `white-space` = `nowrap`；該 span 是 `p` 的子孫，`p` 之外（`li`、`section`、區塊根、`h2`、`h3`）沒有任何元素的 `white-space` 為 `nowrap`／`pre*`；span 沒有其他 class、沒有 `title`／`aria-*`；`p.textContent` 與 API 值逐字相等（包裝沒有改字）。

- [ ] **VP-15 單一版型，無斷點。** 區塊根與所有子孫的 `className` 不含正規式 `(^|\s)(sm|md|lg|xl|2xl|max-sm|max-md|max-lg):`。三個視窗的 DOM 結構（元素標籤序列、`data-kind` 序列、`li` 數量）逐位元組相同；僅寬度與行數可以不同。

- [ ] **VP-16 單欄堆疊，無 flex／grid／表格。** 區塊根與所有子孫的 computed `display` ∈ {`block`, `list-item`}（`ul` 為 `block`，`li` 為 `list-item`）；**【r2 新】唯一例外**是 VP-14 的日期 span（`display: inline`，且必須是 `p` 的直接子元素）；沒有 `flex`、`inline-flex`、`grid`、`table*`。每個 `p`、`h2`、`h3` 的 `left` = 區塊 `left` ±1（左邊緣對齊同一條線）。

- [ ] **VP-17 三類小節的區分（§4）。**
  - 每個小節 `section[data-kind]` 的 `data-kind` 在 {`covering`, `stale`, `unclassified`}；
  - `h3` 存在 若且唯若 API 的 `label` 非 null，且 `h3` 文字 = `label`；前端不自行決定何時顯示；
  - `stale` 小節：`border-top-width` = 2px、色 = neutral-500；`covering`、`unclassified` 小節：`border-top-width` = 0；
  - **三類的行同品**：`text` 的 `color`、`font-size`、`font-weight`、`line-height`、`opacity` 在三類之間完全相同；附註同理；`li` 的 `padding` 相同；

- [ ] **VP-18 與橫幅、狀態列、觸發鈕並存時互不影響。** F6，以及同一 fixture 在「區塊存在」與「區塊不存在」（把 `pending_exit_block` 設 null）兩種情況下各量一次（兩寬度）：

  - `main > div[role="status"]` 仍是同一個 DOM 節點（掛載區塊前後保留引用，`===`）；
  - 區塊掛載（由無到有，例如出清後 `/today` 重新取得）時，**【r2 改】** 判準是「使用者看到的內容沒有被推走」，以下**任一**成立即過：(a) 掛載前後，視窗內**錨定元素**（掛載前位於視窗內、且在區塊之上或與區塊同處的元素，例如橫幅或 h1 列；若視窗全落在區塊之下，取視窗內第一個可見元素）的視窗座標（`getBoundingClientRect().top`）差 0（±1）；(b) `window.scrollY` 的差等於文件高度（`document.documentElement.scrollHeight`）增量（±1）。r1 寫「`scrollY` 差 0」不準：瀏覽器 scroll anchoring 會把 `scrollY` 同步加上增量，內容反而不動；實測差值正好等於文件高度增量（375 寬 1778、1280 寬 958）。加上 `overflow-anchor: none` 時 `scrollY` 差 0 但內容被推開，是較差的結果，**不得**以此作為過關條件，也不得為了讓 `scrollY` 差 0 而在產品碼加 `overflow-anchor: none`。同時要求掛載期間頁面程式沒有呼叫任何捲動函式（`scrollTo`／`scrollBy`／`scrollIntoView`）；
  - V-9、V-10、V-11、V-12、V-47 的量值與無區塊時相同（容差沿用各條）。

- [ ] **VP-22 無互動元素；不改變 Tab 順序。** 區塊內 `a[href]`、`button`、`input`、`select`、`textarea`、`[tabindex]`、`[contenteditable]`、`[onclick]` 數量 = 0；區塊內任一元素的 computed `cursor` = `auto` 或 `default`、`pointer-events` ≠ `none`；對任一行 `hover` 前後 `color`、`background-color`、`border-color` 不變。頁面 Tab 順序（可聚焦元素序列）在區塊存在與不存在時相同。

- [ ] **VP-23 語意與可及性。**
  - 區塊根是 `<section>`，`aria-labelledby` 指向 `h2` 的 id，該 id 唯一；標題層級為 `h1` → `h2`（區塊）→ `h3`（小節標籤），不跳級；

- [ ] **VP-24 無動畫、無過渡。** 區塊及所有子孫的 computed `transition-duration` 皆為 `0s`、`animation-name` 為 `none`、`transform` 為 `none`。區塊掛載與卸載的瞬間，逐 frame 取樣其 `opacity` 恆為 1（不淡入淡出）。
