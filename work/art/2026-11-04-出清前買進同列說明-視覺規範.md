## 1. 帳冊列 `DirectiveRow`

### 1.1 位置

現況列內由上而下：

```
li.border-l-4.border-y.px-4.py-3
  div.flex            規則 chip・parts[0]・parts[1]・parts[2]・狀態
  p  rule_summary     mt-2 text-sm  neutral-400
  div.grid            parts[4] parts[5] parts[6]      mt-2 text-xs neutral-400   ← `line` 的最後一段
  p  limit_note       mt-2 text-xs  neutral-400
  p  資料狀態・來源    mt-1 text-xs  neutral-400
```

定案：在 **grid 之後、`limit_note` 之前**插入 note 堆疊。

```
  div.grid
  ★ div[data-testid="row-notes"]   mt-2 space-y-1     ← 新增；沒有任何非空 note 時整個不渲染
  p  limit_note
```

理由：
- `line` 被拆成兩處顯示（標題列 `parts[0..2]`、grid `parts[4..6]`），`line` 的最末欄位是 grid；note 緊貼 `line` 的最後一段，才讀成「`line` 之後的下一句」，符合 `line` → N-188 → N-189 → W-B2L 系列的順序（§7）。
- 放在 `limit_note` 之後會被「資料狀態」「限價帶說明」兩個註腳隔開，離 `line` 太遠；風控要求同列。
- 放在 `rule_summary` 之前會把觸發條件與 `line` 隔開，打斷既有「動作 → 觸發條件 → 數值」的閱讀順序。
- note 一律是獨立 `<p>`，**不得拼進 `line`、不得改 `splitDirectiveLine`**（風控第 5 點、型別註解）。

### 1.2 層級反轉裁定：沿用 `text-sm text-neutral-300`

| 方案 | 結論 | 理由 |
|---|---|---|
| A. `text-xs text-neutral-400`（與周圍一致） | **否決** | 12px 低於 N-171 與出清畫面規範共同的下限（`text-sm` + `neutral-300`，風控 N-171 第四節第 4 點）；note 內含「請勿就這批到券商下賣單」「以券商回報為準」，是使用者下單前要讀的防超賣句，不能比註腳還小。 |
| B. `text-sm text-neutral-400`（折衷） | **否決** | 字級過了但色階仍低於下限，且與 N-171 同句在不同 surface 看起來不同亮度，使用者會把同一句讀成兩種重要性。 |
| **C. `text-sm text-neutral-300`（N-171 L6）** | **採用** | 同一個後端字面在 N-171 區塊、帳冊、批次列三處同字級、同色階、同字重，使用者辨認得出「這是同一句安全說明」。 |

接受的後果（明文記錄，不是疏漏）：
- 帳冊列內出現**刻意的層級反轉**：note（14px／`neutral-300`）比周圍的 grid、`limit_note`、資料狀態列（12px／`neutral-400`）更大更亮。這是安全句相對註腳的資訊優先序，不是裝飾。
- 列內的亮度順序仍成立：標題列（`text-sm font-medium neutral-100`）> **note（`neutral-300`）** > `rule_summary`（`text-sm neutral-400`）> 其餘 12px 註腳。**標題列仍是最亮的，note 沒有搶走主視覺。**
- note **不加粗、不加底色、不加左線、不加圖示、不縮排**：不靠額外強調去補償反轉，反轉本身已足夠，再加強調會變成警示樣式（出清畫面規範：這是使用者自己的選擇，不是錯誤）。

對比（sRGB 相對亮度公式實算，底色 `pageBg` = `rgb(10,10,10)`）：`neutral-300`（#d4d4d4）**13.35:1**（與 N-171 r2 qa-e2e 實測 13.36 一致）；`neutral-400`（#a3a3a3）約 7.8:1；`neutral-100` 約 18.2:1。全部 ≥ WCAG AA（4.5:1）與 AAA（7:1）。帳冊列 `li` 無自有底色（只有 `border-y`、`border-l-4`），文字底色即 `pageBg`。

### 1.3 class 骨架（load-bearing，數值以此為準）

```tsx
{notes.length > 0 && (
  <div data-testid="row-notes" className="mt-2 space-y-1">
    {notes.map((n, i) => (
      <p key={i} className="break-words text-sm text-neutral-300">
        {withNoBreakDates(n)}
      </p>
    ))}
  </div>
)}
```

- `notes` = 依 §7 順序排好、**已濾掉 `null`／`undefined`／空字串**的字串陣列；缺鍵（舊後端）讀作 `null`，與 `[]` 相同，**不渲染容器、不預留高度**。
- 每句一個 `<p>`；後端若把 W-B2LS 與 W-B2LSr 合成**同一個字串**送來（型別註解寫 "already composed"），就整串放進同一個 `<p>`，前端**不拆、不補分隔、不改字**（待確認項 C-1）。
- 不使用 `whitespace-pre*`、`truncate`、`line-clamp-*`、`overflow-*`、`max-h-*`、`break-all`、`title`、`aria-label`、`aria-describedby`、`details`。
- 不使用 `sm:`／`md:`／`lg:` 前綴。note 本身單欄堆疊，不隨斷點重排（grid 的 `sm:grid-cols-3` 是既有，不動）。

### 1.4 間距表（px，`getBoundingClientRect()`，容差 ±1）

| 量測 | 值 | 來源 |
|---|---|---|
| note 堆疊上緣 − grid 下緣 | **8** | `mt-2` |
| 堆疊內：相鄰兩句 | **4** | `space-y-1` |
| `limit_note` 上緣 − 堆疊下緣 | **8** | 既有 `limit_note` 的 `mt-2` |
| 堆疊左緣 − `li` 內容左緣（border-l 4 + px-4 16） | 0 | 不縮排 |

### 1.5 375px 換行

| 寬度 | `main` 欄寬 | `li` 內容寬（欄寬 − 4 − 32） | 14px 全形字／行 |
|---|---|---|---|
| 375 | 343 | **307** | 約 21 |
| 768 | 736 | **700** | 約 50 |
| 1280 | 992 | **956** | 約 68 |

- 全部 `white-space: normal`、`overflow-wrap: break-word`；ISO 日期 token 以行內 nowrap span 不拆（§6）。
- 行高恆為 20px，每個 `<p>` 高度是 20 的整數倍。
- 整列變高是預期的，不得因此壓縮（§4）。

## 2. 出清橫幅 `ExitReceiptBanner`

**結論：不在範圍，不渲染 note，不改此元件。**

事實（讀 `ExitReceiptBanner.tsx` 全文）：它只渲染 `response.message`、`response.mode_reason`（條件）、`response.attribution`（條件）、`response.warnings`（`<ul>`）。`response.directives` 與 `response.pending_directives` 型別存在（`types.ts` 2072、2080 行），**全前端沒有任何 view 讀它們**（grep 全 `app/` 非測試檔：唯一命中是型別宣告與測試 fixture）。

規範：
- 風控第 5 點的「同列」是「跟 `line` 同列」。橫幅沒有 `line`，就沒有地方可以同列放 note；硬加會變成**新增一份指令清單**，那是新的 surface、新的設計決策，不是 N-168 的範圍。
- 出清後使用者看到的待執行指令，由 **N-171 區塊**（`PendingExitBlock`，讀 `pending_exit_block` 而不是 `response.pending_directives`）與**帳冊**承擔；這兩處已涵蓋。
- 若日後要在橫幅內列指令：先走新規範修訂。預設做法屆時套 §1 的 `DirectiveRow` 骨架，色階對比在橫幅底色 `neutral-900`（#171717）上：`neutral-300` 約 12.1:1、`neutral-400` 約 7.1:1（出清畫面規範 §2.2 已實算），仍過 AA；本次不預先決定。
- 橫幅 computed 樣式與 DOM 在 N-168 前後必須**零差異**（VP-168-6）。

**若 frontend-engineer 發現橫幅或其他處實際有渲染 `directives`／`pending_directives` 的列（本檔讀碼未見），請回報 art-lead，本檔 §2 需改版。**

## 3. 批次列 `PositionSnapshotTable`

### 3.1 現況與約束

- 表格 `<table className="w-full min-w-[640px] text-left text-sm">`，外層 `<div className="mt-3 overflow-x-auto rounded-md border border-neutral-800">`。六欄全部 `whitespace-nowrap`。
- 因此 **375 寬時表格本身本來就會橫向捲動**（欄寬 343 < 640）；768（欄寬 736）與 1280（992）不捲動。這是既有的站內表格慣例（表格視覺規範），**本規範不改欄寬、不改 `min-w`、不改欄數、不調整 `whitespace-nowrap`**。
- 難點：若把 label／note 放進一般的 `<td colSpan=6>`，其寬度 = 表格寬 640px，375 寬時使用者要橫向捲動才讀得到後半句。這等於把 note 藏在捲動後面，與風控「不摺疊」同樣效果，**不接受**。

### 3.2 版面（定案）

每個批次在批次列正下方多一個**子列**，只有在 label 或任一 note 非空時才渲染（不渲染空 `<tr>`）：

```
tr[data-testid="snapshot-batch-row"]                 批次列（六欄，既有，只改 padding）
tr[data-testid="snapshot-note-row"]                  子列（新增）
  td colSpan=6                                       px-3 pb-3 pt-0，不加 whitespace-nowrap，不加底色
    div[data-testid="snapshot-note-pin"]             sticky left-3，寬 = 捲動容器可視寬 − 24px
      p  label (W-B2)                                 text-sm font-semibold neutral-100，break-words
      div[data-testid="row-notes"]  mt-1 space-y-1   note 堆疊
        p  note (W-B2L…)                              text-sm neutral-300，break-words
```

骨架：

```tsx
<div className="@container mt-3 overflow-x-auto rounded-md border border-neutral-800">  {/* @container added */}
  <table className="w-full min-w-[640px] text-left text-sm">
    ...
    <tbody>
      {snapshot.map((batch) => {
        const hasSub = label !== null || notes.length > 0;
        return (
          <Fragment key={`${batch.symbol}-${batch.batch_no}`}>
            <tr data-testid="snapshot-batch-row" className="border-t border-neutral-800">
              {/* each td: existing classes, but "py-2" -> "pb-1 pt-2" only when hasSub */}
            </tr>
            {hasSub && (
              <tr data-testid="snapshot-note-row">
                <td colSpan={COLUMN_HEADERS.length} className="px-3 pb-3 pt-0">
                  <div data-testid="snapshot-note-pin" className="sticky left-3 w-[calc(100cqw-1.5rem)]">
                    {label !== null && (
                      <p className="break-words text-sm font-semibold text-neutral-100">{withNoBreakDates(label)}</p>
                    )}
                    {notes.length > 0 && (
                      <div data-testid="row-notes" className={`${label !== null ? "mt-1 " : ""}space-y-1`}>
                        {notes.map((n, i) => (
                          <p key={i} className="break-words text-sm text-neutral-300">{withNoBreakDates(n)}</p>
                        ))}
                      </div>
                    )}
                  </div>
                </td>
              </tr>
            )}
          </Fragment>
        );
      })}
    </tbody>
```

做法說明：
- `@container` 讓捲動容器成為 container query 的參照，`100cqw` = 捲動容器內容寬（可視寬，不是表格寬）。`sticky left-3` 讓釘住的區塊在橫向捲動時停在可視區左側 12px，**scrollLeft 為 0 或最大時，label／note 都完整落在可視區內**。寬度 `100cqw − 24px` 是為了左右各留 12px（與其他欄 `px-3` 一致）。
- `pin` 的寬度 ≤ 可視寬，所以不會撐寬 `td`，**不會改變六欄的欄寬**（VP-168-9 驗）。
- 768／1280 時表格寬 ≥ 容器寬，`100cqw − 24px` 等於 `td` 內容寬，sticky 無位移，版面等同一般區塊。
- 子列 `td` 與 `pin` **不得**帶 `whitespace-nowrap`（既有 `td` 的 nowrap 是各 cell 自己的 class，不繼承；新 `td` 自己不加即可，VP-168-14 驗）。

### 3.3 label 與 note 的相對版面、字級、色階

| 元素 | 字級／行高 | 字重 | 色 | 間距 |
|---|---|---|---|---|
| label（W-B2，`entry_before_exit_label`） | 14px／20px | 600 | `neutral-100` | 子列第一個元素 |
| note（W-B2L／W-B2LS…，`entry_before_exit_note`） | 14px／20px | 400 | `neutral-300` | 與 label 之間 **4px**（`mt-1`）；note 之間 4px |

- **label 在上、note 在下，各占一行區塊，不並排。** 理由：label 是短標籤、note 約 150 字（W-B2L）到 310 字（W-B2LSf）；並排（flex／inline）會讓 label 與長句搶同一行寬度，375 寬時 label 被擠成窄欄逐字換行，違反「不得縮寫或截斷」的精神。上下堆疊時 label 恆有整個欄寬。
- label 與 note 同字級（14px），label 用 `font-semibold neutral-100`，與 N-171 的 `h3` 同款；不加底色、徽章、圖示。**不使用 `rounded` 膠囊**（W-B2 在批次列表是揭露標籤，不是狀態徽章）。
- **label 被長句擠壓時怎麼處理：結構上不會被擠壓**（獨立區塊、整行寬）。label 自己若長過一行，照常 `break-words` 換行、完整顯示。**不得**縮寫、截斷、省略、換成 tooltip。
- 與批次列的間距（分組判準：子列與其批次的距離 < 到下一批次的距離）：

| 量測 | 值 |
|---|---|
| 批次列文字下緣到 label 上緣 | **4**（批次列 `pb-1`；子列 `pt-0`） |
| 子列最後一句下緣到下一列分隔線 | **12**（`pb-3`） |
| 批次列與子列之間 | 無分隔線（只有下一批次列的 `border-t`） |
| 子列左緣 | 與其他欄 `px-3` 一致（表格左緣 + 12） |

### 3.4 「容得下」的可量測標準

三個視窗各跑一輪：**375×812、768×1024、1280×900**。任何一條不成立，即判定「容不下」，**不得縮寫、截斷、省略、換成 tooltip／摺疊，也不得調小字級或色階**，而是退回風控回審並附截圖（風控第 5 點）。

| # | 判準 | 量法 |
|---|---|---|
| a | 頁面無水平捲軸 | `document.documentElement.scrollWidth ≤ innerWidth` |

## 4. S2 長句（W-B2LSf 約 310 字，可能接 W-B2LSr）

## 7. 預留：多句 note 堆疊（N-188、N-189 之後免重做）

### 7.1 順序

單一 surface 內，所有 note 依下列順序組成同一個堆疊（資料不存在的項目略過，不留空位）：

```
line（不在堆疊內，是堆疊的前一個元素）
  → N-188
  → N-189(D1)
  → N-189(D2)
  → W-B2L 系列（W-B2L，或 W-B2LS［＋W-B2LSr］，或 W-B2LSf）
```

- 堆疊最多 5 句：N-188、N-189(D1)、N-189(D2)，加上 W-B2L 系列最多 2 句（W-B2LS＋W-B2LSr）；W-B2LSf 與 W-B2L 系列其他句互斥。**前端不排序、不合併、不過濾內容**，只依上面順序排列並丟掉 `null`／空字串。
- 實作建議（非字面）：用一個函式（例如 `collectRowNotes(item)`）回傳依此順序排好的字串陣列，三個 surface 共用；新欄位只需在函式裡按順序加一行。

### 7.2 間距與分隔（固定值，之後不得為了多句而改）

| 量測 | 值 |
|---|---|
| 句與句（`<p>` 與 `<p>`） | **4px**（`space-y-1`） |
| 堆疊上緣 − 前一個元素（帳冊：grid 下緣） | **8px**（`mt-2`） |
| 批次列：label → 堆疊 | **4px**（`mt-1`） |
| 堆疊下緣 − 下一個元素（帳冊：`limit_note`） | **8px**（`limit_note` 既有 `mt-2`） |
| 分隔線、項目符號、編號、「注意」類前綴、縮排、左色條、底色、圖示 | **一律禁止** |
| 每句的樣式 | 完全相同：`text-sm neutral-300`，400，不因來源不同而加強或降級 |

理由：
- 4px 與 N-171 §5 一致（附註堆疊 4px），三個 surface 同一個值。4px < 帳冊內其他區塊間距 8px < 列間距 12px（`space-y-3`），所以分組成立：堆疊內最緊、堆疊與其他欄位次之、列與列最鬆。
- 每句都以句號結尾、左緣對齊、各為獨立段落，不靠分隔線即可辨認句界。不加分隔線的原因：任何線、符號或縮排都會暗示「次要」或「作廢」（N-171 §4.2 同理由），而這些句子含防超賣句。
- **回審觸發**：若 N-188／N-189 上線後，qa-e2e 或 CEO 實機判定 3 句以上堆疊在 375 寬難以分辨句界，由 art-lead 出修訂把句距改 8px（`space-y-2`），同時動三個 surface；不得單獨在某一處加分隔。

### 7.3 適用範圍

- 帳冊 `DirectiveRow`、N-171 區塊 `<li>`：有 `line`／`text`，堆疊含上列全部項目。N-171 區塊的 `notes[]` 與 `entry_before_exit_note` 本來就是 4px 堆疊（N-171 §5），**不改**。
- 批次列子列：沒有 `line`，堆疊只含 W-B2L 系列；label 在最前。N-188／N-189 若不屬批次列，不渲染。
- 橫幅、結算：不渲染（§2、§5）。

### 9.2 對 N-171 規範的連動修訂（見 §10 C-3）

N-171 r2 VP-21 規定「`/today` success 時整頁 computed `position: sticky` 的元素恰好 1 個（狀態列）」。本規範在批次列子列引入 `sticky left-3` 的 `snapshot-note-pin`，會使該條在有批次 note 時失敗。修訂方式（只動量測口徑，不動設計）：

- VP-21 改為：「`position: sticky` 的元素，**扣除 `[data-testid="snapshot-note-pin"]` 之後**恰好 1 個（狀態列）；`snapshot-note-pin` 的 sticky 必須只有 `left`（`top`、`right`、`bottom` 為 `auto`）。」
- N-171 VP-5（區塊自身不 sticky）不受影響：`pin` 不在 N-171 區塊內。
- N-171 VP-19（非 success 時整頁 sticky／fixed = 0）不受影響：非 success 時沒有快照表。
