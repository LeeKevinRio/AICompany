### 0.3 兩個需要先讀的發現（會影響風控裁示）

起草中發現，風控或 PRD 現行文字有兩處與程式行為不完全相符。我的字面已依程式行為寫，不照抄原文，**請風控確認這樣處理可以**：

1. **L-18 的「沒有計入…排除計數」過寬。** KT-R-9 內容條件寫「這段期間的模擬交易沒有計入任何指標、權益曲線、回合清單或排除計數」。但 AC-16 情境 (iii) 與 KT-R-3 明列：樣本外內進場、在尾段才平倉的回合，**會**計入樣本外的跨界（已平倉）排除數。所以「尾段的模擬交易」一概不計入排除計數並不為真。我的 L-18 改寫為「在這段期間內才進場的回合，沒有計入被排除的回合數」，這句對所有情況為真。
2. **L-18 的「尾段長度由訓練窗與測試窗長度決定」不完整。** quant §5.8 的公式是 r = (n − 訓練窗) mod 測試窗，r 也取決於資料總根數 n。只講訓練窗與測試窗，會讓讀者以為與資料長度無關。我改寫為「取決於資料總根數、訓練窗與測試窗的長度」。顧慮是：這句是否有「引導使用者調整日期」的嫌疑（KT-R-9.3）。我認為它只是陳述決定因素、沒有任何方向，但請風控裁示（開放題 O-7）。

## L-03　報酬由低到高的小節標題與筆數格式

- **用途**：D-10 的小節標題（原稱「最糟 N 筆」）。**使用者面不用「最糟」「最差」**：n 小或全部獲利時，報酬最低的回合可能是正報酬，「最糟」會與事實不符，而且帶評等意味。
- **主案**

```
回合報酬率最低的幾筆（由低到高排列）：列出 {k} 筆／共 {n} 筆
```

- **備案**（更中性、不用「最低」）

```
回合報酬率由低到高排列：列出 {k} 筆／共 {n} 筆
```

  備案的取捨：不用「最低」可避開任何「最壞情況」聯想，但 k < n 時，讀者要靠「由低到高」加上「列出 k／共 n」自行推出列出的是最低那幾筆。
- **占位與資料來源**
  - `{k}`＝實際列出的筆數＝`min(N_WORST, n)`，取自後端下發的最糟清單長度。
  - `{n}`＝該區段 `RoundTripStats.n`，與「完整回合數」一格同一來源（D-10、F11-A-23）。
- **出現條件**：n > 0 時出現，所有 n 值（含 n < 5、5 ≤ n < 30、n ≥ 30）皆出現且結構相同；n = 0 時不出現，由 L-14 取代。
- **對應風控條件**：D-10、F11-R-22、AC-2、AC-3。

## L-10　筆數提醒句（常駐）
