## 1. R2 歸屬語（帳冊列常駐一行，`{ATTRIBUTION_LINE}` 版位）

### 定位

視覺規範 3.3 明定此行固定在標的／動作行正下方、與該行同一視覺區塊、字級不得最小化。內容須讓使用者
一眼確認：**這筆指令是我自己在某天設定的規則被機械執行的結果，系統沒有做任何判斷，也沒有給我建議。**
三要素缺一不可：①主體是使用者本人（你）②有具體日期（規則設定/最近一次修改日）③明講「機械執行」且
明講「非本系統判斷或建議」。

佔位符：`{RULE_SET_DATE}` — 該規則版本最近一次由使用者本人設定/修改生效的日期（非當日日期，非資料
基準日，避免與帳冊列既有的「依據資料日」「規則版本 v{N}・生效日」混淆而重複，若風控裁定沿用現有
「規則版本・生效日」欄位即可代入不必新增欄位，屬實作細節，交 backend-engineer/art-lead 確認資料源）。

### 候選版本

**版本 A（完整版，三要素展開陳述）**

```
此指令是你於 {RULE_SET_DATE} 自行設定的規則之機械執行結果，非本系統的判斷或建議。
```

- 約 30 字，三要素順序：日期→規則歸屬→執行性質→系統定位澄清，語氣最完整、最不易被誤讀。
- 風險：帳冊列已有多行必顯文字（觸發條件、provenance 四行），此行加長可能撐版面，需 art-lead 覆核
  是否需要換行或字級微調（視覺規範 10 節已預告此可能性）。

**版本 B（精簡版，去除開頭贅詞，推薦）**

```
依你於 {RULE_SET_DATE} 設定的規則機械執行，非系統判斷或建議。
```

- 約 22 字，三要素仍齊全（你／日期／機械執行、非判斷或建議），去掉「此指令是」的敘事包裝，直接以
  「依……執行」開頭，符合本模組既有「最小事實陳述」文風（呼應 `wording.py` 開頭 house style 說明）。
- 為什麼推薦：帳冊列每筆指令已有 7–8 個必顯欄位，此行是**追加**而非取代任何既有欄位，越精簡越不
  擠壓觸發條件與 provenance 四行的可讀性；且三要素齊全，不因精簡而漏字。

**版本 C（弱化「機械」用字，改用「僅按字面執行」）**

```
你於 {RULE_SET_DATE} 設定的規則，本系統僅按字面執行，不加入判斷或建議。
```

- 約 28 字，把「機械執行」換成「僅按字面執行」，語感略柔和但仍是描述執行方式的事實陳述（非溫度詞、
  非安撫詞），供風控評估「機械」一詞是否在中文語境下顯得生硬/易被誤讀為推卸責任。

**推薦**：版本 B。理由：字數最省、三要素齊全、與帳冊列既有文風一致，最不易在視覺規範要求的緊湊
版面下造成換行風險；版本 A 保留供風控認為「機械執行」需要更完整鋪陳時的備選，版本 C 保留供風控認為
「機械」用字需柔化時的備選。

## 2. EMERGENCY_EXIT 確認流程文案

依視覺規範 4.3 版式：Step 1（點擊按鈕）→ Step 2（事實核取，全勾選才能進入 Step 3）→ Step 3（二次
確認）→ 執行後回報。以下提供兩版**整組**候選（Step 1 按鈕、Step 2 標題與四條核取句、Step 2/3 按鈕、
執行後回報句），供風控整組挑選或混搭。

兩版共同遵守：EX-2（無冷卻期/次日生效/等待期——20 交易日凍結是「排程之後的動作」的結果，不是
「執行 EXIT 這個動作本身」被延遲）、EX-3（凍結期間 S/P 可執行、可再次 EXIT）、EX-5（一步式事實核取、
零勸阻語氣）、EX-6（雙出口路徑不混淆：EXIT＝全組合，不可指定單檔）、H-1（零「阻止/鎖住」字眼）。

### 版本 1（沿用視覺規範既有草稿語感，正式化）

**Step 1 按鈕**：`全部出清`

**Step 2 畫面**

```
全部出清 — 確認前請閱讀以下事實

□ 此操作將對目前持有的全部標的、全部批次送出出清指令；
   不可只出清部分標的或部分批次，亦不可指定單一標的（如需針對單一標的停損，
   請改用該標的的 S 系列規則）。

□ 執行後，所有排程動作將凍結 20 個交易日（預計恢復日：{FREEZE_UNTIL}，
   依交易日曆計算）。

□ 凍結期間內，S／P 系列規則（停損／停利）仍正常運作；僅 R 系列（新倉進場）暫停，
   且凍結期間仍可再次執行全部出清。

□ 目前市場狀態：{MODE_LABEL}{若為快市，附「・快市・20 日年化波動率 {VOL}%」}。

                              [ 取消 ]  [ 我已閱讀，繼續 ]
```

**Step 3（二次確認）按鈕**：`取消` ／ `確認送出全部出清`

**執行後回報句**（帳冊列位置替換為常駐橫幅，呼應視覺規範 4.4）：

```
已於 {EXECUTED_DATE} 執行全部出清：出清 {BATCHES} 批、共 {SHARES} 股。
排程凍結中（第 {N}/20 個交易日），預計 {FREEZE_UNTIL} 恢復。
凍結期間 S／P 系列規則仍正常運作，若有觸發將照常顯示於下方。
```

### 版本 2（更口語化、句子更短，降低單句資訊密度）

**Step 1 按鈕**：`執行全部出清`

**Step 2 畫面**

```
確認全部出清

□ 全部標的、全部批次會一次出清，不能只選部分標的或部分批次，
   也不能只指定單一標的（單一標的停損請用該標的的 S 系列規則）。

□ 出清後，排程動作凍結 20 個交易日，預計 {FREEZE_UNTIL} 恢復
   （依交易日曆計算）。

□ 凍結期間，S／P 系列（停損／停利）照常運作；R 系列（新倉進場）暫停；
   凍結期間仍可再次送出全部出清。

□ 目前市場狀態：{MODE_LABEL}{若為快市，附「・快市・20 日年化波動率 {VOL}%」}。

                              [ 返回 ]  [ 確認，前往最後一步 ]
```

**Step 3（二次確認）按鈕**：`返回` ／ `送出全部出清指令`

**執行後回報句**：

```
全部出清已執行（{EXECUTED_DATE}）：{BATCHES} 批、{SHARES} 股。
排程凍結中，第 {N}/20 個交易日，預計 {FREEZE_UNTIL} 恢復；
S／P 系列規則仍照常運作。
```

**推薦**：版本 1。理由：四條核取句每句只承載一個事實，句子略長但資訊完整、與視覺規範既有草稿
（`work/stock-desk-快市排程-視覺規範.md` §4.3）最接近，減少 art-lead 事後對版面重新校對的成本；
版本 2 供風控認為「句子需要更短、更快讀完」時的備選（適合行動裝置窄版位）。

**與現有程式碼字串的落差提醒（非本次修改範圍，僅供風控與 backend-engineer 對照）**：
`apps/stock-desk/backend/app/playbook/wording.py` 現有 `EMERGENCY_EXIT_RESULT` 為
`"EMERGENCY_EXIT 已執行：出清 {batches} 批、共 {shares} 股；所有排程凍結至 {until}。"`，
未含「第 N/20 交易日」進度與「S／P 系列仍運作」這兩項視覺規範 4.4 要求的資訊。以上兩版執行後回報句
已補齊，若風控核定其中一版，交 backend-engineer 同步更新該常數（此為既有字串，非新增，仍需走
CEO 裁決「playbook 全部定稿文案逐句回審」流程，不因是既有字串而略過）。

## 3. 拒絕回覆模板（鐵律④ + 快市加註）

### 定位

視覺規範 4.5 已給出雛形，統一套用於「鐵律④盤中求情拒絕」「快市期間拒絕請求」「凍結期間嘗試繞過」
三種情境，**不因情境不同而加重或減輕語氣**。以下針對任務指定的兩塊（鐵律④基礎模板 + 快市加註）
潤字為定稿候選；三情境共用同一模板，快市加註為條件式附加句（僅快市狀態下出現）。

全篇不使用「拒絕」「駁回」「不允許」字面（呼應 R14「規則修改永遠開放，不稱為拒絕」與
`wording.py` 既有 `RULE_CHANGE_PENDING` 的處理原則：規則修改請求永遠被記錄為「待生效」，不是被
擋下）。

### 3.1 鐵律④基礎模板（盤中求情式規則修改請求）

**候選 A（貼近既有 `RULE_CHANGE_PENDING` 字串，最小改動）**

```
依規則 {RULE_ID}，本次規則修改已記錄為待生效，生效日 {EFFECTIVE_DATE}
（版本 {VERSION}）；今日（{TODAY}）仍依現行規則版本執行。
```

**候選 B（貼近視覺規範 4.5 統一模板，額外附目前狀態，供三情境共用同一句型，推薦）**

```
依規則 {RULE_ID}，目前為{目前狀態}（第 {N}/{M} 期）。本次規則修改將於
{EFFECTIVE_DATE}（版本 {VERSION}）生效，今日仍依現行規則執行。
```

**推薦**：候選 B。理由：候選 A 只適用「規則修改請求」單一情境；候選 B 把「目前狀態」納入固定欄位，
可不改句型直接套用到快市拒絕、凍結期間繞過等其他情境（視覺規範 4.5 明文要求同一套句型不因情境
加重減輕語氣），一套模板打通三種情境，減少之後逐情境各自定稿的工作量與不一致風險。若某情境沒有
「目前狀態」可陳述（例如純粹的規則修改請求、無特殊模式），`{目前狀態}` 可代入「正常模式」維持句型
完整而非省略欄位。

### 3.2 快市加註（僅快市狀態下附加於基礎模板之後）

```
目前符合快市條件（20 日年化波動率 {VOL}%；近 {LOOKBACK} 交易日有 {MOVES} 日
|漲跌幅| ≥2%）；快市期間規則不放寬。
```

- 直接沿用 `apps/stock-desk/backend/app/playbook/wording.py` 既有 `FAST_MARKET_REFUSAL_SUFFIX`
  字串（僅斷句微調，數值不變），理由：該句已符合 R13（純數據陳述、零評價字眼）與 CEO 裁決六
  （快市期間拒絕回覆需附當前波動率數據），無需另立新版本，僅列入本文件供風控與其他候選一併逐句
  核定。
- **FM-2 提醒**（供風控核定時參考，非新增文案）：此加註只說明「規則不放寬」，不代表「改規則路徑
  關閉」——改規則路徑（R14 冷卻期機制）在快市期間仍必須可達，此加註不需要也不應該重複解釋這件事
  （重複解釋反而稀釋「快市期間規則不放寬」這句的訊息密度），路徑是否可達是 UI 層級的呈現義務
  （FM-2），不是這句文案要承擔的責任。
